Pulling Actuals from a Long-Format Database with SUMIFS

Scope: Pulling actuals from a long-format database with SUMIFS keyed on month-end dates

Why it matters

The rolling forecast is only as fast as its actuals feed. If actuals are pasted into a wide grid each month, someone must align columns, check that the right month landed in the right place, and remember to extend formulas. A long-format database with one row per month × account × entity, queried with SUMIFS keyed on month-end dates, eliminates that: a new month is appended at the bottom, and every report picks it up when the cutoff moves. This is also the shape of every EPM data load and Power BI fact table, so building it in Excel is preparation for the tools used in large Indian FP&A teams.

Core notes

Long format vs wide format

Wide (avoid as storage) Long (store this way)
One row per account, one column per month One row per account × entity × month
New month = new column, formulas must extend New month = new rows appended
Hard to add dimensions (entity, version) Any dimension is just another column
Formula reads a column position Formula reads by criteria

Minimum columns for the actuals table Act: Month (month-end date serial), Entity, Acct (forecast account / reporting line), Amt (signed amount in ₹, consistent sign convention), plus optional GLCode, CostCentre, Source, LoadDate.

Why month-end dates as keys

  • EOMONTH produces month-ends, so headers and keys match natively.
  • A date serial is unambiguous across regional settings; "Sep-25" text is not.
  • Range criteria work: ">="&FYStart and "<="&Cutoff sum YTD in one SUMIFS, impossible with text periods.
  • Fiscal-period codes from ERPs (SAP posting period 006 for September under an April FY, Tally's month names) must be converted on load — in Power Query with Date.EndOfMonth combined with Date.AddMonths from the fiscal-year start, or via a period-mapping table (FiscalYear, Period → MonthEnd).

The core formulas

Single month for one account:

=SUMIFS(Act[Amt],Act[Month],C$4,Act[Acct],$A10)

With entity selector (named SelEntity, "All" meaning consolidated):

=SUMIFS(Act[Amt],Act[Month],C$4,Act[Acct],$A10,Act[Entity],IF(SelEntity="All","*",SelEntity))

The wildcard "*" matches any text entity code — ensure entity codes are text, not numbers, or wildcard matching fails.

YTD in one formula (no grid needed):

=SUMIFS(Act[Amt],Act[Acct],$A10,Act[Month],">="&FYStart,Act[Month],"<="&Cutoff)

TTM:

=SUMIFS(Act[Amt],Act[Acct],$A10,Act[Month],">"&EOMONTH(Cutoff,-12),Act[Month],"<="&Cutoff)

Mapping GL to forecast accounts

Actuals come at GL-code level (hundreds of codes); the forecast runs at reporting-line level (s06). Map on load rather than in the grid: a Map table (GLCode → Acct, CostCentre → BU) merged in Power Query, or a helper column in Act: =XLOOKUP([@GLCode],Map[GLCode],Map[Acct],"UNMAPPED"). Add a check: =SUMIFS(Act[Amt],Act[Acct],"UNMAPPED") must be zero, and a TB tie-out: total of Act by month equals the trial balance P&L total from the ERP.

Sign conventions

Ledger extracts usually carry credits as negatives (revenue negative). Choose one convention for the forecast database — commonly revenue positive, costs positive, profit = revenue − costs — and flip signs during load using an AcctType attribute in the mapping table. Mixed conventions are the commonest cause of EBITDA doubling or cancelling in a new model.

Performance

SUMIFS on Excel Tables is fast even on 200,000 rows, but a 60-account × 18-month × 10-entity grid is 10,800 SUMIFS. Keep it fast by: restricting the actuals table to P&L/BS lines needed, pre-aggregating to account × entity × month in Power Query (not transaction level), avoiding whole-column references (A:A) inside SUMPRODUCT, and using a pivot table or Power Pivot when slicing many dimensions.

Illustration

Act contains (₹ lakh):

Month Entity Acct Amt
31-Aug-2025 MUM Revenue 1,250
31-Aug-2025 BLR Revenue 980
30-Sep-2025 MUM Revenue 1,310
30-Sep-2025 BLR Revenue 1,020
30-Sep-2025 MUM Freight 64

With header C4 = 30-Sep-2025, A10 = "Revenue", SelEntity = "All": result 2,330. With SelEntity = "BLR": 1,020. Header 31-Oct-2025 returns 0 (no rows) — correct for an actual column only because the flag will route October to the forecast.

Edge cases & judgement calls

  • Zero vs missing: SUMIFS returns 0 for "no data loaded" and for "true zero". Add a load-status table (Month, Entity, Loaded Y/N) and a check that every month ≤ cutoff is loaded for every entity.
  • Duplicates: re-loading a month without deleting the earlier load doubles actuals. Use Power Query to replace (not append) the current month, or a LoadID and a check of row counts per month.
  • Late adjustments: a post-close journal for September posted in October's period appears in October; decide whether management actuals use posting period (simpler, ties to TB) or restated period, and document it.
  • Intercompany: consolidated actuals need intercompany eliminations; either load eliminated data from the consolidation tool or include an Elim entity.
  • Balance sheet accounts: store closing balances (not movements) per month and use exact-month criteria, never a YTD range sum.
  • Dates stored as text in the extract: SUMIFS silently returns zero; validate with =COUNT(Act[Month])=ROWS(Act[Month]).

Key takeaways

  • Store actuals long: Month (month-end date) × Entity × Account × Amount, in a named Excel Table.
  • Key everything on month-end date serials so headers from EOMONTH match exactly.
  • SUMIFS with range criteria gives single-month, YTD and TTM values from the same table.
  • Map GL codes and flip signs at load, and check for unmapped amounts and TB tie-out.
  • Protect against duplicates, missing loads and text dates with explicit checks.
  • Pre-aggregate in Power Query to keep thousands of SUMIFS fast.

Practice Questions

Q1. Writing the retrieval formulas [L1]

Given table Act with columns Month, Entity, Acct, Amt, write formulas for (a) September 2025 revenue for entity "PUN", (b) FY26 YTD revenue for all entities at the current Cutoff, and (c) TTM freight cost at the current Cutoff.

Q2. Converting SAP posting periods [L2]

An SAP extract has columns FiscalYear (2025), Period (001–012, with 001 = April under an April–March fiscal year variant; FiscalYear 2025 = April 2025–March 2026), GL, ProfitCentre and Balance (credits negative). Describe the Power Query steps to produce the Act table with month-end dates, mapped accounts and revenue-positive signs, and write the M or Excel formula that converts FiscalYear and Period into a month-end date.

💡 Hint: Period 010 of FiscalYear 2025 is January 2026 — the calendar year changes in periods 010–012.

Q3. Tie-out and integrity checks [L2]

Design four checks for the actuals load of a 9-entity group: completeness, duplicates, mapping and TB tie-out. For each, write the Excel formula and explain what a non-zero result would indicate.

Q4. Diagnosing doubled actuals [L2]

After the October close, consolidated YTD revenue in the forecast shows ₹1,674 crore against ₹1,436 crore in the published management accounts. The controller re-ran the September Power Query refresh on WD 1 of October after an adjusting entry. Identify the likely cause, the quantity of the error implied if September revenue was ₹238 crore and other months are correct, and the process fix.
