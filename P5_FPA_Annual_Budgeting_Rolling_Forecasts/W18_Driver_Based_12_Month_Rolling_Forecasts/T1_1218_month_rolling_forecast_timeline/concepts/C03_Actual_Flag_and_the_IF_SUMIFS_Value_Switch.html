Key concept

Actual Flag and the IF-SUMIFS Value Switch

Concept: Actual flag: =--(Hdr<=Cutoff); value: =IF(Flag,SUMIFS(Act[Amt],Act[Month],Hdr,Act[Acct],$A5),Fcst)

Statement

For each timeline column with month-end header Hdr:

Flag   =--(Hdr<=Cutoff)
Value  =IF(Flag,SUMIFS(Act[Amt],Act[Month],Hdr,Act[Acct],$A5),Fcst)

Mathematically, for account \( a \) and month \( t \):

\[ F_t = \begin{cases} 1 & \text{if } H_t \le C \\ 0 & \text{otherwise} \end{cases} \qquad V_{a,t} = F_t \times A_{a,t} + (1 - F_t) \times \hat{V}_{a,t} \]

where \( H_t \) is the header date, \( C \) the cutoff, \( A_{a,t} \) the actual amount for account \( a \) in month \( t \) (sum of matching rows in table Act), \( \hat{V}_{a,t} \) the forecast for that cell, and \( V_{a,t} \) the reported value.

Explanation

The comparison Hdr<=Cutoff yields TRUE/FALSE. The double unary -- coerces it to 1/0 so the flag row can be summed (count of closed months), multiplied (masking) and used in SUMPRODUCT (YTD = values × flags). IF treats 1 as TRUE, so the same flag drives the switch.

In the value formula, SUMIFS aggregates all actual rows that match both the month key and the account in column A ($A5 locks the column, so the formula copies across months and down accounts). When the flag is 0, Fcst — a reference to the forecast calculation row for the same account and month — is returned. IF evaluates only the selected branch, so an error in a not-yet-built forecast row does not contaminate actual months.

Conditions for correctness:

  • Hdr and Act[Month] must both be month-end date serials (c01, s05).
  • Cutoff must be the last hard-closed month.
  • Account labels in column A must exactly match Act[Acct] (watch trailing spaces; TRIM on load).
  • The forecast row must exist for every account; otherwise forecast months show 0 or blank.

Variants: add Act[Entity] criteria for entity selection; replace Act with a combined Fact table and use a version criterion (IF(Flag,"Actual","Working")); the arithmetic form =Flag*SUMIFS(…)+(1-Flag)*Fcst is array-friendly but evaluates both parts.

Illustration

Cutoff 31-Aug-2025. Row 5 = "Freight". Actuals table has freight (₹ lakh): Jul 48, Aug 52. Forecast row 25 = tonnes × ₹ per tonne: Sep 3,500 t × ₹1,550 = 54.25 lakh, Oct 3,800 t × ₹1,550 = 58.9 lakh.

Header 31-Jul-25 31-Aug-25 30-Sep-25 31-Oct-25
Flag 1 1 0 0
Source SUMIFS SUMIFS Fcst row Fcst row
Value 48.00 52.00 54.25 58.90

After the September close (actual freight 56.1), moving the cutoff to 30-Sep-2025 flips the September flag to 1, the cell returns 56.1, and the ₹1.85 lakh difference is September's actualisation variance.

Connections

Core mechanic of s04 (flags and source switching), reading from the database built in s05 and using headers from c01/c02. The flag row produces YTD/YTG and the LE in Topic 2 (c01 there: LE = YTD actual + YTG forecast). In Topic 4, the version-criterion variant is the bridge to database-style version storage. In Power BI (Week 11), the same logic becomes a date-table IsActual column and a measure using IF or CALCULATE with a filter on it.

Q2. Flag arithmetic [L2]

For an FY26 April–March grid with cutoff 30-Nov-2025, write formulas for (a) the number of closed months from the flag row, (b) YTD and YTG for row 12 using SUMPRODUCT, and (c) the average monthly actual YTD. Compute (a) and state what (b) returns for a row whose values are ₹10 crore every month.

Q3. Choosing IF vs arithmetic switch [L2]

The forecast row for "Other income" contains #DIV/0! in months where the driver denominator is zero. Compare the result of the IF form and the Flag*Actual+(1-Flag)*Fcst form in actual and forecast months, and recommend a fix to the forecast row.
