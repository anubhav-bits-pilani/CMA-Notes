Roadmap topic: Scenario & Reforecast Governance: Managing Budget vs Q1 Forecast vs Q2 Forecast versions cleanly without breaking formula references

Overview

Once a company moves from a single annual operating plan (AOP) to rolling forecasts and Latest Estimates, the FP&A team is no longer managing one set of numbers — it is managing a growing family of them. By the end of Q2 of an Indian FY a typical listed mid-cap has the Board-approved Budget, a Q1 Forecast (3+9), a Q2 Forecast (6+6), possibly a monthly flash LE, and within each of those a Base, Upside and Downside case. Every one of these must remain reproducible: the Audit Committee will ask why the Q2 forecast for EBITDA fell ₹18 crore versus Q1, the statutory auditor will test the inputs behind the impairment value-in-use cash flows (Ind AS 36 requires the most recent Board-approved budgets/forecasts), and the CFO will want to know whether the Board was shown the "real" downside before guidance was issued. Governance is the discipline that keeps these numbers distinct, frozen when they should be frozen, comparable and explainable.

The topic has two orthogonal axes. A version is a time snapshot — the organisation's view of the future as at a specific date (Budget at February, Q1 Fcst at July close, and so on). A scenario is an alternative set of assumptions applied at the same point in time (Base, Upside, Downside, Stress). Confusing the two is the root cause of most model breakage: teams copy a sheet to create "Q2 Fcst", then copy it again to create "Q2 Fcst Downside", and within two cycles nobody knows which tab feeds the Board pack. The professional fix is database-style storage — one long-format fact table with Version and Scenario columns — plus selectors that pull the required slice into a fixed reporting layout, plus locking rules that freeze submitted versions.

The learning sequence is: (1) define the version/scenario distinction and the naming taxonomy (s01, c04, c05); (2) restructure storage into long format so adding a version is a row-append, not a sheet-copy (s02, c01); (3) build selectors so the same report layout shows any scenario or version (s03, c02); (4) apply locking, snapshotting and change logs (s04, c04); (5) build the comparison views and forecast-to-forecast movement bridges that management actually consumes (s05, c03); (6) extend scenarios into genuine stress testing with contingency triggers (s06, c05); and (7) map the same concepts onto enterprise performance management (EPM) tools — Oracle EPBCS, Anaplan and Workday Adaptive Planning — because most large Indian groups run one of them (s07).

For the target FP&A roles, this is where an analyst stops being "the person who maintains the model" and becomes the person whose numbers the CFO trusts. Interviewers routinely ask: "How do you store versions?", "How would you explain a ₹50 crore swing between forecasts?" and "What is the difference between a scenario and a sensitivity?" — each maps directly to a subtopic below.

Related concepts to study

Power Query append of version snapshots (Week 10)

→ Week 10: Power Query to append version snapshots into one fact table

When each version is submitted, the cleanest archive is a values-only CSV or Excel table per version (for example FY26_Q2Fcst_Base_20251015.csv) saved to a controlled SharePoint folder. Power Query's From Folder connector, combined with Append Queries, stacks every snapshot into a single fact table without any manual copy-paste. The file name can be parsed into Version, Scenario and Timestamp columns using Split Column by Delimiter, so adding a new version means dropping a file in the folder and clicking Refresh. This is exactly the long-format layout of s02, and it makes version immutability physical: the snapshot file is never edited, only superseded by a newer file.

Power BI version slicers and calculation groups (Week 11)

→ Week 11: Power BI version slicers and calculation groups for variance columns

In Power BI, Version and Scenario become dimension tables related to the fact table. A slicer on Version replaces the Excel selector cell. For comparison columns, two disconnected copies of the Version table ("Base version" and "Compare version") allow a measure such as Var = [Amt Base] - [Amt Compare] where each uses TREATAS or CALCULATE with the selected version. Calculation groups (authored in Tabular Editor or now natively in Desktop) let you define "Actual", "Budget", "LE", "Var vs Budget", "Var %" once and apply them to every base measure — revenue, gross margin, EBITDA — avoiding dozens of duplicated measures. This is the BI-layer equivalent of the s05 comparison grid.

Scenario switches and data tables in 3-statement models (Phase 4)

→ Phase 4: scenario switches and data tables in 3-statement models

The selector techniques here are the same ones used in Phase 4 integrated models: a scenario number on the cover sheet flows through CHOOSE or INDEX into revenue growth, margin, capex and working-capital days, and the three statements re-balance automatically. The governance difference is that a 3-statement model must also re-balance debt, interest and cash, so a downside scenario may trigger covenant tests or revolver draws. Excel data tables (TABLE()) then sweep one or two inputs across a grid to produce sensitivity matrices (for example WACC × terminal growth). Learning version governance now means your Phase 4 models will carry Base/Upside/Downside cleanly without duplicated sheets.

Excel Scenario Manager, Data Tables and model audit tools

Excel Scenario Manager and Data Tables limitations; model audit tools (Inquire, trace precedents)

Excel's built-in Scenario Manager stores up to 32 changing cells per scenario, overwrites the live input cells when "shown", is invisible to anyone reading the sheet and produces a static summary report — it fails every governance test (no audit trail, no long-format storage, easy to leave the model in the wrong case). Data Tables recalculate the whole model for each cell, are volatile, slow large workbooks and cannot reference inputs on other sheets. Use them for small sensitivity grids only. For audit, the Inquire add-in (Microsoft 365 Apps for enterprise) offers Workbook Analysis, Compare Files (ideal for diffing two version snapshots) and relationship diagrams; Trace Precedents/Dependents and FORMULATEXT help reviewers confirm that every version column uses one consistent formula.

Common pitfalls

Copying sheets per version

Copying sheets per version, causing broken references and inconsistent formulas.

The mistake is creating "P&L Budget", "P&L Q1 Fcst", "P&L Q2 Fcst" tabs by duplicating a sheet each cycle. People do it because it is fast and visually intuitive. The consequences: summary formulas must be re-pointed each cycle (and often are not), a formula fix in one copy is not applied to the others, and comparing versions requires INDIRECT or manual links. Correct treatment: one long-format data table with a Version column, one report sheet with a version selector (s02, s03). Detect it in review by listing sheet names, using Inquire's Workbook Analysis to count inconsistent formulas, and checking whether the summary references different tabs for different columns.

Editing a locked version after submission

Editing a locked version after submission, destroying the audit trail.

A business head asks for "one small correction" to the Q1 forecast after it has gone to the Board, and the analyst overwrites it. This destroys comparability: the Q2-vs-Q1 bridge now explains a movement from a number the Board never saw. Correct treatment: submitted versions are immutable; corrections are made in the working version and explained in the next bridge, or a new version "Q1 Fcst v2" is created with a change-log entry and approver. Detect it by comparing the stored snapshot hash/total against the Board pack, checking file modified dates and reviewing the change log for entries after the lock date.

Calling a ±10% sensitivity a scenario

Calling a ±10% sensitivity a "scenario" without internally consistent assumptions.

A "downside" that is simply revenue × 0.9 with costs unchanged is a sensitivity, not a scenario. It overstates the EBITDA hit (variable costs should fall with volume) and understates second-order effects (working-capital release, discounting, raw-material price movements). People do it under time pressure. Correct treatment: build scenarios as coherent narratives — a demand shock lowers volume, raises trade discounts, reduces variable freight and lengthens debtor days together (c05, s06). Detect it by checking whether more than one driver changes between Base and Downside and whether the cost lines move in a direction consistent with the narrative.

Comparing versions without normalisation

Comparing versions with different account mappings or FX rates without normalisation.

If the chart of accounts was remapped in July (say, freight moved from "Selling" to "COGS") or the Budget used ₹83/USD while the Q2 forecast uses ₹88/USD, a raw version comparison mixes structural and economic changes. Correct treatment: restate prior versions to current mapping (or map both to a stable reporting hierarchy), and present FX at constant currency alongside reported currency so that the bridge isolates the FX effect as its own bar. Detect it by checking the mapping version and FX rate table attached to each version record and by reconciling version totals at the trial-balance level.

Practice Questions

Q1. Restructuring a sheet-per-version workbook [L3]

Ganga Consumer Ltd's FP&A workbook has six tabs: "Budget FY26", "Q1 Fcst", "Q1 Fcst Downside", "Q2 Fcst", "Q2 Fcst Upside" and "Q2 Fcst Downside". Each tab holds 40 P&L accounts × 12 months for 3 business units. The summary sheet links to cells on each tab. (a) Design the replacement long-format table: list its columns, give the expected row count, and state the primary key. (b) Write the SUMIFS formula for the summary cell that returns April-2025 Revenue for BU "Foods" for the selected version and scenario, assuming the table is named Fact and selectors are named SelVer and SelScen. (c) Describe the locking procedure you would apply when Q2 Fcst is submitted on 15 October 2025. (d) Explain how you would prove to the internal auditor that the Q1 Fcst numbers in the new table equal those presented to the Board in July.

Q2. Forecast-to-forecast EBITDA bridge [L2]

The Q1 Forecast (3+9) for FY26 EBITDA was ₹412 crore. The Q2 Forecast (6+6) is ₹381 crore. Analysis shows: Q2 actuals (July–September) came in ₹14 crore below what the Q1 forecast had projected for those months; the revised festive-season volume driver reduces H2 EBITDA by ₹22 crore; a palm-oil price increase from ₹1,05,000 to ₹1,18,000 per tonne on 9,000 tonnes of H2 consumption reduces EBITDA; a new export order is included at ₹6 crore EBITDA with 70% probability (included in the forecast at its probability-weighted value); and FX movement adds ₹2.6 crore. (a) Compute the palm-oil impact. (b) Build the bridge in the order actualisation → driver changes → new risks/opportunities → FX, and identify any unexplained residual. (c) Draft three lines of narrative for the CFO.

💡 Hint: Compute the commodity impact first, then check whether all bars sum to the total movement of −₹31 crore.

Q3. Stress scenario with contingency triggers [L3]

A Pune-based auto-components maker (FY26 revenue budget ₹2,400 crore, 62% of COGS is steel and aluminium, 30% of revenue is exported in USD) asks you to design a Board-ready scenario pack. (a) Define Base, Downside and Severe Stress cases with at least five linked assumptions each (volume, price pass-through lag, commodity prices, FX, working-capital days). (b) Explain why each is a scenario rather than a sensitivity. (c) Propose three contingency triggers with measurable thresholds and the pre-agreed management action for each. (d) Explain how you would store all three cases alongside the Q2 Fcst version without duplicating sheets.

Q4. EPM migration interview case [L3]

Your group is moving from Excel to Oracle EPBCS. The CFO wants "Budget, Q1 Fcst, Q2 Fcst" and "Base, Upside, Downside" retained, with Q1 frozen. (a) Explain how EPBCS's Scenario and Version dimensions would be configured for this requirement and how this differs from Anaplan's native version list. (b) Describe how you would lock Q1 Fcst in EPBCS and in Workday Adaptive Planning. (c) List two governance risks that remain even after moving to EPM and how to control them.

Q5. Normalising a version comparison [L2]

The FY26 Budget was prepared at ₹83.0/USD; the Q2 Forecast uses ₹87.5/USD. USD revenue is USD 120 million in the Budget and USD 112 million in the Q2 Forecast. In August, ₹46 crore of outbound freight was remapped from "Selling & distribution" to "Cost of goods sold" in the Q2 Forecast but not in the Budget. (a) Compute revenue under the Budget, the Q2 Forecast, and the Q2 Forecast at Budget FX rate; split the revenue variance into volume/price and FX effects. (b) Explain how the remap distorts a gross-margin comparison and how to restate it. (c) Propose the metadata fields that should be stored with each version record to prevent this problem.
