Key concept

Multi-Criteria Version Lookup with XLOOKUP or SUMIFS

Concept: Live value = =XLOOKUP(1,(Tbl[Version]=SelVer)*(Tbl[Acct]=$A5)*(Tbl[Month]=C$4),Tbl[Amt]) or SUMIFS with version criterion

Statement

The live value in any report cell is retrieved from a long-format table by matching every dimension, including the selected version:

=XLOOKUP(1, (Tbl[Version]=SelVer) * (Tbl[Acct]=$A5) * (Tbl[Month]=C$4), Tbl[Amt])

=SUMIFS(Tbl[Amt], Tbl[Version], SelVer, Tbl[Acct], $A5, Tbl[Month], C$4)

where Tbl is the long-format Excel Table, SelVer is the named version-selector cell, $A5 is the account code in the row label (column-anchored), C$4 is the month-end date in the header (row-anchored) and Tbl[Amt] is the amount column. Logically:

\[ V_{a,m} = \sum_{r} \text{Amt}_r \times \mathbf{1}[\text{Ver}_r = v^{*}] \times \mathbf{1}[\text{Acct}_r = a] \times \mathbf{1}[\text{Month}_r = m] \]

with \(v^{*}\) the selected version, \(a\) the account, \(m\) the month, and \(\mathbf{1}[\cdot]\) an indicator equal to 1 when the condition holds and 0 otherwise.

Explanation

How the XLOOKUP works. Each comparison (Tbl[Version]=SelVer) produces an array of TRUE/FALSE. Multiplying arrays coerces them to 1/0 and acts as a logical AND, so the product is 1 only on rows where all conditions hold. XLOOKUP(1, …) returns the amount of the first such row. It requires Excel 365/2021 (dynamic arrays); in older versions the equivalent is INDEX(Tbl[Amt], MATCH(1, (…)*(…)*(…), 0)) entered as an array formula.

How SUMIFS differs. SUMIFS adds all matching rows. If the table holds exactly one row per key, both return the same value. They diverge in three situations:

Situation XLOOKUP(1, …) SUMIFS
Key missing (e.g., no forecast for a new account) #N/A (use the if_not_found argument, e.g. 0) 0
Duplicate key (version loaded twice) First match only — understated Doubled — overstated
Data at finer grain (several cost centres per account) First cost centre only — wrong Correct aggregate
Text amounts Returns the text Ignores them

Because forecast tables usually hold multiple rows per account (cost centres, products), SUMIFS is the default for financial retrieval; XLOOKUP is preferable for retrieving attributes or rates where a unique row is guaranteed (e.g., an FX rate for a version and month) and where a missing value should be flagged rather than treated as zero.

Adding the version criterion is what makes the report version-agnostic. The same formula serves Budget, Q1F, Q2F or Actual simply by changing SelVer; a comparison column uses CmpVer. A scenario criterion Tbl[Scenario], SelScen is added the same way.

Anchoring. $A5 (column fixed) and C$4 (row fixed) allow one formula to be filled across the whole grid. The header must be a true date equal to the stored month-end; a header of 1-Oct-2025 will not match a stored 31-Oct-2025.

Performance. Array multiplication in XLOOKUP scans every row for every cell; on 200,000 rows × 1,000 cells this is slow. SUMIFS is highly optimised. For large data, aggregate in Power Query or use the Data Model.

Illustration

Tbl contains, among others:

Version Scenario Acct CostCentre Month Amt (₹ lakh)
Q1F Base 6100 CC-101 31-Oct-2025 42.0
Q1F Base 6100 CC-102 31-Oct-2025 18.5
Q2F Base 6100 CC-101 31-Oct-2025 44.2
Q2F Base 6100 CC-102 31-Oct-2025 17.9

With SelVer = "Q2F", $A5 = 6100, C$4 = 31-Oct-2025: SUMIFS returns ₹62.1 lakh (44.2 + 17.9). The XLOOKUP version returns ₹44.2 lakh — only CC-101 — understating October staff cost by ₹17.9 lakh. Switching SelVer to "Q1F" gives ₹60.5 lakh via SUMIFS, so the comparison column shows a ₹1.6 lakh adverse movement.

Connections

This is the retrieval engine for s02 (long-format layout) and s05 (comparison grid), and works together with the scenario selector in c02 and s03. It extends Topic 1's actual-pull formula (SUMIFS keyed on month-end dates) by adding a version criterion. In Week 11 the Power BI equivalent is a measure filtered by a Version slicer, and in EPM (s07) it is simply a member selection on the Version or Scenario dimension.

Practice Questions

Q1. Write version-aware formulas [L1]

Using a table Fact with columns Version, Scenario, Entity, Acct, Month and Amt, write: (a) a SUMIFS returning Q2F Downside revenue (account 4000) for entity "South" for the month in F$6; (b) an XLOOKUP returning the FX rate from a table FX (columns Version, Month, Rate) for the selected version and month, returning the text "MISSING" if not found.

Q2. Diagnose diverging results [L2]

A report shows Q2F travel expense (account 6500) for November 2025 as ₹9.6 lakh using XLOOKUP(1,…) and ₹28.8 lakh using SUMIFS. The table has 14 cost centres. (a) Explain the two possible causes of the difference. (b) Write two check formulas that distinguish between them.

💡 Hint: One cause is legitimate finer grain; the other is a duplicated load. Count rows per cost centre for the key.

Q3. Header mismatch [L1]

A colleague's report returns zero in every column for Q2F although the data exists. The header row was created as =DATE(2025,4+COLUMN()-3,1). Explain the problem and give a corrected header formula consistent with the stored month-end dates.
