Key concept

One Working Version Rule and Frozen Prior Versions

Concept: Version control rule: only one "working" version editable; all prior versions frozen and timestamped

Statement

At any point in time the planning system holds exactly one version with status Working (editable). Every other version is Locked — read-only, stored as values, and stamped with its submission timestamp, approver and control totals:

\[ \sum_{v \in V} \mathbf{1}[\text{Status}_v = \text{Working}] = 1, \qquad \text{Status}_v \in \{\text{Working}, \text{Locked}, \text{Superseded}\} \]

where \(V\) is the set of versions in the version master. A locked version \(v\) satisfies: its stored amounts, row count and control totals at any later date equal those recorded at lock time \(t_v\).

Explanation

Why only one working version? If two versions are open, inputs get entered in the wrong one, BU owners send updates to "the forecast" without knowing which, and comparisons between them shift while being reviewed. A single working version gives every contributor one unambiguous target and makes "the current forecast" well-defined. Scenarios within the working version (Base/Upside/Downside) are all editable together; the rule concerns versions (time snapshots), not scenarios.

Why freeze prior versions?

  • Comparability — forecast-to-forecast bridges (c03) start from what management was actually shown.
  • Accuracy measurement — lag-n MAPE and bias (Topic 5) require the original forecast for each month; editing a prior version retrospectively improves apparent accuracy and hides sandbagging or over-optimism.
  • Audit evidence — Ind AS 36 value-in-use, Ind AS 12 deferred-tax asset recognition and going-concern assessments rely on management-approved forecasts at a date; auditors need the frozen version. Internal financial controls (Companies Act 2013, Sec 134(5)(e) and Sec 143(3)(i)) favour preventive controls over submitted plans.
  • Governance — Board and Audit Committee minutes reference specific forecast numbers; those numbers must be reproducible.

Timestamping records when the view was formed — essential because two versions with the same name prepared a week apart can differ materially. The timestamp, submitter, approver, FX set and mapping version are stored in the version master (s02), not just in a file name.

Implementation: in Excel, a values-only snapshot plus sheet protection plus read-only storage plus control totals (s04); in EPM, approval-state locks, Anaplan edit-range settings or Adaptive's lock-version flag (s07).

Exceptions: a genuine error in a locked version is corrected by creating a new version (e.g., Q1F v2) with a change-log entry; the original stays frozen. Restated copies for mapping changes are separate, flagged versions.

Illustration

Version master for FY26 at 20 October 2025:

Version Status Cut-off Locked at Approved by Σ Amount (₹ cr) Rows
BUD Locked — 20-Mar-2025 17:42 Board 5,120.40 1,440
Q1F Locked 30-Jun-2025 18-Jul-2025 11:05 CFO 4,986.75 1,440
Q2F Working 30-Sep-2025 — — — —

A check cell =COUNTIFS(VerMaster[Status],"Working") must equal 1. On 22 October a BU head emails revised Q1F numbers. Under the rule, the request is rejected for Q1F; the revision is entered into Q2F (Working) and will appear as a driver-change bar in the Q2F vs Q1F bridge. If on 5 November the Q2F is locked and Q3F opened, the master shows Q2F Locked and Q3F Working — still exactly one.

Connections

Operationalised by s04 (copy-as-values snapshots, protection, change logs, naming) and by EPM lock features in s07. It underpins c03 (bridges from the locked prior) and the whole of Topic 5 (lag-n accuracy needs untouched forecasts). Topic 1's pitfall of overwriting actuals with forecast formulas is the same failure at month level.

Practice Questions

Q1. Status transitions [L1]

List the version-master status changes and timestamps required from the Budget approval on 20 March 2025 through the opening of the Q3F (9+3) in January 2026, assuming quarterly forecasts only, and write a check formula that fails if more than one version is Working.

Q2. Retrospective edit and accuracy [L2]

A BU's Q1F forecast for August 2025 revenue was ₹38 crore; actual was ₹31 crore. In October the BU head edited the locked Q1F August value to ₹32 crore. Compute the absolute percentage error for August before and after the edit and explain the effect on the BU's reported lag-2 accuracy and bias.

💡 Hint: Absolute percentage error uses the actual as denominator.

Q3. Two working versions case [L3]

During the December close, FP&A opens Q3F as Working while Q2F is still being revised for the Audit Committee. Describe three things that can go wrong, and propose a process and calendar that respect the one-working-version rule without delaying either deliverable.
