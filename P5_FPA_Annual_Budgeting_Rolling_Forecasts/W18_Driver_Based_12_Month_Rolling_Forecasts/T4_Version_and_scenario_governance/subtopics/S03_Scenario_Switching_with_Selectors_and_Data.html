Scenario Switching with Selectors and Data Validation

Scope: Scenario switching using selectors (CHOOSE, INDEX/XLOOKUP on scenario tables) and data validation

Why it matters

A forecast model is only as useful as the speed with which it can answer "what if?". When the CFO asks in a review meeting to see the Downside EBITDA by quarter, the analyst should change one cell and have every schedule, chart and KPI recalculate — not open a different file. Scenario switches are also the backbone of Phase 4 three-statement models, lender cases and impairment models. Done badly (hard-coded overrides, hidden helper columns, IF chains nested five deep), they are the most error-prone part of a model; done well, they are transparent, auditable and impossible to leave in the "wrong" state unnoticed.

Core notes

Anatomy of a scenario switch

Every scenario switch has four components:

  1. Selector cell — a single input (e.g., Cover!C4, named ScenarioNo or SelScen) holding a number (1, 2, 3) or a name ("Base", "Upside", "Downside").
  2. Data validation — restricts the selector to valid values only (Data → Data Validation → List, source =ScenList where ScenList is a named range or a Table column). This prevents a typo such as "Downsid" from returning zeros silently.
  3. Scenario table — assumptions laid out with one column per scenario (or rows in long format), clearly labelled, on an Inputs sheet.
  4. Live column — the column the model actually uses, populated by a selector formula that picks the active scenario's value for each assumption.
Driver Unit Live Base Upside Downside
Volume growth H2 % (formula) 8.0% 12.0% 2.0%
Realisation / kg ₹ (formula) 182 186 176
Palm-oil cost / t ₹ (formula) 1,08,000 1,02,000 1,22,000
USD/INR ₹ (formula) 86.5 85.0 89.0
Debtor days days (formula) 42 40 50

The model's calculation sheets reference only the Live column. Nothing downstream ever points at the Base/Upside/Downside columns directly.

Selector formulas

CHOOSE — selects the nth argument:

=CHOOSE(ScenarioNo, E7, F7, G7)

Simple and readable for 2–4 scenarios. Weakness: each argument is a separate reference, so adding a fourth scenario means editing every formula, and arguments can be mis-ordered row by row.

INDEX on a scenario range — selects the nth column of a contiguous block:

=INDEX($E7:$G7, 1, ScenarioNo)
=INDEX(ScenRange,,ScenarioNo)        // whole column for array-aware use

Scales to any number of scenarios (just widen the range), has one consistent formula down the column and is non-volatile.

XLOOKUP by scenario name — selects by header label:

=XLOOKUP(SelScen, $E$6:$G$6, $E7:$G7)

Robust to column re-ordering and self-documenting; the selector holds "Downside" rather than 3. Combine with MATCH in older Excel: =INDEX($E7:$G7, MATCH(SelScen,$E$6:$G$6,0)).

Long-format scenario table — if assumptions are stored as rows (Scenario, Driver, Month, Value), retrieve with SUMIFS or multi-criteria XLOOKUP (see c01):

=SUMIFS(Assump[Value], Assump[Scenario], SelScen, Assump[Driver], $A7, Assump[Month], D$5)

This is the most scalable choice when drivers vary by month.

Data validation and selector hygiene

  • Source the list from a Table column (=INDIRECT("ScenTbl[Name]") is needed inside Data Validation for structured references; alternatively define a named range ScenList pointing to the column — prefer the named range to avoid the volatile INDIRECT).
  • Set an Error Alert (Stop) so invalid entries are rejected.
  • If the selector is a name, derive the number with =MATCH(SelScen, ScenList, 0) for any CHOOSE/INDEX that needs it.
  • Display the active scenario prominently on every output page: a header formula such as ="FY26 Q2 Fcst – "&SelScen&" case" and conditional formatting (e.g., red banner when not Base).
  • Add a check cell: =IF(ISNA(MATCH(SelScen,ScenList,0)),"ERROR – invalid scenario","OK") linked to the model's master check.

Combining scenario and version selectors

In a forecast model there are typically two selectors: SelVer (Budget, Q1F, Q2F) and SelScen (Base, Upside, Downside). Retrieval from the long fact table uses both criteria. A third selector, CmpVer, drives the comparison column. Keep all selectors on one Control panel at the top of the Cover or Report sheet.

Running all scenarios at once

A switch shows one scenario at a time. For a Board page showing Base, Upside and Downside side by side, either (a) store each scenario's outputs as values in the long fact table after running it (a mini-snapshot, see s04), or (b) build the calculation so each scenario is calculated in parallel (three blocks or a dynamic array across scenarios), or (c) use a one-variable Data Table with ScenarioNo as the column input — acceptable for small models but slow and volatile (topic.md related item).

Worked illustration

H2 FY26 revenue for a foods company: H1 actual volume 52,000 t; H2 base volume = H1 × (1 + growth). With ScenarioNo = 3 (Downside), Live growth = INDEX({8%,12%,2%},1,3) = 2%, Live realisation = ₹176/kg.

\[ \text{H2 revenue} = 52{,}000 \times 1.02 \times 1{,}000 \times 176 = \text{₹}933.5 \text{ crore} \]

Switching to Base (growth 8%, ₹182/kg) gives \(52{,}000 \times 1.08 \times 1{,}000 \times 182 = ₹1{,}022.1\) crore. The same calculation cells serve both cases; only the selector changed.

Edge cases & judgement calls

  • Nested IF switches (=IF(S=1,E7,IF(S=2,F7,G7))) work but are hard to audit and extend; replace them with INDEX/XLOOKUP.
  • Manual overrides. Business users often want to override one month in one scenario. Provide an explicit override column (blank = use driver, value = override) with a flag and comment, rather than typing over formulas in the Live column.
  • Scenario-specific structure. If the Downside closes a plant (removing cost lines), keep the line in all scenarios with zero values in the Base; never insert rows that exist in one scenario only.
  • Leaving the model in a non-Base state. Add a "Saved in Base?" check and a workbook-open reminder; Board packs have gone out showing Downside numbers labelled as the forecast.
  • Volatile functions. Avoid OFFSET/INDIRECT for selectors; they recalculate on every change and obscure precedents (Topic 1, c05).
  • Sensitivity on top of scenario. A sensitivity flex (e.g., +₹2/kg) can sit on top of the Live value as =Live + SensFlex, keeping scenario and sensitivity separate (c05).

Key takeaways

  • A scenario switch = selector cell + data validation + scenario table + a single Live column used by the model.
  • CHOOSE suits a few fixed cases; INDEX/XLOOKUP scale and stay consistent; SUMIFS/multi-criteria XLOOKUP suit long-format monthly assumptions.
  • Downstream calculations reference only the Live column.
  • Validate the selector, display the active scenario on every page and link a check to the master check.
  • Use explicit override columns rather than typing over formulas.

Practice Questions

Q1. Build a three-scenario control panel [L2]

Build (describe cell by cell) a control panel with SelVer (Budget, Q1F, Q2F) and SelScen (Base, Upside, Downside) selectors using data validation, plus a scenario table for six drivers: store count, footfall per store per day, conversion %, ATV (₹), gross margin %, and rent per sq ft. Write the Live-column formula using XLOOKUP and the alternative using INDEX/MATCH. Add the check cell and the dynamic page header.

Q2. Compute outcomes under a switch [L2]

A retailer's H2 FY26 revenue = stores × footfall per store per day × conversion × ATV × 182 days. Base: 240 stores, 380 footfall, 22%, ₹1,450. Upside: 248, 400, 23%, ₹1,480. Downside: 236, 340, 20%, ₹1,400. (a) Compute H2 revenue for each scenario. (b) If ScenarioNo = 2, write the CHOOSE formula for the conversion cell and state its value. (c) Explain why changing only footfall by −10% in Base would not be a valid Downside.

💡 Hint: Multiply all five factors for each scenario; express the result in ₹ crore.

Q3. Replacing a fragile switch [L3]

A model uses =IF($C$2="Base",Inputs!E7,IF($C$2="Upside",Inputs!F7,IF($C$2="Down",Inputs!G7,0))) in 600 cells, and the selector cell is free text. Users report the model "sometimes shows zero EBITDA". Diagnose the issue, propose a replacement design, and explain how you would migrate the 600 cells safely and prove the results are unchanged in each scenario.

Q4. Side-by-side scenario page [L3]

The Board wants a single page showing FY26 revenue, EBITDA and closing cash for Base, Upside and Downside under the Q2 Fcst version. Compare three implementation options (stored scenario snapshots, parallel calculation blocks, Data Table on the scenario number) on accuracy, speed, auditability and risk of stale numbers, and recommend one.
