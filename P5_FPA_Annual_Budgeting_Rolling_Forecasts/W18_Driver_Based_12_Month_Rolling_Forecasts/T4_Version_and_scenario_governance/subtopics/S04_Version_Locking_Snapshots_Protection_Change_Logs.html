Version Locking: Snapshots, Protection, Change Logs and Naming

Scope: Version locking: copy-as-values snapshot, protected ranges, change logs and naming conventions

Why it matters

A forecast that can still change after it has been presented is not a forecast — it is a moving target. Once the Q2 Fcst has gone to the Board (and, for listed companies, informed the Audit Committee's view of guidance, going-concern and impairment), the numbers must be reproducible exactly, months or years later. Statutory auditors testing Ind AS 36 value-in-use or Ind AS 12 deferred-tax recoverability will ask for "the forecast approved by management at the reporting date"; internal auditors reviewing the planning process under the Companies Act 2013 internal financial controls (IFC) reporting framework (Sec 143(3)(i) for the auditor's report, Sec 134(5)(e) for the directors' responsibility statement) will want evidence that submitted plans cannot be silently altered. Locking is also what makes forecast-accuracy tracking (Topic 5) possible: lag-n accuracy needs the original forecast for each month, not a later edited one.

Core notes

1. Copy-as-values snapshot

The fundamental act of locking is to convert a live, formula-driven version into static values and store it separately from the working model.

Steps at submission:

  1. Run all checks (balance, version total reconciles to template, scenario actuals identical, no errors).
  2. Set selectors to the version and scenario being submitted.
  3. Export the long-format output (Version, Scenario, Entity, Account, Month, Amount) as values — via a macro, Power Query output table, or Paste Special → Values into an archive table.
  4. Stamp metadata: version code, scenario, submission timestamp, submitted by, approved by, FX rate set, mapping version, model file name/version.
  5. Save the snapshot as a read-only file in a controlled folder (SharePoint with versioning enabled), e.g. FY26_Q2F_Base_20251015_v1.xlsx, and/or append to the master fact table with Status = Locked.
  6. Record a control total (sum of Amount, sum of absolute Amount, row count) in the version master so later tampering can be detected.

The working model can then move on to the next cycle; the snapshot never changes.

2. Protected ranges

Within the live workbook, protection prevents accidental edits:

  • Sheet protection (Review → Protect Sheet) with only input cells unlocked (Format Cells → Protection → uncheck Locked). Formulas and archived blocks stay locked.
  • Allow Edit Ranges (Review → Allow Users to Edit Ranges) to let specific BU owners edit only their input block, optionally password-protected per range.
  • Workbook structure protection to stop sheets being added, deleted or renamed (which would break references).
  • SharePoint/OneDrive permissions: archive folder read-only for all but the FP&A lead; version history on.

Excel passwords are weak security — they deter accidents, not determined users. The real control is the values-only snapshot plus the control total plus file-system permissions.

3. Change logs

A change log records every change to a version after it opens and, exceptionally, any change after lock.

Log ID Date Version Scenario Entity Account Month(s) Old value New value Reason Requested by Approved by
CL-041 08-Oct-25 Q2F Base Exports 4000 Revenue Nov–Dec 25 62.0 55.5 Order deferred by customer BU Head Exports FP&A Lead
CL-042 21-Oct-25 Q2F Base Foods 5200 Packaging Jan–Mar 26 18.4 19.1 Post-lock: vendor price notice Plant Head CFO

Rules:

  • Pre-lock changes within the working window can be logged at summary level (or rely on file versioning).
  • Post-lock changes require CFO approval and normally create a new version (Q2F v2) rather than editing Q2F; the original stays in the archive.
  • The change log itself is append-only.

In EPM systems the audit trail is automatic (cell-level history); in Excel it must be designed.

4. Naming conventions

Consistent names make versions self-identifying and sortable:

<FY>_<VersionCode>_<Structure>_<Scenario>_<YYYYMMDD>_v<n>

Examples: FY26_BUD_0+12_Base_20250320_v1, FY26_Q2F_6+6_Downside_20251015_v1, FY26_Q2F_6+6_Base_20251024_v2.

Guidelines:

  • Use ISO dates (YYYYMMDD) so files sort chronologically.
  • Fix a short list of version codes (ACT, BUD, RBUD, Q1F, Q2F, Q3F, LE01…LE12) in the version master; do not allow free text.
  • Never use "final", "final2", "latest" in a name — "latest" becomes wrong the moment a new file arrives.
  • Store the components as fields in the version master; the file name is a human-readable mirror.

Version lifecycle

Status Who can edit Typical duration
Draft / Working BU owners and FP&A Submission window (5–10 working days after close)
Submitted FP&A only (review adjustments, logged) Review period (3–5 days)
Approved / Locked Nobody; values-only snapshot Permanent
Superseded Nobody Permanent (retained for accuracy tracking)

Only one version is Working at a time (c04).

Worked illustration of tamper detection

Q1F Base was locked on 18-Jul-2025 with control totals: row count 1,440; Σ Amount = ₹4,812.37 crore; Σ |Amount| = ₹9,906.20 crore. In November the internal auditor recomputes from the archive: row count 1,440; Σ Amount = ₹4,818.87 crore. The ₹6.50 crore difference proves the snapshot was edited after lock; the change log shows no entry, so the edit is unauthorised. Without control totals, the edit would be invisible.

Edge cases & judgement calls

  • Errors found after lock. If a genuine formula error is discovered (e.g., double-counted depreciation), do not fix the locked version. Create Q1F v2 with a change-log entry, inform recipients, and use v2 for future comparisons while keeping v1 for accuracy measurement — the error was part of what management believed.
  • Restatement for mapping changes. If the chart of accounts is remapped, a restated copy of old versions may be created for comparability, flagged as Restated, alongside the original.
  • Live links from snapshots. A snapshot file that still contains formulas linked to the working model is not a snapshot; it will change when the model changes. Check with Data → Edit Links and Formulas → Show Formulas.
  • Retention. Keep locked versions for at least the statutory record-retention period relevant to the company (books of account are required to be preserved for eight years under Sec 128(5) of the Companies Act 2013); forecasts supporting impairment or tax positions may need retention aligned with the assessment cycle.
  • Macro-based locking. VBA can automate snapshotting, but macros must themselves be version-controlled and tested; a broken macro that pastes the wrong selector state is worse than a manual step with a checklist.

Key takeaways

  • Locking = values-only snapshot + metadata + control totals, stored in a controlled read-only location.
  • Sheet and range protection prevent accidents; file permissions and control totals provide real assurance.
  • Post-lock changes create a new version number with a logged, approved change — never an overwrite.
  • Naming: FY_Version_Structure_Scenario_YYYYMMDD_vn, from a fixed code list; never "final" or "latest".
  • Locked originals are essential for lag-n forecast accuracy and for audit evidence under Ind AS 36 and IFC.

Practice Questions

Q1. Write the locking procedure [L2]

Draft a one-page locking SOP for the Q2 Fcst of an NSE-listed FMCG company with five BUs, covering: pre-lock checks, snapshot steps, metadata fields, control totals, storage location and permissions, naming, communication, and the procedure for a post-lock correction. Include who performs and who reviews each step.

Q2. Detecting an altered version [L2]

The Q1F Base archive for FY26 was locked with row count 2,160, Σ Amount ₹6,240.15 crore and Σ |Amount| ₹12,904.60 crore. A recomputation in December shows row count 2,160, Σ Amount ₹6,240.15 crore and Σ |Amount| ₹12,910.80 crore. (a) What does this pattern suggest about the nature of the edit? (b) Why did Σ Amount not detect it? (c) Propose an additional control total that would localise the change to an entity or account.

💡 Hint: Think about offsetting edits that keep the net sum unchanged but alter gross magnitude.

Q3. Post-lock request from a BU head [L3]

Two days after the Q2 Fcst was presented to the Audit Committee, the Exports BU head asks you to "just update" December revenue from ₹62 crore to ₹48 crore because a customer has cancelled an order. He argues it is better for the Board to see the correct number. Explain how you would handle the request, what versions would exist afterwards, how the change appears in the next forecast bridge, and whether any disclosure considerations under SEBI LODR might arise.

Q4. Naming convention clean-up [L1]

Rename the following files using the convention in the notes and identify which ones cannot be named without more information: "Budget final.xlsx", "Q2 forecast latest v3 (2).xlsx", "Downside – Oct.xlsx", "FY26 RF Jan revised CFO comments.xlsx".
