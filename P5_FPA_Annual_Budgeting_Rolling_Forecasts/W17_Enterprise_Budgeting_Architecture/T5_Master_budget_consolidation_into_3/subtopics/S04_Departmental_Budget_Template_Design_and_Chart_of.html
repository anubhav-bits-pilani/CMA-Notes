Departmental Budget Template Design and Chart-of-Accounts Mapping

Scope: Departmental template design: standard layout, input/calc/output separation, mapping to chart of accounts

Why it matters

A master budget consolidates dozens of departmental submissions — plants, sales regions, marketing, HR, IT, finance, supply chain. If each department submits in its own format, FP&A spends the budget cycle re-keying and reconciling instead of challenging. Standard templates make submissions comparable, enforce drivers, allow automated consolidation (Power Query append or EPM load), and map cleanly to the chart of accounts (CoA) so the budget can be compared with actuals from the ERP every month. Template design is a core FP&A craft skill: it is where modelling standards, governance (owners, sign-offs) and accounting knowledge meet.

Core notes

Design principles

  1. One standard layout for all departments — same tabs, same column order, same timeline (April–March, monthly), same units (₹ lakh or ₹ crore, stated once).
  2. Input / calculation / output separation — inputs in one place, formatted distinctly; calculations never hard-coded; outputs read-only.
  3. Driver-based — every material line has a driver (headcount, volume, rate, square feet, number of trips), not just a number.
  4. Mapped to the CoA — every budget line carries a GL account (or mapping code) and cost centre, so actual vs budget is automatic.
  5. Locked structure — departments can add rows only in defined input areas; formulas and mappings are protected.
  6. Self-checking — submission tab shows checks (totals tie, no blanks in mandatory fields, mapping complete) before sign-off.

Recommended tab structure

Tab Purpose Editable by department?
Cover Department, cost centre, owner, version, submission date, sign-off status Owner fields only
Instructions Definitions, deadlines, policies (FX rates, inflation, increment %) No
Assumptions (global) Central inputs pushed by FP&A — FX, inflation, GST rates, payroll statutory rates No
Inputs_Drivers Department-specific drivers: headcount roster, volumes, rates, contracts Yes
Inputs_Lines Line items: description, GL mapping code, driver link, phasing profile Yes (within table)
Calc Monthly calculations: driver × rate × phasing No
Output_Load Flat table: Entity, Cost centre, GL, Month, Amount, Version — for consolidation No
Output_Summary P&L by natural account and month, vs LE and PY No
Checks All validation flags No

Input/calc/output separation in practice

  • Inputs: coloured (commonly blue font or pale yellow fill), with data validation lists for GL codes, cost centres and phasing profiles (e.g. Flat, Seasonal_Sales, Q4_Heavy, Contract_Dates).
  • Calculations: one formula per row, consistent across columns (no column-specific overrides). Use structured tables and XLOOKUP/SUMIFS against central assumption tables.
  • Outputs: generated only from calculations; the load tab is a flat "long" table — the format Power Query appends and EPM tools load — rather than a wide month-across layout.
=XLOOKUP([@MapCode], tblCoAMap[MapCode], tblCoAMap[GL], "UNMAPPED")

=[@AnnualAmount] * XLOOKUP([@Profile], tblPhasing[Profile], tblPhasing[Apr])

Chart-of-accounts mapping

Departments think in activities ("trade fair in Delhi", "SAP licence renewal"); the ledger thinks in natural accounts (Advertisement and publicity, Software expenses) and Schedule III line items (Other expenses). The mapping hierarchy:

Level Example
Budget line (department language) "Diwali consumer promo — TV"
Mapping code / budget account MKT-ATL-TV
GL natural account 610210 Advertisement — television
Management P&L line A&P — ATL
Statutory line (Schedule III / notes) Other expenses — Advertisement and sales promotion

Maintain the mapping as a single master table owned by FP&A/financial controllership, versioned, with every new GL account added before the budget cycle opens. The same mapping drives the management vs statutory P&L reconciliation (e.g. trade schemes are an A&P cost in some management views but a revenue deduction under Ind AS 115 in the statutory P&L).

Dimensions to carry on each output row: Entity, Cost centre/Department, Account, Month, Scenario, Version, and optionally Product/Channel/Project — mirroring EPM cube dimensions.

Phasing

Annual inputs need a monthly phasing rule. Provide standard profiles (flat 1/12, sales seasonality, working days, contract-specific dates) and require departments to select one per line. Payroll and depreciation are calculated monthly, not phased.

Submission and governance features

  • Version control: file naming (FY27_AOP_MKT_v03_2026-12-15.xlsx), version field on cover, change log tab with date, changer, reason.
  • Sign-off: department head and business finance partner sign the cover; status values Draft → Submitted → Challenged → Revised → Approved.
  • Mandatory fields: a line cannot be submitted without GL mapping, cost centre, driver and phasing — enforced by the checks tab.
  • Comparatives: LE and prior-year actual by line, so challenge can focus on movements.

Illustration: check panel

Check Rule Status
All lines mapped COUNTIF(tblLines[GL],"UNMAPPED")=0 OK
Phasing sums to 100% Each profile's 12 months = 1 OK
Output total = summary total SUM(Output_Load[Amount]) = SUM(Summary) ERROR (diff ₹2.4 lakh)
No hard-codes in Calc Formula count = cell count in Calc range OK
Headcount ties to HR roster Roster FTE = HR file FTE OK

The ERROR flags a line added below the table range that was excluded from the load. Structured tables that expand automatically prevent this.

Edge cases & judgement calls

  • Over-engineering: a 25-tab template for a three-person department will be ignored. Provide a "lite" variant with the same output format.
  • Allocations: departments should budget only controllable costs; corporate allocations (IT, shared services) are applied centrally after consolidation to avoid double-counting.
  • Capex vs opex lines in the same template need distinct mapping (balance sheet accounts) and routing to the capex schedule.
  • Intercompany charges need a counterparty field for elimination.
  • Excel vs EPM: when the company uses Anaplan, Oracle EPBCS or Workday Adaptive, the template becomes a data-entry form; the same principles (drivers, mapping, validation) apply.
  • Late CoA changes mid-cycle break mappings; freeze the CoA for the budget cycle.

Key takeaways

  • One standard layout, timeline and unit across all departments.
  • Strict input/calc/output separation; outputs as a flat load table with full dimensions.
  • Every line mapped via a central, versioned CoA mapping table to GL, management and statutory lines.
  • Mandatory drivers, phasing profiles and checks before sign-off.
  • Version control and sign-off status are part of the template, not an afterthought.

Practice Questions

Q1. Mapping table design [L1]

Design a CoA mapping table for a marketing department with 12 budget lines (ATL TV, digital, BTL in-store, sampling, consumer promotions, trade schemes, agency fees, research, sponsorships, travel, salaries, software). Show the columns you would include and explain which lines map differently in the management and statutory P&L.

Q2. Template review [L2]

A plant submits a budget template where (a) electricity is entered as 12 hard-coded monthly values; (b) two new lines have no GL; (c) repair costs are phased flat though the annual shutdown is in June; (d) the total on the summary tab differs from the load tab. Write the review comments and the template changes that would prevent each issue.

💡 Hint: For each issue, decide whether the fix is a validation rule, a structural change or a governance rule.

Q3. Long vs wide output [L2]

Explain why the load tab should be a long (one row per entity-cost centre-account-month) table rather than a wide (months across) table. Describe the Power Query steps to convert a wide departmental summary into the long format and append 30 departmental files.

Q4. Template specification for HR [L3]

Specify a departmental template for HR's own budget (excluding company-wide payroll) and for the company-wide payroll submission: tabs, mandatory fields, drivers, statutory rate assumptions, phasing, checks and output dimensions. Explain how the two submissions avoid double counting.
