Subtopic note

One Sign Convention Across P&L, Scorecard, Bridges and Power BI

Scope: Consistent conventions across P&L, KPI scorecard, bridges and Power BI

Why it matters

A monthly performance pack is consumed in several forms at once: an Excel P&L with variance columns, a KPI scorecard (often RAG-rated), the EBITDA bridge, commentary slides, and a Power BI dashboard that business heads open on their phones. Each is frequently built by a different person, sometimes in a different tool. If a ₹50 lakh A&P overspend appears as "(50)" in the P&L, "+50" in the cost-centre scorecard, a green bar in the bridge and a red tile in Power BI, the CFO will spend the review meeting reconciling the pack instead of discussing the business. Consistency is a design property you build in, not something you check for at the end.

Core notes

The single-source principle

Every output should compute variances from the same data and the same attributes:

  1. One data layer (Power Query/SQL/Power BI dataset) holding actuals, budget and forecasts in presentation sign, created from ERP natural sign through the mapping table (s01).
  2. One attribute table per dimension: for accounts — line type, sign factor, Dir (better if higher), lens; for KPIs — unit, target direction, RAG thresholds.
  3. One variance definition: Fav/(Adv) = Dir × (Actual − Base); Variance % = Fav/(Adv) ÷ ABS(Base) with the n.m. rules (s04).
  4. One display standard: brackets for adverse, Fav/(Adv) or Better/(Worse) in headers, IBCS green/red for good/bad, units (₹ crore, one decimal; bps for margins).

All outputs read from the layer; none recompute variance with private logic.

Applying it to each output

P&L variance table. Columns: Budget, Actual, Var Fav/(Adv), Var %, plus PY and LE columns where relevant. Subtotal variances must equal the sum of component variances (s03 check).

KPI scorecard. KPIs carry a target direction (higher-is-better for OTIF, gross margin %; lower-is-better for DSO, attrition, cost per tonne). The scorecard shows Better/(Worse) and a RAG status computed from the same variance:

KPI Dir Target Actual Better/(Worse) RAG rule
Gross margin % +1 38.0% 37.2% (80) bps Red if worse by > 50 bps
DSO (days) −1 52 58 (6) days Red if worse by > 5 days
OTIF % +1 95.0% 96.5% 150 bps Green if better or within 50 bps

RAG should be a function of the Better/(Worse) value and thresholds — not a separately maintained judgement — so it always agrees with the sign shown.

EBITDA bridge. Every step is the signed EBITDA effect: positive (upward bar) = favourable. Revenue-side steps use Actual − Budget logic; cost and opex steps use Budget − Actual logic — which is exactly Dir × (Actual − Budget). A ₹50 lakh A&P overspend is a −50 downward red bar, matching "(50)" in the P&L.

Commentary. Words follow numbers: "A&P (₹0.5 cr) adverse due to the Diwali campaign brought forward from November; timing, reverses in Q3." Avoid "+₹0.5 cr increase in A&P" in commentary when the table shows (0.5) — readers cannot tell whether "+" means overspend or favourable.

Power BI. Implement the variance once, as a measure or calculation item:

Variance FA =
SUMX (
    VALUES ( 'Account'[Line] ),
    CALCULATE ( SELECTEDVALUE ( 'Account'[Dir] ) )
        * ( [Actual] - [Budget] )
)

Iterating over lines and applying each line's Dir before summing makes the measure correct at both line and subtotal level: summing component Fav/(Adv) variances gives the subtotal's Fav/(Adv) variance, which works because, with amounts held unsigned (costs positive), subtotals such as EBITDA are better-if-higher and component costs carry Dir −1. (If the dataset stores costs as negatives, Dir is +1 for every P&L line and the measure collapses to Actual − Budget.) With a calculation group, define items "Actual", "Budget", "Var Fav/(Adv)", "Var %" that apply to any base measure. Use conditional formatting rules on the Var Fav/(Adv) measure (green > 0, red < 0, with materiality), and a dynamic format string such as #,##0.0;(#,##0.0);"-" for brackets. For balance-sheet pages, a separate Dir column under the cash lens.

Governance artefacts

  • Convention note (one page in the pack and in the Power BI "About" page): sign rule, colours, units, n.m. rules, lens for balance sheet.
  • Attribute table under change control: new GL accounts or KPIs cannot go live without Dir and sign factor; reviewed at each close by the FP&A lead.
  • Cross-output check sheet: for a sample of lines, the variance in Excel, scorecard, bridge and Power BI is pulled side by side; any difference fails the pack release.
  • Templates: Excel templates with locked variance formulas and pre-set number formats; Power BI themes with defined good/bad colours.

Illustration: tracing one item

October A&P: budget ₹3.20 crore, actual ₹3.70 crore.

Output Correct display
P&L table Budget 3.2; Actual 3.7; Var Fav/(Adv) (0.5); Var % (15.6%)
Cost-centre scorecard Better/(Worse) (0.5), Red (exceeds ₹0.25 cr and 5%)
EBITDA bridge Within "Opex" step: −0.5 contribution, downward bar component
Power BI tile (0.5) in red, tooltip "15.6% over budget; timing"
Commentary "A&P (₹0.5 cr) adverse — Diwali campaign pulled into October; timing"

If any output shows +0.5 in green, the pack fails the consistency check.

Edge cases & judgement calls

  • Different comparison bases. AvB, AvPY and AvLE columns all use the same Dir; only the base changes. For PY comparisons, label "Growth/(Decline)" for revenue but still Better/(Worse) for costs — or use Better/(Worse) throughout for simplicity.
  • Functional reports with their own convention. Procurement or HR teams may insist on "overspend positive". Feed them from the same layer with an explicit, labelled transformation (e.g., a column "Overspend/(Saving)" = −1 × Fav/(Adv)) rather than letting them compute separately.
  • Group consolidation. Subsidiaries submitting Excel packs in their own convention must be normalised on load; validate by re-computing their EBITDA variance from submitted budget and actual.
  • External reporting. Statutory and SEBI LODR results follow Schedule III/Ind AS presentation, not variance conventions; when internal and external numbers appear side by side, label clearly.
  • Copy-paste into PowerPoint. Linked charts retain formatting; pasted images freeze it. Re-paste after every data change or use linked objects/templates.

Key takeaways

  • Build consistency in: one data layer, one attribute table, one variance definition, one display standard.
  • Scorecard RAG must be a function of the same Better/(Worse) value shown in tables.
  • Bridge steps are signed EBITDA effects, matching the P&L's Fav/(Adv) variances line for line.
  • In Power BI, apply Dir per line before aggregating, and centralise via calculation groups and format strings.
  • Release the pack only after a cross-output check on a sample of lines.

Practice Questions

Q1. Trace an item through the pack [L1]

Freight budget ₹4.6 crore, actual ₹4.1 crore, of which ₹0.6 crore is due to lower volumes. Show the correct display of this line in the P&L table, the scorecard (materiality ₹0.25 crore and 5%), the EBITDA bridge (with volume valued at unit contribution) and the commentary.

💡 Hint: Decide first whether the volume-driven freight effect sits in the Volume step or the Opex step.

Q2. Inconsistent scorecard [L2]

A scorecard shows DSO actual 58 vs target 52 with "+6" in green, gross margin 37.2% vs 38.0% with "(0.8%)" in red, and OTIF 96.5% vs 95.0% with "+1.5%" in green. Identify every inconsistency with the pack convention (Better/(Worse), bps for percentage lines, IBCS colours) and restate the scorecard.

Q3. DAX aggregation trap [L2]

A Power BI measure is written as SELECTEDVALUE('Account'[Dir]) * ([Actual] - [Budget]). Explain what it returns at the EBITDA subtotal level of a matrix and why, and how the measure should be rewritten.

Q4. Governance design [L3]

You are the new FP&A lead at a listed mid-cap with four business units, each sending its own Excel pack. Design a 90-day plan to standardise sign conventions across the group P&L, BU scorecards, the group EBITDA bridge and the Power BI dashboard. Include the artefacts, controls, owners and the tests that must pass before the first standardised pack goes to the CFO.
