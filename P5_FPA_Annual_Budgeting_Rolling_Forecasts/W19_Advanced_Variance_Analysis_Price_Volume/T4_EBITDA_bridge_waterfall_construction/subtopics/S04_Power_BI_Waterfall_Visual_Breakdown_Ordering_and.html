Subtopic note

Power BI Waterfall Visual: Breakdown, Ordering and Bridge Measures

Scope: Power BI waterfall visual with breakdown and category ordering

Why it matters

Once a company moves its monthly pack to Power BI, the EBITDA bridge becomes interactive: a regional head slices by channel, the CFO drills from total EBITDA into the SKU driving the mix bar. The native Power BI waterfall can do this, but its default behaviour — sorting bars by value, adding an automatic "Total", treating the Breakdown well as a variance-by-member tool — produces a chart that looks nothing like the agreed bridge unless you model it deliberately. Getting the ordering and step logic right is a common interview task for FP&A roles that list Power BI.

Core notes

How the native waterfall works

The waterfall visual has these field wells:

Well Purpose
Category The bars (steps) along the x-axis
Breakdown Optional field whose members' changes are shown between consecutive categories
Y-axis (Values) The measure plotted
Tooltips Extra measures shown on hover (e.g., bps, % of budget)

Without Breakdown, each Category member is one bar of height equal to the measure, stacked cumulatively from zero, and the visual appends an automatic Total bar at the end. With Breakdown, the visual treats Category as a sequence of periods/scenarios and shows, between each pair, how each Breakdown member changed — the top contributors individually and the rest grouped.

Pattern A: driver-step bridge (the standard EBITDA bridge)

  1. Create a disconnected step table (Enter Data or a DAX table):
Step SortOrder
Budget EBITDA 1
Price 2
Volume 3
Mix 4
COGS inflation 5
Efficiency 6
Opex 7
FX 8
Others 9
  1. Select the Step column → Column tools → Sort by column → SortOrder.
  2. Write one measure per driver (from the Week 11 PVM measures) and a switch measure:
Bridge Value =
VAR s = SELECTEDVALUE ( 'Bridge Step'[Step] )
RETURN
    SWITCH (
        s,
        "Budget EBITDA", [EBITDA Budget],
        "Price", [Price Effect],
        "Volume", [Volume Effect GM],
        "Mix", [Mix Effect GM],
        "COGS inflation", [COGS Inflation Effect],
        "Efficiency", [Efficiency Effect],
        "Opex", [Opex Budget] - [Opex Actual],
        "FX", [FX Effect],
        "Others", [Others Effect]
    )

with a driver measure such as:

Price Effect =
SUMX (
    VALUES ( 'Product'[SKU] ),
    ( [Actual Price] - [Budget Price] ) * [Actual Units]
)
  1. Put Step in Category and Bridge Value in Y-axis. In the visual's More options (…) → Sort axis, sort by Step ascending (not by Bridge Value, which is often the default and scrambles the bridge).
  2. The automatic total bar equals Budget + Σ steps = Actual EBITDA. Add a card or a check measure [EBITDA Actual] - ( [EBITDA Budget] + Σ steps ) on the page (or in a hidden validation page) that must show zero.
  3. Formatting: under the visual's sentiment colours set Increase (green), Decrease (red), Total (dark grey). The Budget bar is drawn as an increase from zero; to make it look like a total, many teams accept the green start bar, set the colour of the start bar via conditional formatting where supported, or switch to a certified custom visual. Rename the automatic total via the format pane if your version offers a total-label option; otherwise state "Actual EBITDA" in the subtitle or data label.

Because SELECTEDVALUE returns the step name per bar, the whole bridge responds to slicers on month, region or channel — the driver measures must respect those filters (they will, if written with SUMX over the filtered SKU table).

Pattern B: Breakdown (variance by member)

Put a Scenario field (Budget, Actual) on Category, an EBITDA-by-scenario measure on Y-axis, and SKU (or Channel, Region) on Breakdown. The visual shows Budget EBITDA, then one bar per SKU for its change from Budget to Actual, then Actual. Settings:

  • Breakdown → Max breakdowns: the number of members shown individually (default 5); the rest are grouped into an "Other" bar automatically.
  • Category order must be Budget then Actual: add a Scenario sort column.

This is not a price/volume/mix bridge — it is a "who contributed" bridge. It is valuable as a second visual next to the driver bridge, and for drill-through ("which SKUs drove the mix bar?").

Ordering and sorting traps

  • Sort axis by value is often the default; switch to the category field.
  • Text sorting puts "COGS" before "Mix" alphabetically; always use a numeric sort column.
  • Blank steps disappear; if FX is blank for a domestic-only filter, the bar vanishes and the bridge still totals correctly. Return 0 instead of BLANK() if you want a fixed layout.
  • Breakdown with period Category (e.g., Jan, Feb, Mar on Category) shows month-on-month changes by member — useful for trend walks, not for AvB.

Labels and tooltips

Data labels show the bar value; Power BI's built-in display units are thousands/millions/billions, not lakh/crore, so the cleanest approach is a display measure that divides the rupee value by 1,00,00,000 and is formatted #,##0.0. Add bps of actual revenue and % of budget EBITDA as tooltip measures:

Step bps =
DIVIDE ( [Bridge Value], [Revenue Actual] ) * 10000

Exclude the Budget step from the bps tooltip (return BLANK() for it).

When to use custom visuals

Native limitations — limited control over total labels, start-bar colour, IBCS notation and negative-crossing labels — lead many Indian corporates to use certified custom visuals (for example IBCS-oriented ones such as Zebra BI or Inforiver). They add licensing cost and governance review (data residency, certified status). The native visual with a properly designed step table is adequate for most internal packs.

Edge cases & judgement calls

  • Cost signs. If the Opex measure returns Actual − Budget, savings show as red decrease bars. Each step measure must return the EBITDA effect (topic 5).
  • Multiple scenarios. For AvPY and LE vs AOP, parameterise the base and comparator with disconnected scenario slicers rather than duplicating measures.
  • Row-level security. If RLS limits a user to one region, the bridge recalculates for that region; ensure the budget table is secured on the same dimension or the bridge will mix regional actuals with total budget.
  • Performance. SUMX over SKU × month with many scenarios can be slow; pre-aggregate unit prices/costs in the model or use aggregation tables.

Key takeaways

  • Use a disconnected step table with a numeric SortOrder and "Sort by column"; sort the visual by Step, not by value.
  • A SWITCH measure returns the right driver per step; the automatic total equals Actual EBITDA if the steps reconcile.
  • Breakdown shows member contributions between scenarios and groups the tail into "Other" via Max breakdowns.
  • Return signed EBITDA effects from every measure; colours follow sign.
  • Put a zero-residual check measure on the page.

Practice Questions

Q1. Fix a scrambled bridge [L1]

A Power BI waterfall shows the steps in the order Volume, Price, Opex, Others, Mix, FX, Budget EBITDA, COGS. List the two causes that typically produce this and the steps to fix them.

Q2. Step table and switch measure [L2]

Write the step table and the DAX SWITCH measure skeleton for a bridge with steps: LE (Sep) EBITDA, Actualisation, Price, Volume, Mix, RM inflation, Conversion efficiency, Opex, FX. Assume measures already exist for each driver. State how the visual's automatic total should relate to the October LE.

Q3. Breakdown visual design [L2]

The sales director wants to see which five channels contributed most to the change in gross margin from Budget to Actual, with the remainder grouped. Describe the Category, Breakdown and Y-axis fields, the settings you would change, and the limitation of this visual compared with a PVM driver bridge.

💡 Hint: Breakdown shows change per member between consecutive category values; it does not separate price from volume.

Q4. RLS and the bridge [L3]

After deploying the bridge with row-level security by region, the West region head reports that her bridge starts at total-company budget EBITDA of ₹420 crore but ends at West actual EBITDA of ₹96 crore, with a large negative "Volume" bar. Diagnose the cause in model terms and specify the fix.
