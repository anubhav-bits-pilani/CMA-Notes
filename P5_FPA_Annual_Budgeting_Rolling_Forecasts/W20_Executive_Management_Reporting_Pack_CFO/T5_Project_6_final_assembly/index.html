Roadmap topic: Finalizing Project 6: Complete Annual Budget, 12-Month Rolling Forecast, PVM Variance Engine, and Management Reporting Deck

Overview

Project 6 is the capstone of Phase 5. Over Weeks 17–20 the learner has built a driver-based annual operating plan, a 12-month rolling forecast with a latest estimate, a price-volume-mix variance engine and, this week, the MBR pack with KPI scorecard, commentary and business-partnering actions. This topic is about turning those parts into one deliverable that a CFO could use and an interviewer could test: an integrated, checked, documented model feeding a short executive deck with a clear storyline and decisions, presented confidently and packaged for a portfolio.

The work has three layers. The engineering layer is integration and integrity: one flow from inputs to outputs, one mapping table, an actual/forecast flag, and a checks dashboard covering balance, cash, variance and forecast consistency (s01, s02, c01–c03). The communication layer is the deck: a stand-alone summary, 5–8 core slides that move from performance to drivers to outlook, risks and decisions, and an appendix (s04, c04). The readiness layer is documentation, rehearsal and packaging: an assumptions sheet, methodology notes, version log and user guide; a question bank and sensitivity grid for Q&A; and a case write-up and demo for interviews (s03, s05, s06).

The recommended sequence is: integrate (s01), then check (s02 with c01–c03) until the master flag is green, then document (s03), then build the storyline and deck (s04 with c04), then rehearse (s05), and finally package (s06). Checking before documenting matters — documentation of a model that later changes is wasted effort — and rehearsal before packaging matters because Q&A usually exposes gaps that must be fixed in the model or deck.

For FP&A roles in India — GCCs, listed corporates and mid-market companies — this is the closest a learner can get to demonstrating the actual job: month-end actuals in, forecast rolled, variances explained, actions proposed, numbers defended. The Saturday assessment (present the MBR and recommend three margin-recovery actions to hit full-year EBITDA guidance) is a rehearsal of exactly this.

ICAEW and FAST model review practice

Model review and audit best practices (ICAEW/FAST)

The ICAEW Financial Modelling Code and the FAST Standard (Flexible, Appropriate, Structured, Transparent) set widely used conventions: separate inputs, calculations and outputs; one formula per row; consistent time axes; no hard-coded numbers in formulas; short, readable formulas; clear labelling and units; and a visible check system. Model review (or model audit) applies these through formula-consistency maps, inputs inventory, check review, scenario testing and reconciliation to source. Applying a self-review against these standards before release is the equivalent of an audit file review for a model and is a strong talking point in interviews.

Power BI publishing and sharing

Power BI publishing and sharing (→ Phase 3)

Phase 3 covered Power BI service: publishing from Desktop to a workspace, apps for distributing reports to audiences, scheduled refresh through an on-premises data gateway when sources are local files or databases, row-level security for BU-wise access, sensitivity labels, and export to PDF or PowerPoint. For Project 6, the MBR can be published as a Power BI app with pages mirroring the deck, refreshed from the model's output tables. Key controls: certified datasets as the single source of truth, a version note on the report, and reconciling Power BI totals to the Excel model before release.

Common pitfalls

Model and deck numbers not tying out

Model and deck numbers not tying out

The mistake: the deck shows EBITDA of ₹24.1 crore while the model now says ₹23.8 crore because a late journal was loaded after the charts were pasted. It happens when slides are built by copy-pasting values or images, and when the model is updated after the deck is "final". Correct treatment: link deck numbers to the model (linked tables, Power BI export, or a tie-out sheet listing every deck number with its source cell), freeze the model version used for the deck, and re-run the tie-out after any change. In review, tick every number on the summary slide back to the tie-out sheet and check the version number on the deck footer.

No documentation

No documentation, making the model unusable by others

The mistake: a working model with no assumptions sheet, no methodology note, no version log and no user guide. It happens because documentation is seen as non-urgent and the builder understands the model. Consequences: no one else can run the monthly cycle, assumptions cannot be defended months later, and interviewers cannot evaluate it quickly. Correct treatment: build the assumptions sheet with source and owner from day one, write methodology notes for judgement areas, keep a version log with reasons, and add a ReadMe tab. In review, ask a colleague to run one monthly update using only the user guide and note where they get stuck.

Overloaded deck without a storyline

Overloaded deck without a clear storyline

The mistake: 30 slides of tables in P&L order, topic titles such as "Opex analysis", and no summary or decisions page. It happens because analysts want to show all their work and fear being asked about something not in the deck. Correct treatment: write the three to five key messages first, build a summary page, limit core slides to 5–8 with action titles that tell the story when read in sequence, and move detail to a referenced appendix. In review, read only the slide titles: if they do not form a coherent argument ending in decisions, restructure.

Not ready for "what if" questions

Not preparing for "what if" questions on key assumptions

The mistake: the presenter cannot say what happens to LE EBITDA if the price increase slips a month, or if input costs rise another 5%. It happens because preparation focuses on the slides rather than the model's sensitivities. Correct treatment: rank assumptions by sensitivity, pre-compute "₹ EBITDA per unit change" for the top five, keep a scenario switch and data tables ready, and rehearse with a colleague asking challenge questions. In review, run a mock Q&A of ten "what if" questions and check that each can be answered within 30 seconds with a number and source.

Practice Questions

Q1. Final assembly review [L3]

You are reviewing a peer's Project 6 three days before presentation. Findings: the balance check fails from January by ₹2.3 crore; the EBITDA bridge has an "other" bar of ₹1.9 crore; LE on the summary slide is ₹146 crore but YTD actual plus YTG forecast in the model is ₹148.4 crore; there is no version log; the deck has 19 slides with the summary on slide 3. (a) Prioritise the findings and explain the likely cause of each numerical issue. (b) Propose the fix for each and the check or control that prevents recurrence. (c) Recommend a revised deck structure within the 1 + 5–8 + appendix format.

Q2. Margin-recovery presentation [L3]

A specialty chemicals company gave FY guidance of EBITDA ₹220 crore. After nine months, YTD EBITDA is ₹152 crore and the YTG forecast is ₹58 crore. Sensitivities: 1% price = ₹7.5 crore full-year (₹1.9 crore for Q4 alone); ₹1 per kg in key solvent = ₹1.2 crore per quarter; each day of DSO = ₹2.4 crore cash. Options: price increase of 1.5% from 1 January (60% probability of full acceptance); solvent switch saving ₹2 per kg from February; discretionary opex freeze worth ₹2.5 crore in Q4; scheme withdrawal worth ₹1.8 crore in Q4 with a volume risk of ₹0.6 crore. (a) Compute the LE, the gap to guidance and the risk-adjusted value of each option. (b) Recommend three actions with owners and timelines and draft the decisions slide. (c) Prepare answers to two likely CFO "what if" questions.

💡 Hint: Use only the Q4 portion of any full-year sensitivity when quantifying actions that start in January or February.

Q3. Documentation and handover [L2]

Your Project 6 model will be handed to a new analyst who will run the January cycle alone. Draft (a) the assumptions sheet header and five rows, (b) the methodology note headings, (c) the version log entries for AOP approval and the December roll-forward, and (d) the ten-step monthly update procedure, including the checks that must be green before release.

Q4. Portfolio and interview readiness [L2]

You have an interview for an FP&A Manager role at a Bengaluru GCC in one week. Prepare (a) the outline of a two-page case write-up for Project 6 using a fictional company, (b) an eight-minute demo plan with a live sensitivity change, and (c) answers to: "How do you know your model is right?" and "How would you put this into Power BI for 15 BU heads with access only to their own data?"
