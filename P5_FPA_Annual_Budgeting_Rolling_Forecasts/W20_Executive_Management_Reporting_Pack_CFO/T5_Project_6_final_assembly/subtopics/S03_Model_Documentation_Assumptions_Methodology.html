Subtopic note

Model Documentation: Assumptions, Methodology, Version Log, User Guide

Scope: Documentation: assumptions sheet, methodology notes, version log, user guide

Why it matters

FP&A models outlive their builders. The person who built the AOP moves teams; the CFO asks in month nine why freight was budgeted at ₹1,850 per tonne; the auditor or the board's audit committee asks how the LE was derived; an interviewer opens the portfolio file and has five minutes to understand it. Documentation is what makes a model reviewable, reusable and defensible. It also protects the analyst: a signed-off assumptions sheet with sources and owners turns a later dispute ("finance assumed too little price increase") into a factual record. For listed companies, forward-looking statements and guidance shared with analysts must be traceable to an approved basis, so documentation is also a governance control.

Core notes

Assumptions sheet

The assumptions sheet holds every input that drives the model, in one place, with metadata. A practical layout:

ID Assumption Unit AOP FY27 RF / LE Source Owner Date agreed Sensitivity rank
A01 Volume growth, core range % YoY 8.0 6.5 Sales consensus, S&OP Dec Head of Sales 12-Jan High
A02 Average price increase % 4.0 3.2 Pricing committee minutes CEO 15-Jan High
A03 Polymer cost per kg ₹ 118 124 Procurement, ICIS index Head of Procurement 10-Jan High
A04 Freight per tonne ₹ 1,850 1,960 Transporter contracts + diesel index Head of Logistics 10-Jan Medium
A05 Salary increment % 9.0 9.0 HR policy CHRO 05-Jan Medium
A06 DSO / DIO / DPO days 55/62/58 57/64/56 Credit policy, S&OP CFO 15-Jan Medium
A07 Effective tax rate % 25.17 25.17 Sec 115BAA regime Tax head — Low
A08 Interest rate on term loan % 9.25 9.40 Sanction letter, MCLR link Treasury 08-Jan Low

Rules: inputs in one colour (commonly blue font, or a pale yellow fill) and only on this sheet or clearly marked input tabs; no input repeated elsewhere; each assumption with a source and an owner; scenario columns (base, upside, downside) side by side with a selector; and a sensitivity rank so the reviewer knows which assumptions matter most.

Methodology notes

Methodology notes explain how the model computes, not what the numbers are. Cover:

  • Scope and structure: entities, BUs, periods, currency and units (₹ crore, FY ending 31 March), reporting basis (Ind AS, reported versus adjusted EBITDA).
  • Revenue build: drivers (volume × price by SKU group; or customers × ARPU), seasonality phasing method.
  • Cost build: variable cost per unit, fixed cost by cost centre, manpower (headcount × cost per FTE × joining month), depreciation method and useful lives.
  • Working capital and cash: days-based schedule, base used for each metric (revenue gross of GST or not), capex phasing.
  • Variance methodology: PVM formulas used (which order — price at actual volume, volume at budget price, mix at budget price), sign convention, treatment of new and discontinued SKUs, FX translation.
  • Forecast methodology: rolling 12-month horizon, LE definition, which drivers are re-forecast monthly.
  • KPI definitions: link to the KPI definition sheet (t2/s05) for formula, source, owner and frequency.
  • Known limitations and simplifications: for example "interest is computed on opening debt to avoid circularity", "SKU groups aggregated to 14 families".

Version log

A version log records every material change:

Version Date Author Change description Reason Reviewed by Checks status
v1.0 20-Jan A. Sharma AOP base case submitted Board approval FP&A head OK
v1.1 05-Feb A. Sharma Polymer cost updated ₹118 → ₹124 Procurement revision FP&A head OK
v2.0 10-Jan (next year) A. Sharma December actuals loaded; RF rolled to Dec-27 Monthly cycle FP&A head OK

Combine with a file naming convention, for example P6_FPA_Model_v2.0_2026-01-10.xlsx, a locked copy of each approved version, and a "changes since last version" bridge (old EBITDA → new EBITDA by change) for material updates. In SharePoint or OneDrive, version history supplements but does not replace the log because it does not record reasons.

User guide

A one- or two-page guide inside the workbook (a "ReadMe" tab) for a new user:

  1. Purpose and outputs of the model.
  2. Tab map with colour coding (inputs, calculations, outputs, checks).
  3. Monthly update steps: export TB from Tally/ERP, paste into Actuals_TB, refresh Power Query, update LastActual, review mapping exceptions, update RF drivers, check dashboard status, refresh MBR pages.
  4. How to run scenarios and sensitivities.
  5. What not to touch (formulas in calculation tabs, protected ranges).
  6. Troubleshooting: what each check failure usually means.
  7. Contacts and owner.

Formatting conventions that support documentation

Consistent colour coding (inputs, links from other sheets, formulas), units in a dedicated column, one formula per row, clear labels and named ranges for key drivers make the model largely self-documenting, reducing the amount of separate text needed.

Edge cases & judgement calls

  • Over-documentation: forty pages nobody reads is as bad as none; keep notes close to the model and focused on judgement areas and limitations.
  • Confidentiality: when packaging the model for a portfolio (s06), anonymise company data but keep the documentation structure.
  • Assumptions without owners: if no one in the business will own an assumption, mark it as a finance estimate and rank its sensitivity — these are the ones to defend in Q&A.
  • Version control in shared files: simultaneous editing in shared workbooks risks overwrites; use check-in or a single model owner for the master.
  • Audit and SOX/ICFR context: for companies with internal financial control requirements under Sec 134(5)(e) of the Companies Act, spreadsheets used in reporting need documented controls; FP&A models feeding guidance may fall in scope.

Key takeaways

  • One assumptions sheet with source, owner, date and sensitivity rank for every input.
  • Methodology notes explain calculation logic, variance conventions and limitations, not just numbers.
  • A version log with reasons, reviewer and check status, plus a bridge for material changes.
  • A ReadMe user guide with monthly update steps lets someone else run the model.
  • Formatting conventions make the model largely self-documenting.

Practice Questions

Q1. Assumptions sheet design [L1]

List the columns you would include in the Project 6 assumptions sheet and populate rows for five assumptions of a packaged-foods company (volume, price, milk cost per litre, ad spend % of revenue, DIO), with realistic Indian numbers, sources and owners.

Q2. Methodology note on PVM [L2]

Write the methodology note paragraph for your PVM engine, covering the formula order, treatment of a new SKU launched in October with no budget, sign convention and how FX is handled for export sales billed in USD.

💡 Hint: State explicitly which quantities are held at budget and which at actual for each effect.

Q3. Version bridge [L2]

Between v1.1 and v1.2 of the AOP, EBITDA fell from ₹86.0 crore to ₹81.4 crore. Changes made: polymer cost +₹4 per kg on 9,500 tonnes; price increase raised from 3.0% to 3.5% on revenue of ₹640 crore; 25 additional sales staff at ₹9 lakh each joining from July; freight unchanged. Build the version bridge and identify any unexplained difference.

Q4. User guide for a successor [L3]

You are moving to a new role next month and a junior analyst will run the monthly forecast. Draft the user guide contents and the monthly update checklist, including the five checks that must be green before the MBR is released.
