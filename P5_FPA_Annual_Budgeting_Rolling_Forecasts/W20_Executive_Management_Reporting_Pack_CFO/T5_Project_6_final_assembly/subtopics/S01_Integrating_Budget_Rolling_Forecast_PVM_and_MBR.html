Subtopic note

Integrating Budget, Rolling Forecast, PVM and MBR into One Deliverable

Scope: Integrating annual budget, rolling forecast, PVM engine and MBR pack into one coherent deliverable

Why it matters

Weeks 17–19 produced separate artefacts: a driver-based annual operating plan (AOP), a 12-month rolling forecast with a latest estimate (LE), and a price-volume-mix (PVM) variance engine. Week 20 adds the MBR pack. Each can look correct on its own while disagreeing with the others — budget revenue in the PVM tab differs from the AOP because of a stale copy, or the MBR shows an LE that does not match the forecast sheet. In a real FP&A team, the same failure shows up as a CFO asking why page 3 and page 9 of the board pack show different EBITDA. Integration means one data flow, one set of definitions and one version of each scenario, so that every number in the deck can be traced back to an input and every scenario change flows through automatically. Interviewers reviewing a portfolio model judge integration before they judge sophistication.

Core notes

Target architecture

Organise the workbook (or Excel + Power BI solution) as a flow from inputs to outputs, with no backward links:

Layer Tabs Content
Control Cover, Contents, Version log, Checks dashboard Model status, scenario selector, period selector, master error flag
Inputs Assumptions, Drivers_AOP, Drivers_RF, Price list, Headcount plan, Capex plan All hard-coded inputs, colour-coded, with source and owner
Data Actuals_TB (GL mapped), Actuals_Volume, Mapping table Monthly actuals by account, BU, SKU group; GL-to-reporting-line mapping
Calculations Revenue_build, COGS_build, Opex_build, Manpower, Capex_FA, WC_schedule, Debt_tax Monthly calculations for AOP, actuals and forecast on the same time axis
Financial statements P&L, Balance sheet, Cash flow (monthly, 24–36 columns) Integrated three statements for AOP and forecast
Analysis PVM_engine, EBITDA_bridge, Variance_AvB_PY, LE_build, KPI_scorecard, Cash_tracker Variance and KPI logic referencing the statements
Outputs MBR pages, Charts, Export to Power BI Formatted pages; no calculations other than look-ups

Key design principles: one time axis (monthly columns, FY ending 31 March, with flags for actual vs forecast); one GL mapping table used by all layers; one scenario switch; inputs never repeated; outputs never hard-coded.

Linking AOP, actuals and rolling forecast

  • Common chart of accounts and dimensions: AOP, actuals and forecast use the same reporting lines, BUs, SKU groups and customers. A mapping table maps GL accounts (from Tally or ERP trial balance exports) to reporting lines.
  • Actual/forecast flag: a row such as =IF(month<=LastActualMonth,"A","F") drives which source each month pulls from. Changing the last actual month rolls the forecast forward without rebuilding.
  • LE construction: LE = YTD actuals + YTG forecast (c03); the YTG months come from the RF driver tab.
  • 12-month rolling horizon: the RF always shows the next 12 months beyond the last actual month, crossing the financial year boundary; the AOP view is fixed at April–March.
  • Version storage: AOP (frozen), LE at each month (snapshots), and actuals stored as separate value columns, so forecast accuracy and LE movements can be analysed.

A typical selection formula on the P&L:

=IF(Flag_Act_Fcst=1, SUMIFS(Actuals_TB[Amount], Actuals_TB[Line], $A8, Actuals_TB[Month], G$5),
    INDEX(Fcst_Line_Values, MATCH($A8, Fcst_Lines, 0), MATCH(G$5, Fcst_Months, 0)))

Linking the PVM engine

The PVM engine reads budget and actual volume, net price and unit cost by SKU group (or customer) from the same input and actuals tabs, never from pasted values. Its outputs — price, volume, mix, cost and FX effects — feed the EBITDA bridge page. The engine must reconcile: AOP EBITDA plus all bridge steps equals actual (or LE) EBITDA (c02). If the engine works at contribution level, the bridge adds fixed-cost variances (manpower, other opex) from the variance tab to reach EBITDA.

Linking the MBR pack

The MBR pages (executive summary, P&L AvBvPY, segment pages, KPI scorecard, cash tracker, capex tracker, risk and action log) are output tabs reading from the analysis layer. Commentary is the only manual content; the numbers inside commentary should also be formula-driven where practical, for example ="Revenue "&TEXT(Var_Rev/1e7,"0.0")&" Cr ("&TEXT(Var_Rev_Pct,"0.0%")&") vs AOP", so text updates with the data.

If Power BI is used for the pack, load the model's output tables (a "fact" table of line × month × version × BU, plus dimension tables) via Power Query and keep the measures simple (SUM, version filters, DIVIDE for ratios) so Excel and Power BI numbers match.

Integration walk-through example

Suppose Q3 actuals are loaded (April–December). The last actual month is set to December. The flag row switches January–March to forecast; LE revenue becomes ₹842 crore (₹628 crore actual + ₹214 crore forecast). The PVM engine recalculates the YTD bridge on actuals and the FY bridge on LE. The cash tracker pulls closing cash and net debt from the balance sheet, and the executive summary headline "FY EBITDA LE ₹118 crore vs AOP ₹126 crore (−6.3%)" updates automatically. No number on any MBR page is typed.

Edge cases & judgement calls

  • Re-forecasting versus re-budgeting: the AOP stays frozen even if the business re-plans; show a "re-plan" version separately rather than overwriting it.
  • Restructured BUs mid-year: restate AOP and PY into the new structure through the mapping table, and disclose the restatement in methodology notes.
  • One-offs and normalisation: decide whether the MBR shows reported or adjusted EBITDA; keep an adjustments schedule bridging the two (relevant to SEBI-listed companies' non-GAAP presentations).
  • Model size: monthly SKU-level detail can make Excel slow; aggregate to SKU groups for the integrated model and keep SKU detail in Power Query or Power BI.
  • Circularity: interest on average debt creates a circular reference with cash; use a copy-paste macro, prior period balances, or a controlled iteration switch, and document it.

Key takeaways

  • Build one flow: inputs → data → calculations → statements → analysis → outputs, with no backward links.
  • Use one GL mapping table, one time axis and an actual/forecast flag to drive AOP, actuals and RF together.
  • The PVM engine and EBITDA bridge must read from the same inputs and reconcile to the statements.
  • MBR pages are output-only; commentary numbers should be formula-linked where possible.
  • Freeze the AOP and store LE snapshots so movements and forecast accuracy can be analysed.

Practice Questions

Q1. Architecture review [L2]

A colleague's Project 6 workbook has 31 tabs, including three copies of the price list (in AOP, RF and PVM tabs), hard-coded budget values on the MBR P&L page and an LE tab built by typing YTD actuals. Write a review note listing the integration problems and the redesign you would recommend, in priority order.

Q2. Actual/forecast switch build [L2]

Your model has monthly columns from April 2025 to March 2027 in row 5 (as month-end dates) and a named cell LastActual holding 31-Dec-2025. Write the formulas for (a) a flag row returning 1 for actual months and 0 for forecast months, (b) a P&L revenue row that pulls actuals or forecast based on the flag, and (c) a YTD actual and YTG forecast total for FY 2025-26.

💡 Hint: Combine the flag with the financial year boundary when summing YTD and YTG.

Q3. Mid-year BU restructure [L3]

In October, management merges the "Retail" and "E-commerce" BUs into "Consumer" and moves two key accounts from "Institutional" to "Consumer". Explain how you would restate AOP, PY and actuals in the integrated model, what you would disclose in the MBR methodology notes, and which checks you would add.

Q4. Interview: one version of the truth [L1]

In an interview you are asked: "How do you make sure the EBITDA on the executive summary matches the EBITDA in the bridge and the segment pages?" Give a structured answer.
