Subtopic note

Automated RAG in Excel and Power BI

Scope: Automated RAG via conditional formatting, icon sets and Power BI rules

Why it matters

Hand-coloured scorecards are a control weakness: colours get forgotten when numbers change, and they can be "managed" — an Amber quietly becomes Green before the CEO meeting. Automated RAG computes the status from actual, target, direction and band, every time, the same way. It also makes the scorecard reusable month after month with no formatting effort, and transferable to Power BI for self-service. Interviewers for FP&A and finance-analytics roles commonly test this: "build a RAG that works for both DSO and OTIF".

Core notes

Design principle: separate status from formatting

Compute the RAG status as a value in a cell or measure (e.g. "G", "A", "R" or 3/2/1), then let formatting read the status. Never let the colour be the only record of the status. Benefits: the status can be counted ("4 Reds"), filtered, exported, audited and used in commentary; formatting rules stay simple.

Excel — the parameter table

Keep one parameter table (tblKPI) with columns: KPI, Direction (HIB / LIB / RANGE), GreenThreshold, AmberThreshold, Unit, Owner. Scorecard rows look up their parameters.

Direction-aware attainment:

=IF([@Direction]="HIB", [@Actual]/[@Target], IF([@Direction]="LIB", [@Target]/[@Actual], NA()))

Status with KPI-specific thresholds (attainment basis):

=IF(ISNA([@Attain]),"n/a",IF([@Attain]>=[@GreenThr],"G",IF([@Attain]>=[@AmberThr],"A","R")))

Status with a signed gap in units (better for percentage KPIs):

=LET(d, IF([@Direction]="HIB",1,-1), gap, d*([@Actual]-[@Target]),
     IF(gap>=0,"G",IF(gap>=-[@AmberBand],"A","R")))

Range KPI (e.g. capex utilisation, band ±10% Amber limit, ±20% Red):

=LET(dev, ABS([@Actual]/[@Target]-1), IF(dev<=0.1,"G",IF(dev<=0.2,"A","R")))

Excel — conditional formatting

Three rule types, in order of robustness:

  1. Formula-based fill on the status column (recommended): select the scorecard range, New Rule → "Use a formula", e.g. =$H5="R" with red fill, =$H5="A" amber, =$H5="G" green. The $H anchors the status column so the whole row can be shaded if desired. Set "Stop if true" ordering.
  2. Icon sets on a numeric status (3/2/1) or on attainment: Home → Conditional Formatting → Icon Sets → 3 traffic lights; edit rule → type "Number", ≥ 3 green, ≥ 2 amber, else red; tick "Show Icon Only". Icon sets on attainment directly are fragile because thresholds are global for the range — use them on the computed status number instead.
  3. Data bars for attainment magnitude alongside the RAG (optional).

Use colour-blind-safe palettes (avoid pure red/green alone): add the letter or icon shape so status is readable in grayscale print.

Power BI — measures

Store KPI parameters in a dimension table DimKPI (KPI, Direction, GreenThr, AmberThr) related to a fact table FactKPI (KPI, Date, Actual, Target).

Actual = SUM ( FactKPI[Actual] )
Target = SUM ( FactKPI[Target] )

Attainment =
VAR dir = SELECTEDVALUE ( DimKPI[Direction] )
RETURN
    SWITCH ( dir,
        "HIB", DIVIDE ( [Actual], [Target] ),
        "LIB", DIVIDE ( [Target], [Actual] ),
        BLANK () )

RAG Status =
VAR att = [Attainment]
VAR g = SELECTEDVALUE ( DimKPI[GreenThr] )
VAR a = SELECTEDVALUE ( DimKPI[AmberThr] )
RETURN
    IF ( ISBLANK ( att ), BLANK (),
        IF ( att >= g, 3, IF ( att >= a, 2, 1 ) ) )

RAG Colour =
SWITCH ( [RAG Status], 3, "#2E7D32", 2, "#F9A825", 1, "#C62828", "#9E9E9E" )

Note that ratio KPIs (DSO, OTIF %) should not be summed across months; use measures that recompute from numerator and denominator (e.g. DIVIDE(SUM(OnTimeInFullLines), SUM(TotalLines))) and pick the correct Actual measure per KPI with SWITCH(SELECTEDVALUE(DimKPI[KPI]), …) or a calculation group.

Power BI — formatting rules

  • Field value: in a table/matrix, Format → Cell elements → Background colour → Format style "Field value" → based on [RAG Colour]. Most flexible; thresholds live in data, not in the visual.
  • Rules: Format style "Rules" based on [RAG Status]: if value = 3 then green, = 2 amber, = 1 red. Simple but thresholds are in the visual if applied to attainment directly — avoid that.
  • Icons: Cell elements → Icons → based on [RAG Status] rules, or a measure returning an icon via conditional formatting "Field value" with Unicode/SVG.
  • Cards and KPI visual: the built-in KPI visual shows actual vs target with direction setting ("High is good"/"Low is good") and trend; useful for headline tiles.
  • Data alerts: on dashboards in the Power BI service, data alerts on card tiles can email owners when thresholds are crossed; Power Automate can push Red statuses to Teams.

Controls and testing

  • Test each direction with boundary cases: exactly at target, exactly at Amber threshold, zero actual, blank target.
  • Lock and protect the formula columns; only Actual and Target are inputs (ideally linked from the model).
  • Add a "Status overridden?" column if management insists on manual overrides, with mandatory reason and approver — visible on the scorecard.
  • Reconcile the count of Reds/Ambers/Greens to the summary tile.

Illustration — Shakti October scorecard extract

KPI Dir. Actual Target Attain. Green ≥ Amber ≥ Status
Revenue growth YTD HIB 4.9% 9.7% 51% 100% 95% R
OTIF HIB 88% 95% 92.6% 100% 97.9% R
Fill rate HIB 93% 97% 95.9% 100% 95% A
DSO LIB 68 60 88.2% 100% 95% R
Attrition LIB 24% 18% 75.0% 100% 90% R
NPS HIB 41 45 91.1% 100% 87% A

OTIF's Amber threshold of 97.9% corresponds to the 2 pp band (93 ÷ 95); NPS's 87% to a 6-point band (39 ÷ 45) — KPI-specific bands expressed as attainment.

Edge cases & judgement calls

  • Division by zero / blanks: use IFERROR sparingly — it hides genuine errors; prefer explicit tests (IF(Target=0, …)).
  • Negative values: margin or EBITDA losses invert ratios; use the gap method for such KPIs.
  • Rounding at thresholds: 94.96% displays as 95.0% but is Red; round attainment to the displayed precision before testing, or display one more decimal.
  • Print and PDF: conditional formatting renders in PDF, but icon sets may shift in size; test the PDF export used for the Board portal.
  • Stale data: if a KPI's data has not refreshed, status should show grey "no data", not the last month's colour.

Key takeaways

  • Compute status as a value from actual, target, direction and KPI-specific thresholds; format from the status.
  • Keep thresholds and direction in a parameter table (Excel) or KPI dimension table (Power BI), not inside formatting rules.
  • Excel: formula-based conditional formatting on the status column; icon sets on a numeric status with "Show Icon Only".
  • Power BI: DAX attainment, status and colour measures; field-value formatting; recompute ratio KPIs from components.
  • Test boundaries, handle zero/negative/blank cases, and log any manual overrides.

Practice Questions

Q1. Write the formulas [L1]

In Excel, columns are: B KPI, C Direction (HIB/LIB), D Actual, E Target, F GreenThr, G AmberThr. Write formulas for H (attainment) and I (status "G"/"A"/"R") for row 5, and the three conditional formatting rules for range B5:I20 that shade the entire row by status.

Q2. Debug a scorecard [L2]

A scorecard uses a 3-traffic-light icon set applied directly to the "Actual" column for all KPIs, with thresholds ≥ 67th percentile green, ≥ 33rd percentile amber. List every problem with this design and redesign it.

💡 Hint: Consider what the percentile thresholds are calculated over, and what happens to lower-is-better KPIs.

Q3. DAX for ratio KPIs [L2]

FactOrders has columns OrderLineID, Date, RequestedDate, DeliveredDate, QtyOrdered, QtyDelivered. Write DAX measures for OTIF %, an OTIF target of 95% from DimKPI, attainment, and a status measure, ensuring OTIF is correct at month, quarter and YTD levels.

Q4. Override governance [L3]

The Sales head asks that DSO be shown Green in October because ₹18 crore of the overdue is a disputed scheme claim "that will be settled". Design the override process in the scorecard (columns, approvals, display) and write the footnote that would appear on the MBR page.
