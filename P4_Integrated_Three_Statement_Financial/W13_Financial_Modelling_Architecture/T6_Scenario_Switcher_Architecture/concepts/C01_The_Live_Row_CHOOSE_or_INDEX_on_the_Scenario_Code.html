Key concept

The Live Row: CHOOSE or INDEX on the Scenario Code

Concept: Live row: =CHOOSE(Scenario,Base_Row,Bull_Row,Bear_Row) or =INDEX(Base_Row:Bear_Row,Scenario)

Statement

For each flexed driver \(d\) and forecast period \(t\):

\[ d^{\text{Live}}_t = d^{(s)}_t, \qquad s = \text{Scenario} \in \{1, 2, 3\} \]

where \(d^{(1)}_t\), \(d^{(2)}_t\), \(d^{(3)}_t\) are the Base, Bull and Bear input values in period \(t\) and Scenario is the single named selector cell. In Excel, in the Live row cell for column H:

=CHOOSE(Scenario, H20, H21, H22)

or, with the three case rows contiguous and in code order:

=INDEX(H20:H22, Scenario)

copied identically across all forecast columns. Calculation sheets reference only the Live row.

Explanation

The Live row is the interface between scenario inputs and calculations. Its value at any moment equals the active case's value; when the selector changes, every Live row changes together, and every calculation follows. This gives the architecture three properties:

  1. Single point of control — only the selector decides the case (c02).
  2. Calculation sheets are scenario-agnostic — a revenue formula reads "Live store adds" and does not care which case is running, which keeps formulas short and consistent.
  3. Side-by-side review — all three cases' values are visible in the block for reviewers.

CHOOSE vs INDEX:

  • CHOOSE lists each case cell explicitly — clearest for Trace Precedents, robust to inserted rows inside the block (references move with the cells), but adding a fourth case requires editing every formula.
  • INDEX is compact and extends naturally if a case row is inserted within the range, but returns the wrong row silently if a non-case row (e.g., a note) is inserted inside the block, because it selects by position.

Both are non-volatile. Avoid OFFSET and INDIRECT (s03). Do not wrap the Live row in IFERROR: an invalid selector should produce a visible error that the Checks sheet catches.

Referencing: the row references are relative in the column (they must move as the formula copies across) and need no row anchoring because the formula is not copied down. Scenario is a name — effectively absolute.

Illustration

Driver block for value-format LFL (FY26E–FY28E):

Row Label FY26E FY27E FY28E
40 LFL — Base 6.0% 6.0% 5.5%
41 LFL — Bull 9.0% 8.5% 8.0%
42 LFL — Bear 1.0% 2.0% 4.0%
43 LFL — Live =CHOOSE(Scenario,H40,H41,H42) same pattern same pattern

With Scenario = 3, row 43 shows 1.0%, 2.0%, 4.0%. The revenue sheet's density row uses =G25*(1+Assumptions!H43) — the same formula regardless of case. Flipping to 2 changes density growth to 9.0%, 8.5%, 8.0% and every downstream line updates.

Practice Questions

Q1. Write the Live row [L1]

A gross margin block has Base in row 60, Bull in row 61 and Bear in row 62, with forecast years in columns H to L. Write the Live row formula for column H using CHOOSE and using INDEX, and state what each returns when Scenario = 2.

Q2. Insertion risk [L2]

A colleague inserts a "Source: concall Q2 FY26" note row between Bull and Bear in an INDEX-based block. Explain what the Live row now returns for each scenario code and how a check would detect it.

💡 Hint: INDEX selects by position within the range, so count rows after the insertion.

Q3. Defending the design [L2]

A senior banker asks why you do not simply put IF(Scenario=1,…,IF(Scenario=2,…,…)) directly inside the revenue formulas. Give three reasons the Live row approach is better.
