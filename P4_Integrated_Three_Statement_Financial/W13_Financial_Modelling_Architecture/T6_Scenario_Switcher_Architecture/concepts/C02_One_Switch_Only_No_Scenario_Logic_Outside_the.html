Key concept

One Switch Only: No Scenario Logic Outside the Driver Block

Concept: One switch only; calculations never contain IF(Scenario=…) logic outside the driver block

Statement

A model has exactly one scenario selector cell (named Scenario), and the only formulas that reference it are the Live rows (or Live scalars) inside driver blocks on the Assumptions sheet, plus labels and checks. Formally, for every calculation cell \(x\):

\[ \frac{\partial x}{\partial \text{Scenario}} \neq 0 \;\Rightarrow\; \text{the dependency runs through at least one Live driver} \]

No calculation, schedule or output formula may contain Scenario directly — whether as IF(Scenario=…), CHOOSE(Scenario,…) or any other construct.

Explanation

Scenario logic scattered across calculation sheets is the most common structural weakness in scenario models (and a topic pitfall). It arises when a builder adds a "quick" Bear adjustment inside a formula — =IF(Scenario=3, C40*0.9, C40) on the revenue sheet — instead of adding a driver row. Consequences:

  • Invisible assumptions. The Bear haircut of 10% is buried in a formula; it is not on the Assumptions sheet, not in the assumption log, and not visible in the case comparison.
  • Incoherence risk. A Bear adjustment in revenue may not be matched by corresponding cost, capex or NWC changes.
  • Inconsistent rows. Formulas with embedded IFs often differ across columns (applied to one year only), breaking "one row, one formula".
  • Audit burden. A reviewer must search every sheet for Scenario references to know what each case does.
  • Multiple switches. Sometimes a second, local selector appears (e.g., a "Capex case" cell on the PPE sheet). Users then run inconsistent combinations — Bull revenue with Base capex — without knowing it.

The rule's test is mechanical: Formulas → Name Manager → select Scenario and use Find (Ctrl+F, "Look in: Formulas", search "Scenario" across the workbook). Every hit should be on the Assumptions sheet's Live rows, the Cover/label cells, the Checks sheet or the scenario summary data table. Inquire's workbook relationship diagram and Trace Dependents from the selector cell give the same answer visually.

Legitimate exceptions, which should be documented: the header label formulas (c04), the scenario summary data table (c03) and checks of the selector value. A need to switch logic (not just values) by case — e.g., whether a project is built at all — should still be expressed as a Live driver (a 0/1 flag or a commissioning date in a driver block) that calculations reference, not as Scenario inside the calculation.

Illustration

Before (scattered logic on the Revenue and PPE sheets):

Revenue!H30 : =H28*H29*IF(Scenario=3,0.92,1)
PPE!H15     : =IF(Scenario=2,Capex_Bull,Capex_Base)

After (all case differences in driver blocks):

Assumptions row Base Bull Bear
Density growth (LFL) 6% 9% 1% (replaces the 0.92 haircut with an explicit driver)
Capex per sq ft (₹) 1,850 1,900 1,850
Live rows =CHOOSE(Scenario,…) 
Revenue!H30 : =H28*H29                    ' density row now driven by Live LFL
PPE!H15     : =Assumptions!H75*Revenue!H12 ' Live capex per sq ft x new area

The Bear case is now visible, documented and coherent with the rest of the block.

Connections

The governing rule for s01 (single selector), s02 (driver blocks) and c01 (Live row). It prevents the topic pitfall of scenario IFs scattered across calculation sheets and supports w13 t2 integrity rules (no hidden constants, one formula per row). It also underpins Week 15 stress testing, which must run through the same switch.

Practice Questions

Q1. Finding stray references [L1]

Describe two Excel methods to find every formula that references the Scenario cell, and state which locations are acceptable.

Q2. Refactor a scattered IF [L2]

A working capital sheet contains =IF(Scenario=3, Revenue*55/365, Revenue*45/365) for receivables. Refactor it into driver-block form and describe the rows you would add on the Assumptions sheet.

💡 Hint: The 55 and 45 are the case values of a DSO driver.

Q3. Logic switches by case [L2]

In the Bull case only, a new plant is built in FY28. Explain how to implement this without referencing Scenario in the PPE or revenue sheets.
