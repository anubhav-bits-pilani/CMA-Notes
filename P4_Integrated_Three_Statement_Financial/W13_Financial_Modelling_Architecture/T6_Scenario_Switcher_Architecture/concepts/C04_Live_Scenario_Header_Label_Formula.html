Key concept

Live Scenario Header Label Formula

Concept: Header label: ="Scenario: "&INDEX(Scenario_Names,Scenario)

Statement

Every output sheet displays the active scenario through a formula:

="Scenario: "&INDEX(Scenario_Names,Scenario)

where Scenario_Names is a named one-dimensional range listing the case names in code order (Base, Bull, Bear) and Scenario is the named selector cell holding the active code. The & operator concatenates the fixed text with the name returned by INDEX, so the header always matches the case actually running.

Explanation

Labels are controls, not decoration. A typed label ("Base case") is a hardcode that becomes false the moment the switch moves; a formula label cannot disagree with the model. The INDEX form is preferred because:

  • It reads the same list used by the dropdown (s01), so adding or renaming a case updates every header.
  • It is non-volatile and transparent — Trace Precedents shows the name list and the selector.
  • It fails visibly: an invalid code returns #REF!, which is itself a warning on the page.

Common extensions:

="Scenario: "&INDEX(Scenario_Names,Scenario)&" | "&Company&" ("&Basis&") | "&Units&" | v"&Model_Version
=IF(Scenario=1,"","NON-BASE CASE ACTIVE — ")&"Scenario: "&INDEX(Scenario_Names,Scenario)

The second prefixes a warning when a non-Base case is active. Pair it with conditional formatting (e.g., amber fill when Scenario<>1) for visibility.

Placement conventions: the same cell on every output sheet (e.g., B2), inside the print area and in rows repeated at the top of printed pages; chart titles linked to the header cell so charts carry the label when pasted into decks. Calculation sheets may also carry the header — it is cheap and helps reviewers — but output sheets must.

Alternatives: CHOOSE(Scenario,"Base","Bull","Bear") works but duplicates the names inside every formula — renaming a case means editing every header. XLOOKUP on a code/name table is fine in Microsoft 365. Avoid TEXT-based tricks or INDIRECT.

Illustration

Scenario list on Inputs!B5:B7 named Scenario_Names = {Base; Bull; Bear}; Scenario = Cover!E6 = 3.

Sheet Header cell B2 formula Displays
Exec Summary ="Scenario: "&INDEX(Scenario_Names,Scenario) Scenario: Bear
DCF =IF(Scenario=1,"","NON-BASE CASE ACTIVE — ")&"Scenario: "&INDEX(Scenario_Names,Scenario) NON-BASE CASE ACTIVE — Scenario: Bear
P&L ="Trent Ltd (Consolidated) / ₹ crore / Scenario: "&INDEX(Scenario_Names,Scenario) Trent Ltd (Consolidated) / ₹ crore / Scenario: Bear

Switching Scenario to 1 changes all three instantly, and the DCF warning disappears.

Connections

The labelling mechanism of s07, using the name list created with the selector in s01. It supports the topic pitfall on files circulated with Bull/Bear active, the Cover conventions from w13 t1 s05 (company, basis, units, version) and the ICAEW Code principle of designing for the end user. In Power BI, the equivalent is a card showing the selected value of a scenario slicer.

Practice Questions

Q1. Write the header [L1]

Write a header formula that displays "Pidilite Industries (Consolidated) | ₹ crore | Scenario: Bull | v2.3" using named ranges for every variable element.

Q2. Why not type it? [L1]

Explain why a typed header is a control failure, with an example of how it leads to a misreported valuation.

Q3. Renaming a case [L2]

The team renames "Bear" to "Downside — demand slowdown". Compare the work required and the error risk under an INDEX-based header versus a CHOOSE-based header with the names typed inside each formula.
