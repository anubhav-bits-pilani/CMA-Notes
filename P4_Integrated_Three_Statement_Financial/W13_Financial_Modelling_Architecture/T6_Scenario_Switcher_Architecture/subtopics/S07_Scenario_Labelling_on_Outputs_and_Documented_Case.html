Subtopic note

Scenario Labelling on Outputs and Documented Case Rationale

Scope: Scenario labelling on every output page and documented rationale per case

Why it matters

Outputs travel. A DCF summary is pasted into an IC memo, a P&L page is printed for a board pack, a chart is dropped into a lender presentation. Once separated from the model, nothing shows which case produced the numbers unless the page itself says so. Misread scenarios are a classic failure in practice: a Bear-case valuation quoted as Base in a fairness opinion discussion, or a Bull-case budget circulated as the plan. Labelling every output page with a live scenario header, and documenting the rationale for every case, closes the gap. It is also a requirement in model-review checklists (ICAEW Code: designed for the end user; outputs clearly labelled) and a basic expectation of auditors and rating agencies reviewing management forecasts — for example in Ind AS 36 impairment testing, where cash-flow projections must be based on reasonable and supportable assumptions that the auditor will trace.

Core notes

Live scenario header

Every output sheet (Executive Summary, P&L, BS, CFS, DCF, Comps, charts) carries a header formula in a consistent location, typically cell B2 or the sheet title row:

="Scenario: "&INDEX(Scenario_Names,Scenario)

Extend it to include units and version so that a printed page is self-describing:

="Trent Ltd (Consolidated) | ₹ crore | Scenario: "&INDEX(Scenario_Names,Scenario)&" | v"&Model_Version

Rules:

  • Formula, not text. A typed "Base case" header will be wrong the moment someone flips the switch.
  • Same position on every sheet, so reviewers know where to look and print areas include it.
  • Print headers. Excel's Page Setup header/footer cannot contain formulas directly; place the label inside the print area (top rows) and set those rows to repeat at top (Page Layout → Print Titles).
  • Conditional formatting. Colour the header differently when a non-Base case is active (e.g., amber fill for Bull/Bear) — a visual warning before printing or circulating (connects to the "left Bear active" pitfall).
  • Charts. Use a chart title linked to a cell (select the title, type = and click the header cell) so charts pasted elsewhere carry the scenario name.

Labelling the scenario summary

The data-table summary (s06) shows all cases; label it "All scenarios" and show the active case separately so readers do not confuse the live pages with the summary. If static snapshots are used, include the capture timestamp and version.

Documented rationale per case

Each case needs a written rationale stored in the model, not in an email. A "Scenario notes" block on the Assumptions sheet or a dedicated sheet holds:

Field Base Bull Bear
One-line narrative Guidance-consistent growth; stable margins Faster rollout and LFL; mild margin gain Urban demand slowdown FY27–FY28; slower openings; markdowns
Key driver differences vs Base — Store adds +25%, LFL +4 pp, GM +100 bps Store adds −33%, LFL −6 pp, GM −150 bps, DIO +10
Evidence / sources FY26 Q2 concall guidance; 5-year averages Peer best-in-class performance; FY23 rebound FY20–FY21 and FY17 analogues; industry slowdown data
Management response assumed — Additional DC capex Capex deferral, A&P trimmed
Owner and date Analyst, date Analyst, date Analyst, date
Status Approved / Draft Approved / Draft Approved / Draft

This connects to the week's assumption log (each driver with source and rationale): the log documents driver values; the scenario notes document why the set of values hangs together.

Change log for scenarios

When a case is revised (e.g., Bear store adds changed after a new concall), record it in the Cover change log with the version number, date, what changed and why. Over a deal or budget cycle, the change log answers the inevitable question, "why is Bear EV ₹2,000 crore higher than last month?"

Checks tied to labelling

  • Base active on save/circulation: a check =--(Scenario<>1) shown on the Cover as "Non-Base case active"; some teams add a workbook-open message or a pre-save macro reminder.
  • All output sheets labelled: a simple audit — every output sheet's header cell contains "Scenario:" — can be tested with =COUNTIF(Header_Cells,"*Scenario:*")=Output_Sheet_Count where Header_Cells is a list of links to each sheet's header.
  • Rationale completeness: every case has a non-blank narrative and status: =COUNTBLANK(Scenario_Notes_Range)=0.

FP&A and reporting context

In budget packs, label versions as well as scenarios (Budget v3 — Base; Reforecast Q2 — Downside). In Power BI, add a scenario slicer and display the selected scenario in a card on every page; never publish a report where the scenario is implicit.

Edge cases & judgement calls

  • Hidden scenario. If a fourth "Management" case exists but is not presented, ensure outputs never default to it silently; exclude it from the dropdown when circulating externally.
  • Mixed-case pages. A page that intentionally shows Base P&L with Bear valuation must label both explicitly — generally avoid such pages.
  • Exported PDFs. Export after checking the header; include a footer with file name and version.
  • Confidentiality. Scenario notes may contain sensitive judgements (e.g., about management credibility); decide whether to strip them before external circulation, but keep them in the master file.
  • Rationale drift. Narratives must be updated when driver values change; a stale narrative is worse than none because it misleads reviewers.

Key takeaways

  • Every output sheet carries a live, formula-driven scenario header in a consistent location.
  • Include entity basis, units and version in the header so printed pages are self-describing.
  • Link chart titles to header cells; use conditional formatting to flag non-Base cases.
  • Document each case's narrative, key differences, evidence, management response, owner and status in the model.
  • Log scenario revisions in the Cover change log.
  • Add checks for non-Base active, missing headers and incomplete rationale.

Practice Questions

Q1. Header formula [L1]

Write a header formula for a DCF sheet that shows company name, entity basis, units, scenario name and model version, using named ranges Company, Basis, Units, Scenario_Names, Scenario and Model_Version.

Q2. Print-ready labelling [L2]

A board member printed the P&L page and the scenario label did not appear. Explain the likely cause and the Page Setup and layout changes that guarantee the label prints on every page.

💡 Hint: Consider where the label sits relative to the print area and repeated title rows.

Q3. Rationale table [L2]

Draft the scenario rationale table for a Pidilite model with Base, Bull and Bear (input-cost spike) cases, including narrative, key driver differences, evidence and management response.

Q4. Review case [L3]

An IC paper quotes a Trent value per share that matches the model's Bull case while the text calls it "our base case". Describe the controls (labelling, checks, change log, circulation process) that would have prevented this, and how you would investigate which version and case produced the number.
