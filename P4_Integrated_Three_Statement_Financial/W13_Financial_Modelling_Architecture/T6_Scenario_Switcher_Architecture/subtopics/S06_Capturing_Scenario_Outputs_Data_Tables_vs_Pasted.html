Subtopic note

Capturing Scenario Outputs: Data Tables vs Pasted Static Values

Scope: Scenario output capture: summary table via data table on the switch cell vs pasted static outputs

Why it matters

The scenario switch runs one case at a time, but decision-makers want to see all cases side by side: EV, share price, EBITDA, net debt, covenant headroom for Base, Bull and Bear in one table. There are two ways to produce it. A data table on the switch cell recalculates the model for each case and populates the table live. Pasted static outputs (copying values after flipping the switch manually, or via a macro) freeze results. Live tables never go stale but cost calculation time and have Excel constraints; static pastes are fast but go out of date the moment an assumption changes — a frequent source of inconsistency between a model's summary page and its live outputs in IC papers and lender decks.

Core notes

Live capture: one-variable data table on the switch

Excel's What-If Analysis → Data Table substitutes each value in a list into an input cell and records the resulting outputs. For scenarios:

  1. On the same sheet as the selector cell (Excel requires the data table's input cell to be on the same sheet as the table), lay out a column of codes 1, 2, 3.
  2. In the row above the first code, to the right, link the outputs: =EV, =Equity_Value_per_Share, =EBITDA_FY27, =Net_Debt_FY27, =Min_DSCR.
  3. Select the whole block (codes column plus output row and the empty grid).
  4. Data → What-If Analysis → Data Table → Column input cell = the Scenario cell. Leave Row input cell blank.
Code Scenario EV (₹ crore) Value per share (₹) FY27 EBITDA (₹ crore) FY27 net debt (₹ crore)
=EV =Price =EBITDA_FY27 =Net_Debt_FY27
1 Base {TABLE} {TABLE} {TABLE} {TABLE}
2 Bull {TABLE} {TABLE} {TABLE} {TABLE}
3 Bear {TABLE} {TABLE} {TABLE} {TABLE}

The Scenario name column is a label (=INDEX(Scenario_Names, code)), not part of the data table.

Properties:

  • Live — every assumption change updates all cases.
  • Constraint — the input cell (Scenario) must be on the table's sheet; if the selector is on Inputs, place the scenario summary on Inputs, or move the selector to the Cover and put the summary there (the topic pitfall on cross-sheet data tables).
  • Calculation cost — each data table cell triggers a full model recalculation; with many tables and circularity, models become slow. Many builders set Calculation to "Automatic except for data tables" and press F9 to refresh — then the Cover must warn that the summary may be stale.
  • Circularity — data tables and iterative calculation (interest on average debt) interact badly; use the circularity breaker (Circ) or a copy-paste macro approach for the debt interest loop (Week 15).
  • Auditability — the {=TABLE(,Scenario)} array cannot be edited cell by cell; reviewers need to know it is a data table.

Static capture: pasted values

Flip the switch to each case, copy outputs, paste as values into a summary table. Usually automated with a short macro that loops the scenario, recalculates and writes values.

  • Pros: no calculation overhead; works with circular models; outputs can be archived with a timestamp.
  • Cons: goes stale silently when any assumption changes; manual versions are error-prone (wrong case active when pasting); values are hardcodes (blue by convention) in an output area.

Controls if you use static capture:

  • Stamp each block with the date/time and model version when captured.
  • Add a staleness check: compare the static value for the currently active case with the live output:
Stale_Flag = --(ABS(INDEX(Static_EV_Col, Scenario) - EV) > 0.5)

and feed it to the Checks sheet so the master flag on the Cover warns when the snapshot no longer matches. - Colour the static block as hardcoded inputs and label it "Snapshot — values as at [timestamp]".

Choosing between them

Situation Preferred capture
Small–medium model, no circularity, live decision work Data table
Large model, slow recalculation, circular interest Macro-driven static snapshot with staleness check
Final IC/lender pack Static snapshot archived with the version, plus live table in the model
Rolling forecasts in FP&A Live table or Power BI reading exported scenario outputs

What to capture

A scenario summary typically includes: revenue and EBITDA (selected years and CAGR), EBITDA margin, PAT, capex, FCF, net debt and leverage (net debt ÷ EBITDA), minimum covenant headroom (DSCR, interest cover), DCF EV, equity value per share and implied multiples. Keep the same output list for every case and every version, so comparisons over time are meaningful.

Edge cases & judgement calls

  • Two-way tables. A two-variable data table with Scenario on one axis and, for example, WACC on the other gives a scenario × sensitivity grid; both input cells must be on the same sheet as the table.
  • Multiple summary tables. Each data table multiplies recalculation; consolidate outputs into one table rather than several.
  • Excel Scenario Manager. Built-in Scenario Manager stores sets of input values and can produce a summary report; it is opaque (values hidden in the tool), limited to 32 changing cells and poorly auditable — not recommended for institutional models.
  • Power BI. For dashboards, export each case's outputs to a table (or use Power BI what-if parameters on a simplified driver model) rather than linking to the live case.
  • Rounding and units. Keep the summary in ₹ crore with consistent decimals; per-share values in ₹ with two decimals.

Key takeaways

  • A one-variable data table with Scenario as the column input cell captures all cases live.
  • The data table must sit on the same sheet as the selector cell.
  • Data tables cost recalculation time and interact badly with circularity — manage calculation mode and warn users.
  • Static snapshots are fast but go stale; timestamp them and add a staleness check.
  • Capture a consistent set of outputs across cases and versions.
  • Avoid Excel Scenario Manager for institutional models.

Practice Questions

Q1. Build the summary table [L1]

Write the step-by-step procedure to build a scenario summary data table returning EV, value per share, FY27 EBITDA, FY27 net debt and minimum DSCR for three cases, including where the table must be placed and how the scenario names are displayed.

Q2. Staleness check [L2]

Your model uses a macro-captured static summary. Write the check formulas that flag (a) a mismatch between the static value and the live output for the active case, for EV and FY27 EBITDA, and (b) a snapshot older than the last change to the Assumptions sheet version number. Explain how both reach the Cover.

💡 Hint: Compare INDEX of the snapshot column at the active code with the live output, and compare version stamps.

Q3. Choosing capture method [L2]

A Trent model has iterative interest calculation, 45 sheets and a full recalculation time of six seconds. The IC wants a live scenario table during a meeting. Recommend a capture approach and the controls you would put in place.

Q4. Scenario × WACC grid [L3]

Design a two-variable data table showing equity value per share for three scenarios against WACC of 10.5%, 11.0%, 11.5%, 12.0% and 12.5%. Specify the layout, input cells, sheet placement constraints and the calculation-mode setting, and explain how you would label the output to prevent misreading.
