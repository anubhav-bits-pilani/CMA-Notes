Subtopic note

Scenario Driver Blocks: Base, Bull, Bear Rows and the Live Row

Scope: Driver blocks: Base/Bull/Bear rows per driver per year plus one "Live" row feeding calculations

Why it matters

The selector cell decides which case runs; driver blocks hold what each case assumes. A driver block is a small, standardised group of rows on the Assumptions sheet — one row per scenario per driver, with values for every forecast year, and one Live row that picks the active scenario's values. Calculations reference only the Live row. This structure keeps all scenario logic in one place (the driver block), makes every case's assumptions visible side-by-side for review, and means calculation sheets never need to know that scenarios exist. It is the standard layout in bank and Big 4 models and is what a model auditor expects to find.

Core notes

Block layout

Each driver occupies five rows (for three cases), all on the same timeline columns as every other sheet:

Row Label Units Const FY26E FY27E FY28E FY29E FY30E
20 Zudio gross store additions — Base stores 200 190 180 170 160
21 Zudio gross store additions — Bull stores 240 230 220 210 200
22 Zudio gross store additions — Bear stores 140 120 110 100 100
23 Zudio gross store additions — Live stores formula formula formula formula formula
24 (blank separator)

Conventions:

  • Inputs in blue on the Base/Bull/Bear rows; the Live row in black (same-sheet formula) and visually distinguished (bold label, light shading, or a "Live" tag in the label column).
  • Same column structure as all calculation sheets (label, units, constant column, then aligned timeline), so the calculation sheet can link the Live row with a column-consistent reference (w13 t1 s04, c03).
  • Live row formula identical across the row (w13 t2 c01):
H23: =CHOOSE(Scenario, H20, H21, H22)

copied to L23. Scenario is the named selector cell (s01).

Historical columns

Driver blocks usually start at the first forecast year. If the block spans the full timeline for column consistency, historical columns are left blank or show the historical value (computed on the Historicals sheet) in the Live row only, using a timeline flag:

=IF(Forecast_Flag=1, CHOOSE(Scenario, H20, H21, H22), Hist_Value)

Prefer keeping historicals out of the driver block entirely and letting the calculation row switch with the flag — the driver block then contains only forecast assumptions.

Grouping and ordering drivers

Organise the Assumptions sheet by driver category, each with its block:

  1. Macro: CPI, nominal GDP, USD/INR, commodity prices (VAM, cotton).
  2. Revenue: UVG, price, store additions, new-store area, LFL, maturity curve parameters.
  3. Costs: gross margin parameters (pass-through ratios), wage increments, A&P %, opex inflation.
  4. Capital: capex per store or per tonne, maintenance capex, project dates.
  5. Working capital: DSO, DIO, DPO.
  6. Financing (often not scenario-flexed): interest rates, dividend payout.

Not every driver must be flexed. Drivers that do not vary by case (e.g., tax rate) have a single input row — no block — to avoid clutter and the false impression that they are scenario-dependent.

Single-value vs time-series drivers

Some scenario inputs are scalars (e.g., practical maximum utilisation, terminal growth if scenario-dependent). Use a compact block with the three values in the constant column and a Live cell:

Label Base Bull Bear Live
Maturity curve age-0 factor 65% 70% 55% =CHOOSE(Scenario, E31, F31, G31)

Name the Live scalar (e.g., Age0_Factor) and reference it by name (w13 t1 s07).

Bull/Bear as deltas vs absolute values

Two input styles exist:

  • Absolute values for each case (as above). Transparent; reviewers see exact values.
  • Base plus delta: Bull row = Base + Bull delta; Bear row = Base − Bear delta, with deltas as inputs. Useful when Base is updated frequently (rolling forecasts) and the spread between cases should persist. The Bull/Bear rows then become formulas (black), and the delta rows are inputs (blue).

Choose one style per model and document it. Mixing styles (some drivers absolute, some deltas) is a common source of review confusion.

Checks within the block

  • Ordering check where economically required (e.g., Bull store adds ≥ Base ≥ Bear) — as a warning, since some drivers legitimately invert (Bear capex may be higher for maintenance, or Bear DPO lower).
  • Completeness: no blank cells in any case row across forecast years: =COUNTBLANK(H20:L22)=0.
  • Live row = selected case: =SUMPRODUCT(ABS(H23:L23-CHOOSE(Scenario,H20:L20,H21:L21,H22:L22)))<0.0001 (a belt-and-braces check that nobody has overwritten the Live row with a hardcode).

Edge cases & judgement calls

  • Many segments. With Trent's formats or Pidilite's segments, the block count grows quickly (drivers × segments). Keep one block per driver per segment, grouped by segment, with consistent ordering; avoid collapsing segments into a single row with mixed meaning.
  • Driver blocks on calculation sheets. Do not place Base/Bull/Bear rows on calculation sheets "for convenience"; they belong on Assumptions to keep inputs separate (FAST/ICAEW).
  • Overrides. A one-year management override should be entered in the relevant case row with a comment, not typed over the Live row.
  • Scenario-dependent timing. Project commissioning dates that vary by case are scalar inputs in a block; downstream flags (commissioning flag by year) are calculations referencing the Live date.
  • Large models. If the Assumptions sheet becomes unwieldy, split by category (Assumptions_Revenue, Assumptions_Cost), but keep the selector single.

Key takeaways

  • Each flexed driver has Base, Bull and Bear rows plus one Live row on the Assumptions sheet.
  • The Live row uses one consistent selection formula across the timeline; calculations reference only Live rows.
  • Inputs blue, Live row black and visually tagged; same column structure as calc sheets.
  • Do not create blocks for drivers that do not vary by case.
  • Choose absolute values or base-plus-delta consistently, and document it.
  • Add completeness and Live-row integrity checks.

Practice Questions

Q1. Build a block [L1]

Lay out a driver block for Pidilite C&B UVG for FY26–FY30 with Base 9%, 9%, 8%, 8%, 8%; Bull 12%, 11%, 10%, 10%, 9%; Bear 5%, 6%, 6%, 7%, 7%. Write the Live row formula for the first forecast column and explain which parts of the reference must be absolute, if any.

Q2. Delta-style block [L2]

Redesign the Q1 block in base-plus-delta style with a Bull delta of +2.5 percentage points and a Bear delta of −3.0 percentage points (both constant over time). State which cells are inputs and which are formulas, and how the colour convention applies.

💡 Hint: The deltas can sit in the constant column and be referenced with a column-anchored address.

Q3. Live-row integrity check [L2]

A reviewer suspects someone typed 10% over one cell of a Live row. Write a check formula that detects any mismatch between the Live row and the selected scenario row across all forecast years, and explain how you would surface it on the Cover.

Q4. Organising a multi-segment Assumptions sheet [L3]

For a Trent model with three formats and drivers for store additions, new-store area, LFL, gross margin, staff per store, store opex per sq ft, capex per sq ft and inventory days, design the Assumptions sheet structure (ordering, grouping, block sizes, naming) and estimate how many rows it needs. Explain how you would keep it navigable.
