Subtopic note

Scenario Selection Functions: CHOOSE, INDEX, XLOOKUP, SWITCH

Scope: Selection functions: CHOOSE, INDEX, XLOOKUP, SWITCH; avoid volatile OFFSET/INDIRECT

Why it matters

The Live row formula is copied across every forecast column of every flexed driver — often several hundred cells in a full model. The function chosen for it affects transparency (can a reviewer see which rows feed it?), robustness (does it break when rows are inserted?), performance (does it recalculate on every keystroke?) and auditability (do Trace Precedents and Inquire show the true dependencies?). Four non-volatile functions do the job well; two volatile functions, OFFSET and INDIRECT, are common in older models and should be avoided. Model-audit firms routinely flag OFFSET/INDIRECT-based scenario switches as a high-risk finding.

Core notes

CHOOSE

=CHOOSE(Scenario, H20, H21, H22)
  • Returns the nth argument, n = Scenario.
  • Pros: most readable; each case's cell is an explicit precedent, so Trace Precedents shows exactly three arrows; robust to row insertions (references adjust); non-volatile.
  • Cons: arguments must be listed individually (unwieldy beyond five or six cases); adding a case requires editing every Live formula; if Scenario exceeds the number of arguments, returns #VALUE!.
  • Best for: three to five cases — the standard choice.

INDEX

=INDEX(H20:H22, Scenario)
  • Returns the nth cell of a contiguous range.
  • Pros: compact; adding a case means inserting a row inside the range (references expand); non-volatile; returns a reference, so it can be used inside other range functions.
  • Cons: relies on the block's rows being contiguous and in the code order — a row inserted inside the block (e.g., a note row) shifts which case is returned without error. Trace Precedents shows the whole range, not the selected cell.
  • Best for: larger case counts and when blocks are strictly standardised.

XLOOKUP

=XLOOKUP(Scenario, $C20:$C22, H20:H22)

where column C holds the code for each case row (1, 2, 3).

  • Pros: looks up by code, not by position — row order inside the block no longer matters; explicit not-found handling (if_not_found argument) can return an error message; non-volatile; available in Microsoft 365 and Excel 2021+.
  • Cons: needs a code column in every block; not available in Excel 2016/2019 — a real issue if counterparties (lenders, auditors) use older versions, where it returns #NAME?. INDEX/MATCH is the backward-compatible equivalent: =INDEX(H20:H22, MATCH(Scenario, $C20:$C22, 0)).
  • Best for: models with many cases or where blocks may be reordered.

SWITCH

=SWITCH(Scenario, 1, H20, 2, H21, 3, H22, NA())
  • Evaluates Scenario against listed values and returns the matching result; a default (here NA()) handles invalid codes.
  • Pros: explicit value-to-result mapping; built-in default; non-volatile; works with text codes (SWITCH(Scenario_Name,"Base",…)).
  • Cons: longer than CHOOSE; Excel 2019+ only; text codes are fragile.
  • Best for: when codes are non-contiguous (e.g., 1, 2, 3, 9 = "Lender") or a default is required.

Why avoid OFFSET and INDIRECT

=OFFSET(H19, Scenario, 0)                 ' volatile
=INDIRECT("H"&(19+Scenario))              ' volatile and text-based
  • Volatility. Both recalculate on every change anywhere in the workbook, not just when their precedents change. Hundreds of volatile cells, plus everything that depends on them, slow large models and data tables markedly.
  • Opacity. Trace Precedents cannot follow OFFSET's target or INDIRECT's text address; Inquire and model-audit tools may miss the dependency. A reviewer cannot see which cell feeds the result.
  • Fragility. INDIRECT uses text addresses that do not update when rows or columns are inserted or sheets renamed — a classic silent error. OFFSET depends on a fixed row count from an anchor; inserting a row inside the block shifts results.
  • Standards. FAST and the ICAEW Code discourage volatile and text-built references; Big 4 model review checklists flag them.

Selecting whole rows (dynamic arrays)

In Microsoft 365 a single formula can return the whole Live row: =CHOOSE(Scenario, H20:L20, H21:L21, H22:L22) spills across. This reduces formula count but breaks the "one formula per cell, identical across the row" visual audit and can confuse users of older versions. Most institutional models still use per-cell formulas.

Edge cases & judgement calls

  • Invalid selector values. CHOOSE and INDEX error on out-of-range codes (#VALUE!, #REF!); this is desirable because it is visible. Do not wrap Live formulas in IFERROR — it would hide an invalid selector (w13 t2 c03).
  • Mixed functions. Use one selection function throughout the model; mixing CHOOSE in some blocks and INDEX in others confuses reviewers.
  • Performance. In very large models, the selection function is rarely the bottleneck unless volatile; data tables over the scenario switch are a bigger cost (s06).
  • Legacy models. When inheriting an OFFSET-based switch, replace it block by block and reconcile outputs before and after the change for each scenario.

Key takeaways

  • CHOOSE is the default Live-row function for three to five cases: readable and non-volatile.
  • INDEX is compact but depends on row order; XLOOKUP and INDEX/MATCH select by code.
  • SWITCH maps explicit codes and provides a default for invalid values.
  • OFFSET and INDIRECT are volatile, opaque to auditing tools and fragile to insertions — avoid them.
  • Never wrap selection formulas in IFERROR; let invalid selectors surface.
  • Use one selection function consistently across the model.

Practice Questions

Q1. Rewrite a volatile switch [L1]

A legacy model uses =OFFSET(Assumptions!G40,Scenario,0) in every Live cell. Rewrite it using CHOOSE and using INDEX, and explain two risks of the original formula.

Q2. Row insertion test [L2]

In a block where Base, Bull and Bear are rows 50–52 and the Live row is 53, a user inserts a comment row between Base and Bull. Explain what happens to CHOOSE-, INDEX-, XLOOKUP- and INDIRECT-based Live rows, and which remain correct.

💡 Hint: Consider whether each function tracks cell references, ranges, codes or text addresses.

Q3. Version compatibility [L2]

Your client's lender uses Excel 2016. Your model uses XLOOKUP for Live rows and SWITCH for a label. Describe what the lender will see and how you would redesign the formulas for compatibility while preserving lookup-by-code.

Q4. Interview — choose a function [L1]

An interviewer asks: "Which function do you use for scenario switches, and why not OFFSET?" Prepare a 60-second answer.
