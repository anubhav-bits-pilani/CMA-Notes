Subtopic note

Version Control, File Naming and Transparent Protection

Scope: Version control, file naming, sheet protection without hidden logic or hidden rows

Why it matters

A financial model is circulated, edited, emailed, uploaded to data rooms and quoted in board papers. Without version control, nobody can say which number came from which file; without a naming convention, "Trent_model_final_FINAL2_revised.xlsx" is the file the IC approved; without protection, an output gets overtyped; and with the wrong kind of protection — hidden rows, very-hidden sheets, locked formulas that cannot be inspected — the model becomes a black box that no auditor will rely on. ICAEW's Code and the FAST Standard both insist that protection prevents accidental change but never hides logic. In Indian listed-company work there is a further reason: models containing unpublished price-sensitive information fall under SEBI (Prohibition of Insider Trading) Regulations, 2015, and access must be traceable.

Core notes

File naming convention

A good name sorts chronologically and identifies content without opening the file:

<Company>_<Purpose>_<Basis>_<YYYYMMDD>_v<major>.<minor>_<status>_<initials>.xlsx
TRENT_DCF_Consol_20251121_v1.3_Draft_AK.xlsx
PIDILITE_Budget_Standalone_20260315_v2.0_Final_RS.xlsx
  • ISO date (YYYYMMDD) sorts correctly.
  • Major version increments for structural change (new tab, new methodology) or a formal sign-off; minor for data updates and fixes.
  • Status: Draft, Review, Final. A "Final" file is never edited — any later change creates a new version.
  • Version and status in the filename must match the Cover (s05).

Version control practice

Practice How
Save-as on every material change New minor version; old file retained read-only
Change log Cover table: version, date, author, change, tabs, check status
Archive folder /archive/ on SharePoint/OneDrive; latest version in the root
Comparison Inquire → Compare Files (Spreadsheet Compare) between consecutive versions before sign-off
Single owner One person holds the "pen" at a time; others send comments
Cloud version history SharePoint/OneDrive version history as a backstop, not a substitute
Git-style tools For teams, xltrail or similar tools track Excel diffs; Power Query M and VBA can be exported to text and stored in Git

Avoid co-authoring live on a full 3-statement model with circularity and data tables — simultaneous edits and iterative calculation interact poorly and make the change trail unreliable.

Sheet protection: what it is for

Protection should prevent accidental change, not conceal. The standard approach:

  1. Format input cells as unlocked (Format Cells → Protection → uncheck Locked) — the Input cell style can include this (topic t2, s02).
  2. Protect calc and output sheets (Review → Protect Sheet) allowing "Select locked cells" and "Select unlocked cells" so users can still click and read every formula.
  3. Do not tick "Hidden" in cell protection (which hides formulas from the formula bar).
  4. Use no password, or a password documented on the Cover or held by the model owner and disclosed to reviewers.
  5. Protect workbook structure (Review → Protect Workbook) to stop tabs being deleted or reordered, if needed.

What not to do

Practice Why it is harmful Transparent alternative
Hidden rows/columns Reviewer does not see logic; Go To Special and copying skip them silently Row grouping (Data → Group) with visible +/– buttons
Hidden sheets Logic outside the tab flow Keep all sheets visible; put lookup tables on a visible "Lists" tab
Very hidden sheets (VBA xlSheetVeryHidden) Not even listed in Unhide Never in a deliverable model
Hidden formulas (cell protection "Hidden") Formula bar blank Never
White font on white fill Invisible numbers Never
Passwords not disclosed Reviewer cannot inspect No password or disclosed password
Merged cells Break copying, selection and sorting Center Across Selection

Detecting hidden content during review

  • Inquire → Workbook Analysis lists hidden sheets, hidden rows/columns, very hidden sheets, external links, and cells with formulas that are hidden.
  • Home → Format → Hide & Unhide; Ctrl+Shift+9 unhides rows in a selection.
  • Check row numbers for jumps (e.g., 45 then 52) and column letters.
  • Go To Special → Visible cells only vs a normal selection: differing counts reveal hidden cells.
  • Document Inspector (File → Info → Check for Issues) reports hidden rows, columns, sheets and personal information.

Illustration

A budget model v2.3 was presented to the board with EBITDA of ₹1,840 crore. A later reviewer found row 63 on the Opex tab hidden, containing a one-off "Opex adj –45" hardcode. Reported EBITDA without it would have been ₹1,795 crore. The fix: unhide, move the adjustment to Inputs as a labelled override with a flag, record "v2.4: exposed and documented opex adjustment ₹45 crore (row 63)" in the change log, and re-issue.

Edge cases & judgement calls

  • Client-facing outputs. A sell-side model shared with investors may protect the Outputs tab with a password to preserve formatting. Acceptable if calc tabs remain viewable and the protection is disclosed.
  • Large data tabs. Raw XBRL dumps can be on a visible "Data" tab with grouped columns; hiding them to "tidy up" is still hiding.
  • Macros. If VBA is used (e.g., a copy-paste macro for circularity), keep it in a documented module, sign it, and describe it on the Model map; never rely on a macro for core calculations.
  • Regulatory retention. Models supporting audited estimates (impairment under Ind AS 36, fair value under Ind AS 113) should be retained as audit evidence with the version that supported the financial statements.
  • Insider information. For models containing UPSI, restrict folder access, maintain the structured digital database required by SEBI PIT Regulations where applicable, and avoid emailing files externally.

Key takeaways

  • Use a sortable naming convention: company, purpose, basis, ISO date, version, status, initials — matching the Cover.
  • Save a new version for every material change and compare versions with Inquire before sign-off.
  • Protect sheets to prevent accidental edits, but keep every formula visible and passwords disclosed.
  • Replace hidden rows with grouping, merged cells with Center Across Selection, and hidden sheets with visible list tabs.
  • Use Inquire and Document Inspector to detect hidden content during review.

Practice Questions

Q1. Rename the files [L1]

Rename the following into a consistent convention and order them: "Pidilite model new.xlsx" (built 3-Oct-2025, first draft), "Pidilite model new reviewed.xlsx" (14-Oct-2025, after reviewer comments), "Pidilite FINAL.xlsx" (20-Oct-2025, IC version), "Pidilite FINAL v2 price update.xlsx" (27-Oct-2025).

Q2. Protection design [L2]

Specify the protection settings for each tab of a 14-tab Trent model (Cover, Model map, Inputs, Historicals, Revenue, Opex, WC, PPE, Debt, Tax, 3-Statement, DCF, Outputs, Checks), including which cells are unlocked, whether a password is used and how users can still inspect formulas.

Q3. Hidden content audit [L2]

Describe a ten-minute procedure to find all hidden rows, columns, sheets, formulas and names in a model received from a client, naming the specific Excel tools and what each reveals.

💡 Hint: Combine Inquire, Document Inspector and Name Manager rather than relying on visual inspection.

Q4. Version dispute [L3]

The board minutes record FY27E PAT of ₹1,212 crore, but the latest file in the folder shows ₹1,185 crore. Three versions exist with no change log. Explain how you would reconstruct which version the board saw, identify the changes, and set up controls so the situation cannot recur.
