Subtopic note

Identical Column Structure on Every Calculation Sheet

Scope: Identical column structure on every calc sheet: label, units, constant column, then aligned timeline columns

Why it matters

A model is a grid. If column H means FY21A on the Revenue tab but FY22A on the Working Capital tab, every link between them must be offset, and an offset link is indistinguishable at a glance from a wrong link. Identical column structure means a cross-sheet formula always points to the same column letter it sits in (=Revenue!K25 sitting in column K), which makes errors visually obvious, lets formulas copy across and lets Inquire or a reviewer's macro test alignment mechanically. It is also what makes the "one formula per row" rule achievable.

Core notes

The standard layout

Column Content Width / format Notes
A Spacer / section marker Narrow Used for row grouping markers or check flags
B Line-item label Wide Indented by level using cell indent, not leading spaces
C Sub-label / description or source Medium e.g., "per concall Q4FY25"
D Units Narrow ₹ crore, %, days, mn sq ft, # stores, x
E Constant column Narrow, blue if input Scalars used across the row: tax rate, useful life, growth cap
F Row total or check (optional) Narrow e.g., sum of forecast years
G Spacer / pre-timeline Narrow Gives a "prior period" cell for corkscrews (opening balance column)
H→Q Timeline: FY21A … FY30E Uniform width Identical on every sheet, linked from master timeline

The exact letters are a house choice; the rule is that they are the same on every calculation sheet. A common Indian bank layout uses columns A–E for labels/units/constants and F onward for time; FAST examples often reserve a column for totals. Pick one and freeze it in a template.

Each element explained

Label. Describes the line in words that match the source (Schedule III caption for historical lines). Avoid abbreviations that only you understand.

Units. Every row states its unit. FAST forbids mixed units in a row — a row cannot be ₹ crore in actual years and ₹ lakh in forecast years, or % in some columns and absolute in others. A units column makes unit errors spot-able: multiplying a "mn sq ft" row by a "₹ per sq ft" row should produce "₹ mn", which must then be converted to ₹ crore (÷ 10).

Constant column. Holds values that do not vary with time — useful life, a cap, the base year's value, a link to a named scalar. Because it sits in the same column on every sheet, a formula can reference it with a column-anchored mixed reference, e.g. =H20*$E20, and copy across the timeline unchanged (topic t2, s04).

Aligned timeline columns. Rows 1–8 of each sheet link to the master timeline (s03). Column H is always FY21A; column M is always FY26E.

Illustration: aligned vs misaligned link

Working Capital tab, FY26E receivables in column M:

Aligned:     =Revenue!M40*M12/365      (M on both sheets is FY26E)
Misaligned:  =Revenue!L40*M12/365      (Revenue tab starts one column later; L is FY26E there)

The misaligned version may even be correct numerically, but it is unauditable: a reviewer cannot distinguish an intentional offset from a lag error. Worse, if someone later inserts a column on one sheet only, every link breaks silently.

With Revenue FY26E = ₹16,800 crore and DSO = 6 days, receivables = 16,800 × 6 / 365 = ₹276.2 crore. If the formula pointed at FY25A revenue of ₹14,600 crore by mistake, the result would be ₹240.0 crore — a plausible number, which is why misalignment is dangerous.

Header block

Every calc sheet starts with the same header rows:

  1. Sheet title and scenario label (="Scenario: "&INDEX(Scenario_Names,Scenario)).
  2. Units statement ("₹ crore unless stated").
  3. Timeline rows linked from the master (period end, FY label, A/E flag, counter).

Freeze panes at the first timeline column and below the header so labels and periods stay visible while scrolling.

Building and enforcing the structure

  1. Build one template sheet with the header, columns and styles. Copy it (right-click → Move or Copy → Create a copy) to create each new calc sheet. Never build a sheet from scratch.
  2. Never insert or delete columns on one sheet in isolation. If a forecast year must be added, add it to the template and all sheets together (group sheets with Ctrl-click, then insert — with care, and ungroup immediately).
  3. Add an alignment check row on each sheet: =--(H2<>Timeline!H2) across the timeline, summed into the Checks sheet. Any non-zero means the sheet's period ends differ from the master.
  4. Use consistent row grouping (Data → Group) rather than hidden rows to collapse detail.

Output sheets

Outputs (dashboards, IC summaries) may use a different layout — e.g., only FY25A–FY28E, or years in rows for a chart. That is acceptable because outputs only display; but they should pull by lookup on the FY number (=INDEX(Model!$H$40:$Q$40,MATCH(D$3,Model!$H$3:$Q$3,0))), not by assumed column positions.

Edge cases & judgement calls

  • Quarterly and annual sheets in one model. Their columns cannot align; keep each family internally consistent and bridge with SUMIFS on the FY number.
  • Comps sheet. Peers are in rows and metrics in columns — it is a database, not a timeline sheet. Keep it outside the calc-sheet rule but label clearly.
  • Opening balance column. Leaving column G (pre-first-year) blank or with an opening balance lets corkscrews use one formula from the first column; otherwise the first column needs a different formula, breaking row consistency.
  • Many constants per row. If a row needs three constants, add constant columns consistently on all sheets, or move them to Inputs as named scalars.
  • Totals columns. A five-year forecast total (e.g., cumulative capex) in column F is useful but must be clearly separated so it is not confused with a period.

Key takeaways

  • Same column = same period on every calc sheet; cross-sheet links point to their own column letter.
  • Every row has a label, units and (if needed) a constant in fixed columns.
  • Build every calc sheet from one template; never insert columns on one sheet alone.
  • Add alignment checks comparing each sheet's period-end row to the master timeline.
  • Output sheets may differ in layout but should retrieve data by FY lookup, not by assumed positions.
  • Units column prevents mixed units and makes conversion errors visible.

Practice Questions

Q1. Spot the misalignment [L1]

The PPE tab's timeline starts in column H (FY21A) and the Revenue tab's in column I (FY21A). The PPE tab's FY27E capex formula is =Revenue!O30*$E15. State which year of revenue this picks up, whether it is likely intended, and how you would fix the root cause.

Q2. Template specification [L2]

Write a one-page template specification for calc sheets in a 10-year model (FY21A–FY30E) for an Indian paint company, including column letters, widths, header rows, freeze-pane position, units list, alignment check formula and the rule for adding a new forecast year.

Q3. Units discipline [L2]

A Trent store build has rows: average area (mn sq ft), revenue per sq ft (₹ per sq ft per year), and revenue (₹ crore). Average Zudio area in FY26E is 9.8 mn sq ft and revenue per sq ft is ₹9,500. Write the revenue formula with an explicit unit conversion and state what the units column should show for each row.

💡 Hint: mn sq ft × ₹ per sq ft gives ₹ mn; decide where the ÷10 lives.

Q4. Review case [L3]

You are reviewing a model where four of eleven calc sheets begin in column G and seven in column H, and several analysts have "fixed" links by offsetting. Draft a remediation plan that restores column consistency without breaking the model, including the order of steps, checks to run before and after, and how to document the change in the change log.
