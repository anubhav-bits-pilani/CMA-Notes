Subtopic note

Named Ranges for Scalars, Direct References for Rows

Scope: Named ranges for scalars (Tax_Rate, Scenario, Circ) vs direct references for time-series rows

Why it matters

Named ranges make formulas read like sentences — =PBT*Tax_Rate is self-documenting in a way that =H45*Inputs!$E$12 is not. But names used indiscriminately become a second, invisible model: hundreds of names, some pointing at deleted ranges, some duplicated at sheet scope, some covering whole rows so that formulas no longer reveal which period they use. The practitioner rule — names for global scalars and switches, direct cell references for time-series rows — captures most of the benefit with little of the cost. It is also a frequent interview question ("When do you use named ranges?") and a standard item in model-audit checklists.

Core notes

What to name

Candidate Name? Reason
Corporate tax rate 25.168% (Sec 115BAA incl. surcharge 10% and cess 4%) Yes: Tax_Rate Global scalar used across Tax, DCF, WACC
Scenario selector (1/2/3) Yes: Scenario Single control cell referenced by every Live row
Circularity switch Yes: Circ Single control referenced by Debt and interest logic
Last actual period end Yes: Last_Actual_End Drives flags
Tolerance for checks Yes: Tolerance Shared by all checks
Units divisor (e.g., 10 for ₹ mn → ₹ crore) Yes: Mn_to_Cr Makes conversions explicit
Terminal growth, WACC Yes: TGR, WACC Valuation scalars
Revenue row FY21A–FY30E No (direct reference) Time series — period must stay visible
DSO by year No Time series
Scenario names list (Base, Bull, Bear) Yes: Scenario_Names Lookup list for labels and validation

Why scalars benefit from names

  1. Readability: =EBIT*(1-Tax_Rate) reads correctly to a non-builder.
  2. Absolute by default: a name behaves like $E$12, so copying across never shifts it.
  3. Single point of change: moving the input cell does not break formulas.
  4. Data validation and links: Scenario is easier to reference from a data table, a chart title or VBA.

Why time-series rows should be direct references

If you name the revenue row Revenue (=Revenue!$H$40:$Q$40) and write =Revenue*EBITDA_Margin in column M, Excel's implicit intersection (or, in Excel 365, dynamic-array spill behaviour, which may return a #SPILL! or require @) decides which column is used. The period dependency becomes invisible: a reviewer cannot see that M uses M. With =M40*M55 the column alignment is explicit and auditable (s04). Direct references also make Trace Precedents arrows point to the exact cell.

Exception: whole-row names are useful in aggregate functions that deliberately operate on the entire row, e.g., the master check =SUMPRODUCT(ABS(Check_Rows)) (c04), or =NPV(WACC, FCFF_Forecast) if the range is fixed and documented.

Naming conventions

  • Use underscores, no spaces: Tax_Rate, Min_Cash, Revolver_Limit.
  • Prefix by type if the model is large: in_Tax_Rate (input), sw_Scenario (switch), ck_Master (check).
  • Workbook scope only, unless there is a reason for sheet scope. Duplicate sheet-scope names (created when copying sheets between workbooks) are a common source of confusion.
  • Document every name in a "Names" table on the Model map: name, refers to, purpose. Formulas → Name Manager → filter "Names with errors" to find broken names; Formulas → Use in Formula → Paste Names → Paste List to print the list.

Creating names

  • Select the cell, type the name in the Name Box (left of the formula bar), press Enter.
  • Or Formulas → Define Name, setting scope to Workbook and adding a comment.
  • For label-adjacent scalars, Formulas → Create from Selection (left column) creates names from row labels in bulk.

LET as a complement

Excel 365's LET gives local names inside one formula — e.g.,

=LET(rev, M40, margin, M55, ebitda, rev*margin, ebitda - M60)

It improves readability of a single long formula but should not replace splitting genuinely long logic into helper rows (topic t2, c05).

Illustration

Tax block (₹ crore), FY26E:

PBT (row 80)           : 2,150.0
Tax expense (row 81)   : =M80*Tax_Rate        → 2,150.0 × 25.168% = 541.1
PAT (row 82)           : =M80-M81             → 1,608.9

If Tax_Rate were a time-series (e.g., a company moving from the old regime to 115BAA in FY27), it becomes a row on Inputs (M30 etc.), and the formula becomes =M80*Inputs!M30 (pulled locally first as a green link). The scalar name is replaced by a row reference precisely because it now varies by period.

Edge cases & judgement calls

  • Scalars that later become time-varying. Start with a row if there is any chance (tax regime transitions, phased MAT credit utilisation).
  • Names in external links. Names referring to other workbooks persist even after the link is "broken" and can re-establish external links; clean them in Name Manager.
  • Hidden names. Some add-ins create hidden names; Inquire's Workbook Analysis lists them. Delete unknown hidden names only after checking dependencies.
  • Data tables and names. A data table's row/column input cell must be on the same sheet as the table; a name pointing to an input on another sheet does not get around this (topic t6 pitfall).
  • Over-naming. Five hundred names in a 20-tab model is a smell; most should be direct references.

Key takeaways

  • Name global scalars and switches: Tax_Rate, Scenario, Circ, WACC, TGR, Tolerance, unit divisors.
  • Use direct cell references for time-series rows so the period dependency stays visible.
  • Keep names at workbook scope, follow a naming convention and document them in a names table.
  • Use Name Manager regularly to delete broken, duplicate or external-pointing names.
  • When a scalar starts varying by period, convert it to a timeline row.

Practice Questions

Q1. Name or reference? [L1]

For each item decide whether it should be a named range or a direct reference and why: (a) WACC 11.8%; (b) Zudio store additions FY26E–FY30E; (c) iterative calculation switch; (d) the master check cell; (e) ₹ lakh → ₹ crore divisor; (f) DPO by year.

Q2. Implicit intersection trap [L2]

A model defines Revenue = Calc!$H$40:$Q$40 and in Calc!M60 has =Revenue*Margin where Margin is a scalar name. The file is opened in Excel 365 and the formula now shows =@Revenue*Margin. Explain what Excel is doing, what happens if the formula is moved to a different row, and how you would rewrite it.

💡 Hint: Consider what implicit intersection returns when the formula is no longer in a column covered by the range.

Q3. Tax regime transition [L2]

A company stays on the old regime with MAT credit until FY27E (effective current tax rate 34.944% on normal income) and opts for Sec 115BAA (25.168%) from FY28E. Redesign the tax-rate input from a named scalar to a time-series, and write the FY28E tax formula on the Tax tab.

Q4. Name hygiene review [L3]

A model you inherit has 640 names, including 210 with #REF!, 85 sheet-scoped duplicates and 30 referencing a file on a former employee's desktop. Write a step-by-step clean-up procedure, the checks you would run before and after, and the policy you would add to the Model map.
