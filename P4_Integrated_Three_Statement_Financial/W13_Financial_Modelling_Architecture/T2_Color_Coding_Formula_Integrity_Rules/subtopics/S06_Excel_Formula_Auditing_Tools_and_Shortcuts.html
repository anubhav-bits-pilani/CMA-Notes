Subtopic note

Excel Formula Auditing Tools and Shortcuts

Scope: Auditing tools: Trace Precedents/Dependents, Evaluate Formula, Ctrl+` (show formulas), Ctrl+[ (jump to precedent)

Why it matters

Building a model is half the job; proving it works is the other half. Reviewers, model auditors and interviewers expect you to navigate a model at keyboard speed — trace where a number comes from, where it goes, how a complex formula evaluates step by step, and what the sheet looks like with formulas instead of values. For someone coming from audit, these are the spreadsheet equivalent of vouching and tracing. They also make Week 15's balance-sheet debugging tractable: an unbalanced model is found by tracing, not by staring.

Core notes

The core toolkit

Jump to dependents — Ctrl+] Selects direct dependents on the same sheet
All-level precedents/dependents — Ctrl+Shift+[ / Ctrl+Shift+] Selects all levels (same sheet)

Mac Excel uses different shortcuts for several of these (the Windows ribbon access keys such as Alt, M, P do not apply); check your environment before an assessment.

Trace Precedents and Dependents in practice

Clicking FY27E net debt on the Outputs tab and pressing Ctrl+[ jumps to the 3-Statement tab cells feeding it. Repeating Ctrl+[ walks the chain backwards: borrowings → Debt tab closing balance → repayment and drawdown rows → Inputs. This is the auditor's "trace to source". Trace Dependents answers the reverse question — if I change this input, what moves? — and is essential before deleting any row (a row with no dependents may be orphaned; one with many is structural).

Arrows have limits: they show only direct links, off-sheet links appear as a single dashed arrow (double-click it to open the Go To list), and they do not show dependencies created via INDIRECT or names used indirectly — another reason to avoid volatile functions (s08).

Evaluate Formula

For a formula such as

=IF(M$5=1,MAX(0,MIN(Revolver_Limit,M88-M86+Min_Cash)),0)

Evaluate Formula shows each step: M$5 → 1, M88-M86+Min_Cash → 140.0, MIN(500,140) → 140, MAX(0,140) → 140. It is the fastest way to find which part of a long formula is wrong. Step In opens a referenced cell's formula in turn.

The F9 technique does the same inside the formula bar: select M88-M86+Min_Cash, press F9 to see 140, then Esc to restore the formula. Forgetting Esc and pressing Enter replaces the expression with a hardcode — a classic way of creating the very pitfall this topic warns against.

Show Formulas (Ctrl+grave accent)

Toggling shows the formula text in every cell, widening columns. Use it to:

  • Scan a row for consistency (are all forecast cells visually the same pattern?).
  • Spot embedded constants (s05).
  • Print a formula view for review files.

Combine with R1C1 reference style (File → Options → Formulas → R1C1 reference style) for row consistency — in R1C1 identical formulas look identical (c01).

A review routine using the toolkit

  1. Watch Window: add master check, EV, FY30E PAT, closing cash.
  2. On each calc sheet, Ctrl+` and scan rows for pattern breaks.
  3. For each key output, Ctrl+[ repeatedly to its inputs; note the chain length (should be short; c04).
  4. On complex formulas, Evaluate Formula.
  5. Before deleting or moving any row, Trace Dependents.
  6. Error Checking for any #REF!, #N/A, #DIV/0!.

Illustration

FY27E Trent EBITDA on Outputs shows ₹4,310 crore but the 3-Statement tab shows ₹4,365 crore. Ctrl+[ on the Outputs cell jumps to '3-Statement'!N60 — but the Outputs formula is =INDEX('3-Statement'!$H$58:$Q$58,…), row 58 (EBITDA before Ind AS 116 adjustment) not row 60. Evaluate Formula on the INDEX shows the MATCH returning column 7 correctly, so the issue is the row. Fix: reference row 60, and add a check that Outputs EBITDA equals 3-Statement EBITDA.

Edge cases & judgement calls

  • Very long precedent chains across many sheets slow tracing and signal daisy-chaining (c04).
  • Precedents through names: Trace Precedents follows names to their cells; Ctrl+[ also works through names.
  • Data tables show {=TABLE(…)}; their precedents cannot be traced in the usual way.
  • Protected sheets: tracing still works if "Select locked cells" is allowed (topic t1, s08).
  • Large models: arrows on thousands of cells are unreadable; use Inquire's Cell Relationship diagram for a selected cell.

Key takeaways

  • Ctrl+[ walks back to source; Ctrl+] finds dependents; F5 + Enter returns.
  • Evaluate Formula and F9 (with Esc) dissect long formulas step by step.
  • Show Formulas (Ctrl+`) and R1C1 view expose row inconsistencies and embedded constants.
  • Watch Window keeps key outputs and the master check in view during edits.
  • Arrows do not reveal indirect dependencies (INDIRECT/OFFSET) — another reason to avoid them.

Practice Questions

Q1. Shortcut drill [L1]

State the shortcut or ribbon path for: (a) showing formulas; (b) jumping to the source of a cross-sheet link; (c) returning to the original cell after the jump; (d) stepping through a nested formula; (e) monitoring the master check while working on another tab.

Q2. Trace a number [L2]

Describe, keystroke by keystroke, how you would trace FY28E closing cash on the balance sheet of a 3-statement model back to its ultimate inputs, listing the tabs you expect to pass through and what you would check at each stop.

💡 Hint: Closing cash usually comes from the CFS; follow each CFS section to its schedule.

Q3. The F9 trap [L2]

A reviewer finds =L40*(1+0.087) in a revenue row that should read =L40*(1+M38), and the builder says they "only checked the value with F9". Explain how this happened, how to detect other occurrences, and the habit that prevents it.

Q4. Review routine design [L3]

Design a 45-minute review routine for a newly received 15-tab Pidilite model using only Excel's built-in auditing tools and Inquire, specifying the order of steps, the time on each, and the findings each step is designed to catch.
