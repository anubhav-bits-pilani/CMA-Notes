Font Colour Convention: Inputs, Formulas and Links

Scope: Font convention: blue hardcoded inputs, black same-sheet formulas, green cross-sheet links, red/purple for external-workbook links

Why it matters

Colour coding is the cheapest audit tool in modelling. A reviewer scanning a sheet should know, without clicking a single cell, which numbers are assumptions they can challenge (blue), which are derived on the sheet (black), which come from elsewhere in the workbook (green) and which depend on another file that may have moved or changed (red/purple). In Indian investment banking, equity research and Big 4 transaction teams this convention is near-universal; in an interview case study, a model without it signals inexperience before any number is checked. In FP&A, it lets budget owners find and change only the cells they are meant to change.

Core notes

The convention

Font colour Cell content Example Reviewer's question
Blue (e.g., RGB 0,0,255) Hardcoded input: typed number, date, text choice 9.0% UVG; 31-Mar-2025; FY24A revenue 14,603.0 on Historicals Is the source documented and the value reasonable?
Black Formula referencing only cells on the same sheet =L40*(1+M38) Is the logic right and consistent across the row?
Green (e.g., RGB 0,128,0) Formula linking to another sheet in the same workbook =Inputs!M20; =Revenue!M40 Does the link point to the right row and same column?
Red or purple Link to another workbook (external link) ='[Peers_FY25.xlsx]Comps'!F12 Is the source file available, current and version-controlled?

Some houses add:

  • Orange/brown for formulas that mix a cross-sheet reference with a calculation (e.g., =Inputs!M20*M38). FAST and many banks discourage such mixed formulas: link the input onto the sheet first (green), then calculate locally (black) — topic concept c04.
  • Grey italics for memo lines or checks.

The key rule is not the exact colour, but that the convention is defined once (legend on the Model map), applied mechanically and kept up to date.

Why blue means "change me"

Blue cells are the only cells a user is entitled to overwrite. On the Inputs tab almost everything should be blue; on calc tabs, ideally nothing is blue (inputs are linked in, green). Historical actuals on the Historicals tab are blue because they are typed or pasted data, even though they are not assumptions.

Green links: one-step, same-column

A green link should be a pure link: =Inputs!M20, not =Inputs!M20/100. Pure links let a reviewer trust green cells as "same number as source"; any transformation is black on the receiving sheet. Combined with column consistency (topic t1, c03), a green link in column M should point to column M.

External links: red/purple and minimised

External links break when files move, are renamed or are opened without the source. Excel prompts "This workbook contains links to external sources", and values may silently remain stale if links are not updated. Best practice:

  • Avoid external links in deliverable models. Paste values from the source into a raw-data tab (blue), with the source file, version and date noted.
  • If unavoidable (e.g., a group consolidation pack linking to subsidiary models), isolate them on one "External" tab in red/purple, and pull from there locally.
  • Data → Edit Links (Workbook Links pane in Excel 365) lists all external links; Break Link converts them to values.

Applying the colours fast

  • Go To Special → Constants (Numbers) → font blue; Go To Special → Formulas → font black; then find cross-sheet formulas with Find (Ctrl+F) on "!" with "Look in: Formulas" → Find All → Ctrl+A selects them → font green; and search "[" for external links → red. (Topic s07 for Go To Special.)
  • Use Cell Styles ("Input", "Calculation", "Link", "External") rather than manual colouring so the convention can be changed globally (s02).
  • Third-party add-ins (Macabacus, Arixcel, PerfectXL, Operis OAK) auto-colour by content type; know the manual method for interviews.

Illustration: Trent revenue block, column M (FY26E)

Row Label Units Formula in M Colour
10 Zudio closing stores # =Inputs!M42 Green
11 Zudio opening stores # =L10 Black
12 Average stores # =AVERAGE(L10:M10) Black
13 Area per store sq ft =Inputs!M43 Green
14 Revenue per sq ft ₹ =L14*(1+M15) Black
15 LFL growth % =Inputs!M44 Green
16 Zudio revenue ₹ crore =M12*M13*M14/Rs_per_Cr (named scalar = 10^7) Black

With 900 average stores × 10,000 sq ft × ₹9,800 per sq ft = ₹88,200 mn → ₹8,820 crore. A reviewer scanning the block sees no blue (no hidden assumptions on the calc sheet) and can audit greens against Inputs.

Edge cases & judgement calls

  • Formulas on the Inputs tab. An input-side aid, e.g., a total of a store-addition table, is black on Inputs; it should not feed calculations unless intended.
  • Historical columns on calc tabs. If historicals are linked from Historicals, they are green; if typed directly (not recommended), they are blue — making the boundary visible.
  • Colour-blind users. Add fill patterns (input fill, s02) so the classification does not rely solely on red/green distinctions.
  • Conditional formatting overriding font colour. Check cells with conditional formats may show red text; keep check colours distinct (e.g., red fill) from the font convention.
  • Pasted values from formulas. A cell that was black and is pasted as value remains black but is now a hardcode — the classic pitfall (topic.md). Re-run the Go To Special colour pass before every issue.

Key takeaways

  • Blue = hardcoded input; black = same-sheet formula; green = cross-sheet link; red/purple = external link.
  • Define the convention in a legend on the Model map and apply it mechanically before every issue.
  • Keep green links pure; transform locally in black.
  • Minimise external links; isolate any that remain and document source files.
  • Calc sheets ideally contain no blue cells at all.
  • Use Cell Styles and Go To Special so colouring reflects actual cell content, not memory.

Practice Questions

Q1. Colour each cell [L1]

Assign the correct font colour and state whether each cell is well-formed: (a) =Inputs!M20; (b) =Inputs!M20*M15; (c) 14,603.0 typed on Historicals; (d) =L40*(1+M38); (e) ='[Pidilite_peers.xlsx]Sheet1'!D8; (f) =SUM(M10:M15); (g) 12.5% typed in a calc row on the Opex tab.

Q2. Re-colour procedure [L2]

Write a step-by-step procedure, using only native Excel features, to re-apply the colour convention to an entire 12-tab model in under fifteen minutes, including how to find cross-sheet links and external links.

💡 Hint: Find All on "!" and "[" with Look in set to Formulas returns a selectable list.

Q3. External link policy [L2]

A group FP&A consolidation workbook links to eight subsidiary budget files on SharePoint. Design a policy covering link isolation, colour, refresh control, version stamping and what happens at month-end close.

Q4. Mixed formulas [L3]

A reviewer flags 340 cells of the form =Inputs!M20*M15 across the Revenue and Opex tabs. Explain why FAST discourages these, how they interact with colour coding and auditability, and design a remediation that does not change any result.
