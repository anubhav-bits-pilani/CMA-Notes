Avoiding Volatile Functions and Whole-Column References

Scope: Avoiding volatile functions (OFFSET, INDIRECT, TODAY) and whole-column references

Why it matters

Volatile functions recalculate every time anything in the workbook changes, not only when their inputs change. In a 3-statement model with iterative circularity and scenario data tables, a handful of OFFSET or INDIRECT formulas can turn a one-second recalculation into a thirty-second one, which in turn tempts users to switch to manual calculation — and manual calculation is how stale numbers reach board packs. Volatile functions also hide dependencies from Trace Precedents and model-audit tools, and TODAY/NOW make results change by date, so the same file gives different answers on different days. Whole-column references (A:A) cause similar bloat. Both are standard review findings.

Core notes

What volatility means

Excel's calculation engine tracks a dependency tree; normally only cells downstream of a change recalculate. A volatile function is marked to recalculate on every calculation event, and so is everything that depends on it. Volatile functions include:

Function Why volatile Typical (mis)use in models
OFFSET Returns a reference computed at runtime Scenario selection, dynamic ranges, "last n years"
INDIRECT Builds a reference from text Sheet-name switching, scenario selection by text
TODAY, NOW Depend on clock Valuation date, "days since", version stamps
RAND, RANDBETWEEN, RANDARRAY Random Monte Carlo (legitimate in a separate simulation model)
CELL (some arguments), INFO Environment Filename display

INDEX (used in reference form, e.g., A1:INDEX(A:A,n)) is not volatile in modern Excel and is the standard replacement for OFFSET. SUMIF/SUMIFS are not volatile.

Why they hurt models

  1. Performance: every dependent recalculates on every edit; with iterative calculation and data tables (topic t6), calculation repeats many times.
  2. Opacity: =INDIRECT("'"&B5&"'!M40") has no static precedent; Trace Precedents shows nothing, Inquire can't map it, and renaming a sheet breaks it silently (text doesn't update).
  3. Non-reproducibility: =TODAY() as valuation date means the DCF changes daily; outputs can't be reproduced for audit.
  4. Fragility: OFFSET with hardcoded offsets (OFFSET(A1,5,3)) breaks when rows or columns are inserted.

Replacements

Need Volatile approach Non-volatile replacement
Pick scenario row =OFFSET(M20,Scenario-1,0) =CHOOSE(Scenario,M20,M21,M22) or =INDEX(M20:M22,Scenario)
Pick by sheet name =INDIRECT(Sheet&"!M40") Bring all candidates into one block; =INDEX(...) or CHOOSE
Dynamic range end =SUM(OFFSET(H40,0,0,1,n)) =SUM(H40:INDEX(H40:Q40,n)) or =SUMIFS(H40:Q40,H$7:Q$7,"<="&n)
Last actual value =OFFSET(G40,0,COUNT(H40:Q40)) =INDEX(H40:Q40,MATCH(Last_Actual_End,H$2:Q$2,0)) or =SUMPRODUCT(H40:Q40,H$8:Q$8) with a last-actual flag
Valuation date =TODAY() Blue input Valuation_Date = 30-Sep-2025
Version stamp =NOW() Typed date in change log

Whole-column and whole-row references

=SUMIFS(Data!C:C,Data!A:A,"FY25",Data!B:B,"Revenue") references 1,048,576 rows per column. Excel optimises many functions to the used range, but not all (SUMPRODUCT and array formulas over whole columns are particularly slow), and whole-column references:

  • Bloat calculation chains, especially with many formulas.
  • Risk picking up stray data below the intended table (a note typed in row 5,000 enters the sum).
  • Make audit harder (what is the intended range?).

Prefer bounded ranges (Data!$C$2:$C$5000), Excel Tables with structured references (tbl_XBRL[Value]) which auto-expand, or named dynamic ranges built with INDEX.

Calculation settings

Keep calculation on Automatic (or "Automatic except for data tables" if large data tables slow the model — and display a warning on the Cover to press F9). Never deliver a model in Manual mode without a prominent note: a user opening it may see stale outputs. With circularity, File → Options → Formulas → Enable iterative calculation (e.g., 100 iterations, max change 0.001) and show the status on the Cover (topic t1, s06).

Illustration

A scenario block in a Pidilite model uses =OFFSET(Inputs!$E$20,Scenario*3-3,M$7) across 400 driver cells, and a data table runs three scenarios across 12 outputs. Every edit triggers recalculation of all 400 OFFSETs and their dependents, and each data-table pass repeats it; recalc time is 14 seconds. Replacing with =INDEX(Inputs!M20:M22,Scenario) (non-volatile) reduces recalc to under 1 second, and Trace Precedents now shows the three scenario rows as precedents.

Edge cases & judgement calls

  • Monte Carlo legitimately uses RAND; isolate it in a separate simulation workbook or sheet with manual calculation and documented seeds/run counts.
  • Filename display via CELL("filename") on the Cover is acceptable if not used in calculations.
  • INDIRECT for consolidation templates across many identical subsidiary tabs is tempting; prefer Power Query to append subsidiary data, or a 3D SUM (=SUM(Sub1:Sub8!M40)) with documented start/end tabs.
  • Conditional formatting formulas are also recalculated frequently; keep them simple.
  • Dynamic arrays (FILTER, SORT, UNIQUE) are not volatile but spill ranges can be large; bound their inputs.

Key takeaways

  • OFFSET, INDIRECT, TODAY/NOW, RAND are volatile: they recalculate on every change and hide dependencies.
  • Replace OFFSET/INDIRECT with INDEX, CHOOSE, XLOOKUP or SUMIFS; replace TODAY with a dated input.
  • Avoid whole-column references; use bounded ranges or Excel Tables.
  • Keep calculation automatic; if not, warn prominently on the Cover.
  • Volatility is both a performance and an auditability problem.

Practice Questions

Q1. Identify volatility [L1]

Which of the following are volatile, and what would you replace each with: (a) =OFFSET(M20,Scenario-1,0); (b) =INDEX(M20:M22,Scenario); (c) =YEARFRAC(TODAY(),M2); (d) =INDIRECT("Inputs!M"&ROW()); (e) =SUMIFS(C:C,A:A,"FY25")?

Q2. Rewrite a dynamic sum [L2]

Rewrite =AVERAGE(OFFSET(H45,0,COUNT(H45:Q45)-3,1,3)) (average of the last three actual-year DSO values) without volatile functions, using the timeline flags available in rows 4–8.

💡 Hint: A flag that is 1 only for the last three actual years turns the average into SUMPRODUCT divided by a count.

Q3. Reproducibility issue [L2]

An Ind AS 113 fair-value model for an unlisted investment uses =TODAY() to compute discounting periods. The auditor re-performs the calculation three weeks after the reporting date and gets a different value. Explain the issue, the correct design, and what documentation the auditor will expect.

Q4. Performance remediation [L3]

A 20-tab group budget model takes 45 seconds to recalculate, with iterative calculation on and three data tables. Inquire shows 1,800 OFFSET formulas, 600 INDIRECTs and 250 SUMPRODUCTs over whole columns. Design a remediation plan, prioritising by impact and risk, with tests proving results are unchanged.
