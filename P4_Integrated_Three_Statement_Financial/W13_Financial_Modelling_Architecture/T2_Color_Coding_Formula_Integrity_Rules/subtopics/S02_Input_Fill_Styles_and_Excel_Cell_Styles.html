Input Fill Styles and Excel Cell Styles

Scope: Input cell fill styles and Excel Cell Styles to enforce colour rules consistently

Why it matters

Font colour alone is fragile: it depends on the builder remembering to recolour, it is hard to see on printouts and it fails colour-blind readers. Adding a distinctive fill to input cells, and implementing the whole convention through Excel's Cell Styles, turns colour coding from a manual habit into a system. A style can be redefined once and every cell using it updates; it can carry number format, protection (unlocked) and borders; and it can be copied to every new model as part of a template. In FP&A budgeting, where many contributors enter numbers, a consistent input fill tells each owner exactly which cells are theirs.

Core notes

Input fill conventions

Element Common choice Purpose
Input font Blue Signals hardcode
Input fill Light yellow (e.g., RGB 255,255,204) or light beige Visible on screen and print; distinguishes inputs even in greyscale
Input border Thin grey or dotted Marks the editable "box"
Protection Unlocked Editable when sheet protection is on
Number format Matches units: 0.0%, #,##0.0, dd-mmm-yy Prevents mis-entry
Optional: data validation Ranges or lists Prevents out-of-range entry

Some houses use fill only for "live assumptions" (yellow) and a different fill (light blue) for historical data, so a reviewer can distinguish forecast assumptions from loaded actuals.

Excel Cell Styles

Home → Cell Styles → New Cell Style lets you define a named style with: Number, Alignment, Font, Border, Fill and Protection. Excel ships with built-in styles "Input", "Calculation", "Linked Cell", "Check Cell", "Output", "Note" — usable but their defaults (orange input fill, etc.) may not match house style; modify them (right-click → Modify) rather than creating duplicates.

A typical style set:

Style name Font Fill Protection Number format Use
In_Number Blue Light yellow Unlocked #,##0.0;(#,##0.0);– Monetary inputs
In_Percent Blue Light yellow Unlocked 0.0% Growth, margins, rates
In_Date Blue Light yellow Unlocked dd-mmm-yyyy Timeline inputs
Hist_Data Blue Light blue Locked #,##0.0 Loaded actuals
Calc Black None Locked #,##0.0 Same-sheet formulas
Link Green None Locked #,##0.0 Cross-sheet links
External Purple None Locked #,##0.0 External links
Check Grey italic None Locked 0.000 Check rows
Header_Year White bold Dark blue Locked General Timeline header

The Protection element matters: when the Input style is set to Unlocked, protecting a sheet automatically leaves inputs editable and everything else locked (topic t1, s08). The "Hidden" protection option must stay unchecked so formulas remain visible.

Applying and maintaining styles

  1. Build the styles in a template workbook; new models start from the template.
  2. To bring styles into an existing workbook: Home → Cell Styles → Merge Styles from the template.
  3. Apply styles (not manual formatting) to whole input blocks.
  4. To change the input fill house-wide, modify the style once; all cells using it update.
  5. Clean up: workbooks copied between clients accumulate hundreds of junk styles (a known cause of "Too many different cell formats" errors). Remove them with Inquire → Clean Excess Cell Formatting (which addresses excess formatting) or a style-cleaner add-in or simple VBA that deletes non-built-in unused styles.

Enforcement with conditional formatting

A self-policing layer can flag mis-coloured cells:

  • Conditional formatting rule on calc sheets, formula =ISFORMULA(M10)=FALSE applied to the forecast range → bright red fill. Any constant in a calc area lights up.
  • On the Inputs tab, =ISFORMULA(M10) → orange fill, highlighting formulas sitting where inputs should be.

These rules use ISFORMULA (Excel 2013+), are non-volatile and cheap.

Data validation on inputs

Inputs styled as editable should also be constrained:

  • Scenario selector: list 1,2,3 (topic t6).
  • Growth rates: decimal between –50% and +100%, with input message showing the source.
  • Days (DSO/DIO/DPO): whole number 0–365.
  • Dates: date between FY start and end.

All value cells use In_Percent or In_Number (blue on yellow, unlocked); labels and sources use a standard text style. If the reviewer asks for inputs to be shaded light green instead, one style modification changes all four rows across the workbook.

Edge cases & judgement calls

  • Printing and PDFs. Light fills can disappear on some printers; test print the Inputs tab.
  • Colour-blind accessibility. Fill plus font plus a border pattern ensures inputs are identifiable without colour perception.
  • Power BI exports. When the model feeds Power BI, styles do not travel; document which ranges are inputs in the data dictionary.
  • Styles and copy-paste. Pasting from another workbook can bring that workbook's styles; use Paste Special → Values or Formulas to avoid style pollution.
  • Locked inputs by design. Some inputs (e.g., historical data) should be locked even though blue; use a separate style with Locked protection.

Key takeaways

  • Combine blue font with a distinctive fill and border for inputs so they are visible in any medium.
  • Implement the convention through named Cell Styles that include number format and protection.
  • Keep input styles unlocked so sheet protection leaves only inputs editable; never use the Hidden option.
  • Merge styles from a template; modify styles centrally; clean junk styles.
  • Add ISFORMULA-based conditional formatting to flag constants in calc areas and formulas in input areas.
  • Constrain inputs with data validation that documents allowable ranges.

Practice Questions

Q1. Define a style set [L1]

Define, in a table, six Cell Styles for a Trent model (inputs, historicals, calculations, links, checks, headers), specifying font, fill, protection and number format for each.

Q2. Self-policing formatting [L2]

Write the conditional formatting rules (formula, range, format) that would flag (a) any constant in forecast columns M:Q of calc sheets, (b) any formula on the Inputs tab in rows 20–120, and (c) any input cell on the Inputs tab left blank in the forecast years.

💡 Hint: ISFORMULA and ISBLANK work on a relative reference anchored to the top-left of the applied range.

Q3. Style pollution [L2]

A model opened from a client shows 4,800 cell styles and a "Too many different cell formats" error. Explain the cause, the risks for the model, and the clean-up steps you would take while preserving your house styles.

Q4. Budget template design [L3]

Design the input-cell styling, protection and data validation for a departmental opex budget template that 25 cost-centre owners at a listed FMCG company will fill in, so that consolidated FP&A can trust that only intended cells were changed.
