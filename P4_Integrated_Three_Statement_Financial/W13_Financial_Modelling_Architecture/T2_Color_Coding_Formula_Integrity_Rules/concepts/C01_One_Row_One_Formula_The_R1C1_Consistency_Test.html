Key concept

One Row, One Formula: The R1C1 Consistency Test

Concept: One row, one formula: in R1C1 view, every forecast cell in a row shows an identical formula

Statement

A forecast row \( r \) is consistent if, for all forecast columns \( j \) from the first forecast column \( f \) to the last \( N \):

\[ \text{R1C1}(r, j) = \text{R1C1}(r, f) \]

where \( \text{R1C1}(r,j) \) is the formula in row \( r \), column \( j \) written in R1C1 notation. In R1C1 notation, relative references are expressed as offsets from the host cell (R[-2]C = two rows up, same column; RC[-1] = same row, one column left) and absolute references as fixed positions (R4C = row 4, same column; RC5 = same row, column 5). Formulas that are properly copied across a row are textually identical in R1C1, even though they look different in A1 notation.

Explanation

In A1 notation, =L40*(1+M38) in column M and =M40*(1+N38) in column N look different, so a reviewer must mentally check that they are "the same". In R1C1 both read =RC[-1]*(1+R[-2]C). Any deviation — a typed value, a wrong reference, an embedded constant — shows up as a different string.

How to use it:

  1. File → Options → Formulas → tick R1C1 reference style. Column headers become numbers.
  2. Press Ctrl+` (show formulas) and scan each forecast row: all cells should be identical text.
  3. Untick R1C1 when finished (it is a workbook-display setting; formulas are unaffected).

Anchoring becomes explicit: $E31 → RC5, M$4 → R4C, $E$12 → R12C5. A missing $ on a flag row shows as R[-36]C, an obvious error.

Excel itself uses R1C1 logic for its "inconsistent formula" green-triangle warning and for Go To Special → Row differences (s07). Both are automated versions of this test.

Exceptions that legitimately differ: the boundary column in a design A split row (s03) and the first forecast year if no pre-timeline column exists — but best practice removes these with flags (c06).

Illustration

Trent Westside revenue row, A1 view (columns M–Q, FY26E–FY30E):

M N O P Q
=M12*M13/Mn_to_Cr =N12*N13/Mn_to_Cr =O12*O13/Mn_to_Cr*1.03 =P12*P13/Mn_to_Cr 5,210

R1C1 view:

13 14 15 16 17
=R[-8]C*R[-7]C/Mn_to_Cr =R[-8]C*R[-7]C/Mn_to_Cr =R[-8]C*R[-7]C/Mn_to_Cr*1.03 =R[-8]C*R[-7]C/Mn_to_Cr 5210

(Row 20 hosts the formula; rows 12 and 13 are average area and revenue per sq ft.) Columns 15 and 17 are instantly visible as breaks — an embedded 3% uplift and a typed FY30E value. If the Base case has average area 7.0 mn sq ft and revenue per sq ft ₹13,000 in FY30E, the formula would give 7.0 × 13,000 / 10 = ₹9,100 crore (mn sq ft × ₹ per sq ft gives ₹ mn; the named divisor Mn_to_Cr = 10 converts to ₹ crore), so the typed 5,210 is also inconsistent in magnitude — evidence that it came from a different version.

Connections

Implements s03 (one consistent formula per row) and relies on s04 (mixed references). Automated by s07 (Row differences, Inquire). Topic t1's FAST Standard (c01) states the rule; topic t1 s03 provides the flags that make it possible across the actual/forecast boundary. Week 15 debugging begins with an R1C1 scan of rows where the balance check first fails.

Practice Questions

Q1. Translate to R1C1 [L1]

Write the R1C1 form of these formulas hosted in cell N40: (a) =M40*(1+N38); (b) =N$4*Hist!N40+N$5*M40; (c) =N30/$E31; (d) =Tax_Rate*N80.

Q2. Read the R1C1 scan [L2]

A row in R1C1 reads, across five forecast columns: =RC[-1]*(1+R[-3]C), =RC[-1]*(1+R[-3]C), =RC[-1]*(1+R[-3]C[-1]), =RC[-1]*(1+R[-3]C), =R[1]C[-1]*(1+R[-3]C). Diagnose each inconsistency and its likely economic effect.

💡 Hint: Focus on which period's growth driver and which row's base value each cell uses.

Q3. Interview: why R1C1 [L1]

Explain in under one minute to an interviewer why you switch to R1C1 view when reviewing a model and what it can and cannot detect.
