Key concept

Link Once, Then Reference Locally

Concept: Link once, then reference locally: avoid daisy-chained links through three or more sheets

Statement

Each value needed from another sheet is brought onto the consuming sheet once, as a pure green link (=Inputs!M20), in a clearly labelled import block; all calculations on that sheet then reference the local copy. Links should go directly to the source sheet, not via intermediate sheets: a chain Sheet A → Sheet B → Sheet C → Sheet D (where B and C merely pass the value on) is a daisy chain and should be replaced by direct links from the source.

Let \( L(x) \) be the number of sheet-to-sheet hops between a value's source and the cell that uses it. The rule targets:

\[ L(x) = 1 \quad \text{for every imported value, and no pass-through sheets} \]

Explanation

Why link once. If the tax rate is referenced as Inputs!$E$12 inside forty formulas on the Tax tab, each formula is a mixed formula (cross-sheet + calculation), coloured inconsistently, and changing the source means checking forty cells. With a local import row (Tax rate — linked from Inputs), there is one green cell and forty black formulas referencing it; Trace Precedents shows a short local chain; and reviewers can confirm the import against the source in one place.

Why avoid daisy chains. Consider revenue: Revenue tab → 3-Statement P&L → WC tab → DCF tab, with WC pulling revenue from the P&L, and DCF pulling "revenue" from WC. Problems:

  1. Tracing is slow: Ctrl+[ must be pressed through three sheets to reach the source.
  2. Fragility: if the WC tab's revenue row is deleted or redefined (e.g., changed to "revenue excluding export incentives"), the DCF silently picks up the changed definition.
  3. Backward links: chains often run right to left, breaking tab flow (topic t1, s01).
  4. Hidden transformations: an intermediate sheet may alter the value (e.g., ÷ 10 for units) without the consumer knowing.

Where the source is. "Source" means the sheet where the value is calculated or input — the Revenue schedule for revenue, the Inputs tab for drivers, the Debt tab for closing debt. The 3-Statement tab is itself a consumer of schedules, and is the legitimate source only for items it computes (e.g., PAT, total assets).

Import blocks. At the top of each calc sheet:

Row Import Units Source
10 Revenue ₹ crore Revenue!row 80
11 COGS ₹ crore Opex!row 40
12 DSO days Inputs!row 70
13 DIO days Inputs!row 71
14 DPO days Inputs!row 72

Every import is green, same column, pure link. Calculations below reference rows 10–14.

Exceptions. Very large models sometimes use a "hub" sheet (e.g., a summary P&L) as a legitimate source for many outputs; that is acceptable if the hub is the documented source and not a pass-through of another sheet's value with possible changes.

Illustration

A Pidilite DCF tab's FY27E FCFF uses =WC!N95 for EBITDA, where WC!N95 is ='3-Statement'!N60, which is =Opex!N120. An analyst redefines WC!N95 to "EBITDA excluding other operating revenue" for a working-capital ratio, reducing it by ₹180 crore. The DCF picks up EBITDA ₹180 crore lower in every year; because it recomputes operating tax on EBIT, FCFF falls by ₹180 × (1 − 25.168%) ≈ ₹134.7 crore per year. At a WACC of 11% and terminal growth of 6%, the EV impact is several thousand crore — from a change made for an unrelated purpose. Direct linking (=Opex!N120 imported once onto the DCF tab) would have isolated the DCF from the WC edit.

Practice Questions

Q1. Identify the chain [L1]

Given: Outputs!N20 =DCF!N15; DCF!N15 =Tax!N40; Tax!N40 ='3-Statement'!N75; '3-Statement'!N75 =Tax!N30. Identify the source, the chain length, any circular or backward link, and the corrected link for Outputs!N20.

Q2. Design an import block [L2]

Design the import block for a Debt tab that needs: opening debt (FY25A actual), scheduled repayments, interest rates by tranche, minimum cash, revolver limit, and pre-financing cash flow. State the source sheet for each and the colour of each cell.

💡 Hint: Pre-financing cash flow is computed elsewhere; decide which sheet is its true source.

Q3. Quantify a daisy-chain error [L2]

In a Trent model, Outputs pulls FY28E EBITDA via WC, where an analyst has replaced the link with EBITDA "pre-Ind AS 116" (₹1,050 crore lower than reported EBITDA). The EV/EBITDA comps page applies a peer multiple of 45x to the Outputs number. Explain the implied valuation error and the control that prevents it.
