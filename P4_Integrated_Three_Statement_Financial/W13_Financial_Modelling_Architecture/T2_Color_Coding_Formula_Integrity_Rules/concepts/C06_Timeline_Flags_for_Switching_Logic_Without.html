Key concept

Timeline Flags for Switching Logic Without Breaking Rows

Concept: Timeline flags: =--(Year>Last_Actual_Year) let one formula switch logic without breaking row consistency

Statement

A timeline flag is a 0/1 row on the master timeline that marks a property of each period. The forecast flag:

=--(Year>Last_Actual_Year)

\[ F_t = \begin{cases} 1 & \text{if } \text{Year}_t > \text{Last Actual Year} \\ 0 & \text{otherwise} \end{cases} \]

where \( \text{Year}_t \) is the fiscal year number of period \( t \) (2026 for the year ending 31-Mar-2026) and the double unary -- converts TRUE/FALSE to 1/0. Formulas then combine logic by multiplication:

\[ x_t = (1 - F_t) \times \text{Actual}_t + F_t \times \text{Forecast}_t \]

so one formula serves every column of the row.

Explanation

Flags convert "which formula applies here?" from a cell-by-cell decision into data. Common flags:

Flag Formula Use
Actual =--(M$3<=Last_Actual_Year) Pick historical values
Forecast =1-M$4 Apply drivers
First forecast =M$5*(1-L$5) One-time items at the boundary (e.g., opening balances)
Phase flag =--(M$3>=Phase2_Start) Change of regime (maintenance capex, new tax regime)
Operation flag =--AND(M$3>=COD_Year,M$3<=End_Year) Plant or contract life
Stub flag / fraction =YEARFRAC(Valuation_Date,M$2) capped at 1 DCF stub
Event flag =--(M$3=Event_Year) One-off item in a specified year

Why multiplication rather than IF. =IF(M$5=1,Forecast,Actual) is acceptable and readable; multiplication is equally valid and works naturally with SUMPRODUCT (e.g., summing forecast years only: =SUMPRODUCT(M40:Q40,M$5:Q$5)). The essential point is that the same formula appears in every column; the flag value differs, not the formula. One caveat: with multiplication, an error in the unused branch (e.g., #DIV/0! in a forecast term during actual years) still propagates, since 0 × error = error; IF evaluates only the chosen branch. Guard the branch or use IF in such rows.

Flags as inputs to logic, not scenarios. Flags describe time; scenario selection is handled by the Live row (topic t6). Do not create "Bull flag" rows inside calculations.

One-off events. A management-guided one-off (e.g., ₹45 crore brand launch in FY27E) is an input row by year on Inputs — effectively its own flag. Alternatively, an event-year input and amount, combined with an event flag: =M$9*Launch_Cost.

Roll-forward. Because flags derive from Last_Actual_Year (or Last_Actual_End), updating that single input when new results arrive moves every flag, and every flagged formula switches automatically (topic t1, s03).

Illustration

Pidilite C&B revenue row using flags (Last_Actual_Year = 2025):

M50 = (1-M$5)*Hist!M12 + M$5*L50*(1+M48)*(1+M49)
FY24A FY25A FY26E FY27E
Forecast flag 0 0 1 1
Hist revenue 9,820 10,500 – –
UVG 9.0% 10.0%
Price/mix 2.0% 3.0%
Revenue 9,820.0 10,500.0 11,673.9 13,226.5

FY27E = 11,673.9 × 1.10 × 1.03 = 13,226.5. When FY26 actuals arrive and Last_Actual_Year becomes 2026, FY26 picks up Hist!N12 and FY27E grows from that actual — no formula edits.

Connections

The master timeline that hosts flags is topic t1 s03. Flags enable c01 (identical R1C1 formulas) and s03 (one formula per row) across the actual/forecast boundary, and s04's M$5 anchoring. Week 14's capex phases and Week 15's opening balances use first-forecast and phase flags; DCF stub periods use stub fractions (Week 16).

Practice Questions

Q1. Write the flags [L1]

For a timeline FY21A–FY30E with Last_Actual_Year 2025, a plant commissioning in FY28 and a valuation date of 30-Sep-2025, write the formulas for the actual, forecast, first-forecast, operation (from FY28) and stub-fraction rows, and state their values for FY26E and FY28E.

Q2. Error propagation through a flag [L2]

A DIO row uses =(1-M$5)*(M45/M41*365)+M$5*Inputs!M71. In FY26E–FY30E, COGS (M41) is linked to a row that is blank in forecast years on that sheet. Explain what happens and give two ways to fix it.

💡 Hint: Consider what 0 multiplied by an error value returns in Excel.

Q3. Replace typed overrides with flags [L2]

A Trent model has typed one-off pre-opening costs of ₹60 crore in FY27E and ₹40 crore in FY29E within the store-opex row. Redesign using Inputs and flags so the row has one formula, and describe how a reviewer would see that the one-offs exist.
