Roadmap topic: Managing Interest Circularity Safely: Understanding average debt balance interest circularity, iterative calculation settings, and building a circuit-breaker toggle

Overview

Once the debt schedule (t3) calculates interest on the average of opening and closing balances, and the closing balance depends on how much cash the business generated after paying that interest, the model contains a genuine logical loop. Interest reduces PAT, PAT reduces cash flow, lower cash flow means a larger revolver draw or a smaller sweep, which raises closing debt, which raises average debt, which raises interest. A second, smaller loop runs through interest income on the average cash balance. Excel cannot resolve such a loop with its normal dependency-tree recalculation; it either flags a circular-reference warning or, if iterative calculation is enabled, recalculates the loop repeatedly until the values stop moving.

For FP&A, equity research and transaction-modelling roles in India, the circularity question is unavoidable. Sell-side and investment-banking models built for NSE-listed companies, LBO models for PE funds and lender base cases for project finance all have to decide whether to accept the loop or design it out. The answer is not only technical: model-review houses following the FAST Standard and the ICAEW Financial Modelling Code discourage circularity, while most banking teams accept it under control. Either way, the reviewer expects three things — the loop is deliberate and documented, there is a circuit-breaker that can switch it off instantly, and there is evidence that the iteration has actually converged.

The learning sequence in this topic is: map the main loop (s01) and the secondary cash-interest loop (s02); set Excel's iteration parameters correctly and understand that they are application-wide (s03, c03); build the breaker switch that collapses interest to opening-balance or zero (s04, c01); know the alternatives — opening-balance interest, closed-form algebra and the copy-paste macro (s05, c02); understand the professional debate on whether circularity is acceptable (s06) and quantify the materiality of choosing average over opening (c04); and finally, drill the recovery routine for when an error value is trapped inside the loop (s07), backed by a convergence check (c05).

Related concepts to study

Revolver and sweep create the circular path

→ Week 14 (w14_t3): revolver and sweep create the circular path

Average-balance interest alone on a fixed term loan with a scheduled repayment is not circular: opening and closing balances are both known before interest is computed. The loop only appears when closing debt depends on cash generated after interest — that is, when a revolver draws on deficits or a cash sweep prepays from surplus. Study the t3 formulas MIN(MAX(-Rev_Open,-Cash_Avail),Rev_Limit-Rev_Open) and the sweep MIN cap alongside this topic: they are the cells that close the loop, and they are also the cells that must stay well-behaved (bounded, non-negative) during iteration, otherwise oscillation and divergence follow.

VBA basics and calculation modes

→ Phase 3 (W9–12): VBA basics and calculation modes

The copy-paste macro (c02) and any automated breaker reset rely on the VBA covered in Phase 3: Application.Calculate, Application.Iteration, Application.Calculation = xlCalculationManual, Range.Value assignment for paste-values, and Do…Loop with an exit condition. Equally relevant is the difference between automatic, automatic-except-data-tables and manual calculation modes. A model set to manual calculation with iteration enabled behaves very differently from an automatic one — values only converge when F9 is pressed repeatedly. Revisit those modules so that the macro approach is something you can write and debug, not just copy.

Turn breaker off before debugging imbalances

→ Week 15 (w15_t4): turn breaker off before debugging imbalances

When the balance sheet fails to balance in Week 15, the first diagnostic step is to set the circularity switch to off. With the loop collapsed, every cell has a deterministic, single-pass value; if the imbalance persists it is a linking error (sign, missing line, wrong period), not an iteration artefact. If the imbalance vanishes when the breaker is off, the problem is inside the loop — usually non-convergence, a trapped error, or a cell that should have been inside the breaker but references average debt directly. This sequencing saves hours of chasing phantom differences.

Circularity slows and destabilises data tables

→ Week 16 (w16_t5): circularity slows and destabilises data tables

Excel data tables recalculate the whole model once per input combination. With iteration on, each of those recalculations runs up to the iteration limit, so a 7 × 7 WACC-growth sensitivity table can mean 49 × 100 loop passes. Worse, data tables and iteration interact unpredictably: cells may display values from a partially converged state. Week 16 recommends switching the breaker to opening-balance interest (or using a macro-driven sensitivity) before running data tables, and checking that the base case in the table matches the live model output.

Common pitfalls

Iteration left on globally, hiding unintended circular references elsewhere

The mistake: the analyst enables iterative calculation once for the debt schedule and never turns it off. Because Excel suppresses the circular-reference warning whenever iteration is on, any accidental circularity created later — a tax cell that references PAT, a cash line linked to itself, a working-capital driver referencing the balance sheet total — is silently iterated instead of being flagged. Why it happens: the setting is buried in Options and it is application-wide (c03), so it also silently persists across every workbook opened in the same session. Correct treatment: keep exactly one intended loop, gated by a breaker; periodically switch iteration off (with the breaker off) and confirm Excel reports no circular references — Formulas → Error Checking → Circular References should be greyed out. Review detection: with the breaker off and iteration disabled, any circular-reference warning that appears is an unintended loop.

No breaker, so one error locks the model and tempts hardcoded fixes

The mistake: interest is written directly as =Rate*AVERAGE(Open,Close) with no switch. When a #REF! or #DIV/0! enters the loop (a deleted row, a zero denominator in a ratio inside the cash flow), it propagates around the loop and every iteration feeds the error back in — the model never recovers even after the original cause is fixed. Why it happens: the breaker looks like an optional nicety during the build. Correct treatment: always route interest through a breaker (c01), and follow the recovery procedure (s07). Review detection: search the debt tab for interest formulas that reference closing balances without an IF on a switch cell; look for hardcoded interest numbers in forecast columns — they are usually the scar of an earlier lock-up "fixed" by typing values.

Assuming convergence without checking that interest stops changing

The mistake: the analyst sees numbers instead of errors and assumes the loop has solved. In fact the iteration may have hit the 100-iteration cap while still oscillating, or a revolver that flips between draw and repay may be cycling. Why it happens: Excel gives no message when the maximum iteration count is reached without meeting the maximum-change criterion. Correct treatment: build a convergence check (c05) — compare live interest with a paste-values helper row or with the opening-balance version, and flag any difference above tolerance; press F9 a few times and see whether results move. Review detection: a check row on the Checks tab showing absolute change in total interest after one extra recalculation; any non-zero value beyond ₹0.001 crore fails.

Practice Questions

Q1. Mapping and quantifying a revolver loop [L2]

Sahyadri Retail Ltd's FY27E model has: opening term loan ₹600 crore, scheduled repayment ₹100 crore, fixed rate 9.0%; revolver limit ₹250 crore, opening revolver ₹40 crore, rate 9.5%, commitment fee 0.35% on undrawn average; minimum cash ₹50 crore; opening cash ₹80 crore; EBITDA ₹310 crore, D&A ₹95 crore, tax rate 25.168%, capex ₹260 crore, increase in NWC ₹45 crore, dividends ₹30 crore; interest income 6% on average cash. (a) Draw the dependency chain for interest, naming every cell type in the loop. (b) Compute FY27E interest using opening balances only. (c) Explain qualitatively the direction in which average-balance interest will move the revolver closing balance relative to the opening-balance case, and estimate the magnitude using the c04 approximation. (d) State which two cells are the "closure" points of the loop.

💡 Hint: For (c), first work out the revolver movement under opening-balance interest, then use Rate × ΔDebt ÷ 2 per tranche.

Q2. Designing a breaker and a convergence check [L3]

You inherit a lender base-case model for a 120 MW solar SPV with a DSRA, a cash sweep of 75% of excess cash and average-balance interest on senior debt. There is no breaker; iteration is set to 1,000 iterations and maximum change 0.1. (a) Specify the switch cell, its location and the three states you would support. (b) Write the interest formula for one period using named ranges. (c) Specify the iteration settings you would change and why. (d) Design a two-row convergence check and its tolerance, and explain where it sits in the Checks tab. (e) Describe what you would tell the client about the DSCR covenant test if the breaker is left on "opening-balance" mode in the delivered file.

Q3. Trapped error under deadline [L2]

At 11 pm before an investment-committee submission, a colleague deletes a helper column on the Working Capital tab. The entire Debt, Tax, P&L, BS and CFS tabs now show #REF!. Undo is no longer available because the file was saved and reopened. Iteration is enabled, 100 iterations, max change 0.001, and the model has a breaker cell on the Cover tab. (a) Write the step-by-step recovery procedure. (b) Explain why repairing the WC formula alone will not clear the errors. (c) Explain what you would check after recovery to prove the model is back to its pre-error state. (d) What control would you add so that this cannot happen silently again?

Q4. Choosing the method for a mandate [L3]

You are building three models in the same month: (i) an FP&A annual operating plan for a listed FMCG company with net cash and no revolver; (ii) a sell-side DCF for a leveraged cement company with a ₹1,500 crore term loan amortising 10% a year and a working-capital CC limit; (iii) a PE LBO with senior term loan, mezzanine NCDs with PIK, a revolver and 100% cash sweep. For each, recommend opening-balance interest, average-balance interest with iteration and breaker, closed-form algebra, or a copy-paste macro, referring to the FAST/ICAEW stance, the materiality approximation and the use of data tables. Justify the documentation note you would put on each Cover tab.
