Key concept

Iterative Calculation Is an Application-Level Setting

Concept: Iterative calculation is an application-level setting; it follows whichever workbook opened first

Statement

Excel holds one set of calculation options — calculation mode (automatic / automatic except tables / manual), iteration on/off, maximum iterations and maximum change — for the Excel application session, not for each workbook. Each workbook stores the settings in effect when it was last saved, but on opening, Excel adopts the stored settings of the first workbook opened in the session; workbooks opened afterwards inherit the session's current settings. Changing the setting while any workbook is open changes it for all open workbooks.

Explanation

Consequences:

  1. Open a non-circular client file first (saved with iteration off), then your circular model: iteration is off, Excel raises a circular-reference warning and the loop does not calculate — your interest may show zero or stale values.
  2. Open your circular model first (iteration on), then a client's file: the client's file now iterates silently. Any accidental circular reference in it is not flagged — a hidden risk for the other workbook's owner.
  3. Save the client's file while iteration is on: the file now stores iteration on, propagating the setting to whoever opens it first next time.
  4. Calculation mode behaves the same way: a manual-calculation workbook opened first makes every subsequently opened workbook manual — a classic cause of "numbers not updating".

Separate Excel instances. Two Excel instances (separate processes) have independent settings. On Windows, starting a new instance (e.g., holding Alt while launching Excel and confirming the prompt in recent versions) isolates a circular model from other files. Behaviour varies by version; test it on your setup rather than relying on it.

Controls:

  • A Cover-tab instruction stating required settings and the order in which to open files.
  • A breaker in opening-balance mode as the default state for files distributed widely, so the model works whatever the session setting.
  • A Workbook_Open macro (in .xlsm files) that sets Application.Iteration = True, MaxIterations = 100, MaxChange = 0.001 and displays a message; and a Workbook_BeforeClose macro restoring the user's prior settings. Some organisations consider auto-changing application settings intrusive — agree the approach with the client.
  • A Checks-tab flag: a deliberate tiny test loop or a convergence check (c05) that fails if iteration is not active while the breaker is on.

Illustration

An FP&A analyst at a Pune auto-component company opens the group's consolidation workbook (saved with manual calculation and iteration off) at 9 am, then opens the debt model with the revolver loop and breaker set to 1. The debt model shows a circular-reference warning; the P&L interest line shows ₹0.0 crore for FY27E–FY30E because the loop never evaluated; the analyst copies EBITDA-to-PAT figures into a board pack. Total finance costs are understated by ₹46 crore across the four years. Root cause: settings inherited from the first workbook. The fix is to close all workbooks, open the debt model first (or enable iteration manually), press F9, verify the convergence check, then open the consolidation workbook — and to flag in the consolidation workbook that it is now iterating.

Practice Questions

Q1. Predict the behaviour [L1]

Workbook A (circular, saved with iteration on, 100/0.001) and workbook B (non-circular, saved with iteration off, manual calculation). Describe Excel's settings and the behaviour of each workbook if (a) A is opened first, then B; (b) B is opened first, then A; (c) B is saved after scenario (a).

Q2. Design an opening routine [L2]

Write the VBA event procedures (or detailed pseudocode) that a circular model would use to store the user's prior settings on open, set iteration parameters, warn the user, and restore the prior settings on close. Discuss one objection a client's IT team might raise.

💡 Hint: Store the prior values in module-level variables or hidden named cells.

Q3. Root-cause a board-pack error [L3]

A board pack shows FY27E interest of zero while the debt schedule shows ₹31 crore when opened today. List the possible explanations involving session-level settings, describe how you would reproduce the error, and recommend permanent controls.
