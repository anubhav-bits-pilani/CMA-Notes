Heat-Map Formatting with the Base Case at the Centre

Scope: Heat-map conditional formatting, base case highlighted at centre

Why it matters

A 5×5 grid of ₹ values contains 25 numbers. Readers in an IC meeting or a client deck absorb it in a few seconds only if the formatting tells the story: where the base case is, which direction is "better", and where the value crosses CMP or turns invalid. Heat maps do this visually. A highlighted centre cell also acts as a control, because it proves the table is wired correctly and centred on the live base case. Poor formatting is a common review comment. Examples are a colour scale anchored on extreme corners that hides differences near the base, a centre highlight that drifts off-centre when inputs change, or inconsistent number formats.

Core notes

Colour scales

Use Home → Conditional Formatting → Color Scales → More Rules.

Grid Scale type Anchors Colours
Implied price (Grids 1–3) 3-colour Min = lowest value; Midpoint = number, base value (link to the centre or the model output); Max = highest Red → white → green (or a light single-hue scale for print)
Upside % 3-colour, diverging Min; Midpoint = number 0; Max Red below 0, green above 0
EV (Grid 3) 3-colour Midpoint = base EV Same as price
Implied g / TV % rows 2-colour or rules Threshold at the cap (e.g. g > Rf flagged) Amber or red flags

Setting the midpoint to the base value (rather than the 50th percentile) makes the colouring symmetric around the base case, even though the grid's values are not symmetric because of Gordon non-linearity. Excel allows a cell reference as the midpoint value, for example =$K$23 pointing to the centre or to Implied_Price.

Base-case highlight that stays centred

Hardcoding a bold border on the centre cell fails as soon as the axes move. A formula-based rule is robust. Select the body of the grid I21:M25 and add a "Use a formula" rule:

=AND(ROUND(I$20,6)=ROUND($D$5,6), ROUND($H21,6)=ROUND($D$6,6))

The rule applies bold, a thick border and a contrasting fill. Here I$20 is the column header (WACC offset), $H21 is the row header (g offset), and D5 and D6 hold the base offsets (0). With absolute-value axes, compare against the base WACC and g cells instead. ROUND guards against floating-point mismatches such as 0.115 stored as 0.11499999.

Place this rule above the colour scale in the Conditional Formatting Rules Manager, and set it to override fill.

CMP threshold highlight

For price grids, add a rule that outlines (rather than fills) cells below CMP:

=I21<CMP

Alternatively, add a dashed border on the cells where the value crosses CMP. Readers can then trace the "break-even" frontier.

Invalid and n.m. cells

Presentation grids (concept c04) show "n.m." where g ≥ WACC or the output is an error. Format these grey and exclude them from the colour scale. Colour scales ignore text, but check that the min and max anchors are not distorted by extreme valid values next to the invalid zone.

Number formats and labels

  • Price: ₹ #,##0 (no decimals unless prices are below ₹ 100).
  • Upside: 0%;[Red]-0%.
  • Headers: WACC 0.0%, g 0.0%, multiple 0.0"x".
  • Axis labels: "WACC →" above the row headers, "Terminal growth ↓" beside the column headers. Add a title with the output, scenario and date, for example ="Implied price (₹/share) – "&Scenario_Name&" – "&TEXT(Val_Date,"dd-mmm-yyyy").
  • Footnote: TV method, mid-year convention, Ind AS 116 basis, CMP and its date, and whether dilution flexes per cell.

Print and deck readiness

  • Choose colours that remain readable in greyscale, such as a single-hue blue scale for print.
  • Paste into PowerPoint as a linked picture or an "Excel table object", or rebuild the table in PowerPoint with the values, never as a stale screenshot without a date.
  • In Power BI, a matrix visual with background-colour conditional formatting (field value or gradient) replicates the heat map for dashboards.

Worked example: rules for Shakti Grid 1

Rule (in priority order) Applies to Format
1. Base cell: =AND(ROUND(I$20,6)=0, ROUND($H21,6)=0) I21:M25 Bold, dark border, white fill
2. Text "n.m." I21:M25 (presentation grid) Grey fill, grey font
3. Below CMP (₹ 405) I21:M25 Red dashed border
4. 3-colour scale, midpoint = number =$K$23 I21:M25 Red–white–green

With a CMP of ₹ 405, no cell falls below CMP (the minimum is ₹ 423), so rule 3 is dormant. That fact is itself informative.

Edge cases & judgement calls

  • Colour-blind accessibility. Red–green scales are problematic. Use blue–white–orange, or add symbols.
  • Over-formatting. More than three rules confuses readers. Prioritise the base highlight, the colour scale and the CMP boundary.
  • Copying grids. Conditional formats with relative references shift when copied. Re-check the "Applies to" ranges after copying.
  • Data-table body. You can format the TABLE() body cells normally. Conditional formatting works on them.
  • Mixed outputs. Do not apply one colour scale across a price grid and an upside grid together. Each needs its own anchors.

Key takeaways

  • Use 3-colour scales with the midpoint fixed at the base value (price) or at zero (upside).
  • Highlight the base case with a formula rule linked to the input cells, with ROUND, so the highlight stays centred.
  • Add a CMP boundary and grey out n.m. cells. Keep rules to three or four.
  • Titles and footnotes must state the scenario, date, TV method and basis.
  • The formatting also acts as a control: an off-centre highlight or odd colouring signals wiring problems.
