Calculation Mode and F9 Refresh Discipline for Data Tables

Scope: Calculation mode "Automatic except for data tables" and F9 refresh discipline

Why it matters

Every cell of a data table triggers a full model recalculation. A 5×5 grid means 25 recalculations, and four grids mean 100, every time any cell in the workbook changes. In a Project 4/5 integrated model with a debt schedule, scenario switch, TSM dilution and a circularity, this turns every keystroke into a multi-second wait. Excel's answer is the calculation mode "Automatic except for data tables". It keeps the model live but freezes the grids until you refresh them. The risk is the opposite problem: grids that silently show results from yesterday's inputs or from a different scenario. Calculation-mode discipline, meaning the setting, the refresh keys and a visible status check, is what separates professional models from fragile ones.

Core notes

The three calculation modes

Set the mode via Formulas → Calculation Options, or File → Options → Formulas → Workbook Calculation.

Mode Model cells Data tables When to use
Automatic Recalculate on every change Recalculate on every change Small models, or final checks
Automatic except for data tables Recalculate on every change Recalculate only on F9 / Calculate Now / Calculate Sheet Default for valuation models with grids
Manual Recalculate only on F9 Only on F9 Very large models. Risky for everyday work

Key behaviours:

  • The calculation mode is an application-level setting, taken from the first workbook opened in the session and saved with the workbook. Opening a manual-mode file first can switch all open workbooks to manual. Check the status bar for "Calculate".
  • "Recalculate workbook before saving" (in Manual mode options) can be ticked to reduce staleness risk.

Refresh keys

Key Effect
F9 Calculate all open workbooks, including data tables in "automatic except tables" mode
Shift+F9 Calculate the active sheet only, including its data tables
Ctrl+Alt+F9 Full calculation of all formulas, regardless of dirty status
Ctrl+Shift+Alt+F9 Rebuild the dependency tree, then full calculation. Use it when results look wrong after structural changes

Discipline protocol

  1. Default setting. Save the model in "Automatic except for data tables". Note it in the cover-sheet instructions.
  2. Status cell. Next to each grid, add a check =IF(ROUND(K23,2)=ROUND(Implied_Price,2),"Grid current","STALE – press F9"), where K23 is the centre cell. This uses concept c02, the centre-cell proof, as a freshness test. Show it in red via conditional formatting when stale. The check compares a frozen table value with a live model value, so it detects staleness immediately.
  3. Master check. Roll all grid status cells into the model's master check (=AND(...)) on the cover sheet.
  4. Before publishing. Press F9, confirm all grid checks show "current", confirm the scenario label, then copy values or a linked picture to the deck.
  5. Scenario runs. After toggling the scenario switch, press F9 before reading any grid. For a set of scenario grids, use a small macro that loops over the scenarios, calculates and pastes values to a static "Sensitivity Pack" sheet with timestamps.
  6. Circularity state. Set the breaker as concept c05 requires before refreshing.

Speed management

  • Keep tables small (5×5) and limit the number of live tables. Derive the upside grids from the price grids by formula rather than with extra tables (s04).
  • Avoid volatile functions (OFFSET, INDIRECT, NOW) in the calculation chain.
  • Replace iterative TSM with the closed form, and use a circularity breaker for average-balance interest when running tables.
  • Remove unused full-column references such as A:A in SUMIFS within the model chain.
  • Use "Calculate Sheet" (Shift+F9) on the DCF sheet for quick checks when only that sheet's tables matter.
  • Excel's multi-threaded calculation helps less with data tables, which are evaluated largely sequentially.

Illustration: timing impact

A Project 5 workbook has 3 statements, a debt schedule with average-balance interest (circular, iterative), the TSM and four 5×5 tables.

Setting Time per edit Risk
Automatic, iterative on ~25–40 s Usable only for final runs. Tables may not converge
Automatic except tables, iterative on < 1 s per edit; ~30 s on F9 Stale tables if F9 is forgotten
Automatic except tables, breaker on (non-circular), TSM closed form < 1 s per edit; ~6 s on F9 Lowest. Status checks catch staleness

The timings are illustrative orders of magnitude for a mid-size model on a standard laptop.

Edge cases & judgement calls

  • Shared workbooks / SharePoint co-authoring. Calculation settings travel with the first-opened file. Collaborators may open in Automatic mode and experience slowness, or in manual mode and see stale numbers. Document the setting on the cover sheet.
  • Excel for the web supports data tables with limited control over calculation mode. Test before sharing web links to grid outputs.
  • VBA macros that change the calculation mode (Application.Calculation = xlCalculationSemiautomatic) must restore the user's setting at the end and on error.
  • Linked decks. Pasted-link charts and tables in PowerPoint update from the workbook's last calculated state. Refresh before updating links.
  • Audit trail. For external reports, archive a values-only copy of the grid with the date, scenario and model version.

Key takeaways

  • "Automatic except for data tables" keeps the model responsive and freezes the grids until F9.
  • F9 or Shift+F9 refreshes the tables. Ctrl+Alt+F9 forces a full recalculation, and Ctrl+Shift+Alt+F9 rebuilds dependencies.
  • A centre-cell status check next to each grid turns staleness into a visible error.
  • Run tables with the circularity breaker on and closed-form dilution for speed and stability.
  • Pre-publication protocol: F9, check all grid flags, confirm the scenario label, then export.

Practice Questions

Q1. Status-check build [L1]

Write the formula and conditional-format rule for a grid status cell, where the grid centre is K23, the model output is DCF!$E$40, and you want "Current" in green or "STALE – press F9" in red. Explain why this check detects staleness only for the centre cell. State what additional check would confirm that off-centre cells are current.

Q2. Calculation-mode incident [L2]

An analyst sent a deck with a WACC × g grid showing a base price of ₹ 610, while the model's DCF output was ₹ 574 after a late WACC update. The workbook was in "Automatic except for data tables" mode. Write a short incident note covering the root cause, why the error was not caught, and the controls that will prevent recurrence.

💡 Hint: Think about which cells recalculated after the WACC change, and which did not.

Q3. Scenario pack macro specification [L3]

Specify (in pseudocode or step list, not full VBA) a macro that, for each of three scenarios (Base, Bull, Bear):

  • sets the scenario switch
  • turns the circularity breaker on
  • calculates
  • copies Grids 1–4 as values to a "Sensitivity Pack" sheet with scenario labels and a timestamp
  • restores the original scenario, breaker and calculation mode

Include error handling.

Q4. Speed optimisation review [L2]
