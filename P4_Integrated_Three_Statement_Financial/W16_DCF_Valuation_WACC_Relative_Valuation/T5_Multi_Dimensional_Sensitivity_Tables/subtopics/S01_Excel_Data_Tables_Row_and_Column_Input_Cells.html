Excel Data Tables: Row and Column Input Cells

Scope: Excel What-If → Data Table with row and column input cells

Why it matters

The Data Table is the only native Excel feature that recalculates an entire model for many input combinations and returns the results to a grid without VBA. Every DCF sensitivity grid in Project 5 depends on it. So do FP&A budget flex tables and covenant-headroom matrices. It is also a frequent source of silent errors: swapped inputs, non-flexing models and stale values. Knowing exactly how Excel evaluates a data table lets you build grids that reviewers can trust, and diagnose broken ones quickly.

Core notes

What a data table does

A data table is a block of cells governed by the array function {=TABLE(row_input, column_input)}. For each cell in the body of the table, Excel does the following:

  1. Temporarily substitutes the value in the table's top row (for that column) into the row input cell.
  2. Temporarily substitutes the value in the table's left column (for that row) into the column input cell.
  3. Recalculates the model.
  4. Reads the formula in the table's top-left corner cell, which references the output.
  5. Writes the result into the body cell, then restores the original inputs.

None of the substitutions are visible. The model's own cells keep their base values throughout.

One-variable vs two-variable tables

Type Layout Dialog entries
1D, values down a column Input values in a column; output formula(s) in the row above, one cell to the right Column input cell only
1D, values across a row Input values in a row; output formula(s) in the column to the left, one row below Row input cell only
2D Row values across the top, column values down the left side, single output formula in the top-left corner Both row and column input cells

A 1D table can return several outputs at once, for example implied price, EV and upside as three columns. A 2D table returns exactly one output.

Step-by-step build (2D)

  1. On the DCF sheet, confirm that the model's WACC and g are each driven by one input cell, for example DCF!$D$5 for WACC and DCF!$D$6 for g. The inputs must be on the same sheet as the table (concept c03).
  2. Lay out the grid. Put the corner cell at H20, with WACC values in I20:M20 and g values in H21:H25.
  3. In H20 enter =Implied_Price, the link to the model's output cell. Either leave it visible, or give it a custom number format that displays only a label, such as "g ↓ / WACC →". A quoted-text format replaces the displayed number while keeping the live value underneath.
  4. Select H20:M25, the whole block including headers.
  5. Go to Data → What-If Analysis → Data Table.
  6. Row input cell: $D$5 (WACC, because the WACC values are across the top row). Column input cell: $D$6 (g, because the g values are down the left column).
  7. Click OK. Excel writes {=TABLE(D5,D6)} into I21:M25.

Rules of the TABLE() array

  • The body cells form a single array, so you cannot edit or delete individual cells. To delete the table, select the whole body and press Delete.
  • The table body cannot be moved separately from its headers. Cut the entire block to move it.
  • Input values in the headers can be constants or formulas. Formulas are useful for centring the axes on the base case (s02). However, header formulas must not depend on the input cells themselves, or the substitution will change the headers mid-calculation.
  • The corner formula can be any cell that depends on the inputs: price, EV, upside, or a check value.
  • Data tables recalculate on every recalculation of the workbook unless the calculation mode excludes them (s06).

Axis design: absolute values vs offsets

There are two robust designs.

Design Input cell holds Header values Pros / cons
Absolute WACC used by the model (a hardcoded input on the DCF sheet, e.g. 12.0%) 11.0%, 11.5% … 13.0% Simple. But the WACC tab's calculated value must be copied or linked into the driver, and the headers must be re-centred when WACC changes
Offset A sensitivity delta, base = 0 bp. Model WACC = WACC!C25 + DCF!D5 −1.0%, −0.5%, 0, +0.5%, +1.0%, with a separate display row showing base + offset Grid always centred. The WACC tab stays live

The offset design suits the Project 5 requirement that grids stay live to the scenario switch.

Alternatives when data tables are unsuitable

  • Manual flex macro. A VBA loop sets inputs, calculates and pastes values. It is faster in very large models and leaves static output, but it must be re-run.
  • Scenario Manager. Discrete cases only.
  • Google Sheets has no native data tables. Use add-ons, or replicate the logic with a closed-form DCF for each cell, which is only feasible when the model is simple.
  • Power BI what-if parameters work on DAX measures (topic overview).

Edge cases & judgement calls

  • Tables on a separate "Sensitivity" sheet fail ("Input cell reference is not valid") because inputs must be on the table's sheet. Place the tables on the DCF sheet, or move the driver cells to the sensitivity sheet and have the DCF reference them.
  • Volatile functions (OFFSET, INDIRECT, TODAY) in the model make every recalculation, and every table cell, slower.
  • Very large tables (for example 21×21) multiply recalculation time. Keep grids at 5×5 or 7×7.
  • Outputs that depend on iterative calculation may not converge within each substitution. Run with the breaker on (concept c05).
  • Protected sheets. Data tables still calculate, but cannot be edited without unprotecting the sheet.

Key takeaways

  • A 2D data table substitutes the top-row values into the row input cell and the left-column values into the column input cell, then reads the corner formula.
  • Input cells must be on the same sheet as the table, and every model use of the variable must flow through them.
  • The table body is a locked TABLE() array: edit it as a block, and never let the header formulas depend on the inputs.
  • Offset-style inputs keep grids centred and live to the WACC tab and scenario switch.
  • Data tables are recalculation-heavy. Manage the calculation mode deliberately.

Practice Questions

Q1. Dialog entries from a layout [L1]

A grid has exit multiples 8×–12× down B30:B34, WACC values 11%–13% across C29:G29, and =Price in B29. The WACC driver is in DCF!F4 and the exit multiple driver is in DCF!F7. State the Row and Column input cells. Write the array formula Excel will place in the body.

Q2. Offset design build [L2]

Design an offset-based WACC × g grid in which the WACC tab computes 11.8% and the base g is 5.25%. Specify:

  • the driver cells and their base values
  • the model formulas that consume them
  • the header values
  • the display header row
  • a check cell that confirms the offsets sum to zero in the base case

💡 Hint: The display row is for humans only. It is the offsets row that the table must read.

Q3. 1D multi-output table [L2]

Build a 1D table that shows implied price, EV, TV % of EV and upside for terminal growth rates of 4.0%–7.0% in 50 bp steps. Describe the layout, dialog entries and formatting. Explain why a 1D table can return multiple outputs but a 2D table cannot.

Q4. Interview: what is Excel actually doing? [L1]

An interviewer asks you to explain, step by step, what Excel does when it computes one cell of a two-variable data table, and why that makes data tables slow in large models. Answer in under two minutes.
