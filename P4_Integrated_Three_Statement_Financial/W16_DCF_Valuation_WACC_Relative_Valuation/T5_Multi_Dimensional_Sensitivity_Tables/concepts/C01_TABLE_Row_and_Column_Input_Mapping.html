Key concept

TABLE() Row and Column Input Mapping

Concept: {=TABLE(Row_Input,Col_Input)}: row input = variable across top, column input = variable down side

Statement

For a two-variable data table occupying range \(R\), with the corner cell at the top-left, the body is filled with:

{=TABLE(Row_Input_Cell, Column_Input_Cell)}
  • Row_Input_Cell is the model cell that receives the values listed across the top row of the table (the column headers).
  • Column_Input_Cell is the model cell that receives the values listed down the left column of the table (the row headers).
  • The corner cell contains the output formula, for example =Implied_Price.

For body cell \((i, j)\), Excel sets \(\text{Row\_Input} = h^{\text{top}}_j\) and \(\text{Column\_Input} = h^{\text{side}}_i\), recalculates, and returns the corner value.

Explanation

The naming is counter-intuitive. The "row input" is the variable whose values are laid out in a row, across the top, even though each value heads a column of results. A reliable mnemonic: the row input cell is filled from the header row; the column input cell is filled from the header column.

You cannot type TABLE() manually. Excel creates it through Data → What-If Analysis → Data Table. The function's first argument is always the row input and the second the column input. A 1D table has one argument blank: {=TABLE(,D6)} for values down a column, or {=TABLE(D5,)} for values across a row.

When the mapping is swapped, Excel substitutes the WACC-axis values into the g cell and vice versa. The grid still computes, but every cell answers a different question from its labels. Detection checks:

  • centre cell = model output (concept c02). This passes only if the base values are in the same relative positions on both axes. With symmetric axes and the base at the centre, the centre can pass even when the axes are swapped, so it is not sufficient on its own.
  • directional test. Price must fall moving right along a WACC axis and rise moving down a g axis (if g increases downward).
  • off-centre spot check. Set WACC and g manually to one corner's values and compare.
  • magnitude test. Along the exit-multiple axis, steps should be large. Along WACC in Grid 2, steps should be small (topic t5, s03).

Illustration

Layout: WACC 11%–13% in I20:M20 (across), g 4.5%–6.5% in H21:H25 (down), =Implied_Price in H20. WACC driver D5, g driver D6.

Dialog entry Correct Swapped
Row input cell $D$5 (WACC) $D$6 (g)
Column input cell $D$6 (g) $D$5 (WACC)
Formula created {=TABLE(D5,D6)} {=TABLE(D6,D5)}

Consider cell I21, labelled WACC 11.0% and g 4.5%. In the swapped version it actually computes g = 11.0% and WACC = 4.5%. With g > WACC, the Gordon formula gives a negative or nonsensical value. The top-left corner often reveals the swap immediately. For an offset design with symmetric offsets of ±1%, however, the swap gives plausible-looking but wrong numbers. That is why the directional test is essential.

Practice Questions

Q1. Write the formula [L1]

A grid has exit multiples in C31:C35 (down) and WACC values in D30:H30 (across). The exit multiple driver is DCF!G8 and the WACC driver is DCF!G5. Write the TABLE() formula that should appear in the body. State the dialog entries.

Q2. Detect a swap with symmetric offsets [L2]

An offset grid uses WACC offsets of −1%, −0.5%, 0, +0.5%, +1% across and g offsets with the same values down. The centre equals the model output. Describe two tests that would reveal whether the inputs are swapped. Explain why the centre-cell test alone cannot.

💡 Hint: Consider which direction value should move along each axis.

Q3. 1D multi-output mapping [L1]

You list terminal growth values in B41:B47 and put three output formulas (price, EV, upside) in C40:E40. Which input box do you fill, and with which cell? Write the resulting TABLE() formula.
