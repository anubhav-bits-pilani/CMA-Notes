Key concept

Centre Cell Must Equal Model Output

Concept: Centre cell must equal model output exactly, proving table wiring

Statement

For a sensitivity grid whose axes are centred on the base-case inputs \((x_0, y_0)\):

\[ T(x_0, y_0) = f(x_0, y_0) = \text{Model output} \]

where \(T(x_0, y_0)\) is the table value at the centre cell and \(f\) is the model's live output, such as implied price. Implement the check as:

=IF(ABS(Centre_Cell - Model_Output) < 0.005, "OK", "CHECK GRID")

Explanation

The centre-cell test is the cheapest and most powerful control on a data table. It fails in each of these cases:

  • Axes not centred on the base. Headers are hardcoded and the base has moved, for example WACC updated from 12.0% to 12.3%.
  • Stale table. The workbook is in "Automatic except for data tables" mode, inputs have changed, and F9 has not been pressed (s06).
  • Model does not flow through the input cell. If WACC is hardcoded, or referenced from another cell, the table shows a constant. The centre might accidentally pass if the constant equals the output, but the whole grid would then be flat, which the directional checks catch.
  • Corner formula references the wrong output, for example price before dilution, or EV instead of price.
  • Circularity non-convergence. If iterative calculation is on, table cells may stop at different iteration states from the main model.

It does not catch symmetric swapped axes (concept c01), or errors elsewhere in the model, which would be reflected identically in both the table and the output.

"Exactly" means within rounding tolerance. The table and the model compute the same formula chain, so any difference beyond floating-point noise indicates a wiring or staleness problem. Use a tolerance of ₹ 0.005, or compare with ROUND. A difference of a few paise usually signals iteration effects. Investigate it.

The centre cell is also the anchor for presentation (s05). The heat-map midpoint and the base-case highlight both key off it. A broken centre means the formatting is misleading too.

The fourth row shows why the centre test should be paired with a flex check:

=IF(MAX(I21:M25)-MIN(I21:M25)>0,"Flexes","FLAT GRID")

Connections

  • This check underpins the subtopic s06 freshness check and the s05 highlight rule.
  • It addresses the topic pitfalls on hardcoded WACC (flat grids) and stale grids.
  • It pairs with concept c01 (directional tests for swapped axes).
  • In model audit practice (FAST and ICAEW model-review standards), every sensitivity output should reconcile to the base model. The centre cell is that reconciliation.
  • In FP&A, the same principle applies to budget flex tables: the base column must equal the approved budget.

Practice Questions

Q1. Build the control block [L1]

For a grid with body I21:M25, centre K23 and model output DCF!$E$40, write three check formulas: the centre match, the flex check, and a directional check that price decreases from I23 to M23. Combine them into a single grid status cell.

Q2. Diagnose from symptoms [L2]

A grid's centre shows ₹ 702 and the model shows ₹ 702. Within each column every cell is identical. Values vary only from column to column, and column K is ₹ 702 throughout. The WACC axis is across the top and g is down the side. What is the likely wiring error, and how would you confirm it?

💡 Hint: Constant down a column means the column-input variable is not affecting the output.

Q3. Interview: one check you always run [L1]

An interviewer asks what single check you would run on a colleague's DCF sensitivity table before it goes to a client. Name it, explain what it catches and what it misses, and say what you would add.
