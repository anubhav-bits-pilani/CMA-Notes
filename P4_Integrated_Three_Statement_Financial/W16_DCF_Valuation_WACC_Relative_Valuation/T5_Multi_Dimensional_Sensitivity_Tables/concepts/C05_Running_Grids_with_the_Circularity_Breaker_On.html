Key concept

Running Grids with the Circularity Breaker On

Concept: Run grids with breaker in non-circular mode for speed and stability

Statement

If the model contains a circular reference, for example interest computed on average debt where debt depends on cash after interest, or TSM dilution based on the implied price, then set the circularity breaker to its non-circular mode before running data tables:

\[ \text{Interest}_t = \begin{cases} r \times \frac{D_{t-1} + D_t}{2} & \text{breaker} = 1 \ \text{(circular, iterative)} \\ r \times D_{t-1} & \text{breaker} = 0 \ \text{(non-circular, opening balance)} \end{cases} \]

Here \(r\) is the interest rate and \(D_{t-1}\), \(D_t\) are opening and closing debt. Use the same pattern for dilution: replace the iterative TSM with the closed form (topic t4, c03).

Explanation

Why circularity and data tables don't mix. Each table cell requires a full recalculation. Under iterative calculation, each recalculation runs up to Maximum Iterations passes, typically 100. A 5×5 table can therefore trigger thousands of passes. Two problems follow.

  • Speed. Grids become unusably slow.
  • Stability. Iterations may stop at Maximum Change before full convergence. Results then differ slightly between table cells and the main model, so the centre-cell check fails by small amounts. A #NUM! or #DIV/0! error anywhere in the loop can also propagate and persist. Excel's iterative engine does not self-heal after an error enters the loop, so a reset requires the breaker.

Does the breaker distort valuation? For a DCF based on FCFF, interest does not enter FCFF at all. It affects only net debt via cash, and only through the forecast balance sheet, not through EV. The valuation-date net debt in the bridge is a historical balance. Setting the breaker to opening-balance interest therefore usually has no effect on EV, and only a second-order effect on forecast cash and debt. Verify this. With the breaker on and off, the base implied price should be identical, or differ only immaterially.

Where WACC weights are derived from the model's own equity value (circular WACC), use target weights for grids (topic t2, s06).

Implementation:

  1. Place a Circ_Breaker cell on the cover or control sheet (1 = circular, 0 = off).
  2. In the debt schedule, write the interest formula as =IF(Circ_Breaker=1, r*AVERAGE(Open,Close), r*Open).
  3. In the TSM: when Circ_Breaker=0, use the closed-form price. When it is 1, use iteration with the implied price.
  4. Add a check that compares the price with the breaker on and off, using a stored value, and flags differences above, say, ₹ 0.5.
  5. Protocol for running the tables: set the breaker to 0, press F9, confirm the grid checks, export, then restore the breaker if desired.

Connections

  • It links to the Week 14–15 debt schedules, where the average-balance interest circularity originates.

  • In FP&A models, the same breaker approach keeps budget flex tables stable when interest income on cash balances is modelled.

Practice Questions

Q1. Breaker formula and check [L1]

Write the interest formula for a debt schedule with opening debt in F40, closing debt in G40, rate in $D$12 and breaker in Control!$C$3. Write a check cell that stores the breaker-on price (pasted as a value) and compares it with the live breaker-off price, with a ₹ 0.50 tolerance.

Q2. Error persistence [L2]

During a data-table run with iterative calculation on, one grid cell produced #NUM! because a negative cash balance fed a LN() in an interest-income formula. Afterwards, the whole model shows #NUM! even with the base inputs restored. Explain why this happens, and describe the steps to recover using the breaker.

💡 Hint: Think about what an iterative loop does with an error value from the previous pass.

Q3. When the breaker is not neutral [L3]

Describe a valuation model where switching interest from average to opening balance would materially change the implied share price. Consider an FCFE valuation of a highly levered infrastructure company, and a model where WACC weights are endogenous. Explain how you would run sensitivities in that case.
