Roadmap topic: Multi-Dimensional Sensitivity Tables: 2D Data Tables for Implied Share Price across WACC vs Terminal Growth Rate and WACC vs Exit Multiple

Overview

A DCF produces a single number from dozens of judgemental inputs. The two that dominate are the discount rate and the terminal assumption, either perpetuity growth or exit multiple. Together they typically drive 60–80% of EV through the terminal value. A professional valuation therefore never presents a point estimate alone. It presents a range, generated by flexing the key drivers in a two-dimensional grid. Excel's What-If Data Table is the standard tool. It recalculates the full model for every combination of a row input and a column input, and returns the chosen output (implied share price, EV or upside) in a grid.

For the target roles, these grids appear everywhere: sell-side initiation reports, fairness opinions, board papers for acquisitions, impairment testing under Ind AS 36 (which requires disclosure of sensitivity to key assumptions in some cases), and FP&A long-range plans. Interviewers often ask candidates to build one live. Reviewers look for three things. The grid must be wired correctly: the centre cell equals the model output, and rows and columns are not swapped. The model must actually flex: no hard-coded WACC inside formulas. The results must be current: calculation mode is managed, and the model is not left on stale "automatic except tables" output.

The learning sequence is:

  1. Data Table mechanics (s01). How the TABLE() function works, where input cells must sit, and how to read the dialog.
  2. Two core grids. WACC × terminal growth (s02) and WACC × exit multiple (s03).
  3. Extra grids for operating drivers and upside (s04).
  4. Presentation. Heat-map formatting with the base case highlighted (s05).
  5. Calculation-mode discipline (s06), so that large models with several tables stay fast and accurate.

The concepts lock in the five rules that make grids reliable:

  • correct row and column mapping (c01)
  • centre-cell proof (c02)
  • same-sheet inputs (c03)
  • masking invalid cells (c04)
  • non-circular running (c05)

Related concepts to study

Scenarios vs sensitivities

→ Week 13 (w13_t6): scenarios vs sensitivities

A scenario changes a coherent set of assumptions together, such as a "bear case" with lower volume, lower price and higher input costs, and tells a story. A sensitivity flexes one or two inputs while holding everything else constant, to isolate their effect. Data tables are sensitivities. The Project 4 scenario switch is a scenario tool. They combine: the grids should recalculate live for whichever scenario is active, so you can present a base-case grid and a bear-case grid. Remember that a 2D grid ignores correlations. A higher WACC often coincides with lower growth, for example. Scenarios capture those joint movements better.

Scenario Manager, tornado charts and Power BI what-if

→ Phase 3 (W9–12): Scenario Manager, tornado charts, Power BI what-if parameters

Excel's Scenario Manager stores named sets of input values and produces a summary report, which is useful for 3–6 discrete cases but cannot produce grids. Tornado charts rank one-at-a-time sensitivities by their swing in value. They are built from a 1D data table, or from manual low/high runs sorted by range, and show which inputs deserve the 2D treatment. In Power BI, a what-if parameter (GENERATESERIES plus SELECTEDVALUE) creates slicers that flex DAX measures. This is a dashboard equivalent of a data table, but it works only on measures defined in the data model, not on Excel cell logic.

Sensitivities in budgets and forecasts

→ Phase 5 (W17–20): sensitivity analysis in budgets and forecasts

In FP&A, the same grid technique flexes budget outputs: EBITDA versus volume and price, cash runway versus collection days and capex phasing, or covenant headroom versus interest rate and EBITDA shortfall. The mechanics are identical: input cells on the same sheet, the centre cell proving the base, and heat-map formatting. The audience is different, though. Management wants to know which levers matter and where the thresholds are, for example the point at which net debt/EBITDA breaches 3.0×. Building valuation grids now prepares you for rolling-forecast and driver-based planning work.

Common pitfalls

Swapped row and column inputs

Row and column input cells swapped, mislabelling the grid

The mistake: WACC values run across the top row, but the dialog's "Row input cell" points to the growth cell. Excel then substitutes WACC-axis values into g and vice versa. The grid looks plausible, but every cell is wrong. With a symmetric-looking range this is easy to miss.

Correct mapping: row input cell = the variable listed across the top row. Column input cell = the variable listed down the left column.

Detection:

  • the centre cell must equal the model output (c02)
  • price must fall as WACC rises along the WACC axis
  • an off-centre cell can be spot-checked by setting the inputs manually

WACC hardcoded in discount formulas

WACC hardcoded inside discount formulas so the table does not flex

The mistake: discount factors are written as =1/(1.12)^E12, or they reference a WACC cell on another sheet that is not the input cell. The data table substitutes values into the input cell, but nothing depends on it, so the whole row shows identical values.

Why it happens: quick prototyping, or a WACC calculated on the WACC tab and referenced directly by the DCF.

Correct treatment: route every WACC use, including the TV formula and mid-year factors, through a single driver cell on the DCF sheet.

Detection: constant rows or columns in the grid, and the Trace Dependents arrows from the input cell.

Stale grids under manual table calculation

Presenting stale grids after calculation mode left on manual for tables

The mistake: the workbook is set to "Automatic except for data tables" for speed. Inputs change, but the grid is not refreshed with F9, so it shows values from a previous scenario.

Why it happens: Excel keeps the workbook-level calculation setting, and users forget to refresh before saving or pasting into a deck.

Correct treatment: keep a visible status cell, for example a check comparing the centre cell to the live output, plus a pre-publication checklist step "press F9, confirm centre-cell check = OK".

Detection: a centre cell that differs from the model output is the tell-tale sign.

Practice Questions

Q1. Build and prove both core grids [L3]

Using your Project 4 model for an NSE-listed manufacturer (base WACC 12.0%, g 5.5%, exit multiple 10.0× FY31 EBITDA of ₹ 1,700 crore, base implied price ₹ 550), specify the layout of:

  • Grid 1: WACC 11.0%–13.0% in 50 bp steps across, g 4.5%–6.5% in 50 bp steps down
  • Grid 2: WACC across, exit multiple 8×–12× down

Your answer should cover:

(a) the driver cells you create on the DCF sheet and how the WACC tab feeds them (b) the exact Data Table dialog entries (c) the centre-cell check formulas (d) the presentation grid with n.m. masking (e) heat-map rules (f) the calculation-mode settings, and the circularity breaker state before running

💡 Hint: Decide first whether the axis values are absolute rates or offsets from a base cell, because this determines how the centre stays aligned when the base changes.

Q2. Diagnose a broken grid [L2]

A reviewer receives a WACC × g grid in which every value in each column is identical and the centre cell shows ₹ 512 while the DCF output shows ₹ 550. The workbook is on "Automatic except for data tables". The TV formula references WACC!C25, and the DCF discount factors reference a driver DCF!$D$5, which is the table's row input. List every fault, its symptom and the fix, in order of priority.

Q3. Operating grid and upside grid for an IC memo [L2]

For a retailer with FY26 revenue of ₹ 8,000 crore, base revenue CAGR of 18%, base EBITDA margin (post-116) of 14% and CMP of ₹ 4,200, design:

  • a revenue-growth (±4 pp in 2 pp steps) × EBITDA-margin (±150 bp in 75 bp steps) grid on EV
  • a WACC × g grid on upside %

Specify the driver cells that flex all forecast years uniformly, how NWC and capex respond, and the colour scale you would use for upside, with zero as the midpoint.

Q4. Speed and stability case [L3]

A Project 5 workbook has four 5×5 data tables, an interest-on-average-debt circularity with iterative calculation enabled, and TSM iteration. Each F9 takes 40 seconds and some grid cells show #NUM!. Write a remediation plan covering:

  • the calculation mode
  • the circularity breaker
  • the TSM closed form
  • table consolidation
  • IFERROR and masking choices
  • a refresh-and-publish protocol for analysts
