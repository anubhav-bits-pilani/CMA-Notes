Hunting Hardcodes with Go To Special, Trace Precedents and Inquire

Scope: Hunting hardcodes with Go To Special, Trace Precedents and Inquire

Why it matters

A hardcode is a typed number where a formula should be. It is the most common cause of imbalances that appear only after an input changes. The model balanced when the number was typed, because the typed value happened to equal the formula result. Once growth, margins or the scenario change, the formula cells move and the hardcode does not. Common examples: FY28E capex overtyped with the management guidance figure, a ΔNWC cell pasted as a value from an older version, a CFS line with =D45+3.2 to "fix" a past difference, or a BS opening balance typed instead of linked. Hardcodes are also an audit finding in their own right. Model review standards (FAST, ICAEW Financial Modelling Code, Big 4 model audit methodology) treat unflagged constants in calculation areas as defects. Being able to sweep a workbook for them in minutes is a core skill for the Saturday test and for any model review role.

Core notes

Types of hardcode

Type Example Detected by
Pure constant in a calc row FY28E capex cell contains 450 Go To Special → Constants
Embedded constant =D22*1.05, =D45+3.2, =D30/365 Inquire, FORMULATEXT search, manual review
Pasted value from another version ΔNWC row: values only Go To Special → Constants, ISFORMULA
Link to an external workbook ='[Model_v6.xlsx]CFS'!H20 Data → Edit Links, Inquire
Hardcoded reference to a fixed cell =$G$20 copied across Row differences, Trace Precedents
Plug "Other adjustments" = check row Trace Precedents on suspicious lines

Not every constant is a defect. Day counts (365), unit conversions (100 for lakh to crore) and the number of months (12) are acceptable only if they sit on the inputs sheet as named constants. The rule is that a constant lives in one labelled place.

Go To Special (F5 → Special, or Home → Find & Select → Go To Special)

Finding constants:

  1. Select the calculation range (for example, the forecast columns of the P&L, CFS and BS, and all schedule tabs).
  2. F5 → Special → Constants → tick Numbers only (untick Text, Logicals, Errors).
  3. Excel selects every typed number. Apply a temporary fill colour (for example bright yellow) to see them all.
  4. Repeat on each calculation tab. Any forecast-column constant outside the inputs sheet needs justification.

Finding inconsistent formulas (row differences):

  1. Select a single row across the forecast columns, starting with the first forecast year.
  2. F5 → Special → Row differences (shortcut: Ctrl+\ after selecting the row).
  3. Excel selects cells whose formula differs in relative structure from the active (first) cell. A FY28E capex cell overtyped with 450 or with =G30*1.1 will be selected.

Other useful options: Formulas → Errors (find #REF! after deleted rows), Precedents/Dependents (select all cells feeding a check), Blanks (find missing links in a row that should be fully populated).

Trace Precedents and related tools

  • Trace Precedents (Formulas → Trace Precedents, or Ctrl+[ to jump to the precedents directly). From a suspicious CFS line, it shows whether it links to the schedule (expected) or to something else (another CFS line, a BS cell, a constant). Dotted arrows with a sheet icon mean cross-sheet precedents. Double-click the arrow to open the Go To list.
  • Trace Dependents (Ctrl+]). From a schedule row, it confirms that the row actually feeds the CFS and BS. A schedule output with no dependents is an orphan, for example an ESOP charge computed but never linked into CFO.
  • Evaluate Formula. Steps through nested logic (IF, MAX, MIN, CHOOSE) to see which branch fires. This is useful for scenario selectors and floors.
  • Show Formulas (Ctrl+`). Displays formulas in place of values. Scan a row and constants stand out as plain numbers.
  • Watch Window. Keep the check row, cash check and the suspect cell visible while working elsewhere.

Formula-based detection

Add a temporary helper row or conditional format:

=ISFORMULA(H22)
=NOT(ISFORMULA(H22))
=ISNUMBER(SEARCH("+", FORMULATEXT(H22))) * ISNUMBER(--RIGHT(FORMULATEXT(H22), 1))

Applying conditional formatting with =AND(ISNUMBER(H22), NOT(ISFORMULA(H22))) to all forecast calculation areas, with a red fill, gives a permanent visual alarm for constants. For embedded constants, a helper using FORMULATEXT and a search for digit patterns after operators catches most +3.2-type fixes. Review hits manually, because references like H22 also contain digits.

Inquire add-in

Inquire ships with Microsoft 365 Apps for enterprise and Office Professional Plus editions. Enable it via File → Options → Add-ins → Manage: COM Add-ins → tick Inquire. Key features:

  • Workbook Analysis. Produces a report with categories including Formulas with hardcoded values (embedded constants), Formulas with numeric values, Inconsistent formulas, Formulas referencing blank cells, Formulas with errors, Hidden sheets/rows/columns, External references and Circular references. Export it to Excel and filter by sheet. This is the fastest full-workbook sweep available.
  • Cell Relationship. A diagram of a cell's precedents and dependents across sheets and workbooks, several levels deep. Use it on the BS check cell to see every input chain at once.
  • Workbook Relationship / Worksheet Relationship. Map links between files and sheets. An unexpected external link is often a pasted-from-another-version block.
  • Compare Files (Spreadsheet Compare). Compares two versions cell by cell and highlights changed values, formulas and entered values. When v7 balanced and v8 does not, this shows exactly what changed.
  • Clean Excess Cell Formatting. Not a debugging tool, but it reduces file size before distribution.

If Inquire is unavailable (Excel for Mac or some home/business editions), use Go To Special, FORMULATEXT helpers, and third-party auditing tools where your firm permits them.

A 15-minute hardcode sweep

  1. Edit Links. Remove or justify any external links.
  2. Go To Special → Constants (Numbers) on every calculation sheet. Highlight the results.
  3. Row differences on each key row of the P&L, CFS and BS forecast columns.
  4. Inquire Workbook Analysis (if available). Filter "Formulas with hardcoded values".
  5. Trace Precedents on every CFS line that has no obvious schedule source.
  6. Fix, then re-run the check row and the checks dashboard.

Illustration

Bhima Agro Ltd: the model balanced in Base. After switching to Bull (revenue growth from 10% to 18%), the FY28E check became +11.20 (assets too high). Row differences on the CFS "Increase in trade receivables" row selected FY28E. Its contents were -38.4, a pasted value. The Base formula result was −38.4, and the Bull result should have been −49.6. The CFS therefore understated the outflow by −38.4 − (−49.6) = 11.2, so cash was 11.2 too high, which is exactly the imbalance. Replace the value with the row formula and the check returns to zero in every scenario.

Edge cases & judgement calls

  • Constants in historical columns are correct. Restrict your Go To Special selection to forecast columns, or the results will be swamped by legitimate historical inputs.
  • Hardcoded management guidance. If capex for FY27E must equal guided ₹450 crore, put 450 on the inputs sheet as a labelled override with a switch (=IF(Override_On, Override_Value, Driver_Formula)). Do not type it in the schedule.
  • Constants in IF thresholds (for example, =IF(Cash<50, …)). Minimum cash and covenant thresholds belong on the inputs sheet.
  • Array or spill formulas may appear as constants to some tools, or be flagged as inconsistent. Check them manually.
  • Hidden rows and very hidden sheets can hold plugs. Inquire lists them. Otherwise check Format → Hide & Unhide, and the VBA project for xlSheetVeryHidden.
  • Data tables ({=TABLE(…)}) are flagged by some audits. They are not hardcodes but should sit on a separate sensitivity sheet.

Key takeaways

  • A hardcode in a calc area is the classic reason a model balances in Base and fails when inputs change. The imbalance equals the gap between the typed value and the current formula result.
  • Go To Special → Constants finds pure typed numbers. Row differences (Ctrl+) finds cells that break a row's formula pattern.
  • Trace Precedents/Dependents confirm every CFS line links to its schedule and every schedule output is used.
  • Inquire Workbook Analysis finds embedded constants, inconsistent formulas, external links and hidden content across the whole workbook. Spreadsheet Compare isolates changes between versions.
  • Legitimate constants (365, overrides, thresholds) live once, labelled, on the inputs sheet.

Practice Questions

Q1. Choosing the right tool [L1]

For each symptom, name the Excel feature you would use first and explain why. (a) You suspect someone typed a value over a formula in one year of the CFS. (b) You think the ESOP charge is calculated but not used anywhere. (c) v12 balanced and v13 does not, and nobody documented the changes. (d) The model asks to "update links" on opening. (e) A formula reads =IF(AND(H10>0,H12<H14),MIN(H15,H16),0) and you need to see which branch fires.

Q2. Imbalance from a pasted value [L2]

In Base, the FY27E "Purchase of PPE" cell in the CFS of Penna Cement Ltd holds the value −320 (pasted). The schedule formula is capex = 8% of revenue. Base FY27E revenue is ₹4,000 crore and Bear FY27E revenue is ₹3,400 crore. Capex in the PPE schedule is linked to revenue correctly. (a) Compute the FY27E check in Bear. (b) State the pattern you would see across FY27E–FY30E if only this cell is wrong. (c) Describe two controls that would have prevented this.

💡 Hint: The schedule moves with revenue, but the pasted CFS cell does not.

Q3. Designing a permanent hardcode alarm [L2]

Write the conditional formatting rule (formula and application range) that highlights any numeric constant in the forecast columns H:L of the P&L, CFS and BS sheets, rows 8 to 120. Then explain how you would extend the approach to flag formulas containing embedded constants, and the false positives you would expect.

Q4. Inquire report triage [L3]

Inquire's Workbook Analysis on an inherited 18-tab model reports: 214 formulas with hardcoded values, 37 inconsistent formulas, 6 external references, 2 hidden sheets, 1 circular reference and 12 formulas referencing blank cells. The model balances in Base but not in Bear. You have 60 minutes. Prioritise these categories for investigation, justify the order, and describe what you would do with the 214 hardcoded-value hits to make the review manageable.
