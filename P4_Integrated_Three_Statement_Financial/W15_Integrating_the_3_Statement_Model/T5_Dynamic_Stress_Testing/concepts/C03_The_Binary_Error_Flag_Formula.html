Key concept

The Binary Error Flag Formula

Concept: Error flag: =--OR(Cash<0,Rev_Close>Rev_Limit,ABS(BS_Check)>0.001)

Statement

For each forecast year:

Error_Flag = --OR(Cash < 0, Rev_Close > Rev_Limit, ABS(BS_Check) > 0.001)

The flag returns 1 if any of three conditions holds, and 0 otherwise:

  • Cash < 0: closing cash is negative (an unfunded deficit).
  • Rev_Close > Rev_Limit: the revolver is drawn beyond its sanctioned limit.
  • ABS(BS_Check) > 0.001: the balance sheet does not balance within tolerance.

The double unary -- converts the logical TRUE/FALSE returned by OR into 1/0, so flags can be summed:

\[ \text{Total errors} = \sum_{t=1}^{T} \text{Flag}_t \]

where \( T \) is the number of forecast years and \( \text{Flag}_t \in \{0, 1\} \).

Explanation

Why --: Excel stores TRUE/FALSE as logical values. SUM ignores logicals in ranges, so SUM of a row of TRUE/FALSE values returns 0. The first unary minus coerces TRUE to −1 and the second makes it +1. Alternatives are N(OR(…)), OR(…)*1 or IF(OR(…),1,0). -- is the most compact and is widely recognised.

Why OR per year, not across ranges: applied to a whole row (OR(Cash_Row<0)), OR returns a single TRUE if any year fails. That is useful for a master flag but loses the year. The per-year version, copied across the timeline, shows which year fails, and SUM or MATCH(1, Flag_Row, 0) then gives the count and first failure year.

Why ABS and a tolerance: the BS check can be negative or positive, and floating-point arithmetic leaves tiny residues such as 1E-13. Testing BS_Check <> 0 would raise false alarms. Testing ABS(BS_Check) > 0.001 catches every real error above ₹10,000 (in ₹ crore units) and ignores noise.

Mixing integrity and warnings: this compact flag combines one integrity test (BS check) with two business warnings (negative cash, revolver over limit). For a quick single cell that is fine. For a full dashboard (s07), split them so a stressed but correct case is not reported as a broken model:

Integrity_Flag = --OR(ABS(BS_Check) > Tol, ABS(Cash_Check) > Tol, Conv_Check > Tol)
Warning_Flag   = --OR(Cash < Min_Cash, Rev_Close > Rev_Limit + Tol, Covenant_Breach = 1)

Edge cases:

  • If Rev_Close is computed with a MIN against the limit (as it should be), the revolver test can never fire from the draw formula itself. It still protects against overrides, hardcodes or a later edit that removes the MIN. Keep it.
  • Use Rev_Limit + 0.001 to avoid flagging a revolver exactly at its limit because of floating-point noise.
  • If Cash includes overdrafts netted per Ind AS 7.8, test the gross cash line or the net line consistently with the model's definition.
  • Error values: if any input is #N/A or #DIV/0!, the OR returns an error. Wrap in IFERROR(…, 1) so an error counts as a failure, never as a pass.

Illustration

Sarayu Foods Ltd, Bear case (₹ crore):

Row FY26E FY27E FY28E FY29E FY30E
Closing cash 85 40 −22 15 60
Revolver closing 120 250 300 300 210
Revolver limit 300 300 300 300 300
BS check 0.000 0.000 0.000 0.000 0.0004
Error flag 0 0 1 0 0

FY28E flags because cash is negative. The revolver is exactly at the limit, which does not breach the > test. FY30E's BS check of 0.0004 is within tolerance, so it does not flag. Total errors = 1 and first error year = FY28E. The model is still valid as a set of statements, but the business has a funding gap, which is why the dashboard should label this a warning.

Connections

The flag is the building block of the checks dashboard (s07) and the scenario check table (s01), where SUM(Error_Flag_Row) gives the count per scenario. It operationalises the topic pitfall on unbounded revolvers (s03) and the Topic 4 pitfall on ignoring small differences, through the tight tolerance. It feeds the Cover sheet master status (t6 s04) and the weekly checklist item on showing check = 0 across scenarios and extreme inputs.
