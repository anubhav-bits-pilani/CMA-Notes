The Cover Sheet: Checks Summary and Model Map

Scope: Checks summary and model map on Cover

Why it matters

The Cover is the first sheet anyone opens. In a professional model it does three jobs. It identifies the model (company, purpose, version, author, date, status). It certifies integrity (a checks summary that shows at a glance whether the model is valid in the live scenario and across all scenarios). And it orients the reader (a model map describing each tab, its role and the flow of calculations). Model review teams (Big 4 model audit, bank credit model validation, PE fund operating teams) check the Cover first. A model without one is treated as a work in progress. For Project 4 and later interview walkthroughs, the Cover is your opening slide: "Here is the structure, here is the status, here is where to look." It also enforces discipline. Once the checks summary sits on the Cover, delivering a model with a red status becomes a visible decision rather than an oversight.

Core notes

Cover layout

Block Contents
Identification Model name, company (NSE/BSE ticker), purpose ("Project 4: 5-year integrated forecast"), basis (consolidated, Ind AS, ₹ crore, FY ending 31 March), version number, date, author, reviewer, status (Draft / Under review / Final)
Checks summary Master status, individual check results, scenario check table, last-tested timestamp
Live settings Scenario label, stress mode on/off, circularity switch, iteration setting reminder
Model map Table of tabs: name, purpose, key inputs, key outputs, hyperlink
Colour legend Inputs (blue font / yellow fill), formulas (black), links to other sheets (green), checks (red/green), external data (purple)
Version log Version, date, author, change description
Disclaimer / notes Data sources, cut-off date (for example, "Actuals to FY25 audited; Q2 FY26 results incorporated"), key limitations

Checks summary

Link it to the Checks sheet (Topic 5 s07). Do not recompute.

Check Live scenario Base Bull Bear Status
BS check (max abs, all years) 0.000 0.000 0.000 0.000 OK
Cash check 0.000 0.000 0.000 0.000 OK
Circularity convergence 0.000 0.000 0.000 0.000 OK
Negative cash years 0 0 0 1 WARNING (Bear)
Revolver over limit years 0 0 0 0 OK
Covenant breach years 0 0 0 2 WARNING (Bear)
Master status OK – WARNINGS

Formulas:

Master_Status = IF(SUM(Integrity_Errors_All_Scen) > 0, "MODEL ERROR",
                IF(SUM(Warnings_All_Scen) > 0, "OK – WARNINGS", "OK"))

The Base/Bull/Bear columns come from the scenario check table (data table on the switch). Add a "last tested" note if a macro snapshot is used, and a check that flags the snapshot as stale if inputs have changed since.

Status semantics:

  • MODEL ERROR (red): any integrity check fails in any scenario. Do not deliver.
  • OK – WARNINGS (amber): integrity passes everywhere, and business warnings (negative cash, covenant breach) exist in some scenarios. Deliver with commentary.
  • OK (green): no integrity errors and no warnings.

Hyperlinks:

=HYPERLINK("#'Debt'!A1", "Go")

Use # for internal links. Quote sheet names that contain spaces. If tabs are renamed, hyperlink text formulas break silently, so add a check using ISREF(INDIRECT("'"&Tab_Name&"'!A1")) for each listed tab. That flags missing or renamed sheets, at the cost of a volatile function, which is acceptable on a Cover.

A simple flow diagram (Inputs → Operating schedules → Financing/Tax/Equity → Statements → Checks → Dashboard), drawn with shapes, helps non-modellers. Keep it to one row of boxes.

Edge cases & judgement calls

  • Cover status vs live status. The live dashboard shows only the current scenario. The Cover should show all scenarios, otherwise a reviewer toggling to Bear is the first to discover a failure.
  • Hidden or very hidden tabs. Do not hide calculation tabs in a delivered model without listing them on the map. Undisclosed hidden sheets are a review red flag.
  • External links. If the model pulls from a data workbook, list it on the Cover with the path and refresh date. Better still, break links before delivery and paste the data into a clearly labelled input sheet.
  • Version control. Use a strict file naming convention (Project4_KAVERI_v1.4_2026-11-22.xlsx) and keep the version log in sync with the file name. A check comparing Version_Cell to the version parsed from CELL("filename") catches mismatches.
  • Over-engineering. The Cover should fit on one screen and one printed page. Move detailed check tables to the Checks sheet and link the summary.
  • Protecting the Cover. Protect the sheet (no password, or a shared one) so users do not overtype status cells. Leave input cells (author, date) unlocked.

Key takeaways

  • The Cover identifies the model, certifies integrity across all scenarios, and maps the tabs in calculation order with hyperlinks.
  • The master status distinguishes MODEL ERROR (integrity) from OK – WARNINGS (business stress) and OK.
  • Link check results from the Checks sheet and the scenario check table. Never type or paste status.
  • Include live settings (scenario, stress, circularity), a colour legend and a version log.
  • Keep it to one screen and one page, and disclose every tab and external link.

Practice Questions

Q1. Draft a Cover [L1]

Draft the identification block, live settings block and colour legend for a Project 4 model of an Indian specialty chemicals company. Include every field listed in these notes, with example values.

Q2. Master status logic [L2]

Write the Excel formulas that produce the Cover's master status from these named ranges: BS_MaxAbs_Scen (3 cells, one per scenario), Cash_MaxAbs_Scen, Conv_MaxAbs_Scen, NegCash_Years_Scen, RevOver_Years_Scen, CovBreach_Years_Scen, with tolerance Tol. The status must be "MODEL ERROR" if any integrity metric fails in any scenario, "OK – WARNINGS" if only warnings exist, and "OK" otherwise. Also write a formula that lists which scenarios have warnings (for example, "Bear").

💡 Hint: Use SUMPRODUCT with logical tests across each 3-cell range.

Q3. Model map review [L2]

A peer's model map lists 11 tabs, but the workbook has 15 (two hidden, one named "Sheet3", one named "old_CFS"). Describe the risks this creates, what you would check on each unlisted tab, and the changes you would require before the model is marked Final.

Q4. Interview opening [L3]

An interviewer says: "Open your model and give me the 90-second tour." Script your answer using only the Cover, covering purpose and basis, structure (model map), integrity status across scenarios, the live case and one key insight. State which hyperlinks you would click and in what order.
