Subtopic note

Self-Review, Peer Review and Model Hygiene Before Delivery

Scope: Self-review and peer review checklist; print setup, number formats, grouping, freeze panes

Why it matters

The last 10% of the work decides how the model is judged. A reviewer who opens a model and finds inconsistent number formats, columns that scroll the labels out of view, hidden rows instead of grouping, and pages that print across 14 sheets of paper will assume the logic is equally careless. Review is also where errors are caught cheaply. Professional standards (the ICAEW Financial Modelling Code, the FAST Standard, and Big 4 model-review methodologies) expect a documented self-review by the builder and an independent review by someone else. In Indian FP&A teams and banks, a "maker-checker" sign-off on forecast models mirrors the control culture you know from audit. For Project 4, a disciplined self-review plus one peer review is the difference between "it balances" and "it is ready to send."

Core notes

Self-review checklist (builder)

Integrity

  • BS check = 0.000 in every year, in Base, Bull and Bear, with circularity on (Topic 5 s01).
  • Cash check, convergence and opening-cash link = 0. Master status not "MODEL ERROR".
  • Extreme-input suite passed (zero/negative growth, margin collapse, 3× capex, DSO/DIO shocks). Stress mode switched OFF before delivery.
  • Breaker set to the delivered state. Iterative calculation setting documented on the Cover.
  • No plugs, rounding lines or balancing figures (search labels: "plug", "balancing", "adj").

Formula quality

  • Go To Special → Constants on all calculation tabs: no unexplained constants in forecast columns.
  • Row differences on every key row: one consistent formula across the timeline.
  • No external links (Data → Edit Links) unless documented.
  • No #REF!, #N/A or #DIV/0! anywhere (Go To Special → Formulas → Errors). IFERROR used only on KPI or presentation rows.
  • Inquire Workbook Analysis reviewed (if available).

Economic sense

  • Ratios within sanity bands or explained (c05): margins, ROCE, ROE, capex/sales, capex/D&A, asset turnover, working capital days, ETR.
  • Interview flow test passes: depreciation +₹10 → PAT −7.48, CFO +2.52, PPE −10, cash +2.52, equity −7.48 (at 25.17%, with the breaker off so interest does not move).
  • Dividends ≥ 0, current tax ≥ 0, NBV ≥ 0, cash ≥ minimum or flagged.

Presentation

  • Dashboard has links only (c04). Charts move with the scenario. Live label on every output.
  • Assumption log complete for top-sensitivity inputs. Cover map and version log updated.

Peer review checklist (reviewer)

The reviewer does not rebuild the model. They test it:

  1. Read the Cover. Check that status, live settings and map match the workbook (tab count, hidden sheets).
  2. Toggle each scenario and the stress mode. Watch the master status.
  3. Pick three outputs (FY28E PAT, FY30E net debt, FY27E ROCE) and trace each back to inputs with Trace Precedents. Confirm the logic matches the stated definitions.
  4. Recompute one schedule independently (for example, the FY27E debt corkscrew or tax with losses) on a scratch sheet.
  5. Perform a one-input change test (raise one cost assumption) and explain the flow through all three statements.
  6. Review five assumption log entries against the cited source.
  7. Record findings in a review log: ID, sheet/cell, issue, severity (High = wrong numbers, Medium = risk of error, Low = presentation), builder response, cleared by/date.

Number formats

Consistency is the goal. Define formats once and apply them with cell styles (Home → Cell Styles → New Cell Style). That makes them easy to change.

Conventions: units stated in every sheet header ("₹ crore unless stated"); input cells blue font (and optionally a light yellow fill); formulas black; links to other sheets green; checks with conditional formatting. Avoid mixing ₹ crore and ₹ lakh in one model. If source data is in ₹ lakh, convert on the input sheet with a named constant (Lakh_to_Crore = 0.01).

Grouping instead of hiding

Use Data → Group (Alt+Shift+Right Arrow) for detail rows (for example, sub-components of other expenses, or vintage rows in the loss triangle) and for historical columns you want to collapse. Grouping shows a visible +/− control, so the reader knows something is collapsed. Hidden rows and columns are invisible and are a classic hiding place for plugs. Review tools flag them for that reason. Set the outline so summary rows are above or below detail consistently (Data → Outline settings).

Freeze panes

Freeze labels and timeline headers on every calculation and output sheet (View → Freeze Panes). Select the first cell to the right of the label columns and below the header rows (for example, E6 when columns A–D hold labels and units, and rows 1–5 hold titles, scenario label, dates and the master check). The year headers and the line labels stay visible while scrolling, which matters for 5-year models with historical columns.

Print setup

For each output sheet (Cover, Dashboard, Statements, Checks, Log):

  • Print area: Page Layout → Print Area → Set. Exclude scratch columns.
  • Orientation and scaling: landscape. Fit to 1 page wide by N pages tall for statements. Fit the dashboard to 1 × 1 on A4 or A3.
  • Print titles: rows to repeat at top (title, scenario label, year headers); columns to repeat at left (labels).
  • Headers and footers: file name (&[File]), sheet name (&[Tab]), page X of Y (&[Page] of &[Pages]), print date (&[Date]). The scenario label must appear inside the printed area (s03), because headers cannot reference cells without VBA.
  • Page breaks: check them in Page Break Preview, and avoid splitting a statement section across pages.
  • Gridlines off for output sheets (View → uncheck Gridlines; Page Layout → Sheet Options → Print gridlines off).
  • Test-print to PDF and read every page before delivery.

Final file hygiene

Save with the calculation set to Automatic (or document "Automatic except tables" on the Cover), cursor in A1 on each sheet, Cover as the active sheet, zoom consistent (for example, 85%), no leftover scratch sheets, file named per convention (Project4_TICKER_v2.0_2026-11-28.xlsx), and a PDF of Cover, Dashboard and Statements for the Base case.

Edge cases & judgement calls

  • Self-review blindness. Builders miss their own errors. Leave a gap (overnight if possible) before self-review, and always get a peer review for anything external.
  • Review scope creep. A peer reviewer can rewrite the model in their preferred style. Agree the scope first: errors and risks, not style preferences.
  • Iteration settings travel with the workbook, but Excel applies the setting of the first workbook opened in a session. A reviewer who opens your model second may calculate with iteration off. Document this on the Cover and include the convergence check.
  • Protected sheets. Protect output sheets to prevent accidental overtyping, but do not password-lock the model from the reviewer.
  • Macros. If the model uses VBA (snapshot, print routines), save as .xlsm, document every macro on the Cover, and make sure the model still works (with a stated limitation) if macros are disabled.
  • Large models. Before delivery, remove unused styles and excess formatting (Inquire → Clean Excess Cell Formatting) to reduce file size.

Key takeaways

  • Self-review covers integrity (all scenarios and extremes), formula quality (constants, row consistency, links, errors), economic sense (sanity bands, flow test) and presentation.
  • Peer review tests the model by toggling, tracing, recomputing one schedule and checking sources. Findings go into a severity-rated review log.
  • Use consistent number formats via cell styles: brackets for negatives, dashes for zeros, one unit per model, stated on every sheet.
  • Group rather than hide, freeze labels and headers, and set print areas, titles, scaling and footers on every output sheet.
  • Deliver with stress mode off, the breaker in its documented state, the Cover active, and a PDF of the key outputs.

Q1. Format codes [L1]

Write custom number format codes for (a) ₹ crore with one decimal, negatives in brackets, zeros as a dash; (b) percentages with one decimal, negatives in brackets; (c) multiples with one decimal followed by "x"; and (d) a year header that displays the number 26 as "FY26E". Explain the purpose of the _) element.

Q2. Peer review log [L2]

You review a colleague's model and find: a hidden row in the BS containing "other adj" of ₹2.4 crore; the Bear BS check of 0.000 but convergence 0.37 in FY28E; inconsistent formats (some ₹ crore with two decimals); three external links to an old version; and an assumption log entry citing "concall" with no date. Write the review log entries (ID, location, issue, severity, recommended fix) and state which items block delivery.

💡 Hint: Severity depends on whether the item can produce wrong numbers.

Q3. Print setup specification [L2]

Specify the print setup for the Dashboard, P&L, BS and CFS sheets of Project 4, including paper size, orientation, scaling, print titles, header/footer codes and how the live scenario label will appear on every page.

Q4. Flow test as a review step [L3]

Explain why the interview flow test (depreciation +₹10 at a 25.17% tax rate) is a useful final review step even when all checks pass. State the expected changes in each statement, how circularity and the timing of tax payment affect the result, and what a deviation from the expected numbers would indicate.
