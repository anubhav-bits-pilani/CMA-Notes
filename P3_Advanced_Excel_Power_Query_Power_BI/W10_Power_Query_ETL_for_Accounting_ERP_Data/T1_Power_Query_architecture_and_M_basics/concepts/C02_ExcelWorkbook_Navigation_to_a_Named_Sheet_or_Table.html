Key concept

Excel.Workbook Navigation to a Named Sheet or Table

Concept: Excel.Workbook(File.Contents(FilePath), null, true){[Item="TB", Kind="Sheet"]}[Data]

Statement

Excel.Workbook(workbook as binary, optional useHeaders, optional delayTypes) returns a navigation table with one row per object in the file and columns:

Column Content
Name Object name (sheet name, table name, defined name)
Data The object's contents as a nested table
Item Item identifier used for navigation
Kind "Sheet", "Table" or "DefinedName"
Hidden Whether the sheet/object is hidden

{[Item="TB", Kind="Sheet"]} selects the single row whose Item is "TB" and Kind is "Sheet" (key lookup on a table); [Data] returns that row's nested table. Arguments: useHeaders = null (or false) means do not promote the first row; delayTypes = true means leave columns untyped so that typing is done deliberately later.

Explanation

The key-lookup syntax table{[field=value, ...]} returns exactly one record and errors if zero or more than one row matches. That is why both Item and Kind are specified — a workbook can contain a sheet "TB" and a table "TB" at the same time.

Choosing the object:

  • Kind = "Table" (an Excel ListObject) is the most robust: fixed header row, defined range, no stray notes. Use it for CoA masters and mappings you control.
  • Kind = "Sheet" brings the used range: Tally/SAP report headers, blank rows, totals and any notes typed to the right. Fine for exports you do not control, but plan header-skipping and column selection by name.
  • Kind = "DefinedName" reads a named range, useful for a fixed input block.

Sheet-name drift is the main recurring risk: Tally exports may name the sheet "Trial Balance" one month and "TB" another, or the sheet may be renamed by a user. Tolerant alternatives:

Source  = Excel.Workbook(File.Contents(FilePath), null, true),
Sheets  = Table.SelectRows(Source, each [Kind] = "Sheet" and not [Hidden]),
TB      = Sheets{0}[Data]          // first visible sheet
// or by pattern
TB2     = Table.SelectRows(Sheets, each Text.Contains([Name], "Trial", Comparer.OrdinalIgnoreCase)){0}[Data]

delayTypes = true interacts with s04: it prevents the connector's own type guesses, keeping all columns as any until your explicit typing step with locale.

In a folder pipeline, File.Contents(FilePath) is replaced by the binary [Content] from Folder.Files, and the navigation is placed inside the cleaning function so every branch file is navigated the same way.

Illustration

Branch_Pune_Mar26.xlsx contains sheets "TB" and "Notes" and a hidden sheet "Old". The navigation table therefore has three Sheet rows. {[Item="TB",Kind="Sheet"]}[Data] returns the TB used range: row 1 "ABC Industries Ltd – Pune", row 2 "Trial Balance as at 31-Mar-2026", row 4 headers "Particulars | Debit | Credit", then ledger rows and a "Grand Total" row. These rows are handled next with conditional skip and filter (Topic 2). If April's file names the sheet "Trial Balance", the hard-coded lookup errors with Expression.Error: The key didn't match any rows in the table; the pattern-based selection survives.

Connections

In FP&A practice, budget templates should be distributed with a named Excel Table so that collection is robust.

Practice Questions

Q1. Key lookup errors [L1]

State what happens when the lookup {[Item="TB", Kind="Sheet"]} is applied to a workbook that (a) has no "TB" sheet, (b) has both a sheet and a table named "TB", (c) has the sheet "TB" hidden.

Q2. Robust navigation [L2]

Branch TB workbooks arrive with sheet names "TB", "Trial Balance", "TB Mar26" and occasionally an extra "Notes" sheet. Write M that reliably picks the trial balance sheet in every case, and explain the fallback you would use if no sheet name contains "TB" or "Trial".

💡 Hint: Filter the navigation table first, then take the first match with optional access.

Q3. Sheet vs Table for budgets [L2]

You design a department budget template that 14 department heads will fill. Argue whether the collection query should navigate to a Sheet or a Table, and list the template design choices that make the Power Query side refresh-safe.
