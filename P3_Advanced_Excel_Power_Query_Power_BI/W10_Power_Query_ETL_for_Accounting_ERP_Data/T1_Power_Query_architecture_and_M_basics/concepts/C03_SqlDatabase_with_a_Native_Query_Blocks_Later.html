Key concept

Sql.Database with a Native Query Blocks Later Folding

Concept: Sql.Database("server", "db", [Query="SELECT ..."]): a native query blocks later folding, so prefer navigation and then filters

Statement

Sql.Database(server as text, database as text, optional options as record) connects to SQL Server. With no Query option it returns a navigation table of tables and views; navigating and then applying steps lets Power Query fold those steps into SQL it generates. With [Query="SELECT ..."], the supplied SQL is sent as-is and the result is treated as an opaque table:

  • Steps after a native Query option do not fold (on SQL Server, the engine does not wrap user SQL in a subquery by default), so every later filter, group or merge runs locally on the full result.
  • Preferred pattern: navigate → filter → remove columns → group, letting Power Query write the SQL.

Explanation

Why the engine refuses to fold over custom SQL: it cannot safely assume your statement can be wrapped as a subquery (it may contain ORDER BY, CTEs, temp tables, multiple result sets or stored procedure calls). So it treats the result as a fixed source, and later steps happen in the mashup engine.

Consequences in finance work:

  1. Volume: SELECT * FROM GLLines as a native query followed by a Power Query filter on FY26 brings every year's lines across the network.
  2. Incremental refresh in Power BI cannot partition a non-folding query efficiently.
  3. Maintainability: SQL hidden in the connector dialog is invisible in Applied Steps; logic splits between SQL and M.
  4. Security prompts: native queries require approval ("Native Database Query" permission prompt) per query text change, unless disabled in options.

When native SQL is justified: window functions, complex CTEs, existing vetted views/stored procedures, or a query that the DBA wants to control. Then put all filtering and aggregation into the SQL itself (so nothing important happens locally), or use Value.NativeQuery(..., [EnableFolding=true]) on supported connectors (c04), or ask for a database view and navigate to it — views fold like tables.

Navigation pattern:

let
    Source   = Sql.Database(ServerName, "FinanceDW"),
    GL       = Source{[Schema="dbo", Item="GLLines"]}[Data],
    FY26     = Table.SelectRows(GL, each [FiscalYear] = 2026 and [CompanyCode] = "IN01"),
    Cols     = Table.SelectColumns(FY26, {"PostingDate","Account","CostCentre","Amount"}),
    ByMonth  = Table.Group(Cols, {"Account","CostCentre"}, {{"Amount", each List.Sum([Amount]), type number}})
in
    ByMonth

View Native Query on ByMonth shows a single SELECT ... WHERE ... GROUP BY.

Illustration

GLLines has 48 million rows across FY17–FY26; FY26 IN01 is 4.2 million; grouped output is 9,600 rows.

Approach Rows transferred Later steps
[Query="SELECT * FROM dbo.GLLines"] + filter + group in PQ 48,000,000 Local
Navigation + filter + group 9,600 Folded
[Query="SELECT ... WHERE FiscalYear=2026 ... GROUP BY ..."] 9,600 Local (but little left to do)

The third is acceptable but hides logic in SQL and cannot be extended with foldable steps.

Connections

Applies s05 (folding) and s06 (parameters for server/database names). Contrasts with c04 (Value.NativeQuery with EnableFolding). Leads to Week 12 (gateway refresh, incremental refresh) and the MySQL refresh item (WHERE/GROUP BY mapping to Power Query steps).

Practice Questions

Q1. Spot the problem [L1]

A query is Sql.Database("fin-sql01", "ERP", [Query="SELECT * FROM dbo.ARInvoices"]) followed by a filter on InvoiceDate ≥ 1-Apr-2025 and a Group By on Customer. Explain the performance impact and rewrite it to fold.

Q2. When native SQL is right [L2]

The DBA provides a 120-line SQL statement with CTEs and a ROW_NUMBER() window to pick the latest exchange rate per currency per day. Describe two ways to consume it in Power Query, and the trade-offs for folding and maintainability.

💡 Hint: Consider asking for a database object instead of pasting the statement.

Q3. Prove folding [L2]

Describe the exact steps to prove to an auditor that a monthly GL extract query sends only the FY26, company IN01 rows to Power Query, including what evidence you would save to the working papers.
