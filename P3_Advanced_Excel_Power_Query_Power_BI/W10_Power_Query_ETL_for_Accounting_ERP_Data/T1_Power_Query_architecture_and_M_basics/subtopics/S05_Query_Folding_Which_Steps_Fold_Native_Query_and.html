Query Folding: Which Steps Fold, Native Query and Diagnostics

Scope: Query folding: which steps fold, View Native Query, Query Diagnostics

Why it matters

When a GL table in SQL Server holds 60 million lines across ten financial years, the difference between Power Query asking the server for "FY26, account class 4–6, summarised by month" and pulling all 60 million rows to the laptop before filtering is the difference between a 20-second refresh and a timeout. Query folding is Power Query's ability to translate your applied steps into the source's native language (SQL) so that the source does the work. It is also a prerequisite for incremental refresh in Power BI and for DirectQuery. Finance analysts who connect to ERP reporting databases must be able to say which steps fold, prove it, and reorder steps so that folding survives as long as possible.

Core notes

What folding is

Power Query builds a logical plan from the step list. For a foldable source, the engine translates as many leading steps as it can into one native query. At the first step it cannot translate, folding stops: the result of the folded part is streamed back, and every subsequent step runs locally in the mashup engine, even if that later step would itself be foldable.

Three outcomes per query: full folding (everything runs at the source), partial folding (a prefix folds, the rest is local), no folding (all local — always the case for CSV, Excel, Folder, SharePoint files, JSON).

Which steps typically fold (relational sources)

Navigate to table/view FROM Native SQL query typed in the connector (c03)

The table is a heuristic: folding depends on the connector and version. Always verify.

View Native Query

Right-click a step in Applied Steps → View Native Query. If enabled, the step folds and you can read the generated SQL:

select [_].[Account], sum([_].[Amount]) as [Amount]
from [dbo].[GLLines] as [_]
where [_].[FiscalYear] = 2026 and [_].[CompanyCode] = 'IN01'
group by [_].[Account]

If greyed out, either the step does not fold or the connector does not expose the query (some ODBC/OData connectors fold without showing it). Check from the last step backwards: the last step that shows a native query marks the boundary.

Folding indicators (Power BI Desktop / Dataflows)

Newer versions show a step folding indicator beside each step: a database-with-lightning icon (folds), a crossed icon (does not fold), or an indeterminate icon. The Query plan view (right-click → View query plan) shows which nodes are "Remote" (folded) versus "Full scan"/local. These are clearer than View Native Query for partial folding.

Query Diagnostics

Tools → Start Diagnostics / Diagnose Step (Power BI Desktop and Excel's Power Query in Microsoft 365) records what the engine actually did during an evaluation:

  • Detailed and Aggregated logs: each operation, duration, data source query sent, rows returned.
  • Performance counters and Partitions (privacy partition evaluation — relevant to s08).

Use it to find which step is slow, confirm the SQL sent to the server, and see whether the engine is hitting the source more than once (repeated evaluation of an unbuffered step referenced twice). Diagnostics results load as queries you can filter in the editor.

Ordering steps to preserve folding

  1. Navigate to the table (no native SQL).
  2. Filter rows (FY, company code, posting period) and remove columns first — the biggest reduction.
  3. Group/summarise if the output grain allows it.
  4. Merge with other tables from the same database at the source.
  5. Only then: index columns, buffers, text cleaning, custom functions, merges with files.

Illustration: a 60-million-row GLLines table. Sequence A: Source → Add Index → Filter FY26 → Group by Account. The index step breaks folding at step 2, so all 60 million rows travel and filter locally. Sequence B: Source → Filter FY26 (folds) → Remove columns (folds) → Group by Account (folds) → Add Index (local on 1,800 summarised rows). Same result, a tiny fraction of the transfer.

Folding and incremental refresh

Power BI incremental refresh filters on RangeStart/RangeEnd datetime parameters. If that filter does not fold, the service imports all data for every partition — defeating the purpose. Power BI warns "Unable to confirm if the M query can be folded".

Edge cases & judgement calls

  • Files never fold — no amount of step-ordering helps a CSV; reduce work by filtering early and removing columns early anyway (it still reduces local memory).
  • Type change with culture stops folding on SQL sources; type on the database side or apply culture-based typing after the folded part.
  • Merging a SQL table with an Excel mapping breaks folding and may also trigger privacy-level combination rules (s08). Consider pushing the mapping into the database or doing the merge after aggregation.
  • Folding is not always faster: a badly indexed view can make the server slower than local processing on a small table — measure with diagnostics.
  • Value.NativeQuery with EnableFolding=true lets a native SQL query remain foldable for later steps on supported connectors (c04).
  • ODBC folding depends on the driver's SQL capability reporting; Tally ODBC folds very little.

Key takeaways

  • Folding translates leading steps into native SQL; it stops at the first non-translatable step and everything afterwards runs locally.
  • CSV, Excel, Folder and SharePoint file sources never fold.
  • Verify with View Native Query, folding indicators/query plan, and Query Diagnostics — do not assume.
  • Put filters, column removal and group-bys first; buffers, indexes and custom functions last.
  • Folding is mandatory for efficient incremental refresh on large GL tables.

Practice Questions

Q1. Folding boundary [L1]

For the query Source (SQL Server dbo.APInvoices) → Removed Columns → Filtered Rows (InvoiceDate ≥ 1-Apr-2025) → Added Index → Grouped Rows (by Vendor, sum Amount) → Merged with VendorMaster.xlsx, state which steps fold and where View Native Query becomes greyed out.

Q2. Reorder for performance [L2]

A query on a 25-million-row SQL GL table: Source → Trimmed Text on Narration → Filtered Rows (CompanyCode = "IN02", FiscalYear = 2026) → Removed Columns (keeps 6 of 41) → Grouped Rows (Account, Period). Refresh takes 14 minutes. Rewrite the step order, justify each move, and describe how you would prove the improvement.

💡 Hint: Ask which step forces local evaluation and whether it needs to happen before the aggregation at all.

Q3. Diagnostics reading [L2]

Query Diagnostics for a refresh shows the same select ... from dbo.Bank statement sent to the server three times, each taking 40 seconds. Give two plausible causes in the query design and the fix for each.

Q4. Incremental refresh readiness [L3]

Your FP&A lead wants incremental refresh on a 7-year GL fact sourced from MySQL, partitioned by month. List the checks you would perform on the Power Query side before enabling it, including how you will confirm folding of the RangeStart/RangeEnd filter and what would make it fail.

Q5. Interview question [L2]

"Explain query folding to a finance manager who has never used Power Query, and tell me one situation where you deliberately broke folding." Write your answer in under 200 words.
