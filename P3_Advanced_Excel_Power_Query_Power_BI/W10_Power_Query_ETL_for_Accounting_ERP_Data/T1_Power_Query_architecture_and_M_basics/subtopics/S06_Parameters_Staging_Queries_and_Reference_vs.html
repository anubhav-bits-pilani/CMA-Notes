Parameters, Staging Queries and Reference vs Duplicate

Scope: Parameters (file path, as-of date) and staging vs referenced queries (Reference vs Duplicate)

Why it matters

A month-end pipeline must run on the controller's laptop, the analyst's laptop and in the Power BI Service, for April and for March, without anyone editing M. Two design tools make that possible. Parameters remove hard-coded values (folder paths, as-of dates, FY labels, server names) from query logic. Staging and referenced queries separate "get the data once" from "shape it several ways", so that the bank file is read and cleaned once and then feeds the reconciliation, the exceptions list and the control-total check. Getting Reference vs Duplicate wrong is a common cause of logic drift (two copies of cleaning steps diverge) and slow refresh.

Core notes

Parameters

Create via Home → Manage Parameters → New Parameter. A parameter has a name, description, Required flag, Type (Text, Date, Decimal, etc.), Suggested values (any value / list of values / query), and Current value. In M it is just a query whose value carries metadata:

"D:\Finance\MonthEnd\BankCSV\" meta [IsParameterQuery=true, Type="Text", IsParameterQueryRequired=true]

Typical finance parameters:

Parameter Type Example Used by
FolderPath Text D:\Finance\MonthEnd\TB\ Folder.Files(FolderPath)
AsOfDate Date #date(2026,3,31) Ageing buckets, cut-off filters
FYLabel Text "FY2025-26" Filtering budget scenario
ServerName/DatabaseName Text "sql-fin-prod" Sql.Database(ServerName, DatabaseName)
Tolerance Decimal 1.00 Reconciliation matching tolerance

Use them by name in any step: Folder.Files(FolderPath), Table.SelectRows(t, each [DocDate] <= AsOfDate).

In Power BI, parameters can be changed in the Service (Dataset settings → Parameters) and are required for incremental refresh (RangeStart/RangeEnd) and for deployment pipelines (switching dev/prod servers). Parameters typed as Text used in a source path also allow the Service to bind the right data source credentials.

In Excel, a common alternative is a named cell driving the path, so users change it on a "Control" sheet without opening the editor:

FolderPath = Excel.CurrentWorkbook(){[Name="rngFolderPath"]}[Content]{0}[Column1]

Or derive the path relative to the workbook location using a CELL("filename") formula in the named cell, so the whole folder (workbook + data subfolder) can be moved or emailed.

Note that a query reading a named cell from the current workbook combined with an external file can trigger Formula.Firewall errors (s08); set privacy levels or keep the parameter query simple.

Staging queries and layering

A staging query connects to a source, does the minimum source-specific work (navigate, skip report header, promote headers, select needed columns, type) and is set to Connection only (disable load). Downstream queries reference it. Recommended layering:

  1. Parameters — paths, dates, tolerances.
  2. Source/staging — stg_BankHDFC, stg_BookLedger, stg_CoA (connection only).
  3. Cleaned/conformed tables — BankAll, BookCash with standard columns: Date, Ref, Amount, Narration, Source.
  4. Outputs — Exceptions_BankNotInBooks, Exceptions_BooksNotInBank, TB_Consolidated (loaded to sheet/model).
  5. Checks — chk_ControlTotals (loaded so it is visible).

Benefits: one place to fix a source layout change, readable lineage in Query Dependencies, fewer source hits, and outputs that read like business logic rather than cleaning.

Reference vs Duplicate

Reference Duplicate
What it creates New query whose Source step is = stg_Bank Independent copy of all steps
Changes to the original Flow through Do not flow through
Lineage Dependency arrow in Query Dependencies No link
Typical use Several outputs from one cleaned table Starting point for a similar but different source (e.g. adapting HDFC cleaning for SBI)
Risk Breaking the base breaks all children Logic drift — fixes applied to one copy only

Choose Reference whenever the outputs should share logic. Choose Duplicate only when you deliberately want to fork — and then consider turning the shared part into a function instead.

Does Reference re-read the source?

Logically a referenced query re-evaluates its base. In Power BI Desktop each loaded query refreshes in its own evaluation, so if three outputs reference stg_Bank, the source may be read three times (caching helps within a refresh but is not guaranteed across separate evaluations). In Excel, likewise each loaded query evaluates separately. Mitigations: keep staging light, consolidate outputs where possible, buffer inside a query that references the same table multiple times (c06), or in Power BI use Dataflows/linked entities for heavy shared staging. Do not assume referencing equals caching.

Illustration

The bank recon file has FolderPath and AsOfDate parameters. stg_BankFiles = Folder.Files(FolderPath) filtered to .csv (connection only). BankAll references it and applies fxCleanBank. BookCash references stg_TallyLedger. Exceptions_Bank and Exceptions_Book both reference BankAll and BookCash with different anti-joins. Moving to a colleague's laptop requires changing one parameter value; the six queries are untouched.

Edge cases & judgement calls

  • Parameters typed "Any" do not appear as parameters in the Power BI Service; set an explicit type.
  • Trailing backslash in folder parameters: be consistent; concatenations like FolderPath & "CoA.xlsx" break if the slash is missing. Use Text.EndsWith to guard.
  • As-of date parameter vs DateTime.LocalNow(): a parameter makes ageing reproducible for audit; LocalNow makes yesterday's report different today (Topic 6).
  • Circular references: a staging query cannot reference an output that references it — Power Query raises a cyclic reference error.
  • Duplicate after converting to function: duplicating a query that calls a function is fine; duplicating the function itself forks the logic.
  • Deleting a referenced query is blocked until dependants are removed or repointed.

Key takeaways

  • Parameterise every value that differs by machine, period or environment: paths, as-of date, server, tolerance.
  • In Excel, a named cell is a user-friendly parameter; in Power BI, typed parameters are editable in the Service.
  • Layer queries: parameters → connection-only staging → cleaned tables → outputs → checks.
  • Reference shares logic; Duplicate forks it. Default to Reference; use functions for shared logic across sources.
  • Referencing does not guarantee the source is read only once; design and measure.

Practice Questions

Q1. Parameterise a query [L1]

Rewrite this source step using parameters for the folder and as-of date, and create the parameter definitions: Source = Folder.Files("C:\Users\priya\OneDrive\Close\Mar26\"), followed by a filter each [Posting Date] <= #date(2026,3,31).

Q2. Reference or Duplicate? [L2]

For each, choose Reference or Duplicate and justify: (a) a summary by ledger and a detail list, both from the cleaned Tally Day Book; (b) a new query for Axis Bank statements whose layout is similar to the existing HDFC query; (c) a Dr/Cr control-total check on the cleaned TB; (d) a "what-if" copy to experiment with a new mapping without disturbing the live report.

💡 Hint: Ask whether a future fix to the base should flow into the new query.

Q3. Design the layering [L2]

Design the query list (names, layer, load setting) for a pipeline that reads 12 branch TB files from a folder, a CoA mapping workbook and a budget workbook, and produces a consolidated TB, a budget fact, a mapping-gap exceptions list and a control-totals table.

Q4. Named-cell path in Excel [L2]

Write the M to read a folder path from a named range rngPath on a Control sheet, and explain how to make the path follow the workbook when the whole close folder is copied to a new month's location. State the privacy-level issue you may encounter.

Q5. Performance case [L3]

Five output queries reference stg_GL, which reads a 300 MB CSV and does 14 cleaning steps. Refresh All in Excel takes 9 minutes. Explain why, and propose two redesigns with their trade-offs.
