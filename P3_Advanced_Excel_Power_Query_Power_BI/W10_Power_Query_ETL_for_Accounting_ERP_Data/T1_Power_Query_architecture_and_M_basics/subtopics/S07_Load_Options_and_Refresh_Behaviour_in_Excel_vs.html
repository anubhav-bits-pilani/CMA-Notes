Load Options and Refresh Behaviour in Excel vs Power BI

Scope: Load options (Connection only, Table, Data Model) and how refresh differs in Excel vs Power BI

Why it matters

Where a query's result lands decides file size, whether users can pivot it, whether it hits Excel's 1,048,576-row limit, and how it refreshes. A consolidated GL of 3 million lines cannot go to a worksheet; a list of 40 unreconciled bank items should go to a sheet the reviewer can annotate; staging queries should go nowhere. Refresh mechanics also differ sharply between Excel (manual, desktop, per-user credentials) and Power BI (Desktop refresh, then Service scheduled refresh through gateways), which matters when you hand a close pack over to someone else or promise the CFO a 7 a.m. dashboard.

Core notes

Load destinations in Excel

Home → Close & Load To… (or right-click query → Load To…) offers:

Option What happens Use for Limits
Table Result written to an Excel table on a sheet Exceptions lists, small mappings, outputs to annotate 1,048,576 rows; file bloats; slower refresh
PivotTable Report / PivotChart Loads to Data Model and creates a pivot Quick analysis Data Model rules apply
Only Create Connection No output; query available to reference Staging, functions, parameters None
Add this data to the Data Model (checkbox) Loads to Power Pivot (VertiPaq, compressed) Large facts, relationships, DAX measures Memory; 2 GB file practical limit in 32-bit, much larger in 64-bit

Table and Data Model can both be ticked, but doing so doubles storage — avoid. Change destinations later via Data → Queries & Connections → right-click → Load To. Connection-only queries show "Connection only" in the pane.

Columns you add manually next to a loaded table (e.g. a "Reviewer comment" column) are kept and stay aligned row-by-row only if the table refreshes with the same sort order and row count — a fragile pattern. A better approach for annotated exceptions is a separate comments table keyed by a stable ID, merged back in.

Load settings in Power BI Desktop

Every query loads to the model by default. Right-click → uncheck Enable load to make it connection-only (shown in italics). Also: Include in report refresh — unchecking it freezes a query's data (useful for a static FX table, dangerous if forgotten). Functions and parameters never load.

Refresh in Excel

  • Refresh (single query) or Data → Refresh All (Ctrl+Alt+F5). Refresh All refreshes every connection, including pivots — but pivots based on worksheet tables refreshed by queries may refresh before the query completes; set background refresh off (Query Properties → uncheck Enable background refresh) or refresh twice.
  • Query Properties: refresh every n minutes, refresh on file open, enable background refresh, refresh this connection on Refresh All.
  • Credentials are stored per user per machine (Data source settings). A colleague opening your file is prompted for their own credentials and must have access to the same paths — hence parameters.
  • Privacy levels are evaluated locally (s08).
  • No native scheduling. Options: Power Automate Desktop/Office Scripts (limited for Power Query), a VBA ThisWorkbook.RefreshAll on open, or move to Power BI/Dataflows.
  • Excel for the web can refresh some cloud sources (SharePoint, OneDrive, certain online sources), not local files or on-prem databases.

Refresh in Power BI

  • Desktop: Home → Refresh refreshes all loaded queries in parallel (subject to parallel-load settings). Results land in the model; visuals update.
  • Service: after publishing, the semantic model (dataset) refreshes on demand or on a schedule (up to 8 per day on Pro, 48 on Premium/Fabric capacity). Credentials are set in the dataset's data source settings. On-premises sources (local folders, on-prem SQL, Tally ODBC) need an on-premises data gateway; cloud sources (SharePoint Online, OneDrive, Azure SQL) do not.
  • Incremental refresh (partition by date using RangeStart/RangeEnd) refreshes only recent periods — requires folding.
  • Refresh failure emails the owner; a failed refresh leaves the previous data in place.

Comparison summary

Aspect Excel Power BI
Destinations Sheet table, Data Model, connection only Model (Enable load) or none
Size Sheet ≤ ~1.05m rows; Data Model larger Model; dataset size limits per licence
Trigger User clicks / on open / timer while open Desktop click; Service schedule/API
Credentials Per user, per machine Stored in Service / gateway
On-prem sources Direct Gateway required in Service
Annotating outputs Easy (but fragile) Not intended — use write-back tools
Consumers Whoever has the file Workspace/app permissions, RLS

Illustration

The bank recon pipeline: stg_BankFiles, stg_TallyBank, fxCleanBank — connection only. BankAll (≈18,000 rows a year) — Data Model only, for a pivot of receipts by month. Exceptions_BankNotInBooks and Exceptions_BooksNotInBank (tens of rows) — sheet tables for review. chk_ControlTotals — sheet table on a "Checks" tab with conditional formatting on the difference column. In Power BI the same design would load BankAll and the two exception queries to the model and disable load on staging.

Edge cases & judgement calls

  • Loading to sheet then pointing another query at that sheet (Excel.CurrentWorkbook) creates a hidden two-stage refresh dependency; reference the query directly instead.
  • Disabling load on a query that a visual uses in Power BI deletes the table from the model and breaks visuals and measures.
  • "Include in report refresh" off is useful for slow, static tables but must be documented; stale FX rates are a classic audit finding.
  • Data Model in Excel and Power BI share VertiPaq: the Excel model can be imported into Power BI Desktop (File → Import → Power Query, Power Pivot, Power View).
  • Row-order assumptions: loaded tables do not guarantee order unless you sort as the final step.
  • Gateway mode: personal gateway does not support all features (e.g. DirectQuery); standard gateway is preferred for team datasets.

Key takeaways

  • Staging, functions and parameters: connection only. Large facts: Data Model. Small review lists: sheet tables.
  • Never load to both a sheet and the Data Model by accident.
  • Excel refresh is user-driven with per-user credentials; Power BI Service refresh is scheduled with stored credentials and gateways for on-prem sources.
  • Cloud folders (SharePoint/OneDrive) avoid the gateway; local paths and on-prem databases need one.
  • Turn off background refresh in Excel when pivots depend on query outputs.

Practice Questions

Q1. Assign load destinations [L1]

For each query in an Excel close workbook choose a load destination and justify: pFolderPath, fxCleanTB, stg_TBFiles, TB_Consolidated (2.4 million rows), CoA_Map (1,200 rows), Exceptions_UnmappedLedgers (35 rows), chk_ControlTotals (12 rows).

Q2. Refresh order problem [L2]

After Refresh All, a pivot on the "Exceptions" sheet still shows last month's numbers until you press Refresh All a second time. Explain why and give two fixes.

💡 Hint: Think about background refresh and what the pivot's source is.

Q3. Moving from Excel to Power BI Service [L2]

Your Excel bank recon reads CSVs from D:\Bank\ and the Tally ledger via ODBC. The CFO wants a Power BI report refreshed daily at 7 a.m. List every change required in sources, credentials, infrastructure and load settings.

Q4. Annotated exceptions [L3]

Reviewers type comments in a column beside the loaded Exceptions table; after the next refresh, comments are misaligned with rows. Design a robust alternative using Power Query so that comments stay attached to the correct exception across refreshes.

Q5. Licence and refresh limits [L2]

A Pro-licensed dataset must refresh hourly during the last 3 days of the close. State whether this is possible and two alternatives if not.
