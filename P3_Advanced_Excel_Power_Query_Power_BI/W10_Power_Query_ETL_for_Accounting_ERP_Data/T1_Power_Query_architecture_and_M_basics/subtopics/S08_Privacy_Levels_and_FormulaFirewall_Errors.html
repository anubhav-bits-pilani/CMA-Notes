Privacy Levels and Formula.Firewall Errors

Scope: Privacy levels and Formula.Firewall errors when combining sources

Why it matters

Reconciliation work is by definition about combining sources: a bank CSV with a Tally ledger, a SQL GL with an Excel mapping, a parameter cell with a folder. Power Query has a security layer — the Data Privacy Firewall — that stops data from one source leaking into a query sent to another (for example, a customer list in Excel being embedded into a WHERE clause sent to a web API). When it cannot prove a combination is safe, it raises Formula.Firewall errors that confuse almost every new user. Knowing the rules lets you fix them correctly instead of reflexively switching privacy off on a file containing payroll or customer PAN data.

Core notes

Privacy levels

Each data source (identified by path/URL/server) carries a privacy level, set in Data source settings → Edit Permissions → Privacy Level:

Level Meaning Examples
Private Sensitive; must not be sent to any other source Payroll file, customer master with PAN/Aadhaar, bank statements
Organizational Can be combined with other Organizational sources; not with Public Company SharePoint, internal SQL Server, shared drive
Public Anyone can see it RBI reference rates web page, public holiday list
None (not set) Treated per the global setting; prompts in Desktop —

The firewall prevents data from a more restrictive source being sent to a less restrictive or different source. Private data can only be combined with data from the same source; Organizational can flow to Organizational; Public can flow anywhere.

Privacy settings (Options)

  • Excel: Query Options → Global/Current Workbook → Privacy. Power BI: Options → Global/Current File → Privacy.
  • Choices: Always combine data according to your Privacy Level settings for each source (default), Combine according to each file's settings, and Always ignore Privacy Level settings (the "fast-combine" option).
  • Ignoring privacy levels can speed up refresh and suppress errors, but in Power BI Service the setting may not apply in the same way, and it removes a genuine protection. Use it only where all sources are internal and you understand the risk.

Two kinds of Formula.Firewall error

1. Privacy-level conflict

Formula.Firewall: Query 'X' (step 'Y') is accessing data sources that have privacy levels which cannot be used together. Please rebuild this data combination.

Cause: e.g. merging a Private bank CSV with a Public web table. Fix: set correct levels (both Organizational if both are internal), or restructure so the data does not need to cross.

2. Partition (rebuild data combination) error

Formula.Firewall: Query 'X' (step 'Y') references other queries or steps, so it may not directly access a data source. Please rebuild this data combination.

This occurs even when privacy levels are compatible. The firewall splits evaluation into partitions; a partition that both accesses a data source and references another query/partition that accesses a data source cannot be evaluated safely. Classic finance triggers:

  • A query reads a folder path from a named cell (Excel.CurrentWorkbook()), then in the same query calls Folder.Files(path).
  • A query takes a list of account codes from one query and passes them into Sql.Database(..., [Query="... IN (" & codes & ")"]).
  • A function is invoked per row where the function accesses a file and the outer query references another source.

Fixes for the partition error

  1. Separate source access from combination: create one query per source access (staging, connection only), then a third query that only references them and combines. Each partition then either accesses a source or combines, not both.
  2. Inline the parameter: if the path parameter is a simple text parameter (Manage Parameters) rather than a query reading a sheet, the firewall treats it as a constant.
  3. Put the source access inside the same query as the combination, so there is one partition (works for simple cases).
  4. Set privacy levels consistently — with all sources Organizational and privacy set to combine by levels, many combination errors disappear because the firewall can prove safety.
  5. As a last resort, ignore privacy levels for the file.

Example restructure for the named-cell path:

// Query: pFolderPath  (connection only)
= Excel.CurrentWorkbook(){[Name="rngFolderPath"]}[Content]{0}[Column1]

// Query: stg_Files    (connection only)
= Folder.Files(pFolderPath)

If stg_Files still errors, set both the current workbook and the folder to Organizational, or replace pFolderPath with a Manage Parameters text parameter.

Power BI Service

In the Service, privacy levels are set per data source in dataset settings or gateway data source settings. A combination that works in Desktop with "ignore privacy levels" may fail in the Service. Gateway data sources and cloud sources must have compatible levels; mismatches surface as refresh failures with the same firewall text.

Performance angle

Privacy partitions also affect performance: with privacy enforced, the engine may have to fully evaluate one source locally before combining, preventing folding of the combination into a database query. Query Diagnostics shows "Partitions" for this.

Illustration

Recon file: Bank CSV (Private, contains account numbers), Tally ledger via ODBC (Organizational), tolerance from a named cell (current workbook). The merge query references both cleaned queries and errors with a privacy-level conflict. Assessment: all three are internal company data handled by the finance team; setting the bank folder to Organizational is defensible, documented in the file's "Read me" tab. The tolerance cell is moved into a typed parameter to avoid the partition error.

Edge cases & judgement calls

  • Do not downgrade sensitive data to Public to silence an error; a Public source can be sent anywhere, including web calls.
  • Web lookups with internal data (e.g. calling a GSTIN validation API with your vendor list) are exactly what the firewall protects against; consider whether the combination is acceptable under company data policy and the DPDP Act 2023 before overriding.
  • Fast combine in shared files: the setting is per file/user; a colleague's global setting may differ, so the file errors on their machine only.
  • Functions and firewall: invoking a function that reads File.Contents(path) with a path derived from another query is a frequent trigger; pass the binary ([Content]) instead of the path.
  • Errors appear at refresh, not at authoring in some cases, because the preview cache already holds the data.

Key takeaways

  • Privacy levels (Private, Organizational, Public) govern which sources may be combined; the firewall enforces them.
  • "Privacy levels which cannot be used together" is a level conflict; "references other queries … may not directly access a data source" is a partition problem.
  • Fix partition errors by separating source access into staging queries and combining in a reference-only query.
  • Set internal sources consistently to Organizational; reserve Private for genuinely restricted data.
  • Ignoring privacy levels is a last resort and may not carry over to the Service.

Practice Questions

Q1. Classify the level [L1]

Assign a privacy level and justify: (a) HR payroll register on a restricted share; (b) Finance SharePoint site with monthly TBs; (c) RBI reference rate web page; (d) bank statement CSVs downloaded from net-banking; (e) on-prem SQL Server GL database.

Q2. Diagnose the error [L2]

Query Recon has the steps: Path = Excel.CurrentWorkbook(){[Name="rngPath"]}[Content]{0}[Column1], Files = Folder.Files(Path), Bank = ..., Merged = Table.NestedJoin(Bank, {"Ref"}, BookLedger, {"Ref"}, "B", JoinKind.LeftAnti). Refresh fails with "references other queries or steps, so it may not directly access a data source". Explain the cause and restructure the queries.

💡 Hint: Count how many partitions both access a source and depend on other queries.

Q3. Policy judgement [L3]

A junior analyst set "Always ignore Privacy Level settings" globally because merges were failing. The file combines payroll data with a public PIN-code web API to geocode employees. Write a short review note: the risk, the correct design and the settings you would require.

Q4. Desktop works, Service fails [L2]

A dataset combining a SharePoint folder and an on-prem SQL Server refreshes fine in Desktop but fails in the Service with a Formula.Firewall error. List the likely causes and where in the Service and gateway you would fix them.
