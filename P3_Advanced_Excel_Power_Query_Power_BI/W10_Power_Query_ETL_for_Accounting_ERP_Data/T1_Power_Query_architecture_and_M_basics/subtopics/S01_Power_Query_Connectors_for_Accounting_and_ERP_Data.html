Power Query Connectors for Accounting and ERP Data Sources

Scope: Connectors: Text/CSV, Excel Workbook, Folder, SQL Server, MySQL/ODBC, SharePoint Folder

Why it matters

Every finance automation starts with a connection. A month-end pack in an Indian mid-size company typically pulls a Tally trial balance exported to Excel, bank statement CSVs from HDFC/ICICI/SBI net-banking, SAP line-item downloads (FBL3N) saved as text, a budget workbook from the FP&A team on SharePoint, and sometimes a direct read from a reporting database (SQL Server or MySQL behind a custom billing system). The connector you choose decides three things that matter later: whether the query can fold (push work back to the source), whether refresh will work on someone else's machine or in the Power BI Service, and how much clean-up the first few steps must do. Choosing "Folder" instead of "Text/CSV" for monthly bank files, for example, is the difference between editing a query every month and simply dropping a file in and pressing Refresh All.

Core notes

How a connector maps to M

Every item in Get Data generates a source function in M. The UI is just a wizard that writes the first one or two steps of the query. Knowing the underlying function lets you edit paths, add options (delimiter, encoding) and parameterise them.

Text/CSV

The CSV connector reads a binary with File.Contents and parses it with Csv.Document. The options record controls the delimiter (comma, tab, pipe — SAP downloads are often tab-delimited), the number of columns, the encoding (65001 = UTF-8, 1252 = Western Windows; Indian bank files with ₹ or Devanagari narrations need UTF-8) and the QuoteStyle (whether commas inside quotes, such as "NEFT/ABC Traders, Pune", are treated as text or as delimiters). The UI preview sniffs these from the first 200 rows; it can guess wrong if the file starts with a report header. Note that Power BI hard-codes Columns=n in the generated step — if next month's file has an extra column it will be silently dropped, so delete that option when the layout can grow.

Excel Workbook

Excel.Workbook returns a navigation table — one row per sheet, defined table and named range, with columns Name, Data, Item, Kind and Hidden. The UI then drills into one item with {[Item="TB",Kind="Sheet"]}[Data]. Prefer Excel Tables (Kind = "Table") over sheets when you control the source: a table has a fixed header and a defined extent, so blank trailing rows and stray notes beyond the range are not picked up. Sheets bring in the used range, including Tally's report header rows. The third argument true (delayTypes) leaves columns untyped so you control typing; null for useHeaders means no auto-promotion.

Folder

Folder.Files(path) returns one row per file in the folder and its sub-folders, with Content (binary), Name, Extension, Date accessed, Date modified, Date created, Attributes and Folder Path. It does not read the files; you filter the list (extension, name pattern, exclude ~$ lock files) and then apply a transform function to each Content. Use Folder.Contents if you want only the top level as a navigable hierarchy. The Combine Files button generates a helper-query set (sample file, parameter, transform function) — covered in Topic 4.

SQL Server

Sql.Database("server", "database") returns a navigation table of schemas, tables and views. Navigating to dbo.GLEntries and then filtering rows and removing columns lets Power Query fold those steps into a single SELECT ... WHERE statement — the server does the work and only the filtered rows travel. Authentication options: Windows (current user), Database (SQL login), Microsoft account (Azure SQL). For Power BI Service refresh of an on-premises server you need a gateway (Week 12).

MySQL / ODBC

MySQL.Database(server, database) requires the MySQL Connector/NET (Oracle) installed on the machine — Power BI Desktop throws "This connector requires one or more additional components" otherwise. Where no native connector exists, ODBC is the universal fallback: Odbc.DataSource("dsn=TallyODBC", [HierarchicalNavigation=true]) or Odbc.Query(dsn, "SELECT ..."). Tally Prime exposes an ODBC server (default port 9000) when the company is open, which lets you pull ledgers without exporting. ODBC folding depends on the driver's SQL capabilities; assume little folding with Tally.

SharePoint Folder

SharePoint.Files("https://contoso.sharepoint.com/sites/Finance", [ApiVersion=15]) takes the site URL, not the folder URL, and returns every file in every document library of that site, with a Folder Path column. You then filter on Folder Path (e.g. contains /Shared Documents/MonthEnd/Bank/). Because it is a cloud source, the Power BI Service can refresh it without a gateway, which is why finance teams move drop-folders from a local C:\ path to SharePoint/OneDrive. SharePoint.Contents is faster on large sites because it navigates lazily instead of listing every file.

Illustration: picking connectors for a close pack

A company with 6 branches receives monthly: branch TB as .xlsx (Tally export), one HDFC and one SBI CSV per month, and a sales register from a MySQL billing system. Design: Folder (or SharePoint Folder) for branch TBs and bank CSVs, each with a custom cleaning function; MySQL for the sales register, navigating to the table and filtering FY and period so that the filter folds; Excel Workbook pointing to a single CoA mapping table. The query count stays fixed as months are added — only folder contents grow.

Edge cases & judgement calls

  • Excel open in another process: reading an Excel file that is open is usually fine, but files on a network share locked by Tally or an antivirus scan can fail with "The process cannot access the file". Copy-to-staging or SharePoint avoids this.
  • .xls (Excel 97-2003) needs the ACE OLEDB provider; 32/64-bit mismatch between Office and Power BI produces provider errors. Re-save as .xlsx where possible.
  • CSV that is really a report: many bank CSVs have 10–15 header lines (account number, period, opening balance). Do not rely on the connector's header promotion — skip rows by condition (Topic 2).
  • SharePoint site vs folder URL: pasting the full folder URL into SharePoint.Files fails; use the site root, then filter Folder Path.
  • Native SQL vs navigation: typing a SQL statement in the SQL Server dialog stops folding for later steps (see c03). Use navigation unless the query genuinely needs SQL the UI cannot express.
  • Credentials are stored per data source path, not per query; changing a server name requires new credentials in Data source settings.

Key takeaways

  • Each connector is a wizard over a source M function; learn the function so you can parameterise and edit it.
  • Files (CSV, Excel, Folder, SharePoint) never fold; databases (SQL Server, MySQL) fold; ODBC folds only as far as the driver allows.
  • Use Folder/SharePoint Folder for recurring monthly drops so the query count stays constant.
  • Prefer Excel Tables over sheets when you control the source layout.
  • MySQL needs the separate connector; Tally is reachable over ODBC on port 9000.
  • Cloud sources (SharePoint/OneDrive) refresh in the Service without a gateway; local paths and on-prem databases need one.

Practice Questions

Q1. Connector choice for a close pack [L1]

List the most appropriate Power Query connector and the M source function for each: (a) a single HDFC bank statement CSV; (b) a folder holding 12 monthly Tally TB exports; (c) the gl_entries table in a MySQL billing database; (d) a budget workbook stored in the Finance SharePoint site; (e) Tally Prime data read live without exporting.

Q2. Which steps fold? [L2]

A query connects to SQL Server table dbo.GLLines (40 million rows), filters FiscalYear = 2026, removes 30 of 38 columns, groups by Account summing Amount, then connects to a CSV of account mappings and merges it. Identify which steps can fold to SQL Server and which cannot, and explain what volume of data is transferred over the network.

💡 Hint: Folding stops at the first step that the source cannot translate; think about where the CSV enters.

Q3. SharePoint Folder setup [L2]

Your drop-folder URL is https://abcltd.sharepoint.com/sites/FinanceOps/Shared Documents/MonthEnd/BankCSV. Write the M for the first two steps that list only the .csv files in that folder, and explain why the obvious first attempt using the full URL fails.

Q4. CSV options audit [L2]

A query built in Power BI Desktop on an April bank file contains Csv.Document(File.Contents("C:\Users\ravi\Downloads\apr.csv"), [Delimiter=",", Columns=7, Encoding=1252, QuoteStyle=QuoteStyle.None]). In May the bank adds a "Value Date" column and narrations include commas inside quotes and the ₹ symbol. List every problem in this step and rewrite it.

Q5. Interview: database vs file source [L3]

An interviewer asks: "Your CFO wants the daily sales flash to come from the billing system. IT offers either a nightly CSV dump on a shared drive or read-only access to the MySQL reporting replica. Which do you choose for Power Query and why?" Structure an answer covering folding, refresh in the Service, data volume, security and dependency on IT.
