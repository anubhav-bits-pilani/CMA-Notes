Objective: Automate repetitive Tally/SAP/Oracle trial balance cleaning, multi-file consolidation, and unpivoting using Power Query.

How this week fits

Week 10 opens the automation half of Phase 3 (Advanced Excel, Power Query & Power BI Automation). Week 9 gave you formula-based tools — dynamic arrays, XLOOKUP, SUMIFS, LET/LAMBDA — which recalculate live but must be rebuilt or extended whenever a new file or month arrives. This week moves the repetitive part of month-end — cleaning Tally/SAP/Oracle exports, stacking branch files, reshaping budgets, matching bank to books — into Power Query, where the logic is recorded once as M and replayed on every refresh.

Prerequisites: Weeks 1–4 (TB structure, Dr/Cr conventions, BRS, month-end close and control-account reconciliations), Week 9 (lookup and aggregation formulas, to compare approaches) and your MySQL background (joins, grouping, unions). What comes next: Week 11 loads the clean tables produced here into the Data Model / Power Pivot as a star schema with a Calendar; Week 12 publishes to the Power BI Service with gateways and scheduled refresh; Weeks 17–20 reuse the budget and actuals facts for variance analysis and rolling forecasts.

The exercise draws on Topics 1, 2, 4 and 5 (architecture, cleaning, folder consolidation, reconciliation joins); the Saturday assessment on Topics 1, 2, 3 and 6 (architecture, cleaning, unpivoting, fiscal columns).

Refresh before starting

MySQL JOIN, GROUP BY, UNION

MySQL JOIN, GROUP BY and UNION, which map directly to Merge, Group By and Append

  • INNER JOIN / LEFT JOIN / RIGHT JOIN / full outer (in MySQL via LEFT JOIN ... UNION ... RIGHT JOIN) → Merge Queries with JoinKind.Inner, LeftOuter, RightOuter, FullOuter.
  • Anti-join LEFT JOIN b ON ... WHERE b.key IS NULL → JoinKind.LeftAnti (and RightAnti for the other side).
  • GROUP BY col with SUM(), COUNT(*) → Group By (Table.Group) with Sum, Count Rows, All Rows.
  • UNION ALL → Append (Table.Combine); UNION (distinct) → Append then Remove Duplicates (Table.Distinct).
  • WHERE → Filter Rows; SELECT col list → Choose Columns; ORDER BY → Sort.
  • Recall: join keys must have identical types; NULL never equals NULL in SQL (Power Query merges, by contrast, do match null to null — watch for that).

Week 9 lookup and SUMIFS patterns

Week 9 lookup and SUMIFS patterns, for comparing formula and ETL approaches

  • XLOOKUP(key, lookup_array, return_array, "Not found") ↔ a LeftOuter merge with an expand; the formula returns the first match only, the merge returns all matches (and can multiply rows).
  • COUNTIFS used to flag unmatched bank lines ↔ a LeftAnti merge.
  • SUMIFS(Amount, Ledger, x, Month, y) ↔ Group By on Ledger and Month.
  • VSTACK across sheets ↔ Append / Folder.Files + Table.Combine.
  • TRIM, CLEAN, TEXTSPLIT, TOCOL ↔ Text.Trim, Text.Clean, Table.SplitColumn, unpivot.
  • Rule of thumb: formulas for ad-hoc, small, interactive analysis; Power Query for recurring, multi-file, large or audit-trailed transformations.

BRS logic, TB structure and Dr/Cr conventions

BRS logic, TB structure and Dr/Cr conventions → Week 1–4

  • BRS reconciling items: cheques issued but not presented; cheques deposited but not credited (deposits in transit); bank charges, interest, direct credits (NEFT/UPI receipts) and ECS debits not yet in books; errors on either side.
  • Sign alignment: a receipt is a debit in the bank book (asset increases) and a credit in the bank statement (the bank's liability to you increases).
  • TB: every ledger's closing balance, Dr total = Cr total; group hierarchy per Schedule III; opening + debits − credits = closing for each ledger.
  • Convention for modelling: Dr positive, Cr negative; a balanced TB nets to zero.

Typical export layouts

Typical export layouts: Tally TB/Day Book, SAP FBL3N line items, Indian bank statement CSVs (UTR, cheque no.)

  • Tally TB: company/period header lines, "Particulars" caption, Debit/Credit columns (text, Indian grouping), groups and ledgers, Grand Total.
  • Tally Day Book: Date, Particulars, Vch Type, Vch No., Debit, Credit; in detailed mode date/voucher fields only on the first line of each voucher.
  • SAP FBL3N: one row per line item — Company Code, G/L Account, Document Number, Posting Date, Amount in LC (credits negative), Text, Cost Center; layout depends on the user's variant.
  • Indian bank CSVs: 10–20 header lines (account number, period, opening balance); columns Date, Narration, Chq./Ref.No., Value Date, Withdrawal, Deposit, Balance; narrations embed UTRs (e.g. 16–22 character NEFT/RTGS references), UPI IDs and cheque numbers; dd/mm/yy dates.

Cross-cutting concepts

Layered pipeline with parameterised paths

Layered pipeline: connection-only source/staging queries → cleaned tables → referenced outputs, with parameterised paths

Treat a Power Query file like a well-organised audit file. Layer 1 — parameters: folder path, as-of date, FY label, tolerance, server name; nothing else in the file contains a literal path or date. Layer 2 — source/staging (connection only): one query per source that only connects, navigates, skips report headers and selects the needed columns; for folders, a filtered file list. Layer 3 — cleaned/conformed tables (connection only or Data Model): standard column names and types — Date, Entity, Ledger/Account, Ref, Amount (Dr positive), Narration, SourceFile. Layer 4 — outputs: queries that reference cleaned tables and express business logic — consolidated TB, exceptions lists, budget fact — loaded to sheets or the model. Layer 5 — checks: control totals and exception logs, loaded visibly. Group queries in folders named by layer. The benefit is that a change in a bank's CSV layout touches one staging query; an output never needs to know where data came from; Query Dependencies reads top to bottom; and moving the file to another machine or to SharePoint means changing one parameter. Use Reference (not Duplicate) between layers so fixes flow downstream.

Refresh-safe steps

Refresh-safe steps: condition-based filters, Unpivot Other Columns, dynamic column lists, no positional row removal

A step is refresh-safe if it gives the correct result when next month's file has more rows, fewer rows, extra columns or a slightly different header block. The unsafe patterns are those that record positions or literal lists from the sample: Remove Top/Bottom Rows with a count, Keep Range, Table.Unpivot with listed months, an auto "Changed Type" listing every column, an expand step listing the sample's columns, Columns=7 in Csv.Document, hard-coded pivot value lists. Their safe counterparts: Table.Skip with a condition to find the caption row; Table.SelectRows with structural or text conditions to remove totals and blanks; Table.UnpivotOtherColumns with identifiers fixed, or a dynamic month list built by parsing headers; column lists built from Table.ColumnNames with List.Select/List.RemoveItems; MissingField.Ignore or MissingField.UseNull on select/remove/rename steps; typing once, at the end, with an explicit culture. The test is behavioural: keep a "torture" sample folder with a file that has two extra header lines, a missing optional column, a new month and an extra footer — refresh against it before every release of the file.

Control totals validation query

Control totals: a validation query capturing row counts and Dr/Cr sums per file

Every pipeline needs a query whose only job is to prove that nothing was lost or double counted. Per source file (and per stage where useful) it records: file name, branch/period parsed from the name, raw row count, cleaned row count, rows removed by rule, error rows, sum of Debit, sum of Credit, net, the report's own Grand Total captured before removal, and the difference. Add a Status column ("OK" when differences are within ₹1 and errors are zero) and load it to a Checks sheet with conditional formatting, or make the output query fail with error when any status is not OK. For bank files add opening and closing balances from the statement header and test opening + deposits − withdrawals = closing. For consolidations add a cross-check that the sum of branch nets is zero for each TB and that the consolidated total equals the sum of file totals. This is the Power Query equivalent of the tick-and-tie on a lead schedule; reviewers look at it first, and it converts silent failures (a skipped file, a misparsed sign, a removed error row) into visible ones.

Exercise pattern: function, folder, anti-joins

Exercise pattern: per-bank cleaning function + Folder.Files consolidation + LeftAnti/RightAnti merges → exceptions table loaded to a sheet

The week's exercise follows a reusable architecture. Per-bank cleaning functions (fxCleanHDFC, fxCleanSBI) take a file binary and return a standard table (Date, ValueDate, Ref, Narration, Amount with receipts positive, Bank, Account, SourceFile); each handles its bank's header block, date format, column names and narration parsing (UTR/cheque extraction). Consolidation: Folder.Files(pBankFolder), filter to .csv and exclude ~$ and archived files, derive the bank from the file name, invoke the matching function per row, then Table.Combine. The book side is the Tally bank ledger (Ledger Vouchers export or GL extract), cleaned and sign-aligned. Matching: normalise keys (trim, upper case, strip leading zeros, same types), add sequence numbers for repeated identical amounts, then JoinKind.LeftAnti (bank not in books — direct credits, charges, ECS debits) and JoinKind.RightAnti (books not in bank — unpresented cheques, deposits in transit). Optional second pass: match remaining items on amount within a date window. Output: a single exceptions table with a Side column, loaded to a sheet, plus control totals. Next month: drop files, Refresh All.

Performance: folding, buffering, load settings

Performance: folding, Table.Buffer before repeated merges, disabling load on staging queries

Performance is mostly design. Folding: for database sources, put filters, column removal and group-bys first so they run in SQL; push index columns, custom functions, buffers and cross-source merges to the end; verify with View Native Query or the folding indicators. Files never fold, so the equivalent is to drop unneeded columns and rows as early as possible. Buffering: a table used repeatedly — a book ledger merged three times, a list used inside a row-by-row List.Contains filter — may be re-evaluated each time; Table.Buffer (or List.Buffer) after it has been reduced keeps one in-memory copy. Do not buffer large tables early or before foldable steps. Load settings: staging and function queries should be connection only; load each fact once (sheet or Data Model, not both); avoid loading intermediate tables. Other levers: in Excel, disable background refresh where pivots depend on queries; in Power BI, consider parallel loading limits, and for very large file sources move the heavy staging into a Dataflow. Use Query Diagnostics to find the slow step before optimising.

Hands-on exercise brief

Roadmap exercise: Build an automated Bank Reconciliation & Multi-Branch GL Consolidator in Power Query that ingests 6 messy monthly CSV files and outputs clean unreconciled exceptions.

Scenario and inputs

Company: Shivneri Components Pvt Ltd, FY ending 31 March, three branches (Pune, Nashik, Aurangabad), two bank accounts (HDFC current account for Pune HO, SBI current account for the plant branches). Period: April–June 2025 (Q1 FY2025-26).

Create the following input files yourself (synthetic data), in …\Recon\Input\:

Folder Files Notes
Bank\ HDFC_2025-04.csv, HDFC_2025-05.csv, HDFC_2025-06.csv, SBI_2025-04.csv, SBI_2025-05.csv, SBI_2025-06.csv (the 6 monthly CSVs) HDFC: 18 header lines, columns Date (dd/MM/yy), Narration, Chq./Ref.No., Value Dt, Withdrawal Amt., Deposit Amt., Closing Balance; SBI: 20 header lines, columns Txn Date (dd-MMM-yyyy), Value Date, Description, Ref No./Cheque No., Debit, Credit, Balance; both with a variable-length footer
Books\ TallyBank_Q1.xlsx Ledger Vouchers for "HDFC Bank A/c" and "SBI Bank A/c": Date, Particulars, Vch Type, Vch No., Debit, Credit; Opening Balance, Current Total, Closing Balance rows
GL\ TB_Pune_2025-04.xlsx … TB_Aurangabad_2025-06.xlsx (9 files) Tally TB exports with report headers, "Particulars" caption, Debit/Credit text with Indian grouping, Grand Total
Master\ CoA_Map.xlsx Excel Table: Ledger Name, Group Code, Schedule III Line

Data volumes and seeded issues: about 250 bank lines per file; HDFC opening balance ₹48,62,350.00 on 1-Apr-2025; SBI opening balance ₹21,05,900.00. Seed these deliberately: 4 cheques issued in June not presented (total ₹3,84,600); 2 deposits in transit on 30 June (₹2,15,000); bank charges and GST on charges each month (₹590–₹1,770); 3 NEFT receipts not yet booked; one TDS-deducted customer receipt where the bank shows ₹98,000 and books show ₹1,00,000 (₹2,000 TDS booked separately); two identical ₹25,000 UPI receipts on the same day; one narration with a non-breaking space in the party name; one HDFC file with two extra header lines; one SBI file with an extra "Remarks" column; a ~$HDFC_2025-05.csv lock file and an HDFC_2025-05 (1).csv duplicate in the folder; branch TBs including inter-branch accounts ("Pune HO Current A/c" in branches, "Nashik Branch A/c" at HO) that net to zero.

Required queries (layers)

  1. Parameters: pRootPath, pAsOfDate (30-Jun-2025), pDateWindow (3 days), pAmountTolerance (₹1).
  2. Staging (connection only): stg_BankFiles (Folder.Files filtered: .csv, no ~$, no "(1)" duplicates — flag them instead), stg_TBFiles, stg_TallyBank, stg_CoA.
  3. Functions: fxCleanHDFC, fxCleanSBI, fxCleanTB — each (file as binary) as table, handwritten, with conditional header skip, footer removal by condition, en-IN typing, text cleaning, and Ref extraction (UTR or cheque number) from narration/ref columns.
  4. Cleaned tables: BankAll (Bank, Account, Date, ValueDate, Ref, Narration, Amount — receipts positive, SourceFile, Month), BookBank (same columns, sign-aligned), TB_Consolidated (Branch, Month, Ledger, Group Code, Schedule III Line, Amount Dr positive).
  5. Reconciliation: key normalisation; sequence numbers for duplicate amounts; pass 1 exact match on Account + Ref + Amount; pass 2 on Account + Amount within pDateWindow for unmatched items; LeftAnti and RightAnti outputs combined into Exceptions with Side ("In bank, not in books" / "In books, not in bank"), Reason guess (charges, direct credit, unpresented cheque, deposit in transit, difference within TDS pattern), Age in days at pAsOfDate.
  6. Checks (loaded): chk_BankFiles (per file: raw rows, cleaned rows, errors, deposits, withdrawals, opening + deposits − withdrawals vs closing), chk_TB (per branch-month: Dr, Cr, net, Grand Total diff), chk_InterBranch (net of inter-branch accounts per month = 0), chk_Unmapped (ledgers missing from CoA), chk_DuplicateFiles.
  7. BRS summary: balance per bank statement at 30-Jun-2025 reconciled to balance per books using the exception categories.

Required behaviour and deliverables

  • Dropping July files into the folders and pressing Refresh All updates everything with no M edits.
  • No absolute paths outside parameters; no positional row removal; no auto "Changed Type" steps; all custom columns typed.
  • Deliverable: one .xlsx with sheets Control (parameters via named cells or instructions), Exceptions, BRS, TB_Consolidated (or Data Model), Checks; Query Dependencies screenshot; a one-page README explaining the layers, matching rules and how to add a new bank.
