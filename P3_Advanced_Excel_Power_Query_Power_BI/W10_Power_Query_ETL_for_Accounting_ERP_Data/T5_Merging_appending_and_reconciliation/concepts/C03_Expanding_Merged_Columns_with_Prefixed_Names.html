Key concept

Expanding Merged Columns with Prefixed Names

Concept: Table.ExpandTableColumn(t, "Book", {"Date","Narration"}, {"Book.Date","Book.Narration"})

Statement

Expanded = Table.ExpandTableColumn(t, "Book", {"Date", "Narration"}, {"Book.Date", "Book.Narration"})

Table.ExpandTableColumn(table, column, columnNames, optional newColumnNames):

  • table — the merged table containing a nested-table column.
  • column — the name of that nested column ("Book").
  • columnNames — which columns of the nested tables to bring out ({"Date","Narration"}).
  • newColumnNames — the names to give them in the output, paired by position ({"Book.Date","Book.Narration"}).

Each outer row is repeated once per row in its nested table; a row whose nested table is empty is kept once with nulls in the new columns.

Explanation

After Table.NestedJoin, the matched right-side rows are hidden inside a nested table. Expanding brings selected columns out. The UI's expand button offers "Use original column name as prefix", which generates exactly the Book.Date style names. Prefixes matter because both sides usually share column names (Date, Narration, Amount); without new names, expansion would fail with a duplicate-column error or force awkward renames later.

Points to control:

  • Explicit column list. The list is hard-coded; columns added to the Book query later are not expanded. That is usually what you want in a recon (a stable output), but be aware of it.
  • Row multiplication. Expansion multiplies rows when a left row has several matches. Compare Table.RowCount before and after; if it grows in a step you expected to be one-to-one, the key is not unique (see sequence keys).
  • Aggregating instead of expanding. When you only need counts or sums from the right side, use Table.AggregateTableColumn(t, "Book", {{"Amount", List.Sum, "Book.Amount"}, {"Amount", List.Count, "Book.Matches"}}) — this cannot multiply rows.
  • Empty nested tables. In a LeftOuter merge, unmatched rows expand to nulls; [Book.Date] = null is then a quick way to flag unmatched rows (equivalent to an anti-join).
  • Types. Expanded columns carry the nested table's declared types only if the nested column had a typed table type; otherwise they may arrive as any. Re-type after expanding.

Illustration

Bank row: Ref "417", Amount −1,20,000, Date 08-Apr-2025, Narration "CHQ PAID 000417". Merged LeftOuter with Book on Ref + Amount; the nested Book table holds one row: VchNo "PMT/0412", Date 02-Apr-2025, Narration "Paid to Sharma Builders".

After Table.ExpandTableColumn(t, "Book", {"VchNo","Date","Narration"}, {"Book.VchNo","Book.Date","Book.Narration"}):

Ref Amount Date Narration Book.VchNo Book.Date Book.Narration
417 −1,20,000 08-04-2025 CHQ PAID 000417 PMT/0412 02-04-2025 Paid to Sharma Builders

A derived column ClearingDays = Duration.Days([Date] - [Book.Date]) = 6 days is then possible because both dates are on one row.

Q1. Write the expand [L1]

Q2. Expand or aggregate? [L2]

For each need, choose expand or Table.AggregateTableColumn and write the step: (a) number of book matches per bank row; (b) the book voucher number of the matched entry; (c) total book amount per bank settlement row.
