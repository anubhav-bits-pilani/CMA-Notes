Key concept

Table.FuzzyNestedJoin Syntax and Options

Concept: Table.FuzzyNestedJoin(t1, {"Party"}, t2, {"Party"}, "M", JoinKind.LeftOuter, [Threshold=0.85, IgnoreCase=true])

Statement

Fuzzy = Table.FuzzyNestedJoin(t1, {"Party"}, t2, {"Party"}, "M", JoinKind.LeftOuter,
    [Threshold = 0.85, IgnoreCase = true])

Table.FuzzyNestedJoin(table1, key1, table2, key2, newColumnName, optional joinKind, optional joinOptions) joins rows whose key values are similar rather than equal. Arguments mirror Table.NestedJoin; the last argument is an options record:

Option Meaning
Threshold Similarity score from 0.00 to 1.00 required to match (default 0.80)
IgnoreCase Case-insensitive comparison (default true)
IgnoreSpace Ignore spaces when comparing ("match by combining text parts", default true)
NumberOfMatches Maximum matches returned per left row
TransformationTable Table with From/To columns applied before scoring
ConcurrentRequests, Culture Performance and culture settings

Explanation

Fuzzy join answers "which master record most probably corresponds to this name?". Each left row's nested M column contains the right rows whose similarity is at or above the threshold. With JoinKind.LeftOuter, rows with no candidate get an empty table.

Practical rules:

  • Text keys only. Fuzzy matching works on text columns; convert other types first.
  • Pre-clean. Upper-case, remove punctuation, strip legal-form words ("PRIVATE", "LIMITED", "PVT", "LTD", "LLP") on both sides. Common words otherwise dominate similarity.
  • Run on leftovers. First match exactly on codes (GSTIN, PAN, customer code) and on cleaned names; fuzzy-match only the remainder. This limits false matches and runtime.
  • Limit candidates. NumberOfMatches = 1 gives the best candidate for a mapping suggestion; 2–3 gives reviewers alternatives.
  • No folding, in-memory. Fuzzy joins are computed by the mashup engine; on large tables, fuzzy-match a distinct list of names, then merge back exactly.
  • Not for references or amounts. Similar invoice numbers are different invoices.
  • Persist results. Load suggestions for review and store confirmed pairs in a mapping table; next month, the exact merge on the mapping table handles known names.

Practice Questions

Q1. Configure the options [L1]

Write a Table.FuzzyNestedJoin call that matches Receipts[Payer] to Customers[Name] with threshold 0.90, case-insensitive, returning at most 2 candidates per row, and using a transformation table query named NameSynonyms.

Q2. Distinct-then-merge pattern [L2]

Receipts has 1,20,000 rows but only 3,900 distinct payer names. Write the M that fuzzy-matches the distinct names to the customer master and then brings the matched customer code back to all 1,20,000 rows with an exact merge.

💡 Hint: Table.Distinct(Table.SelectColumns(Receipts, {"Payer"})) is the small table to fuzzy-match.

Q3. Audit concern [L3]

An auditor objects that the fuzzy match is "non-deterministic and unreviewed". Propose changes to the pipeline and process that address the objection while keeping the time saving.
