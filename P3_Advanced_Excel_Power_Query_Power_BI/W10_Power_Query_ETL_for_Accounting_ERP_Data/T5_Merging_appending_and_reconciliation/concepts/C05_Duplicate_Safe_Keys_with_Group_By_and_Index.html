Key concept

Duplicate-Safe Keys with Group By and Index

Concept: Duplicate-safe keys: Table.Group(t, {"Amount"}, {{"Rows", each Table.AddIndexColumn(_, "Seq", 1, 1)}}), expand, then join on Amount + Seq

Statement

Grouped = Table.Group(t, {"Amount"}, {{"Rows", each Table.AddIndexColumn(_, "Seq", 1, 1), type table}}),
Flat    = Table.ExpandTableColumn(Grouped, "Rows", List.Difference(Table.ColumnNames(t), {"Amount"}) & {"Seq"}),
Matched = Table.NestedJoin(BankFlat, {"Amount", "Seq"}, BookFlat, {"Amount", "Seq"}, "Bk", JoinKind.Inner)
  • Table.Group(t, {"Amount"}, ...) forms one group per distinct Amount; _ inside each is the group's sub-table.
  • Table.AddIndexColumn(_, "Seq", 1, 1) numbers the rows of each group 1, 2, 3 … (start 1, step 1).
  • Expanding returns a flat table with every original row plus Seq.
  • Joining on Amount + Seq pairs the n-th occurrence of an amount on one side with the n-th occurrence on the other.

Explanation

When the same amount appears several times on both sides, Amount alone is a many-to-many key. Adding Seq turns it into a unique key on each side, so each bank row matches at most one book row and surplus occurrences fall into the anti-joins.

Conditions:

  • Deterministic order. Sort before grouping (or sort inside the group) by date and a stable row ID, so the same rows get the same Seq on every refresh and pairing follows FIFO by date.
  • Same grouping on both sides. Group by exactly the key you will join on, minus Seq — e.g. AccountNo + AmtPaise — and apply identical sorting logic.
  • Aligned signs and normalised amounts. Use integer paise or rounded amounts after sign alignment; otherwise ₹25,000.00 and ₹24,999.9999 form different groups.
  • Scope. Adding a date bucket (day, week) to the group key reduces wrong pairings across distant dates; run a second pass on leftovers.
  • Typing. Table.AddIndexColumn accepts a fifth argument for the column type (Int64.Type); declare it so Seq is not any.
  • Expand list. Building the list from Table.ColumnNames(t) keeps the step refresh-safe when columns are added.

The approach is a convention for pairing otherwise indistinguishable items. When references exist (cheque numbers, UTRs), use them first; sequence keys are for the residue.

Illustration

Bank (account 4521, April), amount ₹15,000:

BankRowID Date Seq
B101 03-Apr 1
B188 10-Apr 2
B240 17-Apr 3
B302 24-Apr 4

Book, amount ₹15,000:

VchNo Date Seq
R-077 03-Apr 1
R-121 10-Apr 2
R-165 17-Apr 3

Join on Amount + Seq: B101–R-077, B188–R-121, B240–R-165 matched; B302 is bank-only (perhaps a weekly collection not yet booked). Without Seq: \(4 \times 3 = 12\) expanded rows and no bank-only item.
