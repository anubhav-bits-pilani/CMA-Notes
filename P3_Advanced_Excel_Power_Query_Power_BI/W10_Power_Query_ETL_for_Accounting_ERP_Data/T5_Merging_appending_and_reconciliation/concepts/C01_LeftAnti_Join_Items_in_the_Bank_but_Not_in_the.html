Key concept

LeftAnti Join: Items in the Bank but Not in the Books

Concept: Table.NestedJoin(Bank, {"Ref","Amount"}, Book, {"Ref","Amount"}, "Book", JoinKind.LeftAnti) returns items in the bank but not in the books

Statement

BankOnly = Table.NestedJoin(Bank, {"Ref", "Amount"}, Book, {"Ref", "Amount"}, "Book", JoinKind.LeftAnti)
  • Arguments: left table Bank, left key columns {"Ref","Amount"}, right table Book, right key columns {"Ref","Amount"} (paired by position in the lists), new nested column name "Book", join kind.
  • JoinKind.LeftAnti returns every row of Bank for which no row of Book has equal values in all key columns.
  • The result has all Bank columns plus a Book column containing an empty table for each row; that column is normally removed.

Explanation

This is the "bank-only" or "debited/credited by bank, not recorded in books" list of a BRS. It is equivalent to SQL's LEFT JOIN ... WHERE book.key IS NULL, done in one step.

Conditions for the result to be meaningful:

  • Keys normalised on both sides: same type (Ref as text, Amount rounded to paise), trimmed, upper-cased, leading zeros handled. If types differ, every bank row is returned and the list is useless — with no error.
  • Signs aligned: bank deposits must be compared with book debits to the bank ledger (see concept c06).
  • Key uniqueness: if a key repeats on the bank side, all repeats are returned or none are; one surplus ₹590 charge among seven is invisible unless sequence numbers are added.
  • Null keys excluded: in M, null equals null, so bank rows with no reference could match book rows with no reference. Filter null references into a separate amount-and-date tier.

Typical contents after correct matching: bank charges and GST on charges, interest credited, TDS on interest, NACH/ECS debits (loan EMIs, insurance), direct customer credits not yet identified, returned cheques, and bank errors. Most require a journal entry in the books; some (bank errors) require a request to the bank.

Remove the empty nested column with Table.RemoveColumns(BankOnly, {"Book"}) and add a Side or Category column before loading.

Practice Questions

Q1. Write and clean the anti-join [L1]

Write M that returns bank-only items using keys RefN and AmtPaise, removes the nested column, and adds a column Side = "In bank, not in books" typed as text.

Q2. Why is the list empty? [L2]

A LeftAnti on Ref + Amount returns zero rows, although the bank statement clearly includes ₹1,770 of charges not in the books. Give three possible causes rooted in key design and how you would test each.

💡 Hint: Think about null references, repeated amounts and the effect of null-equals-null.

Q3. From exceptions to entries [L2]

The bank-only list for May contains: NACH debit ₹62,450 (term-loan EMI: principal ₹48,000, interest ₹14,450), interest credit ₹9,200 with TDS ₹920 deducted shown as a separate line, and a returned cheque ₹1,10,000 (customer cheque deposited and credited earlier). Pass the journal entries required in the books.
