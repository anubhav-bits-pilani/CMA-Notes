Subtopic note

Splitting Ledger Code and Name; Parsing Tally Dr/Cr Amounts

Scope: Splitting "400100 - Sales Domestic" into code and name; parsing Tally amounts with Dr/Cr suffixes

Why it matters

Two of the most common shapes in Indian ERP exports need parsing before anything else works. First, combined ledger labels: SAP, Oracle and many Tally setups (where ledger names are prefixed with codes) give "400100 - Sales Domestic" in one column. Mapping to a Chart of Accounts or Schedule III line needs the code as a join key and the name for display. Second, Tally closing balances are often exported as a single text column such as "1,23,456.00 Dr" or "45,000.00 Cr" rather than separate Debit/Credit columns. Until that text becomes a signed number, you cannot sum, test Dr = Cr or compare with a bank file.

Core notes

Splitting code and name

The UI path is Split Column → By Delimiter, which generates Table.SplitColumn. Key choices:

Choice M When
Delimiter " - " at each occurrence Splitter.SplitTextByDelimiter(" - ") Never for names — "Sales - Exports - SEZ" would split into three
At the left-most delimiter only Splitter.SplitTextByEachDelimiter({" - "}, QuoteStyle.None, false) Code first, name may contain " - "
At the right-most delimiter Splitter.SplitTextByEachDelimiter({" - "}, QuoteStyle.None, true) Name first, code last ("Sales Domestic (400100)")
By positions Splitter.SplitTextByPositions({0, 6}) Fixed-width codes, no delimiter
Digit to non-digit transition Splitter.SplitTextByCharacterTransition({"0".."9"}, (c) => not List.Contains({"0".."9"}, c)) "400100Sales Domestic"

Robust M for the common case (c04):

Split = Table.SplitColumn(t, "Ledger",
          Splitter.SplitTextByEachDelimiter({" - "}), {"Code", "Name"}),
Typed = Table.TransformColumns(Split, {{"Code", Text.Trim, type text}, {"Name", Text.Trim, type text}})

Alternatives without splitting the original column, which keep the source column for audit:

AddCode = Table.AddColumn(t, "Code", each Text.Trim(Text.BeforeDelimiter([Ledger], "-")), type text),
AddName = Table.AddColumn(AddCode, "Name", each Text.Trim(Text.AfterDelimiter([Ledger], "-")), type text)

Text.BeforeDelimiter and Text.AfterDelimiter take an optional index ({0, RelativePosition.FromStart}) to choose which occurrence; the default is the first.

Rows with no delimiter (e.g. "Suspense Account" with no code): Table.SplitColumn puts the whole text into Code and null into Name — the code column now holds a name. Guard:

AddCode = Table.AddColumn(t, "Code", each
            let p = Text.BeforeDelimiter([Ledger], " - ") in
            if Text.Contains([Ledger], " - ") and Text.Select(p, {"0".."9"}) = p then p else null,
            type nullable text)

Then list rows with null Code in an exceptions query — they are unmapped ledgers.

Keep codes as text — "001200" must not become 1200; type the Code column as type text immediately.

Parsing Tally Dr/Cr amounts

Tally's TB "Closing Balance" in single-column mode, and the Ledger report's running balance, use a suffix: "1,23,456.00 Dr", "45,000.00 Cr". Sign convention to adopt in the model: Debit positive, Credit negative (so a TB sums to zero and a P&L sums to the loss / negative profit). Formula (c07):

Signed = Table.AddColumn(t, "Amount", each
           (if Text.EndsWith(Text.Trim([Bal]), "Cr") then -1 else 1)
           * Number.From(Text.Select([Bal], {"0".."9", "."})), type number)

How it works: Text.Select keeps only digits and the decimal point, which removes the Indian grouping commas, spaces, the ₹ sign and the Dr/Cr suffix; Number.From converts; the sign multiplier comes from the suffix.

Hardening:

  • Nulls/blanks: Text.Select(null, ...) errors. Use if [Bal] = null or Text.Trim([Bal]) = "" then null else ....
  • Case and spacing variants: "Cr.", "CR", "cr" — normalise with Text.Upper(Text.Trim(...)) and test Text.EndsWith(x, "CR") or Text.EndsWith(x, "CR.").
  • Negative signs or brackets in some exports ("(45,000.00)" or "-45,000.00"): Text.Select strips them, so the sign is lost. Detect brackets/minus first and multiply.
  • Locale: Number.From with "." as decimal works in all English cultures; for robustness use Number.FromText(x, "en-US") after Text.Select.

Separate Debit/Credit columns

When Tally exports separate Debit and Credit columns (text with Indian grouping), convert each with an explicit culture and compute the signed net:

Typed = Table.TransformColumnTypes(t, {{"Debit", type number}, {"Credit", type number}}, "en-IN"),
Net   = Table.AddColumn(Typed, "Amount", each ([Debit] ?? 0) - ([Credit] ?? 0), type number)

Edge cases & judgement calls

  • Hyphen vs en-dash: copy-pasted ledger names may use "–" (en-dash) or "—". Include them as alternative delimiters or normalise with Text.Replace first.
  • Codes with letters (Oracle segments "01-4001-000-IN") — the code itself contains hyphens. Split by the delimiter with spaces (" - "), or by position if the segment structure is fixed; never on "-" alone.
  • "Dr" inside the number text like "Dr 1,23,456.00" (prefix style) — test Text.StartsWith too.
  • Sign convention mismatch across sources: SAP exports credits as negative already; Tally suffixes; bank files have separate withdrawal/deposit columns. Normalise each source to Dr positive before combining (Topic 5 sign alignment).
  • Paise precision: after parsing, type as Currency.Type or check with a tolerance.

Key takeaways

  • Split code/name at the first (or last) delimiter only, keep the code as text, and flag rows without a code.
  • Text.BeforeDelimiter/Text.AfterDelimiter add columns while preserving the original label for audit.
  • Convert Tally "Dr/Cr" text by stripping to digits and dot, then applying a sign from the suffix.
  • Handle nulls, case/spacing variants, brackets and minus signs before trusting the parse.
  • Adopt one sign convention (Dr positive) for every source before combining; a TB must then net to zero.

Practice Questions

Q1. Split safely [L1]

Write M to split the column Account (values like "610210 - Repairs - Plant & Machinery", "700100 - Interest on Term Loan", "Round Off") into Code and Name, ensuring names with hyphens stay intact and rows without a code get a null Code.

Q2. Parse Dr/Cr variants [L2]

A Tally export's Closing column contains: "1,23,456.00 Dr", "45,000.00 Cr.", " 7,890.50 CR", "", null, "(2,500.00) Dr". Write a custom column that converts all of them to signed amounts (Dr positive), returning null for blanks, and state what you would do with the last value.

💡 Hint: Normalise case and trim first; decide how brackets interact with the suffix and document the rule.

Q3. Oracle segments [L2]

An Oracle TB export has "01-4001-000-IN - Domestic Sales" in one column, where the code has four hyphen-separated segments (Company-Account-CostCentre-Country). Design the M to produce Company, Account, CostCentre, Country and Name columns, all as text.

Q4. TB integrity after parsing [L2]

After parsing, the signed amounts of a 1,450-ledger TB sum to ₹2,46,91,000 instead of zero. List four parsing errors that could cause this and, for each, a Power Query check that would reveal it.

Q5. Interview: why text codes? [L1]

Explain in under 120 words why account codes and cost-centre codes should be typed as text, with one example of a failure when typed as whole numbers.
