Subtopic note

Export Layouts: Tally Day Book/Ledger/TB, SAP FBL3N, SALR, Oracle TB

Scope: Source layouts: Tally Day Book / Ledger Vouchers / TB, SAP FBL3N and S_ALR_87012277, Oracle TB exports

Why it matters

Cleaning logic is source-specific. Before writing a single step you need to know where the header row sits, what a data row looks like, which rows are subtotals, how signs are expressed and which fields act as keys. Indian finance teams routinely work across Tally (SMEs, branches, subsidiaries), SAP (large groups and MNC subsidiaries) and Oracle EBS/Fusion (some large corporates and shared-service centres). A consolidation or audit analytics pipeline typically receives at least two of these. Recognising each layout lets you write one staging query or cleaning function per layout and conform them all to a common schema: Date, Entity, Account Code, Account Name, Cost Centre, Debit, Credit, Amount (Dr positive), Document/Voucher No., Narration.

Core notes

Tally Prime: Trial Balance

  • Export: Display → Trial Balance → Export (Alt+E) → Excel (xlsx) or CSV; options include "Show Opening Balance", "Show Transactions (Dr/Cr)", "Detailed" vs "Condensed", and whether to include zero balances.
  • Header: company name, address lines, "Trial Balance", period line ("1-Apr-25 to 31-Mar-26"), then a two-line caption: "Particulars" | "Closing Balance" over "Debit" | "Credit" (plus Opening/Transactions pairs if selected).
  • Rows: in Condensed mode only primary groups appear (Capital Account, Current Liabilities, …); in Detailed mode groups are followed by indented sub-groups/ledgers. Groups carry totals on their own line, so detailed exports double count unless you keep ledgers only (use the ledger master or indentation — s03).
  • Footer: "Grand Total" row; possibly "Difference in opening balances".
  • Signs: separate Debit and Credit columns (text with Indian grouping), or a single balance with Dr/Cr suffix in some report configurations.
  • Key: ledger name (Tally has no mandatory ledger code — codes, if used, are embedded in names or aliases).

Tally Prime: Day Book

  • Content: every voucher for a date range. Columns: Date, Particulars (first/party ledger in condensed mode), Vch Type, Vch No., Debit Amount, Credit Amount (and Inwards/Outwards quantities for inventory vouchers).
  • Detailed mode shows each ledger line of a voucher on its own row: the first row has Date/Vch Type/Vch No., following rows have only Particulars and amounts — those blanks must be filled down (s03) to make each line self-describing. Narrations appear on a separate line under the voucher if enabled.
  • Use: journal analytics, cut-off testing, duplicate-voucher tests, GST reconciliations.

Tally Prime: Ledger Vouchers

  • Content: one ledger's transactions. Columns: Date, Particulars (contra ledger, prefixed "To"/"By" in older styles), Vch Type, Vch No., Debit, Credit; optional running balance with Dr/Cr suffix.
  • Special rows: "Opening Balance" at the top, "Current Total" and "Closing Balance" at the bottom — exclude by condition but capture as control totals.
  • Use: bank book for BRS (exported for the bank ledger), party ledgers for confirmations.

SAP: FBL3N (G/L Account Line Items)

  • Export: List → Export → Spreadsheet (xlsx) or Local File (unconverted/text, tab-delimited). Output depends on the user's layout variant — different users produce different columns, a classic schema-drift issue; agree a standard layout (e.g. /FINRECON).
  • Typical columns: Company Code, G/L Account, Assignment, Document Number, Document Type, Posting Date, Document Date, Posting Key, Amount in Local Currency, Local Currency, Tax Code, Text, Cost Center, Profit Center, Clearing Document, Clearing Date, User Name.
  • Signs: credits are negative in local-currency amount (posting keys 50 etc.), so Amount is already Dr positive.
  • Special rows in spreadsheet export from the ALV list: subtotals and totals marked with */** when totals are active; in text exports, page headers repeat.
  • Key: Company Code + Document Number + Fiscal Year + Line Item uniquely identifies a line.
  • Amount format depends on the user's decimal notation setting (1,234,567.89 vs 1.234.567,89 vs Indian grouping) — fix per user profile or parse with care (s06).

SAP: S_ALR_87012277 (G/L Account Balances)

  • Content: per company code and account — balance carryforward, debit and credit for the reporting periods, period balance and accumulated balance. Selection screen sets fiscal year, reporting periods and output type.
  • Layout: classic list output with report header (title, company code, fiscal year, periods), column captions, one line per account per currency/business area, then subtotals by company code and totals marked with asterisks. Exported to spreadsheet or text, headers repeat per page in text form.
  • Use: TB source for consolidation; reconciles to FBL3N detail by account.
  • Note: accumulated balance already includes carryforward — do not add carryforward and accumulated balance together.

Oracle EBS / Fusion: Trial Balance

  • Reports: EBS "Trial Balance - Detail" / "Trial Balance - Summary 1" (often BI Publisher output to Excel); Fusion "Trial Balance Report" or Financial Reporting Studio/Smart View extracts.
  • Account: a code combination of segments, e.g. 01-110-4001-000-IN (Company-CostCentre-Account-SubAccount-Country); segment structure is defined per ledger's chart of accounts. Split by segment delimiter with care (s04).
  • Columns: Account, Description, Beginning Balance, Period Debits, Period Credits, Ending Balance; amounts usually signed (credit balances negative) in ending balance, but debits/credits are both positive.
  • Header/footers: report parameters (ledger, period, currency, amount type PTD/YTD), page headers in Excel outputs, totals per balancing segment.

Edge cases & judgement calls

  • Tally export settings drift: one branch exports with Opening Balance columns, another without — select columns by name and tolerate missing ones (MissingField.UseNull).
  • Tally multi-currency ledgers show forex amounts in extra columns; decide whether to use base currency only.
  • SAP layout variants are user-specific; require a fixed variant name in the close calendar.
  • Period 13–16 (SAP special periods) for audit adjustments: include them for year-end TB.
  • Oracle PTD vs YTD amount type determines whether balances are period or cumulative — read the parameter line and capture it as a column.
  • CSV vs Excel exports of the same report differ in how numbers arrive (text vs typed) — standardise one format per source.

Key takeaways

  • Learn each source's header, data-row signature, subtotal markers, sign convention and key before writing steps.
  • Tally detailed reports need ledger-only selection or fill-down; Ledger Vouchers carry opening/closing control rows.
  • SAP FBL3N is signed line-item data whose columns depend on the layout variant; S_ALR_87012277 is balance data with carryforward and accumulated columns.
  • Oracle TBs use segment code combinations and PTD/YTD parameters that must be captured.
  • Conform every source to one common schema with Dr-positive amounts before appending.

Practice Questions

Q1. Identify the layout [L1]

For each description, name the likely report and the first two cleaning steps: (a) columns Date, Particulars, Vch Type, Vch No., Debit Amount, Credit Amount, where most rows have blank Date; (b) a file whose amounts are negative for credits and which has a Clearing Document column; (c) a file with "Balance Carryforward", "Debit Rep. Period", "Credit Rep. Period" and "Accumulated Balance"; (d) accounts like "01-210-5101-000".

Q2. Detailed TB double counting [L2]

A Tally TB exported in Detailed mode for a Pune branch sums to ₹18.4 crore on the debit side while the Grand Total shows ₹7.9 crore. Explain why and describe two ways to keep only ledger rows in Power Query.

💡 Hint: Think about which rows are groups and how they can be recognised.

Q3. Common schema design [L2]

Design the common output schema (column names and types) for consolidating a Tally TB (two branches), an SAP S_ALR_87012277 extract (one subsidiary) and an Oracle TB (one subsidiary), and for each source list the transformations needed to conform.

Q4. FBL3N schema drift [L2]

Three users export FBL3N for the same accounts with different layout variants: one lacks Cost Center, one has "Amount in LC" instead of "Amount in Local Currency", one includes 6 extra columns. Describe how your cleaning query should handle this and what process control you would recommend.

Q5. Day Book for cut-off testing [L3]

As part of a year-end audit you receive the Tally Day Book for 25 March to 10 April 2026 in detailed mode. Design the Power Query transformation that produces one row per voucher line with Date, Voucher Type, Voucher No., Ledger, Dr/Cr amount and Narration, and list the cut-off analyses you would then run.
