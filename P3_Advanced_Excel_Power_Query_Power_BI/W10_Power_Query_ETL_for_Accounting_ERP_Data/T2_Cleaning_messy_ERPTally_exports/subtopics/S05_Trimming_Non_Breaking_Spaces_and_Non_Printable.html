Trimming Non-Breaking Spaces and Non-Printable Characters

Scope: Trimming and cleaning non-breaking spaces (char 160) and non-printable characters

Why it matters

Invisible characters are the commonest reason a merge "should match but doesn't". A ledger name copied from a web portal, a vendor name in a GSTR-2B download, or a narration in a bank CSV frequently contains a non-breaking space (Unicode U+00A0, character code 160) instead of a normal space (code 32), a trailing tab, a carriage return from a multi-line cell, or a zero-width character from a PDF conversion. "ABC Traders" and "ABC Traders" with a char-160 look identical on screen, and Power Query's merge is exact, so the bank-to-book match fails, the CoA mapping shows a gap, and Group By shows the same ledger twice. Cleaning text before keys are built is mandatory hygiene.

Core notes

What the built-in functions do

Function Removes Does not remove
Text.Trim(text) Leading and trailing whitespace (spaces, tabs, line breaks and other Unicode whitespace characters at the ends) Whitespace inside the text (double spaces stay)
Text.TrimStart / Text.TrimEnd Leading only / trailing only; optional list of characters to trim —
Text.Clean(text) Control (non-printable) characters, e.g. codes 0–31 such as line feed, carriage return, tab Non-breaking space (160) — it is printable whitespace
Text.Replace(text, old, new) Exact substring replacement —
Text.Remove(text, chars) / Text.Select(text, chars) Remove or keep a list of characters —
Character.FromNumber(n) Builds a character from its code, e.g. Character.FromNumber(160) —

Behaviour differs from Excel: Excel's TRIM removes only code-32 spaces but also collapses internal runs of spaces; Power Query's Text.Trim removes a broader set of whitespace at the ends but does not collapse internal spaces. Test rather than assume, especially with char 160 at the ends — explicitly replacing it first (c05) guarantees the result.

The standard cleaning expression

Convert non-breaking spaces to normal spaces, strip control characters, trim the ends:

Clean = Table.TransformColumns(t, {
          {"Name", each Text.Trim(Text.Clean(Text.Replace(_, Character.FromNumber(160), " "))), type text},
          {"Narration", each Text.Trim(Text.Clean(Text.Replace(_, Character.FromNumber(160), " "))), type text}})

Order: replace 160 first (so that it becomes trimmable or collapsible), then Text.Clean, then Text.Trim. Apply to every column used as a key or grouping attribute.

Collapsing internal double spaces

"ABC Traders" (two spaces) does not equal "ABC Traders". Two approaches:

// split on spaces, drop empties, re-join
Collapse = (x as nullable text) as nullable text =>
             if x = null then null
             else Text.Combine(List.Select(Text.Split(x, " "), each _ <> ""), " ")

or apply Text.Replace(x, " ", " ") repeatedly inside List.Accumulate. The split/select/combine version handles any number of spaces in one pass.

A reusable cleaning function

Put the rule in one function query and use it everywhere:

fxCleanText = (x as nullable text) as nullable text =>
    if x = null then null else
    let
        nbsp   = Text.Replace(x, Character.FromNumber(160), " "),
        zw     = Text.Remove(nbsp, {Character.FromNumber(8203), Character.FromNumber(65279)}),
        ctrl   = Text.Clean(zw),
        parts  = List.Select(Text.Split(ctrl, " "), each _ <> ""),
        joined = Text.Combine(parts, " ")
    in
        joined

Code 8203 is the zero-width space and 65279 the byte-order mark (BOM), which appears at the start of the first header in UTF-8 files saved by some tools — it makes the first column header an invisible BOM followed by "Date" rather than plain "Date", breaking Table.SelectColumns.

Apply to many columns with a dynamic list:

TextCols = Table.ColumnsOfType(t, {type text, type nullable text}),
Cleaned  = Table.TransformColumns(t, List.Transform(TextCols, each {_, fxCleanText, type nullable text}))

Table.ColumnsOfType only works if columns are already typed as text; on untyped (any) columns list the names explicitly or use Table.ColumnNames with exclusions.

Detecting invisible characters

  • Length test: add a column Text.Length([Name]) and compare with the visible length; a difference flags hidden characters.
  • Character codes: List.Transform(Text.ToList([Name]), Character.ToNumber) shows each code — look for 160, 9, 10, 13, 8203.
  • Column profile: distinct counts higher than expected ("ABC Traders" appearing twice in Group By).
  • Merge diagnostics: an anti-join listing keys that look identical in both tables.

Case normalisation

Merges are case-sensitive by default. For keys, apply Text.Upper after cleaning (GSTIN and PAN are uppercase by definition; vendor names may vary). Keep a display version in proper case if needed, and join on the normalised key.

Illustration

Bank narration from an SBI CSV: "NEFT/AXISP00123456/ RAMESH TRADERS " with a char-160 before RAMESH and a CR/LF at the end. Book ledger: "Ramesh Traders". After fxCleanText and Text.Upper on both sides and extracting the party from the narration, both keys read "RAMESH TRADERS" with length 14. Before cleaning, the bank key had length 17 and the merge found no match.

Edge cases & judgement calls

  • Text.Clean removes line breaks inside narrations, joining words ("PAYMENTRECEIVED"). Replace line breaks with a space first if words span lines: Text.Replace(x, "#(lf)", " "), likewise "#(cr)".
  • Do not clean numeric columns as text after typing; clean before conversion — a char 160 in "1,23,456.00" makes number conversion fail with DataFormat.Error, so cleaning is also a typing prerequisite.
  • GSTIN/PAN should also have internal spaces removed entirely (Text.Remove(x, " ")), not just collapsed.
  • Trimming specific characters: Text.Trim(x, {"*", " "}) removes SAP's asterisk markers at the ends.
  • Over-cleaning narrations can destroy information (e.g. the "/" separators used to parse UTRs); clean keys aggressively, narrations lightly.
  • Performance: row-wise text functions never fold; on SQL sources, do this after filtering, or in SQL (LTRIM(RTRIM(REPLACE(x, CHAR(160), ' ')))).

Key takeaways

  • Non-breaking space (160) is not removed by Text.Clean and may not be handled the way you expect by trimming; replace it explicitly first.
  • Standard order: replace 160 → remove zero-width/BOM → Text.Clean → collapse internal spaces → trim.
  • Wrap the rule in a reusable function and apply it to every key column with a dynamic list.
  • Detect hidden characters with length tests and character-code lists before blaming the merge.
  • Clean text before number conversion and before building merge keys; upper-case keys for matching.

Practice Questions

Q1. Explain the failure [L1]

A merge of the CoA mapping on Ledger Name returns 1,180 matches out of 1,212 ledgers. The 32 unmatched names look identical in both tables. List the hidden-character causes you would test for and the M expression you would use to reveal each.

Q2. Write the cleaner [L2]

Write a function fxKey that turns any vendor-name text into a matching key: replaces char 160, removes zero-width spaces and BOM, removes control characters (converting line breaks to spaces first), collapses internal spaces, trims, upper-cases and removes the suffixes " PVT LTD", " PRIVATE LIMITED" and " LTD".

💡 Hint: Process the suffix list with List.Accumulate or a nested replace after upper-casing.

Q3. Header with BOM [L2]

Table.SelectColumns(Promoted, {"Date","Narration","Amount"}) fails with "The column 'Date' of the table wasn't found" although the preview shows a Date column. Explain the likely cause in a UTF-8 bank file and two ways to fix it.

Q4. Number conversion failure [L1]

Table.TransformColumnTypes(t, {{"Amount", type number}}, "en-IN") produces DataFormat.Error on 214 of 9,800 rows whose values look like "1,23,456.00". Describe how you would diagnose and fix the issue.

Q5. Excel vs Power Query trim [L2]

Compare Excel TRIM/CLEAN with Power Query Text.Trim/Text.Clean on: internal double spaces, char 160 at the ends, char 160 in the middle, line feeds, and tabs. Then describe a small test table you would build to confirm the behaviour in your version.
