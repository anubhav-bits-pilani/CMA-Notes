Filling Down Cost-Centre and Group Headers in Report Layouts

Scope: Filling down cost-centre or group headers in report-style layouts, then removing header-only rows

Why it matters

Report layouts carry context in header rows rather than in columns. A Tally Cost Centre Breakup prints "Mumbai HO" once, then the ledgers below it; a Group Summary prints "Indirect Expenses" above its ledgers; an SAP hierarchy report prints the profit centre on a line of its own. A fact table needs that context on every row (Ledger, CostCentre, Amount), otherwise you cannot slice by cost centre or map groups to Schedule III line items. The pattern is: move the header text into its own column, fill it down over the detail rows, then delete the now-redundant header-only rows.

Core notes

The three-step pattern

  1. Isolate the header value into a new column — only on header rows; null elsewhere.
  2. Fill Down that column (Table.FillDown) so each detail row inherits the last header above it.
  3. Remove header-only rows — rows that were headers carry no amounts.
let
    // after skipping report header and promoting
    Flagged  = Table.AddColumn(Promoted, "CostCentre", each
                  if [Debit] = null and [Credit] = null and [Particulars] <> null
                  then Text.Trim([Particulars]) else null, type nullable text),
    Filled   = Table.FillDown(Flagged, {"CostCentre"}),
    Details  = Table.SelectRows(Filled, each [Debit] <> null or [Credit] <> null),
    Cleaned  = Table.SelectRows(Details, each not Text.StartsWith(Text.Trim([Particulars]), "Total"))
in
    Cleaned

How to identify a header row

Signal Example Test
No amounts on the row "Mumbai HO" with Debit/Credit null [Debit] = null and [Credit] = null
Header in a different column Cost centre in Column1, ledgers in Column2 [Column1] <> null and [Column2] = null
Prefix or pattern "CC: 1010 – Mumbai HO", "Profit Center 2000" Text.StartsWith([Particulars], "CC:")
Membership of a master list Cost-centre master or group master List.Contains(CCMaster[Name], [Particulars])
Indentation / formatting Groups in bold, ledgers indented with spaces Count leading spaces before trimming: Text.Length(x) - Text.Length(Text.TrimStart(x))

The master-list test is the most reliable for Tally: Tally's cost-centre and group names are master data, so match against an exported list. The leading-space test works for exports where Tally indents ledgers under groups — capture the indent before any trimming step.

Table.FillDown semantics

Table.FillDown(table, columns) replaces each null in the listed columns with the most recent non-null value above it, in the table's current row order. Two consequences:

  • Empty strings "" are not null, so they are not filled and they stop the fill (an empty string becomes the "last value"). Excel exports frequently contain "" in apparently blank cells — replace "" with null first (c03).
  • Order matters: the fill uses the physical row order at that step. Any sort, merge, or filter that reorders rows before the fill associates detail rows with the wrong header. Fill first, sort later.

Table.FillUp exists for layouts where the label appears below the detail (e.g. a subtotal line that names the group — "Total Indirect Expenses" — and nothing above).

Multi-level headers

A Cost Category → Cost Centre → Ledger layout needs two columns filled, and the lower level must reset when a new upper-level header appears; otherwise the first cost centre of a new category inherits the last cost centre of the previous one. Technique: flag both levels, fill the upper level, then fill the lower level within each upper-level group:

Lvl1   = Table.FillDown(Flagged, {"Category"}),
Grp    = Table.Group(Lvl1, {"Category"}, {{"Rows", each Table.FillDown(_, {"CostCentre"}), type table}},
                     GroupKind.Local),
Expand = Table.Combine(Grp[Rows])

GroupKind.Local groups consecutive rows only, preserving file order — important when the same category name appears in separate blocks.

Illustration

Tally Cost Centre Breakup for "Travelling Expenses":

Particulars Debit Credit
Mumbai HO
Air Fare 3,45,000.00
Hotel 1,20,500.00
Total 4,65,500.00
Pune Plant
Air Fare 85,000.00
Local Conveyance 22,400.00
Total 1,07,400.00

After the pattern: four rows — (Air Fare, Mumbai HO, 3,45,000), (Hotel, Mumbai HO, 1,20,500), (Air Fare, Pune Plant, 85,000), (Local Conveyance, Pune Plant, 22,400). Sum ₹5,72,900 equals the two totals combined. Note the "Total" rows have amounts, so they are not mistaken for headers; they must be removed by a separate condition — and they must not be flagged as headers, or the next block's detail rows would inherit "Total".

Edge cases & judgement calls

  • Header row that also has an amount (some reports print the group total on the header line). Then "no amount" is not a valid signal — use the master list or indentation.
  • Detail rows with both amounts null (zero-balance ledgers) are misread as headers. Use a master-list test or a structural column (ledger code present) instead of amounts alone.
  • First rows before any header get null after fill; decide whether that is "Unallocated" (replace null) or an error.
  • Fill Down on a column that has genuine nulls (e.g. optional narration) wrongly propagates values; fill only the header column you created.
  • Removing header rows before the fill loses the header text — the sequence is flag → fill → remove.
  • Performance: Fill Down never folds; on file sources this is irrelevant, but do not place it early in a database query.

Key takeaways

  • Move header text into its own column on header rows only, then Table.FillDown, then remove header-only rows.
  • Fill Down fills nulls only and follows current row order — replace blanks with null first and never sort before filling.
  • Identify headers by master-list membership or indentation where amounts are unreliable.
  • For nested hierarchies, fill the upper level first and reset the lower level within each block (GroupKind.Local).
  • Reconcile the filled detail back to the report totals.

Practice Questions

Q1. Write the pattern [L1]

An SAP profit-centre report has rows like "Profit Center 1000 Mumbai" (no amounts) followed by GL account rows with an Amount column. Write the M to produce GL, ProfitCenter, Amount rows, with the profit centre code (1000) as a separate column.

Q2. Wrong header assignment [L2]

After a Fill Down, the expenses of "Delhi Branch" appear under "Bengaluru Branch" in the output. The steps were: Promoted → Sorted Rows (by Particulars) → Added CostCentre column → Filled Down → Filtered. Explain the error and fix the step order.

💡 Hint: Fill Down depends on the physical order of rows at that step.

Q3. Two-level hierarchy [L2]

A Tally report has Cost Category rows (e.g. "Branches"), Cost Centre rows (e.g. "Kolkata") and ledger rows; header rows have no amounts, and the category rows are in uppercase. Write M that fills both levels correctly so that the first cost centre of each new category does not inherit the previous category's last cost centre.

Q4. Zero-balance ledgers [L2]

In a TB-by-group export, three ledgers have zero balances (both Debit and Credit blank). Your header test "both amounts null" treats them as group headers, and the following ledgers are assigned to the wrong group. Propose two alternative header tests and the data you would need for each.

Q5. Reconciliation of filled output [L3]

Design a check query that proves the filled-down cost-centre detail is complete: per cost centre, compare the sum of detail rows with the report's "Total" line for that block, and list any mismatches. Describe how you will associate each "Total" line with its cost centre.
