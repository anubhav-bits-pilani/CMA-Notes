Skipping Report Headers Conditionally and Promoting Headers

Scope: Skipping report headers (company name, period, captions) with conditional Table.Skip, then promoting headers

Why it matters

Almost no ERP export is a clean table. A Tally Prime Trial Balance exported to Excel starts with the company name, address lines, "Trial Balance", the period "1-Apr-2025 to 31-Mar-2026", then a two-line caption ("Particulars | Closing Balance" over "Debit | Credit"). An HDFC statement CSV has 15–20 lines of account details before the column header. SAP S_ALR_87012277 prints a report title, selection criteria and page headers. The number of these lines changes — a longer address, a different period text, an extra filter line — so "Remove Top Rows: 6" works this month and silently eats a ledger next month. Conditional skipping finds the header row by its content, which is stable, rather than its position, which is not.

Core notes

Positional vs conditional skip

Table.Skip(table, countOrCondition) removes rows from the top. The second argument can be:

  • a number — Table.Skip(Source, 6) drops exactly six rows (what "Remove Top Rows" generates);
  • a condition function — Table.Skip(Source, each [Column1] <> "Particulars") drops rows while the condition is true and stops at the first row where it is false. That first false row (the header) is kept.

The condition version is the refresh-safe one: however many lines precede the header, skipping stops exactly at it. Table.FirstN and Table.RemoveFirstN take the same two forms.

Promoting headers

After the skip, the header row is the first row. Table.PromoteHeaders(table, [PromoteAllScalars=true]) turns it into column names. PromoteAllScalars=true promotes numbers and dates as text names too (otherwise a header cell like 2026 or a date-formatted month would stay Column5). Then:

  • Rename ambiguous names (Tally often gives Column2/Column3 under a merged "Closing Balance" caption, or duplicates like Debit and Debit_1).
  • Remove the auto Changed Type step if auto-detection is still on (Topic 1 s04).

Choosing a reliable marker

Pick a cell that appears only in the header row and always appears:

Source Marker Condition
Tally TB (Excel) "Particulars" in first column each [Column1] <> "Particulars"
HDFC CSV "Date" in first column and "Narration" in second each not ([Column1] = "Date" and [Column2] = "Narration")
ICICI CSV header starts with "S No." each [Column1] <> "S No."
SAP FBL3N (spreadsheet export) "Document Number" or "DocumentNo" each not List.Contains(Record.FieldValues(_), "Document Number")

Making the marker robust to case and stray spaces:

Skipped = Table.Skip(Source, each Text.Trim(Text.Upper(Text.From([Column1] ?? ""))) <> "PARTICULARS")

Text.From(... ?? "") handles nulls in blank lines (comparing null to text is fine, but Text.Trim(null) returns null and Text.Upper of null returns null, so the coalesce keeps the logic simple). The "search any column" form, using Record.FieldValues(_), is useful when the header might start in column B.

Two-line headers

Tally's TB with "Closing Balance" over "Debit | Credit" has the useful names on the second header line. Options: skip to the first header line, then Table.Skip(_, 1) to drop it and promote the second; or combine both lines (Table.Transpose, merge, transpose back — the same technique as multi-row budget headers in Topic 3). Simplest robust pattern for a known layout: skip to the second line by its marker (e.g. each [Column2] <> "Debit"), promote, then rename Column1 to Particulars.

Capturing header metadata before skipping

The skipped lines often hold information you need — the period ("1-Apr-2025 to 31-Mar-2026"), bank account number, branch name. Capture it in a separate step before skipping, then add it as a column:

let
    Source   = Excel.Workbook(File.Contents(pPath), null, true){[Item="TB",Kind="Sheet"]}[Data],
    PeriodTx = List.First(List.Select(Source[Column1], each _ <> null and Text.Contains(Text.From(_), " to "))),
    Skipped  = Table.Skip(Source, each [Column1] <> "Particulars"),
    Promoted = Table.PromoteHeaders(Skipped, [PromoteAllScalars=true]),
    WithPer  = Table.AddColumn(Promoted, "PeriodText", each PeriodTx, type text)
in
    WithPer

Illustration

Row Column1 Column2 Column3
1 Sharma Auto Components Pvt Ltd
2 Plot 14, MIDC Bhosari, Pune
3 Trial Balance
4 1-Apr-2025 to 31-Mar-2026
5 Particulars Debit Credit
6 Capital Account 2,50,00,000.00

Table.Skip(Source, each [Column1] <> "Particulars") drops rows 1–4 and keeps row 5 onward; promotion gives columns Particulars, Debit, Credit. If next month's export has a second address line, rows 1–5 are dropped and the result is identical. "Remove Top Rows: 4" would have left the address line as the header.

Edge cases & judgement calls

  • Marker never found: if the condition is never false, Table.Skip removes every row and returns an empty table — no error. Add a guard: if Table.IsEmpty(Skipped) then error "Header 'Particulars' not found in " & pFileName else Skipped. Silent empty outputs are worse than failures.
  • Marker appears in data: a ledger named "Particulars Suspense" does not match an exact equality test, but Text.Contains would; prefer exact matches.
  • Repeated page headers further down (SAP list output, PDF-to-Excel conversions) are not handled by Table.Skip, which only acts at the top; remove them with a row filter (s02).
  • Header cells with line breaks ("Closing#(lf)Balance") — clean with Text.Clean before matching or renaming.
  • CSV vs Excel: in CSV everything is text; in Excel the period line may be a real date — Text.From it before testing.
  • Promote before cleaning (the UI default) makes the company name the header; always skip first.

Key takeaways

  • Use Table.Skip with a condition so header skipping depends on content, not row count.
  • Choose a marker unique to the header row; normalise case, spaces and nulls before comparing.
  • Promote with PromoteAllScalars=true, then rename ambiguous columns explicitly.
  • Capture period, account or branch text from the report header before skipping it.
  • Guard against an empty result when the marker is missing — fail loudly.

Practice Questions

Q1. Write the skip [L1]

An ICICI statement CSV has 12 to 16 lines of account details before a header row whose first cell is "S No." and second cell is "Value Date". Write the M steps to skip to the header and promote it, robust to leading/trailing spaces in the marker cell.

Q2. Capture the account number [L2]

The same file has a line Account Number : 000405012345 somewhere in the top 16 lines. Extend your query to capture the account number (as text, keeping leading zeros) and add it as a column on every transaction row.

💡 Hint: Select from the first column's list before skipping, then extract the text after the colon.

Q3. Two-line Tally caption [L2]

A Tally TB export has row 7: "Particulars | Closing Balance | (blank)" and row 8: "(blank) | Debit | Credit". Write two alternative M approaches to end up with headers Particulars, Debit, Credit, and say which is more robust if Tally adds an "Opening Balance" pair of columns.

Q4. Silent failure [L2]

A refresh produced an empty consolidated TB for the Nagpur branch without any error. Explain how a conditional Table.Skip could cause this, and write the guard you would add so that the refresh fails with a meaningful message naming the file.

Q5. Review the generated steps [L1]

The UI generated: Promoted Headers → Changed Type → Removed Top Rows (4) → Promoted Headers1 → Changed Type1. List the problems and rewrite as a two-step refresh-safe sequence.
