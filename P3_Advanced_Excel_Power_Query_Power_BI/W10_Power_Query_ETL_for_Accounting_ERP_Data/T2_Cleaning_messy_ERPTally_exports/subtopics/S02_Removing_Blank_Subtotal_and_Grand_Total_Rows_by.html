Subtopic note

Removing Blank, Subtotal and Grand Total Rows by Condition

Scope: Removing blank, subtotal, "Grand Total" and page-break rows by condition, not by position

Why it matters

Report-style exports interleave data rows with presentation rows: blank spacer lines, group subtotals ("Total Indirect Expenses"), a "Grand Total" at the end, and in paginated outputs a repeated header and "Page 3 of 17" lines every 50 rows. If these survive into a consolidated TB, every group is counted twice and the Dr = Cr check fails by exactly the grand total. If they are removed by position ("Remove Bottom Rows: 2"), next month's file with one extra footer line either keeps a total or deletes the last real ledger. Condition-based removal identifies presentation rows by what they are, so it works whatever their number or position.

Core notes

The filter function

Table.SelectRows(table, condition) keeps rows where the condition returns true. Removing rows means writing the condition for rows you keep:

Kept = Table.SelectRows(Promoted, each
          [Particulars] <> null
          and Text.Trim([Particulars]) <> ""
          and not Text.StartsWith(Text.Trim([Particulars]), "Total")
          and Text.Trim([Particulars]) <> "Grand Total")

Order of tests matters: the null test comes first so that text functions are never called on null (and short-circuits in M — if the left side is false, the right side is not evaluated).

Categories of presentation rows and their tests

Row type Typical appearance Test to identify
Blank All cells null or "" List.NonNullCount(List.RemoveItems(Record.FieldValues(_), {""})) = 0
Blank in key column only Particulars null, amounts null [Particulars] = null and [Debit] = null and [Credit] = null
Group subtotal "Total Current Liabilities", "Sub Total" Text.StartsWith(..., "Total"), Text.Contains(..., "Sub Total")
Grand total "Grand Total", "Total" alone, "Closing Balance" in Day Book exact match list
Page break / repeated header "Particulars" again, "Page 4 of 12", "Continued..." List.Contains({"Particulars","Continued..."}, [Particulars]), Text.StartsWith([Particulars], "Page ")
Carried forward lines "B/F", "C/F", "Opening Balance" exact match list

A convenient pattern keeps the rule list in one place:

DropExact   = {"Grand Total", "Total", "Particulars", "Continued...", "C/F", "B/F"},
DropPrefix  = {"Total ", "Sub Total", "Page "},
IsJunk      = (t as nullable text) as logical =>
                  let x = Text.Trim(t ?? "") in
                  x = "" or List.Contains(DropExact, x)
                  or List.AnyTrue(List.Transform(DropPrefix, each Text.StartsWith(x, _))),
Kept        = Table.SelectRows(Promoted, each not IsJunk([Particulars]))

Note the explicit lambda in IsJunk and the inner each — inside List.Transform, _ is the prefix, while x is the cleaned ledger text.

Structural tests are stronger than text tests

Text tests fail when a real ledger begins with "Total" (e.g. "Total Gas Pvt Ltd — Creditor" or "Totalisator Rentals"). Structural tests use properties of data rows:

  • A data row in a Tally Ledger Vouchers report always has a voucher number or voucher type; subtotal lines do not: keep each [Vch No.] <> null.
  • In SAP FBL3N, data rows have a document number; subtotal rows (marked with * or **) have none.
  • In a Tally TB, group rows (when exported "in detailed" mode) can be recognised by indentation or by matching against the group master; ledgers are what you keep.
  • A grand total equals the sum of the other rows — use it as a control total before removing it (Week 10 cross-cutting item).

Combine both: structure first, text as a backstop.

Using totals as controls before removing them

GrandRow   = Table.SelectRows(Promoted, each Text.Trim([Particulars] ?? "") = "Grand Total"),
ReportDr   = Number.From(GrandRow{0}?[Debit]?),
CleanDr    = List.Sum(Kept[Debit]),
DrCheck    = Number.Abs((ReportDr ?? 0) - (CleanDr ?? 0)) < 1

If DrCheck is false, you removed a real row or kept a subtotal. Expose this in a control-totals query rather than burying it.

Why not Remove Bottom Rows

"Remove Bottom Rows (3)" generates Table.RemoveLastN(t, 3). It assumes a fixed footer. Tally adds a line when there is a difference in opening balances; SAP adds a page footer depending on row count; bank statements add a "Statement Summary" block whose length varies with the number of cheque returns. A positional step has no way to know. If you must use the UI, use Remove Rows → Remove Bottom Rows only on sources with a contractually fixed layout, and still verify with a control total. Table.RemoveLastN also accepts a condition (removes from the bottom while true) — a safer variant when the footer block is contiguous.

Illustration

Tally Group Summary export (12 lines): Capital Account (group header, no amount), Share Capital 5,00,00,000 Cr, Reserves 1,20,00,000 Cr, "Total Capital Account" 6,20,00,000 Cr, blank, Current Liabilities (header), Sundry Creditors 84,50,000 Cr, Duties & Taxes 6,20,000 Cr, "Total Current Liabilities" 90,70,000 Cr, blank, "Grand Total" 7,10,70,000 Cr. Without cleaning, the Cr sum is 21,32,10,000 — three times the true total. After the condition filter (and dropping header-only rows with no amount, s03), four ledgers remain summing to 7,10,70,000, which equals the grand total captured before removal.

Edge cases & judgement calls

  • Real ledgers starting with "Total" — use structural tests or exact matches; review the list of removed rows (load a "removed rows" exceptions query with the inverse filter).
  • Negative/zero rows: a ledger with zero balance is still a data row; do not remove rows just because amounts are null if the ledger name is valid (it may matter for mapping completeness).
  • Grand total missing in some exports (e.g. filtered reports) — make the control-total step tolerant ({0}? optional item access).
  • Language/format variants: "Grand Total" vs "GRAND TOTAL" vs "Total :" — normalise case and trailing punctuation.
  • Page-break rows in CSVs produced from print layouts often carry the report title again; include the title in the drop list.
  • Filters and Fill Down: if you need group headers for Fill Down (s03), do the fill before removing header rows but after removing blanks and totals only if the total lines would otherwise be filled with a header — sequence deliberately.

Key takeaways

  • Remove presentation rows with Table.SelectRows conditions, never with fixed row counts.
  • Test nulls first; and short-circuits, which keeps text functions safe.
  • Prefer structural tests (voucher number present, document number present) over text prefixes.
  • Capture report totals as control totals before removing them, and reconcile the cleaned sum to them.
  • Keep the drop-lists in one step so rules are reviewable and easy to extend.

Practice Questions

Q1. Write the filter [L1]

A Tally Ledger Vouchers export has columns Date, Particulars, Vch Type, Vch No., Debit, Credit. Rows to remove: blank lines, "Opening Balance", "Current Total", "Closing Balance" and repeated header lines where Date = "Date". Write a single Table.SelectRows step that keeps only voucher lines, using a structural test where possible.

Q2. False positive [L2]

After filtering out rows starting with "Total", the cleaned TB of a Chennai branch is ₹14,62,300 lower on the credit side than Tally's grand total. Explain the most likely cause, how you would find the affected row(s) in Power Query, and the corrected rule.

💡 Hint: Build the inverse filter and inspect what was removed.

Q3. Control-total step [L2]

Write M that captures the "Grand Total" row's Debit and Credit before removal, sums the cleaned Debit and Credit columns, and returns a one-row table with ReportDr, ReportCr, CleanDr, CleanCr, DiffDr, DiffCr and a Status column ("OK" if both differences are below ₹1).

Q4. Paginated SAP list [L2]

An S_ALR_87012277 output saved as text repeats the report title, selection line and column header every 60 lines, and subtotal rows are marked with * in the first column. Describe the full set of conditions to remove all non-data rows without using row positions.

Q5. Review judgement [L3]

A reviewer insists the team should "just delete the last 3 rows, they are always totals". Write a short response explaining the risk with two realistic examples from Indian bank or Tally exports, and propose the control you would add if they still prefer the positional approach.
