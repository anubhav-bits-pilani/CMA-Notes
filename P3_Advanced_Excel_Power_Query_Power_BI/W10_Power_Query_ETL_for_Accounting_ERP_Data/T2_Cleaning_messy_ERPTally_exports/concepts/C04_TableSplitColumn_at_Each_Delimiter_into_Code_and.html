Key concept

Table.SplitColumn at Each Delimiter into Code and Name

Concept: Table.SplitColumn(t, "Ledger", Splitter.SplitTextByEachDelimiter({" - "}), {"Code", "Name"})

Statement

Table.SplitColumn(table, sourceColumn, splitter, columnNamesOrNumber) replaces sourceColumn with new columns produced by applying splitter to each value.

Splitter.SplitTextByEachDelimiter(delimiters as list, optional quoteStyle, optional startAtEnd as logical) returns a splitter that splits once per delimiter in the list, in sequence. With the one-item list {" - "}, the text splits at the first occurrence of " - " only (or the last, if startAtEnd = true), producing at most two parts. The fourth argument names the resulting columns: Code and Name.

Contrast: Splitter.SplitTextByDelimiter(" - ") splits at every occurrence.

Explanation

Ledger names often contain the delimiter themselves: "400200 - Sales - Exports - SEZ". Splitting at every occurrence would produce four parts, and with only two target column names the extra parts are silently discarded — the name becomes "Sales", losing "Exports - SEZ". SplitTextByEachDelimiter({" - "}) gives Code = "400200", Name = "Sales - Exports - SEZ".

If the format is name-first ("Sales Domestic - 400100"), use startAtEnd = true so the split happens at the last delimiter.

Behaviour on edge values:

Input Code Name
"400100 - Sales Domestic" 400100 Sales Domestic
"400200 - Sales - Exports - SEZ" 400200 Sales - Exports - SEZ
"Round Off" Round Off null
null null null
"400300 -Sales Misc" (no space after dash) "400300 -Sales Misc" null

The last two rows of real data show why a split must be followed by checks: rows without the exact delimiter put the whole text into Code. Add a validation column — Code must be all digits (Text.Select([Code], {"0".."9"}) = [Code]) — and route failures to an exceptions list.

After splitting:

  • Type Code as text (the UI may auto-detect it as a whole number and drop leading zeros if auto type detection is on).
  • Trim both parts — splitting at " - " leaves no spaces, but a variant like " - " would.
  • Keep the original if you need it for audit: use Text.BeforeDelimiter/Text.AfterDelimiter in added columns instead of a destructive split.

Delimiter variants (en-dash "–", em-dash "—", colon) can be normalised first: Text.Replace(Text.Replace(x, "–", "-"), "—", "-").

Illustration

A SAP-derived mapping list of 1,200 accounts includes 36 names with internal hyphens. Using "Split Column by Delimiter → Each occurrence" truncates all 36 names; the Schedule III mapping by name then fails for 11 of them where the truncated names collide ("Sales" appearing for three different accounts). Using "Left-most delimiter" (the UI option that generates SplitTextByEachDelimiter with startAtEnd = false) keeps all names intact and the code-based mapping covers all 1,200.
