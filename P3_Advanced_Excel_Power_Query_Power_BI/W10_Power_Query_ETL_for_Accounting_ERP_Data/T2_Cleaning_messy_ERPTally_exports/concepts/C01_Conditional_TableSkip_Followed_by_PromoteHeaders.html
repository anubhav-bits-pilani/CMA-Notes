Key concept

Conditional Table.Skip Followed by PromoteHeaders

Concept: Table.Skip(Source, each [Column1] <> "Particulars") then Table.PromoteHeaders(_, [PromoteAllScalars=true])

Statement

Table.Skip(table as table, optional countOrCondition as any) as table removes rows from the top of a table:

  • if the second argument is a number \(n\), the first \(n\) rows are removed;
  • if it is a function (condition), rows are removed while the condition returns true; skipping stops at the first row for which it is false, and that row and all later rows are kept.

Table.PromoteHeaders(table, [PromoteAllScalars=true]) turns the first row into column names. With PromoteAllScalars=true, numbers, dates and other scalar values in the first row are converted to text names; without it, only text values are promoted and other cells keep generic names (Column3).

In the pattern, _ in the second step stands for the result of the first step (written as a nested call or as two named steps).

Explanation

The condition each [Column1] <> "Particulars" is true for every report-header line (company name, address, period, blanks — blanks are null and null <> "Particulars" is true), so all of them are skipped; it becomes false on the caption row, which is kept and promoted. The number of header lines can change without affecting the result — the essence of a refresh-safe step.

Important properties:

  • Stops at the first false only. Rows further down that match the condition are not removed; Table.Skip is not a filter. Repeated page headers need Table.SelectRows.
  • All rows skipped if never false. If "Particulars" is missing (renamed caption, different export language, header in Column2), the result is an empty table with no error. Guard with Table.IsEmpty and raise an error.
  • Exact comparison. Case, trailing spaces and char 160 defeat equality. Normalise: each Text.Upper(Text.Trim(Text.From([Column1] ?? ""))) <> "PARTICULARS".
  • Order with type detection. If auto type detection added a Changed Type on Column1..n before the skip, it can error on mixed content; turn it off or delete that step.
  • Promote then rename. Captions such as "Closing Balance" spanning two cells leave a null header promoted as Column3; rename explicitly or use the two-line technique.

Equivalent using a separate step for readability:

Skipped  = Table.Skip(Source, each [Column1] <> "Particulars"),
Promoted = Table.PromoteHeaders(Skipped, [PromoteAllScalars=true]),
Guard    = if Table.IsEmpty(Promoted) then error "Caption row 'Particulars' not found" else Promoted

Illustration

A Tally TB sheet for "Kaveri Agro Foods Pvt Ltd" has 5 header lines in March and 6 in April (an added GSTIN line).

Approach March result April result
Table.Skip(Source, 5) then promote Correct headers GSTIN line promoted as headers; real caption becomes a data row
Table.Skip(Source, each [Column1] <> "Particulars") then promote Correct Correct

Practice Questions

Q1. Predict the result [L1]

A sheet has rows: (1) "ABC Ltd", (2) null, (3) "Particulars", (4) "Cash", (5) "Particulars", (6) "Bank". State the rows returned by Table.Skip(Source, each [Column1] <> "Particulars") and then by promoting headers, and explain what happens to row 5.

Q2. Header in a different column [L2]

In some branches' exports the caption "Particulars" is in Column2 because Column1 holds a serial number. Write a skip condition that works whether the caption is in Column1 or Column2, with case and whitespace normalised.

💡 Hint: Test the row's values as a list rather than a single field.

Q3. Guard design [L2]

Write the full set of steps (skip, promote, guard) for a function that receives a file name as a parameter and raises an error naming the file if the caption is not found, and explain why failing is better than returning an empty table in a 12-branch consolidation.
