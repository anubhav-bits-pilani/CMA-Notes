Key concept

TransformColumnTypes with an Explicit en-IN Culture

Concept: Table.TransformColumnTypes(t, {{"Date", type date}}, "en-IN") converts with an explicit locale

Statement

Table.TransformColumnTypes(table as table, typeTransformations as list, optional culture as nullable text) as table converts values in each listed column to the target type. The optional third argument culture (a .NET culture name such as "en-IN", "en-US", "en-GB") determines how text is parsed: date component order, month names, decimal and group separators. With "en-IN", "03-04-2026" parses as 3 April 2026 and "1,23,456.00" as 123456.

Without the argument, the conversion uses the file's locale setting, else the machine's — making results environment-dependent.

In newer versions the third argument can also be a record: [Culture="en-IN", MissingField=MissingField.Ignore], which additionally tolerates listed columns that are absent.

Explanation

The culture affects conversion from text only. If a value is already a date (Excel cell typed as date), culture is irrelevant. If it is a number (Excel serial), conversion to date uses the serial.

What "en-IN" gives you:

  • Day-first short dates: dd-MM-yyyy, dd/MM/yyyy, d/M/yy.
  • English month names (Apr, April).
  • "." decimal separator and "," group separator, with lakh grouping accepted.

Practical rules:

  1. One culture per source. If an SAP extract comes from a user with US settings and a bank file from an Indian bank, type each in its own staging query with its own culture.
  2. Locale UI. Right-click column → Change Type → Using Locale… → Data type: Date, Locale: English (India) generates exactly this call.
  3. Combine with MissingField.Ignore when typing a dynamic set of columns that may not all exist each month.
  4. Folding: a culture-based conversion generally does not fold on SQL sources; on files it does not matter.
  5. Verify: after typing, check min/max date per file against the statement period — swaps are silent for days 1–12.

When the pattern is unusual (e.g. "20260403" or "03.04.26"), a culture is not enough; use Date.FromText(x, [Format="yyyyMMdd"]) or [Format="dd.MM.yy", Culture="en-IN"].

Illustration

Bank CSV dates (text): "01/04/2025", "12/04/2025", "13/04/2025", "31/03/2026".

Conversion 01/04/2025 12/04/2025 13/04/2025 31/03/2026
No culture on en-US machine 4 Jan 2025 4 Dec 2025 Error Error
"en-IN" 1 Apr 2025 12 Apr 2025 13 Apr 2025 31 Mar 2026

Under the first row, an FY derivation would put the 12 April receipt into Q3 FY2025-26 instead of Q1, and the year-end receipt would be dropped by "Remove Errors".

Practice Questions

Q1. Write the step [L1]

Write one Table.TransformColumnTypes step that types Txn Date and Value Date as dates and Withdrawal, Deposit and Balance as numbers using Indian conventions, ignoring any of these columns that are missing in a given file.

Q2. Two sources, two cultures [L2]

An SAP extract has dates "04/03/2026" meaning 3 April 2026 (US user settings) and the Tally ledger has "03-04-2026". Describe the staging design and typing step for each so that a combined bank-book recon uses correct dates.

💡 Hint: Type before appending, never after.

Q3. Validation [L2]

Design a check query that, per source file, reports min date, max date, count of dates outside the statement period and count of days greater than 12, and explain how each metric helps detect a locale error.
