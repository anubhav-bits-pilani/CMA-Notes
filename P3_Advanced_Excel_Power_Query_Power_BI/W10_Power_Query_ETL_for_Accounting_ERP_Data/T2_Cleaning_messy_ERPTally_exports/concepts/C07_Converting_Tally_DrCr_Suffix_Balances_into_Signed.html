Key concept

Converting Tally Dr/Cr Suffix Balances into Signed Numbers

Concept: Dr/Cr: (if Text.EndsWith([Bal], "Cr") then -1 else 1) * Number.From(Text.Select([Bal], {"0".."9", "."}))

Statement

For a text balance [Bal] such as "1,23,456.00 Dr" or "45,000.00 Cr":

\[ \text{Amount} = s \times v, \quad s = \begin{cases} -1 & \text{if Bal ends with "Cr"} \\ +1 & \text{otherwise} \end{cases}, \quad v = \text{Number}\big(\text{digits and "." of Bal}\big) \]

  • Text.Select([Bal], {"0".."9", "."}) keeps only the characters 0–9 and the decimal point, removing grouping commas, spaces, ₹ and the Dr/Cr letters.
  • Number.From(...) converts the result to a number.
  • The sign multiplier implements the convention Debit positive, Credit negative.

Explanation

The convention matters for everything downstream: a TB of signed amounts nets to zero; assets and expenses are positive, liabilities, equity and income negative; P&L total is negative for a profit. Choose it once for the whole model and document it.

{"0".."9", "."} is a list built with a character range — "0".."9" expands to the ten digit characters. Text.Select accepts a list of characters to keep.

Weaknesses of the bare formula and how to harden it:

Issue Example Effect of bare formula Fix
Null or blank null, "" Error / Number.From("") error Return null when blank
Lower/mixed case, trailing dot "45,000.00 cr", "45,000.00 Cr." Sign wrong (+) Upper-case, trim, test "CR" and "CR."
Prefix style "Cr 45,000.00" Sign wrong Also test Text.StartsWith
Minus or brackets "-45,000.00", "(45,000.00)" Sign stripped Detect "-" or "(" first
Non-breaking spaces "45,000.00" + char 160 + "Cr" Works (letters stripped) but EndsWith may fail on trailing char 160 Clean text first (c05)
Multiple dots "1.234.567,00" (European) Wrong value Not a Tally format — reject

Hardened version:

Amount = Table.AddColumn(t, "Amount", each
  let raw = [Bal],
      x   = if raw = null then "" else Text.Upper(Text.Trim(Text.Replace(Text.From(raw), Character.FromNumber(160), " "))),
      isCr = Text.EndsWith(x, "CR") or Text.EndsWith(x, "CR.") or Text.StartsWith(x, "CR"),
      neg  = Text.Contains(x, "(") or Text.StartsWith(x, "-"),
      num  = Text.Select(x, {"0".."9", "."})
  in  if num = "" then null
      else (if isCr then -1 else 1) * (if neg then -1 else 1) * Number.FromText(num, "en-US"),
  type nullable number)

Whether brackets plus "Cr" should double-negate is a data question — check how the source produced it, and log such rows rather than guess.

Illustration

Bal Amount
"4,82,36,190.00 Cr" −48236190.00
"3,12,45,600.50 Dr" 31245600.50
"1,69,46,089.00 Dr" 16946089.00
"44,500.50 Dr" 44500.50
Sum 0.00

A four-ledger TB nets to zero (−4,82,36,190.00 + 3,12,45,600.50 + 1,69,46,089.00 + 44,500.50 = 0.00), confirming the parse and sign convention. If any Cr row were misread as Dr, the sum would equal twice that row's value — a useful clue when tracing an imbalance.
