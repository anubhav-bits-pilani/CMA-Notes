Key concept

Filtering Out Null and Total Rows with Table.SelectRows

Concept: Table.SelectRows(t, each [Ledger] <> null and not Text.StartsWith([Ledger], "Total"))

Statement

Table.SelectRows(table as table, condition as function) as table returns the rows for which condition(row) is true. In the pattern, a row is kept when:

\[ \text{Ledger} \neq \text{null} \;\wedge\; \neg\,\text{StartsWith}(\text{Ledger}, \text{"Total"}) \]

The left test is evaluated first; because M's and short-circuits, the text function on the right is never called on a null value.

Explanation

Why the null test must come first. Text.StartsWith(null, "Total") does not return false — it raises an error ("We cannot convert the value null to type Text"), turning the condition into an error for that row and failing the step at load. Placing [Ledger] <> null and in front prevents the call. The same logic applies to or: if the left side is true the right side is skipped.

What the condition removes: blank spacer rows (null ledger), group subtotals ("Total Current Assets"), and "Total" lines. It does not remove "Grand Total" (starts with "G"), empty strings "" (not null), or rows with only spaces. A production version:

Kept = Table.SelectRows(t, each
         let x = Text.Trim(Text.From([Ledger] ?? "")) in
         x <> ""
         and not Text.StartsWith(x, "Total", Comparer.OrdinalIgnoreCase)
         and not List.Contains({"Grand Total", "Closing Balance", "Opening Balance"}, x, Comparer.OrdinalIgnoreCase))

Comparer.OrdinalIgnoreCase makes the tests case-insensitive. Text.StartsWith accepts a comparer as the third argument; List.Contains accepts an equation criteria (comparer) as the third.

False positives: genuine ledgers starting with "Total" ("TotalEnergies Lubricants — Creditor", "Totally Fresh Foods") would be removed. Mitigations: test "Total " with a trailing space, require that the row has no voucher/document number, or keep a whitelist from the ledger master. Always build the inverse query (rows removed) and glance at it during review.

Folding: on SQL sources, <> null and Text.StartsWith fold to IS NOT NULL and LIKE 'Total%'; on files, nothing folds — irrelevant to correctness.

Illustration

The basic pattern leaves two junk rows and drops one real ledger here; the production version plus a ledger-master whitelist handles all six.

Connections

Implements s02 (removing subtotal rows by condition). Uses Topic 1 c05 (each). Pairs with c01 (skip header) and c03 (Fill Down) in the standard cleaning sequence. The control-total cross-cutting item uses the removed "Grand Total" row as a check.

Practice Questions

Q1. Why the order matters [L1]

Explain what happens at refresh if the condition is written each not Text.StartsWith([Ledger], "Total") and [Ledger] <> null on a table containing null ledgers, and why the original order avoids it.

Q2. Extend the rule [L2]

Rewrite the condition to also remove "Sub Total", "Page n of m" lines, repeated "Particulars" captions and rows containing only spaces or char 160, case-insensitively.

💡 Hint: Normalise the text once in a let inside the each, then test the normalised value.

Q3. Inverse query for review [L2]
