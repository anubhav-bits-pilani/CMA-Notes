Roadmap topic: Folder Consolidation Pipeline: Automatically appending 12 monthly branch trial balances or bank statements dropped into a single folder

Overview

A folder consolidation pipeline turns "one file per branch per month" into "one clean table" without anyone opening the files. The pattern is the backbone of almost every Power Query automation an FP&A or financial reporting team builds: branch trial balances from Tally exported by twelve regional accountants, bank statement CSVs downloaded from four banks, GST purchase registers per GSTIN, or monthly payroll registers. Instead of copy-pasting each file into a master sheet (and silently missing one), you point Power Query at a folder, apply one transformation function to every file, stack the results and stamp each row with the branch and period it came from. Next month, someone drops new files in the folder and clicks Refresh All.

For the target roles this matters for three reasons. First, it is the cheapest form of month-end close automation: the consolidated TB or bank feed is ready minutes after the last branch uploads. Second, it is auditable: every row carries Source.Name, so a reviewer can trace any number back to a physical file, and control totals per file can be compared with the source report footers. Third, it is a building block for the week's exercise (bank reconciliation across six CSVs) and for later weeks where the same folder feeds a Power BI data model and a scheduled refresh.

The subtopics follow a learning sequence. Start with the source (Folder.Files / SharePoint.Files) and the filters that decide which files are in scope (s01). Then understand what the Combine Files button generates — Sample File, Parameter, Transform Sample File and the Transform File function (s02) — because most broken consolidations are broken in those helper queries. Next, learn to replace the generated scaffolding with a hand-written custom function that you control (s03), and to read Branch and Month from the file name (s04). With that core in place, handle the realities: schema drift between branches (s05), different bank layouts requiring one function per bank (s06), and the operational workflow of monthly drop-ins, archiving and duplicate detection (s07). The key concepts are the exact M expressions you will type repeatedly: the Folder.Files column set, the extension/temp-file filter, the function signature, the Table.AddColumn + Table.Combine invocation, tolerant column selection with MissingField.UseNull, file-name parsing with Text.BeforeDelimiter / Text.BetweenDelimiters, and the try ... otherwise guard that stops one bad file from failing the whole refresh.

A well-built pipeline has a recognisable shape: a FolderPath parameter, a Files staging query (connection only) that filters and parses names, one or more fx function queries, a Combined query that invokes and appends, a FileLog validation query with row counts and Dr/Cr totals per file, and an Errors query listing files that failed. Everything downstream (the consolidated TB, the BRS exceptions) references Combined.

Related concepts to study

SharePoint/OneDrive refresh in the Service (Week 12)

→ Week 12: SharePoint/OneDrive folders refresh in the Service without a gateway

A local or network folder (C:\Close\Branches or \\fileserver\finance) is an on-premises source: once the report is published to the Power BI Service, scheduled refresh needs an on-premises data gateway installed on a machine that can see that path, and the gateway's service account needs read rights. A SharePoint Online document library or OneDrive for Business folder is a cloud source, so the Service can refresh it directly with OAuth credentials and no gateway. This is why mature finance teams move the drop folder to a SharePoint library before publishing. The M changes are small — Folder.Files(FolderPath) becomes SharePoint.Files(SiteUrl, [ApiVersion = 15]) filtered on [Folder Path] — but the parameter must hold the site URL, not the folder URL. Week 12 covers credentials, privacy levels and refresh schedules in detail.

Multi-branch consolidation and eliminations (Weeks 1–4)

→ Week 1–4: multi-branch consolidation and inter-branch eliminations

The folder pipeline only stacks branch TBs; it does not consolidate in the accounting sense. In a single legal entity with branches (common for Indian companies with branch accounting in Tally), the inter-branch accounts — "HO Account" in the branch books and "Branch Mumbai Current Account" in HO books — must net to zero after adjusting for goods and cash in transit. In a group, intercompany balances and unrealised profit are eliminated under Ind AS 110. In the pipeline, tag those ledgers via a mapping table (an ElimFlag column on the Chart of Accounts), build an elimination check query that sums them by period, and treat a non-zero residual as a reconciling item to investigate before reporting.

Duplicate detection with Table.Distinct or Group By

Duplicate detection with Table.Distinct or Group By on file + voucher keys

Two duplicate risks exist: duplicate files (the same branch-month dropped twice, e.g. MUM_2025-04.csv and MUM_2025-04 (1).csv) and duplicate rows within or across files (a voucher exported in both April and May because of a date filter overlap). For files, group the file inventory on parsed Branch + Period and flag counts above one. For rows, group the combined table on Branch + VoucherNo + Date + Amount with Table.RowCount and keep groups with more than one row as an exception list. Table.Distinct removes exact duplicates, but use it deliberately: two genuine ₹10,000 petty-cash vouchers on the same day are not duplicates, so the key must include a voucher number.

Comparing against VSTACK formula consolidation (Week 9)

→ Week 9: comparing against VSTACK-based formula consolidation

In Excel 365, =VSTACK(Apr:Mar!A2:F500) stacks the same range across twelve sheets, and FILTER/TOCOL can drop blanks. This is fast to build and transparent, but it only works on sheets inside one workbook, needs fixed ranges or careful trimming, cannot read a folder, cannot clean Dr/Cr suffixes or report headers without heavy formulas, and recalculates on every edit. Power Query handles any number of files, applies cleaning once, logs errors and loads to the Data Model. A sound rule: VSTACK for small ad-hoc stacks inside one file; Power Query when files arrive monthly from outside.

Common pitfalls

Unrepresentative sample file

An unrepresentative sample file, so the transform logic fails on other branches.

Combine Files builds Transform Sample File from the first file in the filtered list (by default Source{0}). If that file is the cleanest branch — say Mumbai, with no subtotal rows and headers on row 5 — the recorded steps (Remove Top Rows 4, Removed Columns by name) fail or mis-clean Delhi's file with headers on row 7. People make this mistake because the preview looks perfect. Correct treatment: pick the messiest file as the sample (point the Sample File query at a named file, not position 0), and make the steps condition-based (Table.Skip(each ...), filter by value). Detect it in review by comparing per-file row counts and Dr = Cr totals in the file log; a branch with zero rows or unbalanced totals signals a sample-fit failure.

Expand step hard-codes the sample's columns

The expand step hard-codes the sample's column list, so new columns are silently dropped.

The generated expand step uses Table.ExpandTableColumn(..., Table.ColumnNames(#"Transform File"(#"Sample File"))), i.e. only the columns that the sample produced. If a manual re-expand was done in the UI, the list is literally typed out. A new "Cost Centre" column in the Pune file never appears, and no error is raised. Correct treatment: make the function return a fixed target schema via Table.SelectColumns(..., MissingField.UseNull), and append with Table.Combine(Files[Data]), which unions all column names. Detect by comparing the distinct column names across all nested tables with the output column list.

Temp, lock and duplicate files double counted

Temp files, lock files or old duplicate versions left in the folder get double counted.

When someone has Delhi_2025-05.xlsx open, Excel creates a hidden lock file named with a ~$ prefix in the same folder; OneDrive sync adds "-conflict" copies; users save "v2" and "final" versions. Folder.Files returns all of them, including files in subfolders. Correct treatment: filter by extension, exclude the tilde-dollar lock-file prefix and hidden attributes, exclude an Archive subfolder via [Folder Path], and enforce a naming convention validated by a regex-like parse (Branch must exist in the branch master, period must parse to a date). Detect with a Group By on Branch + Period that flags counts above one and fails the refresh or loads a visible warning.

Trusting Date modified for the period

Relying on file "Date modified" instead of the period parsed from the name or contents.

Date modified records when the file was last saved, not the accounting period: a March TB re-exported on 5 May after audit adjustments shows May. Copying files across machines or syncing through OneDrive can also reset it. People use it because it is a ready-made date column. Correct treatment: derive the period from the file name (Text.BetweenDelimiters([Name], "_", ".")) and, ideally, cross-check against the "Period: 1-Apr-2025 to 30-Apr-2025" caption inside the file. Use Date modified only for operational purposes, such as picking the latest version among duplicates. Detect by a check query comparing the name period with the contents period.

Practice Questions

Q1. Twelve-branch TB consolidator design [L3]

Sixteen Tally branch TBs per month (CSV, 1,200–3,500 rows each) are emailed by branch accountants for FY2025-26. File names are inconsistent: MUM_Apr25.csv, Mumbai-2025-04.csv, DEL_2025-04_final.csv, DEL_2025-04.csv. Some branches add a "Cost Centre" column; two branches export with Dr/Cr suffixes in a single "Closing Balance" column, others use separate Debit and Credit columns. (a) Specify the folder structure and naming convention you would impose. (b) List every query in the pipeline with its load setting. (c) Write the M for the file-scope filter and name parsing. (d) Describe the controls that would make you comfortable signing off the consolidated TB.

💡 Hint: Think in layers: parameter, file inventory, function(s), combine, validation log, error log.

Q2. Diagnosing a missing branch [L2]

After April refresh the consolidated TB total debits are ₹482.6 crore, but the sum of the sixteen branch report footers is ₹511.9 crore. The FileLog query shows fifteen files with rows and one file (PUN_2025-04.csv) with zero rows and no error. The Pune accountant used a new Tally template with three extra caption rows. Explain the probable cause in the generated helper queries, how you would confirm it in the editor, and the permanent fix.

Q3. Bank folder with four banks [L3]

The treasury folder holds monthly CSVs from HDFC (columns: Date, Narration, Chq./Ref.No., Value Dt, Withdrawal Amt., Deposit Amt., Closing Balance), ICICI (Value Date, Transaction Date, Cheque Number, Transaction Remarks, Withdrawal Amount (INR ), Deposit Amount (INR ), Balance (INR )), SBI (Txn Date, Value Date, Description, Ref No./Cheque No., Debit, Credit, Balance) and Axis. Design the common target schema, the routing of each file to its bank function, and the guard that keeps the refresh running when the Axis file arrives as XLS instead of CSV. Write the M for the routing step.

💡 Hint: A record of functions keyed by bank code lets Record.Field pick the right function per row.

Q4. Duplicate-period incident [L2]

In May, Hyderabad's April TB was re-exported after an audit adjustment of ₹18.4 lakh and saved as HYD_2025-04_rev.csv next to the original HYD_2025-04.csv. Both were consolidated. (a) Quantify the effect on the April consolidated TB if the original TB totals were ₹36.2 crore on each side. (b) Design a duplicate-file detection query and state what it should output. (c) Propose a rule for which version wins, and explain why Date modified alone is not sufficient.

Q5. Interview: Power Query vs VSTACK vs macro [L3]

A CFO asks why the team should maintain a Power Query folder pipeline rather than a VBA macro or an Excel 365 VSTACK sheet for consolidating 14 branch TBs. Prepare a structured answer covering maintainability, auditability, handling of messy layouts, error isolation, refresh in the Power BI Service and key-person risk.
