Key concept

Folder.Files Output Columns and Which to Trust

Concept: Folder.Files(FolderPath) returns Content, Name, Extension, Date modified and Folder Path columns

Statement

Folder.Files(path as text) returns a table with one row per file in the folder and all of its subfolders. The columns are:

Column Type Content
Content binary The file's bytes, read lazily when a step consumes it
Name text File name with extension, e.g. MUM_2025-04.csv
Extension text Extension including the dot, original case, e.g. .csv or .CSV
Date accessed datetime Last access timestamp
Date modified datetime Last save timestamp
Date created datetime Creation timestamp on this file system
Attributes record File attributes such as Hidden, ReadOnly, Directory, Size
Folder Path text Full path of the containing folder, ending with a backslash

Explanation

The function is the file inventory: metadata plus a handle (Content) to each file's bytes. Nothing is parsed until a later step passes Content to a parser such as Csv.Document or Excel.Workbook, so filtering on metadata first is both fast and safe.

Which columns to trust for what:

  • Name is the primary business key. Branch and period should be parsed from it under an agreed naming convention.
  • Extension decides which parser to use; normalise case with Text.Lower.
  • Folder Path identifies subfolders. Because the function is recursive, it is the column you filter to exclude Archive or Old subfolders, or to read a period from a folder-per-month structure.
  • Attributes lets you exclude hidden and system files; access it safely as [Attributes]?[Hidden]?.
  • Date modified / Date created / Date accessed describe the file system, not the accounting. They change on re-export, copy, sync or simply opening and saving. Use them only to choose between versions or for operational logging, never as the accounting period.

SharePoint.Files returns the same column set, with Folder Path holding a URL. Folder.Contents is the non-recursive navigational counterpart.

Illustration

A folder D:\Close\TB\ contains MUM_2025-04.csv (saved 3-May-2025) and a subfolder Archive\ with MUM_2025-03.csv (saved 6-Apr-2025, re-saved 2-May-2025 after an audit adjustment). Folder.Files("D:\Close\TB\") returns 2 rows:

Name Extension Date modified Folder Path
MUM_2025-04.csv .csv 03-05-2025 D:\Close\TB\
MUM_2025-03.csv .csv 02-05-2025 D:\Close\TB\Archive\

A pipeline that derived the period from Date modified would label both files May 2025. Parsing the name gives April and March correctly, and filtering [Folder Path] = "D:\Close\TB\" excludes the archived March file.

Practice Questions

Q1. Column purposes [L1]

For each of Name, Extension, Folder Path, Attributes and Date modified, state one legitimate use in a branch TB consolidation and one misuse to avoid.

Q2. Inventory query [L2]

Write a query FileInventory that returns, for every in-scope CSV in the folder parameter FolderPath (no subfolders), the columns Name, Branch, PeriodEnd, SizeKB (from Attributes) and Date modified, typed correctly, without opening any file contents.

💡 Hint: [Attributes][Size] is in bytes; divide by 1,024.

Q3. Version selection [L2]

Two files exist for Kochi, October 2025: KOC_2025-10.csv in the inbox and KOC_2025-10.csv in Inbox\Resubmitted\. Explain how Folder.Files presents them, how you would decide which one to consolidate, and what role, if any, Date modified should play.
