Key concept

Filtering by Extension and Excluding Temp Files

Concept: Table.SelectRows(Source, each [Extension] = ".csv" and not Text.StartsWith([Name], "~$"))

Statement

InScope = Table.SelectRows(Source, each [Extension] = ".csv" and not Text.StartsWith([Name], "~$"))
  • Source is the Folder.Files (or SharePoint.Files) inventory.
  • Table.SelectRows(table, condition) keeps rows for which condition(row) is true.
  • each ... is a one-argument function of the current row _; [Extension] is _[Extension].
  • [Extension] = ".csv" keeps only CSV files (case-sensitive comparison).
  • not Text.StartsWith([Name], "~$") removes Office owner/lock files, whose names begin with a tilde and a dollar sign.

Explanation

The filter defines which files are in the population. Two failure modes motivate it. First, the folder holds things other than data: notes, screenshots, an Excel working file. Second, Office writes an owner/lock file in the same folder when a workbook is open (for example while a branch accountant reviews their TB). That lock file is tiny, often hidden, and has the same extension as the real workbook, so an extension filter alone does not exclude it. Reading it fails or returns garbage and can break the whole refresh.

Hardening the basic expression:

  • Case. .CSV from some systems fails = ".csv". Use Text.Lower([Extension]) = ".csv".
  • Hidden attribute. Lock files are usually hidden; add [Attributes]?[Hidden]? <> true, which the Combine Files UI also generates.
  • Subfolders. Add a [Folder Path] condition because Folder.Files is recursive.
  • Multiple formats. List.Contains({".csv", ".xlsx"}, Text.Lower([Extension])), then route each format to its parser.
  • Logical precedence. not binds tighter than and, and and tighter than or; when mixing or, add parentheses: (a or b) and not c.

Filter on metadata before any step reads Content; otherwise rejected files are still opened.

Illustration

Folder contents and the effect of each version of the filter:

File Basic filter Hardened filter (lower-case, hidden, no subfolders)
DEL_2025-06.csv Kept Kept
DEL_2025-07.CSV Dropped (case) Kept
~$DEL_2025-07.xlsx Dropped (extension) Dropped
DEL_2025-07.xlsx Dropped Dropped (or routed to Excel parser if allowed)
Archive\DEL_2025-05.csv Kept (recursive) Dropped

The basic filter misses July entirely and double-includes May's archived file in a cumulative pipeline — two silent errors in one folder.

Connections

Underpins subtopic s01 (source filtering), s07 (archives and duplicates) and the topic pitfall on temp and lock files. The each shorthand is covered in topic t1 (M structure). In audit language, this step is the population-definition control; a RejectedFiles query showing what was excluded makes it reviewable.

Practice Questions

Q1. Fix the filter [L1]

Rewrite the concept's expression so that it keeps .csv and .txt files in any case, excludes lock files and hidden files, and ignores everything in subfolders of FolderPath.

Q2. Precedence trap [L2]

A colleague wrote each [Extension] = ".csv" or [Extension] = ".CSV" and not Text.StartsWith([Name], "~$"). Explain how M groups this expression, which files would slip through, and give the corrected expression.

💡 Hint: and binds more tightly than or.

Q3. Rejected files instead of silent drops [L2]

Write a companion query that returns the files excluded by your hardened filter, with a Reason column, so that the month-end preparer sees them on a Controls sheet.
