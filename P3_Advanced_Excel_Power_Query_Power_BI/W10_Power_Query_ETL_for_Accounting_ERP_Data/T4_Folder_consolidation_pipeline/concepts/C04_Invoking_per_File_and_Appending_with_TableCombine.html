Key concept

Invoking per File and Appending with Table.Combine

Concept: Table.AddColumn(Files, "Data", each fxCleanTB([Content])) then Table.Combine(Files[Data])

Statement

Files    = Table.AddColumn(InScope, "Data", each fxCleanTB([Content]), type table),
Combined = Table.Combine(Files[Data])
  • Table.AddColumn(table, newName, generator, optional columnType) adds a column whose value for each row is generator(row).
  • each fxCleanTB([Content]) means (_) => fxCleanTB(_[Content]): call the function with that file row's binary.
  • The new Data column holds one nested table value per file.
  • Files[Data] is column access on a table: it returns the column as a list of tables.
  • Table.Combine(tables as list, optional columns) appends the tables, aligning columns by name; a column absent from some tables is filled with null in those rows.

Explanation

This two-step pattern is the hand-written replacement for the Combine Files button. It separates what to do to one file (the function) from how to stack many (the combine), so each can be tested independently.

Important behaviours:

  • Column alignment by name. Unlike SQL UNION, which matches by position, Table.Combine matches by name and unions the column set. Order follows the first table, with new names appended. This makes it robust to column-order drift and makes extra columns visible rather than dropped.
  • Provenance is lost. Table.Combine returns only the nested data; the Name column of the file row is not carried. Either add a SourceFile column inside each nested table before combining, or use Table.ExpandTableColumn(Files, "Data", columnList) which keeps outer columns but needs a fixed column list.
  • Fixed output. Pass a list of names or a table type as the second argument to fix the output schema: Table.Combine(Files[Data], type table [Ledger = text, Debit = number, Credit = number]).
  • Laziness and errors. Each nested table is evaluated when combined; if one function call errors, the combine errors. Guard with try (concept c07).
  • Type of the column. Declaring type table on the added column helps the editor; it does not validate contents.

Logging is easy because the nested column is still available before combining: Table.AddColumn(Files, "Rows", each Table.RowCount([Data]), Int64.Type) and similar Dr/Cr sums produce a per-file control log.

Illustration

Three branch files clean to:

File Columns Rows
MUM_2025-04.csv Ledger, Debit, Credit 1,210
DEL_2025-04.csv Ledger, Credit, Debit, CostCentre 1,488
BLR_2025-04.csv Ledger, Debit, Credit 977

Table.Combine returns 3,675 rows with columns Ledger, Debit, Credit, CostCentre; CostCentre is null for 2,187 rows (Mumbai and Bengaluru) and Delhi's Debit/Credit are correctly aligned despite the reversed order. A sample-based Table.ExpandTableColumn using Mumbai's column list would have returned the same rows but without CostCentre.
