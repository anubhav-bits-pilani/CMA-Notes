Key concept

Parsing Branch and Period with Text Delimiter Functions

Concept: Text.BeforeDelimiter([Name], "_") gives the branch; Text.BetweenDelimiters([Name], "_", ".") gives the period

Statement

For a file named BRANCH_PERIOD.ext:

Branch     = Text.BeforeDelimiter([Name], "_")
PeriodText = Text.BetweenDelimiters([Name], "_", ".")
PeriodEnd  = Date.EndOfMonth(Date.FromText(PeriodText & "-01"))
  • Text.BeforeDelimiter(text, delimiter, optional index) returns the text before the chosen occurrence of delimiter (default: the first).
  • Text.AfterDelimiter(text, delimiter, optional index) returns the text after it.
  • Text.BetweenDelimiters(text, startDelimiter, endDelimiter, optional startIndex, optional endIndex) returns the text between the chosen start delimiter and the chosen end delimiter that follows it.
  • index / startIndex can be a number (0 = first occurrence) or a list {n, RelativePosition.FromEnd} to count from the end.

Explanation

The file name is often the only place the branch and period exist once caption rows have been removed. Parsing it with delimiter functions is simple and readable, but it is only as reliable as the naming convention.

Occurrence control matters when names have several underscores. For HDFC_4521_2025-04.csv:

  • Text.BeforeDelimiter([Name], "_") → "HDFC" (correct bank).
  • Text.BetweenDelimiters([Name], "_", ".") → "4521_2025-04" (start at the first underscore, stop at the first dot after it: wrong).
  • Text.BetweenDelimiters([Name], "_", ".", {0, RelativePosition.FromEnd}, 0) → "2025-04" (start at the last underscore).
  • Text.BetweenDelimiters([Name], "_", "_") → "4521" (account suffix).

Behaviour when a delimiter is missing: the functions do not raise an error; they return the whole text or an empty string, so a name like Mumbai April.csv produces a meaningless Branch value without any warning. Always validate parsed values — branch against a master list, period by attempting a date conversion inside try — and send failures to a rejected-files list.

Parsing belongs on the file inventory (one row per file), not on the combined data, both for speed and because the outer row's values can then be added to every nested row.

Illustration

Name Branch Period text PeriodEnd
MUM_2025-04.csv MUM 2025-04 30-04-2025
DEL_2026-02.csv DEL 2026-02 28-02-2026
BLR_2025-13.csv BLR 2025-13 error → rejected
Pune-2025-05.csv not a valid code not a valid period rejected

For the Pune file, the delimiter functions find no underscore and return text that is not a branch code or a period; no error is raised, so it is the branch-master check and the period try that reject the file, which is the desired outcome.

Q1. Evaluate the expressions [L1]

Q2. Fiscal-period names [L2]

Names follow BRANCH_FY26_M07.csv, where M01 is April 2025 and M12 is March 2026 for FY26. Write the M that converts the name into a month-end date, with a try guard returning null for unparseable names.

💡 Hint: FY26 starts on 1 April 2025; add (month number − 1) months, then take the month end.

Q3. Validation design [L2]

Write a step that adds a Status column ("OK", "Unknown branch", "Bad period") using BranchMaster[Code] and the parsed period, and explain why validating parsed values is necessary even when a naming convention exists.
