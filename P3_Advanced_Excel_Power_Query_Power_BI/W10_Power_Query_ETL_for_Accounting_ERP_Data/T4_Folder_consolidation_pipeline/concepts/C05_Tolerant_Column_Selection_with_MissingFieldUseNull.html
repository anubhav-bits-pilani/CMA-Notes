Key concept

Tolerant Column Selection with MissingField.UseNull

Concept: Table.SelectColumns(t, {"Date","Ledger","Debit","Credit"}, MissingField.UseNull)

Statement

Table.SelectColumns(t, {"Date", "Ledger", "Debit", "Credit"}, MissingField.UseNull)

Table.SelectColumns(table, columns, optional missingField) returns only the listed columns, in the listed order. The third argument controls what happens when a listed column does not exist in table:

Option Behaviour when a listed column is missing
MissingField.Error (default) Raises an error: the column wasn't found
MissingField.Ignore Skips the missing column; output has fewer columns
MissingField.UseNull Adds the missing column filled with null

Columns present in table but not listed are removed.

Explanation

In a folder pipeline the same step runs against every file. Some branch files lack an optional column (Date in a TB export, Cost Centre in older templates). With the default option the whole refresh fails on one file; with Ignore, the shape varies by file and downstream type steps referencing the missing column fail; with UseNull, every file yields exactly the same schema in the same order, which is what a consolidation needs.

The same option exists on other column-oriented functions — Table.RenameColumns, Table.RemoveColumns, Table.ReorderColumns, Table.TransformColumns — and on Record.SelectFields and similar record functions. Typical pairing inside a cleaning function:

  1. Normalise header text (trim, clean, case).
  2. Table.RenameColumns(t, synonyms, MissingField.Ignore) to map variants to standard names.
  3. Table.SelectColumns(t, target, MissingField.UseNull) to force the target schema.
  4. Table.TransformColumnTypes on the target columns.

The judgement call: tolerance must not become blindness. A null-filled mandatory column (Ledger, Debit or Credit for a TB) means the file was not understood. Pair UseNull with a check that flags files where a mandatory column is entirely null, or use MissingField.Error for mandatory columns and UseNull only for optional ones:

Mandatory = Table.SelectColumns(t, {"Ledger", "Debit", "Credit"}),
WithOptional = Table.SelectColumns(t, {"Ledger", "Debit", "Credit", "Date", "Cost Centre"}, MissingField.UseNull)

Evaluating Mandatory first (and discarding it) is a cheap assertion that errors on bad files, which try then logs.

Illustration

Four branch TB files after renaming:

File Columns present
MUM Ledger, Debit, Credit
DEL Date, Ledger, Debit, Credit, Group
BLR Ledger, Credit, Debit
HYD Ledger, Debit Amt, Credit

Table.SelectColumns(t, {"Date","Ledger","Debit","Credit"}, MissingField.UseNull) gives all four files the columns Date, Ledger, Debit, Credit. Date is null for MUM, BLR and HYD; Group is dropped from DEL; BLR's order is corrected. HYD's Debit is null because "Debit Amt" was not in the synonym list — the HYD file fails Dr = Cr and appears in the exception log, which is the intended outcome.

Practice Questions

Q1. Option choice per column [L1]

A bank function must output TxnDate, ValueDate, Narration, Ref, Withdrawal, Deposit. ValueDate and Ref are absent from one bank's export. Write the selection step(s) so that TxnDate, Narration, Withdrawal and Deposit are mandatory and the other two are optional.

Q2. Detect null-filled mandatory columns [L2]

Write a step for the per-file log that returns true when a nested table's Debit column contains only nulls, and explain why List.NonNullCount is preferable to checking the first row.

💡 Hint: List.NonNullCount(t[Debit]) = 0 works whether the column was missing or genuinely empty.

Q3. Ignore vs UseNull downstream [L2]

Describe what happens in a subsequent Table.TransformColumnTypes(t, {{"Date", type date}}) step for a file without a Date column when the selection used MissingField.Ignore, versus MissingField.UseNull.
