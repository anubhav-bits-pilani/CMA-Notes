Folder.Files and SharePoint.Files: Sources and File-Scope Filters

Scope: Folder.Files and SharePoint.Files as sources; filtering by extension and name pattern; excluding ~$ temp files

Why it matters

Every folder pipeline starts with a file inventory: a table with one row per file and a binary Content column. What enters that inventory decides what gets consolidated. If a lock file, a "v2" copy or last year's archive slips through, the consolidated TB is overstated and nothing errors. In audit terms, the file filter is the completeness-and-occurrence control of the pipeline: all in-scope files in, nothing else in. Getting the source right also determines whether the Power BI Service can refresh without a gateway (SharePoint) or needs one (local or network folder).

Core notes

Folder.Files

Folder.Files(path) returns a table of every file in the folder and all its subfolders (it is recursive). Each row has Content (binary), Name, Extension, Date accessed, Date modified, Date created, Attributes (a record with fields such as Hidden, ReadOnly, Directory) and Folder Path. Its sibling Folder.Contents(path) is non-recursive and returns files plus a Table column for navigating into subfolders; the UI's Folder connector uses Folder.Files.

let
    Source = Folder.Files(FolderPath)
in
    Source

FolderPath should be a text parameter (or read from a named cell with Excel.CurrentWorkbook(){[Name="FolderPath"]}[Content]{0}[Column1]), never a hard-coded C:\Users\... string. A trailing backslash matters only when you compare against [Folder Path], which always ends with one.

SharePoint.Files

SharePoint.Files(siteUrl, [ApiVersion = 15]) takes the site URL (for example https://contoso.sharepoint.com/sites/Finance), not the folder URL, and returns every file in every document library of that site, with the same column set; Folder Path holds the full URL. You then filter on Folder Path:

let
    Source = SharePoint.Files("https://contoso.sharepoint.com/sites/Finance", [ApiVersion = 15]),
    InFolder = Table.SelectRows(Source, each Text.StartsWith([Folder Path],
        "https://contoso.sharepoint.com/sites/Finance/Shared Documents/Close/BankCSV/"))
in
    InFolder

On a large site, SharePoint.Files enumerates everything before filtering and can be slow; SharePoint.Contents navigates library by library and is faster for deep structures. OneDrive for Business is a personal SharePoint site, so the same connector works with the -my.sharepoint.com/personal/... URL. The practical advantage is refresh: SharePoint Online is a cloud source, so the Service refreshes it without an on-premises gateway.

Filtering by extension

Extension includes the dot and keeps the original case: .csv, .CSV, .xlsx. Always normalise:

CsvOnly = Table.SelectRows(Source, each Text.Lower([Extension]) = ".csv")

If the folder legitimately mixes formats (some branches send .xlsx), keep both and route each to the right parser later, rather than dropping files silently.

Filtering by name pattern

Name filters enforce the naming convention, for example BRANCH_YYYY-MM.csv. M has no regular expressions, so build the pattern from text functions:

Pattern = Table.SelectRows(CsvOnly, each
    let n = Text.BeforeDelimiter([Name], ".", {0, RelativePosition.FromEnd}),
        parts = Text.Split(n, "_")
    in  List.Count(parts) = 2
        and Text.Length(parts{0}) = 3
        and (try Date.FromText(parts{1} & "-01") otherwise null) <> null)

A stricter design does not silently drop files that fail the pattern; it routes them to a RejectedFiles query loaded to a sheet so the preparer sees "Delhi April.csv rejected: name does not match convention".

Excluding temp, lock and hidden files

When a workbook is open, Excel creates an owner/lock file in the same folder whose name starts with the ~$ prefix. It has the .xlsx extension, so an extension filter alone lets it through, and reading it fails or returns garbage. Exclude it explicitly, along with hidden and system files and anything in an archive subfolder:

InScope = Table.SelectRows(Source, each
    Text.Lower([Extension]) = ".csv"
    and not Text.StartsWith([Name], "~$")
    and ([Attributes]?[Hidden]? <> true)
    and not Text.Contains([Folder Path], "\Archive\"))

The generated Combine Files code already adds Table.SelectRows(Source, each [Attributes]?[Hidden]? <> true); the ? operators make the field access safe when Attributes is null. Other noise to exclude: Thumbs.db, desktop.ini, .tmp files, and OneDrive conflict copies whose names contain the machine name.

Worked illustration

A folder contains: MUM_2025-04.csv, MUM_2025-05.csv, DEL_2025-04.CSV, the lock file ~$DEL_2025-05.xlsx, DEL_2025-05.xlsx, Archive\MUM_2025-03.csv and Notes.txt. With Folder.Files the inventory has 7 rows. After the lower-case .csv filter: 4 rows (both MUM files, the upper-case DEL file and the archived March file). After the archive exclusion: 3 rows. DEL_2025-05.xlsx is excluded by extension, which is a business decision — if Delhi is allowed to send Excel, widen the filter and route by extension; otherwise flag it in RejectedFiles.

Edge cases & judgement calls

  • Recursion surprises. A colleague creates Close\Old\ inside the drop folder; Folder.Files picks it up. Filter on exact [Folder Path] = FolderPath if subfolders must be ignored.
  • Network paths vs mapped drives. S:\Finance works only where S: is mapped; prefer the UNC path \\server\share\Finance for gateway refresh.
  • SharePoint URL encoding. Folder Path returns spaces as spaces in most cases, but copied browser URLs contain %20; compare using the form Power Query returns.
  • Folder permissions. In Excel, refresh runs as the user; in the Service via a gateway, it runs as the gateway's credentials, which may not see a personal folder.
  • Filtering before reading content. Apply all metadata filters before invoking the function so that rejected files are never opened; this is both faster and safer.
  • Case of names. Text.StartsWith is case-sensitive; use Text.Upper if branch codes may come in mixed case.

Key takeaways

  • Folder.Files is recursive and returns Content, Name, Extension, dates, Attributes and Folder Path for every file.
  • SharePoint.Files takes the site URL and is filtered on Folder Path; it refreshes in the Service without a gateway.
  • Normalise extension case and exclude the ~$ lock-file prefix, hidden files and archive subfolders.
  • Enforce a naming convention with text functions, and route non-conforming files to a visible rejection list.
  • Keep the folder path in a parameter or named cell so the pipeline moves between machines.

Practice Questions

Q1. Inventory after filters [L1]

A drop folder contains BLR_2025-06.csv, BLR_2025-07.CSV, HYD_2025-06.csv, ~$HYD_2025-07.xlsx, HYD_2025-07.xlsx, Archive\BLR_2025-05.csv, Archive\HYD_2025-05.csv and ReadMe.docx. State how many rows Folder.Files returns, then how many remain after each of these filters applied in order: (i) [Extension] = ".csv", (ii) lower-cased extension equals .csv, (iii) archive exclusion.

Q2. Write the scope filter [L2]

Write a single Table.SelectRows step that keeps only CSV or XLSX files (any case), excludes lock files and hidden files, ignores any subfolder, and keeps only names beginning with one of the branch codes in a list query BranchCodes (for example {"MUM","DEL","BLR"}).

💡 Hint: List.Contains(BranchCodes, Text.Start([Name], 3)) and an exact comparison of [Folder Path] with the parameter.

Q3. Migrating to SharePoint [L2]

Your consolidated bank feed uses Folder.Files("D:\Treasury\BankCSV") and is being published to the Power BI Service. The files will move to the "Treasury" site, library "Shared Documents", folder "BankCSV". Rewrite the source and filter steps, explain why the parameter should hold the site URL, and state one performance consideration if the site contains 40,000 files.

Q4. Rejected-files log [L3]

Design a RejectedFiles query that lists every file in the folder that is not consolidated, with a Reason column ("Wrong extension", "Lock file", "Bad name", "Archive"). Explain how you would surface it to the month-end preparer in Excel and why silently dropping files is a control weakness.
