Reading Branch and Month from the File Name

Scope: Reading Branch and Month from the file name ([Name] / Source.Name)

Why it matters

Branch trial balances and bank statements rarely contain the branch code or period on every row. Tally's TB export puts "Mumbai Branch" and "1-Apr-2025 to 30-Apr-2025" in caption rows that you deliberately strip off; a bank CSV may show the account number only in the header block. Once files are stacked, the only way to know which rows came from which branch-month is the file name. Branch and Period columns become the dimension keys for consolidation, eliminations, variance analysis and the Calendar relationship in the data model, so parsing them reliably is not cosmetic.

Core notes

Where the name lives

In Folder.Files, the file name is in [Name] (with extension). The Combine Files UI renames it to Source.Name and expands it alongside the data. In a hand-written pipeline, you parse [Name] on the file inventory before invoking the function — parsing 12 file names is cheaper than parsing 30,000 rows — and then either expand or add the parsed values inside each nested table.

Agree a naming convention first

Parsing is only reliable if names are predictable. A good convention: BRANCHCODE_YYYY-MM.ext (e.g. MUM_2025-04.csv), using a fixed branch code from the branch master and ISO year-month. ISO periods sort correctly as text and parse unambiguously. Bank files: BANK_ACCOUNTLAST4_YYYY-MM.csv (e.g. HDFC_4521_2025-04.csv).

Text functions for parsing

Parsed = Table.AddColumn(InScope, "Branch", each Text.BeforeDelimiter([Name], "_"), type text),
Parsed2 = Table.AddColumn(Parsed, "PeriodText", each Text.BetweenDelimiters([Name], "_", "."), type text),
Parsed3 = Table.AddColumn(Parsed2, "PeriodEnd", each
    Date.EndOfMonth(Date.FromText([PeriodText] & "-01")), type date)
  • Text.BeforeDelimiter(text, delimiter) returns everything before the first occurrence.
  • Text.AfterDelimiter(text, delimiter) returns everything after it.
  • Text.BetweenDelimiters(text, start, end) returns text between the first start delimiter and the next end delimiter after it.
  • All three accept an index argument to choose which occurrence: {0, RelativePosition.FromEnd} means the last occurrence. For HDFC_4521_2025-04.csv, the period is Text.BetweenDelimiters([Name], "_", ".", {0, RelativePosition.FromEnd}, 0), i.e. after the last underscore.
  • Text.Split([Name], "_") returns a list; {0}, {1} pick parts. Useful when there are several fixed segments.

Converting the period to a real date

Store a real date (month-end is conventional for TB balances; month-start is also used — pick one and document it). Common name formats and conversions:

Name segment Conversion
2025-04 Date.EndOfMonth(Date.FromText("2025-04" & "-01"))
Apr25 Date.EndOfMonth(Date.FromText("01-" & "Apr25", [Format = "dd-MMMyy", Culture = "en-IN"]))
042025 Date.EndOfMonth(#date(Number.From(Text.End(p, 4)), Number.From(Text.Start(p, 2)), 1))
FY26-M01 Map fiscal month 1 to April of FY start year 2025, i.e. Date.AddMonths(#date(2025, 4, 1), m - 1)

Wrap the conversion in try ... otherwise null and flag nulls: a file whose period does not parse must be rejected, not consolidated with a null period.

Validating against masters

Branch codes should be checked against a branch master (a small table in the workbook or a SharePoint list):

Checked = Table.AddColumn(Parsed3, "BranchValid", each List.Contains(BranchMaster[Code], [Branch]), type logical)

Files with BranchValid = false or a null PeriodEnd go to the rejected list. This also catches Mumbai_2025-04.csv vs MUM_2025-04.csv inconsistencies.

Carrying values into the data

After invoking the cleaning function, either expand the nested table (which keeps Branch and PeriodEnd from the inventory row) or add them inside the nested table:

WithData = Table.AddColumn(Checked, "Data", (f) =>
    let t = fxCleanTB(f[Content])
    in  Table.AddColumn(Table.AddColumn(t, "Branch", each f[Branch], type text),
                        "PeriodEnd", each f[PeriodEnd], type date)),
Combined = Table.Combine(Table.SelectRows(WithData, each [BranchValid])[Data])

Cross-checking against file contents

The strongest control compares the name with the contents. The Tally TB caption "1-Apr-2025 to 30-Apr-2025" can be extracted inside the function (Text.AfterDelimiter(captionRow, "to ")) and returned as a column; a check query flags files where the caption period differs from the name period. This catches the classic error of saving the May export as ..._2025-04.csv.

Worked illustration

File PUN_2025-09.csv: Branch = "PUN", PeriodText = "2025-09", PeriodEnd = 30-Sep-2025. File HDFC_4521_2025-09.csv parsed with first-occurrence Text.BetweenDelimiters would give "4521" (wrong); with the last-occurrence index it gives "2025-09" (right). This is why the convention and the parser must be designed together.

Edge cases & judgement calls

  • Spaces and suffixes. MUM_2025-04 (1).csv or MUM_2025-04_final.csv break the "between underscore and dot" logic; treat them as duplicates or rejects rather than writing ever more tolerant parsers.
  • Two-digit years. Apr25 is ambiguous only in theory, but explicitly use the culture and format; never rely on default parsing of 04/05.
  • Fiscal vs calendar periods. A name 2025-04 means April 2025, which is fiscal month 1 of FY2025-26; compute FY attributes from the date, not from the name.
  • Folder-based periods. Some teams use subfolders per month (FY26\M01\); parse [Folder Path] instead, with the same validation.
  • Date modified is not a period. It is the save timestamp; use it only to break ties between versions.

Key takeaways

  • Parse branch and period from [Name] on the file inventory, before invoking the cleaning function.
  • Use Text.BeforeDelimiter, Text.AfterDelimiter, Text.BetweenDelimiters (with occurrence indices) or Text.Split.
  • Convert the period to a real month-end date with an explicit format and culture, wrapped in try.
  • Validate branch codes against a master and reject unparseable names visibly.
  • Cross-check the name period against the caption period inside the file.

Practice Questions

Q1. Parse the names [L1]

For each file name, write the M expression that returns the branch code and the month-end date: (a) CHN_2025-11.csv, (b) ICICI_0098_2026-02.csv, (c) JAI-Mar26.csv.

Q2. Robust parser with validation [L2]

Write a step that adds Branch, PeriodEnd and Status columns to a file inventory, where Status is "OK", "Unknown branch" (not in BranchMaster[Code]) or "Bad period" (period text does not parse). Assume names follow CODE_YYYY-MM.csv.

💡 Hint: Compute the period with try ... otherwise null, then build Status with a nested if.

Q3. Caption cross-check [L3]

A Tally TB CSV has row 3 reading "1-Oct-2025 to 31-Oct-2025". Design the change to fxCleanTB that returns the caption period end date as a column, and the check query that compares it with the period parsed from the file name. State what the check query should output and who should act on it.

Q4. Convention design [L2]

Your company has 22 branches, 5 banks with 9 accounts and monthly GST registers for 4 GSTINs. Propose file-naming conventions for each feed that make parsing unambiguous, and explain why ISO year-month is preferred over "Apr25".
