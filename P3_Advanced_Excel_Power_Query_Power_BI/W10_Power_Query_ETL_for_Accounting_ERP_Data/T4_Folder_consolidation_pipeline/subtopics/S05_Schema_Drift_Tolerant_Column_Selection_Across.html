Subtopic note

Schema Drift: Tolerant Column Selection Across Branch Files

Scope: Schema drift: column order or names that differ by branch; selecting columns tolerantly

Why it matters

Branch accountants do not coordinate their exports. One branch runs Tally Prime 4 with "Debit Amount", another runs an older release with "Debit", a third adds a "Cost Centre" column, a fourth reorders columns because their TB configuration shows Closing first. Each difference is called schema drift. A pipeline that assumes one fixed schema either crashes ("column not found") or — worse — silently produces wrong numbers (an all-null Debit column for one branch). Making the pipeline drift-tolerant, and making drift visible, is what lets it run unattended month after month.

Core notes

Kinds of drift

Drift Example Typical effect if unhandled
Column order Ledger, Debit, Credit vs Ledger, Credit, Debit Harmless if selected by name; disastrous if by position (Column2)
Column names "Debit" vs "Debit Amount" vs "Dr" Column missing: error, or null values after combine
Extra columns "Cost Centre" in one branch Dropped by sample-based expand; harmless otherwise
Missing columns No "Group" column in one branch Table.SelectColumns / Changed Type error
Case and spaces "debit " vs "Debit" Treated as different columns; M names are case-sensitive
Header row position Header on row 5 vs row 8 Wrong row promoted, all names wrong

Principle 1: never address columns by position

Steps such as Table.RenameColumns(t, {{"Column2", "Debit"}}) or Table.ColumnNames(t){1} assume order. After promoting headers, always use names. If a file has no header, read positions only after verifying a known header row exists.

Principle 2: normalise header names first

Inside the cleaning function, immediately after promoting headers, standardise names so that later steps see one vocabulary:

Promoted = Table.PromoteHeaders(Skipped, [PromoteAllScalars = true]),
CleanNames = Table.TransformColumnNames(Promoted, each Text.Proper(Text.Trim(Text.Clean(_)))),
Renamed = Table.RenameColumns(CleanNames, {
        {"Debit Amount", "Debit"}, {"Dr", "Debit"}, {"Dr Amount", "Debit"},
        {"Credit Amount", "Credit"}, {"Cr", "Credit"}, {"Cr Amount", "Credit"},
        {"Particulars", "Ledger"}, {"Account Name", "Ledger"}},
    MissingField.Ignore)

Table.TransformColumnNames applies a function to every header (trim, clean, proper case). Table.RenameColumns with MissingField.Ignore renames only the variants present. A cleaner design keeps the synonym list in a mapping table (HeaderMap with columns From, To) on a sheet and converts it with Table.ToRows(HeaderMap) — finance users can then add a new synonym without editing M. Beware: if a file contains both "Dr" and "Debit", renaming both to "Debit" raises a duplicate-column error, which is the correct outcome (it needs a human).

Principle 3: select a fixed output schema tolerantly

Result = Table.SelectColumns(Renamed, {"Ledger", "Group", "Debit", "Credit", "Cost Centre"}, MissingField.UseNull)

MissingField.UseNull adds any missing column filled with null; extra columns are dropped. MissingField.Ignore simply leaves missing columns out (shape varies by file); the default MissingField.Error fails. For a consolidation, UseNull is usually right: every nested table has an identical shape, and Table.Combine produces a predictable output.

Principle 4: append by name with Table.Combine

Table.Combine aligns columns by name, not position, and unions the column set: if one table has a column others lack, the others get null. Combined with Principle 3, the output schema is exactly your target list.

Principle 5: make drift visible

Tolerance without visibility hides problems. Build a drift log from the nested tables before selection:

DriftLog = Table.AddColumn(WithRaw, "Columns", each Text.Combine(Table.ColumnNames([Raw]), ", "), type text),
MissingDebit = Table.SelectRows(DriftLog, each not List.Contains(Table.ColumnNames([Raw]), "Debit"))

Load a small table showing, per file, the raw header list and which target columns were null-filled. A Dr = Cr check per file is the ultimate test: if Debit was null-filled for a TB, the file cannot balance.

Typing after normalisation

Apply Table.TransformColumnTypes only to the target columns and only after selection, so a type step never references a column that may be missing. If an optional column may be absent from the whole output, typing it is still safe because UseNull guarantees it exists.

Worked illustration

Four branch files arrive:

Branch Raw headers
MUM Particulars, Debit, Credit
DEL Particulars, Credit, Debit, Cost Centre
BLR Account Name, Dr Amount, Cr Amount
HYD particulars , Debit , Credit

After trim/clean/proper-case and the synonym rename, all four expose Ledger, Debit, Credit (DEL also Cost Centre). Table.SelectColumns(..., {"Ledger","Debit","Credit","Cost Centre"}, MissingField.UseNull) gives four identical shapes; Cost Centre is null for MUM, BLR and HYD. Without the trim step, HYD's "Debit " would not match the rename list and would be null-filled — the drift log and an unbalanced HYD file would flag it.

Edge cases & judgement calls

  • Semantic drift. Same name, different meaning: one branch's "Amount" is net (Dr positive), another's is closing balance with Dr/Cr suffix. Names cannot detect this; per-file balance checks can.
  • Proper case side effects. Text.Proper turns "GSTIN" into "Gstin"; map to target names after normalisation, and be consistent.
  • Duplicate headers. Two blank header cells promote as "Column5" and "Column6"; drop unnamed columns by pattern (Text.StartsWith(name, "Column")) only after confirming they are empty.
  • Excel sources. Sheet name drift ("TB" vs "Trial Balance") is drift too; navigate by Kind = "Sheet" and a name list, or use the first sheet deliberately.
  • Over-tolerance. A pipeline that accepts anything will one day accept a P&L instead of a TB. Require a minimum set of columns and fail the file (into the error log) if they are absent.

Key takeaways

  • Schema drift covers order, names, extra/missing columns, case/whitespace and header position.
  • Reference columns by name only; normalise headers with Table.TransformColumnNames and a synonym map.
  • Use Table.SelectColumns(..., MissingField.UseNull) to force a fixed schema, then Table.Combine.
  • Log raw headers and null-filled columns per file so tolerance does not hide errors.
  • Per-file Dr = Cr checks catch semantic drift that name matching cannot.

Practice Questions

Q1. Choose the MissingField option [L1]

For each scenario state whether MissingField.Error, MissingField.Ignore or MissingField.UseNull is appropriate and why: (a) final schema enforcement in a TB cleaning function; (b) renaming synonym headers; (c) a step that must fail loudly if the "Ledger" column is absent.

Q2. Header map from a sheet [L2]

A sheet table HeaderMap has columns From and To with 14 synonym rows. Write the M that loads it and uses it in Table.RenameColumns with MissingField.Ignore inside fxCleanTB. Explain one Formula.Firewall risk and how to avoid it.

💡 Hint: Table.ToRows returns a list of {From, To} pairs, which is the shape Table.RenameColumns expects.

Q3. Diagnose a balanced-but-wrong consolidation [L3]

The consolidated September TB shows total debits ₹204.9 crore and total credits ₹214.7 crore. No refresh error occurred. The per-file log shows the Chennai branch with debits ₹0 and credits ₹9.8 crore; Chennai's raw header is "Particulars, Dr., Credit" while the synonym map contains "Dr" and "Dr Amount". Explain exactly which steps produced this result without an error, why the difference equals Chennai's credits, and which two controls would have stopped the output from being used.

Q4. Drift log specification [L2]

Specify the columns of a drift-log query loaded to a sheet each month (one row per file), including raw header list, missing target columns, extra columns and a balance check. Write the M for at least two of those columns.
