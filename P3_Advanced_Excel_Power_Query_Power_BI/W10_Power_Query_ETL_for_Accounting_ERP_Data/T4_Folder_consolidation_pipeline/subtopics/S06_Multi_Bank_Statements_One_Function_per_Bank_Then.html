Subtopic note

Multi-Bank Statements: One Function per Bank, Then Table.Combine

Scope: Bank statements from banks with different layouts: one function per bank, then Table.Combine

Why it matters

An Indian mid-size company typically banks with three to six banks — a PSU bank for statutory payments and collections, two private banks for operating accounts, perhaps a foreign bank for forex. Each bank's net-banking CSV has a different header block, column names, date format, amount convention and footer. A bank reconciliation, cash-flow forecast or treasury dashboard needs all of them in one standard transaction table. Trying to write one function that handles every layout leads to an unreadable tangle of conditions; the robust pattern is one small, testable cleaning function per bank, each emitting an identical target schema, followed by a single Table.Combine.

Core notes

Typical layout differences

Exact layouts change when banks upgrade portals, so treat the following as illustrative of the kinds of difference you will meet rather than a permanent specification:

Feature Bank A (private, CSV) Bank B (private, XLS) Bank C (PSU, CSV)
Header block ~20 rows of customer details ~12 rows ~18 rows, account number in a caption
Date column Date (dd/MM/yy) Transaction Date (dd/MM/yyyy) Txn Date (d MMM yyyy)
Value date Value Dt Value Date Value Date
Reference Chq./Ref.No. (UTR embedded in narration) Cheque Number Ref No./Cheque No.
Amounts Separate Withdrawal / Deposit Separate Withdrawal / Deposit with "(INR )" suffix in headers Separate Debit / Credit
Footer A row of asterisks, then a "STATEMENT SUMMARY" block Legends and disclaimers "Closing balance" line
Numbers Plain decimals Indian grouping "1,23,456.00" as text Indian grouping

The target schema

Define the target first, as a contract all bank functions must satisfy:

Column Type Meaning
Bank text Bank code from file name
AccountNo text Account number (text, keeps leading zeros)
TxnDate date Transaction (posting) date
ValueDate date Value date
Narration text Cleaned narration
Ref text Cheque number or UTR, normalised
Withdrawal number Outflow, positive
Deposit number Inflow, positive
Amount number Deposit minus Withdrawal (signed from the company's view)
SourceFile text File name

Encoding the target as a type makes it explicit:

BankSchema = type table [Bank = text, AccountNo = text, TxnDate = date, ValueDate = date,
    Narration = text, Ref = text, Withdrawal = number, Deposit = number, Amount = number, SourceFile = text]

One function per bank

Each function knows its own quirks and ends with the same selection:

fxBankA = (file as binary) as table =>
let
    Raw      = Csv.Document(file, [Delimiter = ",", Encoding = 65001, QuoteStyle = QuoteStyle.Csv]),
    Skipped  = Table.Skip(Raw, each [Column1] <> "Date"),
    Promoted = Table.PromoteHeaders(Skipped, [PromoteAllScalars = true]),
    Data     = Table.FirstN(Promoted, each not Text.StartsWith([Date] ?? "", "*")),
    Renamed  = Table.RenameColumns(Data, {{"Date", "TxnDate"}, {"Value Dt", "ValueDate"},
                 {"Chq./Ref.No.", "Ref"}, {"Withdrawal Amt.", "Withdrawal"}, {"Deposit Amt.", "Deposit"}}),
    Typed    = Table.TransformColumnTypes(Renamed, {{"TxnDate", type date}, {"ValueDate", type date},
                 {"Withdrawal", type number}, {"Deposit", type number}}, "en-IN"),
    Amt      = Table.AddColumn(Typed, "Amount", each ([Deposit] ?? 0) - ([Withdrawal] ?? 0), type number),
    Result   = Table.SelectColumns(Amt, {"TxnDate", "ValueDate", "Narration", "Ref",
                 "Withdrawal", "Deposit", "Amount"}, MissingField.UseNull)
in
    Result

Table.FirstN with a condition keeps rows until the condition first fails — ideal for cutting a footer without counting rows. Functions for other banks differ in the skip marker, the rename list, the date culture/format and any text-to-number parsing, but end in the same Table.SelectColumns.

Routing each file to its function

Parse the bank code from the file name, then look the function up in a record of functions:

Parsers = [HDFC = fxBankA, ICICI = fxBankB, SBI = fxBankC],
Files   = Table.AddColumn(InScope, "Bank", each Text.BeforeDelimiter([Name], "_"), type text),
WithData = Table.AddColumn(Files, "Data", (f) =>
    let fn = Record.FieldOrDefault(Parsers, f[Bank], null),
        t  = if fn = null then error "No parser for bank " & f[Bank] else fn(f[Content])
    in  Table.AddColumn(Table.AddColumn(t, "Bank", each f[Bank], type text),
                        "SourceFile", each f[Name], type text)),
Combined = Table.Combine(WithData[Data], BankSchema)

Functions are first-class values in M, so a record field can hold a function. Record.FieldOrDefault returns null for an unknown bank, which you turn into an explicit error (and catch with try into the failure log). Table.Combine(tables, columns) accepts an optional table type, which fixes the output column set and types.

Account number and other header facts

The account number usually appears in the header block, not in the rows. Extract it inside the bank function from the raw table before skipping — e.g. find the row whose first column starts with "Account No" and take the second column — and add it as a column. If it is not reliably present, use the file-name convention (HDFC_4521_2025-04.csv) and map last-four digits to the full account through a bank-account master.

Opening and closing balance check

Every bank file implies a control: opening balance + deposits − withdrawals = closing balance. Capture opening and closing from the header/footer (or from the first and last running-balance values), and build a per-file check. A failure means rows were lost in cleaning (often the footer cut was too aggressive or a page-break header row was filtered out with data).

Worked illustration

April files: Bank A, 1,284 rows, deposits ₹6.42 crore, withdrawals ₹5.97 crore, opening ₹1.10 crore, closing ₹1.55 crore. Check: \(1.10 + 6.42 - 5.97 = 1.55\), so the file passes. Bank C: 3,911 rows, opening ₹0.84 crore, deposits ₹12.30 crore, withdrawals ₹12.61 crore, statement closing ₹0.48 crore, but cleaned rows imply \(0.84 + 12.30 - 12.61 = 0.53\). The ₹5 lakh gap points to a dropped row — on inspection, a withdrawal whose narration began with "Total" was removed by an over-broad subtotal filter.

Edge cases & judgement calls

  • Portal changes. Banks change exports without notice; a function failing in try with a clear "header marker not found" message is far better than wrong output.
  • XLS vs CSV. Some banks give legacy .xls; Excel.Workbook reads it, but formats and merged cells differ — build that bank's function on the binary format actually received.
  • Single amount column with Dr/Cr flag. Some statements use "Amount" plus "Dr/Cr" indicator; derive Withdrawal/Deposit inside that bank's function.
  • Multiple accounts per bank. Same function, different files; never encode an account number inside a function.
  • Time zones and dates. Statements are in IST; the date-only columns are safe, but datetime stamps in some exports should be converted with Date.From.
  • Combining types. If one function returns Amount as text, Table.Combine with a type ascribes but does not convert; type inside each function.

Key takeaways

  • Define a target bank schema first; every bank function must end by emitting exactly that schema.
  • Write one small function per bank; route files to functions with a record of functions keyed on the bank code.
  • Table.FirstN with a condition and Table.Skip with a condition cut headers and footers without row counts.
  • Extract account numbers and opening/closing balances from the header block and run a balance roll-forward per file.
  • Table.Combine(list, tableType) appends by name and fixes the output columns.

Practice Questions

Q1. Target schema decisions [L1]

Explain why AccountNo and Ref should be typed as text, why both Withdrawal/Deposit and a signed Amount are kept, and why SourceFile belongs in the bank transaction table.

Q2. Write the PSU bank function [L2]

Bank C's CSV has 18 caption rows (row 6 reads "Account Number :,00000031245678901"), a header row starting "Txn Date", date format "5 Apr 2025", Debit and Credit amounts as text with Indian grouping ("1,23,456.00"), and a last line beginning "**Computer generated". Write fxBankC returning the target schema including AccountNo.

💡 Hint: Read the account number from the raw table before Table.Skip, and convert amounts with an explicit "en-IN" culture.

Q3. Roll-forward check failure [L2]

For a Bank B file, opening balance is ₹42,18,350.00, the statement closing balance is ₹38,06,120.50, cleaned deposits total ₹1,94,62,800.00 and cleaned withdrawals total ₹1,99,24,529.50. Determine whether the file passes the roll-forward check, and if not, list three likely cleaning causes to investigate.

Q4. Adding a fifth bank [L3]

A new Kotak account opens in November. Describe every change needed in the pipeline — function, routing record, naming convention, masters, checks — and how you would ensure the existing four banks' outputs are unchanged after the change.
