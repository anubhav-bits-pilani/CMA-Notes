Combine Files Artefacts: Sample, Parameter and Transform Function

Scope: Combine Files artefacts: Sample File, Parameter, Transform Sample File, Transform File function

Why it matters

Clicking Combine Files (or Combine & Transform Data in Excel's Get Data > From Folder) generates a group of helper queries that most users never read. When a consolidation breaks next month — a branch disappears, a column goes missing, refresh throws Expression.Error — the fault is almost always in these helpers. Knowing what each artefact does, how they are wired, and when to discard them for a hand-written function is the difference between a pipeline you maintain and one you rebuild every quarter.

Core notes

What gets generated

After you connect to a folder and click Combine, Power Query creates a Helper Queries group plus modifications to your main query:

Artefact Type What it is
Sample File Query returning binary Navigates to one file in the filtered folder list, by default the first (Source{0}[Content])
Parameter1 (Sample File Parameter) Parameter of type binary A parameter whose current value is Sample File
Transform Sample File Query The editable transformation; its first step reads Parameter1 instead of a fixed file
Transform File Function Generated from Transform Sample File; same steps, but Parameter1 becomes the function argument

The function is linked to the sample query: in the editor, Transform File shows "This query contains transformations that are applied to every file... edit Transform Sample File". Any step you add to Transform Sample File is automatically reflected in Transform File. You should not edit Transform File directly; doing so breaks the link.

The main query steps

Typical generated M in the main query:

let
    Source = Folder.Files(FolderPath),
    #"Filtered Hidden Files1" = Table.SelectRows(Source, each [Attributes]?[Hidden]? <> true),
    #"Invoke Custom Function1" = Table.AddColumn(#"Filtered Hidden Files1", "Transform File",
        each #"Transform File"([Content])),
    #"Renamed Columns1" = Table.RenameColumns(#"Invoke Custom Function1", {"Name", "Source.Name"}),
    #"Removed Other Columns1" = Table.SelectColumns(#"Renamed Columns1",
        {"Source.Name", "Transform File"}),
    #"Expanded Table Column1" = Table.ExpandTableColumn(#"Removed Other Columns1", "Transform File",
        Table.ColumnNames(#"Transform File"(#"Sample File"))),
    #"Changed Type" = Table.TransformColumnTypes(#"Expanded Table Column1",
        {{"Source.Name", type text}, {"Ledger", type text}, {"Debit", type number}, {"Credit", type number}})
in
    #"Changed Type"

Three things to read carefully:

  1. Invoke Custom Function calls the function once per file row, producing a nested table per file.
  2. Source.Name is simply the renamed Name column — the only provenance kept by default.
  3. Expanded Table Column takes its column list from running the function on the sample file. Columns that exist only in other files are dropped without any error; columns that exist in the sample but not in another file come through as null.

The trailing Changed Type step hard-codes column names and fails with "The column 'X' of the table wasn't found" if a column disappears.

How the sample is chosen

Sample File uses the first row of the filtered list at the time of creation. The list is ordered by the file system (usually by name), so if a new file sorts before your chosen sample, the "sample" changes on its own. To stabilise it, edit Sample File to select by name:

Source = Folder.Files(FolderPath),
Navigation = Source{[Name = "DEL_2025-04.csv"]}[Content]

Choose the messiest representative file — the one with the most caption rows, subtotals and blank lines — so the recorded steps are tested against the hardest case.

Worked illustration

Mumbai's file (the sample) has columns Ledger, Debit, Credit. Pune's file has Ledger, Cost Centre, Debit, Credit. After combining, Pune's rows show Ledger, Debit and Credit correctly, but Cost Centre is absent from the output. If the sample were Pune, Mumbai's rows would show Cost Centre = null — preferable, because the column exists and the nulls are visible. If Chennai's file uses "Dr Amount" instead of "Debit", its Debit column is entirely null and Chennai's TB appears as all credits; a Dr = Cr check per file catches this immediately.

When to keep and when to replace the helpers

Keep the generated helpers when files are genuinely uniform (a single ERP extract with a fixed layout) and the users who maintain the file prefer the UI. Replace them with a hand-written function (next subtopic) when layouts vary, when you need a defined output schema, when you want error isolation per file, or when several pipelines should share one cleaning function. A common middle path: keep Transform Sample File for UI-driven editing but change the main query's expand step to Table.Combine over the nested column, which unions all columns.

Edge cases & judgement calls

  • Renaming helper queries. Renaming Transform File to fxCleanTB is fine; Power Query updates references. Deleting Sample File breaks the parameter's current value.
  • Duplicated pipelines. Combining a second folder creates Transform File (2), Parameter2 and so on; the workbook fills with near-identical helpers. Consolidate them into one named function.
  • Excel sources. For an Excel folder, Combine Files asks which sheet or table to use from the sample; the generated navigation (Source{[Item="TB",Kind="Sheet"]}[Data]) fails on files where the sheet is named differently. Normalise sheet names or navigate by position with care.
  • Promote Headers in the function. If the sample's header row is detected automatically, files with different caption rows will promote the wrong row; replace with a conditional Table.Skip.
  • Load settings. The helper queries are connection-only by default; keep them so, otherwise a single file's sample loads to a sheet and confuses users.

Key takeaways

  • Combine Files generates Sample File, a binary Parameter, Transform Sample File and the linked Transform File function.
  • Edit Transform Sample File, never Transform File, while the link is in place.
  • The expand step uses the sample's column names, so columns unique to other files are silently lost.
  • Pin the sample to a named, messy file rather than position 0.
  • Replace the scaffolding with a hand-written function and Table.Combine when layouts vary or control matters.

Practice Questions

Q1. Name the artefacts [L1]

List the four helper artefacts created by Combine Files, state the type of each (query, parameter, function), and explain in one line how Transform File stays in sync with Transform Sample File.

Q2. Silent column loss [L2]

Eight branch files are combined. The sample (AHM_2025-04.csv) has columns Ledger, Group, Debit, Credit. Three branches added a "Branch GSTIN" column in May. Explain what the consolidated output shows for May, why no error occurs, and rewrite the expand step so all columns from all files come through.

💡 Hint: Table.Combine aligns by column name and fills missing columns with null.

Q3. The sample moved [L2]

In June a new file AAA_Test.csv was dropped in the folder and the refresh started failing with "The column 'Particulars' of the table wasn't found". Explain the chain of cause and effect through the Sample File query, and give two fixes: one in the folder filter and one in the Sample File query.

Q4. Refactor decision [L3]

Your workbook has five folder pipelines (branch TBs, bank CSVs, GST registers, payroll, fixed-asset additions), each with its own generated helper group. Propose a refactoring plan that reduces maintenance, describing which helpers to delete, which functions to write, how to name and group queries, and how you would regression-test the refactor against the old outputs.
