Subtopic note

Multi-Row Headers: Transpose, Fill, Merge, Transpose Back, Unpivot

Scope: Multi-row headers (department over month): transpose, fill down, merge headers, transpose back, unpivot

Why it matters

Many budget and MIS workbooks have two (or more) header rows: departments or scenarios in row 1, often in merged cells spanning several columns, and months in row 2. For example, "Sales" over Apr-25 … Mar-26, then "Marketing" over Apr-25 … Mar-26, side by side. Power Query can promote only one row to headers, so a direct unpivot would lose the department. The standard technique — transpose, fill down, combine the header rows, transpose back, promote, unpivot, split — reconstructs both attributes for every value. It is a staple of interview tests and the Saturday assessment.

Core notes

The input

After reading the sheet (no header promotion), the top looks like this (merged cells arrive as a value in the first cell and nulls in the rest):

Column1 Column2 Column3 Column4 Column5 Column6 Column7
null Sales null null Marketing null null
Account Apr-25 May-25 Jun-25 Apr-25 May-25 Jun-25
610100 Salaries 12,00,000 12,00,000 12,00,000 6,00,000 6,00,000 6,50,000
620300 Travel 1,50,000 1,20,000 1,40,000 80,000 75,000 90,000

The department needs to be filled across to the right, but Power Query fills only down. Hence the transpose.

Step-by-step

  1. Transpose (Table.Transpose) — header rows become the first two columns; each original column becomes a row.
Column1 Column2 Column3 Column4
null Account 610100 Salaries 620300 Travel
Sales Apr-25 12,00,000 1,50,000
null May-25 12,00,000 1,20,000
null Jun-25 12,00,000 1,40,000
Marketing Apr-25 6,00,000 80,000
… … … …

  1. Fill Down Column1 (Table.FillDown(t, {"Column1"})) — "Sales" fills the May and Jun rows, "Marketing" its months. The first row (null over "Account") stays null — correct, it is the identifier column. Replace "" with null first if the source has empty strings (Topic 2 c03).

  2. Combine the two header columns into one (Table.CombineColumns(t, {"Column1","Column2"}, Combiner.CombineTextByDelimiter("|", QuoteStyle.None), "Hdr")). Rows become "Sales|Apr-25", "Sales|May-25", … and for the first row, null + "Account" — the combiner skips nulls in current versions and gives "Account", but be explicit: if Column1 is null, use Column2 alone.

  3. Transpose back (Table.Transpose) — the Hdr values return to the first row.

  4. Promote headers — columns are now Account, Sales|Apr-25, Sales|May-25, …, Marketing|Jun-25.

  5. Unpivot Other Columns on Account → Attribute = "Sales|Apr-25", Value = amount.

  6. Split Attribute on "|" into Department and Month; convert Month to a month-end date (s03); type Amount.

Full M (c03):

let
    Source   = Excel.Workbook(File.Contents(pPath), null, true){[Item="Budget",Kind="Sheet"]}[Data],
    Top      = Table.Skip(Source, each [Column2] = null and [Column1] = null),   // drop leading blank rows
    T1       = Table.Transpose(Top),
    Filled   = Table.FillDown(T1, {"Column1"}),
    Hdr      = Table.AddColumn(Filled, "Hdr", each if [Column1] = null then [Column2] else [Column1] & "|" & [Column2], type text),
    Reordered= Table.SelectColumns(Hdr, {"Hdr"} & List.Skip(Table.ColumnNames(Filled), 2)),
    T2       = Table.Transpose(Reordered),
    Promoted = Table.PromoteHeaders(T2, [PromoteAllScalars=true]),
    Long     = Table.UnpivotOtherColumns(Promoted, {"Account"}, "Attribute", "Amount"),
    Split    = Table.SplitColumn(Long, "Attribute", Splitter.SplitTextByEachDelimiter({"|"}), {"Department","Month"}),
    Dated    = Table.TransformColumns(Split, {{"Month", each Date.EndOfMonth(Date.FromText("01-" & _, [Format="dd-MMM-yy", Culture="en-IN"])), type date}}),
    Typed    = Table.TransformColumnTypes(Dated, {{"Amount", type number}, {"Account", type text}, {"Department", type text}}, "en-IN")
in
    Typed

Here an added column replaces Table.CombineColumns to handle the null-department case explicitly; both approaches are valid.

Choosing the delimiter

Use a character that never appears in department or month names: "|" is conventional. Do not use "-" (months contain it: "Apr-25") or a space.

Three header rows

Scenario over Department over Month: transpose, fill down both upper columns (Column1 and Column2), combine all three with "|", transpose back, promote, unpivot, split into three. When filling the second level, reset it when the first level changes (otherwise the first department of "Forecast" inherits the last department of "Budget") — usually not an issue because every block repeats the department name in its first column, but check.

Performance and limits

Table.Transpose materialises the whole table and does not fold. A budget of a few thousand rows is trivial; a 200,000-row sheet would be slow and memory-heavy. For large inputs, an alternative avoids transposing the data body: read only the two header rows, build the combined header list in a small query (List.Zip of filled-right row 1 and row 2), then rename the columns of the data body with Table.RenameColumns(Body, List.Zip({Table.ColumnNames(Body), NewHeaders})) and unpivot.

Edge cases & judgement calls

  • Totals per department block ("Sales Total") as extra columns: after combining, they look like "Sales|Total" — drop them before or after unpivot (filter Month that fails to parse) and use them as controls.
  • Merged cells over the identifier columns (e.g. "Account" and "Description" both under a blank top header) — the null-department rule handles them; list all identifier headers in the unpivot.
  • Empty spacer columns between blocks become rows of nulls after transpose; remove them (Hdr null) before transposing back.
  • Type detection after transpose — mixed types per column cause errors; keep everything untyped until the end.
  • Department names with trailing spaces in the merged cell — trim after split.
  • Header row position varies — locate header rows by condition (Topic 2 s01) before transposing.

Key takeaways

  • Power Query promotes one header row, so multi-row headers must be combined into one first.
  • Transpose turns "fill right" into "fill down"; fill the upper header, combine with a safe delimiter, transpose back, promote.
  • Unpivot on the identifiers, then split the combined attribute back into Department and Month.
  • Handle the null upper header over identifier columns and remove spacer/total columns explicitly.
  • For large inputs, build the combined header list separately and rename columns instead of transposing the body.

Practice Questions

Q1. Trace the steps [L1]

Using the input table in these notes, write out the first five rows of the table after step 2 (fill down) and after step 6 (unpivot), and state the expected number of rows in the final long table if there are 140 accounts, 3 departments and 12 months (no blanks).

Q2. Write the M for three header rows [L2]

A forecast sheet has Scenario (Budget/Forecast) in row 1, Department in row 2 and Month in row 3, with merged cells across. Write the M to produce Scenario, Department, Month (month-end date), Account and Amount.

💡 Hint: Fill down two columns after the first transpose and combine three.

Q3. Block totals [L2]

Each department block ends with a "Total" column, and the sheet has a final "Grand Total" column. Modify the pipeline to exclude them from the fact table but produce a check table comparing each department's unpivoted sum with its Total column.

Q4. Large sheet alternative [L3]

A daily cash-forecast sheet has 6 bank accounts × 365 days as two header rows and 3,000 rows of line items. Describe and write the alternative approach that renames columns from a combined header list instead of transposing the body, and explain why it is faster.

Q5. Delimiter choice [L1]

Explain why "-" and " " are poor delimiters for combining Department and Month headers, and give an example of a department name that would break the split if "&" were used.
