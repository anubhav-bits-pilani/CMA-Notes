Unpivoting TB Columns (Opening, Debit, Credit, Closing)

Scope: Splitting TB columns (Opening, Debit, Credit, Closing) into an attribute and value pair

Why it matters

A full Trial Balance export carries four measures per ledger: Opening balance, period Debits, period Credits and Closing balance — sometimes as eight columns when each balance is split Dr/Cr. For analysis and roll-forward checks (Opening + Debits − Credits = Closing), a long shape with a Measure (attribute) column and an Amount (value) column is often easier to filter, pivot and append across periods and branches. It also aligns with how multi-period TBs are stored in a consolidation fact: one row per ledger × period × measure. Knowing when to unpivot TB measures, and when to keep a couple of measure columns, is a modelling judgement.

Core notes

The typical TB layouts

Four-column signed layout (after cleaning):

Ledger Opening Debit Credit Closing
Trade Receivables 45,60,000 1,82,40,000 1,75,10,000 52,90,000
Trade Payables −38,20,000 1,40,00,000 1,46,50,000 −44,70,000

Tally eight-column layout: Opening Dr, Opening Cr, Transactions Dr, Transactions Cr, Closing Dr, Closing Cr (six amount columns) — with balances in either Dr or Cr column.

Unpivoting measures

Long = Table.UnpivotOtherColumns(TB, {"Entity", "Period", "Ledger"}, "Measure", "Amount")

Result: one row per ledger per measure — Measure ∈ {Opening, Debit, Credit, Closing}. A pivot or matrix can then show any measure combination, and filters like Measure = "Closing" give a closing TB.

For the eight-column layout, unpivot first and then split the attribute into two columns:

Long  = Table.UnpivotOtherColumns(TB, {"Ledger"}, "Attr", "Amount"),
Split = Table.SplitColumn(Long, "Attr", Splitter.SplitTextByEachDelimiter({" "}, QuoteStyle.None, true), {"Measure", "Side"}),
// "Opening Dr" → Measure "Opening", Side "Dr"; "Transactions Cr" → "Transactions", "Cr"
Signed = Table.AddColumn(Split, "Signed", each if [Side] = "Cr" then -[Amount] else [Amount], type number),
Net    = Table.Group(Signed, {"Ledger", "Measure"}, {{"Amount", each List.Sum([Signed]), type number}})

startAtEnd = true splits at the last space, so multi-word measures ("Closing Balance Dr") still split correctly. The Group By collapses Dr and Cr of the same balance into one signed amount for Opening and Closing; for Transactions you may prefer to keep Side to retain gross Dr and Cr movement.

Roll-forward check on the long table

With the long table from the four-column layout (Long in the first snippet, Measure ∈ {Opening, Debit, Credit, Closing}), the check is a pivot back to columns or a grouped calculation. For the eight-column layout, first rename Transactions/Dr and Transactions/Cr to Debit and Credit and keep them gross.

\[ \text{Opening} + \text{Debit} - \text{Credit} = \text{Closing} \]

where Debit and Credit are gross positive movements and balances are signed Dr-positive. In M:

Pivoted = Table.Pivot(Long, List.Distinct(Long[Measure]), "Measure", "Amount", List.Sum),
Check   = Table.AddColumn(Pivoted, "Diff", each ([Opening] ?? 0) + ([Debit] ?? 0) - ([Credit] ?? 0) - ([Closing] ?? 0), type number),
Breaks  = Table.SelectRows(Check, each Number.Abs([Diff]) > 1)

Any row in Breaks indicates a parsing error, an omitted column, a sign error or a genuine data issue (e.g. Tally "difference in opening balances").

When to unpivot measures and when not to

Use Shape
Multi-period TB store; flexible reporting of any measure; appending branches and periods Long with Measure column
Roll-forward checks, movement analysis with Dr and Cr side by side Wide on measures (Opening, Debit, Credit, Closing as columns), long on periods
Power BI fact for P&L/BS reporting Usually only closing (or movement) amount per ledger per month; opening is derived from prior closing
DAX measures needing Dr and Cr together Keep Debit and Credit columns, or filter by Measure in measures

In a star schema, mixing stock (balances — opening/closing) and flow (period debits/credits) measures in a single Amount column is risky: summing Amount across Measure values is meaningless. If you store them long, every DAX measure must filter Measure, and visuals must never total across it. Many teams store only signed movements (Debit − Credit per month) in the fact and compute balances as cumulative sums — the cleanest approach for monthly TBs.

Illustration

Branch TB for March 2026 with 3 ledgers and 4 measures → 12 long rows. Trade Receivables: Opening 45,60,000 + Debit 1,82,40,000 − Credit 1,75,10,000 = 52,90,000 = Closing ✓. Trade Payables (credit balance, signed negative): −38,20,000 + 1,40,00,000 − 1,46,50,000 = −44,70,000 = Closing ✓. A pivot of the long table on Measure reproduces the original columns, proving the unpivot lossless.

Edge cases & judgement calls

  • Balances in both Dr and Cr columns for the same ledger (rare but possible in summarised group rows) — the signed Group By nets them; flag rows where both are non-zero.
  • Closing in a single column with Dr/Cr suffix — parse first (Topic 2 c07), then unpivot.
  • YTD vs period movement: some exports give YTD debits/credits — label the Measure accordingly ("YTD Debit") and do not add YTD figures across months.
  • Nulls dropped by unpivot: a ledger with no movement has null Debit/Credit — its rows disappear, which can make a pivot show blanks rather than zeros; replace with 0 if completeness of the grid matters.
  • Opening of month = closing of previous month across files — check this continuity when appending monthly TBs (gaps reveal back-dated entries after a previous month's export).

Key takeaways

  • TB measure columns can be unpivoted into a Measure/Amount pair; split "Opening Dr"-style headers into Measure and Side at the last space.
  • Convert Dr/Cr sides into signed amounts and group to one figure per ledger per measure where appropriate.
  • Use the long table to run roll-forward checks: Opening + Debit − Credit = Closing.
  • Never sum Amount across stock and flow measures; filter by Measure in every calculation.
  • For reporting facts, storing signed monthly movements and deriving balances is often cleaner.

Practice Questions

Q1. Unpivot and split [L1]

A Tally TB has columns Ledger, Opening Dr, Opening Cr, Transactions Dr, Transactions Cr, Closing Dr, Closing Cr. Write the M to produce Ledger, Measure, Side, Amount, and state how many rows result for 600 ledgers if 40% of the cells are blank.

Q2. Roll-forward check [L2]

Using the long table from Q1, write M that produces, per ledger, signed Opening and Closing, gross Debit and Credit, and a Diff column for the roll-forward test, listing only breaks above ₹1.

💡 Hint: Sign the balances but keep the movements gross before pivoting.

Q3. Choose the fact design [L2]

For a Power BI P&L and balance-sheet report built from 12 monthly TBs of 5 branches, compare (a) a long fact with Measure ∈ {Opening, Debit, Credit, Closing} and (b) a fact of signed monthly movements only. Discuss DAX complexity, risk of wrong totals and data volume.

Q4. Continuity across months [L3]

You append 12 monthly branch TBs (each with Opening and Closing). Design a check that confirms each ledger's April opening equals the prior March closing and each month's opening equals the previous month's closing, and explain what a break might indicate in an Indian audit context.
