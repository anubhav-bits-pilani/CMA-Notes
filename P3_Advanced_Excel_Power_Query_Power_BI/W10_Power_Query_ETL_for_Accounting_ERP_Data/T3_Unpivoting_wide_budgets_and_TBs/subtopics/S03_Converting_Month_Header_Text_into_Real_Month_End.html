Converting Month Header Text into Real Month-End Dates

Scope: Turning month header text ("Apr-25", "Apr 2025") into real month-end dates

Why it matters

After an unpivot, the month sits in a text column with values like "Apr-25", "Apr 2025", "April-2025", "2025-04", "M01" or "P01 FY26". Text months sort alphabetically (Apr, Aug, Dec, Feb …), cannot relate to a Calendar dimension, cannot drive YTD or prior-year measures, and cannot be compared with GL actual dates. Converting them into a real date — conventionally the month-end date for monthly budget and balance data — makes the budget fact joinable to the Calendar (Week 11) and comparable to actuals aggregated to month-end.

Core notes

Why month-end

For balances and period totals, month-end is the natural representative date: a TB "as at 30-Apr-2025", a budget "for the month ended 30-Apr-2025". It also matches Date.EndOfMonth applied to daily GL postings, so actuals and budget meet on the same key. Some teams prefer month-start (1-Apr-2025); either works if both facts use the same convention and the Calendar has every date. Choose one, document it, and use it everywhere.

Core technique: parse, then end-of-month

Text like "Apr-25" lacks a day, so prepend one and parse with an explicit format and culture (c02):

Dated = Table.TransformColumns(Long, {{"Month", each
          Date.EndOfMonth(Date.FromText("01-" & _, [Format="dd-MMM-yy", Culture="en-IN"])), type date}})

"01-" & "Apr-25" → "01-Apr-25" → 1 April 2025 → Date.EndOfMonth → 30 April 2025.

Format tokens (.NET): MMM abbreviated month name, MMMM full name, MM two-digit month, yy two-digit year, yyyy four-digit year, dd day. The culture supplies month names ("Apr"), so use an English culture ("en-IN" or "en-GB"). With two-digit years, .NET's cutoff maps "25" to 2025; it is safe for budgets but state the assumption.

Header variants and their formats

Header text Prefix Format string Result (month-end)
"Apr-25" "01-" dd-MMM-yy 30-Apr-2025
"Apr 2025" "01 " dd MMM yyyy 30-Apr-2025
"April-2025" "01-" dd-MMMM-yyyy 30-Apr-2025
"2025-04" — yyyy-MM (append "-01" and use yyyy-MM-dd) 30-Apr-2025
"04/2025" "01/" dd/MM/yyyy 30-Apr-2025
"Apr'25" replace "'" with "-" first dd-MMM-yy 30-Apr-2025
"Sept-25" replace "Sept" with "Sep" (culture abbreviations are three letters) dd-MMM-yy 30-Sep-2025

Fiscal period labels

Headers like "P01", "M01" or "Month 1" carry fiscal positions, not calendar months. Convert with the FY start (April for Indian companies) and the FY from a parameter or file name:

\[ \text{Date} = \text{EndOfMonth}\big(\text{AddMonths}(\text{Date}(Y_{\text{start}}, 4, 1),\ p - 1)\big) \]

where \(p\) is the period number (1–12) and \(Y_{\text{start}}\) the calendar year in which the FY starts (2025 for FY2025-26).

Dated = Table.AddColumn(Long, "Date", each
          Date.EndOfMonth(Date.AddMonths(#date(pFYStartYear, 4, 1), Number.From(Text.Select([Period], {"0".."9"})) - 1)),
          type date)

SAP special periods 13–16 have no calendar month — map them to the FY end date (31 March) and keep a Period column to distinguish them.

Tolerant parsing for mixed headers

When a template might use "Apr-25" one year and "Apr 2025" the next, try formats in sequence:

fxMonthEnd = (h as text) as nullable date =>
    let x = Text.Trim(Text.Replace(Text.Replace(h, "'", "-"), "Sept", "Sep")),
        d = try Date.FromText("01-" & x, [Format="dd-MMM-yy", Culture="en-IN"])
            otherwise try Date.FromText("01 " & x, [Format="dd MMM yyyy", Culture="en-IN"])
            otherwise try Date.FromText("01-" & x, [Format="dd-MMMM-yyyy", Culture="en-IN"])
            otherwise null
    in  if d = null then null else Date.EndOfMonth(d)

Use it in the transform and route nulls to an exceptions list — a header that does not parse is either a total/remark column that slipped through or a template change.

Deriving FY attributes

Once Month is a date, FY label, fiscal month and quarter follow from Topic 6 formulas (FY end year = year + 1 if month ≥ 4). Ideally those attributes live in the Calendar dimension, not in each fact (Week 11).

Illustration

Unpivoted rows with Month = "Jan-26", "Feb-26", "Mar-26". After conversion: 31-Jan-2026, 28-Feb-2026, 31-Mar-2026 — all in FY2025-26, fiscal months 10–12. Sorted by Date the order is Apr → Mar; sorted as text it was Apr, Aug, Dec, Feb, Jan, Jul, Jun, Mar, May, Nov, Oct, Sep.

Edge cases & judgement calls

  • Excel headers that are real dates: if the header cell contained a date formatted "Apr-25", promotion with PromoteAllScalars=true turns it into text like "01-04-2025 00:00:00" or a serial number depending on source — inspect the actual header text before choosing a format.
  • Leap years: Date.EndOfMonth handles February (29-Feb-2028).
  • Locale mismatch on month names: a "fr-FR" culture expects "avr." — always pass an English culture.
  • Two-digit-year ambiguity for historical data (e.g. "Mar-99") — use four-digit headers in templates.
  • Week or quarter headers ("Q1 FY26", "W14") need their own mapping to dates (quarter-end, week-end).
  • Keep the original label temporarily for audit ("MonthLabel") until the conversion is validated, then remove it.

Key takeaways

  • Convert month header text to a real date; month-end is the usual convention for budgets and balances.
  • Prepend a day, parse with an explicit Format and English Culture, then Date.EndOfMonth.
  • Fiscal period labels (P01–P12) need an FY start-year parameter and Date.AddMonths from 1 April.
  • Use tolerant multi-format parsing and log headers that do not parse.
  • Real dates fix sort order and enable Calendar relationships and time intelligence.

Practice Questions

Q1. Write the conversion [L1]

Write the transformation that turns each of these Month values into a month-end date: "Apr 2025", "May 2025", "Feb 2028". State the result for "Feb 2028".

Q2. Fiscal periods [L2]

A budget for FY2026-27 uses headers "P01" … "P12" plus "P13" for audit adjustments. Write M that converts them into month-end dates using a parameter pFYStartYear, mapping P13 to the FY end date, and keep a Period column.

💡 Hint: Period 1 is April of the start year; add months from there.

Q3. Messy headers [L2]

A template's headers are: "Apr'25", "May-25", "Jun 25", "Sept-25", "FY Total", "Remarks". Write a function that converts every month variant to a month-end date and returns null for the others, and describe the exception handling for the nulls.

Q4. Start vs end convention [L2]

Your GL actuals are aggregated to month-start dates by a colleague while the budget uses month-end. Describe what happens in a Power BI budget-vs-actual visual and two ways to align them.

Q5. Header that is a date [L3]

An Excel budget template's month headers are real Excel dates (1-Apr-2025 formatted as "Apr-25"). After Table.PromoteHeaders, the Attribute values after unpivot look different from what you see in Excel. Explain why, how you would inspect the true values, and how your conversion changes.
