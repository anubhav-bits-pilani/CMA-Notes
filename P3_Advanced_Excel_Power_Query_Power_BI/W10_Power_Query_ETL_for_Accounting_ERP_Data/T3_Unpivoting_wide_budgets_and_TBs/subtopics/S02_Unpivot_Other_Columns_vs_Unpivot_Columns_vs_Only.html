Subtopic note

Unpivot Other Columns vs Unpivot Columns vs Only Selected

Scope: Unpivot Other Columns vs Unpivot Columns vs Unpivot Only Selected Columns, and which survives new months

Why it matters

Power Query offers three unpivot commands that produce identical output on the day you build the query and very different output next year. A budget template that gains a column (a new FY, an extra "Q4 revised" column, a renamed month) will either flow through automatically, be silently left out, or break the refresh — depending on which command generated the step. Since budget loads run every month and rolling forecasts add a new month each cycle, picking the refresh-safe variant is a design decision, not a UI preference.

Core notes

The three commands and the M they generate

Select columns in the editor, then Transform → Unpivot Columns (drop-down):

UI command What you select M generated Columns unpivoted at refresh
Unpivot Other Columns The identifier columns (Account, Department) Table.UnpivotOtherColumns(t, {"Account","Department"}, "Attribute", "Value") Every column except the listed identifiers — including any new ones
Unpivot Columns The value columns (months) Table.UnpivotOtherColumns(t, {"Account","Department"}, "Attribute", "Value") — the UI records the complement of your selection Same as above — new columns are included
Unpivot Only Selected Columns The value columns Table.Unpivot(t, {"Apr-25","May-25", …,"Mar-26"}, "Attribute", "Value") Only the listed columns — new ones are ignored

The important subtlety: the UI's plain Unpivot Columns command, despite selecting the month columns, writes Table.UnpivotOtherColumns with the columns you did not select as the fixed list. So both "Unpivot Other Columns" and "Unpivot Columns" are, in M, the same function with the identifier list hard-coded. Only Unpivot Only Selected Columns writes Table.Unpivot with a hard-coded list of value columns.

(The behaviour is documented by Microsoft; verify in your version by reading the formula bar after clicking — a habit worth keeping.)

Which survives new months

The question is: what is hard-coded, identifiers or values?

  • Identifiers fixed, values dynamic (Table.UnpivotOtherColumns): new month columns are unpivoted automatically. Identifier columns rarely change, so this is refresh-safe. Danger: any new non-month column (an FY Total, a "Remarks" column, a "Prior Year Actual" column) is also unpivoted and mixed into Amount.
  • Values fixed (Table.Unpivot): new months stay as columns — next year's budget is silently missing from the long table, and if April's name changes ("Apr-26"), the step errors with "column not found". Useful only when you deliberately want a fixed subset.

So the refresh-safe pattern is Table.UnpivotOtherColumns plus a guard against non-month columns:

// remove known derived columns tolerantly before the unpivot
NoTotals = Table.RemoveColumns(t, {"FY Total", "H1 Total", "H2 Total", "Remarks"}, MissingField.Ignore),
Long     = Table.UnpivotOtherColumns(NoTotals, {"Account", "Department"}, "Month", "Amount")

Even more robust — select value columns by pattern rather than by exclusion:

MonthCols = List.Select(Table.ColumnNames(t), each
              (try Date.FromText("01-" & _, [Format="dd-MMM-yy", Culture="en-IN"]) otherwise null) <> null),
IdCols    = {"Account", "Department"},
Kept      = Table.SelectColumns(t, IdCols & MonthCols),
Long      = Table.Unpivot(Kept, MonthCols, "Month", "Amount")

Here Table.Unpivot is used with a dynamic list: any header that parses as a month is unpivoted; totals, remarks and anything else that does not parse is excluded automatically. This combines the strengths of both.

Output columns

The unpivot produces two new columns: Attribute (the former header text) and Value (the cell). Rename them in the same function call ("Month", "Amount") instead of adding a rename step. Attribute is text — convert it to a real month-end date next (s03). Value takes the type of the source cells; if the source columns were any, type Amount explicitly.

Nulls

Both functions drop rows where the value is null (c06). Zeros are kept. If "no budget" must appear as an explicit zero row, replace nulls with 0 before unpivoting — but only in the month columns.

Illustration

FY2025-26 budget: identifiers Account, Department; months Apr-25 … Mar-26; FY Total. Next year the template gains Apr-26 … Mar-27 and a "Revised Mar-26" column.

Step FY2025-26 result FY2026-27 result
Table.Unpivot with 12 hard-coded months (Only Selected) Correct FY27 months ignored; Revised column ignored; or error if a listed month was removed
Table.UnpivotOtherColumns on Account, Department FY Total double counts FY Total and Revised Mar-26 unpivoted into Amount; "Revised Mar-26" fails date conversion
Remove totals (MissingField.Ignore) + UnpivotOtherColumns Correct Correct for months; Revised column still needs a rule
Dynamic month list by parse + Table.Unpivot Correct Correct; Revised column excluded and can be logged

Edge cases & judgement calls

  • Identifier columns change: if the template adds "Cost Centre" as a new identifier, UnpivotOtherColumns unpivots it as if it were a month. Validate that Attribute values all parse as months and log the rest.
  • Duplicate headers ("Apr-25" appearing twice after a copy-paste) — Power Query renames the second to "Apr-25_1" on promotion; the dynamic parse rejects it and you can flag it.
  • Mixed types in month columns ("TBD", "-") — unpivot works but Amount becomes mixed; type with try and log failures.
  • Large inputs: unpivot does not fold on files; on SQL sources Table.UnpivotOtherColumns can fold to UNPIVOT on SQL Server, but most budget inputs are Excel.
  • Do not unpivot then filter out totals by name as the only defence — it works but hides the total inside the long table until the filter; removing before unpivot is clearer and faster.

Key takeaways

  • "Unpivot Other Columns" and "Unpivot Columns" both generate Table.UnpivotOtherColumns with fixed identifiers — new months flow in.
  • "Unpivot Only Selected Columns" generates Table.Unpivot with fixed month names — new months are silently excluded.
  • UnpivotOtherColumns also sweeps in totals and remarks; remove them tolerantly first.
  • The most robust design builds the month list dynamically (by parsing headers) and unpivots exactly those.
  • Always read the formula bar after a UI unpivot to see what was hard-coded.

Practice Questions

Q1. Predict the M [L1]

A table has columns Account, Dept, Apr-25 … Mar-26, FY Total. Write the M generated when you (a) select Account and Dept and click Unpivot Other Columns; (b) select the 12 months and click Unpivot Columns; (c) select the 12 months and click Unpivot Only Selected Columns.

Q2. Next year's file [L2]

Your FY2025-26 query uses (c) from Q1. In FY2026-27 the template has Apr-26 … Mar-27 and the same FY Total. Describe exactly what the refresh does, whether it errors, and what the budget-vs-actual report would show.

💡 Hint: Check which listed columns still exist in the new file.

Q3. Build the dynamic unpivot [L2]

Write M that unpivots every column whose header matches the pattern "Mmm-yy" (e.g. "Apr-25"), keeps Account, Department and Cost Centre as identifiers, and creates a separate exceptions query listing any other non-identifier headers found in the file.

Q4. Rolling forecast [L3]

A rolling 18-month forecast file adds one month and drops one each cycle, and sometimes carries a "Commentary" column. Design the unpivot step and a validation check so the load never needs editing, and explain why neither plain UI command is sufficient on its own.

Q5. Control check [L2]

Write a validation step that compares the sum of month columns in the wide table with the sum of Amount in the long table and the FY Total column, and raises an error if they disagree by more than ₹1.
