Subtopic note

Target Fact Schema: Date, Account, Department, Scenario, Amount

Scope: Target schema: Date, Account, Department, Scenario (Actual/Budget), Amount

Why it matters

Every unpivot needs a destination. Defining the target schema before building transformations keeps all sources — the wide budget, the monthly TBs, the forecast — converging on the same five columns, so they can be appended into one plan-vs-actual fact or modelled as two facts sharing the same dimensions. This is the schema that the Week 11 star schema and Weeks 17–20 budget-vs-actual and rolling-forecast work assume. A stable, documented schema also makes the Saturday assessment's deliverable concrete: a clean fact table and a clean CoA dimension.

Core notes

The columns

Column Type Definition Source examples Rules
Date type date Month-end date of the period Budget header "Apr-25" → 30-Apr-2025; GL posting date → Date.EndOfMonth Always month-end (or always month-start) — one convention
Account type text GL account code at the reporting grain "610100" from "610100 - Salaries" Text, trimmed, matches CoA dimension key exactly
Department type text Department / cost centre code Header block "Sales" mapped to "D100" Codes, not names, where a master exists; "UNALLOC" for unassigned
Scenario type text Actual, Budget, Forecast (versioned if needed: "Budget FY26 v2", "RF Sep-25") Added column for budget and forecast loads Controlled list; never null
Amount type number / Currency.Type Signed amount, one sign convention Unpivoted value; GL net Dr − Cr Dr positive (expenses/assets positive, income negative) or a documented presentation convention

Optional columns commonly added: Entity (company/branch, for multi-entity groups), Currency, Version (budget iteration), Source (file name for lineage), LoadDate.

Dimensions that go with it

The fact holds keys and numbers; descriptions and hierarchies live in dimensions:

  • Calendar (Date): FY label, fiscal month, fiscal quarter, month label — Week 11.
  • Chart of Accounts (Account): name, Schedule III line, P&L/BS group, cost behaviour (fixed/variable), MIS hierarchy.
  • Department (Department): name, function, business unit, region.
  • Scenario (Scenario): sort order, actual/plan flag.

The Saturday assessment asks you to produce this fact from the multi-tab budget and a clean CoA dimension from the master — with every Account in the fact present in the CoA (no orphan keys).

Conforming sources to the schema

Budget (wide workbook, one tab per department):

  1. Read each tab (or each department block).
  2. Skip headers by condition, promote, remove totals.
  3. Unpivot months (s02), convert headers to month-end dates (s03).
  4. Derive Department from the tab name or header block (s04).
  5. Split "610100 - Salaries" into Account code (Topic 2 c04).
  6. Table.AddColumn(t, "Scenario", each "Budget", type text) (c05).
  7. Select and order the five columns; type them.

Actuals (GL lines or monthly TBs):

  1. Clean (Topic 2), compute signed Amount.
  2. Date.EndOfMonth([PostingDate]) to bring to month grain; Group By Date, Account, Department summing Amount.
  3. Add Scenario = "Actual".
  4. Select the five columns in the same order and types.

Then either Table.Combine({Actuals, Budget}) into a single Plan-Actual fact, or load as two facts. One combined fact with a Scenario column makes variance measures simple (CALCULATE(SUM(Fact[Amount]), Fact[Scenario] = "Budget")); two facts are preferable when grains differ (see the edge cases below and the topic-level item on grain alignment).

Selecting and ordering columns robustly

Schema = {"Date", "Account", "Department", "Scenario", "Amount"},
Final  = Table.TransformColumnTypes(
           Table.SelectColumns(Conformed, Schema, MissingField.UseNull),
           {{"Date", type date}, {"Account", type text}, {"Department", type text},
            {"Scenario", type text}, {"Amount", Currency.Type}})

Table.Combine aligns columns by name, not position; columns present in one table only become null in the other. Consistent names and types are what make appends safe.

Quality checks on the fact

  • Completeness: sum of Amount by Scenario and FY equals source control totals (budget FY Total, TB net).
  • Orphans: Accounts or Departments in the fact not present in dimensions (LeftAnti merge against the CoA).
  • Duplicates at grain: Group By Date, Account, Department, Scenario with Count Rows > 1 (expected for line-level actuals only before grouping).
  • Dates: all month-ends, within the FY range.
  • Nulls: no null keys or Scenario.

Illustration

Budget tab "Sales" row "610100 - Salaries" with Apr-25 = 12,00,000 becomes (30-Apr-2025, 610100, D100, Budget, 1200000). GL postings to 610100/D100 in April 2025 totalling ₹12,40,000 become (30-Apr-2025, 610100, D100, Actual, 1240000). Appended, a matrix by Scenario shows Actual 12,40,000 vs Budget 12,00,000 and a variance of 40,000 adverse.

Edge cases & judgement calls

  • Sign convention for budgets: budget templates usually show revenue positive; actuals with Dr positive show revenue negative. Flip the budget revenue sign during conforming (based on the CoA account type), or flip both for presentation in DAX — never leave them inconsistent.
  • Budget at a higher level than actuals (budget by account group, actuals by ledger) — map actuals up to the budget grain or allocate budget down; document the choice.
  • Multiple budget versions: include Version or encode it in Scenario; avoid overwriting the original budget when a revision arrives.
  • Departments in budget but not in the cost-centre master (new departments) — add to the dimension or map, do not drop.
  • Foreign-currency entities: include Currency and convert at budget rates vs actual rates explicitly.
  • Statistical accounts (headcount, sq ft) in the budget: keep them in a separate fact or flag them so they are not summed with rupees.

Key takeaways

  • Fix the target schema — Date, Account, Department, Scenario, Amount — before building transformations.
  • Store month-end dates, text keys matching the dimensions, a controlled Scenario list and signed amounts.
  • Conform every source to the same names, order and types; Table.Combine aligns by name.
  • Keep descriptions and hierarchies in dimensions (Calendar, CoA, Department, Scenario).
  • Validate completeness, orphan keys, duplicates at grain and sign conventions before loading.

Practice Questions

Q1. Conform two sources [L2]

You have (a) a wide budget with "Account Name - Code" labels (e.g. "Salaries - 610100"), department in the tab name and months "Apr 2025" … "Mar 2026"; (b) GL actual line items with PostingDate, GLAccount, CostCentre, Debit, Credit. Write the conforming steps for each to reach the five-column schema, including the sign treatment.

Q2. Orphan check [L1]

Write the M for a query listing Accounts in the combined fact that are not in the CoA dimension, with their total Amount by Scenario.

💡 Hint: An anti-join returns rows on one side with no match on the other.

Q3. Grain mismatch [L2]

The budget is prepared by account group (e.g. "Travel" = accounts 620100–620900) and department, while actuals are by ledger account. Propose two designs that allow budget-vs-actual reporting and state the effect on the fact schema.

Q4. Sign policy [L3]

Draft a sign policy for the plan-actual fact covering revenue, expense, asset and liability accounts in both scenarios, where budget templates show all amounts as positive numbers. Explain where in Power Query the flip happens and how it is driven by the CoA.

Q5. Interview: one fact or two? [L2]

An interviewer asks whether you would load actuals and budget as one fact with a Scenario column or as two separate facts. Give a structured answer covering grain, DAX simplicity, refresh and future forecasts.
