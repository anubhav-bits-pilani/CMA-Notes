Key concept

Table.Pivot with a Dynamic Value List and List.Sum

Concept: Table.Pivot(t, List.Distinct(t[Month]), "Month", "Amount", List.Sum)

Statement

Table.Pivot(table as table, pivotValues as list, attributeColumn as text, valueColumn as text, optional aggregationFunction as function) as table:

  • creates one new column for each value in pivotValues (here every distinct Month in the data);
  • groups rows by all other columns (row keys);
  • fills each new column with the valueColumn values for that key and attribute, combined using aggregationFunction — List.Sum adds duplicates.

Without the aggregation function ("Don't Aggregate"), more than one value per key and attribute raises an error in that cell.

Explanation

Dynamic list: the UI writes a hard-coded list ({"Apr-25","May-25",...}), which ignores new months and errors on removed ones in downstream references. List.Distinct(t[Month]) creates a column for whatever months exist. Two consequences:

  1. Order is order of first appearance; sort the list (List.Sort) or sort the table first if column order matters.
  2. Column names vary by refresh, so downstream steps that reference a specific month column break. Keep pivoted outputs at the end of the pipeline (presentation or check tables).

Column names must be text: if Month is a date, convert to a label first (Date.ToText(_, [Format="MMM-yy", Culture="en-IN"])) or pass List.Transform(List.Distinct(t[Month]), Text.From) and convert the column likewise.

Row keys: every column other than Month and Amount becomes part of the key. An unexpected extra column (e.g. a Source file name or a line ID) prevents rows from collapsing and produces a sparse wide table with one non-null per row. Select only the intended key columns before pivoting.

Aggregation choice:

  • List.Sum for amounts from detail rows.
  • List.Count for counts (note it counts nulls too; use each List.NonNullCount(_) to skip them).
  • List.Max/List.Min for dates.
  • No function to assert uniqueness — errors flag duplicates.

Nulls: keys with no row for a month get null in that column — not zero. Replace with 0 if the output feeds formulas.

Illustration

Long table (Account, Month, Amount): (610100, Apr-25, 7,00,000), (610100, Apr-25, 5,00,000), (610100, May-25, 12,00,000), (620300, May-25, 1,20,000).

Table.Pivot(t, List.Distinct(t[Month]), "Month", "Amount", List.Sum):

Account Apr-25 May-25
610100 12,00,000 12,00,000
620300 null 1,20,000

Without List.Sum, the 610100/Apr-25 cell errors because two values exist. With a hard-coded {"Apr-25"} list, the May column would be missing entirely.
