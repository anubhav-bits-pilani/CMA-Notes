Key concept

Adding a Typed Scenario Column Before Appending to Actuals

Concept: Table.AddColumn(t, "Scenario", each "Budget", type text) before appending to actuals

Statement

Table.AddColumn(table, newColumnName, columnGenerator, optional columnType) adds a column whose value for each row is produced by columnGenerator. With each "Budget" the generator ignores the row and returns the constant text "Budget"; type text ascribes the column type. Applied to the budget table (and each "Actual" to the actuals table) before Table.Combine, it labels every row's scenario so that the appended fact can distinguish plan from actual.

Explanation

Why before appending: Table.Combine({Actuals, Budget}) stacks rows and aligns columns by name. Once combined, nothing in a row tells you which source it came from unless a column says so. Adding Scenario in each source query is the only reliable way; trying to infer it afterwards (e.g. from a date range) is fragile.

Why the type matters: without type text, the column is any (ABC/123 icon). In the Data Model it loads as text in most cases, but any columns can cause problems: relationships to a Scenario dimension may fail type checks, and Table.Combine of a typed and an untyped Scenario column produces any. Always ascribe.

Scenario naming and versioning: use a controlled vocabulary: "Actual", "Budget", "Forecast". For multiple versions, either a separate Version column ("FY26 v1", "FY26 v2 revised Oct-25") or a composite Scenario ("Budget FY26 v2", "RF Sep-25"). A parameter can supply the label for forecast loads: each pScenario.

Alignment checklist before Table.Combine:

  • identical column names (case-sensitive: "Amount" ≠ "amount");
  • identical types (Date as date in both, Account as text in both);
  • the same grain (month-end, account, department) — group actuals to month first;
  • the same sign convention;
  • no extra columns in one table only (they become null in the other) unless intended.
BudgetTagged  = Table.AddColumn(BudgetLong, "Scenario", each "Budget", type text),
ActualTagged  = Table.AddColumn(ActualMonthly, "Scenario", each "Actual", type text),
Schema        = {"Date","Account","Department","Scenario","Amount"},
PlanActual    = Table.Combine({Table.SelectColumns(ActualTagged, Schema), Table.SelectColumns(BudgetTagged, Schema)})

Illustration

Budget long table: 5,040 rows, total ₹46.8 crore. Actuals grouped to month: 4,610 rows, total ₹44.2 crore. After tagging and combining: 9,650 rows. Group By Scenario: Actual ₹44.2 crore (4,610 rows), Budget ₹46.8 crore (5,040 rows) — the control check that both sources arrived intact. Without the Scenario column, the combined total of ₹91.0 crore would be meaningless.

Practice Questions

Q1. Fix the append [L1]

A combined fact has 9,650 rows but Scenario shows null for 4,610 rows and the Amount column is type any. Identify the likely mistakes in the two source queries and correct them.

Q2. Forecast versions [L2]

Design the M and the parameter(s) for loading monthly rolling-forecast files (RF Jun-25, RF Sep-25, RF Dec-25) into the same plan-actual fact without overwriting earlier versions, and explain how a report would select the latest forecast.

💡 Hint: Derive the version label from the file name or a parameter, and keep it as its own column.
