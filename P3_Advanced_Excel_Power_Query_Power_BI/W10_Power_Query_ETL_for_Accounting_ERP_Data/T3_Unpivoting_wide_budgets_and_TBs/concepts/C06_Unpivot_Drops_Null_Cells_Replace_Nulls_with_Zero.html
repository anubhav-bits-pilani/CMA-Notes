Key concept

Unpivot Drops Null Cells: Replace Nulls with Zero When Needed

Concept: Unpivot drops null cells, so replace nulls with 0 first if zero rows must stay

Statement

Table.UnpivotOtherColumns and Table.Unpivot emit an output row only for cells whose value is not null. A wide table with \(r\) rows and \(k\) value columns therefore yields

\[ N_{\text{out}} = r \times k - n_{\text{null}} \]

rows, where \(n_{\text{null}}\) is the number of null value cells. Zeros (0) and empty strings ("") are not null and are kept. If every account-department-month combination must appear in the long table (including those with no budget), replace nulls with 0 in the value columns before unpivoting:

MonthCols = List.RemoveItems(Table.ColumnNames(t), {"Account","Department"}),
Zeroed    = Table.ReplaceValue(t, null, 0, Replacer.ReplaceValue, MonthCols),
Long      = Table.UnpivotOtherColumns(Zeroed, {"Account","Department"}, "Month", "Amount")

Explanation

When dropping nulls is fine (usually): for a fact table, a missing row and a zero row give the same SUM. Dropping nulls keeps the fact smaller and is the default for good reason. Most budget-vs-actual reporting works without zero rows.

When zero rows must stay:

  • Completeness checks and row-count controls: if the control expects \(r \times k\) rows, nulls make it fail.
  • Distinguishing "budgeted zero" from "not budgeted": if a blank means "department did not submit", replacing with 0 hides the gap. In that case, keep nulls dropped and run a separate completeness check, or replace with 0 only after confirming submission.
  • Averages and counts: AVERAGE over months, or "number of months with budget", differ when zero rows are absent.
  • Downstream pivots and templates that expect every month column to exist for every account.
  • Rolling calculations in Excel outputs where missing rows misalign row-by-row formulas.

Replace only the value columns: replacing nulls in identifier columns (Department null → 0) would corrupt keys. Build the column list dynamically (as above), excluding identifiers.

Empty strings and text: Excel cells with "" or "-" are not null; they survive unpivot as text in Amount and then fail typing. Convert "" and "-" to null (or 0) according to the rule before unpivoting.

After unpivot, in DAX: an alternative to zero rows is handling blanks in measures (COALESCE(SUM(...), 0)) and using a Calendar dimension to show every month — often the better model design (Week 11).

Illustration

Budget: 3 accounts × 12 months = 36 cells; 7 are null (no budget for Travel in 7 months).

Approach Long rows Sum Months with budget for Travel (COUNT)
Unpivot directly 29 ₹18,60,000 5
Replace nulls with 0 then unpivot 36 ₹18,60,000 12 (counts zero rows)

Totals agree; counts and completeness checks differ. If the FP&A team computes "average monthly travel budget", the first gives ₹X / 5 (where X is Travel's total) and the second ₹X / 12 — a policy decision, not a technical one.

Practice Questions

Q1. Row count check [L1]

A wide budget has 180 rows, identifiers Account and Department, 12 month columns; 214 month cells are null and 31 contain 0. How many rows does a direct unpivot produce, and how many after replacing nulls with 0?

Q2. Policy decision [L2]

Departments leave cells blank when they have not yet submitted, and type 0 when they deliberately budget nothing. Design the Power Query treatment that preserves this distinction and produces a "submission completeness" check per department.

💡 Hint: Decide the treatment of blanks before the unpivot and keep a flag rather than a zero.

Q3. Dynamic replace [L2]

Write M that replaces nulls, empty strings and "-" with 0 only in columns whose headers parse as months, leaving identifier and remark columns untouched, then unpivots.
