Key concept

Month Label to Month-End Date with Date.FromText and Format

Concept: Table.TransformColumns(t, {{"Month", each Date.EndOfMonth(Date.FromText("01-" & _, [Format="dd-MMM-yy", Culture="en-IN"])), type date}})

Statement

For each text value _ in the Month column (e.g. "Apr-25"):

  1. "01-" & _ builds a full date string "01-Apr-25".
  2. Date.FromText(text, [Format="dd-MMM-yy", Culture="en-IN"]) parses it exactly according to the format: dd two-digit day, MMM abbreviated month name in the given culture, yy two-digit year — giving 1 April 2025.
  3. Date.EndOfMonth(date) returns the last day of that month — 30 April 2025.
  4. type date ascribes the column type so the result loads as a date, not any.

Table.TransformColumns replaces the Month column in place.

Explanation

Why a format, not a plain type change? Table.TransformColumnTypes on "Apr-25" with a culture may parse it, but interpretation of partial dates (month-year without day) is culture- and version-dependent — "Apr-25" could be read as 25 April of the current year. A Format string removes ambiguity: the parser accepts only the stated pattern and errors on anything else, which is what you want for validation.

Culture role: with a Format, the culture still determines the month names recognised for MMM. "en-IN" and "en-GB" accept "Apr", "Sep"; note "Sept" (four letters) is not an abbreviation in these cultures — normalise first.

Two-digit years: yy maps "25" to 2025 under the default two-digit-year cutoff (years 00–49 → 2000s in .NET's default calendar settings; exact cutoff behaviour may differ by environment), fine for budgets. Prefer four-digit headers (MMM-yyyy) in templates you control.

Errors: any value that does not match ("FY Total", "Remarks", "Apr 25") raises a cell error. Either remove such columns before the unpivot (c01) or wrap in try ... otherwise null and log nulls. A loud error is often better than a silent null in a budget load.

Month-end vs month-start: drop Date.EndOfMonth if your convention is month-start. The Calendar dimension must contain whichever dates you use; and GL actuals must be brought to the same convention (Date.EndOfMonth([PostingDate])).

Variants of the pattern:

// "Apr 2025"
each Date.EndOfMonth(Date.FromText("01 " & _, [Format="dd MMM yyyy", Culture="en-IN"]))
// "2025-04"
each Date.EndOfMonth(Date.FromText(_ & "-01", [Format="yyyy-MM-dd"]))
// tolerant
each try Date.EndOfMonth(Date.FromText("01-" & Text.Trim(_), [Format="dd-MMM-yy", Culture="en-IN"])) otherwise null

Connections
