Subtopic note

Type Ascription on New Columns

Scope: Type ascription on new columns (type number, Int64.Type, type date) so they are not left as any

Why it matters

Every column in Power Query has a declared type, shown as an icon in the header. A column added by Table.AddColumn without a type argument is declared any (the ABC/123 icon). In the editor preview the values look right, so the problem is invisible — until load. Excel tables may show numbers stored oddly, and the Data Model or Power BI typically loads an any column as text: amounts cannot be summed, fiscal months sort 1, 10, 11, 12, 2…, date columns get no hierarchy and relationships on date keys fail. Declaring types on new columns is a one-argument habit that prevents a whole category of model defects.

Core notes

The fourth argument of Table.AddColumn

Table.AddColumn(table, newColumnName, columnGenerator, optional columnType)

Net    = Table.AddColumn(t, "Net", each ([Debit] ?? 0) - ([Credit] ?? 0), type number),
FM     = Table.AddColumn(Net, "FiscalMonth", each Number.Mod(Date.Month([Date]) + 8, 12) + 1, Int64.Type),
FYLbl  = Table.AddColumn(FM, "FY", each "FY" & Text.From([FYEnd] - 1) & "-" & Text.End(Text.From([FYEnd]), 2), type text),
MonthE = Table.AddColumn(FYLbl, "MonthEnd", each Date.EndOfMonth([Date]), type date),
Flag   = Table.AddColumn(MonthE, "IsMSME", each List.Contains({"Micro", "Small"}, [MSMEStatus]), type logical)

Common types

Type expression UI name Use
type number Decimal Number Amounts (floating point), rates
Currency.Type Fixed Decimal Number Amounts where 4-decimal fixed precision avoids floating residues
Int64.Type Whole Number Counts, fiscal month, year, sort keys, day counts
Percentage.Type Percentage Loss rates, margins
type text Text Labels, codes, references
type date Date Dates without time
type datetime Date/Time Timestamps
type logical True/False Flags
type table, type record — Nested columns (e.g. from merges or All Rows)

type number and Int64.Type differ: Int64.Type is a facet of number (type number with an integer annotation). The Data Model loads it as Whole Number, which compresses better and sorts correctly.

Ascription vs conversion

Ascription declares the type; it does not convert values. If the generator returns text "202601" and you ascribe Int64.Type, the column claims to be a whole number but holds text values. The editor shows no error; the load fails or produces errors for those rows. Therefore:

  • Ascribe when the generator already returns the correct kind (arithmetic returns numbers, Date.EndOfMonth returns dates, & returns text).
  • Convert when the value is of a different kind: Number.From, Date.From, Text.From inside the generator, or Table.TransformColumnTypes afterwards, which converts and validates (producing Error cells for unconvertible values that you can catch).
Key = Table.AddColumn(t, "PeriodKey", each Number.From(Text.From([FYEnd]) & Text.PadStart(Text.From([FM]), 2, "0")), Int64.Type)

Other functions that take a type

  • Table.TransformColumns(t, {{"Name", each Text.Trim(_), type text}}) — the third element of each transformation is the type.
  • Table.Group(t, keys, {{"Amount", each List.Sum([Amount]), type number}}) — each aggregate takes a type.
  • Table.AddIndexColumn(t, "Seq", 1, 1, Int64.Type) — fifth argument.
  • Table.ExpandTableColumn inherits types only if the nested column was typed with a full table type.
  • Table.Combine(tables, tableType) and #table(type table [A = text, B = number], rows) declare full schemas.

Detecting untyped columns

Visually: the ABC/123 icon. Programmatically:

Untyped = Table.SelectRows(Table.Schema(Final), each [Kind] = "any")

Table.Schema returns one row per column with Name, Kind, TypeName and other metadata. A small validation query that must return zero rows is a useful control before publishing.

Worked illustration

An ageing query adds Days (Duration.Days(...), no type), Bucket (no type) and ECL ([OpenAmount] * [LossRate], no type), then loads to Power BI. Symptoms: Days is text, so "Average days" cannot be computed; ECL is text, so the provision total shows "Count of ECL" instead of a sum. After adding Int64.Type, type text and Currency.Type respectively, the ECL total for a ₹5.35 crore receivables book with weighted loss rate 2.1% shows ₹11,23,500 as a summable fixed-decimal value.

Edge cases & judgement calls

  • type nullable number. Columns may contain nulls regardless; type number already allows null in table column types, so nullable is usually unnecessary on columns.
  • Locale in conversion. Table.TransformColumnTypes(t, {{"Amount", type number}}, "en-IN") interprets "1,23,456.00" correctly; ascription never parses text.
  • Changed Type after AddColumn. A separate type step works but adds a step that may hard-code names; prefer the inline type argument.
  • Fixed decimal precision. Currency.Type holds 4 decimal places; rates with more precision (e.g. FX rates to 6 decimals) should stay type number.
  • Dates vs datetimes. A Date/Time column used as a relationship key to a Date dimension does not match; ascribe and convert to type date.

Key takeaways

  • A new column without a type argument is any and usually loads as text.
  • Pass type number, Currency.Type, Int64.Type, type date, type text or type logical as the fourth argument of Table.AddColumn.
  • Ascription declares; it does not convert — convert with Number.From/Date.From or Table.TransformColumnTypes.
  • Use Int64.Type for months, years, keys and day counts; Currency.Type for amounts where fixed precision helps.
  • Check Table.Schema for Kind = "any" before loading.

Practice Questions

Q1. Pick the type [L1]

State the most appropriate type for: (a) DaysPastDue; (b) ECL provision amount; (c) FY label "FY2025-26"; (d) PeriodKey 202611; (e) MSME breach flag; (f) LossRate 0.015; (g) MonthEnd date.

Q2. Ascription trap [L2]

Table.AddColumn(t, "PeriodKey", each Text.From([FYEnd]) & Text.PadStart(Text.From([FM]), 2, "0"), Int64.Type) shows no errors in the editor, but loading to the Data Model fails for every row. Explain why and give two correct alternatives.

💡 Hint: Ask what kind of value the & operator returns.

Q3. Untyped column audit [L2]

Write a query that lists every column of the final fact query whose type is any and every column of kind text whose name ends in "Amount", and explain how you would use it as a pre-publish control.

Q4. Fix the query [L1]

Rewrite these steps with proper types: Table.AddColumn(t, "Net", each [Debit] - [Credit]), Table.AddColumn(t, "MonthEnd", each Date.EndOfMonth([Date])), Table.AddColumn(t, "Bucket", each if [Days] <= 30 then "0-30" else ">30"), also correcting any null-handling defect.
