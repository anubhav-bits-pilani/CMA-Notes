Subtopic note

Receivable and Payable Ageing Against an As-Of-Date Parameter

Scope: Receivable/payable ageing buckets measured against an as-of-date parameter

Why it matters

Ageing is one of the most-used finance analyses: credit control chases overdue customers by bucket, treasury forecasts collections from it, auditors test it, the ECL provision matrix under Ind AS 109 multiplies it by loss rates, Schedule III requires receivable and payable ageing disclosures, and MSME payables must be monitored against the 45-day limit. An ageing is only meaningful as at a date: the March ageing must be the same whether you refresh it on 5 April or 5 June. Building ageing in Power Query against an as-of-date parameter, rather than against "today", makes it reproducible, testable and auditable.

Core notes

The as-of-date parameter

Create a parameter (Manage Parameters > New): Name AsOfDate, Type Date, Current Value 31-03-2026. In Excel, a common alternative is a named cell on a Control sheet read into M:

AsOfDate = Date.From(Excel.CurrentWorkbook(){[Name = "AsOfDate"]}[Content]{0}[Column1])

Either way, every ageing step references AsOfDate, and changing one value re-ages everything. Filter the open items to [InvoiceDate] <= AsOfDate so invoices after the reporting date do not appear with negative ages.

Days outstanding vs days past due

Basis Formula Used for
Days outstanding (from invoice date) Duration.Days(AsOfDate - [InvoiceDate]) Credit-control ageing, DSO analysis
Days past due (from due date) Duration.Days(AsOfDate - [DueDate]) Overdue analysis, ECL provision matrix, Schedule III ageing
Days from acceptance (MSME) Duration.Days(AsOfDate - [AcceptanceDate]) MSMED Act Sec 15 compliance, Sec 43B(h)

Subtracting two dates in M returns a duration; Duration.Days extracts whole days. Both operands must be dates (or both datetimes); a date minus a datetime raises an error, so convert with Date.From first. Due date, if not in the data, is Date.AddDays([InvoiceDate], [CreditDays]).

Bucket logic

Aged = Table.AddColumn(Open, "Bucket", each
    let d = Duration.Days(AsOfDate - [InvoiceDate])
    in  if d <= 30 then "0-30"
        else if d <= 60 then "31-60"
        else if d <= 90 then "61-90"
        else ">90", type text)

Because the conditions are evaluated in order, each else if only needs the upper bound. Add a sort column for buckets (1, 2, 3, 4) so that ">90" does not sort before "0-30".

For a days-past-due basis, include a "Not due" bucket:

PastDue = Table.AddColumn(Open, "DPDBucket", each
    let d = Duration.Days(AsOfDate - [DueDate])
    in  if d <= 0 then "Not due"
        else if d <= 30 then "1-30 DPD"
        else if d <= 90 then "31-90 DPD"
        else if d <= 180 then "91-180 DPD"
        else ">180 DPD", type text)

Configurable buckets

Hard-coded thresholds are fine for one report; a bucket table makes them configurable:

LowerDays UpperDays Bucket SortOrder LossRate
-99999 0 Not due 1 0.5%
1 30 1-30 DPD 2 1.5%
31 90 31-90 DPD 3 4%
91 180 91-180 DPD 4 10%
181 99999 >180 DPD 5 50%

Assign with a lookup function:

fxBucket = (d as number) as record =>
    Table.First(Table.SelectRows(Buckets, each d >= [LowerDays] and d <= [UpperDays])),
WithB = Table.AddColumn(PastDue, "B", each fxBucket(Duration.Days(AsOfDate - [DueDate])), type record),
Expanded = Table.ExpandRecordColumn(WithB, "B", {"Bucket", "SortOrder", "LossRate"})

The loss rate column then gives an ECL provision per invoice: [OpenAmount] * [LossRate]. Buffer the bucket table (Table.Buffer(Buckets)) if it is read per row.

Schedule III ageing

Schedule III (as amended in 2021) requires trade receivables and trade payables ageing "from the due date of payment" in the bands: less than 6 months, 6 months – 1 year, 1–2 years, 2–3 years, more than 3 years (for payables: less than 1 year, 1–2 years, 2–3 years, more than 3 years), split into disputed/undisputed and, for payables, MSME/others. If no due date is specified, the date of the transaction is used. Implement these bands with Date.AddMonths(AsOfDate, -6) style comparisons so that "6 months" means calendar months, or with day counts if the company's policy defines them so.

Worked illustration

As-of 31-03-2026. Invoices: A dated 15-03-2026 (₹4,00,000), B dated 10-01-2026 (₹2,50,000), C dated 20-11-2025 (₹1,80,000), D dated 02-04-2026 (₹90,000).

  • A: \(31 - 15 = 16\) days → 0-30.
  • B: 21 days left in January + 28 in February + 31 in March = 80 days → 61-90.
  • C: 10 + 31 + 31 + 28 + 31 = 131 days → >90.
  • D: after the as-of date → excluded by the filter (otherwise −2 days would fall into 0-30 and overstate receivables at 31 March).

Summary: 0-30 ₹4,00,000; 61-90 ₹2,50,000; >90 ₹1,80,000.

Edge cases & judgement calls

  • Partial payments and unapplied credits. Age open amounts, not invoice amounts; unapplied receipts and credit notes should be allocated (FIFO or as per remittance) or shown separately, not netted into the oldest bucket blindly.
  • Disputed items. Schedule III separates disputed and undisputed; carry a dispute flag from the source.
  • Boundary definitions. "0-30" vs "1-30": decide whether day 0 (invoice dated on the as-of date) is in the first bucket and document it.
  • Time zones. In the Service, "now" is UTC; using a parameter avoids the issue entirely.
  • Refresh vs period change. Changing AsOfDate requires re-filtering open items as at that date; an open-items file extracted on 31 March cannot produce a correct 30 June ageing.

Key takeaways

  • Always age against an AsOfDate parameter, never against DateTime.LocalNow().
  • Duration.Days(AsOfDate - [Date]) gives days; both operands must be the same type.
  • Distinguish days outstanding (invoice date) from days past due (due date) and MSME days (acceptance date).
  • Use ordered if ... else if chains or a bucket table with sort order and loss rates.
  • Filter out items dated after the as-of date and age open amounts, not gross invoice values.

Practice Questions

Q1. Age the invoices [L1]

As-of date 30-09-2025. Assign each invoice to 0-30, 31-60, 61-90 or >90 by invoice date: 12-09-2025 ₹1,20,000; 31-07-2025 ₹2,40,000; 01-08-2025 ₹75,000; 15-05-2025 ₹3,10,000; 05-10-2025 ₹60,000.

Q2. Due-date ageing with credit days [L2]

The open-items table has InvoiceDate, CreditDays (30, 45 or 60) and OpenAmount. Write M that derives DueDate, computes days past due against AsOfDate, assigns "Not due", "1-30", "31-90", "91-180", ">180" buckets with a SortOrder column, and types every new column.

💡 Hint: Date.AddDays([InvoiceDate], [CreditDays]) gives the due date.

Q3. ECL provision matrix [L2]

Using the bucket table in the notes, compute the ECL provision at 31-03-2026 for receivables: Not due ₹3.20 crore, 1-30 DPD ₹1.10 crore, 31-90 DPD ₹0.65 crore, 91-180 DPD ₹0.28 crore, >180 DPD ₹0.12 crore. Then explain how you would adjust the historical loss rates for forward-looking information as Ind AS 109 requires.

Q4. Reproducibility challenge [L3]

An auditor re-performs your March receivables ageing on 20 May and gets different bucket totals. List the possible causes (in M, in source data and in process), and design the controls that would make the ageing reproducible.
