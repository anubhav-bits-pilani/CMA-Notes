Subtopic note

Group By Aggregations for Summary Outputs During Ingestion

Scope: Group By aggregations (Sum, Count Rows, All Rows) for summary outputs during ingestion

Why it matters

Not every output should be a line-level fact table. Finance teams need summaries at ingestion time: a trial balance by FY and ledger from a GL line-item extract, an ageing summary by customer and bucket, control totals (rows, debits, credits) per source file, the latest record per vendor, or a monthly cash-flow summary from bank lines. Group By in Power Query is the SQL GROUP BY equivalent, plus a powerful extra — All Rows, which keeps each group's detail as a nested table for per-group logic such as ranking, sequence numbering or picking the latest version. Summarising upstream also reduces model size when the detail is not needed.

Core notes

The dialog and the generated M

Transform (or Home) > Group By. Basic groups by one column with one aggregation; Advanced allows several grouping columns and several aggregations. Operations include Sum, Average, Median, Min, Max, Count Rows, Count Distinct Rows and All Rows.

Table.Group(Source, {"FY", "Ledger"}, {
    {"Amount", each List.Sum([Amount]), type nullable number},
    {"Lines", each Table.RowCount(_), Int64.Type},
    {"Detail", each _, type table [Date = date, VchNo = text, Amount = number]}
})

Table.Group(table, keyColumns, aggregatedColumns, optional groupKind, optional comparer):

  • keyColumns — list of grouping columns.
  • aggregatedColumns — list of {newName, aggregationFunction, type}. Inside each function, _ is the sub-table of rows in the group, so [Amount] is that sub-table's Amount column as a list, and List.Sum([Amount]) sums it.
  • type — as with Table.AddColumn, declare it so the result is not any.

The three core operations

Sum (each List.Sum([Amount])): totals per group. List.Sum ignores nulls; it returns null for an all-null group, so coalesce if a zero is required (List.Sum([Amount]) ?? 0).

Count Rows (each Table.RowCount(_)): number of rows per group. Count Distinct Rows generates Table.RowCount(Table.Distinct(_)); for distinct values of one column use List.Count(List.Distinct([VchNo])).

All Rows (each _): the group's rows as a nested table. Use it when the per-group logic is more than a single aggregate:

Latest = Table.Group(Files, {"Branch", "Period"}, {{"Latest", each Table.Max(_, "Date modified"), type record}}),
Ranked = Table.Group(Sales, {"FY"}, {{"Top10", each Table.FirstN(Table.Sort(_, {{"Revenue", Order.Descending}}), 10), type table}}),
Seq    = Table.Group(Bank, {"AmtPaise"}, {{"Rows", each Table.AddIndexColumn(_, "Seq", 1, 1, Int64.Type), type table}})

Expand the nested result afterwards with Table.ExpandTableColumn or Table.ExpandRecordColumn.

Typical summary outputs during ingestion

Output Group keys Aggregations
TB from GL lines FY, PeriodKey, LedgerCode Sum Debit, Sum Credit, Net
Ageing summary Customer, Bucket Sum OpenAmount, Count invoices
File control totals SourceFile Count Rows, Sum Debit, Sum Credit
Duplicate check Vendor, InvoiceNo, Amount Count Rows (filter > 1)
Latest version per key Branch, Period All Rows → Table.Max on date
Monthly cash flow PeriodKey, Category Sum Inflow, Sum Outflow

An ageing summary is often pivoted for presentation: group by Customer + Bucket, then Table.Pivot(t, BucketOrderList, "Bucket", "Amount", List.Sum) to get one column per bucket. Keep the long (unpivoted) version for the model.

GroupKind.Local

The optional fourth argument GroupKind.Local groups only consecutive rows with the same key, instead of all rows with the key (GroupKind.Global, default). It is faster and useful for report-style data where blocks are contiguous (e.g. grouping lines under each voucher header in a Day Book), but on unsorted data it creates multiple groups for the same key — a subtle bug if added by copying code.

Folding

On SQL sources, Group By with standard aggregations folds to GROUP BY; All Rows and custom per-group functions do not. On files, everything runs in memory; group after filtering to reduce work.

Worked illustration

GL lines, FY2025-26, ledger "Rent" (code 520100): 12 lines of ₹1,50,000 Dr each, plus one reversal of ₹1,50,000 Cr in June and its re-posting of ₹1,50,000 Dr.

Table.Group(GL, {"FY", "LedgerCode"}, {
    {"Debit", each List.Sum([Debit]), type number},
    {"Credit", each List.Sum([Credit]), type number},
    {"Lines", each Table.RowCount(_), Int64.Type}})

Result: Debit ₹19,50,000 (13 lines × ₹1,50,000), Credit ₹1,50,000, Lines 14, so net ₹18,00,000 — the expected annual rent of 12 × ₹1,50,000. A Count Rows of 14 with only 12 months of rent is the kind of signal that prompts a quick look at the reversal.

Edge cases & judgement calls

  • Null keys. Rows with null in a key column form their own group; decide whether that is a "Unmapped" bucket or an error.
  • Case and whitespace in keys. "Rent " and "Rent" are different groups; normalise before grouping (or pass a comparer such as Comparer.OrdinalIgnoreCase).
  • Types of aggregates. The UI writes type nullable number for sums; keep it, or coalesce and use type number.
  • Losing detail. Summarising in Power Query discards line-level drill-down; in a data model, keep the detail and aggregate with measures unless size demands otherwise.
  • All Rows memory. Nested tables for millions of rows are memory-heavy; aggregate early where possible.

Key takeaways

  • Table.Group is SQL GROUP BY; inside each aggregation, _ is the group's sub-table.
  • Sum uses List.Sum([Col]), Count Rows uses Table.RowCount(_), All Rows returns _ as a nested table.
  • All Rows enables per-group logic: latest record, top N, sequence numbering.
  • Declare types on every aggregate and normalise keys before grouping.
  • GroupKind.Local groups only consecutive rows — use deliberately.

Practice Questions

Q1. Write the TB summary [L1]

From a GL extract with PostingDate, LedgerCode, LedgerName, Debit and Credit, write M that groups by FY label and LedgerCode, returning TotalDebit, TotalCredit, Net (TotalDebit − TotalCredit) and LineCount, all typed.

Q2. Ageing pivot [L2]

From an aged open-items table (Customer, Bucket, OpenAmount), produce a summary with one row per customer and columns "0-30", "31-60", "61-90", ">90" and Total, in that column order, with zeros instead of nulls.

💡 Hint: Group to Customer + Bucket first, then pivot with an explicit bucket list rather than List.Distinct.

Q3. Latest version per vendor [L2]

A vendor master history table has VendorCode, BankAccount, ChangedOn and ChangedBy. Use Group By with All Rows to return the latest record per vendor, and a second output listing vendors whose bank account changed more than twice in FY2025-26 — a classic fraud red flag.

Q4. GroupKind.Local bug [L2]

A query groups bank lines by TxnDate with GroupKind.Local and reports 41 groups for April, although April has 22 banking days. Explain the cause and two possible fixes.
