Date Functions for Fiscal and Ageing Logic

Scope: Date functions: Date.Month, Date.Year, Date.EndOfMonth, Date.AddMonths, Duration.Days

Why it matters

Fiscal attributes, ageing buckets, month-end keys, accrual periods, budget phasing and due dates are all built from a handful of M date functions. Each has behaviours that matter in finance: Date.AddMonths clips to month-end, Date.EndOfMonth returns a datetime when given a datetime, subtracting dates returns a duration rather than a number, and calendar quarter functions do not match the Indian fiscal year. Mastering these five functions and their edge cases removes most of the off-by-one and type errors in date logic.

Core notes

Date.Month and Date.Year

Date.Month(d) returns the calendar month number (1–12); Date.Year(d) returns the year. Both accept date, datetime or datetimezone values. They are the inputs to the FY and fiscal-month formulas:

FYEnd = Date.Year([Date]) + (if Date.Month([Date]) >= 4 then 1 else 0)
FM    = Number.Mod(Date.Month([Date]) + 8, 12) + 1

Related: Date.Day, Date.DayOfWeek(d, Day.Monday) (0-based), Date.QuarterOfYear (calendar quarter — April returns 2, so do not use it for fiscal quarters), Date.WeekOfYear.

Date.EndOfMonth (and friends)

Date.EndOfMonth(d) returns the last day of the month containing d. Given a date it returns a date; given a datetime it returns the last instant of the month (e.g. 30-04-2025 23:59:59.9999999), which will not equal a date key. Convert first: Date.EndOfMonth(Date.From([PostingDate])).

Siblings: Date.StartOfMonth, Date.StartOfQuarter, Date.EndOfQuarter (calendar quarters, whose end dates coincide with Indian fiscal quarter ends: 30 June, 30 September, 31 December, 31 March), Date.StartOfYear/Date.EndOfYear (calendar year — not FY).

FY start and end dates from FY end year:

FYStart = #date([FYEndYear] - 1, 4, 1),
FYEndDt = #date([FYEndYear], 3, 31)

#date(y, m, d) constructs a date literal; it is the safest way to build boundary dates.

Date.AddMonths

Date.AddMonths(d, n) shifts by n months (negative for backwards). If the target month is shorter, the day is clipped to the month-end: Date.AddMonths(#date(2025, 1, 31), 1) = 28-02-2025; Date.AddMonths(#date(2025, 2, 28), 1) = 28-03-2025 (not 31-03). So repeatedly adding one month to a month-end drifts away from month-ends. To step month-ends reliably, add months to the start of the month and take the end:

NextMonthEnd = Date.EndOfMonth(Date.AddMonths(Date.StartOfMonth([MonthEnd]), 1))

Uses: budget phasing (List.Transform({0..11}, each Date.EndOfMonth(Date.AddMonths(#date(2025, 4, 1), _))) gives the 12 month-ends of FY2025-26), Schedule III "6 months" boundaries (Date.AddMonths(AsOfDate, -6)), lease and loan schedules, and prior-year comparatives (Date.AddMonths(d, -12) or Date.AddYears(d, -1)).

Date.AddDays(d, n) adds days (due dates from credit days); Date.AddYears and Date.AddWeeks also exist.

Duration.Days

Subtracting two dates gives a duration, not a number: #date(2026, 3, 31) - #date(2026, 1, 10) = #duration(80, 0, 0, 0). Duration.Days(dur) returns the days component as a number (80). For datetimes, Duration.Days returns whole days only (the remaining hours are in Duration.Hours); Duration.TotalDays returns a fractional total. Both operands must be the same kind — date minus datetime raises an error.

Days = Duration.Days(AsOfDate - [InvoiceDate])

Months between dates (for "1–2 years" bands) are better computed by comparing against Date.AddMonths/Date.AddYears boundaries than by dividing days by 30 or 365.

Building month-end keys and calendars

A month-end date is the standard grain key for monthly facts (TB balances, budgets). A date list for a calendar dimension:

Dates = List.Dates(#date(2024, 4, 1), Duration.Days(#date(2027, 3, 31) - #date(2024, 4, 1)) + 1, #duration(1, 0, 0, 0)),
Cal   = Table.FromList(Dates, Splitter.SplitByNothing(), type table [Date = date])

Fiscal columns are then added with the formulas above (Week 11 builds this fully).

Worked illustration

Expression Result
Date.Month(#date(2026, 2, 15)) 2
Date.Year(#date(2026, 2, 15)) + (if 2 >= 4 then 1 else 0) 2026 (FY2025-26)
Date.EndOfMonth(#date(2024, 2, 10)) 29-02-2024 (leap year)
Date.AddMonths(#date(2025, 8, 31), 1) 30-09-2025
Date.AddMonths(#date(2026, 3, 31), -6) 30-09-2025
Duration.Days(#date(2026, 3, 31) - #date(2025, 3, 31)) 365
Duration.Days(#date(2024, 3, 31) - #date(2023, 3, 31)) 366 (includes 29-Feb-2024)

Edge cases & judgement calls

  • Leap years. Day-count bands of 365 days differ from calendar-year bands across 29 February; choose month-based boundaries where the definition says "year".
  • Datetime inputs from ERPs. SAP and SQL extracts often carry datetimes; convert with Date.From once, early.
  • Time zones. DateTimeZone values from APIs must be switched to IST (DateTimeZone.SwitchZone(x, 5, 30)) before taking the date, or transactions near midnight shift days.
  • Text dates. These functions require real dates; parse text dates with an explicit culture first (topic t2).
  • Clipping in schedules. For EMI or lease schedules starting on the 31st, decide whether payment dates are "same day, clipped" or "month-end", and implement deliberately.

Key takeaways

  • Date.Month and Date.Year drive FY end year and fiscal month; Date.QuarterOfYear is calendar-based and wrong for Indian FY quarters.
  • Date.EndOfMonth gives month-end keys; convert datetimes to dates first.
  • Date.AddMonths clips to month-end; step month-ends via start-of-month then end-of-month.
  • Date subtraction returns a duration; Duration.Days extracts days; operands must be the same type.
  • Build boundary dates with #date and month-based comparisons for "months/years" bands.

Practice Questions

Q1. Evaluate [L1]

Give the results: (a) Date.AddMonths(#date(2025, 5, 31), 1); (b) Date.EndOfMonth(Date.AddMonths(#date(2025, 5, 1), 1)); (c) Duration.Days(#date(2025, 10, 1) - #date(2025, 4, 1)); (d) Date.QuarterOfYear(#date(2025, 11, 5)) and the correct Indian fiscal quarter for that date.

Q2. Month-end list for a budget [L2]

Write M that generates a table with one row per month-end of FY2025-26 (typed date) plus FY label, fiscal month and PeriodKey, starting only from a parameter FYEndYear = 2026.

💡 Hint: Start from #date(FYEndYear - 1, 4, 1) and transform the list {0..11}.

Q3. Schedule III bands with months [L2]

Write a Custom Column that assigns Schedule III receivable bands (less than 6 months, 6 months–1 year, 1–2 years, 2–3 years, more than 3 years) from DueDate as at AsOfDate, using Date.AddMonths and Date.AddYears boundaries rather than day counts, with "Not due" for future due dates.

Q4. Datetime defect [L2]

An ageing query raises "We cannot apply operator - to types Date and DateTime" for some refreshes, and in others month-end keys fail to relate to the Calendar table. Diagnose both symptoms and give the fix.
