Key concept

Table.Group by FY and Ledger with a Typed Sum

Concept: Table.Group(t, {"FY","Ledger"}, {{"Amount", each List.Sum([Amount]), type number}})

Statement

Summary = Table.Group(t, {"FY", "Ledger"}, {{"Amount", each List.Sum([Amount]), type number}})
  • t — the input table, e.g. GL lines with FY, Ledger and a signed Amount.
  • {"FY", "Ledger"} — the grouping keys; the output has one row per distinct (FY, Ledger) pair.
  • {{"Amount", each List.Sum([Amount]), type number}} — a list of aggregations, each {name, function, type}.
  • Inside each, _ is the group's sub-table, so [Amount] is the list of Amount values in that group and List.Sum totals it.
  • type number declares the output column type.

Explanation

This is SQL's SELECT FY, Ledger, SUM(Amount) AS Amount FROM t GROUP BY FY, Ledger. It turns line-level GL data into a ledger-by-FY trial balance during ingestion, useful when the consumer needs only totals (a TB for a schedule, a comparison with the prior year, a mapping check to Schedule III lines).

Points of detail:

  • The sub-table. Because _ is a table, other aggregates are written against it: Table.RowCount(_) for line counts, List.Max([Date]) for the last posting date, List.Count(List.Distinct([VchNo])) for distinct vouchers.
  • Null behaviour. List.Sum ignores nulls; an all-null group returns null, not 0. Use List.Sum([Amount]) ?? 0 if a zero is needed.
  • Signed amounts. Summing a signed Amount (Dr positive, Cr negative) gives the net balance; sum Debit and Credit separately if both sides must be shown.
  • Type. Without the type element, the column is any; the UI writes type nullable number.
  • Key normalisation. "Rent" and "Rent " are separate groups; trim and normalise keys first, or group by a ledger code rather than a name.
  • Folding. On a SQL source this folds to GROUP BY; on files it is computed in memory.
  • Check. For a complete TB, the sum of Amount across all ledgers in each FY must be zero; build that as a second group by FY only.

Illustration

GL lines (₹):

FY Ledger Amount
FY2025-26 Sales −4,20,000
FY2025-26 Sales −3,80,000
FY2025-26 Debtors 8,00,000
FY2025-26 Bank 6,50,000
FY2025-26 Debtors −6,50,000

Result:

FY Ledger Amount
FY2025-26 Sales −8,00,000
FY2025-26 Debtors 1,50,000
FY2025-26 Bank 6,50,000

Check: \(-8{,}00{,}000 + 1{,}50{,}000 + 6{,}50{,}000 = 0\), so the summary balances.

Practice Questions

Q1. Extend the aggregation [L1]

Rewrite the concept's step to also return TotalDebit, TotalCredit (from separate Debit and Credit columns), LineCount and LastPostingDate, each with an appropriate type.

Q2. Balance check by FY [L2]

Write a query that groups the summary output by FY only, returns the net total per FY and a Status column ("Balanced" if the absolute total is under ₹1, otherwise "Out of balance"), and explain why a tolerance of ₹1 rather than exactly 0 is used.

💡 Hint: Floating-point sums of decimals can leave tiny residues; Number.Abs and a threshold handle them.

Q3. Prior-year comparison [L2]

Using the FY-Ledger summary for FY2024-25 and FY2025-26, describe the steps (group, pivot or merge) to produce a table with Ledger, FY2024-25 amount, FY2025-26 amount, variance and variance %, handling ledgers present in only one year.
