Key concept

Ageing Bucket Expression with Duration.Days

Concept: Ageing: let d = Duration.Days(AsOfDate - [InvoiceDate]) in if d <= 30 then "0-30" else if d <= 60 then "31-60" else if d <= 90 then "61-90" else ">90"

Statement

Table.AddColumn(Open, "Bucket", each
    let d = Duration.Days(AsOfDate - [InvoiceDate])
    in  if d <= 30 then "0-30"
        else if d <= 60 then "31-60"
        else if d <= 90 then "61-90"
        else ">90", type text)
  • AsOfDate — a parameter of type date (the reporting date).
  • AsOfDate - [InvoiceDate] — subtraction of two dates returns a duration.
  • Duration.Days(...) — the whole number of days, \(d\).
  • let d = ... in ... — computes \(d\) once per row and reuses it in every test.
  • The if ... else if chain assigns the first bucket whose upper bound is not exceeded.

Explanation

The let ... in inside each is a local variable: it keeps the expression readable and avoids recomputing the duration four times. Because conditions are evaluated in order, each branch needs only an upper bound — a row reaching d <= 60 is already known to have \(d > 30\).

Conditions:

  • Types must match. AsOfDate and [InvoiceDate] must both be dates (or both datetimes). Convert datetimes with Date.From.
  • Nulls. If InvoiceDate is null, the subtraction gives null, d <= 30 gives null and if raises an error. Add a first branch: if [InvoiceDate] = null then "No date" else ... (placing the null test before the let value is used).
  • Future-dated items. Invoices after AsOfDate give negative \(d\) and fall into "0-30". Filter them out ([InvoiceDate] <= AsOfDate) or add a "Future" bucket.
  • Basis. This is ageing by invoice date. For overdue analysis, ECL matrices and Schedule III, use the due date instead and add a "Not due" bucket for \(d \le 0\).
  • Parameter, not clock. Using Date.From(DateTime.LocalNow()) in place of AsOfDate makes buckets change every day and, in the Service, uses UTC.
  • Sorting. Add a BucketOrder column (1–4) so ">90" does not sort first alphabetically.

Illustration

As at 31-03-2026:

Invoice InvoiceDate d Bucket Open amount (₹)
S-1041 05-03-2026 26 0-30 3,60,000
S-0987 28-01-2026 62 61-90 1,25,000
S-0950 31-01-2026 59 31-60 2,10,000
S-0811 15-11-2025 136 >90 95,000

S-0987 and S-0950 are three days apart in date but fall in different buckets — the boundary at 60 days is exactly where reviewers test the logic.

Practice Questions

Q1. Bucket these invoices [L1]

As at 30-06-2025, assign buckets with the concept's expression: 31-05-2025, 01-05-2025, 02-04-2025, 31-03-2025, 15-07-2025. Identify any row that should not be in the ageing at all.

Q2. Harden the expression [L2]

Rewrite the expression to (a) return "No date" for null InvoiceDate, (b) return "Future" for invoices after AsOfDate, (c) handle InvoiceDate stored as datetime, and (d) add a BucketOrder column typed Int64.Type.

💡 Hint: Convert with Date.From inside the let, and test null before any comparison.

Q3. Due-date version for ECL [L2]

Adapt the expression to days past due using DueDate, with buckets Not due, 1-30, 31-90, 91-180, >180, and compute an ECL column using loss rates 0.4%, 1.2%, 3.5%, 12% and 45% respectively. Explain why the due-date basis is used for the provision matrix.
