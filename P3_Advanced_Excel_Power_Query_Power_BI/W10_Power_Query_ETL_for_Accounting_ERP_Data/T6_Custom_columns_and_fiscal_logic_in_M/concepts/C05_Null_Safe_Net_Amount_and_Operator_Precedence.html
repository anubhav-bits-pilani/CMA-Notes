Key concept

Null-Safe Net Amount and Operator Precedence

Concept: Net amount: ([Debit] ?? 0) - ([Credit] ?? 0); the parentheses matter for operator precedence

Statement

Table.AddColumn(t, "Net", each ([Debit] ?? 0) - ([Credit] ?? 0), type number)
  • x ?? y (null-coalescing operator) returns x when x is not null, otherwise y.
  • ([Debit] ?? 0) treats a missing debit as zero; likewise for credit.
  • Net \(= D - C\), with \(D\) and \(C\) the coalesced debit and credit; positive = net debit, negative = net credit.

Precedence: ?? binds more loosely than -. Without parentheses,

[Debit] ?? 0 - [Credit] ?? 0

is parsed as [Debit] ?? ((0 - [Credit]) ?? 0).

Explanation

Exports from Tally, SAP and bank portals typically leave one of Debit or Credit blank on each row. In M, arithmetic with null returns null: [Debit] - [Credit] is null for every row where either side is blank — which is nearly every row. Those nulls then disappear from sums (List.Sum ignores nulls), so totals look plausible but are wrong.

?? fixes the nulls, but its low precedence creates a trap. In the unparenthesised version, if Debit is non-null the whole expression returns Debit and the Credit is never subtracted; if Debit is null, it returns \(0 - \text{Credit}\). The results happen to be right for rows with only one side populated, which is why the bug survives testing — and wrong for any row with both a debit and a credit (common in TB exports with opening/closing or in GL lines with netted entries).

Related points:

  • ?? only replaces null. Empty text "" from a CSV is not null and will error in arithmetic; replace blanks with null or type the columns as numbers first (blank cells become null on conversion).
  • The same pattern applies to closing balances: ([Opening] ?? 0) + ([Debit] ?? 0) - ([Credit] ?? 0).
  • Older M without ?? used (if [Debit] = null then 0 else [Debit]), which is equivalent.
  • Excel's =A2-B2 treats blanks as zero; M does not — a frequent surprise for Excel users.

Illustration

Debit Credit [Debit] - [Credit] Unparenthesised ?? ([Debit] ?? 0) - ([Credit] ?? 0)
50,000 null null 50,000 50,000
null 20,000 null −20,000 −20,000
80,000 30,000 50,000 80,000 50,000
null null null 0 0

Only the last column is right on every row. On a 10,000-row TB where 40 rows have both sides populated, the unparenthesised version overstates net debits by the sum of those 40 credits.

Practice Questions

Q1. Evaluate rows [L1]

For rows (Debit, Credit) = (12,000, null), (null, null), (7,500, 2,500) and (null, 9,000), give the result of [Debit] - [Credit], of [Debit] ?? 0 - [Credit] ?? 0 and of the parenthesised form.

Q2. Closing balance column [L2]

A TB has Opening (signed, Dr positive), Debit and Credit, any of which may be null or empty text. Write M that cleans empty text to null, types the columns, and adds a Closing column, then a check step that returns the sum of Closing (which should be zero for a balanced TB).

💡 Hint: Table.ReplaceValue with Replacer.ReplaceValue converts "" to null before typing.

Q3. Review comment [L2]

In code review you find each [Opening] ?? 0 + [Debit] ?? 0 - [Credit] ?? 0. Write the review comment explaining how M parses it, a concrete example where it fails, and the corrected expression.
