Key concept

SCAN for Running Closing Balances

Concept: =SCAN(Opening, Movements, LAMBDA(acc, m, acc + m)) gives running closing balances

Statement

=SCAN(Opening, Movements, LAMBDA(acc, m, acc + m))
  • Opening — the initial value of the accumulator (opening balance).
  • Movements — a one-dimensional array of period movements (net debits/credits, billings less revenue, additions less depreciation).
  • LAMBDA(acc, m, acc + m) — for each element m, adds it to the running accumulator acc.
  • SCAN returns the accumulator after each step, so the output has the same size as Movements.

For periods \(t = 1, \dots, n\):

\[ C_t = C_{t-1} + M_t, \qquad C_0 = O \]

where \(O\) is the opening balance, \(M_t\) the movement in period \(t\) and \(C_t\) the closing balance returned in position \(t\).

Explanation

A roll-forward (opening + movements = closing) is the backbone of every balance-sheet schedule: fixed assets, debt, deferred revenue, provisions, inventory, retained earnings. Traditionally it is built with a copy-across chain: closing = opening + movements, next opening = previous closing. That chain is reliable but must be extended by hand when the horizon grows. SCAN produces the whole closing row from one formula, and it resizes when Movements is a spill (for example a SUMIFS row driven by EOMONTH(…, SEQUENCE(…)) headers).

Related forms:

  • Opening row: =VSTACK(Opening, DROP(close, -1)) (vertical) or HSTACK(Opening, DROP(close, , -1)) (horizontal) — the prior period's closing shifted by one.
  • YTD cumulative: SCAN(0, Monthly, LAMBDA(a, x, a + x)).
  • End balance only: REDUCE with the same arguments.
  • Non-additive logic: the LAMBDA can be any expression of acc and m. A lease liability with monthly interest rate i and payments p: SCAN(L0, p, LAMBDA(acc, x, acc*(1+i) - x)) — the interest depends on the running balance, which an additive cumulative sum cannot capture.

Constraints:

  • Movements should be a single row or column. On a 2-D array SCAN runs row by row, left to right, carrying the accumulator from the end of one row to the start of the next.
  • Signs must be consistent: increases positive, decreases negative (or the LAMBDA must subtract).
  • Requires Microsoft 365 / Excel 2024.
  • Reviewers cannot see intermediate opening balances unless you output them; for audit-facing schedules show opening, movements and closing as separate rows.

Illustration

Trade receivables, FY26 Q1 (₹ lakh). Opening on 1-Apr-2025: 820.

Month Billings Collections Movement SCAN closing
Apr-25 310 265 +45 865
May-25 295 340 −45 820
Jun-25 330 290 +40 860 
=SCAN(Opening, Billings - Collections, LAMBDA(acc, m, acc + m))

returns {865; 820; 860}. The June closing must agree with the trade receivables control ledger in the 30-Jun-2025 TB; a check cell =TAKE(close, -1) - TB_Receivables should be zero. DSO for the quarter can then use the average of opening and SCAN closings.

Practice Questions

Q1. Opening and closing rows [L1]

Movements for six months are in a horizontal spill D8# and the opening balance is in Open. Write formulas for the closing row with SCAN and the opening row derived from it, and a check that the last closing equals Open plus the sum of movements.

Q2. Loan balance with interest [L2]

A ₹1.2 crore loan carries 0.85% monthly interest with EMI of ₹2,56,147 for 60 months. Write a SCAN formula for the closing balance each month, explain why the LAMBDA cannot be acc + m, and describe what the final value should be close to.

💡 Hint: Interest is a function of the running balance, so it must be computed inside the LAMBDA.

Q3. Retained earnings roll-forward [L2]

FY26 monthly profit after tax is a spill PAT#, opening retained earnings are ₹48 crore, and an interim dividend of ₹6 crore is paid in October. Design a SCAN-based roll-forward and explain how you would show the dividend as a separate visible movement for the reviewer.
