Key concept

Top 10 Vendors by Spend with TAKE and SORTBY

Concept: =TAKE(SORTBY(Exp[Vendor], Exp[Amount], -1), 10) for the top 10 vendors by spend

Statement

=TAKE(SORTBY(Exp[Vendor], Exp[Amount], -1), 10)
  • SORTBY(Exp[Vendor], Exp[Amount], -1) — returns the Vendor column reordered by the Amount column, descending (−1).
  • TAKE(…, 10) — keeps the first 10 rows of that sorted array.

The formula is correct as written only when Exp already holds one row per vendor (a vendor-level spend summary). If Exp is an invoice-level table, it returns the vendors of the 10 largest invoices — which may repeat vendors and miss high-volume, low-ticket vendors. Aggregate first:

=LET(v, UNIQUE(Exp[Vendor]),
     s, SUMIFS(Exp[Amount], Exp[Vendor], v),
     TAKE(SORTBY(HSTACK(v, s), s, -1), 10))

Explanation

SORTBY is chosen over SORT because the sort key (Amount) does not need to be part of the returned array — the formula returns names only, ranked by a column it does not display. TAKE with a positive count returns rows from the top; a negative count returns from the bottom (bottom-10). If fewer than 10 vendors exist, TAKE returns them all without error.

Production refinements:

  • Parameterise N: replace 10 with a named input TopN, validated as a whole number between 1 and 50.
  • Show amounts and share: return HSTACK(v, s, s/SUM(s)) sorted by s so the table shows ₹ and % of spend.
  • Ties: SORTBY is stable, so tied vendors keep source order; add a secondary key (vendor code) to make the cut-off deterministic.
  • Reconcile: add an "All others" and "Total" row (s04) so the table ties to the expense ledgers in the TB.
  • Period: filter the source to the reporting window (e.g. FY26 or a quarter) inside LET before UNIQUE; otherwise the ranking covers all history.
  • Sign: if expenses are stored as negatives, sort ascending (1) or negate the amount.

Illustration

Invoice-level Exp for Q4 FY26 (₹ lakh):

Vendor Amount
Kaveri Packaging 30
Kaveri Packaging 28
Delta Power 41
Kaveri Packaging 26
Om Consultants 47
Shree Logistics 22
Shree Logistics 21
Shree Logistics 19

Raw formula with N = 3 → Om Consultants, Delta Power, Kaveri Packaging (from invoices 47, 41, 30). Aggregated version → Kaveri Packaging 84, Shree Logistics 62, Om Consultants 47. Delta Power, a one-invoice vendor, drops out, and Shree Logistics — invisible in the raw version — becomes number two. The two answers differ materially, which is why "top vendors" must be defined as top by aggregate spend.

Connections

Applies s04 (SORT/SORTBY) and s07 (TAKE, HSTACK). GROUPBY with sort_order −2 (s08) does the aggregation and sort in one function. The top-N filter is one of the Saturday speed-test challenges. In FP&A, top-N vendor spend supports procurement negotiations and concentration-risk analysis; in audit it defines the high-value sample for vendor confirmations and related-party (Ind AS 24) review.

Practice Questions

Q1. Bottom 5 and named N [L1]

Write formulas for (a) the 5 vendors with the lowest aggregate spend, (b) the top-N vendors with amount and share of total, where N is in a named cell TopN.

Q2. Why did the CFO's number change? [L2]

The top-10 list in the July MIS was built with the raw (non-aggregated) formula; August's version was rebuilt with the aggregated formula. Seven of ten vendors changed. Draft a short note to the CFO explaining the change, using the concept of invoice-level vs vendor-level ranking.

Q3. Concentration KPI [L2]

Using the aggregated approach, write a single formula returning the percentage of total FY26 spend accounted for by the top 10 vendors, filtering Exp[Date] between inputs FromDt and ToDt.

💡 Hint: Sort the aggregated amount array, TAKE the first 10, SUM, and divide by the period total.
