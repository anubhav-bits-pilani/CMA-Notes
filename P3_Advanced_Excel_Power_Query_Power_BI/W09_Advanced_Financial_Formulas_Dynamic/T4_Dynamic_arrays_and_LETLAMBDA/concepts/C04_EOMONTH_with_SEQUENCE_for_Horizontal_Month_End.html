Key concept

EOMONTH with SEQUENCE for Horizontal Month-End Headers

Concept: =EOMONTH(StartDate, SEQUENCE(1, 12, 0)) gives horizontal month-end headers

Statement

=EOMONTH(StartDate, SEQUENCE(1, 12, 0))
  • SEQUENCE(1, 12, 0) — one row, twelve columns, starting at 0, step 1: {0, 1, 2, …, 11}.
  • EOMONTH(StartDate, k) — the last day of the month k months after StartDate's month.
  • Because the months argument is an array, EOMONTH returns an array: twelve month-end dates spilling across one row.

For column j (1-based):

\[ H_j = \text{EOMONTH}(S,\ j-1), \quad j = 1, \dots, 12 \]

where \(S\) is StartDate and \(H_j\) the header date in column \(j\).

Explanation

Month headers are the time axis of every MIS grid and forecast. Building them as real dates (serial numbers formatted mmm-yy) rather than text labels matters because:

  • SUMIFS can use date-range criteria — ">"&EOMONTH(C$4,-1) and "<="&C$4 — so each column picks up exactly that month's postings regardless of the posting day.
  • The whole row is driven by one input. Changing StartDate from 1-Apr-2025 to 1-Apr-2026 rolls the year; replacing 12 with a named input Months makes the horizon flexible (18-month rolling forecast).
  • Month-end dates line up with accounting periods and with Ind AS 34 interim period ends, and are what XNPV-style dated schedules need.

Points of detail:

  • Any day of the start month works. EOMONTH ignores the day, so StartDate can be 1-Apr-2025 or 17-Apr-2025; the first header is 30-Apr-2025.
  • Start at 0. Starting SEQUENCE at 1 would skip the start month — a common off-by-one error.
  • Vertical version: SEQUENCE(12, 1, 0) or simply SEQUENCE(12, , 0) spills down a column for a schedule with periods as rows.
  • Quarter-ends: SEQUENCE(1, 4, 2, 3) with an April start gives offsets 2, 5, 8, 11 → 30-Jun, 30-Sep, 31-Dec, 31-Mar.
  • References: downstream formulas must use C4# (spill operator) so they widen with the header. Row-locked references such as C$4 are appropriate only in a traditional copy-across grid where each column has its own formula.
  • Formatting: apply mmm-yy to the full reserved header row so extended columns are formatted too.
  • Inside Tables: Table headers are static text and cannot be dynamic arrays; build the axis on a normal range.

Illustration

StartDate = 1-Apr-2025 (named input).

Column Offset Header
C 0 30-Apr-25
D 1 31-May-25
E 2 30-Jun-25
… … …
M 10 28-Feb-26
N 11 31-Mar-26

A revenue row under it:

=SUMIFS(GLm[Amount], GLm[FSLine], B6,
        GLm[Date], ">"&EOMONTH(C4#, -1), GLm[Date], "<="&C4#)

Because C4# is an array, this single formula spills twelve monthly totals. February FY26 correctly ends on 28-Feb-2026 (not a leap year); FY28's header would show 29-Feb-2028 automatically.

Connections

Applies s05 (SEQUENCE) and the w9_t5 date functions (EOMONTH/EDATE). It is the header half of the week's exercise pattern (UNIQUE FS lines × EOMONTH headers × SUMIFS) and the cross-cutting rule "SUMIFS keyed on date ranges, never on month text". It drives rolling 12-month forecast headers in Weeks 17–20 and dated cash-flow columns for XNPV in Weeks 15–16.

Practice Questions

Q1. Variations [L1]

Write formulas for (a) 24 vertical month-end dates starting from the month of StartDate; (b) four fiscal quarter-end headers for FY27; (c) a row of month-start dates (1st of each month) for FY26.

Q2. Off-by-one diagnosis [L1]

A model uses =EOMONTH(StartDate, SEQUENCE(1, 12)) with StartDate = 1-Apr-2025. The March column shows zero revenue and April revenue is missing from the year total. Explain why and correct it.

Q3. Rolling forecast header [L2]

Actuals are loaded up to the date in named cell LastClose (e.g. 31-Oct-2025). Write a header formula that shows the 6 actual months up to LastClose followed by 12 forecast months, plus a second row that labels each column "A" or "F". Explain how the grid updates after the November close.

💡 Hint: Start the sequence at a negative offset relative to LastClose.
