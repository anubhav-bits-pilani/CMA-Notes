Key concept

FYEND: A Named LAMBDA for the Indian Financial Year

Concept: Name FYEND =LAMBDA(d, YEAR(d) + (MONTH(d) >= 4)); then =FYEND(A2) returns the Indian FY end year

Statement

Defined name FYEND, Refers To:

=LAMBDA(d, YEAR(d) + (MONTH(d) >= 4))

Usage: =FYEND(A2).

For a date \(d\) with calendar year \(Y(d)\) and month \(M(d)\):

\[ \text{FYEND}(d) = Y(d) + \begin{cases} 1 & \text{if } M(d) \geq 4 \\ 0 & \text{if } M(d) \leq 3 \end{cases} \]

The Boolean (MONTH(d) >= 4) is coerced to 1 or 0 by the addition. The result is the calendar year in which the financial year ending 31 March ends — the "FY26" convention used in Indian reporting for 1-Apr-2025 to 31-Mar-2026.

Explanation

Indian companies report on an April–March financial year (Sec 2(41) of the Companies Act 2013 requires the FY to end on 31 March, with Tribunal approval needed for a different year-end, typically for subsidiaries of foreign groups). The Income-tax Act's "previous year" also runs April–March. GL exports carry only the transaction date, so every MIS and TB analysis needs an FY tag. Writing YEAR(d)+(MONTH(d)>=4) inline in dozens of places invites inconsistent variants (>3, >=4, >4); a named LAMBDA makes it one reviewed rule.

How to create and test it:

  1. Test inline in a cell: =LAMBDA(d, YEAR(d)+(MONTH(d)>=4))(DATE(2026,3,31)) → 2026.
  2. Ctrl+F3 → New. Name FYEND, scope Workbook, comment "FY end year (FY ends 31 March)", Refers To the LAMBDA.
  3. Keep test cases on a Functions sheet: 31-Mar-2026 → 2026; 1-Apr-2026 → 2027; 15-Jan-2026 → 2026.

Extensions:

  • Label: ="FY" & RIGHT(FYEND(A2), 2) → "FY26". A companion LAMBDA FYLABEL can wrap this.
  • Arrays: =FYEND(GL[Date]) spills an FY for every GL row; inside SUMPRODUCT or FILTER, FYEND(GL[Date])=2026 gives a Boolean array without a helper column.
  • FY end date: =DATE(FYEND(A2), 3, 31) returns the actual 31 March date (w9_t5 c07).
  • Different year-ends: generalise with a second parameter — =LAMBDA(d, [startm], LET(s, IF(ISOMITTED(startm), 4, startm), YEAR(d) + (s > 1) * (MONTH(d) >= s))) — for a group with a January–December subsidiary. The (s > 1) factor matters: with startm = 1 the result must be the calendar year itself, whereas YEAR(d) + (MONTH(d) >= 1) would add 1 to every date.

Caveats:

  • Text dates from ERP exports return #VALUE! because YEAR cannot read text; convert first.
  • Version: named LAMBDAs need Microsoft 365 or Excel 2024; recipients on 2019 see #NAME?.
  • Name clash: ensure no other workbook name FYEND exists (for example a cell named FYEND holding 31-Mar-2026); Excel will not allow duplicate names at the same scope, but a sheet-scoped name can shadow the workbook one.

A SUMIFS cannot apply FYEND to its criteria range directly, but =SUM(GL[Amount]*(FYEND(GL[Date])=2026)) returns FY26 total postings in Microsoft 365 without a helper column.

Practice Questions

Q1. Companion functions [L1]

Write named LAMBDAs FYLABEL (returns "FY26" style text) and FYQTR (returns 1 for April–June through 4 for January–March). Give two test dates for each, including a boundary.

Q2. Boundary bug hunt [L2]

A colleague's version is =LAMBDA(d, YEAR(d) + (MONTH(d) > 4)). For which months is it wrong, what would an FY26 revenue total computed with it include and exclude, and how would a test block have caught it?

💡 Hint: Check 1 April and 30 April specifically.

Q3. Group with mixed year-ends [L3]

An Indian group has a US subsidiary reporting January–December and a Japanese subsidiary reporting April–March. Design a single LAMBDA (with an optional parameter) that tags each GL row with its entity's fiscal year, and explain how you would document and test it for consolidation use.
