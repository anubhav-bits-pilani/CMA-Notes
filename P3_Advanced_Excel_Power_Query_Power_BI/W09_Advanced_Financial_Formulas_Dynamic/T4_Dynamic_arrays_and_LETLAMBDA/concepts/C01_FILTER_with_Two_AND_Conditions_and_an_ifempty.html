Key concept

FILTER with Two AND Conditions and an ifempty Message

Concept: =FILTER(GL, (GL[Dept]=H1)*(GL[Amount]>100000), "None")

Statement

=FILTER(GL, (GL[Dept]=H1)*(GL[Amount]>100000), "None")
  • GL — the whole GL Table (all columns), so complete rows are returned.
  • (GL[Dept]=H1) — Boolean array, TRUE where the department equals the selection in H1.
  • (GL[Amount]>100000) — Boolean array, TRUE where the line exceeds ₹1,00,000.
  • * — multiplies the arrays element by element; TRUE × TRUE = 1, any FALSE gives 0. This is AND.
  • "None" — the if_empty value, returned when no row has a product of 1.

The include array, row by row, is

\[ \text{include}_i = [\text{Dept}_i = H1] \times [\text{Amount}_i > 100000] \]

where \([\cdot]\) equals 1 if the condition is true and 0 otherwise. Row i is returned if and only if \(\text{include}_i \neq 0\).

Explanation

This is the canonical exception-list formula: "show me every high-value posting for the department I select". It replaces AutoFilter with a live, documented rule. The parentheses around each comparison are essential: without them, operator precedence evaluates * before = and >, so GL[Dept]=H1*GL[Amount]>100000 computes H1*GL[Amount] first (a #VALUE! because H1 is text).

Design choices worth noting:

  • H1 as an input cell, ideally a Data Validation dropdown fed by UNIQUE(GL[Dept]) (w9_t6), so users cannot type a department that does not exist.
  • The threshold is hard-coded as 100000 here; in a production model, move it to a named input (Threshold) so materiality can be changed without editing the formula.
  • if_empty prevents #CALC! when the selected department has no large postings. The text "None" lands in the first cell of the output; the other columns are blank.
  • Returning the whole Table includes every column. To show only Date, Voucher, Ledger and Amount, wrap the array in CHOOSECOLS or use a contiguous column range such as GL[[Date]:[Amount]].
  • Blank H1: GL[Dept]="" matches blank-department rows only. If blank should mean "all departments", use ((H1="")+(GL[Dept]=H1)) as the first factor.
  • Sign convention: if credits are negative (e.g. expense reversals), >100000 ignores large negative lines. Use ABS(GL[Amount])>100000 to catch both sides.

The output is a spill: it must sit outside any Table with clear cells below and to the right, and other formulas should reference it with the # operator.

Illustration

H1 = "Marketing". GL extract:

Date Voucher Dept Ledger Amount (₹)
04-Apr-25 JV-0012 Marketing Advertisement 4,50,000
09-Apr-25 JV-0031 Sales Commission 2,20,000
15-Apr-25 JV-0047 Marketing Printing 38,000
22-Apr-25 JV-0063 Marketing Sponsorship 12,00,000
28-Apr-25 JV-0080 Marketing Advertisement −4,50,000

Products: 1, 0, 0, 1, 0. Rows JV-0012 and JV-0063 are returned. Note the reversal JV-0080 is excluded because −4,50,000 is not > 1,00,000 — so the reviewer sees the original ₹4.5 lakh entry without its reversal. Using ABS() would show both and reveal that the net is nil. If H1 is changed to "HR" (no postings above the threshold), the output is "None".

Connections

Builds on s02 (AND/OR logic) and s01 (spill behaviour). The dropdown in H1 links to w9_t6 Data Validation with a spill-reference source. The same rule in Power BI is a DAX CALCULATETABLE(GL, GL[Dept] = sel, GL[Amount] > 100000) (Week 11). In audit practice this is a journal-entry test under SA 240 fraud-risk procedures; in FP&A it is the drill-down behind a department variance.

Practice Questions

Q1. Extend the rule [L1]

Modify the formula so that it returns only Date, Voucher, Ledger and Amount, uses a named input Thr for the threshold, treats a blank H1 as "all departments", and catches large negative lines as well as positive ones.

Q2. Precedence trap [L2]

A user writes =FILTER(GL, GL[Dept]=H1*GL[Amount]>100000, "None"). Walk through how Excel evaluates the include argument for a row where Dept = "Marketing", H1 = "Marketing" and Amount = 4,50,000, and state the result.

Q3. Reviewer's view [L2]

The output for "Admin" in FY26 shows 46 rows above ₹1 lakh, of which 30 are monthly rent and salary accruals. Propose two changes to the formula (or to the GL data) that reduce noise without hiding genuine exceptions, and explain the risk of each.

💡 Hint: Consider excluding specific recurring ledgers via a list, versus raising the threshold.
