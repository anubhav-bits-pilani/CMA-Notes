SORT and SORTBY for Top-N Expense and Ranked Ageing Reports

Scope: SORT/SORTBY for top-N expense reports and ageing ranked by amount

Why it matters

Management rarely wants the full list; it wants the top 10 vendors by spend, the 20 largest overdue debtors, the five cost lines that drove the variance. CFO packs and board MIS for listed companies routinely include "top-N" tables, and auditors use ranked lists to select high-value samples. The traditional approach — PivotTable sorted descending, then copy the top rows — is manual and breaks every month. SORT and SORTBY produce the ranked list live from the data, and combined with TAKE they give a self-updating top-N table. This is one of the three named challenges in the Week 9 speed test (dynamic top-N expense filter).

Core notes

SORT

=SORT(array, [sort_index], [sort_order], [by_col])
Argument Default Notes
array — Range or array to sort
sort_index 1 Column number within array to sort by (or row number if by_col)
sort_order 1 1 ascending, -1 descending
by_col FALSE TRUE sorts columns left-to-right

Multi-level sort: pass array constants — SORT(data, {2,3}, {1,-1}) sorts by column 2 ascending, then column 3 descending.

SORTBY

=SORTBY(array, by_array1, [sort_order1], [by_array2, sort_order2], ...)

SORTBY sorts by arrays that need not be part of the output, and that can be computed. That makes it the better tool for finance reports:

  • Sort a vendor list by a SUMIFS total that is not displayed.
  • Sort by a computed days-overdue array.
  • Sort by a custom order (e.g. Schedule III sort key looked up from the mapping table).

Each by_array must be the same height (or width) as array.

Top-N pattern

Raw transactions must be aggregated before ranking — sorting invoice lines and taking the top 10 returns the 10 largest invoices, not the top 10 vendors.

=LET(
   v, UNIQUE(Exp[Vendor]),
   amt, SUMIFS(Exp[Amount], Exp[Vendor], v),
   tbl, HSTACK(v, amt),
   TAKE(SORTBY(tbl, amt, -1), N))
  • N is a named input (e.g. 10) so the user can switch to top 5 or top 20.
  • TAKE with a positive count returns the first N rows; if fewer rows exist, it returns all of them without error.
  • Add a share-of-total column: HSTACK(v, amt, amt/SUM(amt)) before sorting.
  • Add a rank column: SEQUENCE(MIN(N, ROWS(v))) prepended with HSTACK.

In Microsoft 365 with GROUPBY available (s08), the aggregation step can be GROUPBY(Exp[Vendor], Exp[Amount], SUM) sorted by the value column.

Top-N with an "All others" line

Board packs often show top 10 plus "Others" so the table still ties to total spend. Compute "Others" as total minus the top-N total (rather than summing the remainder with DROP, which errors when fewer than N vendors exist):

=LET(
   v, UNIQUE(Exp[Vendor]),
   amt, SUMIFS(Exp[Amount], Exp[Vendor], v),
   s, SORTBY(HSTACK(v, amt), amt, -1),
   top, TAKE(s, N),
   VSTACK(top,
          HSTACK("All others", SUM(amt) - SUM(TAKE(CHOOSECOLS(s,2), N))),
          HSTACK("Total", SUM(amt))))

The total row equals the TB expense balance for the period — put a check cell beside it.

Ageing ranked by amount

For debtors, rank customers by total overdue balance and show bucket split:

=LET(
   c, UNIQUE(AR[Customer]),
   od, RptDate - AR[DueDate],
   b1, SUMIFS(AR[Balance], AR[Customer], c, AR[DueDate], ">="&(RptDate-30)),
   b2, SUMIFS(AR[Balance], AR[Customer], c, AR[DueDate], "<"&(RptDate-30), AR[DueDate], ">="&(RptDate-90)),
   b3, SUMIFS(AR[Balance], AR[Customer], c, AR[DueDate], "<"&(RptDate-90)),
   tot, b1 + b2 + b3,
   SORTBY(HSTACK(c, b1, b2, b3, tot), b3, -1, tot, -1))

This sorts primarily by the >90-day bucket (the ECL-relevant risk) and then by total. SUMIFS criteria on dates are built from the report-date cell, never typed dates — the same discipline as in w9_t1. (The od variable is shown for clarity; it can be used instead to build bucket flags with SUMPRODUCT-style arithmetic.)

Illustration

FY26 Q4 expense lines summarised:

Vendor Q4 spend (₹ lakh)
Kaveri Packaging 84.2
Shree Logistics 61.5
Nimbus IT 12.8
Om Consultants 47.0
Delta Power 39.9
41 other vendors 118.6

With N = 3, the output is Kaveri 84.2, Shree 61.5, Om 47.0, All others 218.3, Total 363.9. Changing N to 5 re-cuts the table instantly; the total stays at 363.9, which ties to the Q4 expense ledgers.

Ties

SORTBY is a stable sort — equal values keep their original relative order — but TAKE then cuts arbitrarily at the boundary. If vendor 10 and 11 have equal spend, only one shows. Add a secondary sort key (vendor code) for deterministic output, or disclose ties.

Sort order for statements

Do not alphabetically sort an income statement. Sort by the mapping-table sort key using SORTBY with an XLOOKUP-derived array:

=SORTBY(Lines, XLOOKUP(Lines, Map[FSLine], Map[SortKey]), 1)

Edge cases & judgement calls

  • Sign conventions. If expenses are negative in the GL (credit-positive convention), sort ascending or negate the amount; otherwise the "top 10" will be the smallest spend.
  • Credit notes and reversals. A vendor with a large invoice and a full reversal nets to zero; aggregate before ranking, or the reversed invoice will show as a top item.
  • Related parties. Top-N vendor tables in board packs may need related-party flags (Ind AS 24); add a lookup column.
  • TAKE vs INDEX/SEQUENCE. In older Microsoft 365 builds without TAKE, use INDEX(sorted, SEQUENCE(N), {1,2}).
  • Volatile N. Validate N as a whole number 1–50 with Data Validation (w9_t6) so a user typing 0 does not produce an empty table.
  • Performance. UNIQUE + SUMIFS + SORTBY over 100k+ lines is fine; over 1 million rows, aggregate in Power Query or the Data Model.

Key takeaways

  • SORT sorts by a column inside the array; SORTBY sorts by any same-size array, including computed ones.
  • Aggregate (UNIQUE + SUMIFS or GROUPBY) before ranking, then TAKE the top N.
  • Drive N from an input cell and add "All others" and "Total" rows so the table ties to the TB.
  • Use multi-key sorts for deterministic ordering and for ageing (oldest bucket first, then total).
  • Statements are sorted by mapping sort keys, never alphabetically.

Q1. SORT arguments [L1]

Range A2:D500 holds Vendor, State, Invoices, Amount. Write formulas to (a) sort by Amount descending; (b) sort by State ascending then Amount descending; (c) return only Vendor and Amount sorted by Amount descending, using CHOOSECOLS.

Q2. Top-N with Others and tie-out [L2]

Table Exp has Date, Vendor, VendorCode, Ledger, Amount for FY26 (positive = expense). Build a single formula that returns the top N vendors by spend for a date range defined by inputs FromDt and ToDt, followed by "All others" and "Total" rows. Explain where you would place a check cell and what it compares to.

💡 Hint: Filter by date before UNIQUE, and keep the filtered vendor and amount arrays in LET variables.

Q3. Ranked ageing for ECL review [L2]

AR Table has Customer, InvoiceNo, DueDate, Balance. Report date is 31-Mar-2026. Write a formula producing customer-wise balances in buckets 0–30, 31–90, 91–180 and >180 days past due, sorted by the >180 bucket descending and then total descending. State how the output would feed an Ind AS 109 provision matrix.

Q4. Why is the top 10 wrong? [L2]

A junior's "top 10 vendors" formula is =TAKE(SORT(Exp, 5, -1), 10). The CFO notices one vendor appears three times and a vendor with ₹2 crore annual spend is missing. Explain both problems and rewrite the formula.

Q5. Interview: SORT vs SORTBY [L1]

In an interview you are asked, "When would you use SORTBY instead of SORT?" Give two finance-specific examples where SORT cannot do the job.
