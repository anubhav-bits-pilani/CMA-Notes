GROUPBY and PIVOTBY as Formula-Based Pivots

Scope: GROUPBY and PIVOTBY (Microsoft 365) as formula-based pivots

Why it matters

PivotTables are fast to build but have three weaknesses in a controlled reporting model: they must be refreshed manually (a stale pivot in a board pack is a classic review finding), their layout shifts when new items appear, and they cannot be referenced cleanly by downstream formulas except through GETPIVOTDATA. GROUPBY and PIVOTBY are formula equivalents that recalculate automatically like any other formula, spill to the right size, and can feed further formulas through the # operator. For an FP&A analyst producing a department × month expense summary or a vendor spend analysis every month, they collapse UNIQUE + SUMIFS + SORT + totals into one function call. They are also an excellent independent cross-check of a SUMIFS-built P&L.

Core notes

GROUPBY — one-dimensional summaries

=GROUPBY(row_fields, values, function, [field_headers], [total_depth],
         [sort_order], [filter_array], [field_relationship])
Argument Meaning Common choices
row_fields Column(s) to group by GL[Dept] or GL[[Dept]:[CostCentre]]
values Column(s) to aggregate GL[Amount]
function Aggregation SUM, AVERAGE, COUNT, COUNTA, MAX, MIN, PERCENTOF, or a LAMBDA
field_headers Whether data has headers / show headers 0 no, 1 yes-don't show, 2 no-generate, 3 yes-show
total_depth Totals and subtotals 0 none, 1 grand total (default), 2 subtotals + grand total; negative puts totals at top
sort_order Column index to sort by; negative for descending -2 sorts by the value column descending
filter_array Boolean array of rows to include GL[FY]="FY26"
field_relationship Hierarchy (0, default) or table (1) 1 repeats labels on every row

Example — FY26 spend by department, largest first, with grand total:

=GROUPBY(GL[Dept], GL[Amount], SUM, 3, 1, -2, GL[FY]="FY26")

This replaces:

=LET(d, UNIQUE(FILTER(GL[Dept], GL[FY]="FY26")),
     a, SUMIFS(GL[Amount], GL[Dept], d, GL[FY], "FY26"),
     VSTACK(SORTBY(HSTACK(d, a), a, -1), HSTACK("Total", SUM(a))))

Multiple aggregations: pass HSTACK(SUM, COUNT) as the function and the values twice (HSTACK(GL[Amount], GL[Amount])) to show total spend and number of entries side by side. PERCENTOF gives each group's share of the total.

PIVOTBY — two-dimensional (cross-tab) summaries

=PIVOTBY(row_fields, col_fields, values, function, [field_headers],
         [row_total_depth], [row_sort_order], [col_total_depth],
         [col_sort_order], [filter_array], [relative_to])

Department × month expense grid:

=PIVOTBY(GLm[Dept], GLm[MonthEnd], GLm[Amount], SUM, 3, 1, 0, 1, 0,
         GLm[FSLine]<>"Revenue from operations")

MonthEnd is a column of EOMONTH(Date,0) values in the mapped GL, so columns are real dates in chronological order (format the header row as mmm-yy). If you pivot by a text month ("Apr", "May"), the column order becomes alphabetical — Apr, Aug, Dec … — a recurring error.

Custom aggregations with LAMBDA

The function argument accepts any LAMBDA taking a column of values:

=GROUPBY(AR[Customer], AR[DaysOverdue], LAMBDA(x, MAX(x)))   oldest open item per customer
=GROUPBY(Sales[Branch], Sales[Amount], LAMBDA(x, ROUND(SUM(x)/100000, 2)))   ₹ lakh

Hierarchies for Schedule III roll-ups

Pass two row fields to group FS line within Schedule III head, with subtotals:

=GROUPBY(GLm[[SchIIIHead]:[FSLine]], GLm[Amount], SUM, 3, 2)

total_depth 2 gives a subtotal for each head (e.g. "Other expenses" with its FS lines beneath) and a grand total. Order follows the sort of row fields; to impose Schedule III order, include the sort key as the first row field and hide it with CHOOSECOLS / DROP(…, , 1).

Illustration

Mapped GL extract (₹ lakh):

Dept MonthEnd Amount
Sales 30-Apr-25 42
Admin 30-Apr-25 18
Sales 31-May-25 47
Admin 31-May-25 16
Plant 31-May-25 61

=PIVOTBY(T[Dept], T[MonthEnd], T[Amount], SUM) returns:

Apr-25 May-25 Total
Admin 18 16 34
Plant 61 61
Sales 42 47 89
Total 60 124 184

Blank cells (Plant in April) are genuinely empty in the output, not zero. When June's GL is pasted into the source Table, a Jun-25 column appears automatically.

GROUPBY/PIVOTBY versus PivotTables versus SUMIFS grids

Aspect PivotTable GROUPBY / PIVOTBY UNIQUE + SUMIFS grid
Refresh Manual (or on open) Automatic Automatic
Layout control Pivot styles; limited Fixed by formula; limited formatting Full control (statement layout)
Downstream references GETPIVOTDATA # spill references Direct cell references
Handles calculated FS lines (Gross margin, EBITDA) Calculated items, clumsy No — add with VSTACK Yes, natural
Version All Current Microsoft 365 only 365 for UNIQUE; SUMIFS everywhere
Data size Data Model for millions Worksheet limits; slower above ~100k rows Similar

Practical guidance: use PIVOTBY for analysis tabs and cross-checks; use a UNIQUE/SEQUENCE × SUMIFS grid for the presentation P&L, where you need subtotal lines in Schedule III format, comparatives and fixed formats.

Cross-check pattern

If the PIVOTBY spills from K5, its grand total is the bottom-right cell: =TAKE(K5#, -1, -1). Put that beside the SUMIFS P&L total with a difference cell. A difference flags a mapping or criteria error in one of the two methods — the same idea as using GETPIVOTDATA to cross-check SUMIFS in w9_t1.

Edge cases & judgement calls

  • Availability. GROUPBY and PIVOTBY are recent Microsoft 365 functions; Excel 2021/2024 perpetual and older builds show #NAME?. Check recipients' versions before using them in shared packs.
  • Cannot spill inside Tables, and the output size changes with data — reserve space as for any spill.
  • Sign conventions. Revenue as negative credits will show negative totals; pivot on a presentation-signed amount column.
  • Formatting is not carried with the data; apply number formats to the whole reserved area and use conditional formatting for total rows.
  • Text months sort alphabetically — always pivot on month-end dates.
  • Large data. Above roughly 100k rows, aggregate in Power Query or the Data Model (Week 10–11) and keep GROUPBY for the summarised output.

Key takeaways

  • GROUPBY summarises by row fields; PIVOTBY cross-tabulates rows × columns; both recalculate automatically.
  • Key arguments: function (including LAMBDA), total_depth for subtotals, sort_order, and filter_array.
  • Pivot on month-end dates, not text months, for chronological columns.
  • Use them for analysis and cross-checks; build presentation P&Ls with SUMIFS grids that support calculated lines.
  • They are Microsoft 365-only — confirm recipients' Excel versions.

Practice Questions

Q1. Argument recall [L1]

Write a GROUPBY formula that shows FY26 vendor spend from Table Exp (Vendor, FY, Amount), with headers displayed, a grand total, sorted by amount descending. Then modify it to show both total spend and invoice count.

Q2. Department × month grid [L2]

The mapped GL Table GLm has Date, Dept, FSLine, Amount. Write the steps and formulas to produce a department × month expense grid for April–September 2025 only, columns in chronological order, excluding revenue lines, with row and column totals. Explain why you would add a MonthEnd column first.

💡 Hint: The filter_array can combine a date-range condition and an FS-line condition with *.

Q3. Cross-check a SUMIFS P&L [L2]

Your SUMIFS-based P&L shows total expenses of ₹212.6 crore for FY26; a PIVOTBY on the same GL shows ₹214.1 crore. List four possible causes of the ₹1.5 crore gap and the order in which you would investigate them.

Q4. Choose the tool [L3]

The CFO of an NSE-listed auto-ancillary company wants (a) a board-pack P&L in Schedule III format with comparatives, (b) an ad hoc analysis of spend by vendor and plant, and (c) a monthly cost-centre summary emailed to 40 plant managers, some on Excel 2019. For each, choose between PivotTable, GROUPBY/PIVOTBY and a SUMIFS grid, and justify the choice.

Q5. Custom aggregation [L2]

Using GROUPBY with a LAMBDA, write formulas for (a) the oldest open invoice age per customer, (b) average invoice value per branch in ₹ lakh rounded to one decimal, (c) count of invoices above ₹5 lakh per branch.
