UNIQUE for Dynamic CoA and Department Lists

Scope: UNIQUE for dynamic CoA or department lists; the exactly_once argument for one-off vendors

Why it matters

Every MIS grid has a list down the side: FS lines, ledgers, departments, cost centres, branches, vendors. If that list is typed by hand, it goes stale the day a new ledger is opened in Tally or a new cost centre appears in SAP — and the new item's amounts silently drop out of the report. UNIQUE derives the list from the data itself, so the row axis of the P&L generator is always complete. Its exactly_once option answers a different, audit-flavoured question: which vendors, customers or ledgers appear only once? One-off vendors are a classic fraud and duplicate-payment risk indicator, and one-time ledgers often signal mis-postings.

Core notes

Syntax

=UNIQUE(array, [by_col], [exactly_once])
Argument Default Meaning
array — The range, Table column or array to de-duplicate
by_col FALSE FALSE compares rows; TRUE compares columns (for horizontal data)
exactly_once FALSE FALSE returns every distinct value once; TRUE returns only values that occur exactly one time

Key behaviours:

  • Comparison is case-insensitive: "Sales" and "SALES" are treated as the same value; the first occurrence's spelling is returned.
  • Trailing spaces are significant: "Sales " and "Sales" are different. Clean with TRIM upstream (or in Power Query).
  • Order is order of first appearance, not sorted. Wrap with SORT for presentation.
  • Blanks in the source return as 0 in the output — a frequent source of a mysterious "0" line in a dynamic list.
  • Multi-column arrays return unique combinations.

Dynamic CoA / FS line list for the P&L generator

The P&L row axis is the list of FS lines that actually carry balances, in the order defined by the mapping table, not alphabetical. Two common designs:

Design A — alphabetical dynamic list

=SORT(UNIQUE(FILTER(GLm[FSLine], GLm[FSLine]<>"")))

Design B — mapping-table order (preferred for statements)

Give each FS line a sort key in the mapping table (e.g. 10 Revenue from operations, 20 Other income, 30 Cost of materials consumed, …, following Schedule III Part II order). Then:

=LET(
   lines, UNIQUE(FILTER(HSTACK(GLm[SortKey], GLm[FSLine]), GLm[FSLine]<>"")),
   CHOOSECOLS(SORT(lines, 1), 2))

GLm is the GL after XLOOKUP mapping (a Table with FSLine and SortKey columns added by formula). This produces Schedule III order and automatically adds a line when a ledger mapped to a new FS line first gets a posting.

Unique combinations

=SORT(UNIQUE(GL[[Dept]:[CostCentre]]))

Returns every Dept–Cost Centre pair actually used — useful for a two-level cost report, or to find cost centres posted under the wrong department (a cost centre appearing against two departments is a master-data issue).

Counting distinct values

=ROWS(UNIQUE(GL[Vendor]))            distinct vendors
=COUNTA(UNIQUE(FILTER(GL[Vendor], GL[Month]=H1)))   distinct vendors paid in a month

ROWS(UNIQUE(...)) replaces the old SUMPRODUCT(1/COUNTIF(...)) trick, which was slow and failed on blanks.

exactly_once for one-off vendors

=UNIQUE(AP[Vendor], , TRUE)

Returns vendors with exactly one invoice. For a richer report — vendor, invoice amount, approver — combine with FILTER and COUNTIFS:

=LET(
   once, COUNTIFS(AP[Vendor], AP[Vendor])=1,
   big, AP[Amount]>=200000,
   FILTER(CHOOSECOLS(AP, 1, 2, 4, 6), once * big, "None"))

One-off vendors paid ₹2 lakh or more are a standard internal-audit sample population: verify vendor KYC (PAN, GSTIN on the GST portal), bank account ownership and whether TDS under Sec 194C/194J was deducted.

Note the subtle difference: UNIQUE(x,,TRUE) tests occurrences in the array supplied. If you pass a two-column array (Vendor, Invoice), it finds combinations occurring once, which is almost every row. Pass only the column whose frequency you care about.

Illustration

AP register (FY26 Q4):

Vendor Invoice Amount (₹)
Shree Logistics L-77 1,20,000
Kaveri Packaging KP-12 3,40,000
Shree Logistics L-81 95,000
Om Consultants OC-1 4,75,000
shree logistics L-90 60,000
Nimbus IT NI-55 1,10,000
  • UNIQUE(AP[Vendor]) → Shree Logistics, Kaveri Packaging, Om Consultants, Nimbus IT (4 rows; the lower-case entry is merged).
  • UNIQUE(AP[Vendor],,TRUE) → Kaveri Packaging, Om Consultants, Nimbus IT.
  • One-off ≥ ₹2 lakh → Kaveri Packaging (₹3.4 lakh), Om Consultants (₹4.75 lakh).

The case-insensitivity is helpful here, but a vendor master that differs by a full stop ("Shree Logistics." ) would be counted separately — a reason to test on vendor code, not name.

UNIQUE on horizontal data

For a header row of months pasted from an ERP with repeats, =UNIQUE(B1:Z1, TRUE) de-duplicates across columns.

Edge cases & judgement calls

  • Code vs name. Always build lists on the stable key (ledger code, vendor code), then look up names. Names change; codes do not.
  • Blank → 0. Exclude blanks with FILTER(x, x<>"") before UNIQUE.
  • Mixed types. Ledger 40010 (number) and "40010" (text) appear as two items. Fix the source type.
  • Order stability. Because UNIQUE returns first-appearance order, re-sorting the GL changes the report's row order. Always impose an explicit SORT or sort-key order on outputs.
  • Lines with zero balance. UNIQUE on the TB shows ledgers whose closing balance is zero. Decide whether the P&L should show them (comparatives may need them); filter on Amount<>0 only if the comparative columns are built from the same list.
  • Inside Tables. UNIQUE cannot spill inside an Excel Table; put lists on a dedicated sheet.

Key takeaways

  • UNIQUE derives list axes from data so new ledgers, departments and cost centres appear automatically.
  • It is case-insensitive, space-sensitive, keeps first-appearance order and returns blanks as 0.
  • Use SORT, or a mapping-table sort key, to control presentation order — Schedule III order is not alphabetical.
  • exactly_once = TRUE isolates single-occurrence items such as one-off vendors; pass only the key column.
  • ROWS(UNIQUE(...)) is the clean distinct count.

Practice Questions

Q1. Distinct counts for a dashboard [L1]

Table Sales has InvoiceDate, Customer, Branch, Amount for FY26. Write formulas for (a) the number of distinct customers, (b) the number of distinct customers billed in March 2026 using date-range logic, (c) a sorted list of distinct branches, excluding blanks.

Q2. Schedule III ordered row axis [L2]

The mapping Table has Ledger, FSLine, SortKey (10, 20, 30 …). The mapped GL Table GLm has Ledger, Date, Amount, FSLine, SortKey. Write a formula that returns the FS lines with any posting in the selected FY (input cell SelFY, FY column available), in SortKey order, with no blanks. Then explain what happens to the P&L grid when a ledger mapped to "Exceptional items" receives its first posting.

Q3. One-off vendor audit sample [L2]

The FY26 AP register has 6,200 invoices across 840 vendors. Write a formula returning vendor code, vendor name, invoice number, amount and approver for vendors with exactly one invoice of ₹1 lakh or more. Then list four verification steps you would perform on the sample, referencing Indian tax/GST checks.

💡 Hint: Decide whether to use UNIQUE with exactly_once or COUNTIFS; one gives a list of names, the other a row-level flag.

Q4. Why is there a 0 and a duplicate? [L1]

=SORT(UNIQUE(GL[Dept])) returns: 0, Admin, Finance, Sales, Sales. Explain both anomalies and fix the formula and/or data.

Q5. Master-data integrity check [L3]

Using UNIQUE on Dept–CostCentre combinations, design a check that flags any cost centre posted under more than one department in the FY26 GL. Write the formula(s), describe how the output is presented to the controller, and explain why this matters for departmental budget vs actual reporting.
