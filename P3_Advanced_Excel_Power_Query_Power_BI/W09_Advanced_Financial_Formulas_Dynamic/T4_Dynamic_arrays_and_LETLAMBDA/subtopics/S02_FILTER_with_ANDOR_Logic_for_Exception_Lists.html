Subtopic note

FILTER with AND/OR Logic for Exception Lists

Scope: FILTER with AND (*) and OR (+) conditions for exception lists (unmapped accounts, overdue debtors)

Why it matters

Month-end close and audit work are exception-driven: you do not review 18,000 GL lines, you review the 40 that break a rule. Before dynamic arrays, exception lists meant AutoFilter, copy-paste to a new tab and re-doing it every month — undocumented and error-prone. FILTER turns each exception rule into a live, auditable formula: unmapped ledgers after a TB paste, debtors overdue beyond 90 days above ₹5 lakh, journal entries posted on Sundays by non-finance users, vendor payments without a PO. The formula is the control documentation, and it re-runs the instant new data is pasted.

Core notes

Syntax

=FILTER(array, include, [if_empty])
  • array — the rows (or columns) to return; can be a whole Table (GL), selected columns (CHOOSECOLS(GL,1,3,5)) or a single column.
  • include — a Boolean array the same height as array (for row filtering) or the same width (for column filtering). TRUE/non-zero rows are kept.
  • if_empty — value returned when no rows qualify. Omit it and an empty result returns #CALC!.

AND logic with *

Multiplying Boolean arrays coerces TRUE/FALSE to 1/0; the product is 1 only when every condition is 1.

=FILTER(AR, (AR[DaysOverdue]>90) * (AR[Balance]>500000), "No exceptions")

Rows with both conditions true are returned. Each bracketed comparison must be fully parenthesised — AR[DaysOverdue]>90*AR[Balance]>500000 is parsed as AR[DaysOverdue] > (90*AR[Balance]) > 500000 and produces nonsense.

OR logic with +

Adding Boolean arrays gives 0 when all are false, and 1 or 2 when at least one is true. FILTER treats any non-zero as TRUE.

=FILTER(GL, (GL[Weekday]="Sun") + (GL[Amount]>=10000000), "None")

Returns entries posted on a Sunday or of ₹1 crore and above. Because the sum can be 2, do not test =1; if you need a clean Boolean, wrap as ((a)+(b))>0.

Combining AND and OR

Use brackets exactly as in algebra: AND binds tighter in your intent, so group the OR first.

=FILTER(AR,
   ((AR[Region]="North") + (AR[Region]="East"))
   * (AR[DaysOverdue]>180),
   "None")

North or East debtors overdue beyond 180 days. For many OR values, test membership against a list instead of chaining +:

=FILTER(GL, ISNUMBER(XMATCH(GL[Account], Watchlist[Account])), "None")

Exception list 1 — unmapped ledgers

The Week 9 exercise requires every TB ledger to map to a Schedule III line. With the TB pasted into Table TB and mapping Table Map:

=FILTER(TB[[Ledger]:[Closing]],
   ISNA(XMATCH(TB[Ledger], Map[Ledger])),
   "All ledgers mapped")

Pair it with a count check that drives a red/green status cell:

=IF(SUM(--ISNA(XMATCH(TB[Ledger], Map[Ledger])))=0, "OK", "UNMAPPED")

The P&L output should display this status at the top, so no one reads a P&L that silently omits a ledger. Also filter for ledgers that are mapped but have a blank FS line (Map[FSLine]="") — mapping rows created in a hurry often have the key but no target.

Exception list 2 — overdue debtors

Given an AR Table with Customer, InvoiceNo, InvoiceDate, DueDate, Balance, and a report date in cell RptDate (a named input):

=LET(
   od, RptDate - AR[DueDate],
   keep, (od>90) * (AR[Balance]>0),
   SORTBY(FILTER(HSTACK(AR[Customer], AR[InvoiceNo], AR[Balance], od), keep, "None"),
          FILTER(AR[Balance], keep), -1))

This returns customer, invoice, balance and days overdue for every open invoice beyond 90 days, largest first. The days-overdue column is calculated inside the formula rather than as a helper column, so the report date drives everything. In Ind AS 109 expected credit loss work, the same pattern feeds the provision-matrix ageing buckets.

Worked illustration

Customer Invoice Due date Balance (₹)
Arya Retail INV-101 15-Dec-2025 6,40,000
Bharat Foods INV-118 10-Feb-2026 2,10,000
Arya Retail INV-133 28-Feb-2026 0
Chola Traders INV-140 05-Nov-2025 9,75,000

With RptDate = 31-Mar-2026, days overdue are 106, 49, 31 and 146. Rule: overdue > 90 days AND balance > ₹5 lakh → rows 1 and 4 (Chola first after sorting by balance). Changing RptDate to 30-Apr-2026 adds Bharat Foods only if its balance threshold were met — it is not, so the list stays at two rows.

Returning selected columns

Return only what the reviewer needs. Options:

  • Table column range: TB[[Ledger]:[Closing]] (contiguous columns).
  • CHOOSECOLS(FILTER(GL, cond), 2, 5, 7) (non-contiguous; filter once).
  • Filter the column array: FILTER(CHOOSECOLS(GL,2,5,7), cond) — equivalent; choose the more readable.

Horizontal FILTER

If include is a row of Booleans the same width as array, FILTER keeps columns. Use this to show only months with activity: =FILTER(PL_Grid, PL_MonthTotals<>0).

Edge cases & judgement calls

  • Size mismatch. include must have exactly as many rows as array. Mixing GL[Amount] with A2:A20000 gives #VALUE!.
  • Text-number mismatches in the key column (ledger code "40010" as text vs 40010 as number) make XMATCH fail, so a mapped ledger appears unmapped. Normalise types first.
  • if_empty text in a numeric block. "None" appears in the first column only; downstream SUM of that spill still works because text is ignored by SUM, but arithmetic like +0 will error.
  • Blank criteria cells. (GL[Dept]=H1) with H1 empty matches blank-department rows, not all rows. If you want "blank means all", use ((H1="")+(GL[Dept]=H1)).
  • Performance. FILTER over 200k rows with several conditions recalculates on every change; beyond roughly 100k rows prefer Power Query (Week 10).
  • Materiality. Exception rules need thresholds agreed with the controller; too-low thresholds create review fatigue.

Key takeaways

  • * between bracketed conditions is AND; + is OR; non-zero means include.
  • Always supply if_empty in production reports to avoid #CALC!.
  • Membership tests (ISNUMBER(XMATCH(...)) or ISNA(...)) scale better than long OR chains.
  • Exception lists should sit beside a count/status cell so the report shows "OK" or a failure flag.
  • Calculate derived columns (days overdue) inside LET/FILTER so a single date input drives the report.

Practice Questions

Q1. Write the AND/OR filters [L1]

Table JE has columns EntryNo, PostDate, User, Account, Amount, Weekday. Write FILTER formulas to return: (a) entries by users "temp01" or "temp02"; (b) entries above ₹25 lakh posted on Saturday or Sunday; (c) entries to accounts 410000–419999 (numeric codes) by any user other than "finctrl". Each must return "None" if empty.

Q2. Unmapped ledger control [L2]

A Tally TB of 512 ledgers is pasted into Table TB (Ledger, Group, Closing). The mapping Table Map has 498 rows (Ledger, FSLine, ScheduleIIILine); 3 mapping rows have a blank FSLine and 2 Map ledgers no longer exist in the TB. Design three exception lists and one status cell that together catch every mapping defect, and state which defect each list catches.

💡 Hint: Think in both directions — TB-to-Map and Map-to-TB — plus completeness of the target field.

Q3. Overdue debtor report driven by a date [L2]

Using an AR Table (Customer, InvoiceDate, CreditDays, Balance) and a report date input, build a single LET formula returning customer, balance and days overdue for invoices more than 60 days past due and balance over ₹1 lakh, sorted by days overdue descending. Due date = InvoiceDate + CreditDays. Explain why you did not add a helper column to the Table.

Q4. Debug the filter [L2]

=FILTER(GL, GL[Dept]="Sales"+GL[Dept]="Marketing"*GL[Amount]>50000) returns #VALUE!. Explain the operator-precedence problem step by step and write the corrected formula.

Q5. Audit analytics design [L3]

As an internal auditor at an NSE-listed FMCG company, you must design five journal-entry exception tests for the FY26 GL (about 2.4 lakh lines) using FILTER. List the tests, the Boolean logic for each, the threshold you would propose and why, and explain at what data size you would move these tests into Power Query instead.
