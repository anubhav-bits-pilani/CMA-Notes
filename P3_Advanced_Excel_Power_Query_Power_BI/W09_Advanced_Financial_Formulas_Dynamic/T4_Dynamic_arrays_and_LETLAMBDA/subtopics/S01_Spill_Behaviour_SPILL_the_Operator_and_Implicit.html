Spill Behaviour, #SPILL!, the # Operator and Implicit Intersection

Scope: Spill behaviour, #SPILL! errors, the spill reference operator # and implicit intersection @

Why it matters

Every self-updating schedule you build this week — a dynamic CoA list, an unmapped-ledger exception report, a 12-month header row, a top-10 vendor table — depends on one formula returning many values into neighbouring cells. That is spilling. If you do not understand how a spill range is sized, what blocks it and how other formulas should point at it, you will build reports that silently truncate when the GL grows, or that break with #SPILL! the moment a colleague types a note in the wrong cell. Implicit intersection (@) matters for the opposite reason: legacy workbooks from Excel 2016/2019 open in Microsoft 365 with @ sprinkled through them, and you must know whether removing it will change results before you "clean up" a client's model.

Core notes

What spilling is

In Microsoft 365 (and Excel 2021+), the calculation engine is array-native. Any formula that evaluates to more than one value writes the whole result into a rectangular block starting at the formula cell. Only the top-left cell (the anchor) holds the formula; the other cells show the values in grey "ghost" formula text in the formula bar and cannot be edited individually.

  • =UNIQUE(GL[Dept]) in H2 returns, say, 9 departments into H2:H10.
  • =GL[Amount]*1.18 in a cell outside the Table spills the full column of grossed-up amounts.
  • =SEQUENCE(1,12) spills horizontally across 12 columns.

The spill range resizes automatically on each recalculation: add a tenth department to the GL Table and the UNIQUE output becomes H2:H11 with no edit. This is the property that removes manual filters and copy-down from MIS packs.

The #SPILL! error and its causes

Excel computes the size of the result first, then checks whether the destination block is free. If not, the anchor shows #SPILL! and the yellow warning icon tells you which cause applies. Clicking "Select Obstructing Cells" jumps to the blocker.

Cause Typical finance scenario Fix
Spill range isn't blank A hard-typed subtotal or note sits below a FILTER exception list Move the output to a dedicated area or delete the obstruction; reserve blank rows/columns
Spill range in a Table FILTER written inside the GL Table's calculated column Place dynamic arrays outside Tables; convert the destination Table to a range if needed
Spill range unknown / volatile size A formula wrapped in RANDARRAY or OFFSET whose size keeps changing between passes Remove the volatile sizing; make size deterministic
Spill range too big =A:A*2 written in row 2 would need 1,048,576 rows from row 2 Point at the Table column or a bounded range, not the whole column
Merged cells The report template has merged title cells in the spill path Unmerge; use Centre Across Selection instead
Out of memory Huge cross-joins (e.g. 50,000 × 50,000 comparisons) Reduce dimensionality or move to Power Query

A single space typed into a cell counts as an obstruction, which is why "the cells look empty" is never a defence. Use Go To Special → Constants on the destination area to find them.

The spill reference operator #

Once a formula spills, refer to its entire, current output with the anchor address followed by #:

=SUM(H2#)                       total of whatever UNIQUE returned
=COUNTA(H2#)                    number of departments currently listed
=SUMIFS(GL[Amount], GL[Dept], H2#)   one SUMIFS per department, spills alongside
=XLOOKUP(H2#, Map[Dept], Map[Head])  looks up every department at once

H2# grows and shrinks with the spill. Pointing at H2:H10 instead freezes the reference at today's size: when the tenth department arrives, it is excluded from totals with no error. The # operator works in charts' series ranges via a defined name (e.g. name DeptList =Sheet1!H2#), in Data Validation list sources, in conditional formatting "Applies to" logic through formulas, and inside other dynamic functions.

You can also reference a column or row within a spilled block by combining with INDEX or CHOOSECOLS:

=INDEX(K2#, , 3)                third column of a multi-column spill
=CHOOSECOLS(K2#, 1, 4)          first and fourth columns
=TAKE(K2#, -1)                  last row of the spill (e.g. latest month)

Implicit intersection and the @ operator

Before dynamic arrays, a formula like =GL[Amount] typed in row 7 outside the Table returned the single value from row 7 — Excel "implicitly intersected" the range with the formula's row. Legacy Excel did this silently whenever a function expected a single value but received a range.

Dynamic Excel instead spills by default, so to keep old workbooks calculating identically, Microsoft 365 inserts @ wherever the legacy formula relied on implicit intersection. Examples:

Legacy formula (Excel 2016) Opened in Microsoft 365 Meaning
=A2:A10 in row 5 =@A2:A10 Return A5 only
=INDEX(Rates, 0, 2) returning a column =@INDEX(Rates, 0, 2) Single value (intersection)
A user-defined VBA function returning a range =@MyFunc(x) Single value

Inside Tables, [@Amount] is the structured-reference version of the same idea — "this row's Amount". That is a deliberate, correct use.

Rules for practitioners:

  1. Do not blindly delete @ from inherited models. Removing it changes =@A2:A10 from one value into a 9-row spill, which may throw #SPILL! or, worse, spill into empty cells and alter totals.
  2. If you type @ in front of a function that already returns one value, it does nothing.
  3. If you share a dynamic-array formula with an Excel 2019 user, their Excel shows it as a legacy CSE array formula {=…} sized to the spill at save time — it will not resize on their machine.

Illustration: department expense summary

GL Table has 18,400 lines for FY26 across 9 departments.

Cell Formula Result
H2 =SORT(UNIQUE(GL[Dept])) 9 departments, H2:H10
I2 =SUMIFS(GL[Amount], GL[Dept], H2#) 9 totals, I2:I10
J2 =I2#/SUM(I2#) share of total, J2:J10
I12 =SUM(I2#) ₹48.6 crore, ties to TB expense total

In April FY27 the "ESG" department is created. After pasting the new GL rows into the Table, all four outputs extend to 10 rows. If I12 had been =SUM(I2:I10), ESG's ₹0.4 crore would be missing and the check cell against the TB would fail — that failure is exactly what a TB tie-out check is designed to catch.

Layout discipline

Put each spilling formula in its own reserved block with a header above it and nothing below or to the right within the maximum plausible size. A common convention is a dedicated "Calc" or "Lists" sheet holding all UNIQUE/SEQUENCE outputs, and output sheets that reference them via #. Leave at least one empty column between side-by-side spills so one cannot block another when it widens.

Edge cases & judgement calls

  • Totals below a spill. You cannot place a hard total row immediately under a spill because the spill may grow into it. Either put totals above the list, or append the total inside the formula with VSTACK(list, HSTACK("Total", SUM(...))).
  • Sorting or filtering a spill with the ribbon is not possible; the user must change the formula. Educate report consumers or provide parameter cells.
  • Copy-paste values of a spill produces a static block — fine for archived month-end packs, wrong for live models. Label archived tabs clearly.
  • # on a non-spilling cell returns #REF!. If the anchor cell's formula is edited to return a single value, every dependent # reference breaks.
  • Charts cannot take H2# directly in the series box; use a defined name whose Refers To is the spill reference.
  • Excel for the web and Mac support spills identically in Microsoft 365, but Excel 2019 perpetual does not; recipients see static CSE arrays.

Key takeaways

  • A spilling formula lives only in the anchor cell; the spill range resizes on every recalculation.

  • SPILL! has a finite list of causes — obstruction, Table, merged cells, unknown size, too big — and each has a layout fix.

  • Always reference spills with anchor#, never a fixed range, so downstream totals self-update.
  • @ forces single-value implicit intersection; it is inserted to preserve legacy behaviour and should not be deleted without testing.
  • Reserve dedicated, obstruction-free zones for dynamic arrays and keep them outside Excel Tables.

Practice Questions

Q1. Diagnose five #SPILL! errors [L1]

A colleague's MIS workbook shows #SPILL! in five places: (a) =FILTER(GL, GL[Mapped]="No") in A20, with a "Reviewed by" note typed in C25; (b) =UNIQUE(GL[Vendor]) typed in the first row of a new column inside the GL Table; (c) =SEQUENCE(1,12) in B3, with B3:M3 merged for a title; (d) =D:D*1.18 in E2; (e) =SORTBY(Exp[Vendor], RANDARRAY(ROWS(Exp[Vendor]))) that flickers between sizes. For each, state the cause shown in the warning menu and the fix.

Q2. Fixed range versus spill reference [L2]

UNIQUE in H2 lists 14 cost centres (H2:H15). Column I has =SUMIFS(GL[Amount], GL[CC], H2:H15) and I17 has =SUM(I2:I15). Next month two new cost centres with expenses of ₹6.2 lakh and ₹3.8 lakh are added to the GL. Describe exactly what the output shows, what the TB tie-out check shows, and rewrite both formulas so the issue cannot recur.

Q3. Inherited model with @ symbols [L2]

You open a 2018-built forecasting model in Microsoft 365 and see =@Rates in E10:E30, where Rates is a named range D10:D30, and =@INDEX(Assumptions, 0, 3) in F5. Explain what each formula returns now, what would happen if you deleted the @ in each, and how you would test the change safely before saving.

💡 Hint: Think about which row each formula sits in and whether the named range intersects it.

Q4. Totals for a growing list [L3]

Design a department expense summary where the department list, amounts and a grand total row all live in one self-sizing block, so that nothing can ever obstruct the spill. Write the formula(s) and explain how you would reference just the amount column of the block in a separate check cell that compares it with the TB expense total.

Q5. Interview: explain spilling to a manager [L1]

In under 100 words, explain to a finance manager who uses Excel 2016 why the department list you send in a Microsoft 365 workbook "won't update" on their machine, and what they would see in the formula bar.
