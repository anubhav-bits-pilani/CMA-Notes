Two-Way Lookups on Account × Month Grids

Scope: Two-way lookups on account × month grids: nested XLOOKUP and INDEX-MATCH-MATCH

Why it matters

Finance data often arrives as a matrix rather than a list: a budget file with accounts down and months across, a TB-by-month export from Tally (Columnar Trial Balance), a rate card with tenure across and credit grade down, or a monthly forecast template from each business unit. A two-way lookup retrieves the value at the intersection of a row key and a column key. It is how a BvA report pulls the budget for "Rent – Mumbai" in "Nov-25", how a model reads an interest rate for a 36-month loan at grade B, and how an analyst re-arranges someone else's grid into their own layout without copy-paste. Two patterns dominate: nested XLOOKUP and INDEX-MATCH-MATCH; both are standard interview material.

Core notes

The setup

Source grid on sheet Budget: account codes in Budget!A6:A85 (named Codes), month-start dates in Budget!C4:N4 (named Months), values in Budget!C6:N85 (named Data). The report sheet has account codes in column A and month headers in row 4.

Pattern 1 — INDEX-MATCH-MATCH

=INDEX(Data,
       MATCH($A5, Codes, 0),
       MATCH(C$4, Months, 0))
  • The first MATCH returns the row position of the account within Codes.
  • The second MATCH returns the column position of the month within Months.
  • INDEX returns the cell at that row and column of Data.

Requirements: Codes must have the same number of rows as Data, and Months the same number of columns; all three must be aligned (start on the same row/column). The 0 in each MATCH is essential — MATCH defaults to approximate match (1).

Strengths: works in every Excel version, is non-volatile, and is fast because each MATCH is computed once per cell. INDEX can also return a whole row (INDEX(Data, r, 0)) or column (INDEX(Data, 0, c)).

Pattern 2 — nested XLOOKUP

=XLOOKUP($A5, Codes,
   XLOOKUP(C$4, Months, Data))
  • The inner XLOOKUP searches the month header row and returns the entire matching column of Data (an 80-row vertical array), because Data has 80 rows and the lookup is along its columns.
  • The outer XLOOKUP searches the account codes and returns the matching element from that column.

The order can be reversed — inner lookup on accounts returning a row, outer on months — with the same result. Add if_not_found arguments to make misses visible: "No acct" on the outer, "No month" on the inner.

Comparison

Aspect INDEX-MATCH-MATCH Nested XLOOKUP

Header data types

Two-way lookups fail most often on the column key. If the source grid's headers are text ("Apr-25") and the report headers are dates (01-Apr-2025), nothing matches. Options: convert the source headers to real dates (DATEVALUE("1-"&…) or Power Query), or look up TEXT(C$4,"mmm-yy") against text headers — fragile, since it depends on exact spelling. Headers built with EOMONTH/SEQUENCE on both sides are the robust answer. Similarly, if one grid uses month-start dates and the other month-end dates, normalise with EOMONTH(…,0) on both.

Worked illustration

Budget grid (₹ lakh):

Code Apr-25 May-25 Jun-25
610100 Salaries 82.0 82.0 86.5
640500 Rent 21.0 21.0 21.0
650200 Travel 6.4 7.1 5.8

Report row A5 = 650200, header C4 = 01-May-2025:

  • MATCH(650200, Codes, 0) = 3; MATCH(01-May-2025, Months, 0) = 2; INDEX(Data, 3, 2) = 7.1.
  • Inner XLOOKUP(01-May-2025, Months, Data) returns {82.0; 21.0; 7.1}; outer XLOOKUP for 650200 returns 7.1.

If MATCH were written without the 0 and the codes were not sorted, the row position could be wrong with no error — for instance, returning the Rent row.

Two-way lookups with a third key

Grids by entity or scenario are often stacked (one block per entity). Either:

  • add the entity to the row key (concatenated helper key "MUM|650200") — see multi-key lookups; or
  • use CHOOSE/XLOOKUP to select the block first, then the two-way lookup inside it; or
  • better, unpivot all grids into one long Table (Power Query → Unpivot Columns) and use SUMIFS with three criteria. Long format is the modelling-friendly shape; two-way lookups are for consuming grids you do not control.

SUMIFS vs two-way lookup

When the source is a long table (Account, Month, Amount), use SUMIFS, not a lookup — it aggregates duplicates and returns 0 for no data. Two-way lookups are for grids where each intersection holds exactly one value.

Edge cases & judgement calls

  • Merged or multi-row headers in received templates break MATCH; build a clean header row above the grid.
  • Blank intersections return 0 from INDEX (a reference to an empty cell), which may be read as "budget is zero" when it is "not provided". Test with ISBLANK(INDEX(…)) if the distinction matters.
  • Inserted columns in the source do not break either pattern as long as Months and Data are named ranges or Table references that expand together.
  • Duplicate row keys (the same code twice in a budget file) silently return the first; check with COUNTIF.
  • Whole-grid references across workbooks are fragile; import the grid via Power Query into the model workbook.

Key takeaways

  • INDEX-MATCH-MATCH: two positions feed one INDEX; always use match type 0.
  • Nested XLOOKUP: the inner lookup returns a whole column (or row), the outer picks the element.
  • Ranges must be aligned: row keys with data rows, column keys with data columns.
  • Mismatched header types (text vs date, month-start vs month-end) are the main failure cause.
  • Use two-way lookups for grids you receive; reshape to long format and use SUMIFS for data you control.

Practice Questions

Q1. Write both patterns [L1]

A rate card has loan tenures (12, 24, 36, 48, 60 months) in C3:G3, credit grades (A, B, C, D) in B4:B7 and rates in C4:G7. Write an INDEX-MATCH-MATCH and a nested XLOOKUP that return the rate for the grade in J2 and tenure in K2.

Q2. Budget pull into a BvA report [L2]

The FY26 budget workbook has 140 MIS lines down and month headers stored as text "Apr-25" … "Mar-26". Your BvA report has month-start dates as headers. Explain two ways to make a two-way lookup work, write the formula for one, and recommend which is more robust for a monthly process.

💡 Hint: Either convert one side's headers or convert at lookup time; consider which survives a template change.

Q3. Approximate tenure lookup [L2]

Using the rate card from Q1, a loan of 30 months should use the 24-month rate (the next lower tenure). Modify both formulas so the tenure lookup is approximate and the grade lookup exact, and state any sorting requirement each version imposes.

Q4. Stacked entity grids [L3]

A group consolidation file has three subsidiaries' monthly P&L grids stacked one below another on one sheet, each 45 lines × 12 months with the entity name above each block. Propose two approaches to retrieve the value for a given entity, line and month — one formula-based and one using Power Query — and discuss maintainability when a fourth subsidiary is added.

Q5. Interview: why the wrong row? [L1]

An interviewer shows =INDEX(Data, MATCH(A5, Codes), MATCH(C4, Months, 0)) returning the Rent budget for the Travel account. Explain the cause and the fix.
