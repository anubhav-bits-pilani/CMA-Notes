Subtopic note

Reverse Search for Latest Price, FX Rate and Last Payment Date

Scope: Reverse search (last-to-first) for latest price, latest FX rate and last payment date

Why it matters

Transaction logs are chronological: purchase registers, price lists with effective dates, RBI reference-rate or bank card-rate histories, vendor payment ledgers. Finance questions about them are usually "as at" questions: what is the latest purchase price of this SKU (for inventory valuation sanity checks or standard-cost updates), which FX rate applies to restate this foreign-currency payable at month-end (Ind AS 21 closing rate), when did this customer last pay (for credit-hold decisions and expected-credit-loss staging). A standard lookup returns the first match — the oldest record. Reverse search returns the last, and combined with a date condition it returns the latest record on or before any cut-off date.

Core notes

XLOOKUP with search_mode -1

=XLOOKUP(F2, Px[SKU], Px[Rate], "No price", 0, -1)

search_mode -1 scans from the bottom of the lookup array upward and stops at the first match it meets — i.e. the last occurrence in the data. This gives the latest record only if the data is in chronological order (oldest at the top). If the log is appended monthly by pasting below, that holds; if the data is sorted by anything else, reverse search returns "the bottom-most", not "the latest".

Latest record regardless of sort order

When row order cannot be trusted, find the maximum date first, then look up the row with both conditions:

=LET(d, MAXIFS(Px[Date], Px[SKU], F2),
     XLOOKUP(1, (Px[SKU]=F2)*(Px[Date]=d), Px[Rate], "No price"))

If several rows share the maximum date (two purchases on the same day at different rates), XLOOKUP returns the first such row — decide whether the business wants the first, last, or the average, and document it.

Latest on or before a cut-off date

Month-end restatement under Ind AS 21 uses the closing rate at the reporting date. If 31 March is a holiday or weekend with no published rate, the convention is usually the last available rate on or before that date (confirm the entity's policy — some use the bank's rate on the date):

=XLOOKUP(1, (FX[Ccy]="USD")*(FX[Date]<=RptDate), FX[Rate], "No rate", 0, -1)

The boolean array marks every USD row dated on or before the cut-off; reverse search on a chronological table returns the last of them. On a single-currency table sorted by date, approximate match is an alternative:

=XLOOKUP(RptDate, USD[Date], USD[Rate], "No rate", -1)

match_mode -1 finds the exact date or the next earlier date, independent of sort order (linear search).

Last payment date

From a customer receipts Table Rcpt (Customer, Date, Amount):

=MAXIFS(Rcpt[Date], Rcpt[Customer], $A5)

MAXIFS is the simplest answer for a date — no sort assumption. Remember it returns 0 when the customer has never paid; guard with COUNTIFS. To get the amount of the last payment, use the reverse-search XLOOKUP or the MAXIFS-then-XLOOKUP pattern above.

Legacy pattern: LOOKUP(2, 1/…)

Before XLOOKUP, the "last match" idiom was:

=LOOKUP(2, 1/(Px[SKU]=F2), Px[Rate])

1/(condition) produces 1 for matches and #DIV/0! otherwise; LOOKUP looking for 2 in an array of 1s and errors ignores the errors and returns the position of the last 1. It works in all versions without Ctrl+Shift+Enter, and you will meet it in inherited models — but it is opaque, so replace it with XLOOKUP where all users have Microsoft 365 or Excel 2021+.

Worked illustration

Purchase price log for SKU "PKG-12" (chronological):

Date SKU Vendor Rate (₹/unit)
08-Jan-2026 PKG-12 Shree Packaging 18.40
21-Feb-2026 PKG-12 Shree Packaging 18.90
14-Mar-2026 PKG-12 Pune Cartons 19.25
06-Apr-2026 PKG-12 Shree Packaging 19.10
  • Latest price overall (reverse search): ₹19.10.
  • Latest price on or before 31-Mar-2026 (boolean + reverse search): ₹19.25 — this is the relevant figure for checking net realisable value or replacement-cost tests at the FY26 balance sheet date.
  • First price (default search): ₹18.40 — what a plain VLOOKUP would have returned.

FX example: USD/INR reference rates for 27-Mar-2026 (Fri) = 85.62 and 30-Mar-2026 (Mon) = 85.71, with 31-Mar-2026 assumed to be a holiday in this illustration. The on-or-before lookup for 31-Mar-2026 returns 85.71; a USD 2,40,000 payable is restated at ₹2,05,70,400.

Building it into a model

  • Keep price and FX histories as Tables appended at the bottom (or loaded by Power Query sorted by date ascending, with a sort step you can see).
  • Put the cut-off date in one named input (RptDate) so every "as at" lookup uses the same date.
  • Add a sort check such as =AND(DROP(Px[Date],1)>=DROP(Px[Date],-1)) (TRUE only if every date is on or after the one above it), or simply prefer the MAXIFS + boolean pattern when order is not guaranteed.

Edge cases & judgement calls

  • Back-dated entries appended at the bottom break the "bottom = latest" assumption; reverse search returns the back-dated record. Use the date-based pattern.
  • Multiple records on the same date. Decide on first/last/average; reverse search returns the bottom-most.
  • Cut-off with no prior record (a new SKU first bought after the reporting date) returns the not-found value — make it visible ("No price at cut-off").
  • Ind AS 21 policy. The closing rate is the spot rate at the end of the reporting period; the source (RBI reference rate, FBIL, bank rate) should be consistent with policy and applied consistently across months.
  • Text dates in imported histories make the date comparisons fail silently; validate with COUNT vs ROWS.

Key takeaways

  • search_mode -1 returns the last occurrence — the latest record only if the data is chronological.
  • For robustness, combine MAXIFS (latest date) with a two-condition XLOOKUP.
  • "Latest on or before a cut-off" = boolean condition on the date plus reverse search, or match_mode -1 on a date column.
  • MAXIFS alone is best for last payment date; reverse search retrieves the related amount.
  • LOOKUP(2, 1/condition, result) is the legacy last-match idiom you will see in older models.

Practice Questions

Q1. Latest vendor rate [L1]

Table PO has PODate, Vendor, Item, Rate and is appended chronologically. Write formulas for (a) the latest rate for the item in B2 from any vendor, (b) the latest rate for that item from the vendor in C2, and (c) the date of that latest purchase.

Q2. Month-end FX restatement [L2]

Table FX holds daily USD, EUR and GBP to INR rates from 01-Apr-2025 (Date, Ccy, Rate), but rates are missing for weekends and bank holidays. Foreign-currency payables at 31-Mar-2026 are USD 3,80,000 and EUR 1,15,000. Write the lookup formulas that return the applicable closing rates, compute the restated INR balances, and explain how your formula behaves if 31-Mar-2026 has a published rate.

💡 Hint: A boolean on currency and date, combined with last-to-first search, handles both cases with one formula.

Q3. Unsorted log trap [L2]

A price log is sorted by vendor name, not date. Explain what XLOOKUP(F2, Px[SKU], Px[Rate], , 0, -1) returns and write a sort-independent formula that returns the latest price for the SKU.

Q4. Credit-hold flag [L2]

For each customer in a credit-control sheet, build formulas returning the last receipt date, the amount of that receipt and a flag "HOLD" if no receipt has been received in the last 60 days while the customer has open invoices. Data: Table Rcpt (Customer, Date, Amount), Table AR (Customer, Status, Amount), RptDate.

Q5. Decode a legacy formula [L1]

An inherited model contains =LOOKUP(2,1/((Data!B2:B9000=A5)*(Data!D2:D9000<=CutOff)),Data!E2:E9000), where CutOff is a named date cell. Explain step by step what it returns and rewrite it with XLOOKUP.
