Multi-Key Lookups: Helper Keys vs Boolean Arrays

Scope: Multi-key lookups: concatenated helper keys vs boolean arrays inside XLOOKUP

Why it matters

Real finance keys are compound. A budget is unique only by Branch + Ledger + Month; a TDS rate by Section + Payee type; a standard cost by Plant + SKU; an intercompany balance by Entity + Counterparty + Account. A single-column lookup returns the first row for "Rent" — perhaps the Mumbai branch when you wanted Pune. Two techniques solve this: build a concatenated helper key column, or pass a boolean array of conditions directly to XLOOKUP. Knowing both, and when each fails, is essential for consolidation work, budget-vs-actual reports and reconciliation files.

Core notes

Technique 1 — concatenated helper key

Add a calculated column in the source Table:

=[@Branch]&"|"&[@Ledger]

Then look up the same concatenation:

=XLOOKUP(B2&"|"&C2, T[Key], T[Amount], "No match")

Design rules:

  • Use a delimiter (|) that cannot occur in the data. Without it, "AB"&"C" and "A"&"BC" both give "ABC" — a false match. With numeric parts, "1"&"23" and "12"&"3" collide.
  • Normalise types: concatenation converts numbers and dates to text; a date becomes its serial ("45748"), so build the lookup side the same way. Use TEXT(date,"yyyy-mm") on both sides if you want readable keys.
  • Trim and clean both sides (TRIM, consistent case is not needed — XLOOKUP is case-insensitive).
  • Test uniqueness: =COUNTIF(T[Key],[@Key])>1 flags duplicate compound keys.

Strengths: fast (a single exact-match lookup), works in every Excel version with VLOOKUP/INDEX-MATCH too, visible and auditable, and the same key can feed COUNTIFS, SUMIFS and Power Query merges. Weakness: needs a column in the source, which you may not control.

Technique 2 — boolean array inside XLOOKUP

=XLOOKUP(1, (T[Branch]=B2)*(T[Ledger]=C2), T[Amount], 0)

Mechanics:

  1. (T[Branch]=B2) produces an array of TRUE/FALSE, one per row.
  2. (T[Ledger]=C2) produces another.
  3. Multiplying them coerces TRUE/FALSE to 1/0 and gives 1 only where both are TRUE (AND logic).
  4. XLOOKUP searches this 1/0 array for the value 1 and returns the corresponding Amount.

Variants:

  • OR logic: add instead of multiply and test for a positive value: XLOOKUP(1, --(((T[Branch]="MUM")+(T[Branch]="PUN"))>0), …).
  • Range conditions: (T[Date]<=RptDate) inside the product, combined with search_mode -1 for "latest on or before".
  • Last match: XLOOKUP(1, (…)*(…), T[Amount], 0, 0, -1).
  • Legacy equivalent: INDEX(T[Amount], MATCH(1, (T[Branch]=B2)*(T[Ledger]=C2), 0)), which needs Ctrl+Shift+Enter in Excel 2019 and earlier.

Strengths: no helper column, conditions can include operators and functions, easy to extend. Weaknesses: each formula evaluates the full arrays (slower over many cells and large Tables), and it is less transparent to non-specialist reviewers.

Choosing between them

Factor Helper key Boolean array
Speed with 1,000+ lookup cells on 1 lakh rows fast slow
Source Table editable? required not required
Range or inequality conditions no yes
Excel 2016/2019 compatibility yes only via INDEX-MATCH array formula
Auditability high (key visible) medium
Reuse in SUMIFS/Power Query yes no

Practitioner default: helper keys for high-volume recurring mappings (budget pulls, consolidations); boolean arrays for ad-hoc, few-cell lookups and conditions involving dates or thresholds.

Lookup or SUMIFS?

If the compound key may legitimately appear more than once (several postings for Branch + Ledger in a month) a lookup returns only the first; SUMIFS aggregates all. Use a lookup to retrieve an attribute (a rate, a mapping, a name) and SUMIFS to aggregate amounts. A lookup on amounts is only correct when the key is guaranteed unique — test it.

Worked illustration

Budget Table Bud (₹):

Branch Ledger Month Amount Key
MUM Rent 01-Apr-2025 4,50,000 MUM|Rent|45748
PUN Rent 01-Apr-2025 2,10,000 PUN|Rent|45748
PUN Power 01-Apr-2025 1,35,000 PUN|Power|45748
  • Single-key XLOOKUP("Rent", Bud[Ledger], Bud[Amount]) → ₹4,50,000 (Mumbai) — wrong for Pune.
  • Helper key XLOOKUP("PUN|Rent|"&C3, Bud[Key], Bud[Amount], 0) with C3 = 01-Apr-2025 → ₹2,10,000.
  • Boolean XLOOKUP(1, (Bud[Branch]="PUN")*(Bud[Ledger]="Rent")*(Bud[Month]=C3), Bud[Amount], 0) → ₹2,10,000.

Implementation details that matter

  • A blank condition value (C2 empty) matches rows with blank ledgers — guard with IF(C2="", "", …).
  • In the boolean form, comparing to a numeric cell where the column contains numbers stored as text gives FALSE everywhere; clean types first.
  • Return 0 as if_not_found only for amounts where "no budget" genuinely means zero; for rates or mappings return a visible flag.
  • For three or more keys, the helper-key approach scales better: one key column, one lookup.

Edge cases & judgement calls

  • Delimiter collisions — choose a character absent from all key parts; check with COUNTIF(T[Branch],"*|*").
  • Duplicate compound keys (two budget lines for PUN | Rent) silently return the first; COUNTIFS on all key parts should equal 1.
  • Date keys typed as text in one source and real dates in another never match; normalise in Power Query.
  • Performance — 5,000 boolean-array lookups over a 2 lakh-row Table can take tens of seconds per recalc; switch to helper keys or a Power Query merge.
  • Case sensitivity — both techniques are case-insensitive; codes that differ only by case ("Ab1" vs "AB1") need EXACT inside the boolean array.

Key takeaways

  • Compound keys need either a delimiter-joined helper key or a boolean product inside XLOOKUP.
  • Always use a delimiter in helper keys, normalise types and test uniqueness.
  • XLOOKUP(1, (cond1)*(cond2), return) gives AND logic; addition with >0 gives OR logic.
  • Helper keys are faster and reusable; boolean arrays handle inequalities and need no source changes.
  • Use lookups for attributes and unique keys; use SUMIFS when the key can repeat.

Practice Questions

Q1. Standard cost by plant and SKU [L1]

Table Std has Plant, SKU, EffectiveFrom, StdCost. Write (a) a helper-key column and lookup for the standard cost of the plant in B2 and SKU in C2, ignoring dates, and (b) a boolean-array XLOOKUP that returns the latest standard cost effective on or before the date in D2.

💡 Hint: For (b), combine three conditions and search last-to-first on a Table sorted by EffectiveFrom.

Q2. Delimiter collision [L2]

A helper key =[@Entity]&[@Account] is used in a consolidation file where entity codes are "1", "12", "120" and account codes are 4–6 digits. Construct an example of two different entity–account pairs that produce the same key, explain the consequence for intercompany elimination, and fix the key.

Q3. Intercompany matching [L2]

Entity A's ledger shows receivables from B, C and D by account; each counterparty's ledger shows payables to A. Design lookups that pull the counterparty's matching balance for each row (keys: Entity, Counterparty, Account mapping) and flag differences above ₹10,000. Explain which technique you would use for 3,000 rows and why.

Q4. Lookup vs SUMIFS [L1]

Explain why XLOOKUP(1, (GL[Branch]=B2)*(GL[Ledger]=C2), GL[Amount]) understates November rent for a branch with three rent postings in November, and write the correct formula.

Q5. Performance redesign [L3]

A BvA workbook has 6,800 boolean-array XLOOKUPs against a 1.6 lakh-row budget Table and takes 45 seconds to recalculate. Propose a redesign (helper keys, Power Query merge, or SUMIFS), estimate the effect on calculation load qualitatively, and list the checks you would add to prove the redesigned numbers equal the old ones.
