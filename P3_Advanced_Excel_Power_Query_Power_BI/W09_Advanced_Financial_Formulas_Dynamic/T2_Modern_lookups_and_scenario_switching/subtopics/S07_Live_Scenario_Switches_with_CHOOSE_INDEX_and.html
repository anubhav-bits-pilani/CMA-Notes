Subtopic note

Live Scenario Switches with CHOOSE, INDEX and SWITCH

Scope: Scenario switches (Base / Upside / Downside) with CHOOSE, INDEX or SWITCH driven by a dropdown cell

Why it matters

Every budget, forecast, DCF and lender model has to answer "what if things go better or worse?". The professional answer is a live scenario switch: a single dropdown on the cover or assumptions sheet that re-points every driver to the chosen case, so the whole three-statement model, valuation and covenant tests recalculate instantly. Unlike Scenario Manager (which pastes static values) the switch is transparent, auditable and compatible with Data Tables — you can even run a Data Table over the scenario index to show all cases side by side. It is a staple of banking and FP&A models and a frequent model-test task.

Core notes

Architecture

  1. Scenario list — a small Table or named range ScenList = {Base; Upside; Downside}.
  2. Selector cell — Scenario, a Data Validation list dropdown sourced from ScenList, placed on the cover/control sheet, formatted as an input.
  3. Index cell — ScenIdx =XMATCH(Scenario, ScenList) (or MATCH(Scenario, ScenList, 0)), returning 1, 2 or 3.
  4. Case block — for each driver, one column per scenario on the assumptions sheet.
  5. Live column — a column beside the case block that picks the active value; all model formulas reference only the live column.
Driver Live Base Upside Downside
Volume growth (formula) 8.0% 12.0% 3.0%
Realisation growth (formula) 4.0% 5.5% 1.5%
Gross margin (formula) 38.0% 40.0% 34.0%
Debtor days (formula) 55 50 68

Separating the live column from the case columns is the key discipline: model calculations never point directly at Base/Upside/Downside cells, so adding a scenario changes only the selector logic.

Option 1 — CHOOSE

=CHOOSE(ScenIdx, D6, E6, F6)

CHOOSE returns the index_num-th value from its list (up to 254 values). It is explicit and easy to read for three cases. Weaknesses: adding a fourth scenario means editing every live formula; an index outside 1–3 returns #VALUE!; and a non-integer index is truncated (2.7 → 2).

CHOOSE can also return ranges: =SUM(CHOOSE(ScenIdx, Base_Rev, Up_Rev, Down_Rev)) sums the chosen named range — useful for switching whole rows.

Option 2 — INDEX (or INDEX-XMATCH)

=INDEX(D6:F6, ScenIdx)

INDEX over the case row picks the column by position. Adding a scenario column inside the block (and extending the range) needs no formula change if the block is a named range or Table. With headers, avoid the index cell entirely: =INDEX(D6:F6, XMATCH(Scenario, D5:F5)), or =XLOOKUP(Scenario, D5:F5, D6:F6). This is the most scalable option for models with many scenarios.

Option 3 — SWITCH

=SWITCH(Scenario, "Base", D6, "Upside", E6, "Downside", F6, NA())

SWITCH matches the scenario name directly, so no index cell is needed, and the final default (NA()) makes an invalid selection loud. Like CHOOSE, it must be edited for every new scenario; it is readable for short lists.

Comparison

Criterion CHOOSE INDEX / XLOOKUP SWITCH
Driven by index number index or header name scenario name
Adding a scenario edit every formula extend the block only edit every formula
Invalid selection #VALUE! #REF! / #N/A default value
Readability high for 3 cases medium high
Data Table on the index yes yes needs a name-to-index layer

Showing all scenarios at once

Because the switch is formula-driven, a one-variable Data Table with ScenIdx (or a hard-coded index input it reads from) as the column input cell and outputs such as EBITDA, PAT, equity IRR and minimum DSCR across the top produces a live side-by-side summary — something Scenario Manager can only do as a static snapshot. (Data Table input cells must be on the same sheet as the table; put the index input on that sheet.)

Worked illustration

FY27 revenue build: FY26 revenue ₹420 crore; Live volume growth and realisation growth are selected by ScenIdx.

Scenario Volume Price FY27 revenue = 420 × (1 + v) × (1 + p)
Base (1) 8.0% 4.0% ₹471.7 crore
Upside (2) 12.0% 5.5% ₹496.3 crore
Downside (3) 3.0% 1.5% ₹439.1 crore

Switching the dropdown from Base to Downside changes the live column, revenue falls by ₹32.6 crore and every downstream line — receivables via debtor days, working capital, cash, DSCR — moves with it.

Controls and presentation

  • Show the active scenario name in every output header (="Projected P&L – "&Scenario&" case"), so printed pages cannot be misread.
  • Conditional formatting on the case block to highlight the active column (=D$5=Scenario).
  • A check that ScenIdx is a valid number: =ISNUMBER(ScenIdx).
  • Keep the scenario dropdown on one control sheet only; multiple selectors drift apart.

Edge cases & judgement calls

  • Scenarios that change structure (e.g. a new plant in Upside only) need flags (1/0) switched by scenario, not just different growth rates.
  • Mixed scenario combinations (Upside volume with Downside price) need separate selectors per driver group — more flexible but harder to communicate; document the combination shown.
  • Hard-coded overrides typed into the live column break the switch silently; colour the live column as formulas (black) and protect it.
  • Circularity and Goal Seek interplay: Goal Seek on a scenario model overwrites one case input; record the result as a named scenario rather than leaving it in the Base column.
  • CHOOSE with ranges of different sizes returns inconsistent arrays — keep scenario rows aligned.

Key takeaways

  • One dropdown → one index cell → one live column; model formulas read only the live column.
  • CHOOSE is simplest for a fixed short list; INDEX/XLOOKUP scales best; SWITCH matches names with a safe default.
  • A Data Table over the scenario index gives a live all-scenarios summary.
  • Label every output with the active scenario and highlight the active case column.
  • Live switches are preferable to Scenario Manager's static snapshots for modelling work.

Practice Questions

Q1. Build the switch [L1]

Set up a scenario switch for five drivers (volume growth, price growth, gross margin, employee cost inflation, capex as % of revenue) with Base, Upside and Downside values of your choice. Write the formulas for the index cell, the Live column using CHOOSE, and the same Live column using INDEX with XMATCH on headers.

Q2. Adding a Management case [L2]

The CFO asks for a fourth "Board" case. Compare the work required under CHOOSE, INDEX-XMATCH and SWITCH implementations across a model with 140 live driver formulas, and state which you would choose for a lender model that will be revised monthly.

Q3. Scenario summary table [L2]

Design a one-variable Data Table that shows FY27 revenue, EBITDA, PAT and minimum DSCR for all three scenarios simultaneously, given the switch reads ScenIdx. Specify where the input cell must sit, what goes in the column of input values, and what calculation setting may hide stale results.

💡 Hint: The Data Table substitutes values into a cell that the switch reads — think about what that cell must contain.

Q4. Revenue scenarios [L1]

FY26 revenue is ₹265 crore. Base: volume +6%, price +3%; Upside: +10%, +4.5%; Downside: 0%, +1%. Set up the CHOOSE-based switch and write the formula for FY27 revenue so it updates when the dropdown changes.

Q5. Structural scenario [L3]

In the Upside case, a second production line starts in October 2026 adding 30% capacity, with ₹85 crore capex in Q1 FY27. Explain how you would represent this in a switch-driven model (flags, timing inputs, capex schedule) so that the Base and Downside cases are unaffected and the switch still works with a single dropdown.
