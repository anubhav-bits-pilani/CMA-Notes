XLOOKUP Arguments: Not-Found Value, Match Mode and Search Mode

Scope: XLOOKUP arguments: if_not_found, match_mode (0, -1, 1, 2), search_mode (1, -1, 2, -2)

Why it matters

XLOOKUP is the default lookup in modern finance models: it maps ledgers to FS lines, pulls rates from slab tables, fetches the latest FX rate and drives two-way grid lookups. Its power is in the three optional arguments. Used deliberately, they replace a whole toolbox of older tricks — IFERROR wrappers, sorted helper columns, reverse-order copies and INDEX/MATCH combinations. Used carelessly, they create the quietest errors in a model: a "Not mapped" label that hides a broken key, an approximate match that returns the wrong slab, or a binary search on unsorted data that returns a plausible wrong number.

Core notes

Full signature

=XLOOKUP(lookup_value, lookup_array, return_array, [if_not_found], [match_mode], [search_mode])
Argument Purpose Default
lookup_value what you are looking for (a value, or an array of values to spill) required
lookup_array one row or one column to search required
return_array range/array to return from; same length as lookup_array along the lookup dimension; may be several columns wide required
if_not_found value returned when nothing matches #N/A
match_mode how a match is defined 0 (exact)
search_mode direction and algorithm 1 (first to last)

Because lookup_array and return_array are separate, XLOOKUP can look left, is immune to inserted columns, and the return can be a whole row or block.

if_not_found

The fourth argument replaces IFERROR(VLOOKUP(…),"…") — but only for the "not found" case. Other errors (a #REF! in the return array, a #VALUE! from mismatched array sizes) still show. That is precisely why it is better than IFERROR.

Choose the value by purpose:

  • Mapping: "Not mapped" or "UNMAPPED" — a visible text flag that COUNTIF can count.
  • Rates or amounts feeding arithmetic: 0 only if zero is genuinely correct (e.g. no TDS applies); otherwise leave the #N/A visible so the model fails loudly.
  • Nothing: "" for display layers only.

Leaving the argument empty but present (XLOOKUP(a,b,c,,-1)) is allowed — two commas skip it, and it defaults to #N/A.

match_mode

Value Meaning Typical finance use
0 exact match (default) ledger → FS line, GSTIN → vendor, employee ID → cost centre
-1 exact match, or else the next smaller item tax slabs, TDS thresholds, commission tiers keyed on "From" amounts
1 exact match, or else the next larger item bands keyed on "Up to" amounts, next available shipment date, next interest reset date
2 wildcard match (*, ?, ~) partial ledger names ("Freight"), codes with prefixes

Key behaviour: for -1 and 1, XLOOKUP finds the nearest item regardless of sort order when search_mode is 1 or -1 — it scans everything. This is a major difference from VLOOKUP/MATCH approximate match, which require ascending data. (Recent Microsoft 365 builds also add a regex match mode, 3; it is not available in Excel 2021/2024 perpetual and should not be relied on in shared models.)

Wildcards in match_mode 2 work only on text and are case-insensitive. To search for a literal *, escape it with ~*.

search_mode

Value Meaning Requirement
1 linear search from first to last (default) none
-1 linear search from last to first none
2 binary search, data sorted ascending lookup array must be sorted ascending
-2 binary search, data sorted descending lookup array must be sorted descending
  • -1 returns the last occurrence — the basis of "latest price/rate/payment" lookups on chronological data.
  • 2 / -2 are faster on very large lookup arrays (logarithmic rather than linear search), but on unsorted data they return wrong results without any error. In normal models (lookup tables of a few thousand rows) the speed gain is irrelevant; use binary search only for very large sorted tables, ideally with a sort check (=AND(B3:B5000>=B2:B4999)).

Combining the modes

Need match_mode search_mode
Map ledger to FS line 0 1
First matching transaction 0 1
Latest transaction for a vendor 0 -1
Slab rate for an income (From-based table) -1 1
Partial-name match, latest occurrence 2 -1
Exact match on 5 lakh-row sorted key list 0 2

Worked illustration

Mapping table Map (Ledger, FSLine) and TB ledger "Freight Outward – Exports":

  • =XLOOKUP(A2, Map[Ledger], Map[FSLine], "Not mapped") → "Not mapped" if the exact name is absent.
  • =XLOOKUP("*Freight*", Map[Ledger], Map[FSLine], "Not mapped", 2) → the FS line of the first ledger containing "Freight".
  • Commission table with From values 0, 5,00,000, 10,00,000 and rates 2%, 3%, 4%: for sales of ₹7,40,000, =XLOOKUP(740000, Comm[From], Comm[Rate], , -1) → 3% (the next smaller From is 5,00,000).
  • Price history sorted by date: =XLOOKUP(F2, Px[SKU], Px[Rate], "No price", 0, -1) → the most recent price for the SKU.

Spilling many lookups

If lookup_value is a range (e.g. A2:A600), XLOOKUP spills 599 results in one formula — useful for mapping a whole TB in one go: =XLOOKUP(TB_Ledgers, Map[Ledger], Map[FSLine], "Not mapped"). It cannot spill inside an Excel Table; in a Table, use the row form [@Ledger].

Edge cases & judgement calls

  • if_not_found hides key-quality problems. A mapping with 40 "Not mapped" ledgers may be 40 trailing-space issues. Always count the flags and investigate before mapping them manually.
  • Approximate modes with duplicates. If two rows share the same From value, the first (or last, with -1 search) is used — keep band tables unique.
  • Blank lookup value can match the first blank cell in the lookup array if one exists (returning that row's value) instead of reporting "not found". Guard: IF(A2="","",XLOOKUP(…)).
  • Data types. Exact match does not equate the number 410100 with the text "410100". Type mismatches are the most common cause of "Not mapped".
  • Compatibility. XLOOKUP is Excel 2021/2024 and Microsoft 365 only; Excel 2016/2019 shows #NAME?.

Key takeaways

  • if_not_found handles only the not-found case — better than IFERROR, which hides structural errors.
  • match_mode: 0 exact, -1 next smaller, 1 next larger, 2 wildcard; -1/1 do not need sorted data with linear search.
  • search_mode: 1 first-to-last, -1 last-to-first (latest record), 2/-2 binary (must be sorted, otherwise silent errors).
  • Separate lookup and return arrays mean left lookups and no column-index breakage.
  • Choose the not-found value by purpose: a text flag for mappings, a visible error for rates feeding arithmetic.

Practice Questions

Q1. Pick the modes [L1]

For each requirement, write the XLOOKUP with appropriate match_mode and search_mode: (a) map a ledger name to its Schedule III line; (b) the latest invoice date for vendor in F2 from a chronological purchase register; (c) the depreciation rate for an asset cost of ₹7,80,000 from a band table with "From" values; (d) the cost centre for any ledger whose name contains "Plant 2".

Q2. Silent binary-search failure [L2]

A colleague speeds up a 3 lakh-row product price lookup by using search_mode 2. Month-end gross margin by SKU shifts by up to 6% compared with last month for no business reason. Explain the likely cause, how to prove it with a formula, and when binary search is justified.

💡 Hint: Binary search assumes something about the lookup array that XLOOKUP never checks.

Q3. Not-mapped analysis [L2]

After mapping a 540-ledger TB with =XLOOKUP([@Ledger], Map[Ledger], Map[FSLine], "Not mapped"), 23 ledgers show "Not mapped". Design a three-step diagnostic using formulas to classify them into trailing-space issues, data-type issues, and genuinely new ledgers.

Q4. Not-found value for a rate lookup [L2]

A TDS calculation uses =XLOOKUP([@Section], TDS[Section], TDS[Rate], 0) * [@Amount]. Explain the business risk of the 0 default when a section code such as "194T" is missing from the rate table, and propose a better design including a check cell.

Q5. Interview: XLOOKUP vs VLOOKUP approximate [L1]

Explain, with a one-line example each, two ways in which XLOOKUP with match_mode -1 behaves differently from VLOOKUP(…, TRUE) on a tax slab table.
