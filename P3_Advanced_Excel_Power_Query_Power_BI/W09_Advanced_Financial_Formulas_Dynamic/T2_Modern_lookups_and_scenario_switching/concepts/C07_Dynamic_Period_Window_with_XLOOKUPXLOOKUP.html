Key concept

Dynamic Period Window with XLOOKUP:XLOOKUP

Concept: =SUM(XLOOKUP(StartM, Months, Row):XLOOKUP(EndM, Months, Row)) sums a dynamic period window

Statement

Let Months be the header row \((m_1, \dots, m_n)\) and Row the aligned value row \((x_1, \dots, x_n)\). With \(a\) the position of StartM and \(b\) the position of EndM in Months, each XLOOKUP returns a reference to cell \(x_a\) or \(x_b\); the range operator : joins them into the range from \(x_a\) to \(x_b\), and

\[ \text{Window sum} = \sum_{j=\min(a,b)}^{\max(a,b)} x_j \]

The window length is \(\lvert b - a \rvert + 1\) months.

Explanation

References, not values. Most functions return values, but XLOOKUP and INDEX return references when their return array is a worksheet range. That is what lets : build a range between two lookups. The formula is non-volatile — it recalculates only when its inputs change — unlike OFFSET- or INDIRECT-based windows, which recalculate on every change anywhere in the workbook.

Same range at both ends. Both XLOOKUPs must return cells from the same Row. If Row is a computed array (Row*1, VALUE(Row)), there is no reference and the : operator produces #VALUE!.

Reversed inputs. If StartM is later than EndM, the range is still built (Excel normalises the corners), so the SUM covers the same months — no error. That is mathematically harmless for SUM but usually indicates a user error in the dropdown; add a check =StartM<=EndM.

Not-found behaviour. If either month is missing from Months (e.g. a rolling-12 start before the first month of history), the XLOOKUP returns #N/A and so does the SUM. Supplying a text if_not_found would break the : operator; validate inputs instead, or clamp the start with MAX(StartM, first month).

Typical inputs.

  • YTD: StartM = FY start (01-Apr), EndM = selected month.
  • QTD: StartM = fiscal quarter start of the selected month.
  • Trailing 3 / 12 months: StartM = EDATE(Sel, -2) or EDATE(Sel, -11).

Other aggregators. The same window works with AVERAGE, MAX, MIN, COUNT and COLUMNS (window length). Legacy equivalent: SUM(INDEX(Row, MATCH(StartM, Months, 0)):INDEX(Row, MATCH(EndM, Months, 0))).

Illustration

FY26 EBITDA row (₹ crore), headers 01-Apr-2025 … 01-Mar-2026:

Apr May Jun Jul Aug Sep Oct Nov Dec
2.1 2.4 2.2 2.8 3.0 3.1 3.6 3.3 3.4
  • Selected month 01-Dec-2025, YTD window Apr–Dec: 2.1 + 2.4 + 2.2 + 2.8 + 3.0 + 3.1 + 3.6 + 3.3 + 3.4 = ₹25.9 crore.
  • QTD (Oct–Dec): ₹10.3 crore.
  • Trailing three months to November (Sep–Nov): ₹10.0 crore.
  • Average monthly EBITDA YTD: =AVERAGE(window) = ₹2.88 crore; window length =COLUMNS(window) = 9.

Changing the selected month to 01-Jan-2026 updates all four without editing any formula.

Connections

Applies the range-reference behaviour from the XLOOKUP-returning-rows subtopic and contrasts with the volatile OFFSET/INDIRECT alternatives listed under related concepts. The month headers it relies on are built with EOMONTH/SEQUENCE, and the dropdowns for StartM/EndM are Data Validation lists. In FP&A (Weeks 17–20) the same window logic produces YTD, QTD and rolling-forecast views; in DAX (Week 11) it becomes time-intelligence functions such as DATESYTD.

Practice Questions

Q1. Window toolkit [L1]

Using named ranges Months and PAT, write formulas for FY26 YTD PAT to the selected month Sel, QTD PAT for the fiscal quarter containing Sel, and the number of months in the YTD window.

Q2. Trailing-12 with short history [L2]

A business started operations in 01-Jul-2025, so the 24-month grid starting 01-Apr-2025 has zeros for April–June 2025 and real data from July. For Sel = 01-Feb-2026, explain what a trailing-12 window formula returns and how you would present an annualised run-rate instead.

💡 Hint: Decide whether pre-launch months should be inside the window at all, and adjust the start accordingly.

Q3. Debug the window [L2]

The formula =SUM(XLOOKUP(StartM, Months, Rev, "n/a"):XLOOKUP(EndM, Months, Rev, "n/a")) returns #VALUE! for some selections and correct totals for others. Explain both behaviours and correct the design.
