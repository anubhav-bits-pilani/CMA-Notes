Key concept

Nested XLOOKUP as a Two-Way Lookup

Concept: =XLOOKUP($A5, Acc[Code], XLOOKUP(C$4, Hdr[Month], Data)): the inner lookup returns a column, so this is a two-way lookup

Statement

Let Data be an \(m \times n\) block with row keys Acc[Code] \((a_1,\dots,a_m)\) and column keys Hdr[Month] \((h_1,\dots,h_n)\). The inner lookup returns the whole column \(c\) where \(h_c\) equals the month header in row 4:

\[ \text{Inner} = \left( D_{1,c}, D_{2,c}, \dots, D_{m,c} \right)^{T} \]

The outer lookup then returns the element of that column at the row \(r\) where \(a_r\) equals the account code in column A:

\[ \text{Result} = D_{r,c} \]

where \(D_{i,j}\) is the value in row \(i\), column \(j\) of Data.

Explanation

Why the inner lookup returns a column. The return array Data has many rows; when XLOOKUP finds the matching month in the 1 × n header, it returns the corresponding n-th column of Data — an m × 1 array (in fact, a reference to that column). That array becomes the outer XLOOKUP's return array, aligned with Acc[Code].

Alignment requirements. Acc[Code] must have exactly m rows (same as Data) and Hdr[Month] exactly n columns. If the header row is one column longer than Data (a "Total" column included in one but not the other), the inner XLOOKUP returns #VALUE!.

Anchoring. In a copy-across report, the account code column is locked (column-absolute, row-relative) and the month header row is locked (row-absolute, column-relative), so the formula fills the entire report grid unchanged.

Order is interchangeable. XLOOKUP(C$4, Hdr[Month], XLOOKUP($A5, Acc[Code], Data)) — inner returns a row, outer picks the month — gives the same result. Choose whichever reads better.

Not-found handling. Give the outer XLOOKUP a fourth argument such as "No account". A scalar not-found value on the inner lookup is a poor idea: if the month is missing, the outer lookup would receive a single value instead of an aligned column and return a misleading result or #VALUE!. Leave the inner #N/A visible, and validate headers separately with ISNUMBER(XMATCH(C$4, Hdr[Month])).

Equivalent forms. INDEX(Data, XMATCH($A5, Acc[Code]), XMATCH(C$4, Hdr[Month])) and INDEX-MATCH-MATCH (with match type 0) return the same value and work in older versions (MATCH form).

Illustration

Budget block (₹ lakh), Acc[Code] = 610100, 640500, 650200; Hdr[Month] = 01-Apr-2025, 01-May-2025, 01-Jun-2025:

Code Apr May Jun
610100 82.0 82.0 86.5
640500 21.0 21.0 21.0
650200 6.4 7.1 5.8

Report cell with A5 = 610100 and C4 = 01-Jun-2025: inner XLOOKUP returns {86.5; 21.0; 5.8}; outer finds 610100 at position 1 and returns 86.5. Copied one row down (A6 = 650200) and one column left (B4 = 01-May-2025), it returns 7.1.

If the budget file's headers were text "Jun-25" while the report uses dates, the inner lookup fails and the cell shows #N/A — the visible symptom of a header type mismatch.

Connections

Implements the two-way lookup subtopic and shows XLOOKUP's ability to return whole rows/columns (the spill/range subtopic). The anchoring follows the mixed-referencing rules from the GL-rollups topic. In BvA reporting (Weeks 17–20) it pulls budgets from templates you do not control; in Power Query (Week 10) the better long-term fix is to unpivot the grid and use SUMIFS or a merge.

Practice Questions

Q1. Reverse the nesting [L1]

Rewrite the concept formula with the inner lookup on account codes and the outer on months, and explain what the inner lookup returns in your version.

Q2. Misaligned header [L2]

A budget block Data covers C6:N85 but the header name Hdr[Month] refers to C4:O4 because a "FY Total" column was added in O. Explain what the nested XLOOKUP returns, and give two fixes.

💡 Hint: Compare the width of the header range with the width of the data block.

Q3. Three-dimensional pull [L2]

The FY27 budget workbook has one block per branch (MUM, PUN, NSK) on separate sheets, each with identical layout and named Data_MUM, Data_PUN, Data_NSK. Write a formula that returns the value for the branch in B2, account in A5 and month in C4 using nested XLOOKUP and a CHOOSE or SWITCH to pick the block, and comment on maintainability.
