Key concept

Boolean-Array XLOOKUP for Multi-Criteria Lookups

Concept: =XLOOKUP(1, (T[Branch]=B2)*(T[Ledger]=C2), T[Amount], 0) for multi-criteria lookup without helper columns

Statement

Construct, for each row \(i\) of Table T,

\[ z_i = \mathbf{1}\left[\text{Branch}_i = B2\right] \times \mathbf{1}\left[\text{Ledger}_i = C2\right] \in \{0, 1\} \]

where \(\mathbf{1}[\cdot]\) is 1 when the comparison is TRUE and 0 when FALSE. XLOOKUP searches the array \(z\) for the value 1 and returns \(\text{Amount}_{j^*}\) with \(j^* = \min\{\, i : z_i = 1 \,\}\) — the first row meeting both conditions. If no row has \(z_i = 1\), it returns the if_not_found value, here 0.

Explanation

Coercion by multiplication. Each comparison yields an array of TRUE/FALSE. Arithmetic (*) coerces TRUE to 1 and FALSE to 0, and the product is 1 only when every condition is TRUE — AND logic. Adding arrays instead gives a count of conditions met, so OR logic is ((c1)+(c2)>0)*1 searched for 1.

Lookup value 1. The lookup value must match the array's type: 1 (a number) against the 1/0 product. Searching for TRUE would fail because the product is numeric.

Extending the conditions. Any comparison or function on a whole column can be included: (T[Date]<=RptDate), (LEFT(T[Ledger],4)="Rent"), (T[Amount]>0). Combine with search_mode -1 to get the last qualifying row, e.g. the latest rate for a branch–ledger pair on or before a date.

The not-found value of 0. Returning 0 is appropriate when "no row" genuinely means "nothing" (no budget for this branch–ledger). For attributes — rates, FS lines, vendor names — use a visible flag instead, so missing data is not mistaken for zero.

First match only. If the branch–ledger pair appears several times (several postings), only the first amount comes back. For amounts that may repeat, SUMIFS on the same two criteria is the right tool; the boolean XLOOKUP is for retrieving a single attribute or a unique record.

Performance and compatibility. Each formula builds full-length arrays, so thousands of such cells over a large Table recalculate slowly; a concatenated helper key or a Power Query merge scales better. The pattern needs dynamic-array Excel (2021/2024, Microsoft 365); the legacy equivalent is INDEX(T[Amount], MATCH(1, (…)*(…), 0)) entered with Ctrl+Shift+Enter.

Illustration

Table T (branch rent and power budgets, ₹):

Branch Ledger Amount
MUM Rent 4,50,000
PUN Power 1,35,000
PUN Rent 2,10,000
NSK Rent 95,000

With B2 = "PUN" and C2 = "Rent":

  • (T[Branch]="PUN") → {0; 1; 1; 0}
  • (T[Ledger]="Rent") → {1; 0; 1; 1}
  • product → {0; 0; 1; 0}
  • XLOOKUP finds 1 at position 3 → ₹2,10,000.

With B2 = "DEL", the product is all zeros and the result is 0 — appropriate for a budget pull if Delhi genuinely has no rent budget, but a misleading answer if "DEL" was a typo for "DLH". A Data Validation dropdown on B2 removes that risk.

Connections

The boolean technique from the multi-key lookups subtopic; it is the lookup analogue of the boolean SUMPRODUCT patterns in the SUMPRODUCT topic and of FILTER conditions in the dynamic-arrays topic. The coercion rules (TRUE/FALSE to 1/0) are developed fully under SUMPRODUCT coercion. For large recurring mappings, the helper-key approach or a Power Query merge (Week 10) is preferred.

Practice Questions

Q1. Three-condition lookup [L1]

Table Rates has Bank, Facility (TL, CC, WCDL), Tenor and Rate. Write a boolean XLOOKUP that returns the rate for the bank in B2, facility in C2 and tenor in D2, returning "Not quoted" if none exists.

Q2. Latest qualifying record [L2]

Table Px (Date, Vendor, SKU, Rate) is chronological. Write a formula that returns the latest rate for vendor F2 and SKU G2 on or before the date in H2, and explain why search_mode matters here.

💡 Hint: Include a date comparison in the product and search from last to first.

Q3. When the answer is wrong [L2]

A branch-wise actuals sheet uses =XLOOKUP(1, (GL[Ledger]=C$5)*(GL[Branch]=$B6), GL[Amount], 0) across 30 branches × 40 ledgers on a 1.2 lakh-row GL Table. Identify two problems (one with correctness, one with performance) and propose a replacement formula.
