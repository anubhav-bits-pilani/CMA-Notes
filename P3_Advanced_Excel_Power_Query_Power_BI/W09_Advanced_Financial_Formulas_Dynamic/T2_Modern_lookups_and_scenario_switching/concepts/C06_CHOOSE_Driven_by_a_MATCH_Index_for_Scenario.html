Key concept

CHOOSE Driven by a MATCH Index for Scenario Selection

Concept: =CHOOSE($C$2, Base_Growth, Upside_Growth, Downside_Growth) with $C$2 = MATCH(Scenario, ScenarioList, 0)

Statement

Let \(S\) be the scenario name selected in the dropdown Scenario, and ScenarioList the ordered list \((s_1, s_2, s_3) = (\text{Base}, \text{Upside}, \text{Downside})\). The index cell C2 (fully absolute, so every model formula points at the same cell) holds

\[ k = \text{MATCH}(S, \text{ScenarioList}, 0) \in \{1, 2, 3\} \]

and the live growth driver is

\[ g_{\text{live}} = \text{CHOOSE}(k, g_{\text{Base}}, g_{\text{Upside}}, g_{\text{Downside}}) = g_{s_k} \]

where \(g_{\text{Base}}\), \(g_{\text{Upside}}\), \(g_{\text{Downside}}\) are the named input cells Base_Growth, Upside_Growth and Downside_Growth. CHOOSE returns its \(k\)-th value argument after index_num.

Explanation

Two-step design. The dropdown holds a readable name; MATCH converts it into a number once; every live driver uses CHOOSE on that number. Separating the index into one cell means the name-to-number logic is written once, can be checked (ISNUMBER), and can be overridden by a Data Table that feeds 1, 2, 3 to produce an all-scenarios summary.

Why the reference is absolute. Live-driver formulas are copied down an assumptions sheet (growth, margin, debtor days…); the index must not move. Better still, name it (ScenIdx) — a name never needs anchoring and reads as intent.

Order must match. CHOOSE's value arguments must be in the same order as ScenarioList. If someone sorts the list alphabetically (Base, Downside, Upside), "Upside" now returns position 3, which CHOOSE maps to Downside_Growth — a silent, serious error. Lock the list order (a Table with a protected sheet) or switch to an approach that matches by name (INDEX/XLOOKUP on headers, SWITCH).

Bounds and type. CHOOSE accepts 1 to 254 values; an index of 0, 4 (with three values) or text returns #VALUE!; a fractional index is truncated. The 0 in MATCH forces exact matching — without it, an unsorted list can return the wrong position.

CHOOSE with ranges. The value arguments can be ranges of the same size: SUM(CHOOSE(ScenIdx, Base_Rev, Up_Rev, Down_Rev)) or a whole-row switch that spills in Microsoft 365. This is handy for switching full time series (e.g. monthly volume curves) rather than single rates.

Scaling. Adding a fourth case means adding an item to the list and editing every CHOOSE. With many drivers, an INDEX over a case block (INDEX(D6:G6, ScenIdx)) avoids the edits.

Illustration

Inputs: Base_Growth = 9%, Upside_Growth = 14%, Downside_Growth = 2%; FY26 revenue ₹320 crore; ScenarioList = Base, Upside, Downside.

Dropdown MATCH index Live growth FY27 revenue
Base 1 9% ₹348.8 crore
Upside 2 14% ₹364.8 crore
Downside 3 2% ₹326.4 crore

If the list were re-sorted to Base, Downside, Upside without changing the CHOOSE order, selecting "Downside" would return index 2 → 14% → ₹364.8 crore: the downside case would show the upside revenue.

Connections

The CHOOSE option of the scenario-switch subtopic; the dropdown that feeds Scenario is a Data Validation list (what-if and controls topic). The index cell is the natural input cell for a one-variable Data Table summarising all cases, and the same switch drives the three-statement model and DCF cases in Weeks 13–16. Compare with Scenario Manager, which stores static values rather than a live switch.

Practice Questions

Q1. Build and protect [L1]

Set up the scenario list, dropdown, index cell and three live drivers (growth, EBITDA margin, capex % of revenue) using CHOOSE. Add a check cell that flags an invalid index and explain how you would stop users from re-ordering the scenario list.

Q2. Alphabetical sort incident [L2]

After a colleague sorted ScenarioList alphabetically, the board pack's "Downside" EBITDA rose by ₹18 crore. Explain the mechanism and redesign the switch so that the order of the list no longer matters.

💡 Hint: Match the scenario name against the case-block headers instead of relying on argument order.

Q3. All-cases summary [L2]

With FY26 revenue of ₹320 crore and the growth inputs above, describe how to produce a table showing FY27 revenue, EBITDA (margin Base 18%, Upside 20%, Downside 15%) and the selected-scenario flag for all three scenarios at once without changing the dropdown, using a Data Table on the index cell.
