Roadmap topic: What-If Analysis & Controls: 1D/2D Data Tables, Goal Seek, Scenario Manager, Data Validation dropdowns, and dynamic Conditional Formatting rules

Overview

A model is valuable less for its single answer than for what it says about how that answer moves. This topic covers Excel's tools for asking "what if?" and for controlling what goes into a model. On the analysis side: Data Tables re-run the model over one or two input ranges; Goal Seek back-solves a single input for a target; Scenario Manager stores and compares sets of inputs; Solver optimises many decision variables under constraints. On the control side: Data Validation restricts and documents inputs and creates dropdowns; conditional formatting makes variances, the live scenario and failed checks visible; form controls let non-Excel users flex a model safely; and calculation mode management keeps heavy sensitivity grids fast without letting them go stale.

For the target roles, these tools appear in every serious deliverable. Valuation and corporate finance work needs WACC × growth grids, implied-assumption Goal Seeks and lender stress cases. FP&A needs base/upside/downside budgets, price-volume sensitivities, break-even analysis and variance packs that highlight themselves. Reporting and audit work needs input templates that department heads cannot break and models whose state is obvious to a reviewer. Interviewers routinely ask why Data Table inputs must be on the same sheet, how Goal Seek differs from Solver, and why Scenario Manager is rarely used in professional models.

The learning sequence: start with sensitivity mechanics — Data Tables (s01) and Goal Seek (s02) — then multi-input cases with Scenario Manager (s03). Move to the input layer: Data Validation (s04) and formula-based conditional formatting (s05), then dashboard controls (s06). Finish with optimisation using Solver (s07) and the operational discipline of calculation modes (s08), which ties back to Data Tables. The six key concepts pin down the rules most often tested: the TABLE formula and same-sheet rule (c01), Goal Seek's cell requirements (c02), dynamic dropdown sources (c03), mixed-reference CF rules (c04, c05) and Scenario Manager's limits (c06).

Related concepts to study

WACC × terminal growth grid

→ Week 15–16: WACC × terminal growth sensitivity grid in the DCF

The single most common Data Table in finance is the DCF grid of enterprise value or value per share against WACC (rows) and terminal growth (columns). In Weeks 15–16 you will build it on a full DCF where terminal value often contributes 60–80% of EV, so small changes in WACC − g produce large swings — the convexity seen in s01's illustration. Good practice: keep the base case in the centre, steps of 0.5%, guard against g ≥ WACC (return a blank or "n.m."), highlight the base cell with conditional formatting, and add a staleness check against the live EV. Some analysts add a second grid of EV against exit multiple for the terminal-multiple method.

CVP break-even with Goal Seek

→ Week 21: CVP break-even and margin of safety with Goal Seek

Cost-volume-profit analysis from CMA cost accounting becomes a spreadsheet exercise in Week 21: break-even volume (fixed costs ÷ contribution per unit), break-even revenue (fixed costs ÷ P/V ratio) and margin of safety ((actual − break-even) ÷ actual). Closed-form formulas keep these live; Goal Seek is the tool when the cost structure includes step fixed costs, volume discounts or multi-product mixes where contribution depends on mix. A 1D Data Table of EBIT against volume, and a 2D table of EBIT against price and volume, extend CVP into a sensitivity view. Keep Goal Seek results in a log, since they do not update.

Live scenario switches

CHOOSE/INDEX live scenario switches as an alternative to Scenario Manager → w9_t2

A live switch stores every case's values side by side on the assumptions sheet (Base, Upside, Downside columns) and selects the active column with CHOOSE(ScenIdx, …) or INDEX(CaseBlock, , ScenIdx), where ScenIdx comes from a dropdown via MATCH (s04) or a combo box (s06). Unlike Scenario Manager, there is no 32-cell limit, nothing is overwritten, every value is visible and auditable, and the selected case can be highlighted with a row-locked conditional formatting rule. A 1D Data Table over the scenario index then produces a live side-by-side comparison — the professional replacement for the static Scenario Summary.

Tornado charts

Tornado charts for ranking sensitivities in presentations

A tornado chart ranks inputs by their impact on one output. For each driver, the output is computed at a low and a high value (e.g. ±10% or P10/P90 estimates) with all other inputs at base; the swings are sorted largest first and plotted as horizontal bars around the base value, producing the tornado shape. In Excel, compute the low/high outputs with a 1D Data Table per driver or a single Data Table over a "driver selector" index, then sort with SORTBY (w9_t4) and chart as a clustered bar with the base as the axis crossing. Tornado charts focus board discussion on the two or three assumptions that actually matter.

Model hygiene and colour coding

Model hygiene: input/calculation/output separation and colour coding (blue inputs, black formulas)

The what-if tools only work reliably in a well-structured model. Separate inputs (assumptions, scenario blocks, controls' linked cells), calculations and outputs, ideally on different sheets with one-directional flow. Colour-code: blue font for hard-coded inputs, black for formulas, green for links to other sheets (a common banking convention). This makes Goal Seek and Data Table set-up obvious (inputs are blue), exposes hard-coded numbers in calculation areas, and helps reviewers. Add a checks sheet summarising TB balance, balance-sheet balance, cash tie-out and sensitivity staleness, and a cover sheet stating calculation mode and active scenario.

Common pitfalls

Slow Data Tables and forgotten F9

Data Tables slow big models; teams set "Automatic except data tables" and then forget to press F9

Mistake: sensitivity grids distributed with stale values because calculation was set to "Automatic except for data tables" (or Manual) and nobody recalculated after the last input change. Why it happens: large Data Tables make every keystroke slow, so the mode is changed for speed; the status-bar "Calculate" indicator is easy to miss, and the mode persists across the session. Correct treatment: keep the mode deliberately, press F9 before reading or exporting results, add a staleness check comparing the grid's base-case cell with the live output, and display the calculation mode and "last calculated" on the cover sheet. Reduce the need for the mode by removing volatile functions and keeping grids small. Detection: the base-case cell of the grid disagrees with the live output; "Calculate" in the status bar.

Goal Seek leaves no audit trail

Goal Seek overwrites an input with no audit trail, and the result stops tracking later assumption changes

Mistake: an input like volume = 1,83,467.29 that was Goal Seeked months ago to hit a target, now stale because other assumptions changed. Why it happens: Goal Seek writes a constant into the changing cell, which looks like any other input. Correct treatment: use a dedicated solve cell or a switch between base and solved values; keep a gap cell (Output − Target) that should be zero; record each solve (date, target, result, owner) in a log; prefer closed-form or live formulas (break-even, required CAGR) where they exist; re-run solves in the close checklist. Detection: inputs with unusual decimals and no source note; non-zero gap cells; inquiry of the preparer; Inquire's cell-comparison between versions shows constant changes.

Validation bypassed and fixed list sources

Pasting over Data Validation cells bypasses it; list sources on fixed ranges do not grow

Mistake: invalid values (non-existent cost centres, 800% growth) in validated cells, and dropdowns missing new items. Why it happens: Ctrl+V replaces the cell, including its validation rule; validation only checks typed entries; list sources point to fixed ranges like Lists!B2:B20 that new items exceed. Correct treatment: protect input sheets, instruct users to paste values only, run Data → Circle Invalid Data and completeness checks before consolidation, and build list sources from Table-backed names or spill references (UNIQUE output with #). Detection: Circle Invalid Data; Go To Special → Data Validation to confirm coverage; COUNTIFS checks of entries against master lists.

Duplicated conditional formatting rules

Copy-pasting duplicates Conditional Formatting rules, which bloats the file and creates conflicting priorities

Mistake: Manage Rules shows hundreds of near-identical rules, each applied to small fragments of the range, with inconsistent formats and priorities. Why it happens: copying and pasting cells (or inserting copied rows) duplicates rules with fragmented Applies-to ranges; Format Painter spreads rules unintentionally. Correct treatment: maintain one rule per purpose applied to the full block; after restructuring, clear rules from the sheet and recreate them; paste values or formulas only (Paste Special) when copying within formatted blocks. Detection: Manage Rules with "This Worksheet" selected — look for repeated formulas and fragmented ranges; slow scrolling; file size growth without data growth.

Practice Questions

Q1. Valuation sensitivity pack [L3]

A DCF for an NSE-listed specialty chemicals company gives ₹2,340 per share at WACC 11.5% and terminal growth 5.5%; inputs are on an Inputs sheet, valuation on a Valuation sheet. Design: (a) a 2D Data Table of per-share value for WACC 10.5%–12.5% and growth 4.5%–6.5% in 0.5% steps, including how you satisfy the same-sheet rule; (b) a conditional formatting rule highlighting the base case and another shading values below the current market price of ₹2,050 (a named input); (c) a Goal Seek to find the market-implied WACC with controls so the base WACC is not overwritten; (d) the calculation mode and staleness check you would use. Write the key formulas and dialog entries.

Q2. Budget template for 25 departments [L2]

Design an FY27 department budget input template: department and cost-centre dependent dropdowns, monthly phasing that must sum to 100%, headcount as whole numbers between 0 and 500, salary increase between 0% and 15% with a warning above 12%, and conditional formatting that flags months where phased spend exceeds 15% of the annual budget. Specify each validation and CF rule and the checks you would run on returned templates before consolidation.

💡 Hint: Remember that pasting can bypass validation, so plan detective checks as well as preventive rules.

Q3. Product mix and break-even [L2]

A two-product plant: product X contributes ₹450 per unit using 3 machine hours; product Y contributes ₹380 per unit using 2 machine hours; capacity 18,000 machine hours; maximum demand X 4,000 units and Y 5,000 units; fixed costs ₹2.6 crore. Set up the Solver model for the optimal mix, state how you would read the shadow price of machine hours, then use Goal Seek on the optimal mix to find the uniform percentage fall in both contributions that would bring EBIT to zero.

Q4. Scenario architecture review [L3]

You inherit a budget model that uses Scenario Manager with three scenarios of 28 changing cells, a Scenario Summary pasted into the board pack, three Data Tables with "Automatic except data tables" set, and form controls linked to cells on a hidden sheet. Identify the risks, propose a redesigned architecture (live switch, live scenario comparison, dashboard controls, checks), and outline the migration steps so the board numbers do not change unexpectedly.

Q5. Interview rapid-fire [L1]

Answer briefly: (a) Why must Data Table inputs be on the same sheet? (b) Goal Seek vs Solver — two differences. (c) What does a combo box's linked cell return? (d) What does F9 recalculate compared with Shift+F9? (e) Why is Scenario Manager's summary risky in a board pack?
