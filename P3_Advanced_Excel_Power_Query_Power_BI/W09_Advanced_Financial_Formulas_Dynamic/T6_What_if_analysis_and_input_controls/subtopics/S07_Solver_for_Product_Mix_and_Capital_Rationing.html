Solver for Product Mix and Capital Rationing

Scope: Solver for constrained optimisation such as product mix and capital rationing

Why it matters

Goal Seek changes one input to hit one target. Real decisions involve many decision variables and constraints: which product mix maximises contribution given machine-hour and labour limits and demand caps; which projects to fund within a capex budget; how to allocate a marketing budget across channels; how to blend raw materials at minimum cost; how to schedule debt drawdowns to keep DSCR above a covenant. Solver, Excel's optimisation add-in, handles these. For a CMA, it is the spreadsheet implementation of the linear programming and limiting-factor analysis studied in cost and management accounting, and its sensitivity report gives the shadow prices that underpin "what is one more machine hour worth?" decisions.

Core notes

Enabling Solver

File → Options → Add-ins → Manage: Excel Add-ins → Go → tick Solver Add-in. It then appears at Data → Analyze → Solver (Alt, A, Y, 2 in many builds).

The three components

Component Solver field Must be
Objective Set Objective; Max / Min / Value Of A formula cell (e.g. total contribution)
Decision variables By Changing Variable Cells Hard-coded input cells (up to 200)
Constraints Subject to the Constraints Relations on formula or variable cells: <=, >=, =, int, bin, dif

Tick "Make Unconstrained Variables Non-Negative" for quantities. Choose the solving method:

Method Use when Notes
Simplex LP Objective and constraints are linear (sums of variable × constant) Exact, fast; gives a full sensitivity report
GRG Nonlinear Smooth nonlinear relationships (e.g. price-elasticity curves, ratios) Local optimum; try multiple starting points ("Multistart")
Evolutionary Non-smooth models (IF, LOOKUP, MAX in the objective path) Slow, heuristic; no guarantee of optimality

Design the model so the problem is linear wherever possible — SUMPRODUCT of quantities and per-unit coefficients is the standard construction.

Product mix (linear programme)

A plant makes three products with two scarce resources:

A B C Capacity
Contribution per unit (₹) 400 550 300
Machine hours per unit 2 3 1 12,000
Labour hours per unit 3 2 2 15,000
Maximum demand (units) 3,000 2,500 4,000

Model layout:

  • Decision cells Qty (three cells, start at 0).
  • Objective: =SUMPRODUCT(Qty, Contribution).
  • Usage: =SUMPRODUCT(Qty, MachineHrs) and =SUMPRODUCT(Qty, LabourHrs).
  • Constraints: machine usage ≤ 12,000; labour usage ≤ 15,000; Qty ≤ MaxDemand; Qty ≥ 0 (or integer if units are indivisible).
  • Method: Simplex LP.

Solution: A = 1,000, B = 2,000, C = 4,000 units; contribution ₹27,00,000. Both hour constraints bind (12,000 and 15,000 used), and C is at its demand cap.

Compare with the single-limiting-factor rule (contribution per machine hour: A ₹200, B ₹183, C ₹300), which would rank C > A > B — workable with one constraint, but with two binding resources only an LP finds the optimum.

Sensitivity report

After an LP solve, select Sensitivity in the Solver Results dialog. Key outputs:

Item Value in this example Meaning
Shadow price — machine hours ₹170 per hour Contribution gained per extra machine hour (within the allowable increase)
Shadow price — labour hours ₹20 per hour Value of one extra labour hour — overtime premium above ₹20 is not worth paying
Reduced cost — C at demand cap ₹90 per unit Contribution gained per unit of extra C demand
Allowable increase/decrease (from report) Range over which shadow prices hold

Check: for each product produced in the interior, contribution = Σ(resource use × shadow price): A: 2 × 170 + 3 × 20 = 400. These are exactly the dual values from CMA LP theory, now computed in seconds. The sensitivity report is only available for Simplex LP without integer constraints.

Capital rationing (binary integer programme)

Capex budget ₹100 crore; five indivisible projects:

Project Outlay (₹ crore) NPV (₹ crore) Profitability index
P1 40 12 1.30
P2 30 10 1.33
P3 25 7 1.28
P4 20 6 1.30
P5 35 11 1.31

(Profitability index here = (NPV + outlay) ÷ outlay.)

Model:

  • Decision cells Select (one per project) with constraint Select = bin.
  • Objective: maximise =SUMPRODUCT(Select, NPV).
  • Constraint: =SUMPRODUCT(Select, Outlay) ≤ 100.
  • Optional logic: mutually exclusive projects (P1 + P2 ≤ 1), contingent projects (P4 ≤ P1), multi-period budgets (one budget row per year).

Solver result: P1, P3, P5 — outlay ₹100 crore, NPV ₹30 crore. Ranking by profitability index instead (P2, P5, P4, then P1 and P3 do not fit) gives P2 + P5 + P4 — outlay ₹85 crore, NPV ₹27 crore, with ₹15 crore idle. PI ranking is optimal only when projects are divisible; for indivisible projects, integer programming is required.

Running and saving models

  • Solver settings are saved with the sheet (one model per sheet); use Load/Save to store several models in cell ranges.
  • Keep decision variables on a clearly coloured block, and copy solved results to a results log — like Goal Seek, Solver overwrites the variable cells.
  • Use Options → Integer Optimality (default 1%) — set to 0% for exact integer solutions on small problems.

Edge cases & judgement calls

  • Non-linearity hidden in formulas. An IF or MIN in the objective path makes Simplex refuse ("linearity conditions not satisfied"). Restructure with extra variables and constraints, or switch method knowingly.
  • Local optima in GRG Nonlinear: results depend on starting values; use Multistart and sanity-check.
  • Infeasible models usually reveal inconsistent constraints (e.g. minimum production commitments exceeding capacity) — valuable information in itself.
  • Scaling. Mixing ₹ crore objectives with unit-level constraints can cause numerical issues; tick "Use Automatic Scaling" or rescale.
  • Variable limit is 200 decision cells and 100 constraints on non-variable cells in standard Solver; larger problems need Analytic Solver or Python.
  • Decision vs model. The optimum depends on estimated coefficients; present the sensitivity ranges and qualitative factors (customer commitments, strategic products) alongside.

Key takeaways

  • Solver optimises an objective formula by changing up to 200 variable cells subject to constraints.
  • Build linear models with SUMPRODUCT and use Simplex LP for exact solutions and a sensitivity report.
  • Shadow prices value scarce resources; reduced costs value relaxing variable bounds.
  • Capital rationing with indivisible projects needs binary variables; PI ranking can leave budget idle and miss the optimum.
  • Solver overwrites variable cells — log results and keep models documented.

Practice Questions

Q1. Set up an LP [L2]

A garment unit makes shirts (contribution ₹180, 0.5 cutting hours, 1.2 stitching hours) and trousers (contribution ₹240, 0.8 cutting hours, 1.5 stitching hours). Capacity: 2,400 cutting hours, 5,000 stitching hours; trousers demand is capped at 2,000. Specify the decision cells, objective, constraints and method, and state what the sensitivity report would tell the production head.

💡 Hint: Write each constraint as a SUMPRODUCT of quantities and per-unit hours.

Q2. Capital rationing with conditions [L3]

Six projects (outlay, NPV in ₹ crore): Q1 (50, 14), Q2 (35, 9), Q3 (30, 9.5), Q4 (25, 6), Q5 (20, 5.5), Q6 (45, 12.5). Budget ₹120 crore. Q2 and Q3 are mutually exclusive; Q5 can be done only if Q1 is done. Build the Solver model with binary variables and the extra constraints, and explain why profitability-index ranking might not give the right answer.

Q3. Interpreting shadow prices [L2]

In a product-mix solution, the shadow price of machine hours is ₹170 with an allowable increase of 600 hours, and of labour ₹20. The plant can rent 1,000 extra machine hours at ₹120 per hour, or pay overtime at ₹35 per labour hour. Advise management, explaining the role of the allowable increase.

Q4. Method choice [L2]

For each model, choose the Solver method and explain: (a) blending three coal grades to minimise cost subject to ash and calorific value limits; (b) setting prices for four SKUs where demand falls exponentially with price; (c) selecting distribution centres where costs include fixed charges switched on with IF.

Q5. Linking to CMA theory [L1]

Explain how the Solver sensitivity report corresponds to the dual (shadow) prices and slack variables of the simplex tableau studied in CMA Operations Research, and why the report is unavailable when integer constraints are added.
