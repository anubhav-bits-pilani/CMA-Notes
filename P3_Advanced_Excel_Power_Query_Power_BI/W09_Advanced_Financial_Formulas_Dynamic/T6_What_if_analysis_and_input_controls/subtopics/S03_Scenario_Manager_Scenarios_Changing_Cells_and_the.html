Scenario Manager: Scenarios, Changing Cells and the Summary Report

Scope: Scenario Manager: scenarios, changing cells, and the Scenario Summary report

Why it matters

Boards, lenders and rating agencies ask for cases — Base, Upside, Downside, sometimes a lender's "stress" case — where several assumptions move together (volume, price, raw-material cost, working-capital days, capex). A Data Table flexes one or two inputs; Scenario Manager stores named sets of up to 32 input values and swaps them into the model, then produces a Scenario Summary report comparing chosen outputs across all scenarios. It is quick for one-off analysis on a model that was not designed with a scenario switch, and it appears in CMA/CFA-style Excel tests. Understanding its limits — the summary is a static snapshot, and scenarios overwrite inputs — explains why professional models usually prefer a live CHOOSE/INDEX switch.

Core notes

Concepts

Term Meaning
Scenario A named set of values for the changing cells (e.g. "Downside")
Changing cells The input cells the scenario overwrites — up to 32 per scenario; contiguous or Ctrl-selected
Result cells Output formulas shown in the Summary report (chosen when the report is generated)
Show Writes the scenario's values into the changing cells (the model recalculates)
Summary Creates a new sheet comparing changing-cell values and result cells for all scenarios
Merge Imports scenarios from another sheet or workbook with the same layout

Path: Data → What-If Analysis → Scenario Manager (Alt, A, W, S).

Step-by-step

  1. Name the cells first. Give each changing cell and result cell a defined name (e.g. Vol_Growth, RM_Inflation, EBITDA_FY27). The summary report uses names as row labels; without names, it shows absolute cell addresses (C7 with dollar signs on both parts), which are unreadable.
  2. Save the base case as a scenario before anything else. Scenario Manager overwrites inputs; if you never saved Base, the original values are lost once you Show another scenario.
  3. Add scenarios. Add → name ("Downside"), select changing cells (up to 32), optionally add a comment (author, date, source). Enter values for each changing cell. Values are stored as constants; if you type a formula like =0.05*2, it is converted to its value.
  4. Protection options: "Prevent changes" and "Hide" take effect only when the sheet is protected.
  5. Show a scenario to load it into the model — useful for walking a committee through a case live.
  6. Summary: choose "Scenario summary" (or "Scenario PivotTable report") and the result cells. Excel creates a new sheet.

Illustration

FY27 budget for a packaged-foods company (NSE-listed), three scenarios, four changing cells, three result cells:

Changing cell Base Upside Downside
Vol_Growth 8% 12% 3%
Price_Increase 4% 5% 2%
RM_Inflation 6% 4% 10%
Receivable_Days 38 35 45

Summary report (₹ crore, illustrative):

Current values Base Upside Downside
Revenue_FY27 1,894 1,894 2,000 1,770
EBITDA_FY27 246 246 292 168
FCF_FY27 112 112 151 48

The "Current values" column reflects whatever scenario (or manual inputs) the model held when the summary was generated. The report is formatted with outline grouping and the scenario comments.

The summary is static

The Summary sheet contains values, not formulas. If you later change a non-scenario assumption (say the tax rate or capex), the summary does not update; you must regenerate it (and delete the old sheet). This is the central weakness: a board pack built from an old summary can silently disagree with the model. Date-stamp every summary and regenerate as a close step.

Scenario Manager vs a live scenario switch

Aspect Scenario Manager CHOOSE/INDEX switch (w9_t2)
Storage of case values Hidden inside the scenario objects Visible on an assumptions sheet, side by side
Changing cells Up to 32 Unlimited
Output comparison Static summary Live; or a Data Table over the scenario index for a live comparison
Audit Hard — values only visible via Edit dialog Easy — every case value is a cell
Setup on an existing model Fast, no restructuring Requires building case columns and switch formulas
Risk Overwrites inputs Inputs untouched; selected via dropdown

A powerful hybrid: build a live switch with a scenario index cell, then use a 1D Data Table with the index (1, 2, 3) as the column input and outputs across the top. That gives a live, always-current scenario comparison — the professional replacement for the Scenario Summary.

Scenarios across sheets

Scenarios are stored per sheet; changing cells must be on the active sheet. For models with inputs on a dedicated Inputs sheet, define scenarios there. Merge (from another sheet or workbook) brings in scenarios built by colleagues — common when regional heads submit their own downside cases on a template.

Edge cases & judgement calls

  • Overwriting the base. Showing a scenario replaces live inputs; if the model is saved in that state, the next user may think the downside is the base. Always Show Base before saving, and display the active scenario name in the header (a cell that compares inputs with stored case values).
  • More than 32 drivers. Not supported; this alone pushes serious models to a switch design.
  • Formulas in changing cells are replaced by constants when a scenario is shown — never select formula cells as changing cells.
  • Names matter. Without defined names, the summary is unreadable; with renamed or deleted names, the summary shows addresses.
  • Version control. Scenario values are invisible in the grid, so file comparison tools (Inquire, Spreadsheet Compare) are the only way to diff them.
  • Lender cases. Banks' stress cases often require DSCR outputs per year; Summary shows only single cells, so create result cells for minimum and average DSCR.

Key takeaways

  • Scenario Manager stores named sets of up to 32 changing-cell values and swaps them into the model.
  • Name changing and result cells first, and save the Base case before showing any other scenario.
  • The Scenario Summary is a static values snapshot — regenerate it whenever any assumption changes.
  • For production models, prefer a live CHOOSE/INDEX switch plus a Data Table over the scenario index.
  • Scenario Manager remains useful for quick, one-off case analysis on models without a switch.

Practice Questions

Q1. Set up three scenarios [L1]

List the exact steps (including naming and the base-case precaution) to create Base, Upside and Downside scenarios with five changing cells — volume growth, price increase, RM inflation, employee cost increase and capex — and a summary showing FY27 revenue, EBITDA, PAT and closing net debt.

Q2. Stale summary [L2]

A board pack shows a Scenario Summary dated 12-Jan-2026. On 20-Jan-2026 the effective tax rate assumption was changed from 25.17% to 26.5% to reflect expected disallowances, and capex was cut by ₹40 crore. Neither input is a changing cell in the scenarios. Explain which numbers in the summary are now wrong, how a reviewer could detect it, and the process change you would recommend.

💡 Hint: Distinguish the stored changing-cell values, which are still valid, from the result values, which depend on inputs outside the scenarios.

Q3. Convert to a live switch [L2]

Describe how you would convert a model that uses Scenario Manager (4 scenarios × 12 changing cells) into a live scenario switch with a dropdown, and how you would reproduce the Scenario Summary as a live table.

Q4. Lender stress case [L3]

A bank requires a stress case with volume −10%, price −3%, interest rate +200 bp and debtor days +20 for a ₹350 crore term loan model, and wants minimum DSCR, average DSCR and the year of minimum DSCR. Explain how you would deliver this using Scenario Manager, what result cells you would build, and the risks of delivering the bank a static summary.

Q5. Interview: Scenario Manager limits [L1]

Give three limitations of Scenario Manager that an interviewer would expect you to know, and one situation in which you would still use it.
