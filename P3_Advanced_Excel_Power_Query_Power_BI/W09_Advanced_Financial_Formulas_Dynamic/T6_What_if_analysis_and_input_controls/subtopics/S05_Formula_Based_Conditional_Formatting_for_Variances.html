Formula-Based Conditional Formatting for Variances and Scenarios

Scope: Formula-based Conditional Formatting: negative variances, threshold bands, highlighting the selected scenario column

Why it matters

A budget-vs-actual pack with 60 lines × 12 months is unreadable unless the eye is drawn to what matters: adverse variances, lines breaching a materiality threshold, the scenario currently driving the model, failed check cells. Built-in "Highlight Cells Rules" work on a cell's own value; formula-based rules can test other cells, combine conditions, and reference named thresholds — so formatting follows the model's logic rather than the cell's content. In FP&A reporting this is how you get a variance report that highlights itself after every refresh, and in modelling it is how a reviewer instantly sees which scenario column is live and whether every check is green.

Core notes

How formula rules evaluate

Home → Conditional Formatting → New Rule → "Use a formula to determine which cells to format" (Alt, H, L, N). You write a formula that returns TRUE/FALSE as if for the top-left cell of the Applies-to range. Excel then adjusts relative references for every other cell, exactly like copying a formula. That is why mixed references are the core skill:

Reference Locks Effect across the block
$E5 Column Every cell in row 5 tests E5 — the whole row is formatted by one column's value
E$4 Row Every cell in column E tests E4 — the whole column is formatted by a header
E5 Neither Each cell tests itself (relative)
Named cell (Thr) Both Every cell tests the same input

Rule 1: negative (adverse) variances — whole row

P&L block B5:H64 with variance in column E (Actual − Budget, sign-adjusted so negative = adverse).

  • Applies to: =B5:H64 (written by Excel in absolute form).
  • Formula: =$E5<0
  • Format: light red fill, dark red font.

Because the column is locked and the row is relative, each row looks at its own column E value, and the whole row from B to H is shaded. Writing =E5<0 instead would test a different column for each cell (C tests E, D tests F …) — the most common CF error.

Sign convention: for revenue lines, adverse = actual below budget; for cost lines, adverse = actual above budget. Normalise in the variance column (e.g. =IF(Type="Cost", Budget-Actual, Actual-Budget)) so a single rule works for all lines.

Rule 2: threshold bands

Highlight variances by size relative to materiality inputs Thr_Amber (₹10 lakh) and Thr_Red (₹25 lakh):

Priority Formula Format
1 =ABS($F5)>=Thr_Red Red fill, Stop If True
2 =ABS($F5)>=Thr_Amber Amber fill

Column F holds the ₹ variance. Rules are evaluated in priority order (Manage Rules → move up/down); "Stop If True" prevents a red cell from also being tested for amber (only matters where formats conflict). Percentage bands are similar: =ABS($G5)>=Pct_Red on a variance % column — but guard tiny budgets, where % variances explode; combine with an absolute floor using AND inside a single rule, e.g. =AND(ABS(F5)>=Thr_Amber, ABS(G5)>=Pct_Amber) applied to a single column, or with mixed references applied to the row.

Threshold cells should be named inputs, not typed into the rule, so materiality can be changed by the controller without editing rules.

Rule 3: highlight the selected scenario column

Assumptions block with Base / Upside / Downside in columns E:G, headers in row 4, and a dropdown SelScen (s04):

  • Applies to: =E4:G40
  • Formula: =E$4=SelScen
  • Format: pale blue fill, bold.

Row is locked, so each column compares its own header with the selection. Change the dropdown to "Downside" and column G lights up — the reviewer sees which values are driving the model.

Rule 4: base case in a sensitivity grid

2D Data Table with growth rates across row 5 (D5:F5) and WACC down column C (C6:C8); highlight the cell matching live inputs TG and WACC:

  • Applies to: =D6:F8
  • Formula: =AND(D$5=TG, $C6=WACC)

Use ROUND on both sides if inputs are calculated (floating-point mismatch can prevent a match): =AND(ROUND(D$5,4)=ROUND(TG,4), ROUND($C6,4)=ROUND(WACC,4)).

Rule 5: check cells and data quality

  • Check cell turns red when not zero: =ABS(C3)>0.5 (tolerance for rounding).
  • Unmapped ledger rows in the TB: =ISNA(XMATCH($A5, Map[Ledger])) — conditional formatting cannot use structured references directly in some versions; use a defined name for Map[Ledger].
  • Future dates in an actuals block: =C$4>LastClose greys out forecast columns.

Management of rules

  • Manage Rules (Alt, H, L, R) with "Show formatting rules for: This Worksheet" lists every rule, its formula, format, Applies-to range and order.
  • Keep one rule per purpose applied to the whole block, rather than many small rules.
  • Clear rules from a range before re-applying; copy formats with Format Painter or Paste Special → Formats knowingly (this duplicates rules — see pitfalls).

Accessibility and design

Do not rely on red/green alone (colour blindness affects roughly 8% of men); pair fills with icon sets, bold, or a text flag column ("Adverse"). Keep the palette consistent across the pack: red = adverse/failed check, amber = watch, blue = input/selected scenario.

Edge cases & judgement calls

  • Relative reference drift. If the Applies-to range starts at row 6 but the formula was written for row 5, every cell tests the row above. Always write the formula for the top-left cell of the Applies-to range.
  • Blank cells. =$E5<0 is FALSE for blanks, but =ABS($F5)>=Thr errors on text; wrap with N() or ISNUMBER.
  • Performance. Thousands of rules or volatile functions (TODAY, INDIRECT, OFFSET) inside rules slow scrolling and recalculation.
  • Cross-sheet references in CF formulas are allowed in modern Excel, but defined names are clearer and survive sheet renames.
  • Inserted rows extend the Applies-to range if inserted inside it; rows appended below are not covered — format the full reserved area or use a Table.
  • Printing/PDF: fills print, but some icon sets and data bars render poorly in PDF board packs; test.

Key takeaways

  • Formula rules are written for the top-left cell of the Applies-to range and adjust like copied formulas.
  • =$E5<0 (column locked) formats whole rows; =E$4=SelScen (row locked) formats whole columns.
  • Put thresholds in named input cells; order rules by priority and use Stop If True for bands.
  • Highlight the live scenario column and the base case in sensitivity grids so reviewers see what drives outputs.
  • Manage rules centrally, avoid duplicates, and do not rely on colour alone.

Practice Questions

Q1. Write the rules [L1]

A budget-vs-actual block occupies B6:N80 with the variance (₹, sign-normalised) in column M and variance % in column N. Write formula rules and Applies-to ranges for: (a) shading the whole row when the variance is adverse; (b) bold red text in column N where the absolute variance % exceeds a named input PctThr; (c) greying out rows where the budget is zero.

Q2. Why is the wrong column shaded? [L2]

A colleague applied =E6<0 to B6:H60 to shade rows with negative variances in column E. Describe what actually happens in columns B, C, D and H, and give the corrected rule.

💡 Hint: Treat the rule as a formula written in B6 and copied across the range.

Q3. Scenario and sensitivity highlights [L2]

Design two rules: one that highlights the active scenario column in an assumptions block (Base/Upside/Downside/Stress in F:I, headers in row 5, selection in SelScen), and one that highlights the base-case cell in a 7 × 7 WACC × growth Data Table. Explain why you might need ROUND in the second rule.

Q4. RAG status pack [L3]

The CFO wants a monthly department pack with red/amber/green status per department for cost variances: red if the adverse variance exceeds both ₹20 lakh and 10% of budget, amber if it exceeds either, green otherwise. Design the variance columns, the CF rules and their priority, and an accessible non-colour indicator.
