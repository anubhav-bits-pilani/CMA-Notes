Subtopic note

One- and Two-Variable Data Tables for Sensitivity Analysis

Scope: 1D Data Tables (one input, many outputs) and 2D Data Tables (two inputs, one output) for sensitivity

Why it matters

Every model output rests on assumptions, and decision-makers want to know how much the answer moves when an assumption moves. A DCF without a WACC × terminal growth grid, a budget without a price or volume sensitivity, or a project appraisal without an IRR-vs-capex table is incomplete in any investment committee, board or banker review. Data Tables are Excel's built-in engine for this: they re-run the entire model for each input value and write the results into a grid, without copying the model. They are also a fixture of the Saturday speed test (2D Data Table) and a standard interview question: "why must the input cells be on the same sheet?".

Core notes

How a Data Table works

A Data Table substitutes each value from its input row/column into a designated input cell in the model, recalculates, and records the output formula's result. Internally Excel writes an array formula {=TABLE(row_input_cell, column_input_cell)} into the result cells. You cannot edit, delete or type over part of it — only the whole result block.

Requirements:

  • The input cell must be a hard-coded assumption that the output depends on (directly or through a chain of formulas).
  • The input cell must be on the same sheet as the Data Table. If your assumptions live on an Inputs sheet, either build the table on the Inputs sheet, or create a local "sensitivity driver" cell on the table's sheet that the Inputs sheet links to in a controlled way (see edge cases).
  • The output reference must be a formula that links to the model's result cell.

Menu path: Data → What-If Analysis → Data Table (keyboard: Alt, A, W, T).

1D Data Table — one input, many outputs

Layout (column-oriented):

B C D E
4 =EBIT =PAT =EBIT_Margin
5 600
6 625
7 650
8 675
9 700
  1. Put the input values (selling price per unit) down column B from B5.
  2. In the row above the first value and one column to the right (C4, D4, E4), link to each output.
  3. Select B4:E9 → Data Table → Column input cell = the price assumption cell. Leave Row input cell blank.

Excel fills C5:E9. For a row-oriented 1D table, put values across a row, outputs down the first column, and use Row input cell.

Illustration: volume 2,00,000 units, variable cost ₹420 per unit, fixed costs ₹3 crore. EBIT = 2,00,000 × (P − 420) − 3,00,00,000.

Price (₹) EBIT (₹ crore)
600 0.60
625 1.10
650 1.60
675 2.10
700 2.60

Each ₹25 price step moves EBIT by ₹50 lakh — a price elasticity view the sales head can use immediately.

2D Data Table — two inputs, one output

Layout: the output formula goes in the top-left corner, row-input values across the top, column-input values down the left.

C D E F
5 =EV 4.0% 5.0% 6.0%
6 11.0%
7 12.0%
8 13.0%

Select C5:F8 → Data Table → Row input cell = terminal growth cell; Column input cell = WACC cell.

Illustration: a simplified Gordon-growth EV with next-year FCF of ₹100 crore, EV = 100 ÷ (WACC − g), in ₹ crore:

WACC \ g 4.0% 5.0% 6.0%
11.0% 1,428.6 1,666.7 2,000.0
12.0% 1,250.0 1,428.6 1,666.7
13.0% 1,111.1 1,250.0 1,428.6

The convexity is visible: a 1-point fall in WACC at 6% growth adds ₹333 crore, at 4% growth only ₹179 crore. That is the key message of a DCF sensitivity — terminal value assumptions dominate.

Presentation conventions

  • Format the corner cell with a custom number format ;;; or a label like "WACC ↓ / g →" by using a format such as "WACC \ g" so the output formula is hidden but still present.
  • Highlight the base case cell (conditional formatting rule comparing row/column values with the live inputs, s05).
  • Keep input steps symmetric around the base case and show the base case in the middle.
  • State units (₹ crore, %), and whether values are per share or equity value.

Multiple outputs in 2D

A 2D table returns only one output. For several outputs (EV, equity value per share, implied EV/EBITDA), build one table per output, or make the corner formula switchable via a dropdown and CHOOSE (w9_t2) — then re-calculate.

Data Tables vs alternatives

Tool Live? Multiple inputs Speed Audit trail
Data Table Yes (recalc) 1 or 2 Slow on big models Visible grid
Scenario Manager (s03) No — static summary Up to 32 cells One-off Snapshot
CHOOSE/INDEX switch (w9_t2) Yes Many, one case at a time Fast Clear
Manual flex with formulas (e.g. direct Gordon formula in each cell) Yes Any Fast Works only when output is a closed-form formula

Data Tables are the only tool that re-runs the full model (including schedules, circularity and checks) for each grid point.

Edge cases & judgement calls

  • Same-sheet rule. If the WACC lives on an Inputs sheet, a common workaround is to put a "sensitivity override" cell beside the table and have the Inputs sheet's WACC formula use it (=IF(Override="", BaseWACC, Override)). This must be documented, and the override left blank after use, or the whole model silently runs on the override value.
  • Calculation mode. Data Tables are often set to "Automatic except for data tables" for speed; results then go stale until F9 (s08).
  • Circularity. Models with iterative calculation (interest on average debt) can make Data Tables unstable; test convergence.
  • Do not reference the table's own results inside the model — it creates circular logic.
  • Row vs column input confusion. Swapping them gives a wrong but plausible grid; check the base-case cell equals the live model output.
  • Grid size. A 15 × 15 table on a large model means 225 full recalculations per change; keep grids to what is presented.

Key takeaways

  • A Data Table substitutes values into an input cell, recalculates the whole model and records results as {=TABLE()}.
  • 1D: values in one column/row, multiple output links; 2D: one output in the corner, two input series.
  • Input cells must be on the same sheet as the table; use a documented override cell if inputs are elsewhere.
  • Check the base-case cell in the grid equals the live model output.
  • Data Tables are slow; manage calculation mode deliberately and press F9 before reading results.

Practice Questions

Q1. Build a 1D table [L1]

A product has a contribution margin of ₹380 per unit at a price of ₹1,200, fixed costs of ₹4.56 crore and budgeted volume of 1.5 lakh units. Describe the layout and Data Table dialog entries for a 1D table showing EBIT, EBIT margin and break-even volume for prices from ₹1,100 to ₹1,300 in steps of ₹50.

Q2. DCF sensitivity grid [L2]

Your DCF has WACC (11.8%) and terminal growth (5.0%) on an Inputs sheet and the per-share value on a Valuation sheet. Design a 2D Data Table showing per-share value for WACC 10.8%–12.8% (0.5% steps) and growth 4.0%–6.0% (0.5% steps). Explain how you handle the same-sheet requirement, how you highlight the base case, and the check you would add.

💡 Hint: Think about where the input cells physically sit and how a blank override cell can make the model revert to base.

Q3. Wrong but plausible [L2]

A colleague's 2D table shows values that decline left to right across growth rates 4%–6%. Identify the most likely set-up error, explain how to confirm it in under a minute, and how to fix it.

Q4. Interview: why same sheet? [L1]

Answer the interview question: "Why must Data Table input cells be on the same sheet as the table, and what do you do in a model where all assumptions sit on one Inputs tab?"

Q5. Choosing the sensitivity tool [L3]

For a 3-statement model with 40 assumptions, a debt schedule with iterative interest and a DCF, recommend which combination of Data Tables, a live scenario switch and Scenario Manager you would use for (a) the board's base/upside/downside presentation, (b) a WACC × growth grid, (c) a 10-variable tornado chart, and justify each choice in terms of speed, auditability and staleness risk.
