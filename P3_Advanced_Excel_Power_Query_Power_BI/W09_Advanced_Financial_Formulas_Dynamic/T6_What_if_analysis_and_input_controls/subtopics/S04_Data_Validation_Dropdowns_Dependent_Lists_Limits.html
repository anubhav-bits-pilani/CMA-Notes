Subtopic note

Data Validation: Dropdowns, Dependent Lists, Limits and Messages

Scope: Data Validation: list dropdowns, dependent dropdowns, whole-number/date limits, input and error messages

Why it matters

Most model errors start at the input layer: a scenario name typed as "Base " with a trailing space, a growth rate keyed as 8 instead of 8%, a cost centre that does not exist, an invoice date in the wrong FY, a PAN with nine characters. Data Validation is the first line of defence — it restricts what can be entered, guides the user with input messages and blocks or warns on invalid values. It also creates the dropdowns that drive scenario switches (w9_t2), department selectors for FILTER reports (w9_t4) and entity selectors for close calendars (w9_t5). In budgeting templates sent to 30 department heads, validation is what makes the consolidated file loadable without a week of clean-up.

Core notes

Where and how

Data → Data Validation (Alt, A, V, V). Three tabs: Settings (criteria), Input Message (shown when the cell is selected), Error Alert (shown on invalid entry). Validation applies to the selected cells; copy it with Paste Special → Validation.

Criteria types

Allow Typical finance use Example setting
Whole number Months of tenor, headcount, credit days between 1 and 120
Decimal Growth %, tax rate, discount rate between −0.2 and 0.5
List Scenario, department, entity, Yes/No source Base,Upside,Downside or a range/name
Date Invoice dates within the FY between =FYStart and =FYEnd
Time Shift timings rarely used in finance
Text length PAN (10), GSTIN (15), IFSC (11) equal to 10
Custom Any formula returning TRUE/FALSE =AND(ISNUMBER(C5), C5>=0)

Criteria bounds can reference cells or names (=FYStart), so limits move with the model.

List dropdowns

Three source options, in increasing robustness:

  1. Typed list: Base,Upside,Downside — fine for fixed short lists; comma separator depends on regional settings.
  2. Range or Table column via a name: define ScenarioList as =Lists!B2:B4, or better, refer to a Table column through a name (=tblScen[Scenario]) — Data Validation does not accept structured references directly, but a defined name that refers to one does, and it grows with the Table.
  3. Spill reference via a name: define DeptList as =Lists!H2# where H2 holds =SORT(UNIQUE(GL[Dept])). The dropdown always shows the current departments in the data. (The Name Manager stores the reference in absolute form automatically.)

Source ranges can sit on another sheet (allowed since Excel 2010). Keep all list sources on a hidden or protected "Lists" sheet.

Dependent dropdowns

Requirement: choose a Department in B2, then a Cost Centre in C2 that belongs to that department.

Classic method — INDIRECT with named ranges

  1. Create one named range per department, named exactly as the department appears in the first list (Sales, Marketing, Plant_Pune), each listing its cost centres.
  2. Validation on C2: List, source =INDIRECT(B2) (with the column of B2 locked if copying across rows).

Department names with spaces or symbols cannot be names; use =INDIRECT(SUBSTITUTE(B2, " ", "_")). INDIRECT is volatile and breaks if a name is renamed — fine for small lists, fragile at scale.

Modern method — FILTER spill

  1. On the Lists sheet, J2: =SORT(FILTER(Map[CostCentre], Map[Dept]=Inputs!B2, "—")).
  2. Name CCList = =Lists!J2#; validation on C2: List, source =CCList.

This works for a single selector cell. For a row-by-row dependent list (each row of a 200-row budget template needs its own filtered list), INDIRECT or an OFFSET/MATCH-based source over a department-sorted mapping table is still needed, or the template is better built in Power Apps or a planning tool.

Clearing the child when the parent changes is not automatic: a C2 value left over from a previous department remains. Add a check cell =COUNTIFS(Map[Dept], B2, Map[CostCentre], C2)=1 and conditional formatting to flag mismatches.

Input messages

The Input Message tab shows a yellow tooltip when the cell is selected: title "WACC (post-tax)", message "Enter as a %, e.g. 11.8%. Source: WACC tab, approved by CFO on 10-Jan-2026." This documents the assumption at the point of entry and reduces the 8 vs 8% problem.

Error alerts

Style Behaviour Use for
Stop Rejects the entry (Retry/Cancel) Hard constraints: scenario names, dates outside FY, negative headcount
Warning Allows after "Continue?" (Yes/No/Cancel) Soft limits: growth above 25%, discount rate outside 8–16%
Information Allows with an OK notice Reminders

Write the message in business terms: "Invoice date must fall in FY26 (01-Apr-2025 to 31-Mar-2026)."

Custom formula examples

=AND(LEN(C5)=10, ISNUMBER(--MID(C5,6,4)), NOT(ISNUMBER(--LEFT(C5,5))))   PAN shape check (5 letters, 4 digits, 1 letter, approximately)
=COUNTIF(C:C, C5)=1                                                        unique voucher or vendor code
=ROUND(C5, 2)=C5                                                           at most 2 decimal places
=C5<=D5                                                                    start date not after end date
=SUM(E5:E16)=1                                                             phasing weights sum to 100% (apply to the last cell)

Custom formulas are written relative to the active (top-left) cell of the selection.

Auditing validation

  • Data → Data Validation → Circle Invalid Data draws red circles around cells that already violate rules (e.g. values pasted in before the rule existed).
  • Go To Special → Data Validation → All/Same selects every validated cell, useful to confirm coverage of the input sheet.

Edge cases & judgement calls

  • Paste bypasses validation. Ctrl+V of a value over a validated cell replaces the rule and the value without warning (pasting a whole cell copies the source's validation, or none). Protect input sheets, ask users to Paste Special → Values (which still bypasses checking but keeps the rule), and run Circle Invalid Data before consolidation.
  • Fixed-range sources do not grow. =Lists!B2:B20 misses the 20th-plus item; use Table-backed names or spill references.
  • Volatile INDIRECT recalculates constantly and breaks on renamed names.
  • Blank cells. "Ignore blank" lets users leave inputs empty; required inputs need a completeness check elsewhere.
  • Regional separators. Typed list sources use the list separator from Windows regional settings (comma or semicolon) — a template built in India may break on a European colleague's PC.
  • Validation is not security. It guides honest users; it does not prevent determined edits. Combine with sheet protection and reconciliations.

Key takeaways

  • Data Validation restricts entries (whole number, decimal, list, date, text length, custom) and documents them with input messages.
  • Use Table-backed names or spill references (=Lists!H2# via a name) so dropdown sources grow automatically.
  • Dependent dropdowns: INDIRECT with named ranges (classic, fragile) or FILTER spill lists (modern, single selector).
  • Choose Stop for hard rules, Warning for soft limits; write messages in business language.
  • Pasting bypasses validation — protect inputs and run Circle Invalid Data before relying on the file.

Practice Questions

Q1. Input sheet design [L1]

For a capex request template, specify the validation type, criteria and error style for: asset category (from a list of 8), cost (₹, positive, up to ₹50 crore), useful life (3–40 years, whole), capitalisation date (within FY27), vendor GSTIN (15 characters), and "Funded by debt?" (Yes/No).

Q2. Dependent dropdown both ways [L2]

The mapping Table Map has 12 departments and 140 cost centres. Build (a) an INDIRECT-based dependent dropdown and (b) a FILTER-spill-based dependent dropdown for a single selector pair (department in B2, cost centre in C2). Compare maintenance effort when a new department "Digital Commerce" is added.

💡 Hint: Consider what has to be created by hand in each method when a department is added.

Q3. Consolidating 30 budget files [L2]

Thirty department heads return a budget template with validation on all inputs. On consolidation you find invalid cost centres and growth rates of 800%. Explain how invalid data got past validation, how you would detect it in each file quickly, and two design changes for next year.

Q4. Custom rules [L2]

Write custom validation formulas for: (a) a phasing row of 12 months that must sum to 100%; (b) a voucher number column that must be unique; (c) an end date that must be at least one month after the start date; (d) a discount rate that must be at least the risk-free rate in a named cell Rf.

Q5. Scenario selector [L1]

Build a scenario dropdown in an Inputs sheet whose list comes from a Table on the Lists sheet, with an input message explaining the cases, and the formula that converts the selected name into the scenario index used by CHOOSE.
