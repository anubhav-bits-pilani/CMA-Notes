Calculation Mode: Automatic Except Data Tables and F9 Recalculation

Scope: Calculation mode "Automatic except for data tables" and manual recalculation with F9

Why it matters

Data Tables re-run the whole model for every cell of the grid. In a 3-statement model with a DCF, a 7 × 7 sensitivity table means 49 extra full recalculations every time anything changes — typing a single input can freeze Excel for seconds or minutes. Teams therefore switch to "Automatic except for data tables" or full Manual mode. That fixes speed but creates the most dangerous kind of error: outputs that look fine but are stale. Sensitivity grids sent to an investment committee showing last week's numbers, or a board pack where totals do not reflect the latest inputs because nobody pressed F9, are real and recurring review findings. Knowing exactly how calculation modes and recalculation keys work — and building checks that expose staleness — is basic model hygiene.

Core notes

The three calculation modes

Formulas → Calculation Options (Alt, M, X), or File → Options → Formulas:

Mode What recalculates automatically Typical use
Automatic Everything, after every change Default; small/medium models
Automatic except for data tables Everything except Data Table results Models with sensitivity grids
Manual Nothing until you press a recalc key Very large models, heavy array formulas, bulk data pastes

In Manual mode, File → Options → Formulas also offers "Recalculate workbook before saving" (on by default) — saving triggers a full calculation.

Recalculation keys

Key Action
F9 Calculate all changed ("dirty") formulas in all open workbooks, including Data Tables
Shift+F9 Calculate the active sheet only
Ctrl+Alt+F9 Force a full calculation of all formulas in all open workbooks, dirty or not
Ctrl+Alt+Shift+F9 Rebuild the dependency tree, then full calculation (use when results seem wrong even after Ctrl+Alt+F9)
F2 then Enter Recalculate a single cell (edits and re-enters it)

Formulas → Calculate Now / Calculate Sheet are the ribbon equivalents.

Status bar signal: when calculation is pending, Excel shows "Calculate" in the status bar. In "Automatic except for data tables" mode it appears after any change that affects a Data Table. Train yourself and users to look for it before reading or printing results.

The mode is application-wide

Calculation mode is a setting of the Excel session, not of each workbook, with a twist: the first workbook opened in a session sets the mode, and it is saved with workbooks. Consequences:

  • Open a model saved in Manual first, and every other workbook you open in that session — including your simple reconciliation — is also in Manual. Your reconciliation's totals will not update.
  • Open a normal workbook first, then the Manual model, and the model runs in Automatic (possibly slowly).

Mitigations: put a visible mode indicator on the model's cover sheet, and include an instruction ("Set calculation to Automatic except for data tables; press F9 before reading sensitivities"). A cell cannot read the mode with a built-in function without VBA (Application.Calculation); use a check instead (below).

Staleness checks

Because the base case is part of every sensitivity grid, compare the grid's base-case cell with the live model output:

=ABS(INDEX(SensGrid, MATCH(WACC, WACC_Row_Hdr, 0), MATCH(TG, TG_Col_Hdr, 0)) - Live_EV) < 0.5

If FALSE, the table is stale (or mis-set-up). Show the result as "SENSITIVITY STALE — PRESS F9" with red conditional formatting near the grid and on the model's check summary. This one check catches both forgotten recalculation and row/column input errors.

Similarly, for Manual-mode models, a timestamp check: a cell with =NOW() (volatile) updates only on recalculation — show "Last calculated: dd-mmm hh:mm" on the cover sheet so readers know how fresh results are.

Making models faster instead

Manual mode is a workaround; improving speed is better:

  • Replace volatile functions (OFFSET, INDIRECT, TODAY, NOW, RAND) with INDEX/XLOOKUP and static inputs (OFFSET and INDIRECT force recalculation of all dependents on every change).
  • Avoid whole-column references in SUMIFS/SUMPRODUCT/array formulas; use Tables or bounded ranges.
  • Keep Data Tables small and few; consider placing them in a separate sensitivity workbook linked to the model, or compute sensitivities with closed-form formulas where possible.
  • Move heavy data processing (100k+ rows) to Power Query (Week 10).
  • Use LET to avoid repeated sub-calculations (w9_t4).
  • Turn off iterative calculation unless a deliberate circularity requires it, and add a circuit-breaker switch for circular interest.

Iterative calculation (circular references)

Models computing interest on average debt (interest depends on closing debt, which depends on cash flow after interest) create intentional circularity. File → Options → Formulas → Enable iterative calculation, with Maximum Iterations (default 100) and Maximum Change (0.001). Combined with Data Tables and Manual mode, circular models can produce unstable or non-converged results. Include a circuit breaker input (=IF(CircBreak, 0, average-debt interest)) to reset errors, and test that results converge.

Illustration

A DCF workbook with a 7 × 7 WACC × growth table and a 5 × 5 revenue growth × margin table: in Automatic mode each input change takes about 12 seconds; in "Automatic except for data tables" it is instant. An analyst changes the FY27 capex input from ₹180 crore to ₹220 crore and emails the valuation sheet: EV on the summary updates (₹4,862 crore → ₹4,815 crore), but the sensitivity grid still shows ₹4,862 crore in its base cell. The staleness check shows "SENSITIVITY STALE — PRESS F9". After F9, the grid's base cell reads ₹4,815 crore and the check clears.

Edge cases & judgement calls

  • Saving in Manual mode with "Recalculate before saving" turned off can store stale values — never turn it off for shared models.
  • Linked workbooks. F9 recalculates open workbooks only; closed source files' values are taken from the last saved state — refresh links (Data → Edit Links) first.
  • Power Query and PivotTables do not refresh with F9; they need Refresh All (Ctrl+Alt+F5).
  • Excel for the web has limited calculation options; models relying on Manual mode behave differently when opened online.
  • Volatile functions in Manual mode still update on every F9, so NOW() timestamps reflect the last recalc, not the last input change.
  • Team conventions. Agree a standard (e.g. "Automatic except data tables" + staleness check) across the FP&A team and state it on every model's cover sheet.

Key takeaways

  • "Automatic except for data tables" keeps the model live while freezing sensitivity grids until F9.
  • F9 calculates changed formulas in all open workbooks; Shift+F9 the active sheet; Ctrl+Alt+F9 everything.
  • The calculation mode is session-wide and set by the first workbook opened — a common source of stale results elsewhere.
  • Build a base-case staleness check that compares the grid with the live output and flags "press F9".
  • Prefer making models faster (no volatile functions, bounded ranges, fewer tables) over relying on Manual mode.

Practice Questions

Q1. Keys and modes [L1]

State what happens in each case: (a) Automatic except data tables, you change WACC and do nothing else; (b) same, then press Shift+F9 on a different sheet from the Data Table; (c) Manual mode, you change an input and save with default options; (d) Manual mode set by the first workbook, and you open a simple TB reconciliation and paste a new TB.

Q2. Staleness check [L2]

Your valuation sheet has a 7 × 7 grid (WACC 10.5%–13.5% down rows in C10:C16, growth 3.5%–6.5% across D9:J9) with the live EV in EV_Live and inputs WACC and TG. Write the staleness check formula and the conditional format that displays a warning, and explain why it also catches a swapped row/column input set-up.

💡 Hint: Look up the grid value at the live WACC and growth, then compare it with the live EV within a tolerance.

Q3. Slow model triage [L2]

A 25 MB budget model takes 40 seconds to recalculate. It has 14 Data Tables, OFFSET-based rolling sums, SUMPRODUCT on whole columns of a 3-lakh-row GL, and iterative calculation enabled. Prioritise five changes to improve speed, explaining the expected impact of each.

Q4. Process control [L3]

Draft the model-governance rules (cover-sheet indicators, checks, sign-off steps) for an FP&A team whose valuation and budget models use Data Tables and occasionally Manual mode, so that no sensitivity output or board-pack number is ever distributed stale.
