Key concept

Scenario Manager Limits: 32 Changing Cells and a Static Summary

Concept: Scenario Manager allows up to 32 changing cells, and its summary is a static snapshot, not linked

Statement

  • Each scenario in Scenario Manager can specify at most 32 changing cells; their values are stored as constants inside the scenario object on the sheet.
  • The Scenario Summary (and Scenario PivotTable) report is generated as a new sheet containing values only:

\[ \text{Summary}_{k,s} = f_k\big(\text{inputs with scenario } s \text{ applied}\big)\ \text{evaluated at generation time} \]

where \(f_k\) is result cell \(k\) and \(s\) a scenario. Later changes to any input, scenario or formula do not update the summary.

Explanation

The 32-cell limit. A three-statement model typically has far more than 32 drivers that move between cases (volume and price by segment, cost inflation by category, working-capital days, capex, funding). Workarounds — driving many inputs from a few "master" scenario cells (e.g. a case-level growth multiplier) — reduce transparency. The limit is a key reason professional models use a live scenario switch (CHOOSE/INDEX on a case index, w9_t2), which has no limit and keeps every case value visible.

Static summary. Excel generates the summary by showing each scenario in turn, recalculating, and pasting the result values into a report. Nothing links back to the model. So:

  • If a non-scenario input changes (tax rate, capex, opening balances after audit), every number in the summary may be wrong.
  • If a scenario's values are edited, the summary still shows the old values.
  • If result-cell formulas are corrected, the summary keeps the pre-correction outputs.

Controls: date-stamp the summary, regenerate it as a step in the reporting checklist, delete old summaries, and add a check comparing the summary's current-scenario column with live outputs. Better still, replace it with a live comparison: a 1D Data Table with the scenario index (1, 2, 3 …) as the column input and outputs across the top — it recalculates (subject to calculation mode) whenever the model changes.

Other properties worth knowing:

  • Scenario values are constants; formulas entered as scenario values are converted to values.
  • Showing a scenario overwrites the changing cells — save the Base case as a scenario first.
  • Scenarios belong to a sheet; changing cells must be on that sheet. Merge copies scenarios from other sheets or workbooks.
  • The summary uses defined names as labels; without names it shows cell addresses.

Illustration

A cement company's FY27 model with scenarios Base/Upside/Downside on 6 changing cells. Summary generated on 08-Feb-2026 shows Downside EBITDA ₹1,140 crore. On 15-Feb-2026 the power-and-fuel cost assumption (not a changing cell) is raised by ₹180 per tonne on 32 million tonnes of volume — a ₹576 crore cost increase in all scenarios. The live model's Downside EBITDA is now ₹564 crore; the summary still says ₹1,140 crore. A board pack built from the 08-Feb summary would overstate Downside EBITDA by ₹576 crore with no visible error.

The live alternative — a Data Table over the scenario index — would show ₹564 crore after F9.

Connections

Summarises the limits discussed in s03 and motivates the CHOOSE/INDEX scenario switch (w9_t2, topic related item). The live replacement uses a 1D Data Table (s01, c01) and is subject to the calculation-mode discipline of s08. Scenario cases feed the 3-statement model and DCF cases in Weeks 13–16.

Practice Questions

Q1. Recall the limits [L1]

State the maximum number of changing cells per scenario, what the Scenario Summary contains, and two events that make an existing summary wrong.

Q2. Live replacement [L2]

Design a live scenario comparison for four cases (Base, Upside, Downside, Lender stress) showing FY27 revenue, EBITDA, PAT, net debt and minimum DSCR, using a scenario index cell and a 1D Data Table. Specify the layout, the TABLE input cell and the check that the Base column equals the live model when Base is selected.

💡 Hint: The Data Table's column input cell is the scenario index that CHOOSE or INDEX reads.

Q3. More than 32 drivers [L2]

A model needs 45 inputs to change between cases. Compare (a) consolidating them into 32 or fewer master drivers within Scenario Manager with (b) a case-column assumptions sheet and a live switch, on transparency, auditability and effort.
