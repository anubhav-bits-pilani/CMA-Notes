Subtopic note

Coercing TRUE/FALSE to 1/0: Double Unary, ×1 and N()

Scope: Coercion: double unary --, multiplying by 1, N(); how TRUE/FALSE become 1/0

Why it matters

Every boolean-array formula — SUMPRODUCT conditions, XLOOKUP on (cond1)*(cond2), FILTER logic, counting flags — depends on converting logical values into numbers. Excel does this automatically in some contexts and refuses in others, and that difference explains a large share of "why is my SUMPRODUCT returning 0?" questions. Knowing exactly when and how coercion happens lets you write formulas that are correct, readable and robust to dirty data — and answer a classic interview question about what -- does.

Core notes

Logical values in Excel

TRUE and FALSE are a distinct data type. Comparisons (=, <>, >, …) and IS-functions return them. Excel treats them as 1 and 0 in arithmetic, but many aggregation functions ignore them when they appear inside ranges or arrays:

Expression Result Why
=TRUE+TRUE 2 arithmetic coerces
=SUM(TRUE,TRUE) 2 logicals typed directly as arguments are counted
=SUM(A1:A2) with TRUE, TRUE in cells 0 SUM ignores logicals in ranges
=SUMPRODUCT(A2:A6="West") 0 logical array not coerced; SUMPRODUCT treats non-numerics as 0
=SUMPRODUCT(--(A2:A6="West")) count of "West" coerced to 1/0

That fourth row is the trap: a SUMPRODUCT with a single bare condition returns 0, not the count.

Coercion methods

Method Example Notes
Double unary --(Region="West") First minus turns TRUE into -1, second into +1. Explicit, fast, the most common idiom
Multiply by 1 (Region="West")*1 Same result; readable to non-specialists
Add zero (Region="West")+0 Same result
Multiply conditions together (Region="West")*(FY="FY26") Coerces both and applies AND in one step
N() N(TRUE) → 1 Works on a single value; on arrays its behaviour is inconsistent across versions — do not rely on it for array coercion
-- on text numbers --"125" → 125 Also converts numeric text to numbers (like VALUE)

N() converts TRUE to 1, FALSE to 0, numbers to themselves, dates to serials and text to 0. Its main legitimate modern use is single-cell: embedding a comment in a formula (=SUM(A1:A5)+N("Excludes inter-co")), or coercing a single logical cell.

Comma form vs multiplication form in SUMPRODUCT

=SUMPRODUCT(--(Region="West"), --(FY="FY26"), Revenue)
=SUMPRODUCT((Region="West") * (FY="FY26") * Revenue)

Both give the same answer on clean data, but they differ on dirty data:

  • Comma form: each argument is a separate array; SUMPRODUCT multiplies them internally and treats non-numeric entries as zero. Text in Revenue (e.g. "n/a", or "1,25,000" stored as text) is silently treated as 0. The conditions must be coerced (--) because SUMPRODUCT would treat raw TRUE/FALSE as zeros too.
  • Multiplication form: the * operator does the arithmetic first, so text in Revenue produces #VALUE! for that element and the whole result is #VALUE! — unless the text is numeric-looking, in which case * coerces it to a number.

Choose deliberately: the multiplication form fails loudly on bad data (good for controls); the comma form is tolerant (useful when text placeholders are expected, risky when numbers-as-text are possible because they are dropped silently).

Where coercion happens automatically

  • Inside arithmetic: (cond)*Amount, (cond)+(cond), (cond)/1.
  • In comparisons combined by arithmetic in FILTER: FILTER(data, (c1)*(c2)) — FILTER accepts the 1/0 array as include flags.
  • In XLOOKUP lookup arrays: XLOOKUP(1, (c1)*(c2), …) — the multiplication creates numbers, so look up 1, not TRUE.
  • In Microsoft 365 SUM((cond)*(values)) — arithmetic inside the array, then SUM of numbers.

Where it does not happen: as raw logical arrays passed directly to SUM, SUMPRODUCT, AVERAGE, or as the lookup array when looking up 1.

Worked illustration

Region FY Revenue (₹ lakh)
West FY26 420
North FY26 315
West FY25 380
West FY26 "n/a"
West FY26 145
  • =SUMPRODUCT(Region="West") → 0 (no coercion).
  • =SUMPRODUCT(--(Region="West")) → 4.
  • =SUMPRODUCT(--(Region="West"), --(FY="FY26"), Revenue) → 565 (the "n/a" row counts as 0).
  • =SUMPRODUCT((Region="West")*(FY="FY26")*Revenue) → #VALUE! (text in a multiplied element).
  • If the fourth row held "250" as text, the comma form would still give 565 (text ignored) but the multiplication form would give 815 (text coerced) — two "correct-looking" answers differing by ₹250 lakh.

Edge cases & judgement calls

  • Numbers stored as text — the single most important reason to know which form you are using. Test with SUMPRODUCT(--ISTEXT(Revenue)) before trusting either form.
  • Blank cells — treated as 0 in arithmetic and ignored by the comma form; neither errors.
  • Error values in any array propagate in both forms (#N/A in Revenue → #N/A result). Use IFERROR inside only if you understand why the errors exist.
  • Booleans stored in cells (TRUE/FALSE typed or from formulas) need coercion too: SUMPRODUCT(--Flag, Amount).
  • Readability — reviewers outside finance modelling often do not recognise --; a short note or *1 can help.

Key takeaways

  • TRUE/FALSE are logicals; arithmetic converts them to 1/0, but SUM/SUMPRODUCT ignore raw logical arrays.
  • --(cond) is the standard explicit coercion; *1, +0 and multiplying conditions together also work.
  • N() coerces single values; do not depend on it for arrays.
  • Comma-form SUMPRODUCT treats text as zero silently; the * form errors on non-numeric text and coerces numeric text.
  • Test for text in value columns before choosing a form, and prefer the form that fails loudly in control checks.

Practice Questions

Q1. Predict the results [L1]

For a 6-row Table with Flag column values TRUE, FALSE, TRUE, TRUE, FALSE, TRUE and Amount values 10, 20, 30, "x", 50, "60" (text), state what each returns and why: SUM(T[Flag]), SUMPRODUCT(--T[Flag]), SUMPRODUCT(--T[Flag], T[Amount]), SUMPRODUCT(T[Flag]*T[Amount]).

Q2. Choosing the form for a control check [L2]

You are building a check that the sum of FY26 West-region revenue in the sales register equals the figure in the MIS. The register is exported from an e-commerce platform and occasionally contains "NA" in the revenue column. Which SUMPRODUCT form would you use, and what additional check cell would you add? Justify.

💡 Hint: Consider which failure you want to see rather than suppress.

Q3. Interview: what does -- do? [L1]

Explain to an interviewer, in under a minute, what the double unary operator does, why one minus is not enough, and give one formula where it is required and one where it is unnecessary.

Q4. Coercion in lookups [L2]

A colleague writes =XLOOKUP(TRUE, (T[Branch]=B2)*(T[Ledger]=C2), T[Amount]) and gets #N/A for every row. Explain the cause and give two corrected versions.
