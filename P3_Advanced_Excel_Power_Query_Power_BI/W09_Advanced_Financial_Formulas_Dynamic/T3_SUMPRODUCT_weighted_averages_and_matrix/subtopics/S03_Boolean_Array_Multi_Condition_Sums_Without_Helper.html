Subtopic note

Boolean-Array Multi-Condition Sums Without Helper Columns

Scope: Multi-condition sums with boolean arrays and no helper columns, including functions on ranges (MONTH, LEFT)

Why it matters

SUMIFS is fast but rigid: its criteria ranges must be raw worksheet ranges, and each criterion must be a simple comparison against a value. Many real reporting conditions are not like that — "April postings of any year", "accounts whose code starts with 5", "rows where the amount exceeds that customer's credit limit", "weekend postings", "narration contains GST but not RCM". Building a helper column for each is slow to maintain and clutters the data. Boolean arrays inside SUMPRODUCT express any such condition in one formula, evaluated row by row over the whole column.

Core notes

The pattern

\[ \text{Result} = \sum_{i} \left( \prod_{k=1}^{K} \mathbf{1}\left[C_k(\text{row}_i)\right] \right) \times v_i \]

where \(C_k\) are the \(K\) conditions evaluated on row \(i\), \(\mathbf{1}[\cdot]\) is 1 when the condition is TRUE and 0 otherwise, and \(v_i\) the value to sum. In Excel:

=SUMPRODUCT((condition1) * (condition2) * … * values)

Each parenthesised condition returns an array of TRUE/FALSE; multiplying converts them to 1/0 and keeps only rows where every condition is TRUE (AND logic). Multiplying by the value column then leaves the value on qualifying rows and 0 elsewhere; SUMPRODUCT adds them up.

Functions on ranges — what SUMIFS cannot do

=SUMPRODUCT((MONTH(GL[Date])=4) * (LEFT(GL[Account],1)="5") * GL[Amount])
  • MONTH(GL[Date]) returns an array of month numbers for every row; =4 tests April.
  • LEFT(GL[Account],1) returns the first character of every code as text — this works on numeric codes too, because LEFT converts its argument to text — so the comparison is with "5", not 5.
  • SUMIFS would need helper columns for month and first digit; here none is needed.

Other useful row-wise functions:

Condition Expression
Specific year YEAR(GL[Date])=2025
Fiscal quarter Q3 (Oct–Dec) ROUNDUP((MOD(MONTH(GL[Date])-4,12)+1)/3,0)=3
Weekend posting WEEKDAY(GL[Date],2)>5
Narration contains "RCM" ISNUMBER(SEARCH("RCM", GL[Narration]))
Code in 5-series and 6-series (LEFT(GL[Account],1)="5")+(LEFT(GL[Account],1)="6")
Amount above row's own limit AR[Balance]>AR[CreditLimit]
Case-sensitive match EXACT(GL[Ref], "Ab12")
Round amounts MOD(GL[Amount],100000)=0

OR logic

Add conditions instead of multiplying, and convert the count to a 1/0 flag:

=SUMPRODUCT(((GL[Dept]="Sales")+(GL[Dept]="Marketing")>0) * GL[Amount])

The >0 matters when OR conditions can overlap (a row satisfying both would otherwise count twice). Mixed AND/OR: (A)*((B)+(C)>0).

Counting and averaging

  • Count: =SUMPRODUCT((cond1)*(cond2)) — no value column.
  • Conditional average: =SUMPRODUCT((cond)*values)/SUMPRODUCT(--(cond)) (guard for zero).
  • Conditional weighted average: =SUMPRODUCT((cond)*w*x)/SUMPRODUCT((cond)*w).

Worked illustration

Date Account Dept Amount (₹)
12-Apr-2025 510100 Plant 8,40,000
19-Apr-2025 640500 Admin 2,10,000
26-Apr-2025 520300 Plant 1,65,000
03-May-2025 510100 Plant 7,90,000
14-Apr-2026 510100 Plant 9,05,000

=SUMPRODUCT((MONTH(GL[Date])=4)*(LEFT(GL[Account],1)="5")*GL[Amount]) evaluates:

  • Month = 4 → {1;1;1;0;1}
  • First digit "5" → {1;0;1;1;1}
  • Product × Amount → {8,40,000; 0; 1,65,000; 0; 9,05,000}
  • Sum = ₹19,10,000.

Notice the April 2026 row is included: MONTH()=4 means April of any year. For April 2025 only, add (YEAR(GL[Date])=2025) — or, better, use a date-range condition (GL[Date]>=DATE(2025,4,1))*(GL[Date]<=DATE(2025,4,30)), at which point SUMIFS could do the job faster.

When to use SUMPRODUCT vs SUMIFS vs helper columns

Situation Best choice
Simple equality and range criteria SUMIFS
Function of a column (MONTH, LEFT, SEARCH) used in a few cells SUMPRODUCT
Same derived condition used in hundreds of cells helper column (or Power Query column) + SUMIFS
Row-vs-row comparisons (balance > limit) SUMPRODUCT or a helper flag
Microsoft 365 users only SUM((cond)*values) also works

A helper column computed once (e.g. FiscalMonth) and referenced by SUMIFS across a 40 × 12 grid is far faster than 480 SUMPRODUCTs each recomputing MONTH over 2 lakh rows.

Edge cases & judgement calls

  • Blank dates — MONTH("") on a blank cell returns 1 (blank is treated as 0, i.e. 00-Jan-1900), so blanks count as January. Add (GL[Date]<>"").
  • Text dates — MONTH() on a text date that Excel can parse returns a month; on unparseable text it returns #VALUE! and the whole SUMPRODUCT errors.
  • Text in the value column — the * form errors with #VALUE! (see the coercion subtopic); clean the data or use the comma form deliberately.
  • Leading zeros — LEFT on a numeric code drops leading zeros (they are not stored), so codes like 0450 become "4"; standardise codes as text if leading zeros carry meaning.
  • Unequal array sizes give #VALUE!; Table columns avoid the problem.

Key takeaways

  • SUMPRODUCT((cond1)*(cond2)*values) sums under any row-wise conditions, AND-combined by multiplication.
  • Functions on ranges (MONTH, YEAR, LEFT, SEARCH, WEEKDAY) are the main reason to use it over SUMIFS.
  • LEFT returns text, so compare with "5"; MONTH()=4 ignores the year.
  • OR logic is addition with >0; counts drop the value column; averages divide two SUMPRODUCTs.
  • For conditions reused across a large grid, a helper column plus SUMIFS is faster.

Practice Questions

Q1. Write the conditions [L1]

From Table GL (Date, Account, Dept, Narration, Amount), write SUMPRODUCT formulas for: (a) Q1 FY26 (Apr–Jun 2025) postings to accounts starting with "6"; (b) weekend postings in March 2026; (c) postings whose narration contains "RCM" in departments other than Admin.

Q2. Any-year trap [L2]

A management report labelled "April 2025 raw-material cost" uses =SUMPRODUCT((MONTH(GL[Date])=4)*(LEFT(GL[Account],2)="51")*GL[Amount]) on a GL Table that now holds FY25 and FY26 data. Identify the error, quantify which rows are wrongly included, and rewrite the formula two ways — one with SUMPRODUCT and one with SUMIFS.

💡 Hint: MONTH strips the year; a date range keeps it.

Q3. Credit-limit breach exposure [L2]

Table Cust has Customer, Segment, Balance, CreditLimit, Overdue90. Write single-cell formulas for: the number of customers above their credit limit; the total excess over limit for the "Distributor" segment; and the total balance of customers that are either above limit or have any amount overdue beyond 90 days.

Q4. Fiscal quarter without helpers [L2]

Write a SUMPRODUCT that sums GL[Amount] for fiscal Q3 (October–December) of FY26 for the 5-series accounts, using only functions on the Date and Account columns. Then explain why, for a 12-quarter × 30-line grid on 3 lakh rows, you would add a helper column instead.

Q5. Blank-date audit [L1]

A GL dump has 214 rows with blank dates (opening balance lines). Explain how they affect SUMPRODUCT((MONTH(GL[Date])=1)*GL[Amount]) and correct the formula.
