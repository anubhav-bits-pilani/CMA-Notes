Key concept

Comma-Form SUMPRODUCT and Why Arrays Must Be Numeric

Concept: =SUMPRODUCT(--(Region="West"), --(FY="FY26"), Revenue): comma-separated arrays must be numeric

Statement

For \(k\) comma-separated arrays \(X^{(1)}, \dots, X^{(k)}\) of identical dimensions, SUMPRODUCT returns

\[ \text{SUMPRODUCT} = \sum_{i} \prod_{j=1}^{k} \tilde{x}^{(j)}_i, \qquad \tilde{x} = \begin{cases} x & \text{if } x \text{ is a number} \\ 0 & \text{otherwise (text, logical, blank)} \end{cases} \]

where \(i\) runs over the positions of the arrays. Because non-numeric entries — including TRUE and FALSE — become 0, the logical arrays Region="West" and FY="FY26" must be converted to 1/0 with the double unary -- before being passed as separate arguments.

Explanation

Why the -- is needed here. In the comma form, SUMPRODUCT receives three arrays and multiplies them internally. It does not coerce logicals: a raw (Region="West") array would be read as all zeros and the result would be 0. -- converts TRUE to 1 and FALSE to 0 before SUMPRODUCT sees the array. Any equivalent coercion works ((Region="West")*1, +0).

The text-as-zero behaviour. The same rule applies to Revenue: a text entry such as "n/a" or a number stored as text ("1,25,000") is treated as 0 without warning. This is the defining difference from the multiplication form SUMPRODUCT((Region="West")*(FY="FY26")*Revenue), where the * operator evaluates first: non-numeric text gives #VALUE! (loud failure) and numeric-looking text is coerced to a number.

Revenue cell content Comma form Multiplication form
420 (number) 420 420
"n/a" 0 (silent) #VALUE!
"250" (number stored as text) 0 (silent) 250
blank 0 0
#N/A #N/A #N/A

Same dimensions. All arrays must be the same size and shape; otherwise #VALUE!. Table columns guarantee alignment.

Readability and style. Many modellers prefer the comma form for clarity — one argument per condition — and because it tolerates header text if ranges include headers. Others prefer the multiplication form because it fails loudly. Choose consciously and test the value column with SUMPRODUCT(--ISTEXT(Revenue)).

OR conditions in the comma form. Combine within one argument: --(((Region="West")+(Region="South"))>0).

Illustration

Region FY Revenue (₹ lakh)
West FY26 420
South FY26 290
West FY26 "310" (text)
West FY25 365
West FY26 175
  • =SUMPRODUCT(--(Region="West"), --(FY="FY26"), Revenue) → 420 + 0 + 175 = ₹595 lakh (the text 310 is dropped).
  • =SUMPRODUCT((Region="West")*(FY="FY26")*Revenue) → 420 + 310 + 175 = ₹905 lakh.
  • =SUMPRODUCT((Region="West"), (FY="FY26"), Revenue) (no coercion) → 0.
  • =SUMIFS(Revenue, Region, "West", FY, "FY26") → ₹595 lakh (SUMIFS also ignores text).

The ₹310 lakh gap between the two SUMPRODUCT forms is a data problem, not a formula choice — fix the type at import.

Connections

Core of the coercion subtopic (double unary, ×1, N()) and the "text in the value range" pitfall of this topic. It underlies every SUMPRODUCT in the weighted-average and multi-condition subtopics, and the same coercion logic drives boolean XLOOKUP (topic 2) and FILTER conditions (topic 4). The "numbers stored as text" pitfalls in topics 1 and 2 are the upstream cause of the silent zero.

Practice Questions

Q2. Control-check design [L2]

Q3. Converting to OR logic [L2]
