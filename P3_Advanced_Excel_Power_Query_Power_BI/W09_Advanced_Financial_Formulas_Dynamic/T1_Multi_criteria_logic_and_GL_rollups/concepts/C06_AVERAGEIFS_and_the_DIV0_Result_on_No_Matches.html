Key concept

AVERAGEIFS and the #DIV/0! Result on No Matches

Concept: =AVERAGEIFS(...) returns #DIV/0! with no matches; test with COUNTIFS first or wrap in IFERROR

Statement

AVERAGEIFS computes

\[ \bar{x}_S = \frac{\sum_{i \in S} x_i}{n_S} \]

where \(S\) is the set of rows meeting all criteria, \(x_i\) the numeric value in average_range for row \(i\), and \(n_S\) the count of numeric values in \(S\). When \(n_S = 0\) the denominator is zero and the function returns #DIV/0!.

Guard 1 — test the count first:

=IF(COUNTIFS(SR[Month],C$3,SR[Channel],$A5)=0,
    "",
    AVERAGEIFS(SR[Taxable],SR[Month],C$3,SR[Channel],$A5))

Guard 2 — blanket error trap:

=IFERROR(AVERAGEIFS(SR[Taxable],SR[Month],C$3,SR[Channel],$A5), "")

Explanation

Why COUNTIFS first is the better guard. The COUNTIFS test catches exactly one condition — "no matching rows" — and lets every other error through. IFERROR suppresses all errors: a #VALUE! from unequal-sized ranges, a #REF! from a deleted column, or a #NAME? from a misspelt Table would all display as a reassuring blank. In a reporting model, a hidden structural error is worse than a visible one. Use IFERROR only where the only plausible error is the empty set and the formula is already proven.

What to return. A blank or "–" is usually right for averages ("no transactions"), because 0 would claim the average ticket was ₹0 and would drag down any further average of averages. If downstream arithmetic needs a number, return NA() deliberately so charts skip the point, or 0 with a clear label.

Contrast with siblings. SUMIFS and COUNTIFS return 0 on no match (correct: the sum of nothing is zero). MAXIFS/MINIFS also return 0 (misleading). AVERAGEIFS is the only one that errors — which is mathematically honest.

Note on the COUNTIFS guard. The guard counts rows meeting the criteria; if the average range has blanks or text in those rows, \(n_S\) may still be zero while COUNTIFS is positive. Guard on the value column too (add a criterion SR[Taxable], "<>") when blanks are possible.

Performance. The COUNTIFS guard doubles the scans per cell. On very large grids, compute SUMIFS and COUNTIFS once in helper blocks and divide: =IF(Cnt=0,"",Sum/Cnt) — cheaper and transparent.

Illustration

Average invoice value by channel and month (₹), from a sales register:

Channel Apr-25 May-25 Jun-25
Website 2,140 2,315 2,290
Marketplace 1,480 1,510 1,495
Corporate gifting 38,600 #DIV/0! 41,200

No corporate-gifting invoices were raised in May, so the unguarded AVERAGEIFS errors. Any total row using AVERAGE(C5:C7) or a chart then breaks. With the COUNTIFS guard the cell is blank and AVERAGE ignores it; with IFERROR the result looks the same today — but if someone later renames the SR Table, IFERROR would turn the entire grid blank instead of showing #REF!.

Connections

Part of the AVERAGEIFS/MAXIFS/MINIFS subtopic. It is a specific case of the week's error-discipline cross-cutting rule (prefer targeted tests and IFNA over blanket IFERROR). The sum-and-count helper approach also avoids the "average of averages" error covered under OR logic, and matches how DAX DIVIDE() handles a zero denominator in Week 11.

Practice Questions

Q1. Guard the KPI [L1]

Write the average ticket size formula for the branch in A6 and the month starting in D3 from Table SR (Branch, InvDate, Taxable, VchType), excluding credit notes and returning "–" where there are no invoices, without using IFERROR.

Q2. IFERROR masking a real error [L2]

A grid of AVERAGEIFS wrapped in IFERROR shows all blanks after a colleague added a column to the source data and renamed the "Taxable Value" header to "Taxable". Explain why the grid is blank, why this is dangerous in a month-end pack, and how you would have detected it with a better guard.

Q3. Helper-block design [L2]

For a 120-customer × 12-month average DSO-style grid on a 3 lakh-row receivables history, propose a layout using separate SUMIFS and COUNTIFS blocks that is faster than guarded AVERAGEIFS. Show the formula for one cell of each block and the final ratio.

💡 Hint: Two grids of the same shape, then one division grid that tests the count.
