Key concept

The Department × Account × Month SUMIFS Grid Formula

Concept: =SUMIFS(GL[Amount], GL[Dept], $B5, GL[Account], $A5, GL[Date], ">="&C$3, GL[Date], "<="&EOMONTH(C$3,0))

Statement

For a grid with account codes in column A, departments in column B and month-start dates in row 3, the value for row \(r\) and month column \(m\) is

\[ V_{r,m} = \sum_{i \in GL} \text{Amount}_i \times \mathbf{1}\left[\text{Dept}_i = B_r\right] \times \mathbf{1}\left[\text{Account}_i = A_r\right] \times \mathbf{1}\left[S_m \le \text{Date}_i \le E_m\right] \]

where \(\mathbf{1}[\cdot]\) is 1 when the condition holds and 0 otherwise, \(S_m\) is the month-start date in the header cell of column \(m\) (row 3), and \(E_m = \text{EOMONTH}(S_m, 0)\) is the last day of that month. The formula implements exactly this sum, with all four conditions combined by AND.

Explanation

Argument order. GL[Amount] is the sum range and comes first. Then four criteria pairs: department, account, and the date column twice — once for the lower bound and once for the upper bound. SUMIFS has no "between" operator, so a period is always two criteria on the same column.

Anchoring. The department and account labels are column-absolute: they stay in columns B and A as the formula is copied right, but each row reads its own labels. The month header is row-absolute: it stays in row 3 as the formula is copied down, but each column reads its own month. The structured references need no anchoring. One formula in C5 fills the entire grid.

Criteria strings. ">="&C$3 concatenates the operator with the date serial in the header (for 01-Apr-2025, the string ">=45748"). EOMONTH(C$3,0) returns the month-end serial, so the upper bound is computed from the header rather than typed. This is why headers must be true dates (EOMONTH/SEQUENCE-generated), never text like "Apr-25".

Conditions for correctness.

  • GL[Date] must contain real dates; text dates are ignored silently.
  • If dates include time stamps, replace the upper bound with "<"&EOMONTH(C$3,0)+1.
  • GL[Account] and the label in column A must be the same data type (both numbers or both text).
  • The Amount column must be one signed column (Dr +, Cr –).

Why not a PivotTable? A PivotTable gives the same numbers, but its layout changes with the data and it must be refreshed. The SUMIFS grid has a fixed layout that downstream formulas (variances, ratios, charts, the 3-statement link) can reference reliably, and it recalculates automatically.

Illustration

GL rows (₹):

Date Dept Account Amount
03-Apr-2025 Sales 640500 2,40,000
18-Apr-2025 Sales 640500 60,000
22-Apr-2025 Admin 640500 1,50,000
30-Apr-2025 Sales 610100 5,10,000
02-May-2025 Sales 640500 2,40,000

With A5 = 640500 (Rent), B5 = "Sales", C3 = 01-Apr-2025, the formula in C5 returns ₹3,00,000 (rows 1 and 2). Copied to D5 (D3 = 01-May-2025), it returns ₹2,40,000. Copied to C6 (A6 = 610100, B6 = "Sales"), it returns ₹5,10,000. The Admin row appears only in an Admin row of the grid. The grand total of the April column for all rows must equal the April expense total in the GL — that is the completeness check.

Connections

Practice Questions

Q1. Cost-centre extension [L1]

Extend the formula so the grid is split by cost centre as well, with cost centres in column C and months starting in D3. Write the formula for D5.

Q2. Time-stamped SAP data [L2]

An SAP extract has posting timestamps such as 30-04-2025 17:42. Using the original formula, a ₹12,40,000 provision posted at 18:05 on 30-Apr-2025 is missing from April. Explain why and rewrite the date criteria so the formula is robust.

💡 Hint: Compare the serial value of 30-Apr-2025 18:05 with EOMONTH's result.

Q3. Quarter grid [L2]

Rebuild the formula for a quarterly grid in which row 3 holds quarter-start dates (01-Apr-2025, 01-Jul-2025, 01-Oct-2025, 01-Jan-2026). Which single argument changes, and what is the new expression?
