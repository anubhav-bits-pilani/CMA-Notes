Key concept

IFS with a TRUE Catch-All for Account Classification

Concept: =IFS(code<20000,"Assets", code<30000,"Liabilities", TRUE,"Check"): TRUE is the catch-all; IFS returns #N/A if nothing matches

Statement

IFS(test1, value1, test2, value2, …, testn, valuen) returns the value paired with the first test that evaluates to TRUE, scanning left to right:

\[ \text{IFS} = v_k \quad \text{where } k = \min\{\, j : t_j = \text{TRUE} \,\} \]

Here \(t_j\) is the j-th logical test and \(v_j\) its paired value. If no \(t_j\) is TRUE, the set is empty and IFS returns #N/A. Placing the literal TRUE as the final test guarantees the set is never empty, so its paired value ("Check") acts as the else branch.

Explanation

First-TRUE rule. Because evaluation stops at the first TRUE test, ordered thresholds need only upper bounds. In the concept formula, a code of 15000 satisfies code<20000 and returns "Assets"; a code of 25000 fails the first test, satisfies the second and returns "Liabilities". The test code<30000 does not need code>=20000 because any code below 20000 has already been caught.

No else argument. Unlike IF (which has value_if_false) and SWITCH (which has an optional default), IFS has only pairs. Microsoft's documentation explicitly recommends TRUE as the last test for a default. Without it, a code of 45000 in the formula above would return #N/A.

Why "Check" and not a guess. The catch-all should not assign a nature (e.g. "Expenses") — that would hide new or mistyped codes inside a real category. A distinct value such as "Check" or "UNMAPPED" lets a COUNTIF of "Check" become a control: =COUNTIF(TB[Nature],"Check") must be zero before the TB is rolled up.

Errors that propagate. If any test evaluated before the first TRUE produces an error (e.g. code is #N/A from an upstream lookup), IFS returns that error. Text codes do not error — "25000"<20000 is simply FALSE because text sorts above numbers — so text codes fall through to the catch-all, which is the desired visible behaviour.

Limits and versions. Up to 127 test/value pairs. IFS exists in Excel 2019, 2021, 2024 and Microsoft 365; in Excel 2016 it returns #NAME?.

Reading the concept formula. As written it is a teaching skeleton: everything from 30000 upwards — Income and Expenses — lands in "Check". A complete version for a five-digit CoA would be:

=IFS(code<10000,"Check",
     code<20000,"Assets",
     code<30000,"Liabilities",
     code<40000,"Income",
     code<50000,"Expenses",
     TRUE,"Check")

In a 500-ledger TB, a pivot or COUNTIF on the Nature column showing three "Check" rows and one #N/A tells the reviewer exactly which ledgers need attention before any total is reported.

Practice Questions

Q1. Complete the classification [L1]

A six-digit CoA uses 1xxxxx Assets, 2xxxxx Liabilities, 3xxxxx Equity, 4xxxxx Revenue, 5xxxxx and 6xxxxx Expenses. Write an IFS formula on cell A2 that returns "Check" for any code outside 100000–699999, and explain why no test needs a lower bound except the first.

Q2. Find the faults [L2]

A colleague's formula is =IFS(A2>=10000,"Assets", A2>=20000,"Liabilities", A2>=30000,"Income"). Identify every fault (ordering, missing default, behaviour for codes above 30000 and below 10000) and write a corrected version that still uses >= tests.

💡 Hint: With >= tests the order of thresholds must be reversed for the first-TRUE rule to work.

Q3. Control design [L2]

After applying your IFS classification to a 640-ledger TB, explain how you would build a check cell that blocks the P&L from being reported if any ledger is "Check" or an error, and why you would not wrap the IFS itself in IFERROR.
