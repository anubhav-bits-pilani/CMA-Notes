Key concept

SUM of SUMIFS with an Array Constant for OR Logic

Concept: =SUM(SUMIFS(GL[Amount], GL[Dept], {"Sales","Marketing"})) sums two criteria values (OR logic)

Statement

When a criterion is an array of \(k\) values \(\{c_1, c_2, \dots, c_k\}\), SUMIFS returns an array of \(k\) results, one per value. SUM then adds them:

\[ \text{Result} = \sum_{j=1}^{k} \; \sum_{i \in GL} \text{Amount}_i \times \mathbf{1}\left[\text{Dept}_i = c_j\right] \]

where \(\mathbf{1}[\cdot]\) is the indicator function. Because a row can equal at most one \(c_j\) when the values are distinct, the double sum equals the sum over rows satisfying "\(\text{Dept}_i = c_1\) OR \(\text{Dept}_i = c_2\) OR …".

Explanation

Why it works. SUMIFS itself is AND-only across different criteria pairs. Supplying an array in one criteria argument makes Excel lift the function over the array (it evaluates once per element). The inner result is {Sales total, Marketing total}; SUM collapses it to a scalar. In Microsoft 365, omitting SUM spills the two component totals into two cells — a quick way to audit the pieces.

Version behaviour. With an array constant, the formula works in all versions without Ctrl+Shift+Enter. If the constant is replaced by a range (e.g. a named list SelDepts), legacy Excel (2019 and earlier) needs Ctrl+Shift+Enter or SUMPRODUCT in place of SUM; Microsoft 365 handles it natively.

Conditions.

  • Values must be mutually exclusive. Equality tests on one column always are, unless the list contains a duplicate — {"Sales","Sales"} doubles Sales.
  • Wildcard or operator criteria may overlap ({"*Freight*","*Inward*"} double counts "Freight Inward").
  • With a second OR list on another column, orient one array horizontally (commas) and the other vertically (semicolons) to get all combinations; two horizontal arrays pair element-wise.
  • Array constants hold only literal values — no cell references.

Good practice. Hard-coded constants embed policy inside formulas. In a model, move the list to a Table column on the assumptions sheet and reference it, so additions are visible and auditable.

Illustration

FY26 GL for one expense group (₹ lakh):

Dept Q1 Q2
Sales 42.5 44.0
Marketing 18.0 26.5
Admin 12.0 12.5

With criteria for Q1 dates added, SUMIFS(…, GL[Dept], {"Sales","Marketing"}, …) returns {42.5, 18.0} and SUM gives ₹60.5 lakh — the S&D employee cost for Q1. Changing the constant to {"Sales";"Marketing"} (vertical) gives the same result here because there is only one array. Adding a second criterion GL[Branch], {"MUM","PUN"} while keeping the department array horizontal would pair Sales–MUM and Marketing–PUN only; making the department array vertical produces all four department–branch combinations.

Connections

Implements the OR-logic subtopic and relies on criteria syntax. It is the compact alternative to adding separate SUMIFS calls, and the scalar version of the boolean OR used inside SUMPRODUCT and FILTER (+ between conditions) in the SUMPRODUCT and dynamic-arrays topics. In DAX (Week 11), the equivalent is CALCULATE(SUM(GL[Amount]), GL[Dept] IN {"Sales","Marketing"}).

Practice Questions

Q1. Three-value OR with a date window [L1]

Write a formula for total "Travel" group expense in departments Sales, Marketing and Projects for the month whose start date is in C3, using an array constant.

Q2. Replace the constant with a list [L2]

Rewrite your Q1 answer so the department list comes from a Table column Tbl_Depts[Dept]. State what changes, if anything, for a user on Excel 2019, and add a check that the list has no duplicates.

💡 Hint: COUNTIF of the list against itself, compared with 1, reveals repeats.

Q3. Cross-product audit [L2]

A formula reads =SUM(SUMIFS(GL[Amount], GL[Dept], {"Sales","Marketing"}, GL[Branch], {"MUM","PUN"})) and is used to report "S&D cost for West region". Department–branch totals (₹ lakh) are: Sales–MUM 30, Sales–PUN 12, Marketing–MUM 9, Marketing–PUN 7. What does the formula return, what should it return, and how do you fix it?
