Excel Tables and Structured References for Self-Expanding Rollups

Scope: Excel Tables and structured references so rollups auto-expand when new GL rows are pasted

Why it matters

The single most common reason a monthly MIS is wrong is that the formula ranges stopped at last month's last row. SUMIFS(G2:G48210, …) silently ignores rows 48,211 onwards when the next month's GL is pasted. Converting the raw dump into an Excel Table (Ctrl+T) makes every formula refer to the Table's columns rather than fixed addresses, so ranges grow and shrink with the data. It is also the foundation of a one-directional model: a GL_Raw Table on the input tab, a mapping Table, and calculation formulas that read like sentences (GL[Amount], Map[FSLine]). Power Query loads to Tables, PivotTables point at Tables, and Power BI imports Tables by name — getting this right now pays off across Weeks 10–12.

Core notes

Creating and naming a Table

  1. Select any cell in the data block and press Ctrl+T (or Ctrl+L); confirm "My table has headers".
  2. Rename it immediately in Table Design → Table Name (e.g. GL, Map, TB). Default names like Table3 make formulas unreadable. Names cannot contain spaces and must be unique in the workbook.
  3. Ensure each header is unique and non-blank; Excel auto-renames duplicates to Amount2.
  4. Remove the banded style if you prefer, but keep the Table — formatting is optional, structure is the point.

Structured reference syntax

Reference Meaning
GL[Amount] data rows of the Amount column
GL[[#Headers],[Amount]] the header cell
GL[[#Totals],[Amount]] the total-row cell
GL[#All] whole Table including headers and totals
GL all data rows, all columns
[@Amount] Amount in the same row (inside the Table)
GL[[Date]:[Amount]] contiguous columns from Date to Amount
[@[Cost Centre]] column name containing a space

The @ form ("this row") is what calculated columns use. Outside the Table, a reference such as GL[@Amount] uses implicit intersection with the formula's row — rarely what you want in a report.

Auto-expansion mechanics

  • Paste or type directly below the last row and the Table extends (AutoCorrect option "Include new rows and columns in table"). A blank row between the Table and the pasted block breaks this — the pasted data stays outside.
  • Paste over the Table after deleting old rows: select the data body, delete rows (not just contents), then paste starting at the first data cell. Alternatively, resize via Table Design → Resize Table.
  • Calculated columns fill down automatically to new rows. A formula typed once in a column applies to all rows; an inconsistent manual override shows a green-triangle warning.
  • Power Query output loads to a Table that resizes itself on refresh — the cleanest pattern for monthly dumps.

Every formula pointing at GL[Amount] now covers the new rows without editing. That is the "update when next month's GL is pasted" requirement in this week's exercise.

Structured references in rollups

=SUMIFS(GL[Amount],
        GL[Date], ">="&C$3,
        GL[Date], "<="&EOMONTH(C$3,0),
        GL[FSLine], $A5)

Copying behaviour to know:

  • Drag-fill across columns shifts structured references column by column (GL[Amount] becomes GL[Account] if dragged right!) because column references are relative when filled sideways. Copy-paste (Ctrl+C / Ctrl+V) does not shift them. To lock a column reference for fill-right, use the range form GL[[Amount]:[Amount]].
  • Down-filling does not shift them.
  • References to other Tables in calculated columns are fine: =XLOOKUP([@Ledger], Map[Ledger], Map[FSLine], "UNMAPPED").

Total row

Table Design → Total Row (Ctrl+Shift+T) adds a row using SUBTOTAL(109, [Amount]), which respects filters. Useful for a quick tie-out of the pasted dump to the source system control total, but keep check cells outside the Table so they survive data replacement.

Named ranges vs Tables

Need Better tool
Growing transactional data Table
Single input cell (tax rate, threshold) Named cell via Name Manager (Ctrl+F3)
A list feeding a dropdown Table column (wrapped via a name, or a spill reference)
Fixed matrix in a model (driver grid) Named range

A named range can be made dynamic with OFFSET or INDEX, but OFFSET is volatile; a Table is the non-volatile way to get a growing range.

Limitations

  • Dynamic array formulas (FILTER, UNIQUE, SORT) cannot spill inside a Table — they return #SPILL!. Place spills on a normal sheet area.
  • Tables cannot contain merged cells, and sheets with Tables cannot use the legacy "Shared Workbook" feature.
  • Structured references to another workbook only update while that workbook is open.
  • Very wide Tables with many calculated columns slow recalculation; push heavy transformations to Power Query.

Worked illustration

April 2025 GL has 18,240 rows in Table GL. The P&L grid uses SUMIFS(GL[Amount], …). In May, the accountant pastes 19,870 new rows directly under row 18,241. The Table expands to 38,110 rows; the May column (header 01-May-2025) fills from the formula already present; April is unchanged; the check cell =SUM(GL[Amount]) (should be 0 for a balanced GL) still covers every row. With a fixed range G2:G18241, the May column would show zero and the check cell would still say 0 — a "clean" but wrong result.

Edge cases & judgement calls

  • Pasting with a blank first row or different column order breaks the structure. Standardise the export layout or load through Power Query and let it enforce columns.
  • Header renaming in the source export (e.g. Tally "Debit Amount" → "Debit") changes the Table column name, and every formula referencing the old name shows #REF!. Lock headers through Power Query rename steps.
  • Filters left on the Table do not affect SUMIFS (it reads all rows) but do affect SUBTOTAL-based totals — two different "totals" can confuse reviewers.
  • Table vs spill for outputs: inputs belong in Tables; outputs generated by dynamic arrays belong outside Tables.
  • Drag-fill shift of structured references is the classic hidden error when building month grids by dragging right.

Key takeaways

  • Ctrl+T, then rename the Table; formulas on Table[Column] grow with the data.
  • Paste directly below the last row (no blank row), or load via Power Query, for automatic expansion.
  • [@Column] means this row; it is the basis of calculated columns such as mapping lookups and duplicate flags.
  • Dragging structured references sideways shifts the column; copy-paste does not, and T[[Col]:[Col]] locks it.
  • Dynamic arrays cannot spill inside Tables; keep spills on normal ranges.
  • Use named cells for single inputs and Tables for growing lists; avoid volatile OFFSET ranges.

Practice Questions

Q1. Convert and rewrite [L1]

A GL dump occupies A1:H52,300 on sheet GL_Raw with headers Date, VchType, VchNo, Ledger, Dept, Narration, Debit, Credit. Describe the steps to convert it to a Table named GL, add a signed Amount calculated column, and rewrite =SUMIFS(GL_Raw!H2:H52300, GL_Raw!D2:D52300, A5) using structured references.

Q2. Drag-fill error [L2]

An analyst types =SUMIFS(GL[Amount], GL[Month], C$4, GL[Ledger], $A5) in C5 and drags it right to N5. December onwards shows #VALUE! or wrong totals. Explain what happened to the structured references and give two ways to prevent it.

💡 Hint: Compare drag-fill and copy-paste behaviour for column references.

Q3. The month that would not appear [L2]

After pasting the June 2025 Day Book under the existing data, the June column of the P&L shows zero. The Table name is GL, all formulas use structured references, and the June rows are visible on the sheet. List three possible causes and how you would check each one.

Q4. Design the input layer [L3]

For a monthly close pack, design the input sheet structure using Tables and named cells: the GL dump, the TB, the ledger mapping, the department master, and single inputs (reporting month, rounding unit, materiality threshold). Name each object, specify its key column(s), and explain which objects should be Tables versus named cells and why.

Q5. Interview: Table vs OFFSET named range [L1]

"Why would you use an Excel Table instead of a dynamic named range like =OFFSET(A1,0,0,COUNTA(A:A),1)?" Answer as you would in an FP&A interview, covering volatility, robustness and readability.
