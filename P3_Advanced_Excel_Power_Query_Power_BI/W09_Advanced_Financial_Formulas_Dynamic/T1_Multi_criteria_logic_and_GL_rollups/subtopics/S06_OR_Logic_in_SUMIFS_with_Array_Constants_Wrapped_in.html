OR Logic in SUMIFS with Array Constants Wrapped in SUM

Scope: OR-logic across criteria values using array constants wrapped in SUM

Why it matters

SUMIFS combines all criteria with AND. Real reporting questions are often OR questions: "Sales or Marketing department costs", "freight inward or freight outward", "branches in Mumbai, Pune or Nashik", "voucher types Payment or Contra". Writing one SUMIFS per value and adding them works but bloats formulas and breaks when the list changes. Passing several criteria values at once as an array and wrapping the result in SUM gives compact, auditable OR logic — and with a cell range instead of a hard-coded constant, a list the business can maintain.

Core notes

How it works

=SUM(SUMIFS(GL[Amount], GL[Dept], {"Sales","Marketing"}))
  1. The criterion {"Sales","Marketing"} is an array constant with two elements.
  2. SUMIFS is evaluated once per element and returns an array of two results: {Sales total, Marketing total}.
  3. SUM adds the array into one number.

Because each row has only one department, the two results never overlap, so the sum is a true OR. In Microsoft 365 the formula evaluates natively; in Excel 2019 and earlier it also works without Ctrl+Shift+Enter, because array constants inside SUMIFS are handled natively (entering a range of criteria, however, needs CSE in legacy Excel or SUMPRODUCT instead of SUM).

Without the SUM wrapper, in Microsoft 365 the formula spills two results into adjacent cells — useful for checking the components, but not what a single P&L cell should do. In legacy Excel without SUM, only the first element would display.

Array constant syntax

Element Syntax Example
Text values double quotes {"Sales","Marketing"}
Numbers no quotes {194,195}
Comma separates columns (horizontal array) {"A","B","C"}
Semicolon separates rows (vertical array) {"A";"B";"C"}
Criteria with operators operator inside each string {">=500000","<100000"} — careful, see overlap below

Array constants cannot contain cell references, formulas or other arrays ({A1,B1} is invalid). Use a range instead, e.g. =SUM(SUMIFS(GL[Amount], GL[Dept], DeptList)) where DeptList is a named range or Table column — this becomes a maintainable OR list.

Two OR lists: the cross-product trick

If two criteria each have an OR list, orientation matters:

=SUM(SUMIFS(GL[Amount], GL[Dept], {"Sales","Marketing"}, GL[Branch], {"MUM";"PUN"}))

A horizontal 1 × 2 array and a vertical 2 × 1 array broadcast into a 2 × 2 grid of combinations: (Sales, MUM), (Marketing, MUM), (Sales, PUN), (Marketing, PUN). SUM then adds all four. If both arrays were horizontal ({"Sales","Marketing"} and {"MUM","PUN"}), Excel pairs them element by element — (Sales, MUM) and (Marketing, PUN) only — which is a silent error. Rule: one list horizontal (commas), the other vertical (semicolons). Three OR lists cannot be cross-multiplied this way; use SUMPRODUCT with boolean arrays or FILTER.

Overlapping OR conditions double count

The trick is safe only when the OR values are mutually exclusive. On the same column with equality tests they always are. With operators or wildcards they may not be:

=SUM(SUMIFS(GL[Amount], GL[Ledger], {"*Freight*","*Inward*"}))

A ledger called "Freight Inward" satisfies both patterns and is summed twice. Similarly {">=100000",">=500000"} double counts everything above ₹5 lakh. For overlapping conditions use a boolean OR inside SUMPRODUCT:

=SUMPRODUCT(GL[Amount], --((ISNUMBER(SEARCH("Freight",GL[Ledger])) + ISNUMBER(SEARCH("Inward",GL[Ledger])))>0))

The >0 test converts the count of satisfied conditions into a single 1/0 per row.

The same idea for COUNTIFS and other functions

  • =SUM(COUNTIFS(GL[VchType], {"Payment","Contra"})) — count of bank-related vouchers.
  • =SUM(SUMIFS(TB[Closing], TB[Group], {"Sundry Debtors","Loans & Advances (Asset)"})) — two Tally groups.
  • AVERAGEIFS cannot be combined this way directly — the average of the per-value averages is not the OR average. Compute SUM(SUMIFS) ÷ SUM(COUNTIFS).
  • MAXIFS with an array constant returns one max per value; wrap in MAX: =MAX(MAXIFS(AP[Amount], AP[Vendor], {"V001","V002"})).

Worked illustration

Dept Amount (₹)
Sales 12,40,000
Marketing 6,15,000
Admin 4,80,000
Sales 3,25,000
Marketing 1,90,000

SUMIFS(…, {"Sales","Marketing"}) returns {15,65,000 , 8,05,000}; SUM gives ₹23,70,000. With a range SelDepts holding Sales and Marketing in two cells the result is identical, and adding "Admin" to the range (if it is a Table column) extends the OR list without touching the formula.

Making the list a model input

For MIS, put the OR list on an assumptions sheet as a one-column Table (Tbl_SDDepts[Dept]) labelled, e.g., "Departments included in S&D cost". The formula =SUM(SUMIFS(GL[Amount], GL[Dept], Tbl_SDDepts[Dept], GL[Date], ">="&C3, GL[Date], "<="&EOMONTH(C3,0))) then reads like the policy it implements, and reviewers can see exactly what is included.

Edge cases & judgement calls

  • Duplicates in the criteria list double count: {"Sales","Sales"} sums Sales twice. Validate list uniqueness with COUNTIF.
  • Blank cells in a criteria range add a criterion matching blanks; if the GL has rows with blank Dept, they get included. Trim the list or use a Table without empty rows.
  • Legacy Excel and ranges: SUM(SUMIFS(…, range)) needs Ctrl+Shift+Enter in Excel 2019 and earlier; SUMPRODUCT(SUMIFS(…, range)) avoids that.
  • Readability: array constants hide policy in formulas. Prefer a named list for anything that may change.
  • Performance: each element triggers a full SUMIFS pass; a 30-value OR list over 2 lakh rows is 30 scans per cell.

Key takeaways

  • SUMIFS is AND-only; feeding an array of criteria values and wrapping in SUM produces OR logic.
  • Array constants use commas for columns and semicolons for rows, and cannot contain references.
  • For two OR lists, make one horizontal and one vertical to get every combination.
  • OR via SUM(SUMIFS) is only safe for mutually exclusive values; overlapping patterns double count.
  • Replace hard-coded constants with a named range or Table column so the business can maintain the list.

Practice Questions

Q1. Two-department OR total [L1]

Write a formula that returns the total FY26 expense for departments "Sales", "Marketing" and "Customer Service" from Table GL (Date, Dept, AccGroup, Amount), restricted to AccGroup "Employee cost" and FY dates in FYStart and FYEnd.

Q2. Cross-product of branches and voucher types [L2]

Write a single formula that counts vouchers of type "Payment" or "Receipt" at branches "MUM", "PUN" or "NSK" from Table V (Branch, VchType). Explain what result you would get if both array constants were written with commas, using a concrete pairing to show the error.

Q3. Freight double count [L2]

Ledgers include "Freight Inward", "Freight Outward", "Inward Handling" and "Courier". The analyst wrote =SUM(SUMIFS(GL[Amount], GL[Ledger], {"*Freight*","*Inward*"})) intending "freight or inward costs". Identify which ledger is double counted and write a correct alternative.

💡 Hint: Count, per row, how many patterns are satisfied and test whether that count is greater than zero.

Q4. Maintainable OR list [L2]

The CFO wants "Marketing spend" in the MIS to include a changing list of ledgers (currently 11, from digital ads to trade schemes). Design the assumptions-sheet structure and formula so adding a ledger requires no formula edit, and add a check that flags duplicate or blank entries in the list.

Q5. Average across an OR list [L1]

Explain why =AVERAGE(AVERAGEIFS(SR[Taxable], SR[Channel], {"Website","App"})) does not give the average invoice value across Website and App sales, and write the correct formula.
