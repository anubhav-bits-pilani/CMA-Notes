Mixed References and F4 Cycling for Copy-Across P&L Grids

Scope: Mixed referencing ($A5, C$4) and F4 cycling for copy-across P&L grids

Why it matters

A monthly P&L or department grid typically has 40–80 rows and 12–24 columns: roughly a thousand cells. A professional grid has one formula written once in the top-left cell and copied across and down unchanged; every cell is then structurally identical, so reviewing one cell reviews them all. That only works when each reference is anchored correctly — row labels locked to their column, period headers locked to their row, inputs locked completely. Wrong anchoring is the root cause of "row 37 picks up the wrong month" errors that survive review because the numbers look plausible. Interviewers for FP&A roles routinely test this with a blank grid and a stopwatch.

Core notes

The four reference types

A dollar sign before the column letter freezes the column; a dollar sign before the row number freezes the row.

Type Example When copied right When copied down Typical use in a grid
Relative C4 column shifts row shifts values in the same grid position
Absolute $C$4 fixed fixed single input: tax rate, threshold, FX rate
Row-absolute (mixed) C$4 column shifts row fixed month/period headers in a header row
Column-absolute (mixed) $A5 column fixed row shifts account / FS line labels in a label column

The memory aid: the $ sits in front of whatever must not move.

F4 cycling

With the cursor on or inside a reference in the formula bar (or while building a formula by clicking cells), press F4 to cycle:

Press Result
Typed A1
F4 once $A$1 (absolute)
F4 twice A$1 (row locked)
F4 three times $A1 (column locked)
F4 four times A1 (back to relative)

On laptops where F4 is a media key, use Fn+F4, or switch the function-key lock. On Mac Excel the shortcut is Cmd+T (or Fn+F4 depending on settings). Selecting a whole formula in the bar and pressing F4 cycles all references in the selection together — handy but risky when the references need different anchoring. Outside edit mode, F4 means "repeat last action" — a different feature.

Anatomy of a copy-across grid

Layout: FS lines in A5:A40, departments in B5:B40, month-start dates in C3:N3.

=SUMIFS(GL[Amount],
        GL[FSLine], $A5,
        GL[Dept], $B5,
        GL[Date], ">="&C$3,
        GL[Date], "<="&EOMONTH(C$3,0))

Reading each anchor:

  • $A5 (and likewise the department reference in column B) — the labels are always in columns A and B (column locked), but each row reads its own label (row free).
  • C$3 — the header is always in row 3 (row locked), but each column reads its own month (column free).
  • GL[Amount] etc. — structured references need no $; they are copied by Ctrl+C/Ctrl+V without shifting (but see the drag-fill caveat in the Tables note).

Write it once in C5, then Ctrl+C, select C5:N40, Ctrl+V (or Ctrl+R to fill right and Ctrl+D to fill down). The same pattern applies to a budget grid with a scenario input: an input such as the growth rate is fully absolute or, better, a named cell (GrowthRate), which never needs $.

Variance and percentage columns

For a budget-vs-actual block where actuals are in C:N and budgets in P:AA, a variance in AC5 copied across: =C5-P5 (relative, both shift together). A percentage of revenue line where revenue sits in row 5: =C12/C$5 — the denominator row is locked so every expense row divides by revenue of its own month. A growth % across months: =D5/C5-1, fully relative.

Worked illustration

Grid snippet (₹ lakh):

A C (Apr-25) D (May-25)
5 Revenue 420.0 455.0
12 Employee cost 63.0 66.5
13 Rent 21.0 21.0

The %-of-revenue block mirrors the expense rows from row 30 onwards, so C30 holds =C12/C$5 (employee cost as % of April revenue = 63.0 ÷ 420.0 = 15.0%). Copying C30 to D31 gives =D13/D$5 = 21.0 ÷ 455.0 = 4.6% (rent as % of May revenue). If the author had written =C12/C5, D31 would become =D13/D6 — dividing by whatever is in row 6, often a blank, producing #DIV/0!, or worse, a plausible wrong number.

Speed technique

  1. Build the top-left formula by clicking cells; press F4 immediately after each click to set the anchor.
  2. Test by copying one cell right and one cell down and inspecting with Ctrl+[ (go to precedents) or F2.
  3. Fill the block; switch on Ctrl+` (show formulas) and scan for any cell that looks different.
  4. Use Go To Special → Row differences (Ctrl+) or Column differences (Ctrl+Shift+|) on the block to find any inconsistent formula.

R1C1 view as an audit tool

File → Options → Formulas → R1C1 reference style rewrites references as offsets: C$3 typed in column C becomes R3C (row 3, same column) and $A5 typed in row 5 becomes RC1 (same row, column 1). In a correctly built grid, every cell's formula text is therefore identical in R1C1 view, and any cell whose text differs is an inconsistency. Inquire's Workbook Analysis and Spreadsheet Compare use the same principle to flag inconsistent formulas.

Edge cases & judgement calls

  • Inserted columns. Inserting a column inside the grid adjusts all references automatically, but an inserted column between labels and data can make $A5 point at the wrong label column only if labels were moved — keep labels in fixed columns.
  • Fully absolute inputs vs names. Named inputs (TaxRate) are clearer and immune to anchoring errors; use them for every single-cell assumption.
  • Copying formulas to another sheet keeps anchors but changes sheet context; references to the source sheet remain.
  • Mixed anchors in conditional formatting: the same logic applies (=$E5<0 colours a whole row based on column E), and errors there are invisible until data changes.
  • Over-anchoring (making everything absolute "to be safe") forces manual edits in every cell, defeating the one-formula principle.

Key takeaways

  • $ freezes what follows it: column-absolute for label columns, row-absolute for header rows.
  • F4 cycles absolute → row-locked → column-locked → relative; use Fn+F4 on laptops.
  • One formula, copied across and down, is the standard for P&L and MIS grids.
  • Test a new grid formula by copying one cell right and one down before filling.
  • Use named cells for single inputs; they never need $.
  • Row/column-difference selection and R1C1 view expose inconsistent formulas fast.

Practice Questions

Q1. Anchor the grid [L1]

FS lines are in A6:A45, months (month-start dates) in D4:O4, and a Table GL has FSLine, Date and Amount. Write the formula for D6 that can be copied to D6:O45 without editing, and state for each reference what would go wrong if its $ were omitted.

Q2. Percentage-of-revenue block [L1]

Revenue is in row 8 (columns D:O) and expense lines in rows 10–30. Write the formula for D40 (the first row of a % of revenue block mirroring row 10) that copies correctly to D40:O60.

Q3. Find the inconsistent cell [L2]

A 36 × 12 department grid was built by a colleague; one cell in row 22 was overwritten with a hard-coded ₹4,75,000 and another in column K had its date reference edited to point at J3. Describe at least three Excel techniques to find both cells in under two minutes.

💡 Hint: Think about show-formulas view, Go To Special and the Inquire add-in.

Q4. Budget grid with growth input [L2]

FY26 actual revenue by product is in C6:C20. Build an FY27 monthly budget grid in E6:P20 where each month equals the annual actual × (1 + growth rate in a named cell Gr) × the month's seasonality weight in E3:P3. Write the E6 formula and explain the anchoring of each reference.

Q5. Timed interview drill [L3]

You are given a blank sheet with 25 expense ledgers in column A, 4 departments in row 2 (C2:F2) and a GL Table with Ledger, Dept and Amount. In five minutes you must build the department × ledger matrix, a row total, a column total and a check cell that compares the grand total with the GL total. Describe your exact keystroke sequence and formulas, and explain how you would prove the grid is consistent.
