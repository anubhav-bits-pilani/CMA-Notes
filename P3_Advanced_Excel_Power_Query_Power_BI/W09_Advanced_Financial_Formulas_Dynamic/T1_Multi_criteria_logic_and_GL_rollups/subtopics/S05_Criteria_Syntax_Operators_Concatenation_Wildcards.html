Subtopic note

Criteria Syntax: Operators, Concatenation, Wildcards and Date Ranges

Scope: Criteria syntax: operators inside strings, concatenation with cells, wildcards * ? ~, date-range criteria

Why it matters

The *IFS family (SUMIFS, COUNTIFS, AVERAGEIFS, MAXIFS, MINIFS) and SUMIF/COUNTIF do not take logical expressions — they take criteria strings that Excel parses like an AutoFilter condition. Most wrong rollups in MIS packs are not wrong ranges but wrong criteria: an operator outside the quotes, a date typed as text, a wildcard that only works on text, or an asterisk in a vendor name that is read as a wildcard. Mastering the grammar is what separates a formula that "works on the sample" from one that survives a year of GL dumps.

Core notes

The criterion is a string

A criterion has two parts: an optional comparison operator and a value. Both must form a single text string.

Intent Correct criterion Common wrong version
Equal to "Sales" "Sales" or "=Sales" —
Not equal to "Admin" "<>Admin" <>"Admin" (syntax error)
Greater than or equal to 1,00,000 ">=100000" >=100000
Greater than a cell value ">"&H1 ">H1" (compares with the text "H1")
Not blank "<>" "<>"""
Blank "" or "=" —
Equal to a number in a cell H1 (no operator needed) "="&H1 also works

The six operators are =, <>, >, >=, <, <=. If no operator is present, = is assumed.

Concatenation with cells

To make a criterion dynamic, join the operator string to a cell with &:

=SUMIFS(GL[Amount], GL[Amount], ">="&Threshold, GL[Dept], "<>"&ExclDept)

Excel evaluates ">="&Threshold first, producing for example the string ">=100000", and then parses it. For a date in a cell, ">="&C3 produces ">=45748" (the serial number of 01-Apr-2025), which is exactly what the date column holds — so concatenating a date cell always works. Concatenating a formatted text of a date (">="&TEXT(C3,"dd-mm-yyyy")) depends on the system's regional date settings and breaks when the file moves between an Indian (dd-mm) and US (mm-dd) locale. Never use TEXT inside a date criterion.

You can also concatenate formula results: "<="&EOMONTH(C3,0), ">"&TODAY()-90 for postings older than 90 days, "<"&DATE(2026,4,1).

Wildcards

Wildcards work only in criteria compared against text:

Wildcard Meaning Example Matches
* any number of characters (including none) "*Bank*" "HDFC Bank CC", "Bank charges"
? exactly one character "GST??" "GST18", "GST28" but not "GST5"
~ escape the next wildcard "Rent~*" the literal "Rent*"

Typical uses:

  • "*TDS*" — every TDS-related ledger (TDS payable 194C, TDS receivable).
  • "4*" — account codes starting with 4, only if the codes are text. On numeric codes, "4*" matches nothing, because a wildcard criterion forces a text comparison. Numeric codes need range criteria: ">=400000" and "<500000".
  • "<>*Provision*" — everything except ledgers containing "Provision" (operators and wildcards combine).
  • Cell-driven: "*"&H1&"*" for a "contains" search box.

The escape character ~ matters when data contains * or ? literally — Tally ledger names such as Sundry Creditors* or product codes like SKU?12. To escape a cell value dynamically: SUBSTITUTE(SUBSTITUTE(SUBSTITUTE(H1,"~","~~"),"*","~*"),"?","~?").

Date-range criteria

A date column holds serial numbers (01-Apr-2025 = 45748). A period is two criteria on the same column:

=SUMIFS(GL[Amount],
        GL[Date], ">="&C3,
        GL[Date], "<="&EOMONTH(C3,0))

Patterns:

Period Start criterion End criterion
Month of C3 ">="&EOMONTH(C3,-1)+1 "<="&EOMONTH(C3,0)
FY26 ">="&DATE(2025,4,1) "<="&DATE(2026,3,31)
Last 90 days ">"&RptDate-90 "<="&RptDate
Before cut-off (ageing > 180 days) — "<"&RptDate-180
Date-time stamps to month end ">="&C3 "<"&EOMONTH(C3,0)+1

Two rules: always reference a true date cell or a date-returning formula (DATE, EOMONTH, EDATE), and never type a date string such as ">=01/04/2025" — Excel interprets it using the current locale, so it may be read as 4 January.

Worked illustration

Criteria cell H1 holds 5,00,000, H2 holds "Admin", C3 holds 01-Jul-2025:

  • ">"&H1 → ">500000": postings above ₹5 lakh.
  • "<>"&H2 → "<>Admin": all departments except Admin.
  • ">="&C3 → ">=45839": on or after 01-Jul-2025.
  • "<="&EOMONTH(C3,0) → "<=45869": on or before 31-Jul-2025.
  • "*"&"Freight"&"*" → "*Freight*": inward and outward freight ledgers.

Combined, these return July 2025 postings above ₹5 lakh, outside Admin, on freight ledgers.

Case and type behaviour

  • Text criteria are case-insensitive: "sales", "SALES" and "Sales" are equal. For case-sensitive tests use SUMPRODUCT with EXACT.
  • A criterion that looks like a number ("100") matches both the number 100 and the text "100" in the range.
  • Leading/trailing spaces in data are significant: "Sales " does not equal "Sales". Clean with TRIM in Power Query or a helper column.

Edge cases & judgement calls

  • Criterion "="&H1 when H1 is blank becomes "=", which matches blanks — a silent change in meaning when the dropdown is cleared.
  • Fractional comparisons. ">=0.18" on a GST rate column stored as 18 (whole number) returns everything; check the unit of the data.
  • Wildcards on numeric codes are the most common source of zero results in TB rollups; convert codes to text consistently or use ranges.
  • Regional settings. Decimal separators and date order in typed criteria differ between Indian, European and US machines; cell references are locale-proof.
  • Long numeric text (more than 15 digits) is compared as a number and truncated in COUNTIFS/SUMIFS criteria.

Key takeaways

  • Criteria are strings: the operator goes inside the quotes and a cell is joined with &.
  • Concatenate real date cells or DATE/EOMONTH results; never TEXT-formatted or typed dates.
  • * and ? work only on text; ~ escapes literal wildcard characters in data.
  • Numeric account codes need range criteria; "4*" silently matches nothing on numbers.
  • A period is two criteria on the same date column; use "<"&end+1 when timestamps are present.
  • Criteria are case-insensitive and treat numeric-looking text as numbers.

Practice Questions

Q1. Fix the broken criteria [L1]

Correct each criterion and explain the error: (a) SUMIFS(GL[Amount], GL[Amount], >100000); (b) SUMIFS(GL[Amount], GL[Date], ">=C3"); (c) COUNTIFS(TB[Code], "5*") on numeric codes; (d) SUMIFS(GL[Amount], GL[Date], ">="&TEXT(C3,"dd-mm-yyyy")).

Q2. Contains-search box [L2]

Build a SUMIFS that totals GL[Amount] for ledgers whose name contains the text typed in H1 (e.g. "freight"), for the month in C3, excluding the department in H2. The formula must return the full monthly total when H1 is blank and must handle a user typing a ledger name containing *.

💡 Hint: A blank search text inside "*"&H1&"*" becomes "**", which matches any non-empty text.

Q3. Ageing buckets with date criteria [L2]

Using an AR Table (Customer, InvDate, Balance) and RptDate = 31-Mar-2026, write SUMIFS formulas for buckets 0–30, 31–60, 61–90, 91–180 and >180 days. State the exact boundary convention you use and prove the buckets sum to the total balance.

Q4. Locale-dependent failure [L2]

A file built in Mumbai returns correct FY26 totals, but the same file opened by a colleague at the parent company in the US shows zero for April–December. The formula uses ">=01/04/2025" and "<=31/03/2026". Explain what happens on the US machine and rewrite the criteria so they are locale-independent.

Q5. Interview: wildcards vs ranges [L1]

In an interview you are asked: "Why does COUNTIF(A:A,"4*") return 0 when column A clearly has 40 codes starting with 4?" Give a complete answer, including two ways to fix it.
