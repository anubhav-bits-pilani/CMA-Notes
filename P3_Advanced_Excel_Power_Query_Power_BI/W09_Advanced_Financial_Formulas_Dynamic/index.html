Refresh before starting

Excel Tables, structured references and names

Excel Tables (Ctrl+T), structured references, named ranges and Name Manager

  • Ctrl+T converts a block to a Table; rename it at once (Table Design → Table Name: GL, TB, Map).
  • Structured references: GL[Amount] (column), [@Amount] (this row), GL[#Headers], GL[[Date]:[Amount]]. They expand automatically when rows are pasted directly below.
  • Calculated columns fill down automatically; dynamic arrays cannot spill inside a Table.
  • Named ranges/cells for single inputs (RptDate, TaxRate, Threshold): select the cell and type in the Name Box, or use Ctrl+F3 (Name Manager) to create, edit, find broken (#REF!) names and set scope.
  • Ctrl+Shift+F3 creates names from row/column labels; F3 pastes a name into a formula.

Trial balance, CoA hierarchy and signs

Trial balance structure, CoA hierarchy and Dr/Cr sign conventions → Week 1–4

  • A TB lists every ledger's closing balance; debits equal credits, so a signed TB (Dr +, Cr −) sums to zero.
  • Tally hierarchy: Ledger → Group → Primary group (e.g. Sundry Debtors under Current Assets); SAP/Oracle: GL account → account group → FS item. Your mapping adds FS line → Schedule III line.
  • Natural signs: assets and expenses are debit (+); liabilities, equity and income are credit (−). Present income positive by flipping sign in the output layer, never in the data.
  • Balance-sign reclassifications from Weeks 1–4 (bank OD to borrowings, debit balances in creditors to advances) become explicit mapping rules.

Date serials and numbers stored as text

Excel date serials and spotting numbers stored as text (green triangles, ISTEXT)

  • Dates are serial numbers: 01-Apr-2025 = 45748; times are fractions (0.5 = noon). Format does not change the value.
  • Text dates ("30-04-2025" left-aligned) and text numbers ("1,25,000") break SUMIFS, lookups, XIRR and date criteria silently.
  • Detect: left alignment, green error triangles ("Number stored as text"), ISTEXT, ISNUMBER, COUNT(range) vs ROWS(range).
  • Fix: Text to Columns (Data → Text to Columns → Finish), Paste Special → Multiply by 1, VALUE/DATEVALUE, or a Power Query type change (best for recurring dumps). Beware dd-mm vs mm-dd locale issues.

Cross-cutting concepts

One-directional flow with no hard-codes in outputs

One-directional flow: raw GL dump tab → mapping table → calculations → output P&L, with no hard-codes in outputs

A robust reporting workbook flows one way: Raw (the GL or TB dump pasted as-is into a Table, never edited) → Map (ledger-to-FS-line mapping, maintained by finance) → Calc (cleaned, mapped GL with helper columns and SUMIFS or dynamic-array engines) → Output (the P&L, MIS grid or dashboard). Formulas only ever look "upstream"; outputs never feed back into calculations, and inputs never contain formulas. Every number on an output sheet is a formula traceable to the raw data or to a labelled input (reporting month, rounding unit). That gives three properties: next month's refresh is a paste and nothing else; a reviewer can trace any figure with Ctrl+[ to its source; and errors surface in one place rather than being patched in several. Practical rules: colour inputs (blue) differently from formulas (black); keep a single control sheet with the reporting month, scenario and check status; avoid "plugs" — if the output needs an adjustment, add a mapped adjustment line in the input layer with a narration, so the audit trail survives.

Mapping table design and the unmapped-ledger check

Mapping table design: ledger → FS line → group → Schedule III line, plus an unmapped-ledger check with FILTER/COUNTIF

The mapping Table Map has one row per ledger with columns Ledger (or code), FSLine (MIS line such as "Power and fuel"), Group (e.g. "Other expenses"), ScheduleIII (the Division II line, e.g. "Other expenses" in the statement of profit and loss, or "Trade payables – MSE" in the balance sheet) and Nature/Sign. Keys must be unique (=COUNTIF(Map[Ledger],[@Ledger])>1 flags duplicates) and typed consistently with the TB. In the TB or GL Table, a calculated column =XLOOKUP([@Ledger], Map[Ledger], Map[FSLine], "Not mapped") attaches the FS line. The unmapped check has two forms: a count (=COUNTIF(TB[FSLine],"Not mapped"), which must be zero) with its amount (=SUMIFS(TB[Closing],TB[FSLine],"Not mapped")), and a live exception list =FILTER(TB[[Ledger]:[Closing]], TB[FSLine]="Not mapped", "All mapped") that names every ledger needing attention. The reverse test — mapping rows no longer found in the TB (COUNTIF(TB[Ledger],[@Ledger])=0) — catches renamed Tally ledgers.

Month headers from EOMONTH/SEQUENCE and date-range SUMIFS

Month headers built with EOMONTH/SEQUENCE; SUMIFS keyed on date ranges, never on month text

Month headers should be real dates generated from one input: =EOMONTH(StartDate, SEQUENCE(1, 12, 0)) spills twelve month-end dates across a row (format as mmm-yy). Every SUMIFS then uses two criteria on the date column: ">"&EOMONTH(hdr,-1) and "<="&hdr for month-end headers (or ">="&start and "<="&EOMONTH(start,0) for month-start headers). Keying on dates rather than on a text "Month" column ("Apr-25") avoids three failure modes: text that differs in spelling or locale, the same month name in different years being merged, and a helper column that someone forgets to fill for new rows. Date-keyed headers also make YTD, QTD and rolling windows trivial (shift the start date) and feed XLOOKUP:XLOOKUP dynamic ranges. If postings carry time stamps, use "<"&hdr+1 as the upper bound. Changing StartDate re-dates the whole report — no column is edited by hand.

Error discipline and check cells

Error discipline (IFNA vs IFERROR) and check cells: TB nets to zero, P&L ties back to the TB

IFERROR(x, alt) replaces every error — #N/A, #REF!, #VALUE!, #DIV/0!, #NAME? — with the alternative, so a deleted column or misspelt Table name can turn a whole report into plausible zeros. IFNA(x, alt) replaces only #N/A (the not-found case) and lets structural errors show. Rules: use XLOOKUP's if_not_found or IFNA for expected misses; test explicit conditions (IF(COUNTIFS(…)=0, …)) for expected empties; reserve IFERROR for proven formulas where only one error type is possible. Then prove the output with check cells on a control sheet: TB nets to zero (=ROUND(SUM(TB[Closing]),0)=0); P&L profit equals the TB's income and expense ledgers' net (=ROUND(PL_Profit + SUMIFS(TB[Closing], TB[Nature],"Income") + SUMIFS(TB[Closing], TB[Nature],"Expense"),0)=0, with sign conventions as designed); each month's P&L total ties to that month's GL movement; unmapped count = 0; duplicate count = 0. A master cell =IF(AND(checks),"OK","ERRORS") sits on every output page.

Formula auditing tools

Formula auditing: Trace Precedents/Dependents, Evaluate Formula, the Inquire add-in

Formulas → Formula Auditing provides Trace Precedents (Alt M P) and Trace Dependents (Alt M D), which draw arrows to the cells feeding or using the active cell (dashed arrows with a sheet icon for other sheets; double-click to jump); Remove Arrows (Alt M A A); Evaluate Formula (Alt M V), which steps through a formula one operation at a time — the fastest way to see where a long SUMIFS or nested XLOOKUP goes wrong; Watch Window for monitoring key outputs while editing elsewhere; and Error Checking. Keyboard equivalents Ctrl+[ and Ctrl+] select precedents/dependents directly. The Inquire add-in (File → Options → Add-ins → COM Add-ins → Inquire; available in Microsoft 365 Apps for enterprise and Office Professional Plus editions) adds Workbook Analysis (counts of formulas, constants, errors, hidden sheets, external links, inconsistent formulas), Workbook Relationship and Cell Relationship diagrams, and Compare Files, which highlights every formula and value change between two versions — ideal for reviewing a colleague's month-end update.

The exercise pattern

Exercise pattern: UNIQUE FS lines × EOMONTH headers × SUMIFS on the XLOOKUP-mapped GL, with FILTER for drill-down

The week's build combines one function from each topic into a self-updating P&L. Rows: =SORT(UNIQUE(GL[FSLine])) in A6 spills the distinct FS lines present in the mapped GL (or use the ordered list from Map so the P&L follows Schedule III order). Columns: =EOMONTH(StartDate, SEQUENCE(1, NMonths, 0)) in C4. Body: a single spilled formula

=SUMIFS(GL[Amount], GL[FSLine], A6#, GL[Date], ">"&(C4#-DAY(C4#)), GL[Date], "<="&C4#)

which broadcasts the vertical line spill against the horizontal month spill into a full lines × months grid. (C4#-DAY(C4#) is the previous month-end; EOMONTH and EDATE reject range references such as C4# with #VALUE! — wrap as EOMONTH(+C4#,-1) if you prefer EOMONTH.) The FS line column in GL is itself an XLOOKUP calculated column on Map. Drill-down: with a selected line and month in two dropdown cells, =FILTER(GL[[Date]:[Amount]], (GL[FSLine]=SelLine)*(GL[Date]>EOMONTH(SelMonth,-1))*(GL[Date]<=SelMonth), "No postings") lists the vouchers behind any number. When next month's GL is pasted, the Table grows, new FS lines appear in the row spill, and NMonths extends the columns — no manual filter, no edited formula.

Hands-on exercise brief

Exercise: Build a dynamic GL Trial Balance mapping and automated monthly P&L generator using XLOOKUP, SUMIFS, FILTER, UNIQUE, and EOMONTH without a single manual filter.

Scenario and inputs

Deccan Foods Pvt Ltd (FMCG, FY ending 31 March, Tally Prime, three branches: PUN, MUM, HYD). You receive:

  1. TB at 30-Sep-2025 — about 520 ledgers (Ledger, Tally Group, Closing Dr, Closing Cr). Create it from a Tally export or synthesise it: revenue about ₹62 crore for the half-year, gross margin about 34%, employee cost about 9% of revenue, finance costs about ₹1.1 crore.

  3. Mapping table — Ledger, FSLine (about 35 MIS lines), Group, ScheduleIII line, Nature (Asset/Liability/Equity/Income/Expense).

  • Postings outside the reporting window: count.
  • Text amounts and text dates in the raw dump: count before and after cleaning.
  • Sum of the P&L grid for six months equals the TB's income and expense ledgers' movement for the period (with the opening P&L balances at 1 April being nil).
  • Every month's P&L column ties to the GL movement of P&L ledgers for that month.
  • Master status cell on Control and on PL_Monthly.

Build rules and deliverable

  • No AutoFilter, no manual sort, no hard-coded number in any output cell; every output traceable with Ctrl+[.
  • Paste test: replace Raw_GL with April–October data (add 7,000 rows dated October) and set NMonths to 7; the P&L must extend by one column with all checks still passing.
  • Deliverable: the workbook, plus a one-page note (in the Control tab) listing the seeded issues found by each check and how each was resolved.
