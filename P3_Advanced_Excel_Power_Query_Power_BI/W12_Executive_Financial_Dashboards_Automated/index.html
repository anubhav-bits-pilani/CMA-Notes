Objective: Build an interactive CFO-ready financial dashboard in Power BI and Excel with drill-throughs, KPI cards, and automated refresh.

How this week fits

Week 12 closes Phase 3 (Advanced Excel, Power Query & Power BI Automation) and delivers Project 3. Weeks 9–10 built the ingestion layer: folder consolidation of monthly TB/GL files, cleaning functions and reconciliation exception outputs. Week 11 turned that clean data into a star-schema semantic model with an April–March Date table, base measures, time intelligence, semi-additive balance measures and a P&L layout measure. This week puts a product on top of that model: a three-page Power BI executive pack, an Excel board pack driven by cube formulas against the same model, a control layer that proves the numbers, and a refresh set-up that works with one click.

The prerequisite mindset is that of a reviewer, not a chart-maker. A CFO pack is judged on three things: does it answer the questions the CFO actually asks, does every number tie to the books, and does it refresh next month without someone re-building it. The topics follow that order: visual architecture (t1), interactivity and drill-through (t2), Excel cube-formula reporting (t3), governance and audit-trail controls (t4), and finalising one-click refresh, publishing and distribution (t5).

What comes next: Weeks 13–16 build the integrated 3-statement model and will consume this pack's actuals as the opening position and historicals; Weeks 17–20 run a monthly MIS and rolling-forecast cycle on top of the same model (price/volume/mix bridges plug into this week's waterfalls); Weeks 23–24 use Project 3 as an interview walkthrough piece.

Refresh before starting

Week 11 model: star schema, Date table, measures, P&L layout

  • Facts: GL (voucher lines: Date, VoucherNo, AccountKey, BUKey, CostCentreKey, VendorKey, Amount, Narration), Budget (month-level, stored on the first day of the month), TB snapshots for balances.
  • Dimensions: 'Date' (FY label such as FY2025-26, FiscalMonthNo with April = 1, FiscalQuarter, MonthEnd, MonthOffset), CoA (Statement → FSLine → Ledger, SignFactor), BU, Region, CostCentre, Vendor, Layout.
  • One-to-many, single-direction relationships from dimensions to facts; fact keys hidden.
  • Base measures: [Actual], [Budget], [Revenue], [EBITDA], [EBITDA %]; time intelligence with "3/31" year-end (YTD, PY YTD, Rolling 12M, Last Actual Date guard); semi-additive Closing Bal, Avg AR, DSO.
  • P&L layout measure: SWITCH over Layout[Type] (Account/Subtotal/Ratio), sign-flip through CoA[SignFactor], ISINSCOPE to blank meaningless totals, dynamic format strings for ratio rows.

Week 10 pipelines: folder consolidation and exception outputs

  • Folder.Files / SharePoint.Files → filter extension and name pattern, exclude ~$ lock files → custom transform function per file → combine → add Source.Name.
  • Cleaning: skip header rows by condition, unpivot month columns, type early, trim/clean ledger names, map to CoA through a merge.
  • Exception outputs: unmapped ledgers, Dr ≠ Cr by file, duplicate vouchers, missing months, row counts per branch. This week these exceptions become visible control visuals instead of separate query outputs.

Schedule III structure and working-capital definitions

  • Schedule III Division II (Ind AS) balance sheet: non-current and current assets; equity (equity share capital, other equity); non-current and current liabilities, with financial liabilities split into borrowings, lease liabilities, trade payables (MSME and others) and other financial liabilities.
  • Statement of profit and loss: revenue from operations, other income, cost of materials consumed, purchases of stock-in-trade, changes in inventories, employee benefits expense, finance costs, depreciation and amortisation, other expenses; profit before exceptional items and tax; tax; profit for the period; OCI.
  • EBITDA is not a Schedule III line; define it explicitly (PBT + finance costs + D&A − other income, or including other income — state the policy).
  • NWC = trade receivables + inventories + other operating current assets − trade payables − other operating current liabilities (exclude cash, current borrowings and current maturities of long-term debt).
  • DSO = average trade receivables / revenue × days; DIO = average inventory / COGS × days; DPO = average trade payables / purchases (or COGS) × days; cash conversion cycle = DSO + DIO − DPO.

Power BI Service basics

  • Workspace: a container for semantic models, reports, dashboards and dataflows; roles Admin, Member, Contributor, Viewer.
  • Publishing from Desktop creates two items: the semantic model (data, relationships, measures, refresh settings, RLS roles) and the report (pages and visuals bound to that model). Several reports can share one semantic model.
  • A dashboard (pinned tiles) is different from a report; the CFO pack is a report.
  • Apps package workspace content for consumers with audiences, so viewers never browse the workspace.
  • Refresh requires credentials on the semantic model and a gateway for on-premises sources.

Cross-cutting concepts

Audience-first design

Start from the CFO's questions, not from available fields. A typical list for an Indian listed mid-cap: Are we on budget this month and YTD? What drove the EBITDA variance? Where is the cash and how much do we owe? Is working capital deteriorating? Which BU or cost centre is overspending, and on which vendors? Map each question to one page and one primary visual. "On budget?" becomes the top-row KPI cards with variance-to-budget reference labels on Page 1. "What drove variance?" becomes the Budget-to-Actual EBITDA waterfall. "Where is cash?" becomes the closing cash card and Net Debt trend on Page 2. "Who is overspending?" becomes the Page 3 expense decomposition with drill-through to vouchers. Any visual that does not answer a listed question is removed or moved to a detail page. The test is the five-second rule: a CFO glancing at Page 1 should know whether the month is good or bad before reading a single label. This also fixes ordering (summary → trend → detail, top-left to bottom-right) and the comparison basis (every number shown against Budget or PY).

One measure library, two front ends

The Power BI report and the Excel board pack must never compute the same KPI in two ways. Put every measure — Revenue, EBITDA, EBITDA %, Net Debt, NWC, DSO, variances, control checks — in one semantic model. Power BI visuals bind to those measures; Excel binds to the same measures through CUBEVALUE (against the workbook Data Model, or a published Power BI semantic model via Analyze in Excel). If the board pack needs a new number, it is added as a measure in the model, not as an Excel formula on top of cube values. Benefits: one definition of EBITDA to defend to auditors, one place to fix errors, consistent sign conventions and rounding, and lineage that shows exactly which reports depend on a measure. Store measure descriptions in the model so both front ends expose the same documentation. A display folder structure (Base, Time Intelligence, KPI, Variance, Controls) keeps the library navigable.

Controls built into the product

A dashboard that cannot prove itself will not be trusted. Build checks as measures and show them in the product: Dr = Cr (SUM(GL[Debit]) - SUM(GL[Credit]) within a ₹1 tolerance), BS check (Assets − Liabilities − Equity = 0 at every month-end), TB tie-out (dashboard revenue, EBITDA and PAT per month equal to source TB control totals), unmapped count (GL account codes with no CoA mapping), and a last-refresh stamp converted to IST plus the latest GL posting date. Run each check by month and by branch/file, not only at grand total, because offsetting errors cancel at total level. Show a compact status strip on every page ("All checks PASS · Refreshed 05-May-2026 09:12 IST · Data to 30-Apr-2026") and a full control panel page with pass/fail indicators. Assign an owner who signs off failures before the pack is released.

Exercise Pages 1 and 2 content

Page 1 — Executive P&L & Variance Overview. Top row: five KPI cards (Revenue, EBITDA %, PAT, Cash, Net Debt), each with a reference label versus Budget and PY. Middle: monthly Actual vs Budget vs PY combo chart and Rolling 12M revenue. Bottom: P&L matrix (Layout measure: Actual, Budget, Var, Var %, PY) and a Budget-to-Actual EBITDA waterfall whose steps are revenue, gross margin, employee cost, other expenses and so on, closing at Actual EBITDA. Page 2 — Balance Sheet & Working Capital. Closing balances in Schedule III grouping as at the selected month-end (semi-additive measures), NWC and its components, DSO/DIO/DPO and cash conversion cycle trend over 12 months, and a Net Debt trend (borrowings including current maturities minus cash and cash equivalents, with the policy on other bank balances and liquid investments stated). Page 2 must use closing-balance logic, never summed balances.

Exercise Page 3 content

Page 3 — Expense Drill-Down. Decompose expenses by BU → cost centre → vendor: a matrix with drill-down on the CoA hierarchy, a Top N vendor bar chart driven by RANKX(ALLSELECTED(...)), a decomposition tree for ad hoc root-cause exploration, and variance versus budget at each level. A hidden drill-through page ("GL Detail") has CoA[Ledger] (and optionally Cost Centre and Vendor) as drill-through fields with Keep all filters on, and shows GL[VoucherNo], GL[Date], GL[Narration], GL[Amount], vendor and cost centre. Right-clicking a ledger or an EBITDA variance line anywhere in the pack lands on the vouchers that make up that number for the same FY, month, BU and region. A visual-level filter or a "select a ledger" guard prevents the detail table from rendering millions of unfiltered rows.

Navigation

A pack is used by executives who will not explore the Fields pane. Provide a page-navigator or button bar on every page (Overview · Balance Sheet · Expenses · Controls), a back button on every drill-through and tooltip-adjacent page, and bookmarks for view toggles such as Actual vs Budget or ₹ vs % (built with the selection pane and "Data" unchecked when the bookmark should not overwrite slicers). FY, BU and Region slicers sit in the same position on every page and are synced through View > Sync slicers, so changing FY on Page 1 changes it everywhere. A dynamic title ("P&L – " & [Selected FY]) confirms the current context. Test navigation in the Service, not only in Desktop, because button actions need Ctrl+click in Desktop but a single click when published.

Hands-on exercise brief

Exercise: Complete Project 3: Build a 3-page Power BI Executive Finance Pack (Page 1: Executive P&L & Variance Overview; Page 2: Balance Sheet & Working Capital; Page 3: Expense Drill-Down).

Scenario and inputs

Use a fictional NSE-listed specialty-chemicals company, "Sahyadri Chemicals Ltd", FY April–March, three BUs (Agro, Pharma Intermediates, Performance Polymers) and three regions (North, West, South). Source folder (on SharePoint or OneDrive) contains:

File set Grain Volume
GL_YYYY-MM.csv (24 files, Apr-2024 to Mar-2026) Voucher line: Date, VoucherNo, VoucherType, AccountCode, BU, CostCentre, VendorCode, Narration, Debit, Credit About 18,000 lines per month
Budget_FY2025-26.xlsx Month × AccountCode × BU 12 months
TB_Control.xlsx Month × FSLine control totals from the ERP 24 months
CoA_Map.xlsx AccountCode → Ledger → FSLine → Statement, SignFactor, NWC flag, Net Debt flag About 420 accounts
Vendor.xlsx, CostCentre.xlsx Masters About 650 vendors, 38 cost centres

Assumptions for checking scale: FY2025-26 revenue about ₹1,240 crore, EBITDA margin about 16.5%, borrowings about ₹310 crore, cash and equivalents about ₹85 crore, receivables about ₹205 crore, inventory about ₹180 crore, trade payables about ₹150 crore. Seed at least one known variance (for example, power and fuel ₹4.2 crore over budget in October in the Agro BU) so the drill path can be demonstrated.

Required build

  1. Model: Week 11 star schema plus Vendor, CostCentre, TB_Control, a disconnected Bridge Steps table for the waterfall, and a field-parameter table for the Page 3 dimension switcher.
  2. Measure library in display folders: Base, Time Intelligence, KPI (Revenue, EBITDA, EBITDA %, PAT, Cash, Net Debt, NWC, DSO, DIO, DPO, CCC), Variance (vs Budget, vs PY, Fav/Adv sign-adjusted), Formatting (colour and ₹ crore measures, dynamic titles), Controls.
  3. Page 1 as described in the cross-cutting section, five KPI cards with Budget and PY reference labels, combo trend, P&L matrix, EBITDA bridge.
  4. Page 2 closing balances, NWC components, DSO/DIO/DPO trend, Net Debt trend.
  5. Page 3 expense matrix with drill-down, Top N vendors with a What-if N parameter, decomposition tree, drill-through to a hidden GL Detail page with a back button and a report-page tooltip on vendor bars.
  6. Controls page and a status strip on every page.
  7. Theme JSON with the company palette, favourable/adverse colours, Segoe UI, consistent ₹ crore format with one decimal; alt text on every visual; a mobile layout for Page 1.
  8. Excel board pack (one sheet) with CUBEVALUE formulas against the same model and an FY slicer.

Required checks

  • Waterfall closing value equals [EBITDA] Actual for every month and YTD selection.
  • Page 1 Revenue card equals the P&L matrix revenue row equals TB_Control revenue for each of 24 months.
  • BS check = 0 at every month-end; Dr Cr Diff within ₹1 for each file.
  • Unmapped count = 0 (or every unmapped code listed with an owner).
  • Excel board-pack revenue equals the Power BI card for FY2025-26 and FY2024-25.

Deliverables

PBIX (and PBIP folder if using Git), the Excel board-pack workbook, a one-page data lineage diagram, a measure dictionary (name, DAX, description, format, owner), and a two-page CFO user guide with screenshots of the drill path.
