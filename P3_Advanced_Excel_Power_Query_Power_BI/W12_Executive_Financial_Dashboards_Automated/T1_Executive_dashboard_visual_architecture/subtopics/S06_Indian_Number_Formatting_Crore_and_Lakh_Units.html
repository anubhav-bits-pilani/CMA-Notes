Subtopic note

Indian Number Formatting: ₹ Crore and Lakh Units, Consistent Decimals

Scope: Indian number formatting: ₹ crore/lakh units and consistent decimals

Why it matters

Indian boards, audit committees and analysts read numbers in ₹ crore (listed company results, SEBI filings, investor presentations) or ₹ lakh (smaller companies, Schedule III statements where the rounding-off note under General Instructions permits lakhs or crores depending on turnover). A dashboard that shows "₹1.24bn" or "₹12,400M" forces mental conversion and looks foreign; one that mixes lakhs on a card with crores in the matrix invites misreading by a factor of 100. Power BI's built-in display units are Western (thousands, millions, billions, trillions), so Indian units must be engineered deliberately.

Core notes

The units

Unit Value in ₹ Power of ten Typical use
Thousand 1,000 \(10^3\) Rarely used in India for reporting
Lakh 1,00,000 \(10^5\) SMEs, branch MIS, Schedule III for smaller companies
Crore 1,00,00,000 \(10^7\) Listed companies, board packs, investor decks

Schedule III (General Instructions, rounding) requires figures to be rounded off according to total income: below ₹100 crore, to the nearest hundreds, thousands, lakhs or millions (or decimals thereof); ₹100 crore or more, to the nearest lakhs, millions or crores (or decimals thereof). Once a unit is chosen it must be used uniformly in the financial statements. The same discipline should apply to the dashboard: one unit per pack, stated in the title band ("₹ crore unless stated").

Indian digit grouping

Indian grouping places commas after the first three digits from the right, then every two digits: 12,34,56,789 rather than 123,456,789. In Excel this needs a conditional custom number format:

[>=10000000]##\,##\,##\,##0;[>=100000]##\,##\,##0;##,##0

This handles positive numbers only (Excel allows two conditions plus a default); negatives need a separate approach (formula-driven formatting, or Windows regional settings set to English (India), which makes the standard #,##0 grouping Indian in Excel). In Power BI, grouping follows the model and report locale; English (India) grouping is rendered by some visuals but behaviour can differ between Desktop and the Service (which uses the browser language). Do not rely on locale for board packs — use scaled units instead, where grouping rarely matters (₹1,240.6 Cr).

Option 1: scaled measures (most robust)

Create presentation measures that divide by \(10^7\) (crore) or \(10^5\) (lakh), as in Concept c03:

Revenue ₹ Cr = DIVIDE ( [Revenue], 1e7 )      -- format: #,##0.0
EBITDA ₹ Cr  = DIVIDE ( [EBITDA], 1e7 )

Pros: works in every visual, in exports and in Analyze in Excel. Cons: doubles the measure count; tooltips and drill-through tables must also use the crore measures to be consistent.

Option 2: a units table with a dynamic label

A disconnected table Units with rows (₹, 1), (₹ lakh, 1e5), (₹ crore, 1e7) and a slicer lets the user pick. The measure divides by the selected divisor and its dynamic format string appends the label:

Revenue Display =
DIVIDE ( [Revenue], SELECTEDVALUE ( Units[Divisor], 1e7 ) )

-- Format: Dynamic; format string expression:
"#,##0.0 """ & SELECTEDVALUE ( Units[Label], "Cr" ) & """"

Dynamic format strings for measures became generally available in 2024; they change only the display, and the measure still returns a number, so sorting and conditional formatting work.

Option 3: a calculation group

A calculation group "Units" with items Crore and Lakh, each with expression DIVIDE(SELECTEDMEASURE(), 1e7) (or 1e5) and a format string expression, applies scaling to every measure in a visual without duplicating measures. Exclude ratio measures (EBITDA %, DSO) from scaling with IF(ISSELECTEDMEASURE([EBITDA %], [DSO]), SELECTEDMEASURE(), DIVIDE(SELECTEDMEASURE(), 1e7)). Note that calculation groups affect all measures in a visual, so test cards, waterfalls and KPI visuals.

Format-string-only tricks

Format strings can scale only by thousands (each trailing comma divides by 1,000). A literal-decimal trick inserts a decimal point as text: in Excel, 0"."00, displays 12,34,567 as 12.35 (lakhs) and 0"."0,, displays 1,23,45,67,890 as 123.5 (crore, one decimal). It is clever but fragile — it fails for two-decimal crores, can confuse reviewers, and should be documented if used in a board pack.

Consistent decimals

Fix a decimals policy and apply it via the theme and measure formats:

Measure type Format Example
₹ crore amounts #,##0.0 (one decimal) 1,240.6
₹ lakh amounts (SME packs, expense detail) #,##0.00 482.61
Percentages and margins 0.0% 16.5%
Margin changes +0.0 "pp";-0.0 "pp" −0.8 pp
Days (DSO, DIO, DPO) 0 61
Multiples (Net Debt/EBITDA, interest cover) 0.00"x" 1.52x

Negative numbers: decide between minus sign and brackets, and use it everywhere — cards, matrix, waterfall labels. Finance packs often use brackets #,##0.0;(#,##0.0);– for tables; if so, cards must also show brackets.

Rounding and casting

Rounded crore numbers will not always foot: three BUs with revenue 412.36, 300.36 and 528.36 total 1,241.08, displayed as 1,241.1, while the displayed parts 412.4 + 300.4 + 528.4 add to 1,241.2. Compute totals from unrounded values (the measures do this automatically) and add the footnote "Totals may not add due to rounding", as listed companies do.

Edge cases & judgement calls

  • Mixed units on one page. A ₹ lakh vendor table next to ₹ crore cards invites 100x errors; if detail needs lakhs, label the column header with the unit.
  • Small values in crore. A ₹3.6 lakh expense shows as 0.0 Cr; for expense drill-down pages, use lakh or full rupees.
  • Export to Excel. "Export data" exports the measure value; a divided measure exports crores, a format-string approach exports rupees — tell users which.
  • Text measures for display. FORMAT([Revenue]/1e7, "#,##0.0") & " Cr" returns text, which breaks sorting, totals and conditional formatting; avoid except in titles.
  • Locale of the model. Format strings such as #,##0.0 use the culture's separators; a model with a European culture swaps comma and period.

Key takeaways

  • Indian packs use ₹ crore (listed) or ₹ lakh (smaller entities); state the unit once and use it everywhere.
  • Power BI display units do not include lakh/crore; use divided measures, a units table with dynamic format strings, or a calculation group.
  • Indian digit grouping requires conditional formats in Excel and is unreliable via locale in Power BI.
  • Fix decimals by measure type: crore one decimal, % one decimal, pp one decimal, days zero, multiples two.
  • Keep sign conventions identical across cards, tables and waterfalls; footnote rounding.

Practice Questions

Q1. Unit conversions [L1]

Express ₹4,82,61,30,500 in crore (two decimals) and in lakh (zero decimals), and write it with Indian digit grouping.

Q2. Units slicer [L2]

Build a disconnected Units table in DAX (or Power Query) with rows for ₹, ₹ lakh and ₹ crore and write the [EBITDA Display] measure plus its dynamic format string expression so that the default is crore with one decimal. Explain why EBITDA % must not be affected by the slicer.

Q3. Schedule III rounding policy [L2]

A company with total income of ₹86 crore wants its management pack in ₹ crore with two decimals while the audited financial statements are in ₹ lakh. Explain whether this is permitted, what the pack must disclose, and how you would reconcile a pack number to the financial statements.

Q4. Fix the inconsistent pack [L3]

A review finds: cards show "₹1.24K Cr" (display units Thousands on a crore measure), the matrix shows rupees with brackets for negatives, waterfall labels show lakhs with minus signs, and Var % shows two decimals on some rows. Write a remediation plan covering measure design, theme settings and a test to confirm consistency.
