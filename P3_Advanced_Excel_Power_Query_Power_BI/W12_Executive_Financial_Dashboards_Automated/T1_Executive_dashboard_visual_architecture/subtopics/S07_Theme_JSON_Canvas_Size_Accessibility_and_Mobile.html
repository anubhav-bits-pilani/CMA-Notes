Subtopic note

Theme JSON, Canvas Size, Accessibility and Mobile Layout

Scope: Theme JSON, canvas size, accessibility (contrast, alt text), mobile layout

Why it matters

A CFO pack is a product used every month by people who did not build it: the CFO on a laptop in a review meeting, the MD on a phone at an airport, a board member who prints to PDF, and possibly a colleague with low vision using a screen reader. Formatting each visual by hand does not scale and drifts between pages. A theme JSON file enforces the palette, fonts and default visual settings in one place; a deliberate canvas size makes exports and projectors behave; accessibility settings make the pack usable by everyone (and are increasingly required by corporate IT and listed-company ESG/disability-inclusion policies); and a mobile layout makes Page 1 readable in the Power BI mobile app.

Core notes

Theme JSON

A report theme is a JSON file applied via View > Themes > Browse for themes (or customised through Customize current theme and saved). Key sections:

  • name — theme name.
  • dataColors — the ordered series palette used by default for series and categories.
  • good, neutral, bad — sentiment colours used by KPI visuals and waterfalls (increase/decrease) in some contexts.
  • maximum, center, minimum — default gradient colours for conditional formatting.
  • foreground, background, tableAccent — text, canvas and table accent colours.
  • textClasses — font family, size and colour for title, label, callout, header and so on.
  • visualStyles — default formatting per visual type and property card ("*" applies to all visuals), e.g. card callout size, title alignment, gridline colour, matrix banding.

A compact finance theme:

{
  "name": "Sahyadri Finance",
  "dataColors": ["#1F3A5F", "#7A8DA6", "#B8C4D4", "#E3A33B", "#4C7A6B", "#9B5D73"],
  "good": "#2E7D32",
  "neutral": "#9E9E9E",
  "bad": "#C62828",
  "foreground": "#212121",
  "background": "#FFFFFF",
  "tableAccent": "#1F3A5F",
  "textClasses": {
    "title":   { "fontFace": "Segoe UI Semibold", "fontSize": 12, "color": "#212121" },
    "callout": { "fontFace": "Segoe UI Semibold", "fontSize": 24, "color": "#1F3A5F" },
    "label":   { "fontFace": "Segoe UI", "fontSize": 9, "color": "#424242" }
  },
  "visualStyles": {
    "*": { "*": { "title": [{ "show": true, "alignment": "left" }],
                  "border": [{ "show": false }] } }
  }
}

Store the theme in the pack's repository (with PBIP, the theme is saved inside the report folder) and reuse it via a .pbit template so every new page starts consistent. Hex codes in variance colour measures (Concept c02) must match good/bad in the theme.

Canvas size

Format page > Canvas settings offers 16:9 (1280 × 720), 4:3 (960 × 720), Letter, Tooltip (320 × 240) and Custom sizes. For an executive pack:

  • 16:9, 1280 × 720 is the default and fits laptops, projectors and PowerPoint export.
  • Custom tall pages (e.g. 1280 × 1440) suit a scrolling detail page but export poorly to PDF and PowerPoint.
  • Page view: Fit to page for the overview, Fit to width for long pages.
  • Use the same size on all main pages so navigation does not jump; tooltip pages use the Tooltip size (Topic 2).

Accessibility: contrast

WCAG 2.1 AA requires a contrast ratio of at least 4.5:1 for normal text and 3:1 for large text and graphical objects. The contrast ratio is

\[ \text{CR} = \frac{L_1 + 0.05}{L_2 + 0.05} \]

where \(L_1\) and \(L_2\) are the relative luminances of the lighter and darker colours (0 for black, 1 for white). Dark navy (#1F3A5F) on white comfortably passes; light grey text (#B8C4D4) on white fails and should only be used for non-essential gridlines. Check palettes with a contrast checker. Avoid encoding favourable/adverse by red/green alone: add ▲/▼ icons, "F/A" text, or use a colour-blind-safe pair (blue #1565C0 / orange #E65100).

Accessibility: alt text, tab order and titles

  • Alt text (Format visual > General > Alt text, up to 250 characters) is read by screen readers. It can be dynamic via fx using a measure: "Revenue " & FORMAT([Revenue ₹ Cr], "#,##0.0") & " crore, " & FORMAT([Revenue vs Budget %], "+0.0%;-0.0%") & " versus budget".
  • Tab order (View > Selection pane > Tab order) controls keyboard navigation; put the KPI row first, hide decorative shapes from tab order.
  • Titles on every visual, with meaningful text (not "Sum of Amount by Month").
  • Show as a table (Alt+Shift+F11) lets keyboard users read underlying data; keep measures well named.
  • Markers and line styles differentiate series beyond colour.

Mobile layout

View > Mobile layout opens a phone-shaped canvas where you place existing visuals from the page (they are the same visuals, filtered identically, but with separate size and position). Design guidelines:

  • Page 1 only, or a dedicated "CFO mobile" page: the five KPI cards stacked, then the Actual vs Budget trend, then the EBITDA waterfall.
  • Slicers: one FY slicer as a dropdown; BU/Region in the filter pane or omitted.
  • Avoid matrices with many columns; use cards and simple bars.
  • Format visuals for mobile separately where supported (the mobile canvas allows some property overrides).
  • Test in the Power BI mobile app after publishing; reports without a mobile layout open in landscape web view.

Illustration: theme rollout

Sahyadri's pack had 27 visuals with 11 different blues and three fonts. Applying the theme above, then resetting visuals to default formatting (Format > Reset to default) for colours only, reduced manual formatting to card accent colours and the waterfall sentiment colours, and made the Excel board pack (using the same hex codes) match the Power BI pack.

Edge cases & judgement calls

  • Theme vs explicit formatting. Explicit formatting on a visual overrides the theme; a theme applied late will not fix visuals formatted manually. Apply the theme first.
  • Corporate brand colours that fail contrast. Use the brand colour for accents and a darker variant for text.
  • Dark mode/high contrast. Windows high-contrast modes are honoured by Power BI Desktop and the Service for many visuals; test the pack in high-contrast mode if accessibility is a stated requirement.
  • Custom visuals may not support alt text or keyboard navigation; prefer native visuals for the executive page.
  • Mobile layout and bookmarks. Bookmarks and buttons work on mobile, but complex toggles are hard to tap; keep mobile interaction simple.
  • Export to PDF ignores mobile layout and uses the canvas size; very tall custom pages are shrunk.

Key takeaways

  • A theme JSON centralises palette, sentiment colours, fonts and per-visual defaults; apply it first and reuse via .pbit templates.
  • Use 1280 × 720 for executive pages; tooltip pages use the tooltip canvas size.
  • Meet WCAG contrast (4.5:1 text, 3:1 graphics), never rely on colour alone, and write meaningful, dynamic alt text.
  • Set tab order and visual titles for keyboard and screen-reader users.
  • Build a mobile layout for the CFO overview with stacked cards and one trend.

Practice Questions

Q1. Write a theme fragment [L1]

Write a theme JSON fragment that sets the series palette to five colours of your choice, good = #2E7D32, bad = #C62828, card callout font Segoe UI Semibold 24 pt, and left-aligned titles for all visuals.

Q2. Contrast check [L2]

Relative luminances: white 1.000, #1F3A5F 0.040, #7A8DA6 0.250, #E3A33B 0.430. Compute the contrast ratio of each colour against a white background and state which can be used for body text, for large callouts only, or for non-text graphics only under WCAG 2.1 AA.

Q3. Dynamic alt text [L2]

Write a DAX measure for the alt text of the Net Debt card that reads, for example, "Net debt 226.9 crore as at 31 October 2025, 18.4 crore above budget", and explain where to bind it.

💡 Hint: Combine FORMAT with the selected month-end date and a sign-aware word.

Q4. Mobile design for the MD [L3]

The MD will only use the phone app and wants to see whether the month is on budget and where cash stands. Design the mobile layout (visual order, sizes, slicers, interactions) for Page 1, list what you would omit and explain how you would test it before the board meeting.
