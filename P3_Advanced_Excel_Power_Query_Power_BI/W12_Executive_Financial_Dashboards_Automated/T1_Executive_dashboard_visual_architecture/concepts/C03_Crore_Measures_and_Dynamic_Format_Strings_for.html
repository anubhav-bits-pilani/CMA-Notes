Key concept

Crore Measures and Dynamic Format Strings for Indian Units

Concept: Revenue ₹ Cr = DIVIDE([Revenue], 1e7), or a dynamic format string, because display units do not offer lakh/crore

Statement

Revenue ₹ Cr = DIVIDE ( [Revenue], 1e7 )      -- Format: #,##0.0
Revenue ₹ L  = DIVIDE ( [Revenue], 1e5 )      -- Format: #,##0.00
  • [Revenue] is the base measure in rupees.
  • 1e7 is scientific notation for \(10^7 = 1{,}00{,}00{,}000\) (one crore); 1e5 = one lakh.
  • DIVIDE returns BLANK when the divisor is zero or blank; with a constant divisor it is used for consistency and readability (a plain / would also work).

Alternative: keep one measure and give it a dynamic format string (Format = Dynamic) whose expression returns a format string, combined with a divisor selected from a disconnected Units table:

\[ \text{Displayed value} = \frac{\text{Revenue}_{\text{₹}}}{d}, \qquad d \in \{1, 10^5, 10^7\} \]

where \(d\) is the divisor chosen by the user, and the format string appends the matching label ("L" or "Cr").

Explanation

Power BI's Display units option on cards, axes and data labels offers Auto, None, Thousands, Millions, Billions and Trillions. Lakh (\(10^5\)) and crore (\(10^7\)) do not fit the thousand-step scale, so choosing Millions shows ₹1,240.6 Cr as "12.4bn"/"12,406M" — unusable for an Indian board. Format strings can only scale by thousands too (trailing commas), so scaling has to happen in DAX.

Design points:

  • Name with the unit. Revenue ₹ Cr tells report users and Analyze-in-Excel users what they are looking at.
  • Presentation layer only. Base, variance and control measures stay in rupees. Controls such as TB tie-out compare rupees so ₹1 tolerances stay meaningful.
  • Format on the measure, not the visual. Set #,##0.0 in the measure's format so cards, tables and tooltips agree, and set display units to None on visuals.
  • Ratios are not scaled. EBITDA % and DSO are unitless; never divide them.
  • Dynamic format strings (generally available since 2024) let the measure keep returning a number while the format string changes with context — e.g. "#,##0.0 \"Cr\"" vs "#,##0.00 \"L\"" — so sorting, conditional formatting and totals still work. This is preferable to FORMAT(), which returns text.
  • Calculation groups can apply the divisor to every measure in a visual; useful when the whole pack switches between lakh and crore.

Illustration

Revenue for FY2025-26 is ₹12,40,63,48,210.

\[ \frac{12{,}40{,}63{,}48{,}210}{10^7} = 1{,}240.63 \Rightarrow \text{displayed as } 1{,}240.6 \text{ Cr} \]

and in lakh, \(1{,}24{,}063.48\) L. With display units set to Millions on the original measure, the card would show "12,406.35M" — technically correct and practically useless. A Units slicer pattern:

Revenue Display = DIVIDE ( [Revenue], SELECTEDVALUE ( Units[Divisor], 1e7 ) )

-- Dynamic format string expression for [Revenue Display]
VAR lbl = SELECTEDVALUE ( Units[Label], "Cr" )
RETURN "#,##0.0 """ & lbl & """"

Practice Questions

Q1. Write the measures [L1]

Write crore measures for EBITDA, PAT, Cash and Net Debt, with format strings, and state which existing measures must not be converted.

Q2. Display units trap [L2]

A card bound to [Revenue ₹ Cr] shows "1.24K". Explain what setting causes this and how to make the card show "1,240.6" consistently with the matrix.

Q3. Calculation group vs measures [L3]

The CFO wants a single toggle that switches the entire pack (cards, matrix, waterfall labels, tooltips) between ₹ lakh and ₹ crore. Compare a calculation-group design with duplicate measures and with a units table plus dynamic format strings, including the effect on ratio measures and on Analyze in Excel.
