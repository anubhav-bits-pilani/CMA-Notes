Key concept

Excel Native Waterfall Chart with "Set as Total"

Concept: Excel: native Waterfall chart (Insert > Waterfall) with "Set as total" on subtotal points

Statement

Excel 2016 and later (Microsoft 365 included) provide a native Waterfall chart: select a two-column range (step label, value) and choose Insert > Charts > Insert Waterfall, Funnel, Stock, Surface or Radar Chart > Waterfall. Each value is plotted as a floating bar that starts where the previous cumulative total ended. Points that represent a total (start, subtotal, end) must be marked with right-click the point > Set as total (also under Format Data Point > Series Options). A total point is drawn from zero to its value, so its cell must hold the cumulative amount, not an increment.

For a bridge with start \(S\), drivers \(\Delta_1 \dots \Delta_n\) and a subtotal after driver \(k\):

\[ \text{Subtotal}_k = S + \sum_{i=1}^{k} \Delta_i, \qquad \text{End} = S + \sum_{i=1}^{n} \Delta_i \]

Explanation

Before 2016, Excel waterfalls were built with stacked columns and invisible "base" series — fragile with negative values crossing zero. The native chart handles positive and negative steps, colours Increase, Decrease and Total categories (format them by clicking the legend entry, then Fill), and supports data labels and connector lines (Show connector lines in Series Options).

Mechanics and limits that matter for a board pack:

  • Set as total is per point position. It is stored against the point index. If the source range later inserts a new step above a total, the "total" flag stays on the old position and the chart becomes wrong. Fix the step list (a fixed Schedule of steps) or re-check total flags after layout changes.
  • Cumulative cells for totals. A subtotal cell must be a formula such as =B5+SUM(B6:B8); if it holds an increment, the bar is drawn from zero at the wrong height.
  • Not available as a PivotChart. The newer chart types (waterfall, treemap, sunburst, histogram, box and whisker, funnel) cannot be based on a PivotTable. Feed them from normal cells — ideal for a cube-formula board pack (Topic 3), where CUBEVALUE cells supply the steps.
  • Responds to slicers indirectly: if the step values are CUBEVALUE formulas referencing a slicer, the chart updates when the FY slicer changes.
  • Sign convention. Cost overruns must be negative numbers in the source range; compute steps as sign-adjusted variances, as in the Power BI bridge.
  • Compatibility. Older Excel versions show the chart as an unsupported object; save the pack for Microsoft 365 users or export to PDF.

Illustration

Board-pack sheet, ₹ Cr, October 2025 YTD:

Row A (step) B (value) Set as total?
5 Budget EBITDA 122.6 Yes
6 Revenue −22.8 No
7 Material 16.1 No
8 Contribution vs budget (subtotal) =B5+SUM(B6:B7) → 115.9 Yes
9 Employee −1.4 No
10 Power & fuel −4.2 No
11 Other opex 2.9 No
12 Actual EBITDA =B8+SUM(B9:B11) → 113.2 Yes

A check cell =ROUND(B12 - EBITDA_Actual, 1) = 0 (where EBITDA_Actual is a named CUBEVALUE cell for Actual EBITDA) confirms the chart closes to the reported number.
