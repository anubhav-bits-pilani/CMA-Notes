Key concept

ISFILTERED and ISCROSSFILTERED for Context-Aware Labels

Concept: ISFILTERED(BU[BusinessUnit]) and ISCROSSFILTERED for context-aware labels and warnings

Statement

  • ISFILTERED(<column or table>) returns TRUE when the specified column (or any column of the specified table) is directly filtered in the current context — by a slicer, filter pane, cross-filter, or a row/column of the visual.
  • ISCROSSFILTERED(<column or table>) returns TRUE when the column or table is filtered directly or indirectly — including filters on other columns of the same table or filters propagated through relationships from other tables.

So ISFILTERED implies ISCROSSFILTERED, but not the reverse:

\[ \text{ISFILTERED}(c) \Rightarrow \text{ISCROSSFILTERED}(c) \]

BU Label =
IF ( ISFILTERED ( BU[BusinessUnit] ),
     "BU: " & CONCATENATEX ( VALUES ( BU[BusinessUnit] ), BU[BusinessUnit], ", " ),
     "All BUs" )

Explanation

Context-aware labels tell users what they are looking at and warn when the context makes a number misleading:

  • Labels. "All BUs" vs "BU: Agro" in titles and status strips.
  • Warnings. A card "⚠ Region filter active — totals exclude other regions" when ISFILTERED(Region[Region]).
  • Guarding measures. Budget may exist only at BU level, not by vendor. A budget measure can return BLANK when the vendor dimension is filtered, rather than repeating the BU total on every vendor row: IF(ISCROSSFILTERED(Vendor[Name]), BLANK(), [Budget]). ISCROSSFILTERED is appropriate here because a filter on Vendor[Category] also narrows vendors.
  • Voucher-table guard. On the GL Detail page, show the table only when the ledger is filtered: IF(ISFILTERED(CoA[Ledger]), 1, 0) as a visual filter.

Differences that cause bugs:

  • A filter on BU[Region] makes ISFILTERED(BU[BusinessUnit]) FALSE but ISCROSSFILTERED(BU[BusinessUnit]) TRUE.
  • A filter on GL (fact) does not cross-filter BU unless the relationship is bidirectional; dimension columns are filtered by the fact only through bidirectional or CROSSFILTER logic.
  • ISFILTERED returns TRUE even if the filter selects all values explicitly (e.g. a filter card with everything ticked may or may not be treated as a filter, depending on whether "Select all" was used) — prefer comparing counts if the distinction matters: COUNTROWS(VALUES(BU[BusinessUnit])) < COUNTROWS(ALL(BU[BusinessUnit])).
  • Use ISINSCOPE (not ISFILTERED) to detect the level of a hierarchy in a matrix: a matrix row on BU makes the column filtered in that row, but ISINSCOPE distinguishes the row's grouping level from slicer filters.

Illustration

Model: BU (BusinessUnit, Region attribute), Vendor (Name, Category), GL. Context: Region slicer = West, no BU slicer, matrix rows by Vendor Category.

Expression Result Reason
ISFILTERED(BU[BusinessUnit]) FALSE Only BU[Region] filtered directly
ISCROSSFILTERED(BU[BusinessUnit]) TRUE Region filter on the same table
ISFILTERED(Vendor[Name]) FALSE Rows are on Category
ISCROSSFILTERED(Vendor[Name]) TRUE Category row filters vendors
[BU Label] "All BUs" Misleading — should mention West

Improved label: IF(ISCROSSFILTERED(BU), "BUs in view: " & CONCATENATEX(VALUES(BU[BusinessUnit]), ...), "All BUs").

Practice Questions

Q1. Predict the result [L1]

With a slicer on Region[Region] (a separate dimension related to GL) set to South, and no other filters, state the result of ISFILTERED(BU[BusinessUnit]) and ISCROSSFILTERED(BU[BusinessUnit]) with single-direction relationships, and explain.

Q2. Budget by vendor [L2]

Budget is held by BU and FSLine only. Write a budget measure that shows budget at BU/FSLine levels but BLANK whenever any vendor attribute is filtered or grouped, and a variance measure that respects it.

💡 Hint: Decide whether direct or indirect filtering should trigger the blank.

Q3. Warning strip [L2]

Write a status-strip measure that lists every active filter among FY, BU, Region and Cost Centre, e.g. "Filters: FY 2025-26 · BU: Agro · Region: West", omitting dimensions not filtered.
