Key concept

Field Parameter Tables Built with NAMEOF

Concept: Field parameters (Modeling > New parameter > Fields) generate a table of NAMEOF('Date'[FY])-style entries

Statement

Modeling > New parameter > Fields creates a calculated table defined by a table constructor of tuples:

Period By = {
    ( "Fiscal year",    NAMEOF ( 'Date'[FY] ),            0 ),
    ( "Fiscal quarter", NAMEOF ( 'Date'[FiscalQuarter] ), 1 ),
    ( "Month",          NAMEOF ( 'Date'[MonthName] ),     2 )
}

Each tuple is (display name, field reference, order). NAMEOF(<column or measure>) returns the fully qualified name of the object as text — e.g. "'Date'[FY]" — and, unlike a typed string, keeps tracking the object if it is renamed. The table gets three columns (here Period By, Period By Fields, Period By Order); the Fields column carries extended-property metadata (ParameterMetadata) that tells visuals to substitute the referenced field.

Explanation

The visible column (Period By) is used in slicers; the Fields column is what you place in a visual's axis, rows or values. When the user selects "Month", the visual behaves as if 'Date'[MonthName] were in the well, including its sort-by-column setting (FiscalMonthNo) and formatting.

Points to note:

  • Columns or measures, not mixed in one visual well. A parameter can mix columns and measures technically, but a dimension parameter should list columns and a measure parameter measures.
  • Editing. The DAX is editable: rename display text, add rows (NAMEOF([Revenue PY])), change order values. A typed text string instead of NAMEOF (e.g. "'Date'[FY]") works until something is renamed — always use NAMEOF.
  • Grouping. Add a fourth column (e.g. "Group") to build a hierarchy slicer of options.
  • Metadata. If you create a similar table manually without using the dialog, the parameter metadata is missing and visuals will not swap fields; create via the dialog, then edit the expression.
  • Selections. SELECTEDVALUE('Period By'[Period By]) returns the chosen display name for titles; with multiple selections in a matrix, rows nest in Order sequence.
  • Limitations. Field parameters are not supported for every feature (e.g. some AI visuals, Analyze in Excel usage) and implicit measures behave differently; test the target visuals.

Illustration

Page 1 trend chart with Period By on the x-axis and [Revenue ₹ Cr] on values:

Slicer choice Axis becomes Points shown (FY2025-26 selected)
Fiscal year 'Date'[FY] 1 (₹1,240.6 Cr)
Fiscal quarter 'Date'[FiscalQuarter] 4 (Q1 ₹294.7, Q2 ₹301.2, …)
Month 'Date'[MonthName] 12, sorted April → March

Adding ( "Week", NAMEOF('Date'[FiscalWeek]), 3 ) later extends the choice without touching the visual.

Practice Questions

Q1. Write the measure parameter [L1]

Write a field parameter table "KPI Choice" listing [Revenue ₹ Cr], [EBITDA ₹ Cr], [EBITDA %] and [PAT ₹ Cr] with sensible display names and order.

Q2. Rename robustness [L2]

A colleague hand-edited a parameter to use the string "'Date'[Fiscal Year]" instead of NAMEOF. After the column is renamed to FY, the visual errors. Explain why NAMEOF would have avoided this and what the error tells you.

Q3. Manually built table [L2]

Another analyst built Period By with DATATABLE containing the same three rows and columns, but the chart axis does not change when the slicer selection changes. Explain the cause and the fix.

💡 Hint: The dialog adds something the table expression alone does not.
