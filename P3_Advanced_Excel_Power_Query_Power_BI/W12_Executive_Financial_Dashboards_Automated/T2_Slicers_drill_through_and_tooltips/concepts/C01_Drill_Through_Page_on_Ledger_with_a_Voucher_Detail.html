Key concept

Drill-Through Page on Ledger with a Voucher Detail Table

Concept: Drill-through page: CoA[Ledger] in the Drill through well; a table of GL[VoucherNo], GL[Date], GL[Narration], GL[Amount]

Statement

A voucher-detail drill-through page consists of:

  • Drill through well: CoA[Ledger] (a dimension column), with Keep all filters on.
  • Detail table: columns GL[VoucherNo], GL[Date], GL[Narration], GL[Amount] (optionally GL[VoucherType], Vendor[Name], CostCentre[Name], GL[Debit], GL[Credit]), sorted by date.
  • Header: cards for the ledger name, the period and the total, where

\[ \text{Detail total} = \sum_{v \in V} \text{Amount}_v = \text{value clicked in the source visual} \]

with \(V\) the set of GL lines satisfying the drill-through ledger and all carried filters (FY, month, BU, region).

Explanation

The ledger is the natural drill key: it is the lowest level of the CoA hierarchy that users see in the P&L matrix, and it is a column on the dimension, so every visual that shows ledgers (matrix rows, bar axes, decomposition tree) offers the drill. Using GL[LedgerName] from the fact instead would break the link with visuals built on CoA[Ledger].

The detail table shows raw fact columns. To keep it auditable:

  • Set GL[VoucherNo] and GL[Narration] to Don't summarize behaviour (text columns are not summed anyway), and GL[Amount] as Sum so lines with the same voucher, date and narration combine; include a line ID if every line must be visible.
  • Add a measure-based total in the header ([Actual] or [Actual Signed]) and compare it with the source.
  • Show amount in rupees with two decimals (vouchers are evidence, not presentation).
  • Turn on word wrap for narrations; Tally/SAP narrations can be long.
  • Guard against unfiltered rendering: a visual-level filter "[Actual] is not blank" and a check that a single ledger is in context; e.g. a card IF(HASONEVALUE(CoA[Ledger]), "", "Select a single ledger").
  • Consider adding a URL column to the ERP document (Tally, SAP Fiori) formatted as a web URL so reviewers can open the source voucher.

Dates: GL[Date] should be the posting date that the Date table relationship uses; showing the document date alongside helps cut-off review (Week 11 role-playing dates).

Drill from "Repairs – Plant & machinery", Agro BU, October FY2025-26 (source cell ₹48,62,310):

The header total equals the source cell, and the largest item (shutdown maintenance) explains the variance.

Q1. Build the page [L1]

List the fields, formatting and filters you would put on a GL Detail page for CoA[Ledger], including the guard against rendering all vouchers.

Q2. Lines collapse [L2]

A voucher with three lines to the same ledger (₹1,00,000; ₹1,00,000; ₹50,000, identical date and narration) shows as one row of ₹2,50,000. Explain why and how to show each line.

💡 Hint: Table visuals group by all non-summarised columns.

Q3. Wrong key column [L2]

The GL Detail page uses GL[LedgerName] in the Drill through well. Explain which source visuals will and will not offer the drill, and why switching to CoA[Ledger] is better.
