Subtopic note

Edit Interactions: Filter vs Highlight vs None

Scope: Edit interactions per visual: filter vs highlight vs none

Why it matters

In Power BI, clicking a data point in one visual cross-filters or cross-highlights every other visual on the page. That is powerful for exploration — click "Pharma" on a BU bar and the whole page re-scopes — but on an executive page it can also destroy context: clicking a waterfall bar should not blank the KPI cards, and clicking a month in the trend chart should probably not change the rolling 12-month line. Edit interactions is the control that decides, for every pair of visuals, whether a selection filters, highlights or does nothing. Getting it right is part of making the pack behave predictably for a CFO.

Core notes

The three interaction types

Select the source visual, then Format > Edit interactions (the ribbon button shows small icons on every other visual on the page). For each target visual choose:

Icon Interaction Effect on target Typical finance use
Filter (funnel) Cross-filter Target recalculates for the selected item only Click BU in a bar chart → P&L matrix shows that BU
Highlight (chart) Cross-highlight Target keeps totals but highlights the selected portion; the rest is dimmed Click a BU → stacked column trend shows BU share of each month
None (circle-slash) No interaction Target ignores the selection KPI cards should keep company totals when a detail visual is clicked

Highlight is available only on visuals that can show a part-of-whole (column, bar, pie); cards, tables and matrices offer Filter or None. Slicers are sources too: each slicer can be set to filter or not filter each visual — this is how one visual can ignore the FY slicer.

Default behaviour and report-level setting

By default, most visuals cross-highlight. File > Options and settings > Options > Current file > Report settings > "Change default visual interaction from cross highlighting to cross filtering" switches the default to filter for the whole report. For finance packs, cross-filter is usually more intuitive, because highlighted partial bars with measures like variance or margin can be misleading (a highlighted portion of a margin bar is meaningless).

Designing interactions for the executive page

A sensible pattern for Page 1:

Source → Target KPI cards Trend combo R12M line P&L matrix EBITDA waterfall
FY/BU/Region slicers Filter Filter Filter (BU/Region only) Filter Filter
Trend combo (click a month) None — None Filter Filter
P&L matrix (click a line) None Filter Filter — None
Waterfall (click a step) None None None None —

The logic: headline cards show the slicer scope and should not flicker when a user explores; clicking a month on the trend lets the matrix and bridge explain that month; clicking an FS line in the matrix shows that line's trend. The waterfall's own steps are categories from a disconnected table, so it cannot meaningfully filter other visuals — set None to avoid confusing blanks.

Interactions with disconnected tables and measures

Cross-filtering works through the model. If a visual is built on a disconnected table (bridge steps, field parameters, units), clicking it filters only that table; measures in target visuals change only if they read the selection with SELECTEDVALUE or TREATAS. This can be useful (clicking a step in a bridge could drive a detail table via a measure) but must be deliberate.

Interactions and drill

Visuals with drill-down enabled (matrix hierarchy, s03) have a further option under **Format > Edit interactions

Drilling filters other visuals**: when on, drilling into a level filters other visuals to that level's selection. On an expense page, drilling from BU to cost centre in a matrix can then filter the vendor Top N chart.

Ctrl+click and multi-select

Users can Ctrl+click several data points to filter on multiple items. Clearing selection is by clicking the same point again or an empty area. Novice users often leave a selection active and think numbers are wrong — a dynamic title or an ISFILTERED-based warning ("Filtered by: Pharma") helps (Concept c04).

Illustration

On the Sahyadri expense page, a bar chart "Opex by BU" filters the vendor Top N chart and the cost-centre matrix, highlights the monthly stacked column trend, and does nothing to the "Total opex vs budget" cards. A user clicks Performance Polymers: vendor ranks recompute within Polymers (because RANKX(ALLSELECTED(...)) respects the cross-filter), the trend shows Polymers' share of each month's opex, and the cards still show company opex of ₹261.6 Cr against budget ₹264.8 Cr.

Edge cases & judgement calls

  • Highlight with ratio measures. Highlighting a portion of an EBITDA % column shows a meaningless partial bar; use Filter.
  • Cards that must ignore a slicer. Setting a slicer → card interaction to None means the card ignores that slicer entirely; label it ("Company total, all BUs") to avoid misinterpretation.
  • Interactions do not carry across pages. Cross-filter selections are page-specific; to carry context, use synced slicers or drill-through.
  • Bookmarks capture the current selection state of visuals if "Data" and "Current page" are included; a bookmark may restore a cross-filter the user did not expect.
  • Performance. Each cross-filter click re-queries every target visual; on pages with heavy matrices, setting None on non-essential targets speeds up interaction.
  • Mobile layout inherits interactions; test that taps do not blank key cards.

Key takeaways

  • Edit interactions sets, per source-target pair, Filter, Highlight or None.
  • Switch the report default to cross-filtering for finance packs.
  • Headline KPI cards usually ignore visual clicks; detail visuals respond.
  • Disconnected-table visuals filter only through measures that read their selection.
  • Use titles or warnings so users see when a cross-filter is active.
