Field Parameters for User-Selected Dimensions and Measures

Scope: Field parameters for user-selected dimensions and measures

Why it matters

The Page 3 expense analysis needs to show spend by BU, by cost centre, by vendor or by region — and sometimes Actual, Budget, Variance or PY. Building one visual per combination bloats the page; bookmarks (s06) multiply maintenance. Field parameters let the user choose the dimension on the axis and the measure on the values of a single visual through a slicer. They are the standard modern technique for "analyse by …" selectors in finance dashboards.

Core notes

What a field parameter is

Modeling > New parameter > Fields opens a dialog where you pick fields (columns or measures) and order them. Power BI generates a calculated table using NAMEOF (Concept c03):

Expense By = {
    ( "Business Unit", NAMEOF ( BU[BusinessUnit] ), 0 ),
    ( "Cost Centre",   NAMEOF ( CostCentre[Name] ), 1 ),
    ( "Vendor",        NAMEOF ( Vendor[Name] ),     2 ),
    ( "Region",        NAMEOF ( Region[Region] ),   3 )
}

The table has three columns — display name, field reference, order — with special metadata that tells visuals to swap in the referenced field. Ticking "Add slicer to this page" creates a slicer on the display-name column.

Dimension parameters

Put the parameter's field column (shown as Expense By) on a visual's axis or rows. Selecting "Vendor" in the slicer makes the axis Vendor[Name]; selecting several values in a matrix's rows creates a dynamic hierarchy in the selected order. Uses:

  • Bar chart "Opex by [selected dimension]" with Top N (s08).
  • Matrix rows switching between CoA hierarchy levels.
  • Decomposition-tree-like exploration without the decomposition tree.

Measure parameters

A parameter of measures:

Expense Metric = {
    ( "Actual",       NAMEOF ( [Expense] ),            0 ),
    ( "Budget",       NAMEOF ( [Expense Budget] ),     1 ),
    ( "Var vs Budget", NAMEOF ( [Expense Var Fav/Adv] ), 2 ),
    ( "PY",           NAMEOF ( [Expense PY] ),         3 )
}

Put the parameter on the Values well; the visual shows whichever measures are selected (several selected = several series/columns). Each measure keeps its own format string, so ₹ crore and % measures display correctly.

Combining both

A single bar chart with Expense By on the axis and Expense Metric on values gives 4 × 4 = 16 views from one visual and two slicers. Pair with a dynamic title:

Expense Title =
"Expense " & SELECTEDVALUE ( 'Expense Metric'[Expense Metric], "Actual" )
    & " by " & SELECTEDVALUE ( 'Expense By'[Expense By], "Business Unit" )
    & " – " & [Selected FY]

Reading the selection in DAX

The display-name column can be read with SELECTEDVALUE. To branch logic on the selected field, use the order column or the hidden fields column:

Selected Dim No = SELECTEDVALUE ( 'Expense By'[Expense By Order] )

Field parameter tables cannot be referenced in calculated columns of other tables in a way that changes dynamically; logic stays in measures.

Editing parameters

The generated table is ordinary DAX; edit it in the formula bar to add fields, rename display names (e.g. "Vendor (top 20)"), or reorder. Add a grouping column (e.g. "Dimension" vs "Measure" type) if you want a hierarchy in the slicer. Renaming the underlying field breaks nothing because NAMEOF updates with renames.

Illustration

Page 3: slicer "Analyse by" (BU, Cost Centre, Vendor, Region), slicer "Show" (Actual, Budget, Var, PY). User picks Cost Centre + Var: the bar chart shows 38 cost centres' favourable/adverse variance, sorted ascending, with the [Var Colour] measure colouring bars (fx works because the measure is fixed for colour). Switching to Vendor shows the top 10 vendors (visual Top N filter on the parameter field by [Expense]).

Edge cases & judgement calls

  • Drill-through and field parameters. If the axis is the parameter field, the visual carries the underlying field (e.g. Vendor[Name]) only when that option is selected; a drill-through page expecting CoA[Ledger] becomes available only for the matching choice.
  • Conditional formatting applies to the field parameter values well as a whole in some versions; per-measure rules may not behave as expected — test.
  • Sorting. Sort settings persist per field; switching parameters can reset sort order. Use a sort measure if order matters.
  • Analyze in Excel. Field parameters do not translate to Excel PivotTables meaningfully; the Excel pack uses real fields.
  • RLS and parameters. Parameters do not bypass RLS; a BU head choosing "Business Unit" sees only their BU.
  • Too many choices. Six dimensions × six measures overwhelms users; offer the four that answer CFO questions.

Key takeaways

  • Field parameters generate a NAMEOF-based table that lets slicers swap fields in visuals.
  • Dimension parameters switch axes/rows; measure parameters switch values, keeping each measure's format.
  • Combine both with a dynamic title for a compact "analyse by" visual.
  • Read selections with SELECTEDVALUE or the order column; keep logic in measures.
  • Test drill-through, sorting and conditional formatting for every parameter option.

Practice Questions

Q1. Create a dimension parameter [L1]

Write the DAX table for a field parameter "Revenue By" with Business Unit, Region, Customer Segment and Product Group, and describe where you would place it.

Q2. Measure parameter with formats [L2]

A measure parameter includes [Expense] (₹ crore format), [Expense % of Revenue] (0.0%) and [Expense Var Fav/Adv] (₹ crore, signed). Explain how formats and the y-axis behave when a user selects all three on a clustered bar, and propose a better design.

💡 Hint: Consider what a shared axis does to values with different scales.

Q3. Drill-through by parameter [L2]

A bar chart uses Expense By on the axis. Users can drill through to GL Detail only when "Vendor" is selected. Explain why and propose how to make drill-through work for Cost Centre as well.

Q4. Replace bookmarks [L3]

Page 3 currently has eight bar charts hidden/shown by bookmarks (four dimensions × Actual/Var). Redesign with field parameters, listing the tables, slicers, visuals, titles and the tests you would run before releasing.
