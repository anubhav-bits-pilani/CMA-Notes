Drill-Through Setup: Fields, Keep All Filters, Cross-Report, Back Button

Scope: Drill-through setup: drill-through fields, Keep all filters, cross-report drill-through, back button

Why it matters

The checklist target for this week is "drill from an EBITDA variance line to voucher-level GL entries in under a minute". That only works if the drill-through page receives exactly the context of the number clicked — the same ledger, FY, month, BU and region — and if the user can get back. Most drill-through failures in finance packs are configuration errors: the wrong field in the drill-through well, Keep all filters switched off, or a field from a fact table that the source visual does not use. This note is the configuration checklist.

Core notes

Creating the target page

  1. Add a new page, name it "GL Detail" and hide it (right-click the tab > Hide page) — users reach it only by drilling.
  2. With no visual selected, in the Visualizations pane find the Drill through section (page-level settings).
  3. Drag the drill-through fields into Add drill-through fields here — typically CoA[Ledger], optionally CoA[FSLine], CostCentre[Name] and Vendor[Name]. Use dimension columns, the same columns the source visuals use.
  4. Power BI automatically adds a back button (an arrow image with action Back). Keep it top-left and style it consistently.
  5. Build the detail visuals: header cards (ledger, period, total) and a voucher table (Concept c01).

Drill-through fields: matching rules

  • A source visual offers Drill through > GL Detail on right-click only if it contains at least one of the target's drill-through fields (as a category, such as rows of a matrix or axis of a bar).
  • The match is by table and column, not by name shown. If the source uses GL[LedgerName] and the target expects CoA[Ledger], there is no option.
  • With several drill-through fields, the target receives the values of whichever fields the source has; others are not filtered by the drill (but may be filtered by Keep all filters).
  • Drill through when: Used as category / Summarized. For a field in the well, the option controls whether drilling is offered when the field is a category (normal) or when it appears summarised (e.g. a count) in the source. Measures cannot be drill-through fields.

Keep all filters

The Keep all filters toggle (on by default in current versions, but verify) decides what else travels:

Keep all filters What the target receives
On Drill-through field values plus every filter affecting the source visual: slicers, page and visual filters, cross-filters from other visuals, and the source visual's other row/column members
Off Only the drill-through field values (report-level filters still apply because they apply to all pages)

For voucher detail, On is essential: right-clicking "Power and fuel" in the October column of a matrix filtered to Polymers must show October Polymers vouchers, not all-time vouchers for all BUs. With it Off, the detail total will not tie to the clicked cell — the classic symptom of lost context. Synced slicers (s01) are a partial mitigation but do not carry cross-filters or the matrix column (month) context.

Cross-report drill-through

Large finance estates split content: an executive pack report and a separate "GL Explorer" report sharing the same semantic model. Cross-report drill-through lets the executive pack jump to a page in another report:

  • In the target report's drill-through page, switch Cross-report on.
  • In the source report, enable File > Options and settings > Options > Current file > Report settings > Allow visuals in this report to use drill-through targets from other reports.
  • Publish both to the same workspace (or include both in the same App); cross-report targets are resolved in the Service, not in Desktop.
  • Fields are matched by table and column name, so both reports should use the same semantic model (or models with identical names).

Use it to keep the executive pack light while still offering voucher-level evidence from a heavier detail report.

Back button and drill-through buttons

  • The auto back button uses action type Back, returning to the page the user came from. In Desktop, button actions need Ctrl+click; in the Service a single click.
  • A drill-through button (Insert > Buttons > Blank, Action type = Drill through, Destination = GL Detail) becomes enabled when the user selects a data point that contains the drill-through field. Set disabled-state tooltip text such as "Select a ledger to view vouchers", and a dynamic button label via fx, e.g. "View vouchers for " & SELECTEDVALUE(CoA[Ledger], "selected ledger").
  • The destination can itself be dynamic (fx with a measure returning a page name) to route to different detail pages.

Illustration

Source: Page 3 matrix, rows CoA[FSLine] → CoA[Ledger], columns 'Date'[MonthName], filtered by slicers FY2025-26, BU = Performance Polymers, Region = West. Target: GL Detail with drill-through fields CoA[FSLine], CoA[Ledger], Keep all filters On. User right-clicks the October cell for "Power and fuel" (₹2.31 Cr) → GL Detail shows 7 vouchers totalling ₹2.31 Cr with header "Power and fuel · Oct FY2025-26 · Polymers · West". Back button returns to Page 3 with drill state preserved.

Edge cases & judgement calls

  • Drill-through from a measure-only card is not possible; the card contains no category field.
  • Disconnected-table visuals (bridge steps, field parameters) do not carry dimension fields; drill-through from a waterfall needs the step mapped to a CoA field, or a separate visual.
  • Field parameters on the source can carry the underlying field if selected; test drill-through with each parameter choice.
  • Hidden drill-through fields filters appear in the target's filter pane; users can clear them and see all vouchers — lock or hide the filter card if that is undesirable.
  • RLS applies on the target page too; a BU head drilling sees only their vouchers, which is correct.
  • Mobile supports drill-through, but tables with many columns are hard to read; keep the detail page narrow.

Key takeaways

  • Drill-through fields must be the same dimension columns that source visuals use.
  • Keep all filters On is required for detail totals to tie to the clicked number.
  • Cross-report drill-through needs the target toggle, the source report setting and same-workspace publishing.
  • An automatic back button is added; drill-through buttons improve discoverability.
  • Always validate that the target page header total equals the source value.

Practice Questions

Q1. Configuration checklist [L1]

List, in order, every setting required to create a hidden GL Detail drill-through page reachable from any ledger row in the pack, including the back button and Keep all filters.

Q2. Detail does not tie [L2]

The source cell shows ₹2.31 Cr (October, Polymers, West), but the GL Detail page shows ₹31.5 Cr for Power and fuel. Keep all filters is Off and slicers are synced on all pages. Explain which context was lost and why synced slicers did not fully help.

💡 Hint: Which part of the source context came from the matrix column rather than a slicer?

Q3. Cross-report set-up [L2]

The executive pack and a GL Explorer report are in different workspaces and the drill-through option does not appear in the Service. List all the conditions that must hold and the changes needed.

Q4. Drill-through button UX [L3]

Design a "View vouchers" button for the Page 3 expense matrix: action, destination, enabled/disabled behaviour, dynamic label and tooltip, and how you would explain its use in the CFO user guide in three sentences.
