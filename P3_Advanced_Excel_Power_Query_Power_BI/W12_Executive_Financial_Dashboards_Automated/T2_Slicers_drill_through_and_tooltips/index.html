Roadmap topic: Interactive Slicers, Drill-Through & Tooltips: Filtering by Fiscal Year, Business Unit, Region, and drilling down from P&L line item to voucher-level GL detail

Overview

Topic 1 decided what the executive pages show; this topic decides how users move through them. A CFO pack is interactive in three ways: it is scoped (by FY, Business Unit and Region slicers that stay in sync across pages), it is explorable (clicking a visual filters others, hovering reveals detail, toggles switch views), and it is provable (any P&L line can be drilled down to ledger and drilled through to the vouchers behind it). The last property is what separates a finance dashboard from a marketing dashboard: an auditor, a CFO or an interviewer can ask "show me the entries", and the pack answers in under a minute.

The learning sequence starts with scope: slicers for FY, BU and Region, including hierarchy and relative date slicers and Sync slicers (s01), and edit interactions that decide which visuals respond to clicks (s02). Then the drill path: the difference between drill-down in a matrix hierarchy and drill-through to a voucher page (s03), and the exact drill-through configuration — fields, Keep all filters, cross-report targets and back buttons (s04). Next come lightweight context tools: report page tooltips (s05), bookmarks, buttons and the selection pane for view toggles (s06), and field parameters for user-chosen dimensions and measures (s07). Finally, the structural filters in the Filters pane and Top N filtering (s08).

The key concepts are the DAX and configuration patterns that make these features robust: the voucher-detail drill-through page (c01), the Selected FY measure for dynamic titles (c02), NAMEOF-based field parameter tables (c03), ISFILTERED/ISCROSSFILTERED for context-aware labels and warnings (c04), and RANKX over ALLSELECTED for slicer-responsive Top N (c05). All of them depend on the Week 11 star schema: slicers and drill fields must come from dimension tables so that every fact — Actual, Budget, TB — responds consistently.

Related concepts to study

Forensic drill-down to anomalous vouchers (Weeks 5–8)

→ Week 5–8: forensic drill-down to anomalous vouchers

Weeks 5–8 covered red flags: round-sum entries, postings on holidays or late at night, manual JVs to revenue near period-end, duplicate vendor invoices, and Benford's-law digit tests. The drill-through page built here is the delivery mechanism for those tests: add calculated columns or measures (weekday, hour, round-amount flag, manual voucher flag) to the GL table and let reviewers filter the detail page by them after drilling from a P&L line. A forensic "exceptions" page can be a second drill-through target from the same ledger key, so the CFO pack and the internal-audit view share one model and one evidence trail.

Row-level security with USERPRINCIPALNAME()

Row-level security with USERPRINCIPALNAME() for BU-wise access

Static roles hard-code a filter (BU[BusinessUnit] = "Agro"); dynamic RLS uses a security table mapping user e-mail to BU and a role filter such as BU[BusinessUnit] IN CALCULATETABLE(VALUES(UserBU[BusinessUnit]), UserBU[Email] = USERPRINCIPALNAME()). Roles are defined in Desktop (Modeling > Manage roles), tested with View as, and members are assigned in the Service on the semantic model. RLS interacts with this topic: slicers show only permitted BUs, drill-through shows only permitted vouchers, and Top N ranks only within visible data. RLS applies to Viewer-role users; workspace Admins, Members and Contributors bypass it.

Decomposition tree and Key Influencers

Decomposition tree and Key Influencers for root-cause analysis of expenses

The Decomposition tree visual takes a measure (Expense or Expense variance) and a list of "Explain by" dimensions (BU, cost centre, vendor, ledger, month); users expand nodes in any order, or use AI splits (High value/Low value) to find the dimension with the largest contribution. It is ideal for Page 3 ad hoc root cause ("why is opex over budget?"). Key Influencers uses statistical analysis to rank factors associated with a metric increasing or a category occurring (e.g. "what influences an invoice being paid late?"). Both are AI visuals with limitations (no drill-through from some nodes, field-parameter restrictions); treat their output as leads to verify, not conclusions.

Excel equivalents: slicers, timelines and Report Connections

Excel equivalents: slicers and timelines connected to several PivotTables via Report Connections

In Excel, a slicer can control several PivotTables that share the same source (the same Data Model or pivot cache) through Slicer > Report Connections (or PivotTable Analyze > Filter Connections). A timeline (Insert > Timeline) is a date-specific slicer for days, months, quarters and years — but it uses calendar quarters and years, so fiscal-year selection needs an FY slicer on the Date table instead. Connected slicers also drive cube formulas by name (Topic 3). This is the Excel analogue of Sync slicers, and the board pack uses it so one FY slicer moves the whole workbook.

Common pitfalls

Slicing on a fact column

Slicing on a fact column instead of a dimension column, so other facts (Budget) are not filtered

The builder drags GL[BU] into a slicer because it is visible in the GL table. That filter applies to GL only; Budget and TB are not filtered, so variances compare Pharma actuals with company budget. People do it when fact foreign keys or attribute columns are not hidden. Correct treatment: hide fact columns used as keys (Week 11), slice only on BU[BusinessUnit], 'Date'[FY], Region[Region]. Detection: select one BU and check that Budget changes; scan slicers and filters for any field from a fact table.

Drill-through loses context

Drill-through loses context because Keep all filters is off or the field differs from the source visual

Symptoms: the GL Detail total does not equal the clicked cell, or the drill option does not appear at all. Causes: Keep all filters off (month and cross-filter context lost), or the source uses GL[LedgerName] while the target expects CoA[Ledger]. Correct treatment: dimension-column drill fields matching source visuals, Keep all filters on, header total for tie-out (s04, c01). Detection: a test script of five drills from different visuals comparing source and target totals.

Unfiltered voucher-detail tables

Unfiltered voucher-detail tables with millions of rows that render slowly

A detail page opened directly (or via a bookmark, or after a user clears the drill filter) tries to render every GL line for all years — several million rows — and times out or uses huge memory. It happens because the page is tested only via drill-through. Correct treatment: hide the page, add a visual-level guard (ISFILTERED(CoA[Ledger]) = 1 or row count below a threshold), show a "Select a ledger" message otherwise, and limit columns. Detection: open the page directly and run Performance Analyzer; check DAX query rows returned.

Slicers not synced

Slicers not synced, so each page shows a different FY

Slicers are copied page to page without choosing "Sync", or new pages are added later without updating the Sync pane. Users change FY on Page 1 and Page 2 still shows last year — the most damaging failure because numbers look plausible. Correct treatment: one sync group per slicer (FY, BU, Region), synced on every relevant page, visible where useful; dynamic titles showing the FY on every page. Detection: change each slicer on Page 1 and visit every page, including hidden ones, checking the titles.

Practice Questions

Q1. Design the interaction model for Project 3 [L3]

Pages: Overview, Balance Sheet, Expenses, GL Detail (drill-through), TT Vendor (tooltip), Controls. (a) Specify the FY, BU and Region slicers (type, selection mode, default) and the Sync pane settings. (b) Specify edit interactions on the Overview page for five KPI cards, the trend combo, the P&L matrix and the EBITDA waterfall. (c) Configure the GL Detail page (drill fields, Keep all filters, back button, guards) and describe the test that proves a drill from the October "Power and fuel" cell for Polymers (₹2.31 Cr) ties.

Q2. Expense page with parameters and Top N [L3]

Page 3 must let users choose "Analyse by" (BU, Cost Centre, Vendor, Region) and "Show" (Actual, Budget, Var, PY), display the top N items (N from 5 to 25) plus "All others", and drill through to vouchers. Write the field parameter tables, the rank and filter measures, the dynamic title, and explain which combinations allow drill-through and why.

💡 Hint: Drill-through depends on which underlying field the parameter currently places on the axis.

Q3. View toggles without losing scope [L2]

The CFO wants the P&L matrix to toggle between ₹ crore and % of revenue, and a "Reset" button that restores Current FY, all BUs and all regions. Specify the selection-pane groups, bookmarks (with Data/Display/Selected visuals settings), buttons, and the test that proves the ₹/% toggle does not change the FY.

Q4. Security and labels [L3]

BU heads must see only their BU; the CFO sees all. (a) Design the dynamic RLS table and role. (b) Write a status measure that shows "Viewing: Agro (restricted)" for a BU head and "Viewing: All BUs" for the CFO with no slicer filter, and explain why ISFILTERED/ISCROSSFILTERED alone cannot detect the RLS restriction. (c) Explain how RLS affects the vendor rank, the drill-through page and the Excel pack connected via Analyze in Excel.
