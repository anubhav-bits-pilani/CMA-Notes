Key concept

Unmapped Count with EXCEPT over GL and CoA Account Codes

Concept: Unmapped Count = COUNTROWS(EXCEPT(VALUES(GL[AccountCode]), VALUES(CoA[AccountCode])))

Statement

Unmapped Count =
COUNTROWS ( EXCEPT ( VALUES ( GL[AccountCode] ), VALUES ( CoA[AccountCode] ) ) )
  • VALUES(GL[AccountCode]) — the distinct account codes present in the GL rows visible in the current filter context.
  • VALUES(CoA[AccountCode]) — the distinct codes in the mapping (CoA) dimension visible in the current context.
  • EXCEPT(T1, T2) — rows of T1 that do not appear in T2 (set difference, matched on all columns; column names need not match, types must be compatible).
  • COUNTROWS — the number of unmapped codes. Target value: 0.

In set notation:

\[ \text{Unmapped Count} = \left\lvert \, G \setminus C \, \right\rvert \]

where \(G\) is the set of GL account codes and \(C\) the set of CoA account codes in context.

Explanation

A GL code with no CoA row cannot carry an FS line, statement or sign, so its amount drops out of every P&L and BS measure that filters on CoA attributes. The TB still balances, so this is a completeness failure that s01 controls miss.

Behaviour worth knowing:

  • Blank row. When GL contains codes with no match, Power BI adds a blank member to CoA. VALUES(CoA[AccountCode]) then includes BLANK, but the unmapped codes themselves are not in CoA, so EXCEPT still returns them. (A GL row with a genuinely blank code is a separate data-quality issue — count it with COUNTROWS(FILTER(GL, ISBLANK(GL[AccountCode]))).)
  • Filter context. Under an FS-line slicer, CoA is filtered, the blank member disappears, and GL rows of unmapped codes are filtered out too — the measure returns 0 even when ledgers are unmapped. Evaluate it with CALCULATE([Unmapped Count], REMOVEFILTERS(CoA)). Keep Date and Company filters if you want "unmapped codes with postings this month".
  • Key hygiene. Matching is exact; trailing spaces, leading zeros and text-vs-number types create false unmapped codes. Clean keys in Power Query before loading. Note DAX comparisons of text are case-insensitive, so "gst01" and "GST01" match in EXCEPT, but the relationship engine also treats them as the same key — which can cause duplicate-key errors on the CoA side.
  • Materiality companion. Count tells you how many; pair it with an absolute-amount measure (s03) to tell you how much.
  • Listing the codes. For the reviewer, a table visual of GL[AccountCode] with a visual-level filter "CoA[FSLine] is blank" lists them; or build an anti-join query in Power Query.

Illustration

CoA mapping holds 812 codes. The FY2025-26 GL has 806 distinct codes, of which three are new: 41057 (Sales – Quick commerce, Cr ₹2.40 crore), 62310 (Platform fees, Dr ₹56 lakh) and 62311 (Platform fees – GST RCM, Dr ₹10 lakh).

  • Unmapped Count = 3.
  • Signed unmapped amount = −2.40 + 0.56 + 0.10 = −₹1.74 crore; absolute = ₹3.06 crore.
  • Revenue on the P&L page is understated by ₹2.40 crore and Other expenses by ₹66 lakh.
  • If the YTD profit plug in equity is computed from mapped P&L ledgers only, equity is understated by the net ₹1.74 crore credit and the BS Check shows +₹1.74 crore. If instead the plug is "every code not mapped to the BS", the BS Check passes and only Unmapped Count reveals the problem — a reason to keep both controls.

Connections

  • s03 (completeness checks) places this among file and month completeness tests; s05 shows it as control C06.
  • c02 — a non-zero BS Check is often explained by the same unmapped codes.
  • Week 10 pipeline exception outputs (left anti-join of GL to CoA) produce the same list at load time.

Practice Questions

Q1. Why the measure shows zero [L1]

A user adds [Unmapped Count] to the P&L page, which has an FS Line slicer set to "Revenue from operations", and sees 0, while the control page shows 4. Explain the result and correct the measure.

Q2. False unmapped codes [L2]

After a new Tally export, Unmapped Count jumps from 0 to 312 while total GL amounts are unchanged. Give the two most likely data-type or formatting causes and the Power Query steps that would fix them.

💡 Hint: Compare a few GL and CoA codes character by character, including their data types.

Q3. Unmapped listing [L2]

Write a DAX table expression (for DAX query view) that returns each unmapped account code with its absolute FY2025-26 balance, sorted by that balance in descending order.
