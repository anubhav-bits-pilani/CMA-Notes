Key concept

Dr Cr Diff and Dr Cr Status Control Measures

Concept: Dr Cr Diff = SUM(GL[Debit]) - SUM(GL[Credit]); Dr Cr Status = IF(ABS([Dr Cr Diff]) < 1, "PASS", "FAIL")

Statement

Dr Cr Diff   = SUM ( GL[Debit] ) - SUM ( GL[Credit] )
Dr Cr Status = IF ( ABS ( [Dr Cr Diff] ) < 1, "PASS", "FAIL" )

In symbols, for any set \(V\) of complete vouchers:

\[ D = \sum_{i \in V} \text{Debit}_i - \sum_{i \in V} \text{Credit}_i, \qquad \text{Status} = \begin{cases} \text{PASS} & \text{if } \lvert D \rvert < \tau \\ \text{FAIL} & \text{otherwise} \end{cases} \]

where \(\text{Debit}_i\) and \(\text{Credit}_i\) are the debit and credit amounts on GL line \(i\) (one of them zero), and \(\tau\) is the tolerance, here ₹1.

Explanation

Double entry guarantees \(D = 0\) for every voucher, so it holds for any union of whole vouchers — a day, a month, a company. The measure is therefore a test of the load, not of the accounting: if it fails, rows were lost, duplicated on one side, mis-typed (a credit column read as text and nulled), or truncated mid-file.

Conditions for the test to be meaningful:

  • Remove line-level filters. Under a filter on account, FS line or cost centre, only some legs of each voucher remain and \(D \neq 0\) legitimately. Wrap it as CALCULATE([Dr Cr Diff], REMOVEFILTERS(CoA), REMOVEFILTERS(CostCentre)) for the control page.
  • Keep voucher-level filters such as Date, Company and Voucher Type, under which whole vouchers stay intact.
  • Tolerance. < 1 allows sub-rupee floating-point noise from CSV parsing and decimal-number columns, while any real error (smallest real voucher line is usually at least ₹1) fails. Typing amount columns as Fixed decimal (Currency.Type) in Power Query removes most noise; the tolerance then guards against residual rounding.
  • Blank behaviour. With no rows in context, both sums are blank and [Dr Cr Diff] is blank; ABS(BLANK()) is treated as 0, so Status shows PASS for a month with no data. Add an ISBLANK branch returning "NO DATA".
  • Signed single-column models. If the GL has only a signed Amount, the equivalent test is SUM(GL[Amount]) with account filters removed (concept of "TB nets to zero").

Illustration

March 2026 Tally Day Book export for a Coimbatore textile company, loaded from three files:

File Debit (₹) Credit (₹) Diff (₹)
CBE_2026-03_part1.csv 41,22,10,500.00 41,22,10,500.00 0.00
CBE_2026-03_part2.csv 38,04,66,250.00 37,96,16,250.00 8,50,000.00
CBE_2026-03_part3.csv 12,90,04,000.00 12,98,54,000.00 −8,50,000.00
March total 92,16,80,750.00 92,16,80,750.00 0.00

The month passes, yet two files fail individually — a voucher split across files (part 2 ends mid-voucher). That is harmless if both parts are always loaded together, but it shows why the per-file control in c06 complements the period-level measure.

Practice Questions

Q1. PASS with no data [L1]

For a month with no GL rows loaded, explain what [Dr Cr Status] returns and why, and rewrite it to return "NO DATA" in that case.

Q2. Counting failing months [L2]

Write a measure that returns the number of months in the selected FY for which the absolute Dr Cr Diff (account and cost-centre filters removed) is at least ₹1, and a second measure returning the largest absolute monthly difference.

💡 Hint: Iterate over VALUES('Date'[MonthKey]) inside the CALCULATE that removes the CoA and cost-centre filters.

Q3. Choosing the tolerance [L2]

A controller proposes a tolerance of ₹1,000 "because the CSV export sometimes shows small differences". The largest recurring difference seen is ₹0.03. Evaluate the proposal and recommend a tolerance and a data-type fix.
