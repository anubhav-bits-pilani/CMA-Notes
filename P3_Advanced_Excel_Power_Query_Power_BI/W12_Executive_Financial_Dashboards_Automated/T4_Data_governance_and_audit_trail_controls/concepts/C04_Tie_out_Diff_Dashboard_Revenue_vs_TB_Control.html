Key concept

Tie-out Diff: Dashboard Revenue vs TB Control Totals

Concept: Tie-out Diff = [Dashboard Revenue] - SUM(TB_Control[Revenue]) by FY and month, shown with icon formatting

Statement

Tie-out Diff = [Dashboard Revenue] - SUM ( TB_Control[Revenue] )

\[ \Delta_{m} = R^{\text{dash}}_{m} - R^{\text{ctrl}}_{m}, \qquad \text{for each FY and month } m \]

where \(R^{\text{dash}}_{m}\) is revenue as computed by the production measure used on the dashboard, and \(R^{\text{ctrl}}_{m}\) is revenue per the independent control total exported from the ERP for the same month. The status is PASS when \(\lvert \Delta_m \rvert < \text{₹}1\), FAIL otherwise, and NO CONTROL when \(R^{\text{ctrl}}_{m}\) is blank.

Explanation

TB_Control here is a wide table with one row per Company × Month and columns per control line (Revenue, PBT, …), loaded from ERP-generated reports (Tally P&L, SAP financial statement) placed by the accountant in a controls folder. It relates to the shared Date table (via a month-end date) and to Company, so the same FY and month slicers filter both sides of the comparison.

Points that make the measure reliable:

  • Same measure as the report. [Dashboard Revenue] should simply be [Revenue] — the exact measure on the executive P&L. Re-deriving revenue in the tie-out tests a copy.
  • By FY and month. Put 'Date'[FY] and 'Date'[Month] on matrix rows. Annual agreement can mask monthly offsetting errors (cut-off or voucher-date vs entry-date problems).
  • Blank control. If the control file is missing, SUM(TB_Control[Revenue]) is blank and the difference equals the dashboard revenue — a large FAIL, which is at least visible. But if dashboard revenue is also blank (new month, nothing loaded), the difference is blank and an ABS-based PASS would be false. Use explicit ISBLANK tests.
  • Sign normalisation. ERP reports show revenue positive; a signed GL stores it as credit (negative). Ensure [Revenue] already flips the sign, or the diff equals twice revenue.
  • Icon formatting. Create a status-code measure for the icons:

DAX Tie-out Icon Code = SWITCH ( TRUE (), ISBLANK ( SUM ( TB\_Control[Revenue] ) ), 0, ABS ( [Tie-out Diff] ) < 1, 1, -1 )

In the matrix, apply Conditional formatting > Icons to the Diff (or status) column with rules based on this field: 1 → green check, 0 → grey/amber circle, −1 → red cross. Icons placed left of the value keep the number visible. - Wide vs long control table. A wide table (one column per line) suits a few lines; for many lines a long table (ControlLine, Amount) with a SWITCH measure generalises better (see s02).

Illustration

A Mumbai FMCG company, FY2025-26 H1 (₹ crore):

Month Dashboard Revenue TB_Control Revenue Tie-out Diff Icon
Apr-25 312.45 312.45 0.00 green
May-25 298.10 298.10 0.00 green
Jun-25 305.72 306.02 −0.30 red
Jul-25 321.66 321.66 0.00 green
Aug-25 330.18 — blank control grey
Sep-25 344.90 344.90 0.00 green

June fails by ₹30 lakh: a sales-return ledger "Sales returns – Modern trade" was mapped to Other expenses rather than netted in Revenue from operations in the ERP report. The fix is the CoA mapping. August has no control file yet; the grey icon prompts the accountant to upload it.

Practice Questions

Q1. Building the icon rule [L1]

Write the DAX measure that returns 1, 0 or −1 for PASS, NO CONTROL and FAIL for the revenue tie-out, and describe the Icons conditional-formatting rules you would configure on the matrix.

Q2. A tie-out equal to twice revenue [L2]

For every month the Tie-out Diff is exactly −2 times the control revenue (e.g. −₹624.90 crore when control revenue is ₹312.45 crore). Identify the cause and give the corrected measure.

💡 Hint: Consider how credit balances are stored in a signed GL.

Q3. Extending to five lines [L2]

The CFO wants tie-outs for Revenue, Other income, Total expenses, PBT and Total assets. Compare extending the wide TB_Control table with switching to a long table, and write the measures for the approach you recommend.
