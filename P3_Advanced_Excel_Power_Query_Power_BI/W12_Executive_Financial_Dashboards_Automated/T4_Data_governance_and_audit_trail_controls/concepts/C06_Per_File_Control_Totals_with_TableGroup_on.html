Key concept

Per-File Control Totals with Table.Group on Source.Name

Concept: Per-file controls: Table.Group(t, {"Source.Name"}, {{"Rows", Table.RowCount, Int64.Type}, {"Dr", each List.Sum([Debit]), type number}})

Statement

let
    t = GL_Combined,   // folder-combined GL keeping the Source.Name column
    PerFile =
        Table.Group(
            t,
            {"Source.Name"},
            {
                {"Rows", Table.RowCount, Int64.Type},
                {"Dr",   each List.Sum([Debit]),  type number},
                {"Cr",   each List.Sum([Credit]), type number},
                {"MinDate", each List.Min([PostingDate]), type date},
                {"MaxDate", each List.Max([PostingDate]), type date}
            }
        ),
    WithDiff = Table.AddColumn(PerFile, "DrCrDiff", each [Dr] - [Cr], type number)
in
    WithDiff
  • Table.Group(table, keys, aggregations) groups rows by the key columns; each aggregation is {newColumnName, function, type}, where the function receives the sub-table of rows for that key.
  • Table.RowCount is passed as a function value (it already takes a table), hence no each.
  • each List.Sum([Debit]) — [Debit] here is the Debit column of the sub-table, i.e. a list, summed.
  • Source.Name is the file-name column added by the Combine Files (folder) pattern from Week 10.

Explanation

This query produces the evidence a reviewer needs: one row per source file with row count, debit and credit totals, the difference and the date range inside the file. It runs at load time, so it catches problems before DAX sees the data, and it can be loaded as its own table (File_Control) for the control page.

What each column tests:

  • Rows — empty files, truncated exports and duplicates (compare to expected or historical counts).
  • Dr, Cr, DrCrDiff — whether each file is internally balanced. A non-zero difference means truncation, a split voucher across files, or a parsing error (e.g. amounts with commas read as text and nulled).
  • MinDate / MaxDate — whether the file contains only its own month (a March file with April vouchers indicates a wrong export period, which will double count when the April file arrives).

Implementation notes:

  • Keep Source.Name. The default Combine Files step keeps it; do not remove it in a later step. If combining manually with Table.Combine, add the file name as a column first.
  • Nulls. List.Sum ignores nulls, so a Credit column wholly null (type failure) shows Cr = null rather than an error. Add a check column CrNullCount = List.Count(List.Select([Credit], each _ = null)) if the export leaves blanks instead of zeros.
  • Types. Set Debit and Credit to Currency.Type before grouping so totals are exact to the paisa.
  • Branch from file name. Parse branch and month from Source.Name (Text.BeforeDelimiter, Text.BetweenDelimiters) and join to the expected-files register to find missing files (s03).
  • Performance. Grouping a folder of CSVs reads every file again unless the query references the same staged query; place it after the combined-GL staging query and disable load of intermediate queries. Power BI may still evaluate the source twice; for very large folders, compute per-file totals in DAX instead (SUMMARIZECOLUMNS(GL[SourceFile], ...)) from a SourceFile column kept on the fact.
  • Folding. Folder and CSV sources do not fold, so this is computed in the mashup engine — acceptable for a few hundred files.

Illustration

March 2026 folder for a logistics company:

Source.Name Rows Dr (₹) Cr (₹) DrCrDiff MinDate MaxDate
MUM_2026-03.csv 22,410 64,18,22,000 64,18,22,000 0 01-Mar-26 31-Mar-26
DEL_2026-03.csv 18,905 51,77,40,500 51,77,40,500 0 01-Mar-26 02-Apr-26
CHN_2026-03.csv 0 null null null null null
NAG_2026-03.csv 7,312 9,84,10,000 9,62,35,000 21,75,000 01-Mar-26 19-Mar-26

Three exceptions: Delhi includes April vouchers (wrong export period); Chennai's file is empty; Nagpur's file stops on 19 March with an unbalanced last voucher — a truncated export. Group-level Dr = Cr would also fail here, but only the per-file view says which branch to call.

Connections

Practice Questions

Q1. Writing the grouping step [L1]

Write a Table.Group step that, for each Source.Name, returns the row count, total debits, total credits, the number of distinct voucher numbers, and the latest posting date, with appropriate types.

Q2. Parsing branch and month [L2]

File names follow the pattern GL_<Branch>_<YYYY>-<MM>.csv (for example GL_PUN_2026-03.csv). Write the M steps that add Branch and MonthKey columns to the per-file table and then flag any month for which a branch has more than one file.

💡 Hint: Use text functions to extract the parts, then a second Table.Group on Branch and MonthKey.

Q3. Interpreting the control [L2]

A per-file table shows a file with 15,200 rows, Dr = Cr, MinDate 01-Feb-2026 and MaxDate 28-Feb-2026, but the historical average for that branch is 15,000 rows and the file name says 2026-03. What has probably happened, which other controls would flag it, and what is the effect on the dashboard if it goes undetected?
