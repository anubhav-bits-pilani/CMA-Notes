Subtopic note

Control Measures: Dr = Cr, TB Nets to Zero, A = L + E

Scope: Control measures: Total Debits = Total Credits, TB nets to zero, Assets = Liabilities + Equity

Why it matters

A CFO dashboard is only as credible as the ledger beneath it. In an audit you would never sign off a trial balance that does not agree, yet many Power BI packs publish numbers without ever proving that the imported GL is arithmetically complete. Three accounting identities give you that proof cheaply and continuously:

  • every voucher (and therefore every period) has equal debits and credits;
  • the trial balance, stored with signed amounts, sums to zero;
  • the balance sheet built from that TB balances.

Building these as DAX measures turns a one-off month-end tick into a control that runs on every refresh. It also answers the interview question "how do you know the dashboard is right?" with something better than "I checked it once in Excel". Under the Companies Act IFC regime (s.134(5)(e), s.143(3)(i)) these are exactly the kind of automated, evidenced controls over financial reporting that auditors test, and they support the CFO certification under SEBI LODR Reg 17(8) and Reg 33 when the pack feeds results.

Core notes

Control 1 — Total Debits = Total Credits

Where the GL extract carries separate GL[Debit] and GL[Credit] columns (typical of Tally Day Book or SAP FBL3N exports), the base control is:

Total Debits  = SUM ( GL[Debit] )
Total Credits = SUM ( GL[Credit] )
Dr Cr Diff    = [Total Debits] - [Total Credits]
Dr Cr Status  = IF ( ABS ( [Dr Cr Diff] ) < 1, "PASS", "FAIL" )

The identity must hold at voucher level, so it also holds for any set of complete vouchers — a month, a branch, a company. It does not necessarily hold for a subset of lines inside a voucher: filter by cost centre or by FS line and the difference is legitimately non-zero (the other leg of a salary voucher sits in "Salaries payable", not in the cost centre). The control must therefore be evaluated with filters on accounts and cost centres removed:

Dr Cr Diff (Period) =
CALCULATE ( [Dr Cr Diff], REMOVEFILTERS ( CoA ), REMOVEFILTERS ( CostCentre ) )

Keep filters on Date, Company and (if every voucher is single-branch) Branch, because those are voucher-level attributes. If inter-branch vouchers exist, a branch-level Dr = Cr check will fail by design; either test at company level or verify that the inter-branch control account nets to zero across branches.

A voucher-level drill helps root-cause failures:

Unbalanced Vouchers =
COUNTROWS (
    FILTER (
        VALUES ( GL[VoucherNo] ),
        ABS ( CALCULATE ( [Dr Cr Diff] ) ) >= 1
    )
)

Control 2 — The TB nets to zero

When the model stores a single signed column (GL[Amount], Dr positive, Cr negative — the convention recommended in Week 11), the equivalent check is:

TB Net = CALCULATE ( SUM ( GL[Amount] ), REMOVEFILTERS ( CoA ) )
TB Status = IF ( ABS ( [TB Net] ) < 1, "PASS", "FAIL" )

Two different questions are answered depending on the date filter:

Test Date context What a non-zero result means
Period TB (movements) A single month Unbalanced vouchers posted in that month, or a sign flip in the load
Cumulative TB (closing) All dates up to month-end Opening balances missing or unbalanced, or a period dropped

The closing version uses the Week 11 pattern CALCULATE([TB Net], 'Date'[Date] <= MAX('Date'[Date])), or with a fully cumulative ledger, DATESBETWEEN('Date'[Date], BLANK(), MAX('Date'[Date])). Many failures are in opening balances: an FY2025-26 GL extract that starts on 1 April 2025 must be accompanied by an opening TB as at 31 March 2025 (loaded as a separate "OB" voucher type), otherwise balance-sheet ledgers have no history.

If the model keeps both Debit/Credit columns and a derived signed Amount, also add a consistency check SUM(GL[Amount]) - ([Total Debits] - [Total Credits]). A non-zero value reveals a Power Query transformation bug (for example, a Credit column imported as text in one file and coerced to null).

Control 3 — Assets = Liabilities + Equity

The balance-sheet identity tests the mapping as well as the data. Even with a perfectly balanced TB, the BS will not balance if a ledger is unmapped, mapped to a P&L line by mistake, or if current-year profit has not been carried into equity.

Total Assets      = CALCULATE ( [Closing Balance], CoA[Statement] = "BS", CoA[Side] = "Asset" )
Total Liabilities = - CALCULATE ( [Closing Balance], CoA[Statement] = "BS", CoA[Side] = "Liability" )
Total Equity      = - CALCULATE ( [Closing Balance], CoA[Statement] = "BS", CoA[Side] = "Equity" )
                    - [Profit for the Period YTD]
BS Check          = [Total Assets] - [Total Liabilities] - [Total Equity]

The critical line is the profit plug: during the year, P&L ledgers have not been closed to retained earnings, so equity in the TB is opening equity only. Schedule III presents "Other equity — Retained earnings" including the current-year profit, so the measure must add YTD profit (which is a credit balance, hence the minus on a signed model). After the year-end closing entry, profit is already in retained earnings and adding it again would double count; a robust design adds only P&L ledgers of the current FY and lets prior FY profits flow through the closing entry or a "brought-forward profit" calculation.

Illustration

A Pune-based NSE-listed auto-components company loads its March 2026 GL:

Measure Value (₹)
Total Debits (March) 4,82,15,63,210.40
Total Credits (March) 4,82,15,63,210.40
TB Net (cumulative to 31-Mar-26) 0.00
Total Assets 21,40,00,00,000 (₹2,140 crore)
Total Liabilities 12,15,00,00,000 (₹1,215 crore)
Total Equity incl. YTD profit of ₹165 crore 9,25,00,00,000 (₹925 crore)
BS Check 0

Suppose a new ledger "GST Input – RCM Kerala" (Dr balance ₹38 lakh) is not yet in the CoA. Dr = Cr still passes and the TB still nets to zero, but Total Assets excludes the ₹38 lakh, so BS Check shows −₹38,00,000. The three controls are complementary: the first two test the data, the third tests the data plus the mapping.

Presentation

Show each control as a row in a control table (Control, Value, Tolerance, Status) rather than three separate cards; this scales to the completeness and tie-out checks of later subtopics. Use a consistent sign: display differences as signed ₹ with two decimals so paise-level issues are visible.

Edge cases & judgement calls

  • Tolerance. Tally and SAP store amounts to two decimals, but CSV exports and Power Query type conversions can introduce floating-point noise (0.0000001). Use a tolerance of ₹1 for totals, or round in Power Query to 2 decimals using Currency.Type (fixed decimal) on amount columns. Never widen the tolerance to "make it pass".
  • Foreign-currency ledgers. If the GL holds both transaction and functional currency amounts, run the controls on the functional (INR) amount; transaction-currency amounts do not balance across currencies.
  • Multi-company consolidation. Dr = Cr must hold per company; intercompany eliminations are separate vouchers that should themselves balance. A consolidated BS check fails if elimination entries are loaded for only one side.
  • Blank or zero rows. Header rows and narration-only rows in Tally exports carry no amount; they do not affect sums but inflate row counts (relevant to completeness checks in s03).
  • Offsetting errors. A grand-total PASS can conceal a +₹5 lakh error in one month and −₹5 lakh in another. Always evaluate the control by month (and by company) and count failing periods, not only the total.
  • Performance. FILTER(VALUES(GL[VoucherNo])) over millions of vouchers is expensive; keep the voucher-level measure on the control page only, not on executive pages.

Key takeaways

  • Dr = Cr, TB = 0 and A = L + E are three distinct tests: data arithmetic, period completeness, and mapping integrity.
  • Evaluate Dr = Cr with account and cost-centre filters removed; it holds only for complete vouchers.
  • The BS check must include current-year profit in equity until the year-end close.
  • Run every control by period and entity, not only at grand total, to catch offsetting errors.
  • Use a small, explicit tolerance (₹1) and fixed-decimal types instead of loose thresholds.
  • Present controls in one table with value, tolerance and status so they scale.

Practice Questions

Q1. Why the cost-centre filter breaks Dr = Cr [L1]

A user places [Dr Cr Status] on a page filtered to cost centre "CC-210 Plant Maintenance" and sees FAIL with a difference of ₹12,40,500. The GL is known to be balanced. Explain why the measure fails in this context and rewrite the measure so it reports correctly regardless of cost-centre and FS-line slicers.

Q2. Locating an unbalanced month [L2]

A GL for FY2025-26 shows a full-year Dr Cr Diff of ₹0.00. Monthly differences are: April +₹3,20,000, May 0, June −₹3,20,000, all other months 0. List two plausible data-load causes for this pattern and write the DAX measure that counts the number of months in the selected FY with a non-zero difference.

💡 Hint: Think about vouchers dated at a month boundary and about iterating over months with a tolerance.

Q3. Building the BS check with in-year profit [L2]

At 30 September 2025 a company's signed TB (Dr positive) shows: asset ledgers ₹840 crore, liability ledgers −₹410 crore, equity ledgers (share capital and opening retained earnings) −₹350 crore, P&L ledgers −₹80 crore. Write measures for Total Assets, Total Liabilities, Total Equity and BS Check that return a zero BS Check, and state what the BS Check would show if the P&L adjustment were omitted.

Q4. Choosing which controls to build [L3]

A group with three companies uses Tally for two of them and SAP for the third. The SAP extract has a signed Amount column; Tally exports have separate Debit and Credit columns. Design the set of control measures (names, logic, the filters each must remove or retain) you would put on the control page, including how you would handle intercompany vouchers and opening balances.

Q5. Interview: what does a balanced TB not prove? [L1]

An interviewer says: "Your TB nets to zero every month, so your dashboard must be right." Give three distinct errors that would leave the TB balanced but make the dashboard wrong, and name the control that would detect each.
