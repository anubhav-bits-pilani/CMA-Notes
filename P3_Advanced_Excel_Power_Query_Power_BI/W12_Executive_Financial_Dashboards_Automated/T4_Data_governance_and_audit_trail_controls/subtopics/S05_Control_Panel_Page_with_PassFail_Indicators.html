Control Panel Page with Pass/Fail Indicators

Scope: A control panel page with pass/fail indicators and conditional formatting

Why it matters

Individual control measures are useless if nobody looks at them. The control panel page is where s01–s04 come together: one page, opened first by the report owner after every refresh, showing every check with a value, a tolerance, a status and an owner. It is the reporting equivalent of a month-end close checklist with sign-off, and it is what you will demonstrate in the Week 12 Saturday validation ("drop in a new month's file, refresh, show every control passing"). In interviews for FP&A and reporting roles, walking through a control page is one of the most convincing ways to show you think like a controller, not just a dashboard builder.

Core notes

Design principles

  1. One row per control, one status vocabulary. Use PASS / WARN / FAIL / NO DATA consistently. Do not mix "OK", "✓", "Balanced" and "0".
  2. Show the evidence, not just the verdict. Value, tolerance and status side by side, so the reviewer sees that "PASS" means a difference of ₹0.32 against a tolerance of ₹1.
  3. Summarise, then detail. A top-row card "All checks passed (14/14)" or "3 checks failing", then the control table, then period × entity detail grids, then exception lists (unmapped ledgers, missing files).
  4. Context-independent. The page should not respond to executive slicers in ways that hide failures; apply REMOVEFILTERS inside the measures or use edit interactions set to none for slicers on this page.
  5. Owner and sign-off. Each control row shows the owner (e.g. "GL Accountant – Bengaluru") and a sign-off reference. Power BI is read-only, so sign-off lives outside it (see below).

Building the control table with a disconnected table

Create a static table Controls in Power Query or with Enter data:

ControlID Control Category Tolerance Owner Sort
C01 Total Debits = Total Credits Accuracy 1 GL Accountant 1
C02 TB nets to zero (closing) Accuracy 1 GL Accountant 2
C03 Balance sheet balances Mapping 1 Reporting Lead 3
C04 Revenue ties to ERP P&L Tie-out 1 Reporting Lead 4
C05 PBT ties to ERP P&L Tie-out 1 Reporting Lead 5
C06 Unmapped ledgers Completeness 0 Mapping Owner 6
C07 Missing branch files Completeness 0 Branch Finance 7
C08 Data lag (days) Freshness 7 FP&A Lead 8

Then one SWITCH measure returns the value for the current row:

Control Value =
SWITCH (
    SELECTEDVALUE ( Controls[ControlID] ),
    "C01", [Dr Cr Diff (Period)],
    "C02", [TB Net Closing],
    "C03", [BS Check],
    "C04", [Tie-out Diff Revenue],
    "C05", [Tie-out Diff PBT],
    "C06", [Unmapped Count],
    "C07", [Missing Branch Files],
    "C08", [Data Lag Days]
)

Control Status =
VAR v   = [Control Value]
VAR tol = SELECTEDVALUE ( Controls[Tolerance] )
RETURN
    SWITCH (
        TRUE (),
        ISBLANK ( v ), "NO DATA",
        ABS ( v ) <= tol, "PASS",
        "FAIL"
    )

Control Status Code =
SWITCH ( [Control Status], "PASS", 1, "WARN", 0, "FAIL", -1, -2 )

Note that ISBLANK(v) is treated as NO DATA, not PASS — for counts like Unmapped Count, wrap the measure in + 0 (or COALESCE(..., 0)) inside its own definition when zero is a genuine result, so that only truly missing inputs show NO DATA. The tolerance comparison uses <= here to allow a zero-tolerance control; be consistent with the individual measures (s01 used < 1).

Conditional formatting

  • Background colour by field value: a measure Status Colour = SWITCH([Control Status], "PASS", "#2E7D32", "WARN", "#F9A825", "FAIL", "#C62828", "#9E9E9E") applied via the fx button on the Status column (Format style = Field value). Field-value formatting accepts hex codes returned by a measure.
  • Icons: Conditional formatting > Icons on [Control Status Code] with rules (= 1 green tick, = 0 amber, = −1 red cross). Icons survive greyscale printing better than colour alone, which also helps accessibility — never rely on red/green alone; include the word.
  • Data bars on absolute differences in the period grid show where the money is.

Summary card

Checks Failing =
SUMX ( Controls, IF ( CALCULATE ( [Control Status] ) = "FAIL", 1, 0 ) )

Overall Status =
VAR f = [Checks Failing]
VAR n = COUNTROWS ( Controls )
RETURN IF ( f = 0, "All checks passed (" & n & "/" & n & ")", f & " of " & n & " checks FAILING" )

CALCULATE around [Control Status] triggers context transition, so each row of Controls is evaluated as if it were the current row in the table visual. Put this card on the executive cover page as well, small and in a corner: viewers then know whether the numbers they see passed control.

Detail grids

Beneath the table, add matrices of Month × Company (or Branch) for C01, C04 and C07, each cell coloured by status. This exposes offsetting errors that pass at total (see pitfall on grand-total controls). Add exception tables — unmapped ledgers with absolute amount, missing files, unbalanced vouchers — each with a drill-through to the voucher detail page built in Topic 2.

Sign-off and alerting

Because Power BI does not record approvals, attach a lightweight sign-off process:

  • a SharePoint list or Excel log (Period, Control, Status at review, Reviewer, Date, Comment), loaded back into the model so the panel shows "Signed off by A. Rao on 07-Apr-2026";
  • Power BI data alerts on a dashboard tile pinned from the Checks Failing card (alert when above 0) — alerts work on card, KPI and gauge tiles in dashboards, not on report visuals directly;
  • or a Power Automate flow triggered by the alert to email the owner and post in a Teams channel.

Illustration

After loading April 2026 files, the panel shows: C01 PASS (₹0.00), C02 PASS (₹0.40), C03 FAIL (−₹38,00,000), C06 FAIL (1 ledger), C08 PASS (5 days). The card reads "2 of 8 checks FAILING". The unmapped-ledger table lists 13208 "GST Input – RCM Kerala" with ₹38,00,000 — the same amount as the BS check failure. One root cause explains both; once the mapping owner adds the ledger to CoA and the pack refreshes, both turn green.

Edge cases & judgement calls

  • Hidden page syndrome. A control page that is hidden from viewers and never opened by the owner is decoration. Keep it visible to the finance team (or in a separate "Controls" app audience) and make reviewing it a close step.
  • Too many controls. Forty checks with frequent WARNs train reviewers to ignore the page. Keep hard controls few and meaningful; demote heuristics to WARN.
  • RLS interaction. With row-level security, a BU head sees controls for their BU only — useful, but the group controller must review the unrestricted version.
  • Mixed signs and scales. Unmapped count is a number, differences are ₹; use a format column or separate FORMAT measures so the table does not show "1.00 ₹".
  • Performance. SWITCH over many heavy controls computes only the branch selected for each row, but the summary SUMX evaluates all; keep heavy voucher-level controls off the summary or pre-compute them in Power Query.

Key takeaways

  • One page, one row per control, showing value, tolerance, status and owner.
  • Drive the table with a disconnected Controls table and a SWITCH measure; derive a numeric status code for icons.
  • Treat blank inputs as NO DATA, never as PASS.
  • Use colour plus text or icons, applied by field-value conditional formatting.
  • Put the overall status card on the cover page and back it with period × entity detail grids.
  • Record sign-off outside Power BI and alert owners on failures.

Practice Questions

Q1. Build the Controls table [L2]

Write the Controls table (at least eight rows) and the Control Value, Control Status and Status Colour measures for a pack that has Dr = Cr, closing TB, BS check, revenue and PBT tie-outs, unmapped count, missing months and data lag. Specify the tolerance you would use for each and justify any non-zero tolerance.

Q2. False PASS from blanks [L1]

A control row for "PBT ties to ERP" shows PASS for a month in which no control file was uploaded. Identify the two measure-design errors that could cause this and correct them.

Q3. Alerting without Premium [L2]

The company uses Power BI Pro only. Describe how you would notify the reporting lead by email and Teams within an hour of a refresh that produces any failing control, naming the Power BI and Power Automate features involved and their limitations.

💡 Hint: Consider where data alerts can be set and what they can trigger.

Q4. Control panel review at a listed company [L3]

The Audit Committee of an NSE-listed company wants evidence that the monthly MIS pack is controlled. Design the control page layout (sections, visuals, interactions), the sign-off log, and the evidence you would retain for the statutory auditor's IFC testing for the year.

Q5. Interview: why a separate control page? [L1]

Explain why you built a dedicated control page rather than putting check measures as tooltips on the P&L visuals.
