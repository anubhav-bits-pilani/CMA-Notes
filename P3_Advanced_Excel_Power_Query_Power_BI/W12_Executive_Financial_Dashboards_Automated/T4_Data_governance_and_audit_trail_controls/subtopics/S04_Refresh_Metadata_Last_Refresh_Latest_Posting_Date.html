Subtopic note

Refresh Metadata: Last Refresh, Latest Posting Date, Source Files

Scope: Refresh metadata: last refresh time, latest GL posting date, list of source files

Why it matters

The first question a CFO asks when a number looks odd is "how current is this?". A dashboard without a freshness stamp invites wrong decisions — a board slide prepared from a model that silently failed to refresh three days ago looks identical to a current one. Refresh metadata answers three distinct questions:

  1. When did the model last refresh? (pipeline ran)
  2. How far does the data go? (latest GL posting date actually loaded)
  3. What was loaded? (list of source files, their dates and row counts)

These are different. A refresh that succeeded today on a folder whose newest file is from last month is "fresh" by the first measure and stale by the second. Showing all three is the reporting equivalent of an auditor recording the date and source of every piece of evidence — and it supports the audit-trail expectation in the Companies (Accounts) Rules that you can show what data a reported number came from.

Core notes

1. Last refresh time

Power BI has no built-in DAX function returning the model's last refresh time. The standard approach is a one-row table created in Power Query that is evaluated at every refresh:

let
    Source = #table(
        type table [LastRefresh = datetimezone],
        {{ DateTimeZone.SwitchZone(DateTimeZone.UtcNow(), 5, 30) }}
    )
in
    Source

DateTimeZone.UtcNow() returns the current UTC time with a zone offset; DateTimeZone.SwitchZone(..., 5, 30) converts it to IST (UTC+05:30). This matters because Power BI Service refreshes run on Microsoft servers set to UTC: DateTime.LocalNow() gives the correct IST time on your laptop in Desktop, but in the Service it returns UTC, making the stamp 5½ hours behind. India has no daylight saving, so a fixed offset is safe; for multi-country groups use UTC explicitly and label it.

In DAX, display it:

Last Refresh Label =
"Data refreshed: " & FORMAT ( MAX ( 'Refresh Info'[LastRefresh] ), "dd-mmm-yyyy hh:mm" ) & " IST"

Do not use NOW() in a DAX measure for this purpose: NOW() evaluates at query time, so it shows when the report was viewed, not refreshed. A calculated column with NOW() evaluates at refresh but uses the server clock (UTC in the Service), with the same IST problem.

Two cautions: the stamp updates only if the table's query actually runs, so make sure the table is not disabled from refresh ("Include in report refresh" must be ticked); and with incremental refresh the stamp table should be a separate import query, not part of a partitioned table.

2. Latest GL posting date

The posting date of the last voucher loaded is the true freshness of the data:

Latest GL Posting Date =
CALCULATE ( MAX ( GL[PostingDate] ), REMOVEFILTERS () )

Data Lag Days =
DATEDIFF ( [Latest GL Posting Date], DATEVALUE ( MAX ( 'Refresh Info'[LastRefresh] ) ), DAY )

REMOVEFILTERS() with no argument clears all filters so the card shows the model-wide latest date regardless of slicers. Show it per company or branch too (keep the Branch filter, remove others): the group may have data to 31 March while one branch stops at 24 March.

Be careful with future-dated vouchers: a single mis-keyed posting date of 31-03-2062 would make the "latest date" meaningless. Either cap the measure at the last closed month-end, or show a separate "Future-dated vouchers" count as a control.

3. List of source files

Keep a metadata query that lists every file the folder connector found, before any transformation:

let
    Source  = SharePoint.Files("https://contoso.sharepoint.com/sites/Finance", [ApiVersion = 15]),
    GLFiles = Table.SelectRows(Source, each Text.StartsWith([Folder Path],
                "https://contoso.sharepoint.com/sites/Finance/Shared Documents/GL/")
                and [Extension] = ".csv"),
    Meta    = Table.SelectColumns(GLFiles, {"Name", "Folder Path", "Date modified", "Date created"})
in
    Meta

Join this (on file name) with the per-file control table from concept c06 to show Name, Date modified, Rows, Total Dr, Total Cr, Min date, Max date. On the control page, a table visual sorted by Date modified descending tells the reviewer at a glance which file is newest and whether a file was replaced after close (a Date modified later than the close date is a flag: someone overwrote a closed month).

Putting metadata on every page

A footer text or card on every report page — "Refreshed 06-Apr-2026 07:15 IST • GL to 31-Mar-2026 • 168 files" — is cheap insurance. On exported PDFs and PowerPoint snapshots, it is the only evidence of the data's currency. Bind it to measures, not typed text.

Illustration

Metadata item Value
Last refresh 06-Apr-2026 07:15 IST (Service scheduled refresh at 01:45 UTC)
Latest GL posting date (group) 31-Mar-2026
Latest GL posting date (Kochi branch) 27-Mar-2026
Files loaded 168 (14 branches × 12 months)
Newest file KOC_2026-03.csv, modified 05-Apr-2026 22:40

Had the stamp used DateTime.LocalNow(), it would display 06-Apr-2026 01:45 — a CFO reading it at 9 a.m. would wrongly believe the overnight refresh ran in the middle of the night before the Kochi file was final.

Service-side metadata

The Service records refresh history (semantic model settings > Refresh history) with start, end, status and error messages, but this is not visible to report viewers. For a richer audit trail, Premium/Fabric workspaces can expose refresh history through the REST API ("Get Refresh History"), which can be logged to a SharePoint list or Lakehouse by a Power Automate flow or notebook.

Edge cases & judgement calls

  • Partial refresh. If a refresh fails midway, the Service keeps the previous data and the old stamp — that is correct behaviour, and why the stamp must come from the same refresh transaction.
  • Desktop vs Service stamps. A file refreshed in Desktop then published carries the Desktop time until the first Service refresh. Label the stamp as IST only after converting.
  • Time-zone of posting dates. GL dates are dates, not datetimes; do not convert them.
  • Excel packs. In Excel, the equivalent is a Power Query stamp loaded to a cell, or a cube formula on the model's refresh table. =NOW() in a cell recalculates on every edit and is not a refresh stamp.
  • Caching. Dashboards (pinned tiles) refresh their cache after the model refresh; a tile may lag briefly.

Key takeaways

  • Show three different freshness facts: when the model refreshed, how far the data goes, and which files were loaded.
  • Build the refresh stamp in Power Query with DateTimeZone.UtcNow() switched to +05:30; DateTime.LocalNow() gives UTC in the Service.
  • NOW() in a measure is view time, not refresh time.
  • Compute the latest posting date with all filters removed, and also per branch.
  • Keep a file-list query with Date modified and per-file control totals for the reviewer.
  • Put a measure-driven footer on every page so exports carry their own provenance.

Practice Questions

Q1. Diagnosing a wrong stamp [L1]

A report footer built with DateTime.LocalNow() shows "Refreshed 14-Jul-2025 00:30" although the scheduled refresh in the Service is set for 06:00 IST. Explain the discrepancy and write the corrected Power Query table.

Q2. Freshness vs currency [L2]

The pack refreshed successfully at 07:00 IST on 5 May 2025. The latest GL posting date is 31 March 2025 for the group, and the April files for 9 of 12 branches are in the folder. Write the DAX measures that would make this situation obvious on the cover page, and describe the cards or table you would show.

💡 Hint: Compute the latest posting date per branch and count branches whose latest date is before the last closed month-end.

Q3. Overwritten closed-month file [L2]

March 2026 was closed and the pack signed off on 8 April 2026. On 20 April, a branch accountant replaced PUN_2026-03.csv with a corrected file. Design the metadata check that would flag this at the next refresh, stating which file attributes and which reference date you would use.

Q4. Audit-trail evidence pack [L3]

An internal auditor asks you to prove which source files and which refresh produced the Q4 FY2025-26 numbers presented to the Audit Committee. Describe the metadata you would capture at each refresh, where you would store it so that it survives subsequent refreshes, and how you would present it.

Q5. Interview: why not NOW()? [L1]

An interviewer asks why you did not just put =NOW() in a DAX measure for the refresh stamp. Answer in three or four sentences.
