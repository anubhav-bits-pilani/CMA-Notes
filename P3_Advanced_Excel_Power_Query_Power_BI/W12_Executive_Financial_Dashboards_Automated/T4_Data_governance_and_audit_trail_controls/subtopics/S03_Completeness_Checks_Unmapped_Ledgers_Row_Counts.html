Subtopic note

Completeness Checks: Unmapped Ledgers, Row Counts, Missing Months

Scope: Completeness checks: unmapped ledgers, row counts per file/branch, missing months

Why it matters

Accuracy controls (Dr = Cr, tie-out) answer "are the numbers that arrived correct?". Completeness controls answer "did everything arrive, and does every number land on a reporting line?". In audit language this is the completeness assertion, and it is where automated packs fail most often in practice: a branch forgets to drop its file, a new ledger is created in Tally without being added to the mapping, or a month is skipped in a folder that holds 36 monthly files. None of these necessarily unbalances the TB, so s01 checks will not catch them.

Completeness checks are cheap to build in Power Query and DAX, and they are the controls a CFO will notice first when they fail ("why is Kolkata branch revenue zero this month?"). Showing them proactively on a control page turns an embarrassing surprise into a managed exception.

Core notes

1. Unmapped ledgers

Every GL account code must map to exactly one CoA row carrying FS line, statement, sign and sub-group. A ledger that exists in the GL but not in the CoA mapping is "unmapped"; its amount falls into the blank row of the CoA dimension (Power BI's automatically added blank member when the many-side key has no match).

Three complementary measures:

Unmapped Count =
COUNTROWS ( EXCEPT ( VALUES ( GL[AccountCode] ), VALUES ( CoA[AccountCode] ) ) )

Unmapped Amount =
CALCULATE ( SUM ( GL[Amount] ), ISBLANK ( CoA[AccountCode] ) )

Unmapped Abs Amount =
CALCULATE (
    SUMX ( VALUES ( GL[AccountCode] ), ABS ( CALCULATE ( SUM ( GL[Amount] ) ) ) ),
    ISBLANK ( CoA[AccountCode] )
)

Unmapped Count is the headline control (target 0). Unmapped Abs Amount shows materiality: ten unmapped ledgers with ₹200 each matter less than one with ₹4 crore. The plain signed sum can net to near zero if a debit and a credit ledger are both unmapped, so do not use it as the status driver. Filtering CoA[AccountCode] to blank selects the blank member, which is exactly where unmatched GL rows land; iterating VALUES(GL[AccountCode]) inside that filter then sums each unmapped code's absolute balance. An alternative is an IsMapped flag column added in Power Query by merging GL with CoA — often the better design because it also produces the list of unmapped codes.

Filter context trap. If a user selects an FS line in a slicer, the CoA filter excludes the blank row and the unmapped amount disappears from view — the control falsely shows 0. Evaluate completeness measures with REMOVEFILTERS(CoA) or keep them on a control page with no CoA slicers.

Mapping the other way. Also check for CoA rows mapped to more than one FS line (duplicate keys break the one-to-many relationship at refresh — Power BI errors with "column contains duplicate values") and for CoA entries with a blank FS line, which are technically mapped but still land nowhere in the P&L layout.

In Power Query, a left anti-join produces the exception list for the reviewer:

Unmapped = Table.NestedJoin(GL_Accounts, {"AccountCode"}, CoA, {"AccountCode"}, "m", JoinKind.LeftAnti)

2. Row counts per file and per branch

The Week 10 folder-consolidation pattern keeps Source.Name (the file name) on every row. Group by it to produce a per-file control table (see concept c06): rows, total debits, total credits, min and max posting date. Compare against an expected-files register — a small table listing, for every branch and month, the file you expect (BLR_2026-03.csv, DEL_2026-03.csv …).

Check Logic Fails when
File present Expected register left-anti-joined to actual files A branch file is missing
Duplicate file Count of files per Branch × Month greater than 1 DEL_2026-03.csv and DEL_2026-03 (1).csv both loaded
Row-count reasonableness Rows this month vs average of last 3 months Rows fall below 50% or exceed 200% of average
Empty file Rows = 0 or only header Export ran but returned nothing
Date range inside file Min/Max posting date within the file's month March file contains April entries

The row-count band is a judgement threshold, not an accounting identity; set it per branch from history and label it "WARN" rather than "FAIL". A month-end with heavy provisioning legitimately has more rows.

In DAX, if the model has a Branch dimension and a Date table, row counts can be checked directly:

GL Rows = COUNTROWS ( GL )
Branches With No Rows =
COUNTROWS ( FILTER ( VALUES ( Branch[BranchCode] ), ISBLANK ( [GL Rows] ) ) )

Placed in a matrix by Month, this shows which branches have no data for which months.

3. Missing months

A continuous Date table (Week 11) has every month; the GL may not. Detect gaps:

Months Expected =
COUNTROWS (
    FILTER (
        VALUES ( 'Date'[MonthKey] ),
        'Date'[MonthKey] <= [Last Closed MonthKey]
    )
)

Months With Data =
COUNTROWS ( FILTER ( VALUES ( 'Date'[MonthKey] ), NOT ISBLANK ( [GL Rows] ) ) )

Missing Months = [Months Expected] - [Months With Data]

[Last Closed MonthKey] comes from a parameter or a control table set by the accountant, not from TODAY(), so that the current open month is not flagged. Evaluate per company and per branch, because a group total will show data in every month even if one branch is missing.

For balance-sheet completeness, also check that the opening-balance voucher exists for the first month of the FY.

Illustration

A retail chain with 14 branches drops monthly Tally exports. For February 2026 the control table shows:

Branch Expected file Loaded Rows 3-month avg rows Status
BLR BLR_2026-02.csv Yes 18,420 17,950 PASS
CHN CHN_2026-02.csv Yes 6,110 16,800 WARN (36%)
KOL KOL_2026-02.csv No 0 9,400 FAIL
HYD HYD_2026-02.csv Yes ×2 25,860 12,900 FAIL (duplicate)

Unmapped Count = 2 (ledgers 41057 "Sales – Q-commerce" and 62310 "Platform fees") with absolute value ₹1.84 crore. Every one of these issues passes Dr = Cr.

Edge cases & judgement calls

  • New ledgers created mid-month. Accountants create ledgers freely in Tally; an "unmapped" exception is normal at first refresh. Route the exception list to the mapping owner and require mapping before the pack is published.
  • Inactive branches. A closed branch is not "missing". Maintain an effective-to date in the expected-files register.
  • Case and whitespace in keys. "41057 " and "41057" do not match; trim and standardise keys in Power Query before the join, or the unmapped count is inflated.
  • Numeric vs text keys. Codes with leading zeros (0045) lose them if typed as numbers in one source.
  • Row counts in incremental refresh. Historical partitions are not reloaded, so row-count checks should target the refreshed window.
  • Sub-ledger completeness. GL completeness does not prove AR/AP sub-ledger completeness; tie the debtors control account to the AR ageing total separately if Page 2 shows DSO.

Key takeaways

  • Completeness failures (missing files, unmapped ledgers, gaps) usually pass Dr = Cr; they need their own controls.
  • Use unmapped count for status and absolute unmapped amount for materiality; evaluate both with CoA filters removed.
  • Compare loaded files with an expected-files register; check duplicates, empties and date ranges inside files.
  • Row-count bands are warnings based on history, not hard failures.
  • Missing-month checks must run per entity and must stop at the last closed month.
  • Standardise keys (trim, text type, leading zeros) before mapping joins.

Practice Questions

Q1. Why unmapped amounts vanish [L1]

On the P&L page, a user filters FS Line = "Other expenses". The Unmapped Amount card shows ₹0, but the control page shows ₹26,40,000. Explain the discrepancy in terms of filter context and the blank CoA row, and state how the measure should be written.

Q2. Expected-files register [L2]

A company has 6 branches and receives one CSV per branch per month for FY2025-26 (April to March). Two branches opened on 1 October 2025 and one closed on 31 December 2025. Design the expected-files register (columns and logic), calculate how many files are expected for the full year, and write the Power Query join that lists missing files.

💡 Hint: Count branch-months that fall within each branch's active window.

Q3. Setting row-count thresholds [L2]

Branch HYD has had monthly row counts of 11,200, 12,800, 13,600, 12,100 and 24,900 (the last being March, a year-end month with heavy accruals). Propose a warning rule that would not flag March as abnormal but would flag a February file with only 4,000 rows. Explain your reasoning.

Q4. Completeness design for a new pack [L3]

You inherit a pack that loads 3 years of GL from 36 monthly SAP files plus a CoA mapping maintained in Excel. No completeness checks exist. Specify every completeness measure and Power Query exception table you would add, the filter context each must use, and who should own each exception.

Q5. Interview: completeness vs accuracy [L1]

Explain the difference between completeness and accuracy controls in a reporting pack, giving one example of an error each catches that the other misses.
