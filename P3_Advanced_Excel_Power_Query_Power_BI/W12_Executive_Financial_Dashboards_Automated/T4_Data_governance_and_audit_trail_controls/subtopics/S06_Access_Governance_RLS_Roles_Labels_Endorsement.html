Subtopic note

Access Governance: RLS, Roles, Labels, Endorsement, Lineage

Scope: Access governance: RLS, workspace roles, sensitivity labels, endorsement (Promoted/Certified), lineage view

Why it matters

A finance pack contains unpublished price-sensitive information (UPSI under the SEBI (Prohibition of Insider Trading) Regulations, 2015), salary costs and BU profitability that managers should not see for each other's units. Getting the numbers right is half the job; making sure only the right people see the right numbers, that viewers know which version is official, and that changes to the shared model do not break downstream reports is the other half. Auditors reviewing IT general controls (ITGCs) under the IFC framework look at access management — who can view, who can edit, how access is granted and reviewed. These five features are Power BI's answer.

Core notes

1. Row-level security (RLS)

RLS restricts rows a viewer can see, defined as DAX filter expressions on roles in Power BI Desktop (Modeling > Manage roles), and users or security groups assigned to roles in the Service (semantic model > Security).

Static RLS hard-codes the filter: role "BU South" with BU[Region] = "South". Simple but needs one role per BU.

Dynamic RLS uses the signed-in user's identity and a mapping table:

UserEmail BusinessUnit
ravi.k@contoso.in Pharma API
ravi.k@contoso.in Formulations
meera.s@contoso.in Consumer Health

The UserAccess table relates to BU (many-to-one on BusinessUnit), and a single role filters it:

-- Role "BU Managers", filter on UserAccess
UserAccess[UserEmail] = USERPRINCIPALNAME ()

The filter flows UserAccess → BU → GL and Budget facts. If the relationship is from BU to UserAccess (one-to-many), the filter direction must allow UserAccess to filter BU — set the relationship to bidirectional with "Apply security filter in both directions", or instead put the filter on BU: BU[BusinessUnit] IN CALCULATETABLE(VALUES(UserAccess[BusinessUnit]), UserAccess[UserEmail] = USERPRINCIPALNAME()). The second form avoids bidirectional relationships and is usually preferred.

Key facts:

  • RLS applies only to users with the Viewer role on the workspace (or app/shared access). Workspace Admins, Members and Contributors see all data regardless of RLS — so BU managers must not be workspace Members.
  • Test with "View as" in Desktop and "Test as role" in the Service, including with a specific user.
  • USERPRINCIPALNAME() returns the UPN (usually email); USERNAME() returns DOMAIN\user in Desktop but UPN in the Service. Prefer USERPRINCIPALNAME().
  • Object-level security (OLS), defined via Tabular Editor, hides whole tables or columns (e.g. the salary table).
  • Control measures under RLS show only the user's BU — the group controller needs unrestricted access to review the whole-group control page.

2. Workspace roles

Role Can view Edit/publish content Share / manage app Manage access
Viewer Yes (RLS applies) No No No
Contributor Yes Yes App update only if allowed by Admin No
Member Yes Yes Yes (publish/update app, share) Add Members/Contributors/Viewers
Admin Yes Yes Yes Full, including delete workspace

Good practice for a finance pack: a development workspace where the BI developer is Member; a production workspace where only the reporting lead and IT are Admin/Member; consumers get access through a Power BI App (audiences per group), not through workspace roles. Assign Azure AD (Entra ID) security groups, not individuals, so joiners and leavers are handled by HR-driven group membership — this makes periodic access review (an ITGC) feasible.

3. Sensitivity labels

Microsoft Purview Information Protection sensitivity labels (e.g. Public, Internal, Confidential, Highly Confidential – UPSI) can be applied to semantic models, reports and dashboards in Power BI. When data is exported to Excel, PowerPoint or PDF, or analysed through Analyze in Excel, the label travels with the file and its protection (encryption, access restrictions) applies. Tenant admins can enable mandatory labelling, default labels and downstream inheritance (a report built on a Highly Confidential model inherits that label). Labels require appropriate Microsoft 365/Purview licences and admin enablement, and label policies are tenant-specific.

Labels are about classification and protection of exported content; they do not restrict who can see the report in the Service — that is workspace/app permissions plus RLS.

4. Endorsement

Endorsement signals which content is trustworthy:

  • Promoted — any Member/Contributor can mark their content as ready for use.
  • Certified — only users authorised by the Power BI admin can certify, after a defined review (e.g. controls page passes, measures documented, owner named). Certified semantic models appear first in discovery and in "Get data > Power BI semantic models".
  • Fabric also offers a Master data badge for core reference data items (availability depends on tenant settings).

For a finance team, certify the single GL semantic model that feeds both the Power BI report and the Excel cube pack; the CFO's analysts then build on the certified model instead of exporting their own copies.

5. Lineage view and impact analysis

Lineage view (workspace > View > Lineage) shows the chain: data sources (SharePoint folder, Tally ODBC via gateway) → dataflows → semantic models → reports → dashboards and apps, including cross-workspace links. Impact analysis on a semantic model lists downstream reports, dashboards and workspaces, with view counts, and can notify their contacts before you rename a measure or change a relationship. Use it before every change to a shared model.

Illustration

A pharma group's pack: the certified semantic model "GL – Group (Certified)" in workspace Finance – Prod, labelled Highly Confidential – UPSI during the quiet period before quarterly results. The App has three audiences: CXO (all pages), BU Heads (P&L and expense pages, dynamic RLS by BU), Finance Controllers (all pages including controls, no RLS restriction through a separate unrestricted role). Impact analysis before renaming [EBITDA] shows 4 reports and 2 Excel workbooks depending on it.

Edge cases & judgement calls

  • Excel and Analyze in Excel honour RLS because queries run against the model as the user; but a workbook with pasted values does not — a reason to prohibit value-pasted circulation of RLS data.
  • Build permission. Granting Build on a model lets users create their own reports — appropriate for analysts, not for all BU heads.
  • Email subscriptions for RLS-protected reports render with the subscriber's identity when they subscribe themselves; subscribing others is constrained under RLS (rules vary; check current documentation).
  • Service principals and embedding require an effective identity for RLS.
  • Composite models and DirectQuery to another semantic model propagate RLS of the source model.
  • Quiet period / insider trading. Restricting the pack to the designated persons list during the trading-window closure is a governance decision; Power BI enforces it only if the groups are maintained.

Key takeaways

  • RLS filters rows for Viewers only; Admins, Members and Contributors bypass it.
  • Use dynamic RLS with USERPRINCIPALNAME() and a user-to-BU mapping table, preferably filtering the dimension with IN rather than relying on bidirectional relationships.
  • Distribute via Apps with security groups; keep workspace membership to builders.
  • Sensitivity labels classify and protect exported content; they do not replace permissions.
  • Certify the one governed finance model; use Promoted for work in progress.
  • Run lineage and impact analysis before changing a shared model.

Practice Questions

Q1. RLS that does not work [L1]

A BU head who is a Member of the production workspace complains she can see all BUs although dynamic RLS is defined. Explain why and describe the correct access setup.

Q2. Dynamic RLS design [L2]

Five BU heads each see one BU; two regional CFOs each see three BUs; the group CFO sees all. Design the mapping table, the relationships and the DAX role filter(s), and state how the group CFO's unrestricted access is achieved without listing every BU.

💡 Hint: Consider a flag column in the mapping table or a separate role with no filter.

Q3. Labels and exports [L2]

The quarterly results pack is labelled "Highly Confidential – UPSI". A user exports the P&L matrix to Excel and emails it to an external consultant. Explain what the sensitivity label does and does not do in this scenario, and what additional Purview control would stop the email.

Q4. Certification policy [L3]

Draft a certification policy for finance semantic models in your organisation: the criteria a model must meet, who reviews, how certification is withdrawn, and how this policy supports IFC over financial reporting.

Q5. Interview: impact analysis [L1]

An interviewer asks what you do before renaming a measure in a shared semantic model. Describe the steps, naming the Power BI features you would use.
