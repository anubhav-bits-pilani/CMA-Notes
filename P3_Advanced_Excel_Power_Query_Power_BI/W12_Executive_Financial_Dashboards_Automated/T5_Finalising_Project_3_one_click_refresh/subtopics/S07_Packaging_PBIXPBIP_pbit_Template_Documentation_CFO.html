Subtopic note

Packaging: PBIX/PBIP, .pbit Template, Documentation, CFO Guide

Scope: Packaging: PBIX/PBIP, a .pbit template, measure and control documentation, a short CFO user guide

Why it matters

Project 3 is delivered when someone else can run, audit and extend it without you. Packaging is what makes that possible: the right file formats for editing and version control, a template that recreates the pack for a new company or year, documentation that lets a reviewer verify every measure and control, and a two-page guide that lets the CFO use the pack confidently. For your portfolio (Week 23–24), a well-packaged project is also the evidence an interviewer can open and inspect.

Core notes

File formats

Format What it contains Use it for
.pbix Report + model + imported data, binary zip Publishing, sharing a working copy, demo
.pbip (Power BI Project) Folder of text files: .SemanticModel (TMDL/BIM, Power Query M), .Report (report JSON/PBIR), local cache excluded from Git Source control, code review, diffing, collaborative development
.pbit (template) Report + model definition + queries + parameters, no data Reusable starting point for a new company/FY; a safe file to share externally
.vpax VertiPaq Analyzer metrics export Performance evidence

The PBIX is the deployable artefact; the PBIP is the source of truth in Git (Topic 4 s07). Save both at each release tag: v1.2 – May 2026 release.

Building the .pbit template

File > Export > Power BI template. Add a template description. When opened, the template prompts for each Power Query parameter (SiteUrl, GLFolderPath, AsOfDate, FYStartMonth, Environment), then loads data from the new sources. For a template to work cleanly:

  • every source path must come from a parameter (s02) — hard-coded paths break the template's purpose;
  • parameters should have meaningful descriptions (shown in the prompt) and sensible defaults;
  • the mapping files (CoA, BU) must be in the expected schema in the new site, so include sample mapping files and a schema note;
  • RLS roles and their DAX are included, but role membership is not (it lives in the Service);
  • test the template against an empty or sample folder to ensure every query handles zero files gracefully.

A .pbit contains no data, so it can be shared with a peer or interviewer without leaking client information — but it still contains M code, which may reveal internal URLs; review before sharing outside.

Measure documentation

Document from the model, not from memory:

  • Set a Description on every measure, and group measures in display folders (01 Base, 02 Time intelligence, 03 Variance, 04 KPIs, 09 Controls).
  • Generate a dictionary with DAX query view: EVALUATE INFO.VIEW.MEASURES() (recent Desktop versions) returns name, expression, description, format string and display folder; copy into an Excel or Markdown appendix. DAX Studio's DMV $SYSTEM.TMSCHEMA_MEASURES is an alternative on older versions.
  • For key measures, add a worked tie-back: "EBITDA FY2025-26 ₹612.4 crore = PBT ₹468.1 crore + Finance costs ₹38.2 crore + D&A ₹121.5 crore − Other income ₹15.4 crore; ties to audited P&L Note 25–28."

Control documentation

A control register, one row per control from the control panel page (Topic 4 s05):

ID Control Measure / query Logic Tolerance Frequency Owner Evidence
C01 Debits = credits by month [Dr Cr Diff (Period)] CoA and cost-centre filters removed ₹1 Every refresh GL Accountant Control page screenshot + sign-off list
C04 Revenue ties to ERP P&L [Tie-out Diff Revenue] vs TB_Control ₹1 per month Monthly at close Reporting Lead Signed tie-out export
C06 No unmapped ledgers [Unmapped Count] EXCEPT GL vs CoA 0 Every refresh Mapping Owner Exception list

This register can be lifted directly into the company's IFC risk-control matrix.

The CFO user guide (two pages)

Write for a CFO with ten minutes, not for a developer:

  1. What this pack is — three pages, sources, refresh time ("data refreshed daily at 06:30 IST; GL to last working day"), who owns it.
  2. How to read each page — KPI card conventions (green = favourable vs budget; pp = percentage points; ₹ crore), where variance explanations come from.
  3. How to interact — FY/BU/Region slicers (synced across pages), drill-through from an EBITDA line to vouchers (right-click > Drill through > Voucher detail), back button, bookmarks for Actual vs Budget and ₹ vs %.
  4. How to know the numbers are right — the overall control status card, the control page, the refresh stamp.
  5. Excel board pack — open, enable editing, click Refresh, wait for "All checks OK".
  6. When something looks wrong — whom to contact; what to report (page, filters, screenshot, time).

Include screenshots with callouts. Keep a one-page "quick card" version for the board pack's inside cover.

Release package checklist

  • PBIX and PBIP (tagged in Git), .pbit template, sample source files
  • Measure dictionary and control register
  • Data lineage diagram (from the Service lineage view, plus a hand-drawn source map)
  • Refresh setup notes: schedule, gateway (if any), credential owner, failure-email recipients
  • RLS design: roles, mapping table, testing evidence ("View as" screenshots)
  • CFO user guide and quick card
  • Release notes: version, changes, known issues

Illustration

Version 1.0 of Project 3 is packaged as: FinancePack.pbix (148 MB), FinancePack.pbip folder in GitHub, FinancePack_Template.pbit (1.2 MB, prompting for five parameters), Measure_Dictionary.xlsx (86 measures in 7 folders), Control_Register.xlsx (12 controls), CFO_Guide.pdf (2 pages). A peer opens the template, points it at a sample folder, and has a working pack in 12 minutes — the test that the packaging works.

Edge cases & judgement calls

  • Confidential data in demos. For interviews, use anonymised or synthetic data; a .pbit with sample files is ideal.
  • Template drift. Fixes made in one company's PBIX must be ported back to the template; manage the template in Git as the master.
  • Description quality. "Sum of amount" adds nothing; describe business meaning, sign convention and exclusions.
  • Large models cannot be shared as PBIX after incremental refresh in the Service; the PBIP and template become the distribution formats.
  • Guide currency. Out-of-date screenshots erode trust; regenerate the guide at each major release.

Key takeaways

  • Use PBIX to deploy, PBIP for source control, .pbit as a data-free reusable template.
  • A template only works if every source and setting is parameterised and mapping schemas are documented.
  • Generate the measure dictionary from the model with descriptions and display folders.
  • Maintain a control register that mirrors the control page and can feed the IFC risk-control matrix.
  • Write a two-page CFO guide focused on reading, interacting with and trusting the pack.
  • Test packaging by having someone else rebuild the pack from the template.

Practice Questions

Q1. Choosing formats [L1]

For each recipient — the Git repository, the BI team in a sister company, an external interviewer, the production workspace — state which file format(s) you would provide and why.

Q2. Template readiness review [L2]

You export a .pbit and a colleague reports: (a) no parameter prompts appear; (b) after pointing to their folder, three queries error with "column 'Narration' not found"; (c) RLS does not restrict anyone in their Service. Diagnose each issue and state the fix.

💡 Hint: Consider which settings live in the file and which live only in the Service.

Q3. Writing dictionary entries [L2]

Write measure-dictionary entries (name, business definition, DAX summary, format, sign convention, tie-back) for [Net Debt], [DSO] and [EBITDA % vs Budget] as used in the Executive Finance Pack.

Q4. CFO guide draft [L3]

Draft the "How to know the numbers are right" section of the CFO user guide (about 200 words), referring to the specific cards, pages and checks in your pack, and stating what the CFO should do if the status card shows a failure.
