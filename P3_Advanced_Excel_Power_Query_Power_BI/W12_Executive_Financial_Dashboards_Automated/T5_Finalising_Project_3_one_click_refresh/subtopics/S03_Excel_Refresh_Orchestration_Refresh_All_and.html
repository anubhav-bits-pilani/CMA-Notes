Excel Refresh Orchestration: Refresh All and Connection Settings

Scope: Excel refresh orchestration: Refresh All, background refresh off, "Refresh data when opening the file"

Why it matters

Half of Project 3's "one-click" promise lives in Excel: the CFO's board pack, built with Power Query outputs, PivotTables and cube formulas, must update completely with one action. Excel's refresh engine is less predictable than the Service: queries can run in the background, PivotTables can refresh before the queries feeding them finish, cube formulas calculate asynchronously, and a user may print the pack while half of it is stale. Knowing exactly which connection settings control order and completion is what separates a reliable pack from one that "usually works if you click Refresh All twice".

Core notes

What Refresh All does

Data > Refresh All (Ctrl+Alt+F5) refreshes every connection in the workbook that has "Refresh this connection on Refresh All" ticked: Power Query queries (each is a connection), the workbook Data Model, external connections (to a Power BI semantic model or SSAS), and PivotTables based on them. It then recalculates dependent formulas.

The order is not guaranteed to be dependency-driven when background refresh is on: Excel starts refreshes and returns control while they run, so a PivotTable may refresh against a query table that has not yet reloaded. With the Data Model, Excel handles query-to-model dependencies better, but mixed workbooks (some queries loaded to sheets, some to the model, some PivotTables on sheet tables) remain risky.

Connection properties that matter

Data > Queries & Connections > right-click a query > Properties (or Data > Connections > Properties):

Setting Recommended for board pack Why
Enable background refresh Off Forces synchronous refresh in sequence; Refresh All completes before control returns
Refresh every n minutes Off Unexpected refreshes during review change numbers
Refresh data when opening the file On for the cube connection (optional for queries) CFO opening the pack gets current numbers
Remove data from the external data range before saving Optional Smaller file; forces refresh on open
Refresh this connection on Refresh All On for all production queries; off for archival or slow reference queries Controls scope of one-click
Enable Fast Data Load (Power Query, query options) Situational Faster but may freeze Excel during load

Turning background refresh off for every query is the single most important setting. It is per connection, so check each one (Power Query > Query Options > Data Load can set defaults for new queries). With it off, Excel refreshes queries in turn and the user sees a modal progress state; when the status bar clears, everything is done.

PivotTables and cube formulas

  • PivotTables on the Data Model refresh when the model refreshes. PivotTables based on worksheet ranges need their own refresh (Refresh All covers them), and PivotTable Options > Data > "Refresh data when opening the file" applies to their cache.
  • Cube formulas (CUBEVALUE, CUBEMEMBER) are evaluated asynchronously; after Refresh All, cells can briefly show #GETTING_DATA. In VBA, Application.CalculateUntilAsyncQueriesDone waits until they finish (concept c04). Printing or exporting to PDF before that moment captures placeholders.
  • The cube connection to a published Power BI semantic model does not re-run Power Query; it re-queries the model, which reflects the last Service refresh. Refreshing the Excel pack therefore does not refresh the Service model — orchestrate the Service refresh first.

Sequencing for a hybrid pack

For a workbook that contains its own Power Query staging and a cube connection to the Service model:

  1. Service scheduled refresh completes (e.g. 06:30 IST).
  2. User opens the workbook — the cube connection refreshes on open (setting on).
  3. User clicks a "Refresh pack" button (macro) that runs ThisWorkbook.RefreshAll, waits for async cube queries, then recalculates the checks and updates a "Pack refreshed at" cell.
  4. The "All checks OK" flag on the cover confirms Dr = Cr, BS check and tie-out values read from the model.

Settings checklist in practice

  • Workbook saved as .xlsx if no macros; .xlsm if using the button.
  • Calculation mode Automatic (Formulas > Calculation Options). In Manual mode cube formulas do not update after refresh.
  • Data > Get Data > Query Options > Privacy set consistently (Organizational for internal sources) to avoid firewall prompts on other users' machines.
  • Trust Center: external data connections enabled; for files opened from SharePoint, Protected View may block refresh until "Enable Editing" is clicked — tell users.
  • Credentials: each user's Excel authenticates as that user to SharePoint and Power BI; RLS applies to cube formulas.

Illustration

A CFO board pack has 6 Power Query queries (loaded to sheets for commentary tables), a cube connection to the certified model, 4 PivotTables and 220 cube formulas. With background refresh on, Refresh All returns control in 2 seconds; the cover's EBITDA shows ₹41.10 crore (old) while the variance table, from a query still loading, shows May data. With background refresh off on all six queries and the macro from c04, refresh takes 48 seconds and every cell, including the check flag, reflects May.

Edge cases & judgement calls

  • Excel for the web. Supports refreshing some Power Query sources and Power BI-connected PivotTables, but capabilities differ from desktop and VBA does not run; test the pack in the environment the CFO uses.
  • Long refreshes. Turning background refresh off blocks Excel; for a 10-minute refresh, schedule it (Power Automate Desktop or a Windows task opening Excel) rather than make the CFO wait.
  • Refresh on open with RLS. Different users see different numbers in the same file — intended, but warn users not to email refreshed copies across BUs.
  • Pasted values. If anyone pastes values over cube formulas, refresh silently stops updating those cells; protect formula ranges (Topic 3 pitfall).
  • Query dependencies. A query that references another loaded query is refreshed after it when background refresh is off; still, avoid sheet-table-to-query round trips (a query reading a table that another query writes).

Key takeaways

  • Refresh All refreshes every connection flagged for it, plus PivotTables and dependent calculations.
  • Turn background refresh off on every production query so refresh is sequential and complete when control returns.
  • Use "Refresh data when opening the file" for the cube connection so the pack opens current.
  • Cube formulas are asynchronous; wait for them before printing or exporting.
  • Refreshing Excel re-queries the published model; it does not refresh the model itself.
  • Keep calculation Automatic and protect formula ranges.

Practice Questions

Q1. Diagnosing a half-refreshed pack [L1]

After Refresh All, a board pack's cover shows April revenue while the detail sheet shows May. Explain the likely setting causing this and how you would verify and fix it for every query.

Q2. Designing connection settings [L2]

A workbook has: (a) a cube connection to the Power BI model; (b) three Power Query queries loading commentary tables; (c) one large query loading five years of archive data that never changes; (d) two PivotTables on a sheet table. Specify, for each, background refresh, refresh on open and Refresh All participation, with reasons.

💡 Hint: Consider which items change monthly and which only slow the refresh.

Q3. Stale model behind Excel [L2]

The CFO refreshes the Excel board pack at 08:00 and sees last month's numbers, although new files were dropped at 07:00. The Service schedule is 06:30. Explain what happened and propose two ways to orchestrate the sequence.

Q4. User guide section [L3]

Write the "How to refresh the board pack" section of the CFO user guide: steps, what the user should see on success, three common error messages and what to do for each.
