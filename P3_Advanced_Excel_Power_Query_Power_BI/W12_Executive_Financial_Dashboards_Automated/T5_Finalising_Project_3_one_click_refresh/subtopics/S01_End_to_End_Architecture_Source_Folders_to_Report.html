End-to-End Architecture: Source Folders to Report and Cube Pack

Scope: End-to-end architecture: source folders (SharePoint/OneDrive) → Power Query → model → Power BI report + Excel cube pack

Why it matters

Project 3 is judged on one thing: a new month's files go in, one refresh runs, and every number in both the Power BI pack and the Excel board pack updates correctly with all controls passing. That only works if the architecture is deliberate — each layer has one job, data flows in one direction, and both front ends read from one model. In interviews, "walk me through your data lineage" is a standard question; a clear layered answer (sources → staging → model → presentation) shows you can build something a finance team can run without you.

Core notes

The layers

Layer Tool Responsibility Week built
1. Sources SharePoint document library or OneDrive for Business folders Monthly GL CSVs per branch, CoA mapping, budget, TB control totals, AR/AP ageing Week 10
2. Ingestion & staging Power Query (in Power BI Desktop, or a dataflow) Folder combine, type, clean, unpivot, validate, exception outputs Week 10
3. Semantic model Power BI semantic model (VertiPaq) Star schema, fiscal Date table, relationships, measure library, RLS Week 11
4a. Report Power BI report (3 pages + control page) Executive P&L & variance, BS & working capital, expense drill-down Week 12 T1–T2
4b. Board pack Excel workbook with cube formulas connected to the published model Schedule III layouts, variance columns, commentary Week 12 T3
5. Distribution Power BI App, subscriptions, exports Audience-specific access Week 12 T5

Source folder design

Use a SharePoint site owned by Finance (not a personal OneDrive, which dies with the employee's account). A practical structure:

Folder Content Naming rule
/GL/ One file per branch per month GL_<Branch>_<YYYY-MM>.csv
/Budget/ Annual budget and re-forecasts Budget_FY2025-26_v3.xlsx
/Mapping/ CoA mapping, BU and cost-centre masters Single current file; history via SharePoint versioning
/Controls/ ERP TB/P&L control totals per company-month TB_<Company>_<YYYY-MM>.csv
/Archive/ Superseded files Excluded by the folder filter

Rules: one schema per folder, no ad hoc files dropped beside the data, filter by extension and folder path in the query, and require a naming convention that encodes branch and month (s03 completeness checks depend on it).

Connect with SharePoint.Files (or SharePoint.Contents) using the site URL, not the OneDrive sync path on a laptop (C:\Users\...\OneDrive - Contoso\...). The sync path works in Desktop but needs a gateway for Service refresh; the SharePoint connector refreshes in the cloud (concept c03).

Power Query staging pattern

  1. Src_GL_Files — SharePoint file list filtered to /GL/ and .csv (connection only).
  2. fx_TransformGLFile — custom function applied to each file's binary (promote headers, types, trim codes).
  3. Stg_GL — combined table with Source.Name, standardised columns, Currency.Type amounts.
  4. GL — loaded fact; File_Control, Unmapped_Exceptions — loaded control tables.
  5. Dimensions (CoA, BU, CostCentre, Vendor) from mapping files; Date from M or DAX with FY start parameter.

Keep heavy transforms upstream (Power Query) and calculations downstream (DAX measures). Disable load for intermediate queries.

One model, two front ends

Publish the PBIX/PBIP to the Service; the semantic model becomes the single source of truth.

  • The Power BI report is bound to it (in the same file, or as a thin report with a live connection).
  • The Excel cube pack connects via Analyze in Excel or Excel's Data > Get Data > From Power Platform > From Power BI. Cube formulas reference the connection name and the same measures ([Measures].[Actual]), so the board pack and the dashboard cannot disagree.

Avoid a second copy of the model inside the Excel workbook (Power Pivot) for production: two models drift. The workbook Data Model is fine for prototyping (Topic 3) but the production board pack should point to the published semantic model.

Where Tally fits

Tally Prime data reaches the folder either by scheduled export (XML/CSV to a synced folder, then uploaded to SharePoint by a script or Power Automate Desktop), or directly through Tally's ODBC interface (port 9000) queried by Power BI. The direct route requires the Tally application to be running on a machine with an on-premises data gateway (s04). For a month-end pack, the export-to-SharePoint route is usually simpler and more auditable, because the exported file is itself evidence.

Illustration

A Bengaluru IT-services company with 4 delivery centres: 48 GL files per year, one budget file, one mapping file and 12 control files. After adding May 2026, the folder holds 4 new GL files and 1 control file. One scheduled refresh at 06:30 IST updates the model; the App shows May; the CFO's Excel board pack, opened at 09:00 with "Refresh data when opening the file" on, shows the same EBITDA of ₹38.42 crore as the Power BI card.

Edge cases & judgement calls

  • Dataflows vs in-model Power Query. A dataflow (Gen1 or Fabric Gen2) centralises staging for several models but adds a refresh dependency: the model refresh must run after the dataflow completes.
  • Multiple models. Separate models for finance and sales are acceptable if they share conformed dimensions; avoid duplicating GL logic.
  • Large files. CSVs of several hundred MB per month push towards incremental refresh (s05) or Fabric.
  • SharePoint permissions. The refresh credential must have read access to every folder; a restricted sub-folder causes refresh failures that look like missing data.
  • Excel-only users. Users without Power BI licences cannot use Analyze in Excel against a Pro workspace; plan licensing for board-pack consumers (Premium/Fabric capacity at F64 or above allows free-licence viewing of reports, but building in Excel generally needs Build permission and a licence).

Key takeaways

  • Five layers: sources, Power Query staging, semantic model, presentation (report + Excel), distribution.
  • Store sources in a Finance-owned SharePoint site with one schema per folder and encoded file names.
  • Connect through the SharePoint connector, not a local sync path, to refresh in the cloud without a gateway.
  • One published semantic model feeds both the Power BI report and the Excel cube pack.
  • Keep transformations in Power Query and business logic in DAX measures.
  • Prefer exported Tally files in SharePoint over live ODBC for auditable month-end packs.

Practice Questions

Q1. Draw the lineage [L1]

Draw (as a text diagram or table) the lineage for a pack with GL, budget, CoA mapping and TB control files, naming each Power Query query, the semantic model, the report, the App and the Excel workbook, and the refresh trigger between layers.

Q2. Folder hygiene failure [L2]

An analyst saves GL_BLR_2026-04 - Copy.csv and Notes on April.xlsx in the /GL/ folder. Describe what happens at the next refresh with a naive folder query, and specify the filters and naming checks that would prevent or detect each problem.

💡 Hint: Consider both the extension filter and the duplicate-period check.

Q3. Two models drifting [L2]

The CFO's office has an Excel board pack with its own Power Pivot model loading the same GL files, while FP&A maintains the Power BI model. In March, Excel shows EBITDA ₹1.6 crore higher. List likely causes and argue for the target architecture.

Q4. Architecture for Tally plus SAP [L3]

Two subsidiaries run Tally Prime on on-premises servers; the parent uses SAP S/4HANA in the cloud. Design the source layer and ingestion approach (export vs ODBC, gateway need, folder structure, schedules) so that a single 07:00 IST refresh produces a consolidated pack, and identify the failure points.

Q5. Interview: why SharePoint? [L1]

Explain in four sentences why you used a SharePoint library rather than a shared network drive or a personal OneDrive for the source files.
