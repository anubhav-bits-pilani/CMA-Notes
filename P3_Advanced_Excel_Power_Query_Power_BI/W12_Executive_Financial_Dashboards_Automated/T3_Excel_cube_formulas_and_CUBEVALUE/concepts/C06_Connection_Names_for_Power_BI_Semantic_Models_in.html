Key concept

Connection Names for Power BI Semantic Models in Cube Formulas

Concept: For Power BI semantic models, replace "ThisWorkbookDataModel" with the workbook connection name

Statement

Every cube function's first argument is a connection name — the name of a workbook connection listed in Data > Queries & Connections > Connections (or Data > Connections > Workbook Connections):

  • For the workbook's own Data Model, the name is always "ThisWorkbookDataModel".
  • For a Power BI semantic model connected through Analyze in Excel or Get Data > From Power BI, Excel creates an OLEDB/MSOLAP connection with its own name (often long and containing workspace, model or ID text). That exact name replaces "ThisWorkbookDataModel":
=CUBEVALUE("PBI_FinancePack", "[Measures].[Actual]", "[Date].[FY].&[FY2025-26]")

Best practice is to put the name in a named cell Conn and reference it everywhere:

=CUBEVALUE(Conn, "[Measures].[Actual]", Slicer_FY)

Explanation

The connection name is just text matched against the workbook's connection list. Consequences:

  • Rename first. Open the connection's Properties and rename it to a short, stable name (PBI_FinancePack) before writing formulas. Renaming later breaks every formula that uses the literal old name (Excel does not rewrite cube formulas when a connection is renamed) — another reason to reference a Conn cell.
  • Switching models. Moving a pack from the workbook Data Model to the Power BI semantic model (or from a Dev to a Prod workspace model) becomes a single-cell change in Conn, provided both models share table, column and measure names. This is how the Excel pack follows the Dev/Test/Prod discipline of Topic 5.
  • Slicers. Slicers belong to a connection. After switching Conn, existing slicers still point at the old connection and must be recreated on the new one (or the pack kept on one connection per environment).
  • Unique names. In a Power BI model, MDX unique names follow the same [Table].[Column].&[Key] grammar, with the model's table names; implicit measures are not available, so only explicit measures can be referenced.
  • Authentication and permissions. The connection uses the user's Microsoft Entra ID sign-in; the user needs Build permission on the semantic model; RLS applies. If the user cannot authenticate, every cube cell returns #N/A.
  • Sensitivity labels. The connection inherits the model's sensitivity label into the workbook where the tenant enables inheritance.
  • Refresh. Refresh All on a Power BI connection re-queries the Service; it does not refresh the semantic model itself (that is scheduled refresh in the Service).

Sahyadri's board pack:

1 Analyze in Excel on "Finance Pack – Prod" Connection created with a long system name
