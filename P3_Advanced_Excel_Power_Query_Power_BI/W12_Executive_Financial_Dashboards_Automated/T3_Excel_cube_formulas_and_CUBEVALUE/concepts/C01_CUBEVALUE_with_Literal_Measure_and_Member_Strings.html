Key concept

CUBEVALUE with Literal Measure and Member Strings

Concept: =CUBEVALUE("ThisWorkbookDataModel", "[Measures].[Actual]", "[Date].[FY].&[FY2025-26]", "[CoA].[FSLine].&[Revenue]")

Statement

=CUBEVALUE("ThisWorkbookDataModel",
           "[Measures].[Actual]",
           "[Date].[FY].&[FY2025-26]",
           "[CoA].[FSLine].&[Revenue]")
  • "ThisWorkbookDataModel" — the connection: the workbook's own Data Model (Power Pivot).
  • "[Measures].[Actual]" — the measure to evaluate (DAX Actual = SUM(GL[Amount]) or its signed version).
  • "[Date].[FY].&[FY2025-26]" — member of column FY in table Date with key "FY2025-26".
  • "[CoA].[FSLine].&[Revenue]" — member of column FSLine in table CoA with key "Revenue".

The result is the measure evaluated in the filter context

\[ \text{Actual}\big(\text{FY} = \text{FY2025-26},\ \text{FSLine} = \text{Revenue},\ \text{all other columns unfiltered}\big) \]

Explanation

CUBEVALUE builds one query context from all its member arguments (each must come from a different hierarchy) and returns the measure value. Hierarchies not mentioned are at their All member, so this formula returns revenue for all BUs, regions and months of FY2025-26.

Writing literal strings is the clearest way to learn and to build a one-off check cell, but it has drawbacks in a pack:

  • Hard to maintain. Changing the year requires editing every formula; use a slicer (c03) or a cell reference.
  • Silent #N/A. A typo in any string (e.g. &[FY 2025-26]) returns #N/A, which can be hidden by IFERROR or by a SUM that ignores it in an aggregate — the most dangerous failure in a pack (topic pitfall).
  • Not reusable. Literal members cannot be copied down a column of FS lines; references to CUBEMEMBER cells (c02) can.
  • Sign and units. The measure returns the model's sign convention and rupees. For a pack in ₹ crore, use a [Revenue ₹ Cr] measure or divide by 1e7 consistently, and ensure revenue is positive in the measure.

Interpretation of "Revenue" depends on the CoA mapping: if CoA[FSLine] distinguishes "Revenue from operations" and "Other income", the key must be the exact FSLine value used in the model. Using the key form (&[...]) rather than the name form is precise and faster.

Illustration

Sahyadri's model: FSLine values include "Revenue", "Other income", "Material cost" and others; GL for FY2025-26 has revenue credits of ₹12,40,63,48,210 stored as negative amounts; the measure [Actual] uses SignFactor to show revenue positive. The formula returns 12406348210. A check cell beside the Power BI card value:

=ROUND(CUBEVALUE("ThisWorkbookDataModel","[Measures].[Actual]",
       "[Date].[FY].&[FY2025-26]","[CoA].[FSLine].&[Revenue]")/1e7, 1)

returns 1,240.6, which must equal the Power BI card ₹1,240.6 Cr.

Practice Questions

Q1. Write the variants [L1]

Write CUBEVALUE formulas for (a) Budget revenue FY2025-26; (b) Actual revenue FY2025-26 for the Agro BU; (c) Actual "Other income" for FY2024-25.

Q2. Spot the silent error [L2]

A pack's "Total income" cell is =IFERROR(C5,0)+IFERROR(C6,0) where C5 is the revenue CUBEVALUE. After a CoA change renaming "Revenue" to "Revenue from operations", Total income drops by ₹1,240.6 Cr without any error showing. Explain what happened and redesign the cells so the error cannot be hidden.

💡 Hint: Consider what IFERROR does to a #N/A from an invalid member.

Q3. Default members [L2]

Explain what the formula in the concept returns if the Date table also has a Month column and nothing selects a month, and what changes if the model's BU table has RLS restricting the user to Pharma.
