Converting PivotTables to Cube Formulas with OLAP Tools

Scope: Converting PivotTables to formulas with OLAP Tools > Convert to Formulas

Why it matters

Writing CUBEVALUE formulas from scratch requires exact MDX unique names, which are easy to get wrong. The fastest reliable start is to build a PivotTable on the model with the right rows, columns, filters and slicers, then let Excel convert it into formulas. The result is a grid of CUBEMEMBER and CUBEVALUE cells with correct syntax that you can then rearrange freely — insert blank rows, move subtotals, add commentary — which a PivotTable would never allow. Most professional cube-formula board packs start this way.

Core notes

Prerequisites

  • The PivotTable must be OLAP-based: built on the workbook Data Model, a Power BI semantic model, or an Analysis Services cube. Ordinary range/table PivotTables do not offer Convert to Formulas (the OLAP Tools button is greyed out).
  • Use explicit measures in Values.
  • Arrange the pivot close to the target layout: rows = CoA[FSLine] (or a hierarchy), columns = scenario measures or months, filters = FY, connected slicers for FY/BU/Region.

The conversion

Select a cell in the PivotTable > PivotTable Analyze > Calculations > OLAP Tools > Convert to Formulas.

  • If the pivot has fields in the Filters area, a dialog asks whether to Convert Report Filters. If ticked, filter cells become CUBEMEMBER formulas too and are referenced by every CUBEVALUE; if unticked, a residual PivotTable holding only the report filter stays on the sheet and the CUBEVALUE formulas reference its filter cell, so users can still change the filter with the pivot dropdown.
  • Row and column labels become CUBEMEMBER formulas, values become CUBEVALUE formulas referencing the label cells, the measure cell and any slicer names.
  • The PivotTable object is removed; formatting is preserved (number formats, fonts) but PivotTable styles may be lost.
  • Slicers that were connected to the pivot stay on the sheet and are referenced by name in each CUBEVALUE.

A typical converted cell (here, revenue for FY2025-26 in column C):

A5:  =CUBEMEMBER("ThisWorkbookDataModel","[CoA].[FSLine].&[Revenue from operations]")
C4:  =CUBEMEMBER("ThisWorkbookDataModel","[Measures].[Actual]")
C5:  =CUBEVALUE("ThisWorkbookDataModel",C4,Slicer_FY,Slicer_BU,A5)

After conversion, review each formula's references: Excel writes relative references, so copying or moving cells can shift them. Make measure rows anchored (C$4) and row labels column-anchored ($A5) before copying across.

What conversion gives and takes away

Gains Losses
Free layout: insert rows, blank lines, custom subtotals, notes Automatic expansion when new members appear (new FS line, new BU)
Mix measures from one model with Excel calculations Drill-down, sorting and filtering via pivot UI
Cells referenceable by charts (including native waterfall) Pivot "Show values as" calculations (convert to measures first)
Stable shape for printing and PDF Grand totals become ordinary CUBEVALUE cells that you must maintain

The loss of auto-expansion is the key risk: if a new FS line "Exchange loss on operations" appears next month, a converted grid does not show it, and the totals computed by CUBEVALUE on the "All" member will include it — the displayed lines no longer add up to the total. Controls (below) catch this.

Making the converted grid robust

  1. Replace hard-coded member strings with references to label cells (Concept c02) so lines can be renamed in one place.
  2. Keep a hidden "member key" column with the exact FS line keys; visible labels can then be Schedule III wording.
  3. Add a check row: total from CUBEVALUE on the parent member versus the sum of displayed lines — difference must be zero.
  4. For lists that should expand (vendors, cost centres), use CUBESET-driven lists (s07) instead of converted static members.
  5. Name key cells: measure cells (MsrActual, MsrBudget), connection (Conn).

Illustration

A pivot on Sahyadri's Data Model: rows = 14 Schedule III P&L lines, columns = [Actual], [Budget], [PY], filters = FY via a slicer Slicer_FY, BU via Slicer_BU. Convert to Formulas produces 14 CUBEMEMBER row labels, 3 CUBEMEMBER measure headers and 42 CUBEVALUE cells plus a grand-total row. The analyst inserts blank rows between "Total income" and expenses, adds "Var" and "Var %" columns (as [Variance] measures added as CUBEVALUE, not Excel subtraction where sign logic matters), and a commentary column. A check cell compares the converted grand total revenue ₹1,240.6 Cr with CUBEVALUE(Conn, MsrActual, "[CoA].[Statement].&[Profit and Loss]", ...).

Edge cases & judgement calls

  • Converting with Values in rows. If measures are on rows ("Σ Values" in Rows), the measure becomes part of each row member reference; layout can get confusing — put measures on columns.
  • Hierarchies. Converting a pivot with expanded hierarchies writes members with hierarchy-level unique names (e.g. [CoA].[FS Hierarchy].[FSLine].&[...]); keep consistent with the rest of the sheet.
  • Undo only. Conversion cannot be reversed except by Undo immediately; keep a copy of the pivot sheet.
  • Report filter multi-select. A multi-select report filter converts to a set reference; check that the set is what you expect.
  • Data Model edits. Renaming a column in the model breaks member strings in converted formulas (e.g. [CoA].[FSLine] → [CoA].[FS Line]); establish naming before converting.
  • Number formats from the measure's model format are not always carried; apply Excel formats deliberately.

Key takeaways

  • Convert to Formulas works only for OLAP-based PivotTables (Data Model, Power BI, SSAS).
  • It produces CUBEMEMBER labels and CUBEVALUE values with correct syntax — the safest way to start.
  • Converted grids gain layout freedom but lose automatic expansion; add completeness checks.
  • Anchor measure rows and label columns before copying; name key cells.
  • Prefer measures for variance logic and CUBESET lists for members that change over time.

Practice Questions

Q1. Convert and inspect [L1]

Build a PivotTable on a Data Model with FS lines on rows, [Actual] and [Budget] on columns and an FY slicer, convert it to formulas, and write down the formula produced in one value cell. Identify each argument's role.

Q2. Report filter choice [L2]

Explain what happens to an FY field in the Filters area when you tick versus untick Convert Report Filters, and which you would choose for a board pack that must respond to a slicer.

Q3. New FS line next month [L2]

After conversion in October, November data includes a new FS line "Exchange loss on operations" of ₹1.3 Cr. Describe what the converted grid shows, why the total no longer matches the displayed lines, and the check that would flag it.

💡 Hint: Compare a CUBEVALUE on the parent member with the sum of the displayed children.

Q4. Pivot or formulas [L3]

A CFO wants a monthly pack with (a) a Schedule III P&L in fixed format, (b) a vendor list that grows and shrinks with activity, and (c) an ad hoc analysis sheet for the FP&A team. Decide for each whether to keep a PivotTable, convert to formulas or use CUBESET-driven formulas, and justify.
