Dynamic Top N Lists with a Sorted CUBESET and CUBERANKEDMEMBER

Scope: Dynamic Top N lists with a sorted CUBESET and CUBERANKEDMEMBER

Why it matters

Board members ask "who are our top 10 vendors this year?" and "which cost centres overspent most?". A static list typed into the pack is wrong next month. A CUBESET sorted by a measure, read row by row with CUBERANKEDMEMBER, produces a list that re-ranks itself after each refresh — the Excel equivalent of the Power BI RANKX(ALLSELECTED()) Top N in Topic 2. It is also the way to make cube-formula packs expand: unlike converted PivotTables, a CUBESET list grows when new vendors or cost centres appear.

Core notes

The three-formula pattern

  1. Set cell (e.g. B2): a sorted set.
=CUBESET(Conn, "[Vendor].[Name].Children", "Top vendors", 2, "[Measures].[Expense]")

  1. Count cell (e.g. C2): =CUBESETCOUNT(B2) — number of vendors in the set.

  2. List rows (A5 downward): the n-th ranked member, with n from the row position, blank past the end or past N.

A5:  =IF(ROWS(A$5:A5) > MIN(TopN, C$2), "", CUBERANKEDMEMBER(Conn, B$2, ROWS(A$5:A5)))
B5:  =IF(A5="", "", CUBEVALUE(Conn, MsrExpense, Slicer_BU, A5))

TopN is a named input cell (e.g. 10). ROWS(A$5:A5) returns 1 in row 5, 2 in row 6, and so on as the formula is filled down. Pre-fill 25 rows; only the first N show.

Making the ranking respond to slicers

CUBESET has no slicer arguments: its sort_by is evaluated in the default context (all FYs, all BUs) unless the context is written into the expressions. So a list sorted with "[Measures].[Expense]" ranks vendors by all-years spend, even though the CUBEVALUE beside it shows the selected FY — the order looks wrong. Fixes:

  • Put the context in sort_by as a tuple: build the tuple text from the selected FY's unique name, e.g. "([Measures].[Expense], [Date].[FY].&[" & SelFY & "])", where SelFY is a cell holding the FY key (from a data-validation dropdown, or derived from the slicer caption).
  • Put the context in the set expression: an MDX filter such as "NonEmpty([Vendor].[Name].Children, ([Measures].[Expense], [Date].[FY].&[" & SelFY & "]))" removes vendors with no spend in the selected year, keeping the list short.
  • Use MDX TopCount: "TopCount([Vendor].[Name].Children, 10, ([Measures].[Expense], [Date].[FY].&[" & SelFY & "]))" returns exactly the top 10 already ordered; use sort_order 0.

A selected-FY cell from a slicer: =CUBERANKEDMEMBER(Conn, Slicer_FY, 1) displays the caption; if captions equal keys (FY2025-26), SelFY can reference that cell's displayed text. Where BU also matters, add it to the tuple.

"Others" line and coverage

Board lists usually show coverage:

  • Top N total: =SUM(B5:B14).
  • All vendors total: =CUBEVALUE(Conn, MsrExpense, Slicer_FY, Slicer_BU).
  • Others = All − Top N; coverage % = Top N / All ("Top 10 vendors = 61.6% of spend").

Ranked lists of other things

  • Cost centres by adverse variance: sort by [Variance Fav/Adv] ascending (sort_order 1) to get the worst first.
  • Customers by overdue receivables (Weeks 17–20 working-capital pack).
  • Ledgers by YoY growth (use a growth measure as sort_by).

Performance

One CUBESET plus N CUBERANKEDMEMBER and N CUBEVALUE cells is far cheaper than a CUBEVALUE for every vendor on a hidden sheet sorted with LARGE/INDEX. Sorting happens once in the engine; each list row is a light lookup. Keep sets as small as possible with NonEmpty or TopCount.

Illustration

FY2025-26, Polymers BU, TopN = 5, set sorted with the FY tuple:

Rank Vendor (CUBERANKEDMEMBER) Expense ₹ Cr (CUBEVALUE)
1 Gujarat Industries Power 8.94
2 Reliance Polymers 7.20
3 IOCL 6.85
4 Gujarat Gas 6.85
5 BASF India 4.10
Others (209 vendors) 67.36
Total 101.30

Coverage = 33.94 / 101.30 = 33.5%. Changing the BU slicer to Agro re-ranks vendors only if the BU is also in the sort tuple; this is the test to run.

Edge cases & judgement calls

  • Ties. Two vendors with equal spend appear in model order; add a tie-break measure (spend + tiny code-based offset) if order matters.
  • Rank beyond count returns #N/A — the IF wrapper with CUBESETCOUNT/MIN prevents it.
  • Captions vs keys. If vendor captions differ from keys (codes as keys), the list shows captions; CUBEVALUE uses the member, so values remain correct.
  • Empty selections. If the selected BU has fewer vendors than N, the list shortens — intended.
  • Multi-select slicers cannot be expressed as a single FY key in the tuple; use a set {[Date].[FY].&[...], ...} or restrict to single selection.
  • Manual calculation mode leaves stale ranks; Refresh All followed by calculation is needed.

Key takeaways

  • Pattern: sorted CUBESET → CUBESETCOUNT → CUBERANKEDMEMBER by ROWS() → CUBEVALUE beside each member.
  • CUBESET ignores slicers unless the context is in the sort_by tuple or set expression.
  • Use NonEmpty or TopCount in MDX to keep sets short and correctly ordered.
  • Show Others and coverage so the list reconciles to the total.
  • Guard rows beyond the set size or N to avoid #N/A.

Practice Questions

Q1. Build the Top 10 [L1]

Write the set, count, member and value formulas for a Top 10 cost centres list by [Actual] for the FY in cell SelFY, including the IF guard.

Q2. Order looks wrong [L2]

A Top 5 vendor list shows values 3.1, 8.9, 2.4, 7.2, 6.9 (₹ Cr) for FY2025-26. Explain why and fix the CUBESET formula.

💡 Hint: Ask in which context the sort measure is evaluated.

Q3. Worst variances first [L2]

Write a CUBESET and list formulas that show the 8 cost centres with the most adverse [Variance Fav/Adv] for the selected FY and BU, with an "All other cost centres" line and a check that the list plus others equals the total variance.

Q4. TopCount vs sorted set [L3]

Compare a TopCount MDX set with a fully sorted CUBESET read by CUBERANKEDMEMBER for a list of the top 20 customers out of 1.8 lakh, considering performance, Others calculation, ties and maintainability. Recommend one.
