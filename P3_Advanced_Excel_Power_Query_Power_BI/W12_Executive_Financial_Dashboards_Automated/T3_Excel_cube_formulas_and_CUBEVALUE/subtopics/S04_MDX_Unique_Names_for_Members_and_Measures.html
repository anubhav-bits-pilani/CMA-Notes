Subtopic note

MDX Unique Names for Members and Measures

Scope: MDX unique-name syntax: [Table].[Column].&[Key] for members and [Measures].[Name] for measures

Why it matters

Every cube formula identifies what it wants by an MDX unique name. Get one character wrong — a space in a column name, a label instead of a key, a date in the wrong format — and the cell returns #N/A, often silently inside a large pack. Understanding the naming grammar lets you write formulas directly, build members from cell text, and debug the board pack quickly. MDX (Multidimensional Expressions) is the query language Excel uses to talk to tabular models through cube formulas and PivotTables.

Core notes

How a tabular model looks to MDX

A Power Pivot or Power BI model exposes each table as a dimension, each column as an attribute hierarchy, and each user hierarchy (e.g. Statement → FSLine → Ledger) as a multi-level hierarchy. Measures live in a special dimension called [Measures].

Model object MDX unique name pattern Example
Measure [Measures].[Measure Name] [Measures].[Actual]
Column member (by key) [Table].[Column].&[Key] [CoA].[FSLine].&[Revenue from operations]
Column member (by name) [Table].[Column].[Name] [BU].[BusinessUnit].[Agro]
All member [Table].[Column].[All] [BU].[BusinessUnit].[All]
Children of All [Table].[Column].Children [Vendor].[Name].Children
Level members [Table].[Column].[Column].Members [Vendor].[Name].[Name].Members
Hierarchy member [Table].[Hierarchy].[Level].&[Key] [CoA].[FS Hierarchy].[Ledger].&[Power and fuel]
Tuple (member1, member2) ([Date].[FY].&[FY2025-26], [Measures].[Budget])
Set {member1, member2} {[Region].[Region].&[North], [Region].[Region].&[West]}

Brackets and the ampersand

  • Square brackets delimit identifiers: [Date Table] allows spaces; brackets are needed even without spaces in practice.
  • &[...] means "member with this key". Without &, [Agro] means "member with this name". In tabular models key and name are usually the same for text columns, but differ for columns with Sort by column (the key can still be the column value) and especially for dates and numbers.
  • A closing bracket inside a name must be doubled: a ledger "Repairs [Plant]" is &[Repairs [Plant]]].
  • Table and column names are the model names, not display captions. Renaming a column in the model changes the unique name and breaks formulas.

Measures

[Measures].[Actual] refers to the explicit DAX measure "Actual". Measure names with special characters are written as-is inside brackets: [Measures].[EBITDA %], [Measures].[Revenue ₹ Cr]. Display folders do not appear in the unique name. Implicit measures created by dragging a numeric column into a PivotTable appear as [Measures].[Sum of Amount] in the workbook Data Model, but are not available through live Power BI connections; use explicit measures.

Keys for different data types

Column type Key format in &[...] Example
Text The text, exact case-insensitive match, including internal spaces &[FY2025-26]
Whole number The number [Date].[FYEnd].&[2026]
Date / datetime ISO-like datetime [Date].[Date].&[2025-10-31T00:00:00]
Boolean &[True] / &[False] [Vendor].[IsMSME].&[True]

The date key is the topic pitfall: the displayed "31-10-2025" or "Oct-25" is a caption, not the key. Build date members with TEXT(d, "yyyy-mm-dd") & "T00:00:00" or avoid date-column members entirely by using text month keys (e.g. a MonthKey column "2025-10").

Finding the right unique name

  • Convert a PivotTable to formulas (s02) and read the generated strings.
  • Excel's IntelliSense: typing =CUBEMEMBER("ThisWorkbookDataModel", "[ shows a dropdown of tables, columns and members — Excel lists available names as you type.
  • DAX Studio connected to the model: the metadata pane shows tables, columns and measures; an MDX query SELECT {} ON 0, [CoA].[FSLine].Members ON 1 FROM [Model] lists members.
  • The cube name for a tabular model is [Model] (relevant only in DAX Studio MDX queries; cube formulas use the connection name).

Illustration

Sahyadri's CoA has FS line "Power & fuel" and a ledger "Freight [inward]". Correct unique names:

"[CoA].[FSLine].&[Power & fuel]"
"[CoA].[Ledger].&[Freight [inward]]]"
"[Date].[MonthEnd].&[2025-10-31T00:00:00]"
"[Measures].[Actual]"
"([Date].[FY].&[FY2025-26], [BU].[BusinessUnit].&[Pharma Intermediates])"

Incorrect: "[CoA].[FS Line].&[Power & fuel]" (column name has no space), "[Date].[MonthEnd].&[31-10-2025]" (caption, not key), "[CoA].[FSLine].&[Power & Fuel ]" (trailing space).

Edge cases & judgement calls

  • Duplicate names across a hierarchy. "Others" under several FS lines: use the hierarchy path or a unique key column (e.g. AccountCode) as the member, and show the name as caption.
  • Leading/trailing spaces and non-breaking spaces from Tally exports make keys differ from labels; clean in Power Query (Text.Trim, Text.Clean, replace character 160).
  • Case. MDX member matching in tabular models is case-insensitive, but keep exact case for readability.
  • Blank members. Unmatched fact rows create a blank member in tabular models (shown as "(blank)" in PivotTables; convert a pivot to formulas to see its exact unique name). CUBEVALUE on it returns orphan amounts — useful as a control (unmapped ledgers).
  • Numbers stored as text (cost centre "0105") must be quoted as text keys &[0105]; numeric typing would drop the leading zero.
  • Localisation. Decimal separators in numeric keys follow invariant culture; avoid decimal keys.

Key takeaways

  • Members: [Table].[Column].&[Key]; measures: [Measures].[Name]; sets in braces, tuples in parentheses.
  • &[...] is by key, [...] by name; prefer keys and clean, stable key columns.
  • Dates use datetime keys, not captions; text month keys avoid the issue.
  • Double a closing bracket inside names; watch spaces and renamed columns.
  • Use Convert to Formulas, IntelliSense and DAX Studio to discover exact names.

Practice Questions

Q1. Write the unique names [L1]

Write MDX unique names for: the measure "Budget EBITDA %"; FY "FY2024-25"; month-end date 31 March 2026 in 'Date'[MonthEnd]; cost centre code "0105" in CostCentre[Code]; and the set of BUs Agro and Polymers.

Q2. Five broken strings [L2]

Diagnose each: (a) "[Date].[FY].[FY2025-26]" returns a value but "[Date].[FY].&[FY 2025-26]" returns #N/A; (b) "[CoA].[Ledger].&[Repairs [Plant]]" errors; (c) "[Measures].[Sum of Amount]" works in the workbook model but not after switching to Power BI; (d) "[Date].[Date].&[31/10/2025]" returns #N/A; (e) "[Vendor].[Name].&[ABC Traders]" returns #N/A although the vendor exists.

💡 Hint: For (e), think about how the vendor master was imported.

Q3. Build date keys from a cell [L2]

Cell B1 holds the date 31-Oct-2025 (a real Excel date). Write a CUBEMEMBER formula that builds the month-end member of 'Date'[MonthEnd] from B1, and propose a model change that would make such formulas unnecessary.

Q4. Unmapped control via the blank member [L3]

Explain how the blank member in a tabular model arises when GL account codes are missing from CoA, and design a cube-formula control cell that shows the amount posted to unmapped accounts for the selected FY.
