Connecting Excel to the Data Model or a Power BI Semantic Model

Scope: Connecting Excel to models: the workbook Data Model (Power Pivot), or a Power BI semantic model via Analyze in Excel

Why it matters

Boards and audit committees in India still receive the monthly pack as an Excel or PDF document laid out in Schedule III format, with variance columns and commentary. Power BI is excellent for exploration but poor at pixel-exact, free-form statement layouts. The answer is not to re-key numbers into Excel but to connect Excel to the same model that feeds Power BI and pull numbers with cube formulas. The first decision is which model Excel connects to: the workbook's own Data Model (Power Pivot), or a published Power BI semantic model through Analyze in Excel. That choice determines refresh, security, file size and whether the Excel pack and the Power BI report are guaranteed to agree.

Core notes

Option 1: the workbook Data Model (Power Pivot)

The Data Model is an in-memory VertiPaq (tabular) engine inside the .xlsx file, the same engine family as Power BI. Tables loaded from Power Query with Add this data to the Data Model, relationships in the Power Pivot diagram view, and DAX measures (Power Pivot > Measures, or right-click a table in the PivotTable field list > Add Measure) make it a full star schema.

  • Connection name: ThisWorkbookDataModel — fixed and used as the first argument of every cube formula.
  • Refresh: Data > Refresh All re-runs Power Query and reloads the model; the cube formulas then recalculate.
  • When to use: a standalone Excel pack, smaller data (a few million rows is fine), no Power BI licence, or when the finance team owns the workbook end to end.
  • Limits: the file carries the data (size grows), two people cannot co-author model changes, and the measure library may drift from the Power BI model unless both are generated from one source.

Enable the Power Pivot add-in (File > Options > Add-ins > COM Add-ins > Microsoft Power Pivot for Excel) to edit the model; consumers do not need it to use cube formulas.

Option 2: a Power BI semantic model via Analyze in Excel

A published semantic model can be queried from Excel with a live connection:

  • In the Power BI Service: open the semantic model or report > Export > Analyze in Excel (downloads a workbook with a connected PivotTable), or
  • In Excel: Data > Get Data > From Power Platform > From Power BI (or Insert > PivotTable > From Power BI), then pick the semantic model.

Excel talks to the model over the XMLA/MSOLAP protocol (the provider is installed with recent Microsoft 365 builds). No data is imported — every PivotTable and cube formula sends queries to the Service.

  • Connection name: Excel creates a connection whose name typically contains the workspace/model identity — check Data > Queries & Connections > Connections. Concept c06: this name replaces ThisWorkbookDataModel in every cube formula. Rename the connection to something short (e.g. PBI_FinancePack) before writing formulas.
  • Permissions: users need Build permission on the semantic model (granted directly or via workspace Contributor and above, or via an App setting).
  • Security: RLS defined on the model applies to Excel users — a BU head's board pack shows only their BU.
  • Sensitivity labels: a label on the semantic model (e.g. "Confidential – Finance") is inherited by the Excel file when the connection is created, if the tenant enables inheritance (related item in the topic).
  • Refresh: the model refreshes in the Service (scheduled refresh, gateway); Excel's Refresh All only re-queries.

Comparing the options

Aspect Workbook Data Model Power BI semantic model
Where data lives Inside the .xlsx Power BI Service
Measure library Separate copy unless synchronised Same as the Power BI report (single source of truth)
Refresh Excel Refresh All (needs source access) Scheduled in the Service; Excel re-queries
Security File-level only RLS, workspace roles, sensitivity labels
Offline use Yes No (needs connectivity and sign-in)
File size Grows with data Small
Licence Excel only Power BI Pro/PPU or Premium/Fabric capacity

For Project 3, the target architecture is Option 2: one semantic model feeding both the Power BI pack and the Excel board pack. Option 1 is the fallback for users without Power BI, and the learning environment for cube formulas.

Getting from a PivotTable to cube formulas

Whichever model you use, start by building a PivotTable on it (Insert > PivotTable > From Data Model, or the Analyze in Excel PivotTable), then convert to formulas (s02) or write CUBE functions directly (s03).

Edge cases & judgement calls

  • Implicit vs explicit measures. Live connections expose only measures defined in the model; implicit "Sum of Amount" may not be available. Always use explicit measures.
  • Desktop-only models. Excel cannot connect live to a PBIX open in Power BI Desktop for production use (developers can via the local port with external tools); publish first.
  • Mixed connections. A cube formula cannot combine members from two connections; one sheet section, one connection.
  • Calculation groups and field parameters behave differently in Excel PivotTables; test before relying on them.
  • Authentication prompts. Users outside the tenant or with expired sessions see sign-in prompts and #N/A; include a "Refresh/sign-in" instruction in the user guide.
  • Version. Older Excel versions (2016 perpetual) may lack the Power BI connector; standardise on Microsoft 365.

Key takeaways

  • Excel cube formulas can target the workbook Data Model (ThisWorkbookDataModel) or a Power BI semantic model.
  • The Power BI semantic model route gives one measure library, RLS, sensitivity labels and Service refresh.
  • Users need Build permission on the semantic model; RLS applies to their Excel queries.
  • Rename the live connection to a short stable name before writing formulas.
  • Use explicit measures only; implicit measures are not reliable through live connections.

Practice Questions

Q1. Choose the connection [L1]

For each scenario choose the Data Model or a Power BI semantic model and justify: (a) a 3-person finance team with no Power BI licences; (b) a listed group with 40 BU heads needing BU-restricted board packs; (c) an offline board pack reviewed on a flight.

Q2. Permission failure [L2]

A BU controller opens the Excel board pack connected to the "Finance Pack" semantic model and every cube cell shows #N/A after refresh, while the CFO's copy works. List the access and connectivity causes you would check, in order.

💡 Hint: Separate sign-in, permission, RLS and connection-name causes.

Q3. Migration plan [L3]

The board pack currently uses ThisWorkbookDataModel with 1,200 cube formulas. Write a migration plan to a Power BI semantic model that keeps the pack working at each step, including connection naming, formula changes, measure reconciliation and a parallel-run test.
