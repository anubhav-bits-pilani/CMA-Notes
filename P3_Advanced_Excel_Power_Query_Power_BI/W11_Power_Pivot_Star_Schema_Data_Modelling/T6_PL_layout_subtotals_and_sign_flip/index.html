Roadmap topic: P&L Subtotal & Sign-Flip Logic: Using SWITCH(TRUE(), ...) in DAX to render formatted P&L statements with Gross Profit, EBITDA, and EBIT margins inside Pivot/Matrix visuals

Overview

A statement of profit and loss is a designed document: account groups in a prescribed order, interleaved with computed subtotals (Gross Profit, EBITDA, EBIT, PBT, PAT), margin rows, headings and spacing, with income shown positive whatever the ledger's debit/credit convention. A BI model's natural output — a matrix of accounts with an automatic total — is not that document. This topic closes the gap with four pieces: a layout dimension that makes the statement's structure data; a sign convention that keeps arithmetic simple and presentation familiar; a dispatcher measure that routes each row to the right calculation with SWITCH(TRUE(), …) and SELECTEDVALUE; and formatting that makes the matrix look like the board pack.

For FP&A and reporting roles this is the capstone of the week. The monthly MIS P&L, the Actual / Budget / Variance pack of Weeks 17–20, the quarterly results deck and the CFO's dashboard all render from it. It also concentrates the most common, most visible bugs — blank subtotal rows, revenue showing negative, favourable variances coloured red — so reviewers and interviewers probe it hard.

Learning sequence: design the layout table (s01); map the CoA to its lines and compute subtotals from sort-order ranges (s02, c03); decide the sign convention and implement Actual Signed (s04, c02); build the dispatcher (s03, c01); add margin rows with dynamic format strings (s05, c04); format the matrix and blank meaningless totals (s06, c05); and evaluate alternatives — calculation groups, field parameters, visual calculations, Excel PivotTables (s07).

Related concepts to study

Weeks 1–4: Schedule III Division II P&L format

→ Week 1–4: Schedule III Division II P&L format and Ind AS line items

Schedule III Division II (Ind AS companies) prescribes the statement of profit and loss: Revenue from operations, Other income, Total income; expenses by nature (cost of materials consumed, purchases of stock-in-trade, changes in inventories, employee benefits expense, finance costs, depreciation and amortisation, other expenses), Total expenses; profit before exceptional items and tax; exceptional items; tax (current and deferred); profit for the period; OCI split into items that will and will not be reclassified to P&L; total comprehensive income; EPS. Your statutory layout table should mirror it exactly, with range subtotals for Total income and Total expenses. EBITDA is not a Schedule III line (though Schedule III permits companies to present EBITDA as a separate line item on the face of the statement) — keep it in the MIS layout.

Weeks 17–20: MIS P&L with variance columns

→ Week 17–20: MIS P&L with Actual / Budget / Variance columns and favourable/adverse logic

The budgeting weeks add Budget and Forecast scenarios to the same layout. In a profit-signed model, Var ₹ = Actual − Budget is favourable when positive on every line — revenue above budget and costs below budget both give positive variances — so one conditional-formatting rule (green > 0) works for the whole statement. If expenses are displayed as positive numbers, the favourable rule must be reversed on expense lines using the layout's display sign. Var % on margin rows becomes a basis-point variance, and YTD columns use the capped YTD logic from Topic 4.

Calculation groups for scenario columns

Calculation groups for switching Actual / Budget / PY columns

Instead of writing PnL Actual, PnL Budget, PnL PY, PnL Var ₹ and PnL Var % measures, a Scenario View calculation group applies each view to the single [PnL] dispatcher via SELECTEDMEASURE(). Put the group's column on the matrix columns and the dispatcher in values: rows come from the layout table, columns from the calculation group. Format string expressions per item (Var % as percentage, others deferring to SELECTEDMEASUREFORMATSTRING()) keep the dynamic ₹/% formatting intact. Remember precedence if a Time Calc group (YTD, PY) is also present.

Week 12: Excel cube formulas for board packs

→ w12_t3: Excel cube formulas for fixed board-pack layouts

When a board pack must have a fixed, formatted layout — bold subtotals, commentary boxes, specific cells referenced by charts — Excel cube formulas read individual values from the Power Pivot or published Power BI model: CUBEMEMBER picks a layout line, a period and a scenario; CUBEVALUE returns [PnL] for that intersection. The layout table and dispatcher built here are exactly what those formulas query, so the same logic serves the interactive Power BI matrix and the static Excel pack, with one source of truth.

Common pitfalls

Blank subtotal rows

Subtotal rows show blank because the layout row filters out every account and the layout filter was not removed

Mistake: computing the subtotal with CALCULATE([Actual Signed], Layout[SortOrder] < s, …) without REMOVEFILTERS(Layout). Why: a boolean filter on SortOrder replaces only that column's filter, and people assume it replaces the row filter. Correct treatment: capture s in a variable, then REMOVEFILTERS(Layout) and re-filter to Account lines below s (c03). Detect it: every Subtotal and Ratio row is blank while Account rows are correct; evaluating the measure in DAX query view with only Layout[LineID] = "PL040" returns blank.

Flipping signs twice or inconsistently

Flipping signs twice (in Power Query and in DAX), or inconsistently between Actual and Budget

Mistake: Power Query multiplies revenue by −1 and DAX applies a −1 SignFactor again; or the GL is natural-signed while the budget upload has revenue and costs positive. Why: different people own the Power Query and DAX layers, and budget templates are designed for planners. Correct treatment: store natural signs, flip once in DAX, normalise the budget to natural signs in Power Query, and document the convention in the model. Detect it: revenue shows negative; variances are roughly twice the expected size; Actual and Budget revenue have opposite signs; the profit-signed sum of all lines does not equal PAT in the TB.

Favourable/adverse not reversed for expenses

Favourable/adverse variance logic not reversed for expense lines

Mistake: colouring Actual − Budget > 0 green on every row when expenses are displayed as positive numbers, so a cost overrun shows green. Why: the rule is right for revenue and is copied down. Correct treatment: compute variances in the profit-signed convention (positive always favourable) or multiply by the layout's display sign before applying the rule; for Ratio rows, use percentage-point logic. Detect it: review a line where costs clearly exceeded budget and check its colour; test a matrix with one deliberately adverse expense line.

Hard-coded LineIDs in SWITCH

Hard-coding LineIDs inside SWITCH without a layout table, which makes restructuring painful

Mistake: SWITCH(TRUE(), lid = "PL040", [Gross Profit], lid = "PL070", [EBITDA], lid = "PL075", [EBITDA %], …) with one branch per line, or a calculated row list in DAX. Why: it is the quickest way to make the first version work. Correct treatment: dispatch on Layout[Type] and drive subtotals and ratios from layout columns (SortOrder, SubtotalFrom/To, RatioNumeratorLine/DenominatorLine), so new lines need only table edits. Detect it: the dispatcher has more branches than there are line types; adding "Exceptional items" requires editing DAX in several measures.

Practice Questions

Q1. Build the MIS P&L end to end [L3]

A listed auto-components company has a GL with natural signs and a CoA of 180 P&L accounts. YTD December FY26 profit-signed values by line (₹ crore): Revenue 1,240; Cost of materials −742; Changes in inventories 8; Employee −118; Other expenses −171; D&A −52; Other income 14; Finance costs −29; Exceptional items (VRS) −12; Tax −34. Budget: Revenue 1,300; Materials −780; Changes in inventories 0; Employee −112; Other expenses −176; D&A −50; Other income 10; Finance costs −31; Exceptional 0; Tax −40. (a) Design the layout table with sort orders, types and ratio references, placing Other income below EBIT and exceptional items between PBT-before-exceptional and PBT. (b) Write Actual Signed, Subtotal, Margin % and PnL measures and the dynamic format string. (c) Compute every row for Actual, Budget, Var ₹ and Var % (margins in bps). (d) State the conditional-formatting rule for favourable/adverse.

💡 Hint: Fix the sign convention first; then subtotals are running sums and variances have a single favourable direction.

Q2. Debug a broken P&L matrix [L2]

A matrix shows Revenue −₹ 1,240 crore, blank Gross Profit and EBITDA rows, EBITDA % as left-aligned text, a "Total" row of ₹ 2,870 crore at the bottom, and missing "Expenses" header and spacer rows. Diagnose each symptom, naming the DAX or setting at fault, and write the corrected measures and settings.

Q3. Statutory and MIS formats from one model [L3]

Design a model that renders both a Schedule III Division II statement (with Total income, Total expenses, exceptional items, OCI and total comprehensive income) and an MIS format (GP, EBITDA, EBIT with margins) from the same GL and CoA. Specify the tables and relationships, how the user switches formats, how range and cumulative subtotals coexist, how OCI accounts are excluded from the MIS view, and the reconciliation check showing both formats give the same profit for the period.

Q4. Choose the rendering approach [L2]

The CFO wants (i) an interactive monthly P&L with drill to GL vouchers, (ii) a quarterly board pack in a fixed format with true bold subtotals and commentary, and (iii) a KPI page where the user picks EBITDA, EBITDA % or PAT and compares to Budget or PY. Recommend for each the combination of layout table, calculation groups, field parameters, visual calculations, Excel PivotTables or cube formulas, and list the tests you would run before go-live.
