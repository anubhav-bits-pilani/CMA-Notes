Key concept

The PnL Dispatcher Measure with SWITCH(TRUE())

Concept: PnL = VAR t = SELECTEDVALUE(Layout[Type]) RETURN SWITCH(TRUE(), t = "Account", [Actual Signed], t = "Subtotal", [Subtotal], t = "Ratio", [Margin %])

Statement

PnL =
VAR t = SELECTEDVALUE ( Layout[Type] )
RETURN
    SWITCH (
        TRUE (),
        t = "Account",  [Actual Signed],
        t = "Subtotal", [Subtotal],
        t = "Ratio",    [Margin %]
    )

For a matrix row with layout type \(t\):

\[ \text{PnL} = \begin{cases} \text{Actual Signed} & t = \text{Account} \\ \text{Subtotal} & t = \text{Subtotal} \\ \text{Margin \%} & t = \text{Ratio} \\ \text{BLANK} & \text{otherwise (Header, Spacer, totals)} \end{cases} \]

Explanation

The measure is a router. SELECTEDVALUE(Layout[Type]) reads the type of the layout line in the current filter context; when exactly one line is visible (a matrix row) it returns that line's type, and at a grand total or a multi-line selection it returns BLANK. SWITCH(TRUE(), …) tests each condition in order and returns the result of the first TRUE one; with no else argument the result is BLANK, which covers Header and Spacer rows and the grand total.

Why this design works:

  • One value field per column. The matrix uses [PnL] for every row, so Actual, Budget and PY columns each need only one measure (or one calculation-group item applied to [PnL]).
  • Separation of concerns. Each branch is a small measure that can be tested independently: [Actual Signed] against the TB, [Subtotal] against a manual sum, [Margin %] against Excel.
  • Layout-driven. Adding a line only requires a new layout row of an existing type; the dispatcher does not change.

Conditions: the matrix rows must be at layout-line grain (unique labels), the Layout table must relate to CoA (so Account rows filter GL), and the branch measures must handle their own filter manipulation (REMOVEFILTERS(Layout) in [Subtotal], line references in [Margin %]). All branches should return numbers; format with a dynamic format string (c04) rather than returning text.

SWITCH(t, "Account", …, "Subtotal", …, "Ratio", …) is equivalent here because every test is on t. The TRUE() form is preferred as a habit because rules soon combine conditions (t = "Subtotal" && hasRange), and it reads like a CASE WHEN in SQL or an if-else chain in Java.
