Key concept

Blanking P&L Grand Totals with ISINSCOPE

Concept: IF(ISINSCOPE(Layout[Line]), [PnL]) blanks meaningless grand totals in the P&L matrix

Statement

PnL (scoped) = IF ( ISINSCOPE ( Layout[Line] ), [PnL] )

ISINSCOPE(column) returns TRUE when the column is being used as a grouping level in the current cell of the visual (the cell is "inside" a Layout[Line] row) and FALSE at subtotal or grand-total levels where that column is not grouped. The measure therefore returns [PnL] on every statement row and BLANK on the matrix's automatic total row.

Explanation

A P&L built from a layout table already contains its own subtotals (GP, EBITDA, PAT). The matrix's automatic grand total row evaluates the measure with no layout filter: everything is in context. What it shows depends on the dispatcher — SELECTEDVALUE(Layout[Type]) returns BLANK when several types are visible, so [PnL] may already be blank; but a measure such as [Actual Signed] or a Budget/Variance column might show a "total" equal to the sum of every account (which is PAT in profit-signed form — coincidentally meaningful) or worse, a sum of mixed lines in display-signed form. For ratio-heavy statements, any non-blank grand total is noise. Turning off row subtotals in the format pane hides it, but a measure-level guard is more robust because it also applies in other visuals, exports and Analyze in Excel.

Why ISINSCOPE rather than HASONEVALUE:

  • HASONEVALUE(Layout[Line]) is TRUE whenever exactly one line is filtered — including when a slicer selects one line and the matrix shows only a grand total. It cannot tell "a row of the matrix" from "a filtered total".
  • ISINSCOPE(Layout[Line]) tests whether the visual is grouping by that column at the current level — exactly the "am I on a statement row?" question. It is the standard function for level-aware calculations in hierarchies (e.g., showing % of parent only at child levels).

In a drill-down hierarchy (Layout line → Account), use ISINSCOPE(CoA[AccountName]) to detect account level and ISINSCOPE(Layout[Line]) for line level; the line-level total of a drilled line is then the line's value, while the grand total is blank.

Illustration

Matrix rows Layout[Line], columns Actual and Budget, row subtotals left on (₹ lakh, profit-signed, display flip on expenses):

Row [PnL] Actual [PnL (scoped)] Actual
Revenue from operations 4,100 4,100
Cost of materials consumed 2,380 (display +) 2,380
Gross Profit 1,720 1,720
GM % 42.0% 42.0%
Total (automatic) blank, or a mixed sum such as 8,200 from a non-dispatcher column blank

The scoped measure guarantees a blank total regardless of how individual column measures behave at the top level.

Q1. ISINSCOPE vs HASONEVALUE [L1]

Q2. Drill-down totals [L2]

The matrix has a hierarchy Layout line → Account, with drill-down expanded on "Other expenses". Write a measure that shows values at account and line level, blanks the grand total, and shows the account's share of its line (as a separate measure) only at account level.

💡 Hint: Test the deeper level first in a SWITCH(TRUE(), …).

Q3. When a total is meaningful [L2]

Explain why, in a profit-signed model, the sum of all account lines across the whole P&L equals PAT, and argue whether the matrix should nonetheless show a grand total row. Consider display-flipped expense lines and ratio rows in your answer.
