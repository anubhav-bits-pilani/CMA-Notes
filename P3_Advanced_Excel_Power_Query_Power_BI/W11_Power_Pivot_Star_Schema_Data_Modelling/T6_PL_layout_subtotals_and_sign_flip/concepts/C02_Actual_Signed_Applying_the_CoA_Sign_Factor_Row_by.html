Key concept

Actual Signed: Applying the CoA Sign Factor Row by Row

Concept: Actual Signed = SUMX(GL, GL[Amount] * RELATED(CoA[SignFactor]))

Statement

Actual Signed = SUMX ( GL, GL[Amount] * RELATED ( CoA[SignFactor] ) )

\[ \text{Actual Signed} = \sum_{r \in \text{GL}} \text{Amount}_{r} \times \text{SF}\big(\text{Account}_{r}\big) \]

where \(\text{Amount}_{r}\) is the natural-signed amount on GL row \(r\) (debit positive, credit negative) and \(\text{SF}(a)\) is the sign factor of account \(a\) in the CoA (−1 for P&L accounts in the profit-signed convention, so income becomes positive and expenses negative).

Explanation

SUMX iterates the GL rows visible in the current filter context. For each row, RELATED(CoA[SignFactor]) follows the many-to-one relationship from GL to CoA and fetches the account's sign factor — RELATED works because the iterator creates a row context on the many side. The product is summed.

Why a per-account sign factor rather than a blanket -[Actual]:

  • Mixed statements. A BS layout needs +1 for assets and −1 for liabilities/equity, while P&L lines need −1; a single measure serves both if the factor lives in the CoA.
  • Contra accounts (sales returns within revenue, accumulated depreciation within PPE) keep their natural sign and are handled correctly by the same factor as their parent line.
  • Transparency. The sign rule is visible data that a reviewer can audit in the CoA table.

Performance: iterating every GL row is fine for a few million rows, but an equivalent that iterates only the distinct sign values is faster on large facts:

Actual Signed (fast) =
SUMX ( VALUES ( CoA[SignFactor] ), CoA[SignFactor] * [Actual] )

Here [Actual] (a measure) is evaluated for each distinct sign factor through context transition — usually two iterations instead of millions.

Rules to keep the sign consistent:

  • Flip in one place only — if Power Query has already flipped revenue, set factors to +1 or remove the Power Query step.
  • Apply the same factor to Budget (Budget Signed) after normalising the budget to the GL's natural convention.
  • Compute subtotals from Actual Signed, never from display-flipped values.

Illustration

GL rows for October 2025 (₹ lakh):

Account Amount (natural) SignFactor Product
Sales of products −3,450 −1 3,450
Sale of services −250 −1 250
Sales returns 100 −1 −100
Raw material consumed 2,050 −1 −2,050
Freight inward 40 −1 −40

Actual Signed for Revenue from operations = 3,450 + 250 − 100 = 3,600; for Cost of materials = −2,090; Gross Profit = 1,510. The same rows with a blanket -[Actual] would give the same P&L numbers, but the per-account factor also serves a balance-sheet layout from the same measure.

Q1. Compute signed values [L1]

Q2. Fast version [L2]

Explain step by step how SUMX(VALUES(CoA[SignFactor]), CoA[SignFactor] * [Actual]) arrives at the same result as the row-by-row version on a matrix row for "Revenue from operations", including the role of context transition. Under what CoA design would it return a wrong answer?

Design SignFactor values for a balance sheet layout (PPE, accumulated depreciation, receivables, ECL allowance, cash, share capital, retained earnings, borrowings, payables) so that Actual Signed presents assets and claims as positive, and state the check that proves the balance sheet balances.
