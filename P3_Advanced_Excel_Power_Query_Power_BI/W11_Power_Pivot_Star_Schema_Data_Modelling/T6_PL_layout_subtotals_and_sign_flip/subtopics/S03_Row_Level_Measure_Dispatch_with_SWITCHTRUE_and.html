Subtopic note

Row-Level Measure Dispatch with SWITCH(TRUE()) and SELECTEDVALUE

Scope: Measure dispatch per row with SWITCH(TRUE(), ...) and SELECTEDVALUE

Why it matters

A P&L matrix has a single values field, yet different rows need different calculations: account lines sum their mapped GL postings, subtotal rows sum everything above, ratio rows divide one subtotal by revenue, headers and spacers show nothing. The bridge is one dispatcher measure that inspects which layout row it is being evaluated for and calls the right sub-measure. This is the same idea as a switch statement in Java or a CASE WHEN in SQL, applied to filter context. It keeps the matrix to one measure per column (Actual, Budget, PY, Variance) and makes the statement render correctly at every row.

Core notes

SELECTEDVALUE

SELECTEDVALUE ( <column> [, <alternate_result>] )

Returns the single value of the column if the filter context contains exactly one distinct value; otherwise returns the alternate result (BLANK by default). On a P&L matrix row, SELECTEDVALUE(Layout[Type]) returns that row's type; at the grand total (all lines visible) it returns BLANK. It is shorthand for IF(HASONEVALUE(col), VALUES(col), alt).

SWITCH(TRUE(), …)

SWITCH(expression, value1, result1, value2, result2, …, else) compares an expression against values. Writing SWITCH(TRUE(), condition1, result1, condition2, result2, …, else) evaluates conditions in order and returns the result of the first that is TRUE — an if-else-if chain that is easier to read than nested IFs.

The dispatcher

PnL =
VAR t = SELECTEDVALUE ( Layout[Type] )
RETURN
    SWITCH (
        TRUE (),
        t = "Account",  [Actual Signed],
        t = "Subtotal", [Subtotal],
        t = "Ratio",    [Margin %],
        BLANK ()                          -- Header, Spacer, grand total
    )

Because the condition is on a single value, SWITCH(t, "Account", [Actual Signed], "Subtotal", [Subtotal], "Ratio", [Margin %]) is equivalent; SWITCH(TRUE(), …) becomes necessary when conditions combine several columns:

PnL (extended) =
VAR t   = SELECTEDVALUE ( Layout[Type] )
VAR lid = SELECTEDVALUE ( Layout[LineID] )
VAR hasRange = NOT ISBLANK ( SELECTEDVALUE ( Layout[SubtotalFrom] ) )
RETURN
    SWITCH (
        TRUE (),
        t = "Account",                [Actual Signed],
        t = "Subtotal" && hasRange,   [Subtotal (range)],
        t = "Subtotal",               [Subtotal],
        t = "Ratio",                  [Margin %],
        t = "Memo",                   [Actual Signed],
        BLANK ()
    )

Evaluation behaviour

  • Lazy evaluation of branches. DAX generally evaluates only the branch that is selected, so a subtotal row does not compute [Margin %]. In complex measures the engine may still compute branches eagerly for performance; keep each branch cheap and side-effect-free.
  • Data types. All branches should return the same type (number). Returning text ("n.m.") from one branch makes the whole measure a variant that some visuals and exports treat as text. Prefer BLANK plus a format string or a separate commentary column.
  • Parameterising by scenario. The same dispatcher works for Budget by swapping [Actual Signed] for [Budget Signed]. To avoid duplicating the dispatcher for Actual, Budget and PY, use a scenario column on a unified fact or a calculation group (s07).

Column measures built on the dispatcher

PnL Actual   = [PnL]
PnL Budget   = CALCULATE ( [PnL], Scenario[Scenario] = "Budget" )      -- unified fact with scenario column
PnL Var ₹    = [PnL Actual] - [PnL Budget]
PnL Var %    =
VAR t = SELECTEDVALUE ( Layout[Type] )
RETURN
    IF ( t <> "Ratio", DIVIDE ( [PnL Var ₹], ABS ( [PnL Budget] ) ) )

For Ratio rows, the variance of a margin is in percentage points ([PnL Actual] - [PnL Budget] already gives that) and a "variance %" of a percentage is meaningless — blank it.

Worked illustration

Matrix for November 2025 (₹ lakh, profit-signed):

Line Type SELECTEDVALUE(Layout[Type]) Branch called Value
Revenue from operations Account "Account" [Actual Signed] 4,100
Cost of materials consumed Account "Account" [Actual Signed] −2,380
Gross Profit Subtotal "Subtotal" [Subtotal] 1,720
GM % Ratio "Ratio" [Margin %] 41.95%
Expenses (header) Header "Header" BLANK() (blank)
Grand total — BLANK BLANK() (blank)

Debugging the dispatcher

  • Add a temporary measure Row Type = SELECTEDVALUE(Layout[Type], "<multiple>") next to [PnL] to see what each row reports.
  • If a row shows "", the matrix row field is not at layout-line grain (e.g., label not unique, two LineIDs sharing a label).
  • Evaluate a single row in DAX query view:
EVALUATE
CALCULATETABLE (
    ROW ( "PnL", [PnL], "Type", SELECTEDVALUE ( Layout[Type] ) ),
    Layout[LineID] = "PL070",
    'Date'[FY] = "FY26"
)

Edge cases & judgement calls

  • Hard-coded LineIDs in SWITCH (lid = "PL070", [EBITDA]) work but turn every layout change into a DAX change; keep the dispatch on Type and drive specifics from layout columns (topic pitfall).
  • Drill-down to accounts: if users expand a layout line to accounts (Layout[Line] → CoA[AccountName]), account rows still have one Layout type ("Account"), so the dispatcher works; subtotal rows have no children.
  • Multiple layout lines selected in a slicer: SELECTEDVALUE returns BLANK in cards; for KPI cards use dedicated measures ([EBITDA]), not the dispatcher.
  • Excel PivotTables: the dispatcher works identically in Power Pivot; Excel shows blank rows unless "Show items with no data on rows" is enabled.
  • Readability: keep sub-measures small and named ([Subtotal], [Margin %]); the dispatcher should be a router, not a 200-line formula.

Key takeaways

  • SELECTEDVALUE(Layout[Type]) identifies the row type; it is BLANK at totals and multi-selections.
  • SWITCH(TRUE(), …) is an ordered if-else chain — use it when conditions combine several columns.
  • The dispatcher routes Account, Subtotal and Ratio rows to small, testable sub-measures and returns BLANK otherwise.
  • Keep branch return types numeric; use format strings, not text, for presentation.
  • Blank variance % on ratio rows; margin variances are percentage points.

Practice Questions

Q1. Write the dispatcher [L1]

Write a PnL measure that handles Account, Subtotal (cumulative), Subtotal (range), Ratio, Memo, Header and Spacer rows, given sub-measures [Actual Signed], [Subtotal], [Subtotal (range)] and [Margin %].

Q2. SWITCH value versus SWITCH(TRUE()) [L1]

Explain when SWITCH(SELECTEDVALUE(Layout[Type]), …) is sufficient and give two examples of P&L rendering rules that require SWITCH(TRUE(), …).

Q3. Multiple-value rows [L2]

After a layout edit, the "Other expenses" row of the matrix shows blank while the label appears twice in the layout table (LineIDs PL060 and PL065, both labelled "Other expenses"). Explain the mechanism through SELECTEDVALUE and propose two fixes.

💡 Hint: Think about how many distinct Type or LineID values are visible on that matrix row.

Q4. Actual, Budget and Variance columns [L3]

Design the measures for a matrix with columns Actual, Budget, Var ₹ and Var % for November 2025 and YTD, using one dispatcher and a unified fact with a Scenario column. For the data — Revenue Actual 4,100 / Budget 4,300; Materials −2,380 / −2,450; Employee −610 / −590 (₹ lakh) — compute every cell for Revenue, Materials, Gross Profit, GM %, Employee and the EBITDA-so-far subtotal, and explain how Var % should behave on the GM % row.
