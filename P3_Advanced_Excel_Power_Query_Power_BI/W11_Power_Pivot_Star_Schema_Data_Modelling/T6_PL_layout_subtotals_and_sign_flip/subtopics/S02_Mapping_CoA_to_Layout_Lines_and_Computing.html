Subtopic note

Mapping CoA to Layout Lines and Computing Subtotals by Sort Order

Scope: Mapping CoA to layout lines; computing subtotals (Gross Profit, EBITDA, EBIT, PBT, PAT) from sort-order ranges

Why it matters

Once the layout table exists, two pieces of logic make the P&L work: every GL account must land on exactly one printed line, and every subtotal row must compute the right aggregate of the lines above it. Get the mapping wrong and revenue leaks into "Unmapped" or EBITDA silently includes depreciation; get the subtotal logic wrong and the Gross Profit row is blank or double-counts. A sort-order-driven subtotal is the standard pattern because it lets the controller insert a new line ("Exceptional items" between EBIT and PBT) without changing any DAX.

Core notes

Mapping accounts to lines

Add LineID to the CoA (one column per layout if you maintain several). Mapping rules:

Account group LineID Line
4000–4099 Sales of products, 4100 Sale of services, 4150 Other operating revenue PL010 Revenue from operations
5000–5099 Raw material consumption PL020 Cost of materials consumed
5100 Changes in inventories of FG/WIP PL030 Changes in inventories
6000–6099 Salaries, PF, gratuity, staff welfare PL050 Employee benefits expense
6500–6999 Power, rent, repairs, travel, CSR, etc. PL060 Other expenses
7000 Depreciation, 7010 Amortisation, 7020 ROU depreciation PL080 Depreciation and amortisation
8000 Interest income, 8010 Dividend, 8020 FX gain PL100 Other income
7500 Interest on borrowings, 7510 Lease interest PL110 Finance costs
9000 Current tax, 9010 Deferred tax PL130 Tax expense

Mapping is maintained by the controller (Week 10: CoA mapping table with FS lines) and validated each refresh: zero unmapped P&L accounts, and the sum over all Account lines equals the P&L total of the GL.

The subtotal idea: running totals in statement order

In a profit-signed convention (income positive, expenses negative), each common P&L subtotal is the sum of all account lines above it:

\[ \text{Subtotal}_{s} = \sum_{\ell \,:\, \text{Type}_{\ell} = \text{Account},\ \text{SortOrder}_{\ell} < s} \text{Value}_{\ell} \]

where \(s\) is the sort order of the subtotal row and \(\text{Value}_{\ell}\) the profit-signed value of account line \(\ell\). With the example layout (Topic overview / s01):

  • Gross Profit (40) = Revenue (10) + Materials (20) + Changes in inventories (30)
  • EBITDA (70) = Gross Profit lines + Employee (50) + Other expenses (60)
  • EBIT (90) = EBITDA lines + D&A (80)
  • PBT (120) = EBIT lines + Other income (100) + Finance costs (110)
  • PAT (140) = PBT lines + Tax (130)

DAX

Actual Signed = SUMX ( GL, GL[Amount] * RELATED ( CoA[SignFactor] ) )

Subtotal =
VAR s = MAX ( Layout[SortOrder] )
RETURN
    CALCULATE (
        [Actual Signed],
        REMOVEFILTERS ( Layout ),
        Layout[SortOrder] < s,
        Layout[Type] = "Account"
    )

Why REMOVEFILTERS(Layout): the matrix row "Gross Profit" filters Layout[LineID] = "PL040", which has no CoA accounts; any measure evaluated under that filter returns blank. Removing the Layout filter and replacing it with "Account lines above sort order 40" sends the right accounts through CoA to GL. Note that the other filters (Date, Branch, Cost Centre, Scenario) stay intact — only the Layout filter is replaced.

Explicit ranges for non-cumulative subtotals

Some subtotals are not running totals: Schedule III "Total income" (revenue + other income), "Total expenses", or an MIS "Total opex" block. Store explicit range bounds on the subtotal row:

Subtotal (range) =
VAR fromS = SELECTEDVALUE ( Layout[SubtotalFrom] )
VAR toS   = SELECTEDVALUE ( Layout[SubtotalTo] )
RETURN
    CALCULATE (
        [Actual Signed],
        REMOVEFILTERS ( Layout ),
        Layout[SortOrder] >= fromS,
        Layout[SortOrder] <= toS,
        Layout[Type] = "Account"
    )

Use the range version when SubtotalFrom is populated and the cumulative version otherwise. For "Total expenses" in profit-signed form, the value is negative; flip on display if the statement prints it positive (s04).

Revenue from operations 10 Account 480.0

Each subtotal equals the sum of all Account values with lower sort order; the ratio rows (s05) divide by revenue 480.0. A positive "Changes in inventories" reflects an inventory build-up (credit to P&L).

Edge cases & judgement calls

  • Sort-order gaps: number in tens so a new line (e.g., "Exceptional items" at 115) can be inserted; the cumulative subtotal automatically includes it in PBT and PAT. Check that insertion is intended for every subtotal below.
  • Lines that should not flow into subtotals below: a memo line ("of which: CSR expense") placed in the statement must have a Type other than Account (e.g., Memo) or it will be double-counted.
  • Ratio and Header rows are excluded by Layout[Type] = "Account".
  • Account mapped to a subtotal line by mistake: its value vanishes from the subtotal (the subtotal row computes from Account lines only) and appears nowhere. Validation: no CoA account may map to a non-Account line.
  • Performance: MAX(Layout[SortOrder]) and CALCULATE per row is cheap — layout tables have tens of rows.
  • OCI and EPS: OCI items (Ind AS 1 paragraph on items that will/will not be reclassified) follow PAT; EPS (Ind AS 33) is a ratio row with a share-count denominator, not a P&L line sum.

Key takeaways

  • Map every P&L account to exactly one Account line; validate unmapped and mis-mapped accounts every refresh.
  • In profit-signed form, GP/EBITDA/EBIT/PBT/PAT are running totals of Account lines above them.
  • The subtotal measure replaces the Layout filter (REMOVEFILTERS(Layout)) with a sort-order condition.
  • Use explicit SubtotalFrom/SubtotalTo ranges for non-cumulative totals.
  • Number sort orders with gaps and exclude memo lines from the Account type.

Practice Questions

Q1. Compute the subtotals [L1]

Q3 FY26 (₹ crore, profit-signed): revenue 172; materials −96; changes in inventories −3; employee −22; other expenses −27; D&A −8; other income 2.5; finance costs −4.5; tax −3.6. Using the example layout, compute every subtotal and state which Account sort orders each includes.

Q2. Insert exceptional items [L2]

The company records an exceptional loss of ₹ 9 crore (voluntary retirement scheme) in Q3. Specify the new layout row(s), CoA mapping and any DAX change needed so that PBT and PAT include it but EBIT does not, and show the revised PBT and PAT from Q1's data.

💡 Hint: Consider where in the sort order the new line must sit relative to EBIT and PBT.

Q3. Blank Gross Profit row [L2]

A colleague's Gross Profit row is blank. Their measure is CALCULATE([Actual Signed], Layout[SortOrder] < MAX(Layout[SortOrder]), Layout[Type] = "Account"). Explain why it returns blank (or why it might not), and correct it.

Q4. Total income and total expenses [L3]

Extend the model to render a Schedule III statement that shows Total income (revenue + other income) and Total expenses (all expense lines including finance costs and D&A) followed by "Profit before exceptional items and tax". Specify the layout rows with SortOrder, SubtotalFrom and SubtotalTo, write a single subtotal measure that handles both cumulative and range subtotals, and explain how expenses are shown as positive numbers without breaking the arithmetic.
