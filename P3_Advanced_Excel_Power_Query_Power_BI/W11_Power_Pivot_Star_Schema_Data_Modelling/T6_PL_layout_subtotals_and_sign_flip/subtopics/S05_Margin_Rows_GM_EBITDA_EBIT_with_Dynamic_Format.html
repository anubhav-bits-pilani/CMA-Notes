Subtopic note

Margin Rows (GM %, EBITDA %, EBIT %) with Dynamic Format Strings

Scope: Margin rows (GM %, EBITDA %, EBIT %) with dynamic format strings

Why it matters

An MIS P&L without margins is half a report: management reads EBITDA % before EBITDA, lenders track EBITDA margin covenants, and analysts benchmark gross margin against peers. In a layout-driven matrix, margin rows sit between ₹ rows in the same column, so the same measure must return ₹ 1,720 lakh on one row and 41.9% on the next — with the right format on each. Before dynamic format strings, the only way was FORMAT(), which converts numbers to text and breaks sorting, conditional formatting, totals and Excel export. Dynamic format strings solve the presentation problem while keeping the values numeric.

Core notes

Ratio rows in the layout

Each Ratio row references a numerator line and a denominator line:

LineID Line SortOrder Type RatioNumeratorLine RatioDenominatorLine
PL045 GM % 45 Ratio PL040 PL010
PL075 EBITDA % 75 Ratio PL070 PL010
PL095 EBIT % 95 Ratio PL090 PL010
PL145 PAT % 145 Ratio PL140 PL010

Margin measure driven by the layout

Line Value (by ID) =
-- value of any layout line given its LineID, used inside ratio calculations
VAR t = SELECTEDVALUE ( Layout[Type] )
RETURN
    SWITCH ( t, "Account", [Actual Signed], "Subtotal", [Subtotal] )

Margin % =
VAR numID = SELECTEDVALUE ( Layout[RatioNumeratorLine] )
VAR denID = SELECTEDVALUE ( Layout[RatioDenominatorLine] )
VAR num = CALCULATE ( [Line Value (by ID)], REMOVEFILTERS ( Layout ), Layout[LineID] = numID )
VAR den = CALCULATE ( [Line Value (by ID)], REMOVEFILTERS ( Layout ), Layout[LineID] = denID )
RETURN
    DIVIDE ( num, den )

CALCULATE moves the filter from the ratio row to the referenced line; the sub-measure then sees that line's Type and computes either an account sum or a subtotal. Simpler models use dedicated measures:

Revenue  = CALCULATE ( [Actual Signed], REMOVEFILTERS ( Layout ), Layout[LineID] = "PL010" )
EBITDA   = CALCULATE ( [Subtotal], REMOVEFILTERS ( Layout ), Layout[LineID] = "PL070" )
EBITDA % = DIVIDE ( [EBITDA], [Revenue] )

The dedicated measures are useful for KPI cards; the layout-driven version keeps the matrix free of hard-coded IDs.

Ratio mathematics

\[ \text{GM \%} = \frac{\text{Gross Profit}}{\text{Revenue}}, \qquad \text{EBITDA \%} = \frac{\text{EBITDA}}{\text{Revenue}}, \qquad \text{EBIT \%} = \frac{\text{EBIT}}{\text{Revenue}} \]

Ratios are non-additive: the YTD margin is YTD EBITDA ÷ YTD revenue, and the margin for a region is the region's EBITDA ÷ its revenue — the measure recomputes automatically in every context. Margin variances (Actual vs Budget) are differences in percentage points; display them in bps if the audience expects it:

Margin Var bps = ( [Margin % Actual] - [Margin % Budget] ) * 10000

Dynamic format strings

A measure's format can be an expression evaluated per cell (Power BI Desktop: select the measure → Measure tools → Format → Dynamic, then write the expression). For the dispatcher:

-- Format string expression for [PnL]
IF ( SELECTEDVALUE ( Layout[Type] ) = "Ratio", "0.0%", "#,##0" )

Extended for Indian presentation and negative numbers in brackets:

SWITCH (
    SELECTEDVALUE ( Layout[Type] ),
    "Ratio", "0.0%;(0.0%)",
    "#,##0;(#,##0);-"
)

The value stays numeric, so conditional formatting rules (e.g., red when EBITDA % < budget), sorting and exports work. Lakh/crore scaling is best done in the measure (/ 1e5 for ₹ lakh) or with a scale selector; Power BI's display units (thousands, millions) do not include lakhs.

Alternatives and limits:

  • Calculation groups can carry a format string expression per item (e.g., a "Margin" item), the original way to get dynamic formats before measure-level dynamic formats existed.
  • FORMAT([Margin %], "0.0%") returns text — avoid in matrices; acceptable only in titles or tooltips.
  • Excel clients (Analyze in Excel, Power Pivot) honour static measure formats; support for dynamic format strings in Excel depends on the client version — test before relying on it for board packs.

Worked illustration

YTD December FY26 (₹ crore): Revenue 480.0; Gross Profit 218.0; EBITDA 82.0; EBIT 61.0; PAT 41.0. Budget: Revenue 500.0; EBITDA 92.5.

Line Actual Format Displayed
Gross Profit 218.0 #,##0.0 218.0
GM % 0.4542 0.0% 45.4%
EBITDA 82.0 #,##0.0 82.0
EBITDA % 0.1708 0.0% 17.1%
EBIT % 0.1271 0.0% 12.7%
EBITDA % budget 0.185 0.0% 18.5%
Margin variance −0.0142 bps −142 bps

Edge cases & judgement calls

  • Negative or zero revenue (a branch with credit notes exceeding sales): DIVIDE returns blank for zero; a negative denominator flips the margin's sign — blank margins when revenue ≤ 0.
  • Ratio rows at grand total: with layout on rows, the grand total is meaningless anyway; with time on columns, the FY column of a Ratio row recomputes correctly.
  • Budget for ratio rows: use the same Margin % logic on budget measures; never budget margins as inputs and sum them.
  • Ratio rows in exports: exporting the matrix gives decimals (0.1708) with formats applied only if the export preserves them; label columns.
  • Format string on blank values: the third section of a format (;-) controls zeros, not blanks; blanks remain empty.

Key takeaways

  • Ratio rows reference numerator and denominator lines in the layout; the margin measure recomputes in every context.
  • Margins are non-additive and their variances are percentage points (or bps).
  • Dynamic format strings keep values numeric while showing ₹ and % in the same column.
  • Avoid FORMAT() in matrix values; it returns text.
  • Scale to ₹ lakh/crore in the measure; check dynamic format support in Excel clients.

Q2. Margin variance in bps [L2]

Q2 FY26 actual: revenue ₹ 165 crore, EBITDA ₹ 26.4 crore; budget: revenue ₹ 158 crore, EBITDA ₹ 27.7 crore. Compute actual and budget EBITDA %, the margin variance in bps, and the EBITDA variance in ₹, and explain how both can move in opposite directions.

Q3. FORMAT versus dynamic format [L2]

A legacy report uses FORMAT([EBITDA %], "0.0%") in the [PnL] ratio branch. List three problems this causes (in visuals, conditional formatting and exports) and migrate the measure to a dynamic format string.
