Key concept

Base Actual Measure and a Filtered Revenue Measure

Concept: Actual = SUM(GL[Amount]); Revenue = CALCULATE([Actual], CoA[FSLine] = "Revenue")

Statement

Actual  = SUM ( GL[Amount] )
Revenue = CALCULATE ( [Actual], CoA[FSLine] = "Revenue" )
  • [Actual] — base measure: sum of GL amounts (debits positive, credits negative) visible in the current filter context.
  • [Revenue] — derived measure: [Actual] evaluated with the filter on CoA[FSLine] replaced by "Revenue" (in a Schedule III-labelled CoA this would read "Revenue from operations").
  • Internally the boolean filter is FILTER(ALL(CoA[FSLine]), CoA[FSLine] = "Revenue").

Explanation

This pair is the root of measure branching: one base measure holds the aggregation logic; every P&L line, variance and time-intelligence measure is built on it. If the base changes (e.g. to exclude reversal entries, or apply a sign factor), every derived measure inherits the change.

Behaviour to understand:

  • Overwrite semantics. On a matrix with FSLine on rows, [Revenue] shows the revenue total on every row because the row's FSLine filter is replaced. Use it in cards, KPI rows and ratio denominators (DIVIDE([EBITDA], [Revenue])) where you want revenue regardless of the row. For row-aware behaviour use KEEPFILTERS (c06).
  • Other filters survive. Date, Branch, CostCentre and other CoA columns (e.g. AccountName) still filter. On an account row belonging to Employee benefits, [Revenue] returns blank, because AccountName and FSLine filters intersect to nothing.
  • Sign. With credits negative, [Revenue] is negative. Either define a sign-flipped measure (Revenue = -CALCULATE([Actual], …)) or use a signed base ([Actual Signed] from topic 6). Decide once.
  • Hard-coded labels. The string must match the CoA exactly (case-insensitive in DAX, but spaces and wording matter). If the FS line is renamed in the mapping, the measure silently returns blank. Many teams filter on a stable code column (CoA[FSLineCode] = "PL010") instead.
  • Budget twin. Create Revenue Budget = CALCULATE([Budget], CoA[FSLine] = "Revenue") so variance is [Revenue] - [Revenue Budget].

Illustration

FY2025-26 GL by FS line (₹ crore, raw signs): Revenue −640, Other income −18, Cost of materials 352, Employee benefits 74, Other expenses 96, Depreciation 28, Finance costs 12, Tax expense 24.

Matrix row [Actual] [Revenue]
Revenue −640 −640
Other income −18 −640
Employee benefits 74 −640
Total (P&L) −72 −640

The P&L total −72 = profit after tax ₹72 crore in credit-negative convention. DIVIDE(-[Actual], -[Revenue]) on the total gives PAT margin \(\frac{72}{640} = 11.25\%\).
