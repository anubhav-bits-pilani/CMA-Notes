DIVIDE, Measures vs Calculated Columns, and VAR/RETURN

Scope: DIVIDE for safe ratios; measures vs calculated columns; VAR/RETURN for readability

Why it matters

Ratios are the language of financial analysis — gross margin, EBITDA margin, ROCE, DSO, cost-to-income, variance %. Every one has a denominator that can be zero or blank in some cell: a new branch with no revenue yet, a month with no budget, a cost centre closed mid-year. DIVIDE handles those cases cleanly. Equally fundamental is deciding whether a computation is a measure (evaluated at query time in filter context) or a calculated column (stored per row at refresh). And as measures grow — sign-aware variance %, margin with fallbacks — VAR/RETURN keeps them readable, debuggable and efficient. Together these three habits separate maintainable finance models from fragile ones.

Core notes

DIVIDE

DIVIDE ( <numerator>, <denominator> [, <alternate_result>] )
  • Returns numerator / denominator.
  • If the denominator is 0 or BLANK, returns alternate_result if supplied, otherwise BLANK (concept c07).
  • Equivalent to IF(denominator = 0, alternate, numerator / denominator) — note BLANK() = 0 is TRUE in DAX, so blank denominators are caught too — but DIVIDE is optimised by the engine.
  • The / operator returns Infinity (or NaN for 0/0) on division by zero, which visuals show as "Infinity" or "NaN" — not an error like Excel's #DIV/0!, but equally ugly, and it pollutes totals and conditional formatting.
Gross Margin % = DIVIDE ( [Gross Profit], [Revenue] )
EBITDA Margin % = DIVIDE ( [EBITDA], [Revenue] )
DSO Days = DIVIDE ( [Avg Trade Receivables], [Revenue] ) * [Days in Period]

Returning BLANK matters for matrices: rows where every measure is blank are hidden automatically, so branches with no revenue disappear rather than showing 0%. Use an alternate result of 0 only when a zero is meaningful and you want the row shown.

When to still use /: when the denominator is a constant or can never be zero (e.g. [Amount] / 100000 for lakhs), / is marginally faster and perfectly safe.

Measures vs calculated columns

Aspect Measure Calculated column
Evaluated At query time, per visual cell At refresh, per row
Context Filter context (responds to slicers) Row context (static)
Storage None (formula only) Stored and compressed; adds memory
Use for Aggregations, ratios, time intelligence, variances Row attributes for slicing/grouping, keys, sort columns, bands
Example Actual = SUM(GL[Amount]), Var % CoA[IsPL] = CoA[Statement] = "Profit and Loss", 'Date'[FiscalMonthNo]

Decision rule: if you would put it on rows, columns or a slicer, it may be a column; if you would put it in the values area, it must be a measure. Ratios as columns are a classic error: a calculated column GL[Margin] = GL[GP] / GL[Revenue] computes per row, and summing ratios across rows is meaningless. Prefer Power Query custom columns over DAX calculated columns for row attributes (better compression, computed upstream).

VAR / RETURN

Variance % =
VAR ActualAmt = [Actual]
VAR BudgetAmt = [Budget]
VAR Diff      = ActualAmt - BudgetAmt
RETURN
    DIVIDE ( Diff, ABS ( BudgetAmt ) )

Benefits:

  1. Readability. Named intermediate results, like a Java local variable (double diff = actual - budget;).
  2. Evaluate once. Each VAR is evaluated once, in the filter context where it is defined; repeated references reuse the value — faster than repeating [Actual] three times.
  3. Debugging. Temporarily RETURN Diff to inspect an intermediate value.
  4. Capturing outer context. A VAR defined outside CALCULATE or an iterator holds the outer value, replacing EARLIER:
Share of Max Branch =
VAR CurrentSales = [Revenue]
VAR MaxBranch = MAXX ( ALL ( Branch ), [Revenue] )
RETURN DIVIDE ( CurrentSales, MaxBranch )

Key subtlety: variables are constants once evaluated. CALCULATE(ActualAmt, 'Date'[FY] = "FY2024-25") does not recompute ActualAmt for FY2024-25 — it returns the already computed value. To shift context, reference the measure inside CALCULATE, not the variable.

Illustration

Branch P&L, FY2025-26 (₹ lakh):

Branch Revenue EBITDA Budget EBITDA [EBITDA] / [Revenue] DIVIDE([EBITDA], [Revenue]) Var % (ABS)
Pune 1,200 180 160 15.0% 15.0% 12.5%
Nagpur (new) 0 −22 −30 −Infinity blank 26.7%
Nashik 640 51 0 8.0% 8.0% blank

Nagpur's start-up loss is better than budget by ₹8 lakh: \(\frac{-22 - (-30)}{\lvert -30 \rvert} = 26.7\%\) favourable. Nashik had no EBITDA budget, so variance % is blank, not infinite.

Edge cases & judgement calls

  • Blank vs zero numerator. DIVIDE(BLANK(), 100) = BLANK; DIVIDE(0, 100) = 0. A zero revenue numerator shows 0%, which may be correct.
  • Tiny denominators. DIVIDE avoids division by zero but not by ₹1 — a budget of ₹1 yields a variance % of millions. Add a materiality guard: IF(ABS(b) < 100000, BLANK(), DIVIDE(a - b, ABS(b))).
  • Negative denominators (expense budgets in credit-negative conventions, losses) flip signs; use ABS or sign-aware logic (concept c05).
  • Calculated columns referencing measures trigger context transition per row and slow refresh; acceptable on small dimensions only.
  • VAR scope. Variables are local to the measure; they cannot be shared across measures (use a base measure).

Key takeaways

  • DIVIDE returns BLANK (or the alternate result) for zero or blank denominators; / returns Infinity or NaN.
  • Blank results let matrices hide empty rows; use an alternate result only when a zero is meaningful.
  • Measures aggregate in filter context; calculated columns store row attributes — ratios are always measures.
  • VAR/RETURN improves readability, evaluates once and captures outer context.
  • Variables are constants: re-evaluate in a new context by referencing the measure, not the variable.

Practice Questions

Q1. Rewrite safely [L1]

Rewrite ROCE = [EBIT] / ([Equity] + [Net Debt]) with DIVIDE and VAR, and state what the measure should show when capital employed is zero or blank.

Q2. Column or measure [L1]

Classify each as calculated column (or Power Query column) or measure: FY label; gross margin %; account age band (0–30, 31–60 days) for invoices; YTD revenue; MSME vendor flag; average DSO.

Q3. The constant-variable trap [L2]

A measure reads VAR a = [Actual] RETURN a - CALCULATE(a, SAMEPERIODLASTYEAR('Date'[Date])) and always returns 0. Explain why and correct it.

💡 Hint: Where is the variable's value computed?

Q4. Materiality guard [L2]

Write a Variance % measure that returns blank when the absolute budget is below ₹1 lakh, uses ABS for the denominator, and returns "n.m." semantics (blank) when both actual and budget are blank. Explain how it behaves at the FY total.

Q5. Interview: DIVIDE vs IFERROR [L1]

An interviewer asks why DAX has DIVIDE when Excel users simply wrap formulas in IFERROR. Answer in under 100 words, covering blank handling, performance and visual behaviour.
