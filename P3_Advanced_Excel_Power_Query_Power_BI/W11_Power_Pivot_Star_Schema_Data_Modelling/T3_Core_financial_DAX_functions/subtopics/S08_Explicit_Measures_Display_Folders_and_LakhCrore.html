Subtopic note

Explicit Measures, Display Folders and ₹ Lakh/Crore Formats

Scope: Explicit measures, display folders and format strings (₹, lakhs/crores)

Why it matters

A finance semantic model is used by many report authors and read by CFOs, auditors and business heads. If users drag raw columns and get implicit sums, numbers have no sign logic, no format and no budget counterpart. If fifty measures sit in one alphabetical list, nobody finds "EBITDA Margin %". If revenue shows as 4823719442.17 instead of ₹482.37 crore, the board pack is rejected. Explicit measures, organised in display folders, with format strings that match Indian reporting conventions (₹, lakh, crore, brackets for negatives) are the presentation layer of the model — the equivalent of a well-laid-out Schedule III note.

Core notes

Explicit vs implicit measures

  • Implicit measure: created when a user drags a numeric column (e.g. GL[Amount]) into a visual; Power BI applies a default aggregation (Sum, Average…). No name, no format control in the model, not reusable in other measures, and not usable in calculation groups or Excel's Analyze in Excel reliably.
  • Explicit measure: written in DAX with a name, home table, format string, description and folder:
Actual = SUM ( GL[Amount] )
Budget = SUM ( Budget[Amount] )
Variance ₹ = [Actual] - [Budget]

Good practice:

  1. Write explicit measures for every number shown in reports; hide the underlying numeric columns (topic 1 c06).
  2. Set the model property Discourage implicit measures (Model view → model properties), which stops users dragging columns as values. It is enforced automatically once calculation groups exist.
  3. Add a description to each measure (shown as a tooltip in the field list) stating sign convention and source.
  4. Build base measures (Actual, Budget, Signed Actual) and branch derived measures from them; never repeat SUM logic.

Measure home table and display folders

  • Home table: each measure belongs to a table. Many teams create a dedicated, otherwise empty table (Home → Enter data → one dummy column, then hide the column) named _Measures or Fin Measures so measures appear at the top of the field list, separate from dimensions.
  • Display folders: in Model view, select measures → Properties → Display folder. Use backslash for nesting:
Folder Measures
01 Base Actual, Budget, Actual Signed, Budget Signed
02 Variance Variance ₹, Variance %, Fav/Adv flag
03 Time Intelligence\YTD YTD Actual, YTD Budget, PY YTD, YoY %
03 Time Intelligence\Rolling R12M Revenue, T3M Opex
04 P&L Lines Revenue, Gross Profit, EBITDA, EBIT, PBT, PAT
05 Ratios GM %, EBITDA %, DSO, ROCE
09 Data Quality Unmapped Amount, RI Orphans, TB Difference

Numeric prefixes force the order. Multiple folders per measure are allowed by separating with semicolons. Power Pivot in Excel supports display folders only through external tools; the measure list is flatter there.

Format strings

Power BI measure format strings follow .NET/VBA-style custom formats:

Format string 12345678.9 displays Notes
#,0 12,345,679 or 1,23,45,679 Digit grouping follows locale; with en-IN the default thousands separator groups as lakh/crore in most visuals — verify in your Desktop/service version
₹#,0 ₹12,345,679 Literal ₹ prefix
₹#,0;(₹#,0);- positive; negative in brackets; zero as dash Three sections: positive; negative; zero
0.0% 1234567890.0% For ratios: value 0.153 shows 15.3%
#,0.00,,"M" 12.35M Each comma before the decimal point scales by 1,000 — only thousands/millions/billions

Lakhs (\(10^5\)) and crores (\(10^7\)) are not powers of 1,000, so comma scaling cannot produce them. Options:

  1. Divide in the measure:
Revenue ₹ Cr = DIVIDE ( [Revenue], 1E7 )        -- format: #,0.00 "Cr"
Revenue ₹ L  = [Revenue] / 1E5                 -- format: #,0.00 "L"
  1. Units selector: a disconnected table Units (Rupees = 1, Lakhs = 1E5, Crores = 1E7) and a pattern [Revenue] / SELECTEDVALUE(Units[Divisor], 1), or a calculation group "Units" whose items divide SELECTEDMEASURE() and set the format string — one switch for the whole page.
  2. Dynamic format strings (measure property Format → Dynamic): the format string is a DAX expression, e.g. percentage for ratio rows and ₹ for amount rows in a P&L (topic 6). It changes the display pattern, not the underlying value.

Excel PivotTables on Power Pivot can use Excel's conditional custom format to show Indian grouping: [>=10000000]##\,##\,##\,##0;[>=100000]##\,##\,##0;##,##0 — a well-known trick limited to positives (two conditions plus a default), so negative amounts need care.

Always state units on the page ("₹ crore") and keep the same unit in a whole table; mixing lakh and crore rows in one P&L is a review error.

Illustration

Revenue FY2025-26 = ₹4,82,37,19,442. Presentations:

Measure Value Format Display
Revenue 4823719442 ₹#,0 (en-IN grouping) ₹4,82,37,19,442
Revenue ₹ Cr 482.3719442 #,0.00 "Cr" 482.37 Cr
Revenue ₹ L 48237.19442 #,0.0 "L" 48,237.2 L
GM % 0.3812 0.0% 38.1%

Edge cases & judgement calls

  • Formatting does not round values. Totals are computed on unrounded values; a column of figures rounded to crores may not foot visually. Disclose "figures may not add due to rounding" or round in the measure (ROUND(x, 2)) at the line level, consciously.
  • Analyze in Excel honours model format strings only partially; dynamic format strings may not carry to Excel pivots — test.
  • Locale settings. Model culture (set when the file was created) and report/browser locale both affect display; a model created with en-US culture may show 3-digit grouping for en-IN users. Check File → Options → Regional settings.
  • Sign display. Showing expenses as positive with brackets for credits is a presentation choice; combine with sign factors (topic 6), not by format string alone.
  • Measure names with ₹ or %. Allowed, but keep them stable — renaming breaks report-level references in some external tools and Excel CUBE formulas.

Key takeaways

  • Write explicit measures for every reported number; discourage implicit measures and hide numeric columns.
  • Use a dedicated measures table and numbered display folders (Base, Variance, Time Intelligence, P&L, Ratios, DQ).
  • Format strings control display only; brackets for negatives use three-section formats.
  • Lakh and crore scaling needs division in measures, a units selector or a calculation group — not comma scaling.
  • State units on every page and keep one unit per table; watch rounding and locale.

Practice Questions

Q1. Folder design [L1]

Propose a display-folder structure for 45 measures covering base amounts, variances, YTD/PY, rolling windows, P&L subtotals, margins, working-capital ratios and data-quality checks, and explain how numbering controls order.

Q2. Units switch [L2]

Design a "Units" slicer that lets users switch a P&L page between ₹, ₹ lakh and ₹ crore. Describe the table, the measure or calculation-group logic, and the format strings, and explain how ratios (GM %) must be excluded from the division.

💡 Hint: A ratio should not be divided by the unit divisor.

Q3. Format strings [L2]

Write format strings for: (a) ₹ amounts with negatives in brackets and zero as "–"; (b) percentages with one decimal and negatives in brackets; (c) days with no decimals and the suffix " days". State the display for −2,50,000, 0.1234 and 47.6 respectively.

Q4. Review findings [L3]

In a model review you find: users building visuals with GL[Amount]; 60 measures in one list; revenue shown in rupees on one page and crores on another; Excel board-pack pivots showing 3-digit grouping. Write review comments with the fix for each, in the order you would prioritise them.
