Subtopic note

ALL, ALLEXCEPT and ALLSELECTED for Share and Contribution Analysis

Scope: ALL, ALLEXCEPT and ALLSELECTED for % of total, % of parent and contribution analysis

Why it matters

FP&A commentary is full of shares: "Employee cost is 14.2% of revenue", "Pune contributes 23% of West-zone sales", "Top 10 customers account for 61% of receivables". Each is a ratio of the current cell to a denominator computed in a wider context: the grand total, the parent in a hierarchy, or the total of what the user has selected. ALL, ALLEXCEPT and ALLSELECTED are the three tools for constructing those denominators. Picking the wrong one gives shares that do not add to 100%, change when an unrelated slicer moves, or show 100% on every row.

Core notes

ALL — ignore filters entirely (on the named table/columns)

% of Total Opex =
DIVIDE ( [Actual], CALCULATE ( [Actual], ALL ( CostCentre ) ) )

The denominator removes every filter on CostCentre (rows, slicers, page filters on CostCentre columns) but keeps filters on other tables (Date, CoA). So in a matrix of cost centres for FY2025-26 opex, each cost centre's share of total FY2025-26 opex is shown; if the user slices CostCentre[Function] = "Sales", the denominator still includes non-sales cost centres — shares no longer sum to 100% of the visible rows. That is ALL's defining behaviour: total of everything, regardless of user selection on that dimension.

Variants:

  • ALL(CostCentre[Department]) — remove filters only on one column (other CostCentre columns still filter).
  • REMOVEFILTERS(CostCentre) — same as ALL as a modifier, clearer intent.
  • ALL() with no arguments — removes all filters in the model (use with care; only as a modifier).

ALLEXCEPT — keep only the parent

% within Statement =
DIVIDE ( [Actual], CALCULATE ( [Actual], ALLEXCEPT ( CoA, CoA[Statement] ) ) )

ALLEXCEPT(table, col1, col2…) removes all filters on table except those on the listed columns. In a matrix with Statement → FSLine → Account, the denominator for any account row is the total of its Statement — "% of parent at the top level". For % of immediate parent at each level, use ISINSCOPE to branch:

% of Parent =
SWITCH (
    TRUE (),
    ISINSCOPE ( CoA[AccountName] ), DIVIDE ( [Actual], CALCULATE ( [Actual], ALLEXCEPT ( CoA, CoA[Statement], CoA[FSLine] ) ) ),
    ISINSCOPE ( CoA[FSLine] ),      DIVIDE ( [Actual], CALCULATE ( [Actual], ALLEXCEPT ( CoA, CoA[Statement] ) ) ),
    ISINSCOPE ( CoA[Statement] ),   1
)

Caveats:

  • ALLEXCEPT keeps filters on the listed columns only if they exist; if a slicer filters CoA[AccountType], ALLEXCEPT removes it (since AccountType is not listed), which may surprise users.
  • A safer pattern for "remove only the levels below the parent" is REMOVEFILTERS(CoA[FSLine], CoA[AccountName]) combined with VALUES(CoA[Statement]) — or CALCULATE([Actual], REMOVEFILTERS(CoA), VALUES(CoA[Statement])), which restores exactly the visible statements.

ALLSELECTED — total of what the user selected

% of Selected =
DIVIDE ( [Actual], CALCULATE ( [Actual], ALLSELECTED ( CostCentre ) ) )

ALLSELECTED removes filters coming from the visual's own rows and columns but keeps filters from slicers, page and report filters (the "outer" selection). With CostCentre[Function] = "Sales" sliced, each sales cost centre's share is of the sales total, and visible rows sum to 100%. This is "contribution analysis" as users intuitively expect.

Cautions:

  • Its result depends on the query's shadow filter context; inside iterators or measures called by other measures it can behave unexpectedly. Use it at the top level of a measure used directly in visuals.
  • Visual-level filters (e.g. Top N filter on the visual) are part of the "selection" — a Top 10 visual's shares then sum to 100% of the top 10, not of all customers. Decide which you want and label it.

Contribution and cumulative share (Pareto)

Cumulative Share of Receivables =
VAR CurrentAR = [Closing AR]
VAR Cum =
    CALCULATE (
        [Closing AR],
        FILTER ( ALLSELECTED ( Customer[CustomerName] ), [Closing AR] >= CurrentAR )
    )
RETURN
    DIVIDE ( Cum, CALCULATE ( [Closing AR], ALLSELECTED ( Customer[CustomerName] ) ) )

Ranks customers by balance and shows the running share — the basis of ABC analysis and concentration disclosures (Ind AS 107 concentration of credit risk; Ind AS 108.34 disclosure of reliance on major customers with 10% or more of revenue).

Edge cases & judgement calls

  • Negative values. Shares of a P&L where some cost centres have credits (recoveries) can exceed 100% or be negative; use ABS or present with commentary.
  • Sign conventions. Revenue is negative in the GL; DIVIDE([Employee cost], [Revenue]) gives a negative % unless sign-adjusted (topic 6 sign flip).
  • Hierarchy totals. In the grand total row, ALLEXCEPT-based "% of parent" may show 100% or be meaningless; blank it with ISINSCOPE.
  • Removing sort-by columns. ALL on a label column must also clear its sort-by column (topic 2 s04); ALL on the whole table avoids this.
  • Double-entry totals. ALL(CoA) across both statements nets to zero; always anchor the denominator to Statement or a specific FSLine (e.g. revenue for cost ratios).

Key takeaways

  • ALL: share of everything on that dimension, ignoring user selections — shares may not sum to 100% of visible rows.
  • ALLEXCEPT: share of the retained parent columns; removes every other filter on the table, including slicers.
  • ALLSELECTED: share of the user's selection; visible rows sum to 100%.
  • Use ISINSCOPE to compute % of immediate parent at each hierarchy level and to blank meaningless totals.
  • Anchor finance denominators to a statement or revenue line; ALL(CoA) on a balanced GL is zero.

Practice Questions

Q1. Pick the function [L1]

For each requirement, choose ALL, ALLEXCEPT or ALLSELECTED and write the denominator: (a) each branch's share of company revenue regardless of a Region slicer; (b) each branch's share of the selected region's revenue; (c) each account's share of its FS line.

Q2. Shares not adding up [L2]

A % of Total measure using ALL(Branch) shows shares summing to 38% when the Zone slicer is set to "South". The business wants 100%. Explain the behaviour and give two alternative measures with the trade-offs.

💡 Hint: Consider what "total" the business actually means and where the Zone filter sits.

Q3. Cost ratios to revenue [L2]

Write a measure "% of Revenue" that, for every P&L row (FSLine on rows), divides the row's sign-adjusted actual by total Revenue from operations for the same period and branch, ignoring the row's FSLine filter.

Q4. Pareto of receivables [L3]

Using a Customer dimension and a [Closing AR] measure at 31-Mar-2026, design a visual and measures to show how many customers make up 80% of receivables, and explain how ALLSELECTED interacts with a visual-level Top N filter.

Q5. % of parent at every level [L3]

Write a single measure that, in a matrix with Statement → FSLine → FSSubLine → AccountName, returns each row's share of its immediate parent and blanks at the grand total, and explain how ISINSCOPE determines the level.
