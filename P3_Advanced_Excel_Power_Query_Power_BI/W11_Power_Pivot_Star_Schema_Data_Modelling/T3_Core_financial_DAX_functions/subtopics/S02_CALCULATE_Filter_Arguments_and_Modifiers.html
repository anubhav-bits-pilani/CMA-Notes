CALCULATE Filter Arguments and Modifiers

Scope: CALCULATE filter arguments: boolean filters, table filters, and modifiers ALL, REMOVEFILTERS, KEEPFILTERS, USERELATIONSHIP

Why it matters

CALCULATE is the only function that changes filter context, and nearly every finance measure beyond SUM uses it: Revenue as Actual filtered to an FS line, % of total, budget on an inactive date, YTD, PY, closing balances. Its arguments come in two families — filters (which add or replace filters) and modifiers (which change how filters or relationships behave). Knowing exactly when a filter overwrites the visual's filter, when it intersects with it, and when a modifier removes filters is what lets you write a P&L measure that behaves correctly in every cell of a matrix.

Core notes

Evaluation order of CALCULATE

CALCULATE(<expression>, <filter1>, <filter2>, …):

  1. Filter arguments are evaluated in the original (outer) filter context.
  2. If CALCULATE is in a row context, context transition turns the row into filters.
  3. Modifiers (ALL/REMOVEFILTERS, USERELATIONSHIP, CROSSFILTER, KEEPFILTERS) are applied.
  4. The evaluated filter arguments are applied: each one replaces existing filters on the same columns (unless wrapped in KEEPFILTERS); filters on different columns combine with AND.
  5. The expression is evaluated in the new filter context.

Boolean filters

Revenue = CALCULATE ( [Actual], CoA[FSLine] = "Revenue from operations" )

A boolean filter is a predicate on one column (since 2021, multiple columns of the same table are allowed in a single predicate). DAX rewrites it internally as a table filter:

CALCULATE ( [Actual], FILTER ( ALL ( CoA[FSLine] ), CoA[FSLine] = "Revenue from operations" ) )

Because of the ALL(CoA[FSLine]), the boolean filter overwrites any existing filter on CoA[FSLine]. In a P&L matrix with FSLine on rows, the Revenue measure shows the revenue figure on every row — including "Employee benefits expense". That is correct semantics, not a bug; to intersect instead, use KEEPFILTERS (concept c06).

Rules for boolean filters (per Microsoft documentation): they may reference columns of a single table; they cannot reference measures or use a nested CALCULATE; since 2021 they may contain scalar aggregations such as MAX('Date'[Date]), which are evaluated in the outer filter context. To use a measure's value, capture it in a variable first:

Large Vouchers =
VAR Threshold = [Materiality Threshold]          -- a measure, evaluated once in the outer context
RETURN CALCULATE ( [Actual], GL[Amount] > Threshold )

(The predicate GL[Amount] > Threshold filters a fact column — valid, but see s04 on performance.)

Table filters

Any table expression can be a filter argument; its columns become filters:

Revenue & Other Income =
CALCULATE ( [Actual], CoA[FSLine] IN { "Revenue from operations", "Other income" } )

Budget (virtual) =
CALCULATE ( SUM ( Budget[Amount] ), TREATAS ( VALUES ( 'Date'[MonthEnd] ), Budget[MonthEnd] ) )

Accounts over 1 crore =
CALCULATE ( [Actual], FILTER ( VALUES ( CoA[AccountKey] ), ABS ( [Actual] ) > 10000000 ) )

The last is a table filter built with FILTER over a dimension's VALUES — necessary because the condition uses a measure. Table filters also overwrite filters on the columns they contain; FILTER(VALUES(...)) returns only currently visible values, so in effect it restricts within the current context.

ALL and REMOVEFILTERS

  • ALL(table) / ALL(column, …) as a CALCULATE modifier removes filters from the table or columns.
  • REMOVEFILTERS(...) is an alias introduced for readability; it can only be used as a CALCULATE modifier (not as a table expression), which makes intent explicit.
  • ALL used as a table function (e.g. in FILTER or COUNTROWS) returns all rows ignoring filters.
% of Total Revenue = DIVIDE ( [Revenue], CALCULATE ( [Revenue], REMOVEFILTERS ( Branch ) ) )

ALLEXCEPT and ALLSELECTED are covered in s05.

KEEPFILTERS

KEEPFILTERS(<filter>) makes the filter intersect with existing filters on the same columns rather than overwrite them:

Revenue (row-aware) =
CALCULATE ( [Actual], KEEPFILTERS ( CoA[FSLine] = "Revenue from operations" ) )

On the "Revenue from operations" row it returns revenue; on the "Employee benefits expense" row the intersection is empty, so it returns blank. KEEPFILTERS is also used around iterator tables to preserve filters, e.g. SUMX(KEEPFILTERS(VALUES(...)), ...).

USERELATIONSHIP (and CROSSFILTER)

USERELATIONSHIP(col1, col2) activates an inactive relationship for this evaluation (topic 1 c01):

Receivables by Due Date =
CALCULATE ( [Actual], CoA[FSLine] = "Trade receivables", USERELATIONSHIP ( GL[DueDate], 'Date'[Date] ) )

CROSSFILTER (topic 1 c04) changes direction. Both are modifiers, applied before the filter arguments.

Illustration — one matrix, four measures

FY2025-26, rows = FSLine. Revenue from operations −₹500 crore (credit), Other income −₹20 crore, Employee benefits ₹60 crore (raw signs).

Row (FSLine) [Actual] CALCULATE([Actual], CoA[FSLine] = "Revenue from operations") with KEEPFILTERS CALCULATE([Actual], REMOVEFILTERS(CoA))
Revenue from operations −500 −500 −500 0
Other income −20 −500 blank 0
Employee benefits expense 60 −500 blank 0

The REMOVEFILTERS column shows the same value on every row — the total across all accounts — which for a balanced double-entry GL is nil, because every voucher's debits equal its credits. That is why "% of total" measures in finance need a narrower denominator (all accounts within the Statement or within income lines), not simply "all CoA".

Edge cases & judgement calls

  • Filters on related tables. A filter on CoA[FSLine] does not remove a filter on CoA[AccountName] placed by the visual. If AccountName is on rows, CALCULATE([Actual], CoA[FSLine] = "Revenue from operations") intersects with the account filter (different column) — revenue accounts show their own revenue; others show blank.
  • Sort-by columns. Removing filters from MonthName without also removing FiscalMonthNo leaves the sort column's filter (topic 2 s04).
  • ALL on fact vs dimension. As a CALCULATE modifier, REMOVEFILTERS(GL) works on the expanded GL table — GL plus every dimension reachable through its many-to-one relationships — so it wipes filters on CoA, Date, CostCentre and Branch as well. That is rarely intended. Remove filters on the specific dimension or columns instead (REMOVEFILTERS(CostCentre)).
  • Auto REMOVEFILTERS on Date. Filtering 'Date'[Date] in a marked Date table automatically removes other Date filters — why CALCULATE([Actual], 'Date'[Date] <= MAX('Date'[Date])) returns a running total from inception, not within the month.

Key takeaways

  • Filter arguments are evaluated in the outer context, then applied after context transition and modifiers.
  • A boolean filter is FILTER(ALL(column), predicate) and overwrites existing filters on that column.
  • Table filters (IN lists, TREATAS, FILTER over VALUES) handle multi-value and measure-based conditions.
  • ALL/REMOVEFILTERS remove filters; KEEPFILTERS intersects; USERELATIONSHIP and CROSSFILTER alter relationships.
  • Remove filters on the dimension columns the visual uses, not on the fact.

Practice Questions

Q1. Predict the matrix [L1]

A matrix has CostCentre on rows. Measure Sales Opex = CALCULATE([Actual], CostCentre[Function] = "Sales"). What does it show on the row for cost centre "MUM-ADM" (Function = Admin)? What changes with KEEPFILTERS? Explain.

Q2. Rewrite as FILTER [L2]

Rewrite CALCULATE([Actual], CoA[Statement] = "Profit and Loss", 'Date'[FY] = "FY2025-26") using explicit FILTER and ALL, and explain why the visual's filter on 'Date'[FY] = "FY2024-25" no longer applies.

💡 Hint: Each boolean filter becomes its own table filter over one column.

Q3. Measure-based condition [L2]

Write a measure that returns the total actual of accounts whose FY2025-26 actual exceeds budget by more than 10%, so that it works in a matrix by FSLine. State why a boolean filter cannot express the condition.

Q4. Order of evaluation [L3]

Explain step by step how DAX evaluates CALCULATE([Actual], ALL('Date'), 'Date'[FY] = "FY2024-25") inside a matrix cell for March 2026, and contrast with CALCULATE([Actual], 'Date'[FY] = "FY2024-25").

Q5. Due-date receivables [L2]

Write a measure for trade receivables falling due in the selected month, combining a boolean filter on CoA and USERELATIONSHIP, and explain the order in which the modifier and the filter are applied.
