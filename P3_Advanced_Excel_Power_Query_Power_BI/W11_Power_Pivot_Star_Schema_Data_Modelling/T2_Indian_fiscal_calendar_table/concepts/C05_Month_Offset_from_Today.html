Key concept

Month Offset from Today

Concept: Month offset: (YEAR([Date]) - YEAR(TODAY())) * 12 + MONTH([Date]) - MONTH(TODAY())

Statement

MonthOffset =
( YEAR ( 'Date'[Date] ) - YEAR ( TODAY () ) ) * 12
    + MONTH ( 'Date'[Date] ) - MONTH ( TODAY () )

\[ \text{MonthOffset}(d) = 12 \times (\text{YEAR}(d) - \text{YEAR}(r)) + \text{MONTH}(d) - \text{MONTH}(r) \]

where \(d\) is the row date and \(r\) is the reference date (TODAY() here). Result: 0 for every day in the current month, −1 for last month, +1 for next month, −12 for the same month last year.

Explanation

The formula converts each date to a running month count (\(12 \times \text{year} + \text{month}\)) and subtracts the reference month's count. Because it uses absolute months, it is independent of the fiscal year: crossing 31 March or 31 December changes nothing. That makes it the backbone of:

  • Dynamic report filters: "last 3 months" = MonthOffset between −2 and 0; "last 12 months" = −11 to 0.
  • Calendar-agnostic rolling windows in measures (s05).
  • Default selections: a calculated column IF([MonthOffset] = 0, "Current month", [MonthYear]) allows a slicer to default to "Current month" and roll forward automatically.

Key caveats:

  • Evaluated at refresh. As a calculated column, TODAY() is evaluated when the model refreshes, not when the report is viewed. A failed refresh leaves the offsets stale.
  • UTC in the service. In the Power BI service, TODAY() returns the UTC date; between 00:00 and 05:30 IST it is still the previous day in UTC. On the 1st of a month that shifts every offset by one.
  • Finance reference date. For MIS, "today" is usually wrong: the current month is not closed. Replace TODAY() with the last closed month-end from a Close parameter table, giving MonthOffsetClosed (s05), so offset 0 = latest closed month.
  • FY offset companion: [FYEnd] - FYEnd(r) gives 0 for the current fiscal year and −1 for last year.

Illustration

Refresh on 12-Nov-2025 (reference month count \(12 \times 2025 + 11 = 24{,}311\)):

Date Month count MonthOffset
15-Nov-2025 24,311 0
31-Oct-2025 24,310 −1
01-Sep-2025 24,309 −2
18-Aug-2025 24,308 −3
20-Nov-2024 24,299 −12
05-Jan-2026 24,313 +2

A page filter "MonthOffset −3 to −1" shows August to October 2025 (offsets −3, −2, −1), i.e. the last three complete months — useful when the current month is open. On 2-Dec-2025, after a refresh, the same filter shows September to November.

Practice Questions

Q1. Evaluate offsets [L1]

With TODAY() = 3-Apr-2026, compute MonthOffset for 31-Mar-2026, 1-Apr-2025, 15-Oct-2026 and 28-Feb-2025, and FYOffset for the same dates.

Q2. Closed-month version [L2]

Rewrite the column to use the last closed month-end from a one-row table Close[LastClosedMonthEnd], and design a report filter that always shows the latest closed quarter in fiscal terms.

💡 Hint: A quarter filter needs a QuarterOffset built from FYEnd and FiscalQuarterNo, not months.

Q3. Service refresh issue [L2]

A dataset refreshes at 01:00 IST daily. On 1-Jan-2026 users see December 2025 as "Current month" and on 2-Jan-2026 they see January 2026. Explain the cause precisely and propose two fixes.
