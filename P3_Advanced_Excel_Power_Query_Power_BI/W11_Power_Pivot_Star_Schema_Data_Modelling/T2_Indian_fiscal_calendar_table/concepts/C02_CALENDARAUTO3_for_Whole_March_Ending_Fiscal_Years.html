Key concept

CALENDARAUTO(3) for Whole March-Ending Fiscal Years

Concept: CALENDARAUTO(3) builds whole fiscal years ending in March from every date column in the model

Statement

Date = CALENDARAUTO ( 3 )

CALENDARAUTO([fiscal_year_end_month]) returns a single-column table [Date] with a contiguous range of dates:

  • It scans the model for the earliest and latest dates in date columns (per Microsoft documentation, values in calculated columns and calculated tables are ignored).
  • It extends the range to whole fiscal years whose last month is fiscal_year_end_month (an integer 1–12; default 12 = calendar year).

With argument 3:

\[ \text{Start} = \text{1 April of the FY containing } d_{\min}, \qquad \text{End} = \text{31 March of the FY containing } d_{\max} \]

Explanation

CALENDARAUTO saves writing MIN/MAX logic and rounds to whole fiscal years automatically, satisfying the contiguity and whole-year requirements for time intelligence. Add columns with ADDCOLUMNS exactly as in c01:

Date =
ADDCOLUMNS (
    CALENDARAUTO ( 3 ),
    "FYEnd", IF ( MONTH ( [Date] ) >= 4, YEAR ( [Date] ) + 1, YEAR ( [Date] ) )
)

Cautions:

  • Every date column counts. Employee date of birth, a fixed-asset "useful life end date" in 2045, or placeholder dates (01-01-1900, 31-12-9999) silently stretch the calendar to decades or centuries. Clean such columns in Power Query or switch to explicit bounds.
  • The range changes with data. New far-future due dates extend the table at the next refresh — usually harmless, but offset columns and slicer lists change.
  • Not available in Excel Power Pivot (no calculated tables).
  • Circular dependencies. Since the table depends on all date columns, adding calculated columns elsewhere that depend on the Date table can trigger circular-dependency errors in some designs.
  • DirectQuery sources may restrict or slow CALENDARAUTO scans.

Use it for prototypes and well-controlled models; for corporate standard calendars, prefer explicit CALENDAR bounds or a Power Query table.

Illustration

Model dates: GL PostingDate 3-Jun-2021 to 22-Nov-2025; Budget MonthStart up to 1-Mar-2026; Employee[DOB] from 14-Aug-1968.

Case Result
Employee table not in model 1-Apr-2021 to 31-Mar-2026 (5 FYs, 1,826 rows)
Employee[DOB] in model 1-Apr-1968 to 31-Mar-2026 (58 FYs, about 21,000 rows), slicers list FY1968-69 onwards
Using CALENDARAUTO() (default 12) 1-Jan-2021 to 31-Dec-2026 — calendar years, wrong for Indian YTD edges

Practice Questions

Q1. Predict the range [L1]

A model contains GL dates 10-May-2022 to 15-Jan-2026, Budget dates to 1-Mar-2027 and a Contracts[EndDate] column with some values of 31-Dec-9999. State the range CALENDARAUTO(3) produces and how you would correct it.

Q2. Default argument trap [L2]

A model uses CALENDARAUTO() and TOTALYTD with "3/31". Explain the effect on FY2025-26 YTD in March 2026 if the latest fact date is 31-Mar-2026, and on PY YTD for April 2021 if the earliest fact date is 15-Apr-2021.

💡 Hint: Compare where the calendar begins and ends with the fiscal-year boundaries.

Q3. Defend or replace [L3]

Your manager prefers CALENDARAUTO(3) "because it is automatic". Write a short recommendation for a group model with HR, Fixed Assets and GL tables, weighing automation against control, and propose a compromise.
