Subtopic note

Month and FY Offset Columns for Dynamic Period Filters

Scope: Offset columns (month/FY offset from today or the as-of date) for dynamic "last 3 months" filters

Why it matters

Monthly MIS dashboards should open on "the latest closed month", "last 3 months" or "current FY vs last FY" without someone editing slicers every month. Relative date slicers in Power BI work only from today's date and only on calendar periods; they cannot say "last 3 closed months" or "current fiscal year". Offset columns — integers stating how many months or fiscal years a date is from a reference date — make these filters trivial (MonthOffset between −2 and 0) and also support custom time intelligence for non-standard calendars and the rolling windows used in forecasting.

Core notes

Definitions

  • MonthOffset: months between the date's month and the reference month. Current month = 0, previous = −1, next = +1.
  • FYOffset: fiscal years between the date's FY and the reference FY. Current FY = 0, last FY = −1.
  • QuarterOffset and WeekOffset follow the same idea.

With today (or as-of) = \(r\):

\[ \text{MonthOffset} = (\text{YEAR}(d) - \text{YEAR}(r)) \times 12 + \text{MONTH}(d) - \text{MONTH}(r) \]

\[ \text{FYOffset} = \text{FYEnd}(d) - \text{FYEnd}(r) \]

\[ \text{QuarterOffset} = (\text{FYEnd}(d) - \text{FYEnd}(r)) \times 4 + \text{FQ}(d) - \text{FQ}(r) \]

where \(d\) is the row's date, \(\text{FYEnd}\) is the year in which the fiscal year ends and \(\text{FQ}\) is the fiscal quarter number (1–4).

DAX calculated columns

MonthOffset =
VAR r = TODAY ()
RETURN
    ( YEAR ( 'Date'[Date] ) - YEAR ( r ) ) * 12 + MONTH ( 'Date'[Date] ) - MONTH ( r )

FYOffset =
VAR r = TODAY ()
VAR rFYEnd = IF ( MONTH ( r ) >= 4, YEAR ( r ) + 1, YEAR ( r ) )
RETURN
    'Date'[FYEnd] - rFYEnd

Today vs an as-of date

Finance rarely wants "today". On 5 May the April books are still open; the dashboard should treat March as the latest closed month until the April close is signed off on working day 5 or so. Use an as-of date instead:

  • From data: CALCULATE(MAX(GL[PostingDate]), REMOVEFILTERS()) — but late postings or future-dated entries move it.
  • From the close calendar: a small parameter table Close[LastClosedMonthEnd] maintained by the controller, or a Power Query parameter updated at month-end.
  • From the TB snapshot: the latest MonthEnd in TB.
MonthOffsetClosed =
VAR r = MAX ( Close[LastClosedMonthEnd] )
RETURN
    ( YEAR ( 'Date'[Date] ) - YEAR ( r ) ) * 12 + MONTH ( 'Date'[Date] ) - MONTH ( r )

(In a calculated column with no filter context, MAX over the one-row Close table returns its single value.)

Using offsets in reports and measures

  • Report filter "last 3 closed months": filter pane on 'Date'[MonthOffsetClosed] is between −2 and 0. Rolls forward automatically after each refresh.
  • Default to latest month: slicer on MonthYear with a hidden filter MonthOffsetClosed = 0, or a "Period" column labelled "Current" when offset = 0 so a slicer can default to "Current".
  • Custom rolling window measure:
Trailing 3M =
VAR cur = MAX ( 'Date'[MonthOffset] )
RETURN
    CALCULATE ( [Actual], REMOVEFILTERS ( 'Date' ), 'Date'[MonthOffset] > cur - 3, 'Date'[MonthOffset] <= cur )

This works on any calendar (4-4-5 included) because it uses integers rather than date arithmetic.

  • Prior FY same period: 'Date'[FYOffset] = -1 combined with fiscal month filters.

Refresh timing and time zone

Calculated columns (DAX) and Power Query columns are computed at refresh, not at query time. If the dataset refreshes nightly, offsets are current; if refresh fails, offsets go stale. In the Power BI service, TODAY() and DateTime.LocalNow() evaluate in UTC. IST is UTC+5:30, so a refresh between 00:00 and 05:30 IST computes "today" as the previous date — on the 1st of a month the offsets would still treat the prior month as current. Use DateTimeZone.SwitchZone(DateTimeZone.UtcNow(), 5, 30) in Power Query, schedule refresh after 05:30 IST, or, better, use the as-of-date parameter which is time-zone-neutral.

Illustration

As-of (last closed month-end) = 31-Oct-2025.

Month MonthOffsetClosed FYOffset (vs FY2025-26)
Aug-25 −2 0
Sep-25 −1 0
Oct-25 0 0
Nov-25 1 0
Mar-25 −7 −1
Oct-24 −12 −1

"Last 3 closed months" = Aug–Oct 2025 (offsets −2 to 0). Same month last year = offset −12 (Oct-24). After the November close the controller changes the parameter to 30-Nov-2025, the refresh shifts every offset by one, and the report moves to Sep–Nov without editing any slicer.

Edge cases & judgement calls

  • Relative date slicer vs offsets. The built-in relative date filter ("in the last 3 months") includes the current partial month and uses calendar months from today; it cannot reference a closed-period parameter.
  • Incremental refresh. Offsets computed in a large fact (instead of the Date table) would require full refresh; keep them on the Date table only.
  • Offsets on DirectQuery must be computed in the source or via a calculated table refreshed separately.
  • Cached reports in Excel. Analyze-in-Excel files show values as of the last dataset refresh — communicate as-of date on every page.
  • Year-end close overlap. In April–May, FY2024-25 audit is still open while FY2025-26 months close; a separate IsAuditClosedFY flag may be needed.

Key takeaways

  • MonthOffset and FYOffset turn "last N months" and "current vs last FY" into simple integer filters.
  • Use an as-of (last closed) date rather than TODAY() for finance dashboards.
  • Offsets are computed at refresh; refresh failures or UTC evaluation in the service can make them stale or wrong.
  • Integer offsets enable custom rolling windows on any calendar, including 4-4-5.
  • Keep offset columns on the Date table, never on the fact.

Practice Questions

Q1. Compute offsets [L1]

With the as-of date 31-Jan-2026, compute MonthOffset, QuarterOffset and FYOffset for 15-Apr-2025, 31-Dec-2025, 1-Mar-2026 and 10-Jan-2025.

Q2. Close-driven filter [L2]

Design the parameter table, the calculated columns and the report filter so that the MIS dashboard always shows the last three closed months and the same three months of the prior year, and describe the controller's monthly step to roll it forward.

💡 Hint: Two offset ranges combined with OR in a filter require a helper column or a measure filter.

Q3. UTC problem [L2]

A scheduled refresh runs at 02:00 IST on 1-Dec-2025 and the dashboard still shows November as month offset 0 — which the users wanted — but on 1-Jan-2026 a refresh at 06:30 IST shows December as offset −1 and January as 0, with no data. Explain both behaviours and propose a robust design.

Q4. Trailing measure on offsets [L3]

Write a trailing-6-month average monthly revenue measure using MonthOffset, which works when a single month is on the matrix rows and blanks for months with no actuals. Explain why it is calendar-agnostic.
