Key concept

Last Actual Date and Capping YTD at Posted Data

Concept: Last Actual Date = CALCULATE(MAX(GL[Date]), REMOVEFILTERS()); return YTD only when MIN('Date'[Date]) <= [Last Actual Date]

Statement

Last Actual Date =
CALCULATE ( MAX ( GL[Date] ), REMOVEFILTERS () )

YTD Actual (capped) =
VAR lastDate = [Last Actual Date]
RETURN
    IF (
        MIN ( 'Date'[Date] ) <= lastDate,
        CALCULATE ( [Actual], DATESYTD ( 'Date'[Date], "3/31" ) )
    )

A period is displayed if and only if its first date is on or before the last posting date:

\[ \text{Show}(P) \iff \min_{d \in P} d \le D_{\text{last}} \]

where \(P\) is the set of dates in the current filter context and \(D_{\text{last}}\) is the latest GL posting date across the whole model.

Explanation

The Date table covers whole fiscal years, so future months always exist. Without a cap, DATESYTD for December–March returns the same YTD as November (no new postings), producing a flat line, and PY measures for those future months return real prior-year values — so the FY total compares eight months with twelve.

REMOVEFILTERS() with no arguments clears every filter on every table, making the measure independent of slicers and of the row being evaluated: it is a model-wide constant (subject to row-level security, which it does not bypass). Storing it in a variable before the IF evaluates it once and makes it safe to use inside CALCULATE filter arguments elsewhere (for example 'Date'[Date] <= lastDate for a like-for-like PY cut).

Why MIN and not MAX: a month that is partly posted (1–18 November) must still show; its MIN (1 November) is before the last date while its MAX (30 November) is after. Using MAX would hide the current month until month-end.

Design variants:

  • REMOVEFILTERS('Date') instead of REMOVEFILTERS() — caps per entity/branch selection rather than globally.
  • Anchor on the last closed period for MIS: CALCULATE(MAX('Date'[Date]), 'Date'[IsClosedPeriod], REMOVEFILTERS()).
  • Exclude future-dated vouchers: CALCULATE(MAX(GL[Date]), REMOVEFILTERS(), GL[Date] <= TODAY()).

Illustration

Actuals to 18 November 2025; YTD revenue (₹ crore): October 236.0, November (to date) 268.0.

Oct 2025 1 Oct 2025 236.0 236.0
Nov 2025 1 Nov 2025 268.0 268.0
Dec 2025 1 Dec 2025 268.0 blank
Mar 2026 1 Mar 2026 268.0 blank
FY26 1 Apr 2025 268.0 268.0

The capped line chart stops at November instead of running flat to March. A single voucher dated 31 March 2026 (a mis-keyed date) would push Last Actual Date to year-end and silently disable the cap — include a data-quality card counting GL rows dated after today.

Connections

Central to s05 (partial periods, like-for-like PY cut), used as the anchor cap in s04/c04 for R12M, and placed inside calculation items in s07 so every measure inherits it. The closed-period variant relies on the IsClosedPeriod and IsYTD flags of Topic 2. In Weeks 17–20, the same date splits a full-year forecast into YTD actual plus remaining budget or forecast.

Practice Questions

Q1. MIN versus MAX [L1]

Explain, using dates, what happens to the November 2025 row in a monthly trend if the capped YTD uses MAX('Date'[Date]) <= [Last Actual Date] when actuals are posted to 18 November 2025.

Q2. Per-branch cap [L2]

Branch Kochi has posted to 30 November 2025 and branch Indore only to 22 November 2025. Compare the behaviour of REMOVEFILTERS() and REMOVEFILTERS('Date') in the Last Actual Date measure for (a) a page sliced to Indore and (b) the consolidated page, and recommend which to use for a branch performance league table.

💡 Hint: Ask which filters survive the removal in each version.

Q3. Data-quality guard [L2]

Write a measure that counts GL rows dated after the last closed period and a second measure that returns the last actual date excluding future-dated entries, and describe where in the report you would surface each.
