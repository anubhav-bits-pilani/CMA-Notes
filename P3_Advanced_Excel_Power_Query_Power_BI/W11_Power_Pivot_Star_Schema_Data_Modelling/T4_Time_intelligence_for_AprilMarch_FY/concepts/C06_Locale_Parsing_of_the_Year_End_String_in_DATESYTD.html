Key concept

Locale Parsing of the Year-End String in DATESYTD

Concept: The year-end string is parsed in the model/client locale; check that YTD resets in April (en-IN may need "31/3")

Statement

The year_end_date argument of DATESYTD, TOTALYTD, PREVIOUSYEAR, NEXTYEAR, OPENINGBALANCEYEAR, CLOSINGBALANCEYEAR and ENDOFYEAR is a string literal, not a date value. The engine converts it to a day and month using the locale (culture) of the model; the year portion, if present, is ignored.

  • In a model with an en-US culture, "3/31" (month/day) is parsed as 31 March.
  • In a model with a day-first culture (en-IN, en-GB), "31/3" is the unambiguous day/month form; "3/31" may fail to parse as intended and the function can silently behave as if the year ended on 31 December.

The control is behavioural: the April YTD must equal the April monthly value, and the March YTD must equal the full-FY total.

Explanation

Because the argument is text, there is no compile-time check that it means 31 March. Microsoft's documentation describes it as a date string in the locale of the client where the model (or workbook) was created. Power BI Desktop models carry a Model culture (visible in model properties; set from the regional settings when the file is first created), Power Pivot workbooks follow Excel's locale, and a model authored on one laptop and refreshed on a service or another machine keeps the model culture, not the viewer's.

Practical consequences for Indian teams:

  • A template built by a consultant in en-US and edited by a team in en-IN keeps its en-US culture — "3/31" keeps working.
  • A new file created on a laptop with Indian regional settings may need "31/3".
  • An ambiguous string such as "3/4" can mean 3 April or 4 March depending on culture. Use 31 as the day so only one interpretation is valid.
  • Some practitioners avoid the issue entirely by writing custom fiscal YTD on Date-table columns (FY number and fiscal month) — locale-proof and also usable for non-standard calendars:
YTD Actual (custom) =
VAR fy  = MAX ( 'Date'[FYEnd] )
VAR lastDate = MAX ( 'Date'[Date] )
RETURN
    CALCULATE (
        [Actual],
        REMOVEFILTERS ( 'Date' ),
        'Date'[FYEnd] = fy,
        'Date'[Date] <= lastDate
    )

Whatever form is used, document it in the measure description and include a test visual (fiscal months on rows, monthly and YTD columns) on a hidden QA page.

Illustration

A new model on an en-IN laptop uses TOTALYTD([Actual], 'Date'[Date], "3/31"). Revenue (₹ lakh):

Month Monthly YTD shown Expected FY YTD
Dec 2025 920 9,050 6,780
Jan 2026 870 870 7,650
Apr 2026 900 3,560 900

The January reset and the April accumulation show that the string was interpreted as a 31 December year end. Switching to "31/3" (or to the custom measure) and re-running the QA visual confirms an April reset: April 2026 YTD = 900.

Practice Questions

Q1. Diagnose from a pattern [L1]

YTD revenue in a model is equal to the monthly value in January and keeps accumulating through April and May. Explain what that tells you about the year-end argument and list two fixes.

Q2. Write a locale-proof QA check [L2]

Write a DAX measure that returns TRUE for every April row where [YTD Actual] = [Actual] and FALSE otherwise, and a card measure that counts failing April rows across all FYs in the Date table.

💡 Hint: Iterate fiscal years and compare the two measures for the first fiscal month in each.

Q3. Template governance [L3]

Your FP&A team distributes a Power BI template to 14 business units across India and Singapore. Draft a short governance note covering how the year-end argument should be written, how model culture is checked, and what test evidence each unit must attach before publishing.
