YTD, QTD and MTD Measures for an April–March Fiscal Year

Scope: YTD, QTD and MTD with the fiscal year-end parameter

Why it matters

Every Indian MIS pack, board note and SEBI LODR Regulation 33 quarterly result is presented on an April–March fiscal year: "Q3 FY26" means October–December 2025 and "YTD December" means 1 April to 31 December. A Power BI or Power Pivot model that cannot produce these cumulative windows correctly is useless to a CFO office. The to-date family of functions (TOTALYTD, TOTALQTD, TOTALMTD and their DATESYTD, DATESQTD, DATESMTD table equivalents) is the first time-intelligence block you build, and the year-end parameter is the single argument that decides whether your YTD resets in April or wrongly in January.

Core notes

What a "to-date" function actually does

A to-date function does not aggregate anything by itself. It reads the last date visible in the current filter context on the Date table, then returns a table of dates from the start of the period (year, quarter or month) up to that last date. CALCULATE then replaces the existing date filter with that table and re-evaluates the base measure.

Function Returns Period start logic Year-end argument?
DATESYTD(dates, [year_end]) Table of dates Day after the previous year-end Yes
DATESQTD(dates) Table of dates First day of the calendar quarter No
DATESMTD(dates) Table of dates First day of the month No
TOTALYTD(expr, dates, [filter], [year_end]) Scalar Wraps CALCULATE(expr, DATESYTD(...)) Yes
TOTALQTD(expr, dates, [filter]) Scalar Wraps CALCULATE(expr, DATESQTD(...)) No
TOTALMTD(expr, dates, [filter]) Scalar Wraps CALCULATE(expr, DATESMTD(...)) No

The year-end parameter

DATESYTD and TOTALYTD accept a year-end string such as "3/31". The year part, if supplied, is ignored; only day and month matter. Without it the function assumes 31 December, so on Indian books a "YTD November" value would cover only January–November of the calendar year, straddling two fiscal years.

YTD Actual = TOTALYTD ( [Actual], 'Date'[Date], "3/31" )

YTD Actual (table form) =
CALCULATE ( [Actual], DATESYTD ( 'Date'[Date], "3/31" ) )

The string is interpreted in the locale of the model, so in some en-IN or en-GB models "31/3" is required (covered in c06). The test is always behavioural: put fiscal month on rows and confirm that the April row equals the April monthly value.

Why QTD and MTD need no parameter

The April–March year is aligned to calendar quarters: fiscal Q1 = April–June = calendar Q2, fiscal Q2 = July– September = calendar Q3, and so on. DATESQTD simply finds the start of the calendar quarter containing the last visible date, which is also the start of the fiscal quarter. Quarter labels differ (calendar "Q2" vs fiscal "Q1"), but those come from your Date table columns, not from the function. Months are identical in both calendars, so MTD needs nothing either.

QTD Actual = TOTALQTD ( [Actual], 'Date'[Date] )
MTD Actual = TOTALMTD ( [Actual], 'Date'[Date] )

A company with a non-March year-end (for example a subsidiary of a foreign parent reporting January–December, or a 30 September year-end for group reporting) would need its own year-end string, and if its quarters do not align to calendar quarters, QTD would need custom logic using fiscal quarter columns.

The optional filter argument

TOTALYTD(expr, dates, filter, year_end) takes an optional filter as the third argument. This trips people up: if you write TOTALYTD([Actual], 'Date'[Date], "3/31") the third position is read as the year end because it is a string literal; if you want a filter and a year end you must supply both in order:

YTD Revenue = TOTALYTD ( [Actual], 'Date'[Date], CoA[FSLine] = "Revenue", "3/31" )

Many teams standardise on the CALCULATE + DATESYTD form because positional ambiguity disappears and additional filters can be added freely.

Worked illustration

GL revenue (credits shown as positive after sign-flip), FY26 in ₹ lakh:

Month Monthly YTD (with "3/31") YTD (no year-end)
Nov 2025 410 3,020 3,400 (Jan–Nov 2025)
Dec 2025 450 3,470 3,850
Jan 2026 380 3,850 380 (reset!)
Feb 2026 400 4,250 780
Mar 2026 520 4,770 1,300

The column without the year-end looks plausible until January, when it resets. The Q4 QTD for March would be 380 + 400 + 520 = 1,300, which is correct under either setting because Q4 FY26 = calendar Q1 2026.

At different visual granularities

  • Month row: last date = month-end; YTD = 1 April to that month-end.
  • Quarter row: last date = quarter-end; YTD = 1 April to quarter-end.
  • FY row or total: last date = 31 March; YTD = full year (so YTD at FY level equals the full-year sum).
  • Day level: YTD to that day, useful for daily cash or sales flash reports.

If the Date table extends into future months with no actuals, the FY-level YTD equals the YTD to the last posted date, which is correct as a number but labelled "FY26" — see s05 on capping.

Edge cases & judgement calls

  • Balance sheet accounts: YTD of a balance is meaningless (it sums movements, not balances); use the closing balance patterns of topic t5. YTD of BS movements is legitimate (e.g., YTD capex additions).
  • Filters on non-date columns of the Date table: if the user slices on 'Date'[FY Label], DATESYTD still works because a marked Date table automatically removes other Date-table filters when the date column is replaced. On an unmarked table related through an integer key, that removal does not occur and YTD collapses to the month — mark the table.
  • Fiscal-month slicer for "YTD as of": a single-select month slicer gives the as-of month; selecting multiple months makes the last selected month the as-of point, which surprises users. Use a single-select slicer.
  • Multi-entity groups with different year ends: one measure cannot serve two year ends; either standardise reporting to March or create per-entity YTD logic using fiscal columns.
  • Opening entries dated 1 April: they fall inside YTD of every month for P&L if they hit P&L accounts by mistake; check that opening-balance vouchers hit only BS accounts.

Key takeaways

  • To-date functions return a table of dates ending at the last visible date; CALCULATE applies it.
  • "3/31" (or the locale-equivalent "31/3") is mandatory for YTD on Indian books; QTD and MTD need no year-end.
  • TOTALYTD is syntactic sugar for CALCULATE(..., DATESYTD(...)); the table form avoids positional confusion.
  • Always validate that the April YTD equals the April month and that March YTD equals the FY total.
  • YTD applies to flows; balances need semi-additive patterns.

Practice Questions

Q1. Diagnose a January reset [L1]

A user reports that the YTD Revenue in your report drops from ₹ 38.5 crore in December 2025 to ₹ 3.8 crore in January 2026. The measure is YTD Revenue = TOTALYTD([Revenue], 'Date'[Date]). Explain the cause and rewrite the measure in both the TOTALYTD and the CALCULATE + DATESYTD forms.

Q2. Build a QTD/YTD matrix for SEBI results [L2]

Monthly revenue for FY25 (₹ crore): Apr 12, May 14, Jun 13, Jul 15, Aug 16, Sep 15, Oct 18, Nov 17, Dec 19, Jan 16, Feb 15, Mar 21. Lay out the values your QTD and YTD measures must show for each month, label each quarter in fiscal terms (Q1 FY25 … Q4 FY25), and state which test rows you would use to prove the model is correct.

💡 Hint: Fiscal quarters coincide with calendar quarters shifted by one label; check the first month of each quarter.

Q3. Filter argument versus year-end argument [L2]

A colleague writes YTD Opex = TOTALYTD([Actual], 'Date'[Date], "3/31", CoA[Statement] = "PL"). Explain what DAX will do with each argument, whether it will error, and write a correct version that returns YTD opex for cost centres in the "Corporate" division only.

Q4. Non-aligned group year-end [L3]

Your Indian subsidiary (March year-end) consolidates into a parent with a 30 September year-end, and the parent wants a "Parent-YTD" view alongside the Indian "FY-YTD" view in the same report. Design the measures and any Date table columns needed, explain why QTD may or may not need custom logic for the parent view, and describe the reconciliation test you would run between the two views for the six months October–March.

Q5. YTD on balance sheet lines [L1]

A junior analyst applies YTD Actual to the Trade Receivables line and shows ₹ 9,800 lakh at December when the trial balance shows ₹ 1,150 lakh. Explain what the YTD number represents and which kind of measure should be used instead.
