Subtopic note

SAMEPERIODLASTYEAR vs DATEADD vs PARALLELPERIOD

Scope: Prior-year comparisons with SAMEPERIODLASTYEAR, DATEADD and PARALLELPERIOD, and how they differ

Why it matters

Prior-year comparatives are mandatory in Ind AS financial statements (Ind AS 1.38), in SEBI quarterly results (corresponding quarter of the previous year and YTD comparatives) and in every management dashboard ("vs LY"). DAX offers three functions that look interchangeable but return different sets of dates. Picking the wrong one produces numbers that are internally consistent but silently cover the wrong period — the most dangerous kind of error in a board pack.

Core notes

The three functions

All three are table functions: they take the dates currently visible in filter context and return a different set of dates, which CALCULATE then applies as the new date filter.

Function Syntax What it returns
SAMEPERIODLASTYEAR SAMEPERIODLASTYEAR(dates) The visible dates shifted back exactly one year. Identical to DATEADD(dates, -1, YEAR)
DATEADD DATEADD(dates, n, DAY/MONTH/QUARTER/YEAR) The visible dates shifted by n intervals, keeping the same shape (contiguous set in, contiguous set out)
PARALLELPERIOD PARALLELPERIOD(dates, n, MONTH/QUARTER/YEAR) The entire period(s) at the chosen granularity, n periods away from the visible dates — always whole months, whole calendar quarters or whole calendar years 
PY Actual        = CALCULATE ( [Actual], SAMEPERIODLASTYEAR ( 'Date'[Date] ) )
PY Actual (DA)   = CALCULATE ( [Actual], DATEADD ( 'Date'[Date], -1, YEAR ) )
PY Full Month    = CALCULATE ( [Actual], PARALLELPERIOD ( 'Date'[Date], -12, MONTH ) )

DATEADD: shape-preserving shift

DATEADD shifts each date and returns the shifted set. If the visible context is 1–15 November 2025, DATEADD(..., -1, YEAR) returns 1–15 November 2024. If the context is a whole month, it returns the whole corresponding month, and there is month-end handling: when the selection runs to the last day of a month, the result runs to the last day of the target month. So February 2025 (1–28 Feb) shifted back one year returns 1–29 February 2024, not just the first 28 days. Shifting 29 February 2024 forward one year maps to 28 February 2025.

Interval choices matter:

  • DATEADD(..., -1, MONTH) → prior month (MoM comparisons, s03).
  • DATEADD(..., -1, QUARTER) → prior quarter (QoQ, as needed for "sequential quarter" commentary in results).
  • DATEADD(..., -1, YEAR) → same period last year.

SAMEPERIODLASTYEAR: a fixed-interval DATEADD

SAMEPERIODLASTYEAR has no interval argument; it is defined as a one-year back shift. It respects whatever period is selected — month, quarter, YTD window, or an arbitrary range — which is why it composes cleanly with YTD:

PY YTD = CALCULATE ( [YTD Actual], SAMEPERIODLASTYEAR ( 'Date'[Date] ) )

PARALLELPERIOD: whole-period expansion

PARALLELPERIOD ignores the exact shape of the selection. It identifies the periods (at the chosen granularity) that contain the visible dates, moves n periods, and returns them in full. Two consequences:

  1. At month level, PARALLELPERIOD(..., -12, MONTH) returns the entire month a year earlier even if the current context is a partial month (a date-range slicer ending on 15 November). Useful when you deliberately want a full-month comparative; dangerous when you want like-for-like.
  2. With YEAR granularity it returns entire calendar years (January–December). PARALLELPERIOD('Date'[Date], -1, YEAR) for November 2025 returns all of calendar 2024 — not FY25. There is no year-end argument. For an April–March business, use PARALLELPERIOD(..., -12, MONTH) on a full-FY selection, PREVIOUSYEAR(dates, "3/31"), or custom fiscal logic.

Side-by-side illustration

Date range slicer: 1 April 2025 – 15 November 2025 (a partial current month). Monthly revenue in FY25: Apr–Oct total ₹ 98 crore, November 2024 full month ₹ 17 crore, of which 1–15 November 2024 ₹ 8 crore. Calendar 2024 total ₹ 190 crore.

Measure Dates returned Value
SAMEPERIODLASTYEAR 1 Apr 2024 – 15 Nov 2024 98 + 8 = ₹ 106 crore
DATEADD(-1, YEAR) 1 Apr 2024 – 15 Nov 2024 ₹ 106 crore
PARALLELPERIOD(-12, MONTH) 1 Apr 2024 – 30 Nov 2024 (whole months) 98 + 17 = ₹ 115 crore
PARALLELPERIOD(-1, YEAR) 1 Jan 2024 – 31 Dec 2024 ₹ 190 crore

Only the first two give like-for-like comparison; the fourth is wrong for any Indian fiscal comparison.

Related helpers

  • PREVIOUSYEAR(dates, "3/31"), PREVIOUSQUARTER, PREVIOUSMONTH, PREVIOUSDAY return the whole prior period relative to the current selection (check dax.guide for whether the first or last visible date is the anchor for each function). PREVIOUSYEAR does accept a year-end and is a clean way to get "full prior FY" regardless of how much of the current FY is selected.
  • NEXTYEAR, NEXTQUARTER, NEXTMONTH are the forward equivalents (useful in forecast models).
  • DATESBETWEEN and DATESINPERIOD build explicit windows (s04).

Choosing the function

Need Use
Same months/days last year, including YTD windows SAMEPERIODLASTYEAR or DATEADD(..., -1, YEAR)
Prior month / prior quarter DATEADD with MONTH / QUARTER
Full prior FY whatever is selected PREVIOUSYEAR(..., "3/31")
Full prior month even if current month is partial PARALLELPERIOD(..., -12, MONTH) (deliberately)
Prior calendar year (rare in India; e.g., a US parent) PARALLELPERIOD(..., -1, YEAR)

Edge cases & judgement calls

  • Dates outside the Date table: if the shifted dates fall before the first date of the Date table, they are dropped, so the first FY in the table always has blank PY. Extend the calendar one year further back than the oldest comparative you need.
  • Non-contiguous selections: DATEADD requires a contiguous set in some engine versions and returns an error or unexpected results with multi-select non-adjacent months; avoid multi-select on month slicers for PY visuals.
  • Leap years: a daily comparison on 29 February 2024 has no exact match in 2023; SAMEPERIODLASTYEAR maps it to 28 February 2023, so that day is double-counted against 28 February in a daily trend. Rarely material, but explain it if a daily sales flash is audited.
  • Restated comparatives: if FY25 figures were restated (Ind AS 8 prior period error, or a business combination under common control under Appendix C of Ind AS 103), the PY measure reads whatever is in the GL. Comparative restatements must be posted or loaded as a separate scenario, not overwritten silently.
  • Mixed granularity in one visual: at FY total, DATEADD(..., -1, MONTH) shifts the whole year by a month (March prior FY to February) — nonsense. Blank MoM measures above month level (s03).

Key takeaways

  • SAMEPERIODLASTYEAR = DATEADD(dates, -1, YEAR); both preserve the shape of the selection.
  • PARALLELPERIOD returns whole periods; with YEAR it returns calendar years and has no fiscal argument.
  • For "full prior FY", use PREVIOUSYEAR(dates, "3/31") or PARALLELPERIOD(..., -12, MONTH) on a full FY.
  • Extend the Date table to cover all comparatives, or the earliest PY is blank.
  • Test each PY measure against a known period (e.g., Q3 FY25 from the published results).

Practice Questions

Q1. Pick the function [L1]

For each requirement, name the DAX function and write the measure: (a) revenue for the corresponding quarter of the previous year in a SEBI results table; (b) revenue for the immediately preceding quarter; (c) full FY24 revenue shown on every month row of FY25; (d) prior calendar-year revenue for a US parent reporting pack.

Q2. Reconcile three PY numbers [L2]

A dashboard with a date-range slicer set to 1 April 2025 – 20 December 2025 shows three "PY" tiles: ₹ 142 crore, ₹ 151 crore and ₹ 205 crore. FY25 monthly revenue: Apr–Nov 2024 total ₹ 128 crore, December 2024 ₹ 23 crore (1–20 December 2024: ₹ 14 crore), and calendar 2024 total ₹ 205 crore. Identify which function each tile most likely uses and state which one the CFO should see.

💡 Hint: Work out the date set each function would return for the slicer range, then add up the months.

Q3. Blank PY in the first year [L1]

Your Date table runs from 1 April 2023 to 31 March 2026 and GL data starts from 1 April 2023. Explain why the FY24 "PY Actual" column is blank, whether that is correct, and what you would change if FY23 comparatives are loaded later from a legacy Tally export.

Q4. Restated comparatives [L3]

In FY26 the company corrects a material prior-period error (inventory overstated by ₹ 4.2 crore at 31 March 2025) under Ind AS 8. The FY25 GL is locked and will not be re-posted. Design how the model should present PY figures in the FY26 results pack so that SAMEPERIODLASTYEAR-based measures show restated comparatives, and explain how you would keep the original "as reported" FY25 figures available for audit trail.
