Key concept

Closing Balance with LASTDATE on a Snapshot Fact

Concept: Closing Bal = CALCULATE(SUM(TB[Balance]), LASTDATE('Date'[Date])) for snapshot facts

Statement

Closing Bal = CALCULATE ( SUM ( TB[Balance] ), LASTDATE ( 'Date'[Date] ) )

For a filter context covering the date set \(P\):

\[ \text{Closing}(P) = \sum_{r \in \text{TB} \,:\, \text{Date}_{r} = \max(P)} \text{Balance}_{r} \]

where \(\max(P)\) is the latest date in the Date table visible in the current context and \(\text{Balance}_{r}\) is the snapshot balance on TB row \(r\). Across accounts, entities and cost centres the measure sums; across time it takes the period-end value.

Explanation

LASTDATE('Date'[Date]) returns a single-row, single-column table holding the last date visible in the current filter context. Used as a CALCULATE filter, it replaces the period filter with that one date, so SUM(TB[Balance]) reads only the snapshot rows dated at the period end. Because the filter is on the marked Date table's date column, other Date-table filters (month name, FY label) are removed and do not interfere.

Conditions for correctness:

  • Snapshot fact — the TB table holds closing balances, not movements.
  • Snapshots dated at period-ends that coincide with the Date table's last date in each displayed period — month-end dates for month/quarter/FY rows.
  • A snapshot exists for that date. If not (current month before close, FY row of an incomplete year), the measure returns blank. That may be desirable — a balance sheet "as at 31 March 2026" should not exist in November — but it must be handled explicitly with LASTNONBLANK (c02) or a cap at the last closed date.
  • Context transition is not needed — LASTDATE works on the filter context directly. Note that inside an iterator over the Date table LASTDATE would see the row-context date only if wrapped by CALCULATE.

LASTDATE vs MAX: LASTDATE returns a table (usable as a filter), MAX returns a scalar (usable in comparisons and variables). CALCULATE(SUM(TB[Balance]), 'Date'[Date] = MAX('Date'[Date])) is equivalent in most contexts, and the variable form is clearer when the date must be shown or capped.

Illustration

Month-end TB snapshots for Trade receivables (₹ lakh) exist to 31 October 2025: Apr 1,340; May 1,360; Jun 1,380; Jul 1,390; Aug 1,410; Sep 1,450; Oct 1,480.

Row Last visible date Closing Bal Sum of month-ends (wrong)
Aug 2025 31 Aug 2025 1,410 1,410
Q2 FY26 (Jul–Sep) 30 Sep 2025 1,450 4,250 (with July 1,390)
Oct 2025 31 Oct 2025 1,480 1,480
Nov 2025 30 Nov 2025 blank blank
FY26 31 Mar 2026 blank 9,810

The quarter shows the quarter-end balance; the FY row is blank because 31 March 2026 has no snapshot yet. A plain SUM(TB[Balance]) would show ₹ 9,810 lakh of "receivables" at FY26 — the sum of seven month-ends.
