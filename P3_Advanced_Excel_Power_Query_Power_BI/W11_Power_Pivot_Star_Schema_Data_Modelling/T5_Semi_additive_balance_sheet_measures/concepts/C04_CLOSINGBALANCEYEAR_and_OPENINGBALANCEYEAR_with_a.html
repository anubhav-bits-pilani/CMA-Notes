Key concept

CLOSINGBALANCEYEAR and OPENINGBALANCEYEAR with a March Year-End

Concept: CLOSINGBALANCEYEAR([Snapshot Bal], 'Date'[Date], "3/31"); OPENINGBALANCEYEAR([Cum Bal], 'Date'[Date], "3/31")

Statement

Closing Bal FY = CLOSINGBALANCEYEAR ( [Snapshot Bal], 'Date'[Date], "3/31" )
Opening Bal FY = OPENINGBALANCEYEAR ( [Cum Bal], 'Date'[Date], "3/31" )

For the fiscal year \(Y\) containing the last visible date (FY ending 31 March \(Y\)):

\[ \text{Closing}_{\text{FY}} = X\big(\text{31 Mar } Y\big) \qquad \text{Opening}_{\text{FY}} = X\big(\text{31 Mar } (Y-1)\big) \]

where \(X(d)\) is the balance measure passed as the first argument, evaluated with the date filter set to the single date \(d\). Full syntax: CLOSINGBALANCEYEAR(expression, dates [, filter] [, year_end_date]), and the same for OPENINGBALANCEYEAR.

Explanation

Both functions are date-shifting wrappers around CALCULATE. They do not know whether the measure is a snapshot sum or a cumulative total; they only set the date. Hence the pairing in the concept:

  • Snapshot fact → CLOSINGBALANCEYEAR([Snapshot Bal], …) with [Snapshot Bal] = SUM(TB[Balance]). At 31 March of the FY the TB snapshot exists (once the year is closed), so the measure returns the audited closing balance. For the current FY before year-end, the date 31 March 2026 has no snapshot and the result is blank.
  • Movement fact → OPENINGBALANCEYEAR([Cum Bal], …) with [Cum Bal] a running total. At 31 March of the prior FY the cumulative measure returns the closing balance carried forward, which is the opening of the current FY. Behaviourally, the opening functions evaluate at the day before the period starts, although the official documentation words it as the first date of the period — test once against a known TB.

The year-end string sets which 31 March counts. Without it the functions use 31 December: OPENINGBALANCEYEAR would return the balance at 31 December of the previous calendar year, a date that appears in no Ind AS statement. The string is parsed in the model locale ("3/31" or "31/3", Topic 4 c06).

Interaction with the Date table: the opening of the first FY in the model needs the prior 31 March to exist in the Date table. If the calendar starts on 1 April 2023, the FY24 opening is blank. Extend the calendar back by a year and date opening entries on 31 March 2023.

Note the asymmetric pitfall with CLOSINGBALANCEYEAR on a cumulative measure: for an incomplete year it evaluates at 31 March 2026, where [Cum Bal] simply returns the latest cumulative balance (no postings after the last actual date) — a number that looks like a year-end balance but is not. Cap or label it.

Illustration

Inventories (₹ lakh). Snapshot TB at 31 March 2024: 2,860; at 31 March 2025: 3,140. Movement GL gives cumulative 3,140 at 31 March 2025 and 3,420 at 31 October 2025 (data to that date).

Row Closing Bal FY (snapshot) Opening Bal FY (cumulative) CLOSINGBALANCEYEAR([Cum Bal], …)
FY25 3,140 2,860 3,140
FY26 (to Oct) blank 3,140 3,420 (not a year-end figure)
Oct 2025 row blank (31 Mar 2026) 3,140 3,420

The opening measure gives the same FY26 opening on every month row of FY26, which is what a roll-forward schedule needs.

Connections
