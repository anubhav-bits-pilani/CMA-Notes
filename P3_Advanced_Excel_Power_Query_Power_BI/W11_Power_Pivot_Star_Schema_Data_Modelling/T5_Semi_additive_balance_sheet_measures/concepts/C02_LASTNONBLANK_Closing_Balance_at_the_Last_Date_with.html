Key concept

LASTNONBLANK: Closing Balance at the Last Date with Data

Concept: CALCULATE(SUM(TB[Balance]), LASTNONBLANK('Date'[Date], CALCULATE(SUM(TB[Balance])))) takes the last date that has data

Statement

Closing Bal LNB =
CALCULATE (
    SUM ( TB[Balance] ),
    LASTNONBLANK ( 'Date'[Date], CALCULATE ( SUM ( TB[Balance] ) ) )
)

\[ d^{\dagger} = \max \{\, d \in P : B(d) \ne \text{BLANK} \,\}, \qquad \text{Closing}(P) = B(d^{\dagger}) \]

where \(P\) is the set of visible dates, \(B(d)\) is the sum of TB balances on date \(d\) in the current context (all other filters — account, entity — still applied), and \(d^{\dagger}\) is the latest date in \(P\) on which data exists.

Explanation

LASTNONBLANK(column, expression) iterates the distinct values of the column in the current context and returns, as a one-row table, the largest value for which expression is not blank. Two details make or break it:

  1. The inner CALCULATE is essential. During the iteration each date is a row context, which does not filter anything by itself. Wrapping the expression in CALCULATE performs context transition, turning the iterated date into a filter so that SUM(TB[Balance]) is evaluated for that single date. Without it, the sum is computed over the whole period for every date, is never blank, and the function simply returns the last calendar date — identical to LASTDATE.
  2. "Non-blank" is evaluated in the current context as a whole. At a total over many accounts, \(d^{\dagger}\) is the last date on which any account has a balance. Accounts without a snapshot on that date contribute nothing. For a per-account last date, iterate accounts: SUMX(VALUES(CoA[AccountKey]), [Closing Bal LNB]).

When to prefer it over LASTDATE: FY or quarter rows of the current year (shows the latest available balance instead of blank), daily balance tables with missing weekend snapshots, and dashboards where the "latest" balance is wanted at any grain. Costs: the expression is evaluated once per visible date (slower on daily snapshots across many years), and zero-balance rows dropped in Power Query make the function skip back to an older non-zero date. The newer LASTNONBLANKVALUE('Date'[Date], SUM(TB[Balance])) returns the value directly and applies context transition internally.

Illustration

Bank balance snapshots (₹ lakh), daily, but no rows on Sundays and bank holidays. Week ending Sunday 2 November 2025; the last snapshot in that week is Saturday 1 November at 845.

Measure Weekly row (27 Oct – 2 Nov) FY26 row (data to 18 Nov)
LASTDATE version blank (2 Nov has no row) blank (31 Mar 2026)
LASTNONBLANK without inner CALCULATE blank (returns 2 Nov) blank
LASTNONBLANK with inner CALCULATE 845 (1 Nov) balance at 18 Nov

Connections

Q1. Context transition walk-through [L2]

💡 Hint: Write down the filter context in force when SUM(TB[Balance]) is evaluated for one iterated date.

Q2. Total vs per-account [L2]

Compute the FY26 group receivables shown by Closing Bal LNB and by SUMX(VALUES(Entity[Entity]), [Closing Bal LNB]), and explain which a group CFO should see on a balance sheet page.
