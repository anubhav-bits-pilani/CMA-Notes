Subtopic note

Cumulative Balances from GL Movements, Including Opening Entries

Scope: Cumulative balance from movements: running total from inception, including opening entries

Why it matters

When the model holds GL movements rather than month-end TBs, every balance sheet number is a running total: the sum of all postings to that account from the first day of the books (or from the opening-balance entry) up to the as-of date. This is how the ledger itself works — a balance is opening plus debits minus credits — and it lets the same fact drive P&L, balance sheet, cash-flow movements and voucher-level drill-through. It is also the pattern most likely to produce a balance sheet that does not balance, because it depends on opening entries and on how P&L accounts are rolled into reserves.

Core notes

The running-total measure

Cum Bal =
CALCULATE (
    SUM ( GL[Amount] ),
    FILTER ( ALL ( 'Date'[Date] ), 'Date'[Date] <= MAX ( 'Date'[Date] ) )
)

Mechanics:

  1. MAX('Date'[Date]) — evaluated in the outer context inside FILTER's condition, but FILTER iterates ALL('Date'[Date]) in a row context, and MAX there still sees the outer filter context (row context does not filter), so it returns the period-end of the cell (e.g., 31 October 2025).
  2. ALL('Date'[Date]) removes the filter on the date column; FILTER keeps dates up to that period-end — every date from the start of the calendar.
  3. CALCULATE applies that list; because the Date table is marked, filters on other Date columns (month, FY) are removed too. All GL rows dated on or before the as-of date are summed.

A more readable and usually faster equivalent:

Cum Bal =
VAR asOf = MAX ( 'Date'[Date] )
RETURN
    CALCULATE ( SUM ( GL[Amount] ), REMOVEFILTERS ( 'Date' ), 'Date'[Date] <= asOf )

At any period row, the result is the closing balance at that period's end; the quarter shows the quarter-end balance and the FY shows 31 March — semi-additive by construction.

Opening entries

A movement-based model starts on some date (say 1 April 2023). Everything before that must arrive as opening entries: one row per BS account carrying the audited closing balance at 31 March 2023, voucher type "Opening". Rules:

  • Date them on the first day of the Date table (1 April 2023) or extend the calendar back to cover them. An opening entry dated outside the Date table does not join to a calendar date and its inclusion depends on accident.
  • Include every BS account — share capital, reserves, deferred tax, provisions, not only debtors and creditors. The opening entries must sum to zero (debits = credits).
  • Exclude them from P&L views: P&L measures filter CoA[Statement] = "PL", and opening entries hit only BS accounts. If the prior-year profit is in "Profit and Loss Account" (Tally style), map it to Retained earnings.
  • Flag them (GL[VoucherType] = "Opening") so movement analyses (cash flow, receivables roll-forward) can exclude them.

Rolling P&L into retained earnings

In the GL, P&L accounts are never "closed" in DAX: Cum Bal for a revenue account at 31 October 2025 accumulates revenue since April 2023. On the balance sheet, those P&L accounts must be presented as part of Other equity — Retained earnings / Surplus in the statement of P&L (Schedule III, Division II), split into:

  • Prior years' profits: cumulative P&L of all fiscal years before the current one.
  • Current-year profit: YTD P&L of the current fiscal year.
Retained Earnings (incl. P&L roll) =
VAR asOf = MAX ( 'Date'[Date] )
RETURN
    CALCULATE ( SUM ( GL[Amount] ), REMOVEFILTERS ( 'Date' ), 'Date'[Date] <= asOf,
                REMOVEFILTERS ( CoA ), CoA[FSLine] = "Retained earnings" )
    + CALCULATE ( SUM ( GL[Amount] ), REMOVEFILTERS ( 'Date' ), 'Date'[Date] <= asOf,
                  REMOVEFILTERS ( CoA ), CoA[Statement] = "PL" )

Profit for the Period =
VAR asOf    = MAX ( 'Date'[Date] )
VAR fyStart = DATE ( YEAR ( EDATE ( asOf, -3 ) ), 4, 1 )   -- 1 April of the FY containing asOf
RETURN
    CALCULATE ( SUM ( GL[Amount] ), REMOVEFILTERS ( 'Date' ),
                'Date'[Date] >= fyStart, 'Date'[Date] <= asOf,
                REMOVEFILTERS ( CoA ), CoA[Statement] = "PL" )

Retained Earnings Brought Forward =
[Retained Earnings (incl. P&L roll)] - [Profit for the Period]

EDATE(asOf, -3) moves back three months so that dates from April to December map to the same calendar year and January–March map back to the previous one; this gives the FY start without a Date-table lookup. In a layout-driven balance sheet, "Retained earnings brought forward" and "Profit for the period" can be shown as separate lines, which together equal Other equity — surplus in the statement of profit and loss.

If the ERP does post year-end closing entries (P&L accounts zeroed into retained earnings at 31 March), do not add P&L again for closed years: include P&L only from the start of the current FY. Know your source.

The balancing check

With signed amounts (debits positive, credits negative), all BS accounts plus all P&L accounts cumulatively sum to zero at every date — the trial balance balances. Build a check measure:

TB Check = CALCULATE ( [Cum Bal], REMOVEFILTERS ( CoA ) )

It must be zero (within rounding) on every month-end. A non-zero value means an unbalanced load (missing opening entry, filtered voucher type, partial refresh).

Worked illustration

Opening entries at 1 April 2024 (₹ lakh): Cash 400 Dr, Receivables 900 Dr, Payables 600 Cr, Share capital 300 Cr, Retained earnings 400 Cr. FY25 movements: sales 5,000 (Receivables Dr / Revenue Cr), collections 4,700 (Cash Dr / Receivables Cr), expenses 4,200 (Payables Cr / Expenses Dr), payments 4,100 (Payables Dr / Cash Cr).

Account Cum Bal at 31 Mar 2025
Cash 400 + 4,700 − 4,100 = 1,000 Dr
Receivables 900 + 5,000 − 4,700 = 1,200 Dr
Payables 600 + 4,200 − 4,100 = 700 Cr
Share capital 300 Cr
Retained earnings (account) 400 Cr
P&L accounts (Revenue 5,000 Cr, Expenses 4,200 Dr) 800 Cr
Retained earnings presented 400 + 800 = 1,200 Cr

Assets 2,200 = Payables 700 + Share capital 300 + Retained earnings 1,200. Without the P&L roll the balance sheet would be short by 800.

Edge cases & judgement calls

  • Performance: a running total from inception over a daily calendar is fine for tens of millions of rows in VertiPaq; if matrices slow down, pre-aggregate an account-month snapshot in Power Query and keep GL for drill.
  • Restated history: re-mapping an account to a new FS line instantly restates all historical balances; good for comparability, but historical reports will not match previously issued packs.
  • Multiple entities: with entity on rows, Cum Bal is per entity; inter-company eliminations must be posted as an elimination entity, or the group balance sheet will be grossed up.
  • Foreign-currency balances: INR cumulative balances on monetary items need month-end revaluation entries (Ind AS 21); otherwise the model differs from the TB by the unrealised exchange difference.
  • Opening entries for P&L accounts in a mid-year migration: if the model starts on 1 October, opening P&L YTD balances must be loaded too, or H1 profit is missing from the current-year profit line.

Key takeaways

  • Cum Bal sums all movements up to the as-of date, removing all Date filters; it is semi-additive by construction.
  • Opening entries must cover every BS account, net to zero, and fall within the Date table.
  • P&L accounts must be rolled into retained earnings in BS presentation (prior years plus current YTD), unless the ERP posts closing entries.
  • A TB check (all accounts cumulative = 0) on every month-end proves completeness.
  • Choose the readable VAR + REMOVEFILTERS form; pre-aggregate only if performance requires.

Practice Questions

Q1. Write and explain [L1]

Write the Cum Bal measure in both the FILTER(ALL(...)) and the VAR + REMOVEFILTERS forms, and explain why MAX('Date'[Date]) inside the FILTER condition returns the period-end of the cell rather than each iterated date.

Q2. Build a balanced balance sheet [L2]

Opening entries at 1 April 2025 (₹ lakh): PPE 2,500 Dr, Inventory 800 Dr, Cash 300 Dr, Borrowings 1,200 Cr, Share capital 1,000 Cr, Retained earnings 1,400 Cr. April–September movements: revenue 3,600 (all collected in cash), material cost 2,100 (paid in cash), depreciation 150, interest 60 (paid), loan repayment 200. Compute each account's cumulative balance at 30 September 2025, the retained earnings to present, and verify assets = equity + liabilities.

💡 Hint: Post each movement as a two-sided entry first, then accumulate by account.

Q3. Closing entries in the source [L2]

Your source ERP posts a closing entry each 31 March transferring all P&L balances to Retained earnings. Explain what the Retained Earnings (incl. P&L roll) measure in this note would show at 31 October 2025 and rewrite it so it is correct for this ERP.

Q4. TB check failing [L3]

The TB Check measure is zero for all months to March 2025 and then −₹ 3.4 lakh for every month from April 2025. List the plausible causes (at least four, covering data load, Power Query steps, CoA mapping and Date table), and describe the DAX queries or visuals you would use to isolate the cause.
