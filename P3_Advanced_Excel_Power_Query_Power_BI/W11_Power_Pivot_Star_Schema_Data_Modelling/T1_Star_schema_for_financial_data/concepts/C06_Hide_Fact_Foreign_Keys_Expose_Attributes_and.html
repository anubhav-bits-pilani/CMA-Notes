Key concept

Hide Fact Foreign Keys; Expose Attributes and Measures

Concept: Hide fact foreign keys; expose only dimension attributes and measures to report users

Statement

In a finance star schema, set Is hidden = Yes (Power BI) or Hide from Client Tools (Power Pivot) for:

  • every foreign-key column in fact tables (GL[AccountKey], GL[CostCentreKey], GL[BranchKey], GL[PostingDate], GL[DueDate], Budget[MonthStart], TB[MonthEnd]);
  • raw numeric columns that should only be aggregated through measures (GL[Amount], Budget[Amount], TB[Balance]);
  • technical columns in dimensions (surrogate keys, sort-order columns, SignFactor).

Expose to users only dimension attributes (FY, FiscalQuarter, FSLine, CostCentre name, Branch, State) and explicit measures ([Actual], [Budget], [Variance ₹], [Variance %], [YTD Actual], [PY YTD]). Optionally hide fact tables entirely so they appear only as measure homes, or move measures to a dedicated measures table.

Explanation

Why it matters:

  1. Correct filtering. If a user drags GL[AccountKey] or GL[PostingDate] onto a slicer, the filter is placed on the fact column. It filters GL but not Budget or TB, so Budget shows totals that ignore the slicer — a classic "Budget doesn't respond to my filter" complaint. Slicing by CoA[AccountName] or 'Date'[Date] filters all facts through conformed dimensions.
  2. Time intelligence. Time functions must receive 'Date'[Date]; a visible GL[PostingDate] invites users and developers to use it (topic 2 pitfall).
  3. Implicit measures. A visible numeric GL[Amount] lets users drag it and get an implicit SUM with no format, no sign logic and no Budget equivalent. Hiding it forces use of explicit, governed measures. Power BI also offers a model setting Discourage implicit measures (required automatically when calculation groups exist).
  4. Usability. The field list shows a clean, business-oriented set: Date, Accounts, Cost Centres, Branches, and a folder of measures.
  5. Sort columns. Hiding LineSort and FiscalMonthNo prevents users from putting numbers on rows by accident; the Sort by Column setting still works on the visible label.

Hiding is not security: hidden columns are still queryable (DAX query view, Analyze in Excel with field lists toggled, XMLA). Use row-level and object-level security for confidentiality, such as hiding salary accounts.

Columns can still be used in measures and relationships after hiding. In Excel Power Pivot, hidden columns are greyed in Diagram View and disappear from the PivotTable field list.

Illustration

Before cleanup, the field list for a Mumbai-based NBFC's MIS model shows GL with 14 fields (AccountKey, CostCentreKey, BranchKey, PostingDate, DocDate, DueDate, VoucherNo, Amount, …). A regional manager builds a table with GL[PostingDate] as a slicer set to March 2026, plus [Actual] and [Budget]. Actual shows the March figure (₹6.8 crore) while Budget shows the full FY2025-26 figure (₹78 crore), because the slicer never reaches Budget. After hiding all GL columns and exposing only 'Date' attributes and measures, the same report built with 'Date'[MonthName] shows March budget ₹6.5 crore beside actuals.

Practice Questions

Q1. Hide list [L1]

For a model with GL, Budget, TB, CoA, Date, CostCentre and Branch, list every column you would hide and every field you would leave visible, grouped by table.

Q2. Diagnose the complaint [L2]

A user reports that Budget ignores the Branch slicer, while Actual responds correctly. The model has Branch → GL and no Branch → Budget relationship, and the slicer uses GL[BranchKey]. Explain the two separate problems and the fixes.

💡 Hint: One problem is about which column the slicer uses; the other is about Budget's grain.

Q3. Hidden is not secure [L2]

The HR head asks you to hide the "Directors' remuneration" accounts from branch users. Explain why hiding columns is insufficient and outline the RLS or OLS approach you would use instead.
