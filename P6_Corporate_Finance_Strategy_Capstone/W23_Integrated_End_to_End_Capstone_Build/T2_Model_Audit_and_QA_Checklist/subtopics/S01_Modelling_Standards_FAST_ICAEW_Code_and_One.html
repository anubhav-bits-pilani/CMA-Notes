Modelling Standards: FAST, ICAEW Code and One Formula per Row

Scope: Standards: FAST Standard, ICAEW Financial Modelling Code, consistent column structure and one formula per row

Why it matters

A model is a communication device as much as a calculation engine. Someone else, whether a reviewer, an investment committee, an auditor or your successor in an FP&A team, has to understand, check and change it. Modelling standards turn individual style into shared conventions, so a reviewer can predict where things are and how they are built. In the capstone portfolio audit, "Dynamic Structure" and "Visual Clarity" are rubric categories in their own right, and most of their marks follow from these standards. Indian banks, Big 4 transaction services, infrastructure lenders' engineers and project finance teams frequently specify FAST or a house standard derived from it for models submitted to them.

Core notes

The FAST Standard

FAST stands for Flexible, Appropriate, Structured, Transparent. It is a free, openly published set of rules maintained by the FAST Standard Organisation, originally developed in project finance practice. Its core ideas:

  • Flexible: the model can be updated and extended without redesign (new year, new scenario, new segment).
  • Appropriate: the detail matches the decision. No 50-row schedule for a 1% cost line.
  • Structured: a consistent logical flow, consistent layouts across sheets, and separation of inputs, calculations and outputs.
  • Transparent: any user can follow any number back to its inputs quickly.

Representative FAST rules applied in the capstone:

FAST principle Capstone application
Separate inputs, calculations and outputs Inputs and Historicals sheets hold all hard-codes; schedules hold calculations; DCF, Sensitivity and Cover are outputs
Consistent timeline across sheets Same year in the same column on every calc sheet (e.g. FY27 always in column J)
One formula per row, copied across No column-specific formulas in forecast blocks
Short, simple formulas ("a formula should be no longer than your thumb") Break long nested IFs into helper rows
Calculate once, link thereafter WACC computed once on DCF, referenced elsewhere; not recomputed
Avoid multi-sheet chains Link to the source line on the sheet where it is calculated, not to an intermediate link
Flags for timing Use 1/0 flag rows (forecast flag, commissioning flag) multiplied into formulas instead of nested IF on dates
Labels and units on every row Column B label, column C unit (₹ crore, %, days, MT)
No hidden rows/sheets with live logic Use grouping, not hiding

Some FAST rules are stricter than common banking practice: discouraging circularity entirely, discouraging named ranges for time series, and preferring that a sheet's calculations do not reference later sheets. Know where your model departs and state it on the Cover.

The ICAEW Financial Modelling Code

The Institute of Chartered Accountants in England and Wales published its Financial Modelling Code in 2018 (updated since) as a principles-based, vendor-neutral code, developed with input from modelling practitioners and existing standards bodies. Its principles cover the following areas (paraphrased here; check the current edition for its exact section structure):

  • Model purpose and specification: document what the model is for, its scope and its users.
  • Structure and design: logical flow, clear separation of inputs, calculations and outputs, and consistency.
  • Inputs: clearly identified, sourced, dated and stored once.
  • Calculations: consistent, simple, without hard-coded numbers in formulas, and free of unnecessary complexity.
  • Outputs: clear and linked to calculations, with checks.
  • Checks and review: built-in integrity checks, a review and testing process, and version control.

The Code is less prescriptive than FAST. It sets out what good looks like, and FAST tells you exactly how to build it. For an Indian CMA moving into FP&A, the ICAEW Code is useful as an audit checklist framework, because it reads like a set of control objectives, and it maps neatly to spreadsheet controls in ICFR (topic related item).

Consistent column structure

Every calculation sheet should use the same column skeleton:

Column Content
A Spacer / section marker
B Line label
C Unit
D Constant or source reference (single-value inputs, totals, notes)
E–I Historical years FY22A–FY26A
J–S Forecast years FY27E–FY36E
T Terminal or check column (optional)

Benefits: any cross-sheet link pulls the same period (column J on the IS is FY27 because column J on every sheet is FY27); fill-right and R1C1 checks work; and printing is consistent. The timeline row (year label, period end, forecast flag) sits in rows 3–6 of every sheet and links to Inputs.

One formula per row

Within a forecast block, every cell in a row should contain the same formula structure, copied across. If FY27 needs special treatment (e.g. linking opening balance from the last actual year), handle it with a flag or a separate row, not by typing a different formula in column J.

Bad (three different formulas in one row):

J20: =I20*1.08
K20: =J20*(1+K$12)
L20: =K20*(1+L$12)+15

Good (one formula, with differences driven by inputs):

J20: =I20*(1+J$12)+J$13
K20: =J20*(1+K$12)+K$13

Here row 12 holds the growth input and row 13 holds a one-off adjustment row (blue, mostly zero). In R1C1 view, every cell in row 20 reads =RC[-1]*(1+R12C)+R13C, which is the basis of the row consistency test (c02).

Mapping to the assessment rubric

Rubric category Standards that earn marks
Accuracy Calculate once, checks, no hard-codes in formulas
Dynamic Structure Consistent timeline, one formula per row, flags, scenario switch
Visual Clarity Labels and units, colour coding, grouping, consistent layout
Business Insight Appropriate detail on value-driving lines, outputs that answer the question

Edge cases & judgement calls

  • Historical versus forecast blocks. Historical columns hold hard-coded or linked actuals, and forecast columns hold formulas. A row can legitimately have two formula types split at the actual/forecast boundary. Make that boundary visually clear (a vertical border and a shaded header) and test consistency within each block.
  • First forecast year. Opening balances from the last actual year can be handled with a flag-based single formula, for example =IF(J$6=1,I45,J44), rather than a special cell.
  • Long formulas versus helper rows. Helper rows add length, but they are auditable. Prefer them.
  • House style conflicts. If an employer's template uses different colours or layouts, follow the house style and apply the underlying principles.
  • Standards are not compliance regimes. No regulator mandates FAST in India. Claim "built broadly in line with FAST principles" rather than "FAST compliant" unless you have actually tested every rule.

Key takeaways

  • FAST means Flexible, Appropriate, Structured, Transparent. It is prescriptive build rules from project finance practice.
  • The ICAEW Financial Modelling Code is principles-based: purpose, structure, inputs, calculations, outputs, checks and review.
  • Use the same column skeleton and timeline on every calculation sheet so the same column always means the same period.
  • One formula per row, copied across. Drive exceptions with input or flag rows, not special-cased cells.
  • Map your model to the rubric. Standards earn most Dynamic Structure and Visual Clarity marks.

Practice Questions

Q1. Rewrite to one formula per row [L2]

A revenue row reads: J30 =I30*1.12, K30 =J30*1.10, L30 =K30*1.10+25, M30 =L30*(1+M$8). Row 8 holds growth inputs only from column M. Redesign the input rows and write a single formula for J30 that can be copied to S30 and reproduces the intended values.

💡 Hint: Every number embedded in a formula needs a home in an input row.

Q2. FAST versus house style [L2]

Your employer's template uses named ranges for every time series and a circular interest calculation. Compare these two practices with FAST guidance and recommend how to handle the capstone model you will share with an external reviewer.

Q3. Column skeleton design [L1]

Specify the column skeleton and the timeline rows for a model with FY22A–FY26A actuals, a FY27 stub and FY28E–FY36E forecasts, and explain how the stub affects the consistent-column rule.

Q4. ICAEW Code as an audit checklist [L3]

Convert the ICAEW Financial Modelling Code principles into a 12-item review checklist for an FP&A budget model, with one test procedure per item, written so that an internal auditor could execute it.
