Subtopic note

The Executive Cover Sheet: Purpose, Outputs, Checks, Versions

Scope: Executive cover sheet: purpose, key outputs, scenario selected, check status, version log, assumptions source list

Why it matters

The Cover is the first, and for many readers the only, sheet they look at. A CFO, an investment committee member or an interviewer decides in under a minute whether to trust the model, based on whether they can see what it is for, what it concludes, which scenario they are looking at, whether its checks pass, which version it is and where the assumptions come from. A good Cover also protects you: it records the conditions under which outputs were produced (scenario, calculation mode, circularity switch), so a number lifted out of the model can be traced back. The roadmap calls for "clear executive cover sheets", and the week's cross-cutting exercise requires the check status to be recorded on the Cover.

Core notes

Layout (one screen, one printed page)

Block Contents Linked or typed
Header Company name, NSE symbol, model title, valuation date, units ("₹ crore unless stated"), model status (Draft / Final v1.0) Typed (blue) except status
Purpose 2–4 lines: what decision the model supports, scope (consolidated, FY27–FY36), intended users Typed
Key outputs EV, equity value, value per share, CMP, upside/downside %, implied EV/EBITDA and P/E, TV % of EV, WACC, g Linked (green) from DCF
Operating snapshot FY26A and FY28E revenue, EBITDA, margin, PAT, net debt/EBITDA, ROCE, key KPI (e.g. EBITDA/tonne) Linked
Scenario selected Live scenario name in large font, switch value, warning if not base Linked + conditional format
Model settings Calculation mode note, circularity switch state, lease basis (post-116), sign convention, tax rate Mixed
Check status Master check (OK/ERROR), counts by check type, error count, last checked timestamp Linked from Checks
Version log Version, date, author, description of changes, reviewer Typed table
Sources Source list S1–Sn with document, date, page Typed or linked from Inputs
Navigation Hyperlinked index of sheets with one-line descriptions, colour legend Formulas

Purpose statement

A good purpose statement is specific: "Estimate the intrinsic equity value per share of Kaveri Building Products Ltd as at 30-Nov-2026 using a 10-year FCFF DCF cross-checked with peer EV/EBITDA, and identify FP&A levers on working capital and capex phasing. Built from public filings for portfolio purposes; not investment advice." It states the decision, the method, the date and the limitation.

Key outputs block

Link every output. Never type a value-per-share number onto the Cover. Show the CMP with its date and source. Include the base-case value and the scenario range (bear–bull) from the scenario output table. Format consistently with the deck (same units, rounding and labels) so that model, dossier and deck tie (week cross-cutting concept on consistency).

Scenario selected

=INDEX(Scenario_Names,Scenario)
=IF(Scenario<>1,"WARNING: NON-BASE SCENARIO ACTIVE","Base case")

Format the warning cell with an amber fill when not on base. This guards against sending a file on the bear case (topic pitfall 4).

Check status

Link to the master check (c01) and show a breakdown:

Check group Status Sum of abs. differences
Balance and cash OK 0.000
Roll-forwards (RE, PPE, CWIP, debt, leases) OK 0.000
Historical tie-outs OK 0.04 (within ±0.05)
Signs OK 0
Errors in calc sheets OK 0
Sensitivity centre = base OK 0.000
Master check OK

Add "Checks last confirmed: 23-Nov-2026 18:40, scenario base, CB = 1, F9 pressed", typed at freeze. This text is what the week's QA exercise requires.

Version log

Version Date Author Changes Reviewed by Master check

The file name should carry the version (P4_Capstone_KBPL_v1.0.xlsx) and match the log (t3 naming convention).

Assumptions source list

Either a full list on the Cover or the top 8–10 value-driving assumptions with sources, linking to the full Sources table on Inputs:

Disclaimers and protection

Add a short disclaimer (public data only, not investment advice, no employer data) and consider sheet protection on the Cover and outputs, with the password noted in the README if the file is shared for review (t3 on protected xlsx).

Edge cases & judgement calls

  • Cover overload. If the Cover exceeds one screen, move the source list and version log to a second "Admin" sheet and keep a summary on the Cover.
  • Typed "OK". A check status typed as text is worse than none. It must be a live link.
  • Model settings that cannot be read by formula (calculation mode, iteration). Record them as typed notes at freeze and include them in the version log entry.
  • Charts on the Cover. A small revenue/EBITDA chart and a value-range bar are useful. Keep them linked and minimal.
  • Different audiences. For an FP&A budget model, the "key outputs" become budget EBITDA, cash, headcount and variance to prior year rather than value per share, but the structure is the same.

Key takeaways

  • The Cover answers six questions: what for, what result, which scenario, do checks pass, which version, from what sources.
  • All outputs and check status are live links, never typed values.
  • Show the live scenario prominently with a non-base warning.
  • Keep a version log matching file names, with master check status per version.
  • List the top value-driving assumptions with dated sources, linked to the full source table.

Practice Questions

Q1. Draft a purpose statement [L1]

Write a purpose statement (40–70 words) for (a) your capstone DCF model and (b) an FY28 annual operating budget model for a consumer durables company's FP&A team.

💡 Hint: Include decision, method, scope, date and limitation.

Q2. Cover formula set [L2]

Write formulas for the Cover cells: value per share (linked), upside/downside % versus CMP, scenario name, non-base warning, master check status and a "TV % of EV" flag that turns amber above 75%.

Q3. Version log review [L2]

A model's file name is Capstone_final_FINAL2.xlsx, the Cover says v0.9 and the version log's last entry is v0.7 with master check "ERROR". Explain the control failures and prescribe the corrective process before sharing.

Q4. Design a Cover for review [L3]

Design (as a table of blocks, cells and sources) a one-page Cover for your capstone that would let a reviewer complete the Saturday rubric's Accuracy and Business Insight scoring without opening any other sheet first.
