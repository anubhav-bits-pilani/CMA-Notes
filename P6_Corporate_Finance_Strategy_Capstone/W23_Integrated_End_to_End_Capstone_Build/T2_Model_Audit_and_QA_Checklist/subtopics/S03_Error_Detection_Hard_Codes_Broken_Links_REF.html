Subtopic note

Error Detection: Hard-Codes, Broken Links, #REF!, IFERROR, Circularity

Scope: Error detection: hard-codes inside formulas, broken links, #REF!, masked errors via blanket IFERROR, circular references

Why it matters

Studies of operational spreadsheets have repeatedly found errors in a large share of the models examined, and the most damaging errors are often invisible: a growth rate typed into a formula, a link to last year's file, an IFERROR returning zero where a calculation failed. In a valuation, one hidden hard-code in the terminal year can move value per share by 10–20%. Auditors, investment committees and capstone reviewers therefore look for these five error classes first. Each has a characteristic cause, a detection method and a fix, and together they form the core of the one-hour model audit in the week's checklist.

Core notes

1. Hard-codes inside formulas

What: a number typed into a formula that should be an input: =J20*1.08, =K45+15, =L30*0.2517. Exceptions that are usually acceptable are mathematical constants (/2 for an average, *12 for months, /365, /100 for units), and these should be documented.

Why it is dangerous: invisible on the face of the sheet, not changed by the scenario switch or sensitivity tables, and impossible to source.

Detection:

  • Go To Special → Constants on calculation ranges finds pure hard-codes (s04).
  • ISFORMULA-based conditional formatting highlights constants in forecast blocks.
  • Hard-codes inside formulas need a text search: Find (Ctrl+F, Look in: Formulas) for *1., +1, 0.25, or a helper row with =FORMULATEXT(J20) plus a search for digits.
  • The Inquire add-in's Workbook Analysis report lists formulas containing constants.

Fix: move the constant to an input row (blue) with a label, unit and source, and reference it.

2. Broken links

What: references to other workbooks (='[Peers_v3.xlsx]Comps'!F12) that no longer exist, have moved or are an old version. Opening the file triggers an "update links" prompt, and if the user declines or the source is missing, the stale cached value persists without warning.

Detection: Data → Edit Links (or Workbook Links in Microsoft 365) lists every external source and its status. Find [ in formulas. Inquire also reports links. Check named ranges (Name Manager) and chart series for hidden external references.

Fix: for a capstone, have no external links. Paste the peer data as values on a dated input sheet with a source note, then Break Link. If links are essential (a live FP&A consolidation), document the source path on the Cover.

3. #REF! errors

What: a reference whose target cell, row, column or sheet was deleted. It appears as =#REF!*J12 in the formula.

Detection: Go To Special → Formulas → Errors, Find "#REF!" in formulas, and the master check (errors propagate into totals and checks). Inside an iterative loop, #REF! floods the model (Week 23 t1 c06).

Fix: restore the reference (undo, or rebuild from the row's consistent neighbours). Prevention: do not delete rows that feed other sheets without first tracing dependents (s04). Use Ctrl+[ to check before deleting.

4. Masked errors via blanket IFERROR

What: wrapping whole calculations in IFERROR(…,0) or IFERROR(…,"") so that any error, including a genuine #REF! or a wrong lookup, silently becomes zero (topic pitfall 1).

Why people do it: to make a model look clean, or to handle a known, legitimate case (division by zero in years with no revenue) with a catch-all.

Correct practice:

  • Handle the specific expected condition explicitly: =IF(J10=0,0,J20/J10) instead of =IFERROR(J20/J10,0).
  • For lookups, use IFNA (catches only #N/A) or XLOOKUP's if_not_found argument, so other errors still surface.
  • If IFERROR is unavoidable, return a visible flag ("CHECK") or feed an error-count check.

Detection: Find IFERROR across the workbook, list each instance, and justify or replace it. Temporarily replace IFERROR( with a dummy text such as xIFERROR( and see which cells would error.

5. Circular references

What: a formula chain that refers back to itself. Intended circularity (interest on average debt) differs from accidental circularity (e.g. tax computed on PBT that includes interest income on cash that depends on tax paid, created by an innocent link).

Detection: with iterative calculation off, Excel shows "Circular References" in the status bar and under Formulas → Error Checking → Circular References, which lists the cells. With iteration on, Excel stays silent, so audit with the circuit breaker at 0 and iteration off and confirm that no circular warning remains.

Fix: remove accidental loops (link to opening balances), and confine intended loops to one documented loop with a circuit breaker (t1 c06).

Error-count check

Add an error-count row to the Checks tab for each calculation sheet:

=SUMPRODUCT(--ISERROR(IS!E8:S120))

It feeds the master check, so any error anywhere turns the Cover to "ERROR". This only works if errors are not masked, which is one more reason to avoid blanket IFERROR.

Audit routine (one hour)

Minutes Test Tool
0–10 Error and circularity scan Go To Special → Errors; status bar circular warning with iteration off
10–20 External links and names Edit Links; Name Manager filter for errors/external
20–35 Hard-codes Go To Special → Constants on calc sheets; Find for embedded numbers; FORMULATEXT review
35–45 IFERROR inventory Find all; justify or replace
45–55 Row consistency R1C1 view or FORMULATEXT comparison (c02)
55–60 Checks and flex test Master check, one extreme input (c04)

Edge cases & judgement calls

  • Unit constants. /10^7 to convert rupees to crore is acceptable if consistently applied and noted. A better approach is a named unit factor input.
  • Hard-coded historical actuals are inputs, not errors, but they belong on Historicals with a source, not typed into a statement sheet.
  • IFERROR around XIRR or IRR: these can fail to converge for legitimate cash flow patterns. Return a flag text rather than zero.
  • Phantom links that remain in charts, data validation lists or defined names after you break cell links. Check all three.
  • Deliberate circularity versus FAST preference. Even if your loop is intended, an external reviewer may require it removed. Have the opening-balance fallback ready.

Key takeaways

  • The five error classes are hard-codes in formulas, broken external links, #REF!, masked errors and circular references.
  • Find hard-codes with Go To Special, ISFORMULA formatting and formula-text searches, then move them to labelled inputs.
  • Eliminate external links in portfolio models. Paste values with dated sources and check names and charts for residual links.
  • Replace blanket IFERROR with explicit conditions or IFNA, and let genuine errors surface into an error-count check.
  • Audit circularity with iteration off and the circuit breaker at 0. Accept only one documented, switchable loop.

Practice Questions

Q1. Classify and fix [L1]

For each formula, identify the error class and write the corrected version with any new input rows: (a) =K30*(1+0.06); (b) =IFERROR(VLOOKUP(B5,Peers!A:F,4,0),0); (c) ='[Capex_plan_old.xlsx]Sheet1'!D9; (d) =#REF!+K44; (e) =K40*0.2517.

💡 Hint: Decide for each whether the fix is relocation, replacement or removal.

Q2. IFERROR inventory [L2]

A model has 214 IFERROR instances. Describe a step-by-step method to inventory them, decide which are justified, and replace the rest, including how you would prove that no hidden error was introduced or removed.

Q3. Accidental circularity [L2]

After you add interest income on average cash to the IS, Excel reports a circular reference although your debt interest uses opening balances. Trace the loop in words and propose two ways to resolve it.

Q4. Audit under time pressure [L3]

You are given a 22-sheet DCF model built by someone else and one hour before an investment committee meeting. Using the audit routine in these notes, prepare a minute-by-minute plan and a one-page findings template with severity ratings (critical, major, minor) and the value impact of each finding.

Q5. Error-count check design [L2]

Write the formulas for an error-count row on the Checks tab covering the IS, BS, CFS and DCF sheets, and explain why the check is meaningless if blanket IFERROR is used elsewhere in the model.
