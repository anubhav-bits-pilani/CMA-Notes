Subtopic note

Sensitivity Integrity: Live Data Tables and Tested Scenarios

Scope: Sensitivity integrity: data tables wired to live inputs, calculation set appropriately, scenario switches tested end-to-end

Why it matters

Sensitivity tables and scenarios are what turn a point estimate into a decision range. They are the heat map in the executive deck, the football field's DCF bar and the "what if" answer in an interview. They are also the part of the model most likely to be silently wrong. A data table whose input cell is on another sheet returns nonsense or a constant. A table that has not been recalculated shows yesterday's numbers. A bear-case switch that changes revenue but not capex makes the downside look milder than it is. Because these outputs are read without re-deriving them, integrity testing must be deliberate.

Core notes

Data table mechanics

Data → What-If Analysis → Data Table creates a {=TABLE(row_input, col_input)} array:

  1. Place the output formula (e.g. =DCF!H62 value per share) in the top-left corner of the table.
  2. Enter the row input values across the top (e.g. terminal g 4.0%–6.0%) and column input values down the left (WACC 11.0%–14.0%).
  3. Select the whole block and set Row input cell = the g input cell and Column input cell = the WACC input cell.

Excel substitutes each pair into the input cells, recalculates the whole model and records the output. Rules:

  • The input cells must be on the same sheet as the data table. Excel refuses ("Input cell reference is not valid") if you point to another sheet. A common workaround then produces the topic pitfall: placing a local copy of the input on the Sensitivity sheet that the model does not actually use.
  • Correct wiring: either build the data table on the Inputs sheet next to the live inputs, or make the model's live input a formula that picks up a sensitivity "override" cell on the Sensitivity sheet:
Inputs!D20 (live WACC used by model):  =IF(Sens!$C$3="ON",Sens!$C$4,Inputs!D19)

Here Inputs!D19 is the base WACC and Sens!C4 is the data table's column input cell. Simplest of all is to locate the WACC and g inputs on the DCF sheet and build the table there. - The table's axis values must be inputs, not formulas that depend on the input cell, otherwise the axis moves as Excel substitutes values. - The centre value must reproduce the base output. Put the base WACC and g in the middle of the axes and check that the centre cell equals the DCF output. Add this as a check row (Sens centre − DCF value = 0).

Typical capstone sensitivity set

Table Rows × columns Output Purpose
WACC × terminal g 5 × 5 (±100 bps, ±1%) Value per share Core DCF sensitivity
WACC × exit multiple 5 × 5 (±2×) Value per share TV method sensitivity
Volume growth × realisation growth 5 × 5 EV or FY28 EBITDA Operating sensitivity for FP&A
RM cost/tonne × realisation 5 × 5 EBITDA margin Margin squeeze
One-way tornado Each key input ±10% Value per share Ranks value drivers

Format with conditional formatting (3-colour scale) for heat maps. Show the CMP in the title so readers see where the market sits.

Calculation settings

Data tables recalculate the whole model once per cell. A 5 × 5 table means 25 full recalculations, and five tables mean 125, so a large model with tables becomes slow. Options (Formulas → Calculation Options):

  • Automatic: everything recalculates on every change. This is the safest, but slow with many tables.
  • Automatic except for data tables: the model recalculates normally, while tables update only on F9 (c05). This is the standard setting for large models, but you must press F9 before reading or pasting sensitivities, and record the setting on the Cover.
  • Manual: risky for anything shared. Users see stale numbers. Avoid it in sent files.

The calculation mode is application-wide: the first workbook opened in a session sets it, so a colleague's file can change your setting. Check the status bar for "Calculate" (it signals pending recalculation).

Scenario switches tested end to end

A scenario switch (base = 1, bull = 2, bear = 3) is only reliable if every scenario-dependent driver is wired through it and every output responds. End-to-end test procedure:

  1. Inventory drivers on Inputs: list every driver that should differ by scenario (volume, realisation, cost per unit, capex, commissioning date, working capital days, WACC adjustments if any).
  2. Trace each to the live row: confirm that calculations reference only the live (selected) row, never the base row directly. Search formulas for references to the base block (Find on the base row address).
  3. Flip the switch to each scenario and record value per share, FY28 EBITDA, peak net debt/EBITDA and the master check in a scenario results table. All checks must pass in every scenario.
  4. Directional test: bull > base > bear for value and EBITDA. If bear capex is higher but value moves the "wrong" way, investigate.
  5. Delta test: change one driver in the bear block only and confirm that only the bear output moves.
  6. Reset to base before saving and sending (topic pitfall), with the Cover showing the live scenario name in large type and a check that turns amber if the switch is not on base.

A scenario output table built with a one-variable data table on the switch cell gives all scenarios simultaneously: column input = switch cell, values 1, 2, 3, output = value per share. It obeys the same same-sheet rule, so place the switch on the sheet hosting the table or use the override approach.

Illustration

Base value per share ₹612 at WACC 12.3% and g 5.0%. Sensitivity table centre cell shows ₹598. Diagnosis: the table was last calculated before a capex update, because calculation was set to "Automatic except for data tables". After F9 the centre shows ₹612. The check row "Sens centre − DCF value" would have flagged the ₹14 difference.

Edge cases & judgement calls

  • Data tables inside circular models. Iterative calculation plus data tables can be slow or unstable. Switch the circuit breaker to opening-balance interest for sensitivity runs, or accept longer calculation times, and disclose which.
  • Scenario Manager (built-in tool). Excel's What-If → Scenario Manager stores input sets but is opaque and rarely used in institutional models. Prefer the visible CHOOSE/INDEX block.
  • Asymmetric scenarios. Bear is often not the mirror image of bull (a commissioning delay matters more than an early start). Do not force symmetric ±% changes.
  • Pasting sensitivities as values into a deck appendix. Paste after F9 and timestamp the paste.
  • Too many tables. Over five large tables, consider a macro-driven sensitivity loop or moving the analysis to a separate copy.

Key takeaways

  • Data table input cells must be on the table's own sheet. Wire them to the model's live inputs, never to orphan copies.
  • The centre cell must reproduce the base output, so add it as a check.
  • "Automatic except for data tables" speeds large models but requires F9 before reading. Record the mode on the Cover.
  • Test scenarios end to end: driver inventory, live-row tracing, flip and record, directional and delta tests, all checks passing.
  • Reset the switch to base before sending, and show the live scenario on the Cover.

Practice Questions

Q1. Wiring a cross-sheet sensitivity [L2]

Your WACC input is on Inputs!D19 and g on Inputs!D21, while the 5 × 5 data table must sit on the Sensitivity sheet. Design the override cells, the live-input formulas on Inputs and the data table set-up, and write the check that proves the table is live.

💡 Hint: The model must read one cell for each input whose value the table can drive.

Q2. Stale table diagnosis [L1]

A reviewer notices that changing WACC on Inputs moves the DCF value but none of the sensitivity cells. List the three most likely causes and how to confirm each.

Q3. Scenario test log [L2]

Design a scenario test log table (columns and rows) for a base/bull/bear model with eight scenario drivers, including directional and delta tests, and specify the pass criteria for each test.

Q4. Performance versus safety [L3]

A 40-sheet model with six data tables takes 90 seconds to recalculate in Automatic mode. The FP&A head wants it shared with business unit controllers who are not modellers. Recommend calculation settings, design changes and user instructions, and explain the control risks of each option.
