Subtopic note

Presentation Standards: Colour Codes, Units, Freeze Panes, Grouping

Scope: Presentation: colour coding (blue inputs, black formulas, green cross-sheet links), units labels, freeze panes, grouping

Why it matters

Presentation conventions are not decoration. They tell the reader, without clicking, what each cell is: something to change, something calculated or something brought in from elsewhere. A reviewer who can see at a glance that a forecast cell is blue (an input) where it should be black (a formula) has found a hard-code in a second. In the portfolio audit, "Visual Clarity" is scored separately, and interviewers form a view of a candidate's discipline in the first ten seconds of opening a file. Consistent formatting also reduces your own errors in a timed build.

Core notes

Colour coding (font colour)

Colour Meaning Examples
Blue Hard-coded input or historical data Growth rates, WACC inputs, historical financials, scenario switch
Black Formula calculated on the same sheet Schedules, totals, ratios
Green Formula that links to another sheet IS revenue pulled from Revenue build, BS cash from CFS
Red (optional) Check cells or warnings Balance check, flags
Purple/other (optional) Links to external files Avoid entirely in the capstone (s03)

Conventions in practice:

  • Colour applies to font, not fill. Optionally add a light fill (pale yellow) for input cells so they stand out in print.
  • Apply colours with cell styles (Home → Cell Styles: create "Input", "Calc", "Link", "Check") rather than manual formatting, so one change updates the whole model.
  • Use Go To Special to apply colours systematically: Constants → blue; Formulas → black; then green for cross-sheet links. Excel cannot select cross-sheet links directly, so search formulas for ! with Find All → Ctrl+A to select the results → apply green.
  • Some house styles differ (e.g. green for links to other files, black for same-workbook links). State the legend on the Cover.

Units labels

Every row needs a unit, and every sheet needs a stated base unit:

  • Column C holds the unit: ₹ crore, ₹/tonne, %, days, MT mn, x (multiple), # (count).
  • The sheet title row states "All figures in ₹ crore unless stated".
  • Percentages are formatted as %, not as decimals labelled "%".
  • Number formats are consistent: #,##0.0;(#,##0.0);"–" for ₹ crore (negatives in brackets, zero as a dash), 0.0% for ratios and 0.0"x" for multiples.
  • Indian digit grouping (lakh/crore commas, 1,00,000) can be set with a custom format [>=10000000]##\,##\,##\,##0;[>=100000]##\,##\,##0;##,##0, but in models reported in ₹ crore, standard thousands grouping is clearer.

Unit errors (₹ lakh mixed with ₹ crore, % entered as a whole number) are among the commonest material errors in Indian models. They also undermine the week's consistency theme across model, dossier and deck.

Freeze panes

View → Freeze Panes on every calculation sheet at the cell below the timeline header and to the right of the label/unit columns (e.g. E7). Labels and years then remain visible while scrolling. Apply the same freeze point on every sheet for a consistent navigation feel. Remove split panes in favour of freeze.

Grouping

Data → Group (Shift+Alt+Right arrow) collapses detail rows or columns behind outline buttons:

  • Group detailed build-ups (individual cost lines, debt tranches) under their totals so a reader can view the summary first.
  • Group historical columns to show forecasts only when presenting.
  • Never hide rows or columns with live logic. Hidden rows are invisible to readers and easy to miss in review. Grouping shows the outline symbol, which signals that there is more.
  • Set outline settings so that summary rows sit below the detail (Data → Outline settings) consistently with the flow of the sheet.

Other layout conventions

  • Sheet structure: title (row 1), units statement (row 2), timeline (rows 3–6), sections with bold headers and a blank row between sections.
  • Totals: single top border for subtotals, double bottom border for grand totals, bold.
  • Tab colours: a colour per sheet type (inputs, calculations, outputs, checks) and a navigation index on the Cover.
  • Hyperlinked contents: =HYPERLINK("#'DCF'!A1","DCF") links on the Cover for navigation.
  • Column widths: uniform period column widths, and no merged cells in calc areas. Use "Centre Across Selection" instead.
  • Zoom: set each sheet to the same zoom (85–100%) and select A1 before saving, so the file opens cleanly.
  • Comments/notes: use cell notes for source references on inputs (S1 p.214).

Formatting pass in the timebox

Format in one pass during the QA block (t1 s07) using styles: select inputs → Input style; select formulas → Calc style; select links → Link style; then number formats; then freeze panes, grouping and tab colours. This takes 20–30 minutes with styles and much longer without them.

Edge cases & judgement calls

  • Formulas on the Inputs sheet (e.g. a computed timeline or WACC) are black even though they sit on an input sheet. Colour reflects cell content, not sheet type.
  • Historical data linked from a data sheet is green on statements and blue on the Historicals sheet where it was typed or pasted.
  • Colour-blind readers. Supplement colour with fill patterns or a style legend. Blue and green can be hard to distinguish for some readers.
  • Conditional formatting overuse. Heat maps belong on sensitivity outputs, not across calc blocks, where they obscure the colour code.
  • Over-grouping. Three levels of nested groups confuse more than they help. Keep it to one or two.

Key takeaways

  • Blue = input, black = same-sheet formula, green = cross-sheet link. Apply them with cell styles, and put the legend on the Cover.
  • Every row carries a unit in column C. Every sheet states its base unit and uses consistent number formats.
  • Freeze panes at the same point (below the timeline, right of labels) on every calc sheet.
  • Group, never hide, rows with live logic.
  • Format in a single styles-based pass during QA to protect time.

Practice Questions

Q1. Colour audit [L1]

Classify the correct font colour for: (a) FY24 revenue typed on Historicals; (b) FY28 revenue on the IS linked from Revenue build; (c) the WACC formula on the DCF sheet; (d) the scenario switch; (e) a check cell on the Checks tab; (f) a timeline formula on Inputs.

💡 Hint: Colour follows what the cell contains, not where it sits.

Q2. Style-based formatting routine [L2]

Write a step-by-step routine, using cell styles and Go To Special, to recolour a 17-sheet model that was built entirely in black font, including how to identify cross-sheet links.

Q3. Unit error hunt [L2]

A model shows FY27 RM cost of ₹1,46,250 against revenue of ₹2,630 crore, and an EBITDA margin of −5,500%. Explain the likely unit error, how the unit column and number formats should prevent it, and add a check that would catch it.

Q4. Presentation review [L3]

You receive a peer's capstone with merged cells in the IS, hidden rows in the Debt sheet, no units column, manual fills in six colours and frozen panes only on the Cover. Write a prioritised list of presentation fixes with the reason for each and an estimate of the time needed.
