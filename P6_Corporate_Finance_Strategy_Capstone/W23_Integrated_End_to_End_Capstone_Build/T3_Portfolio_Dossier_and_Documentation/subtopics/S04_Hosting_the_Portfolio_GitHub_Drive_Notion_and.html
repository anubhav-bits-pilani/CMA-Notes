Hosting the Portfolio: GitHub, Drive, Notion and LinkedIn

Scope: Hosting: GitHub repository with README, Google Drive/OneDrive folders, Notion page, LinkedIn Featured section

Why it matters

A portfolio that cannot be opened is no portfolio. Hosting decisions determine how reviewers reach your work, whether files render in a browser, whether links survive for months, and how the portfolio is discovered from your CV and LinkedIn. Each platform has strengths: GitHub provides version history and a professional README landing page; Drive/OneDrive provides easy file viewing and downloading; Notion provides a polished, navigable front page; LinkedIn Featured puts the portfolio in front of recruiters. A layered set-up — one canonical store, one front page, one discovery channel — is more robust than relying on one platform.

Core notes

GitHub repository with README

GitHub is designed for code but works well for portfolios because of version control, a rendered README.md landing page and stable URLs. Set-up:

  1. Create a public repository, e.g. fpa-portfolio or cma-finance-portfolio.
  2. Root README.md as the index: one-paragraph profile, a table listing P1–P6 with one-line descriptions and links to each folder and brief PDF, a skills matrix summary, contact details, and a confidentiality statement ("All data is public or synthetic").
  3. One folder per project: P1_IndAS_ClosePack/, P2_Ratio_Forensic_Benchmark/, etc., each with its own README.md (per c03), the brief PDF, the working file, a screenshots/ subfolder, and optionally sources/ with links rather than copies of large PDFs.
  4. Use Git commits with meaningful messages ("P4 v1.1: fix lease liability in EV bridge") so the history doubles as a change log.
  5. Use the Releases feature to tag frozen versions (v1.0) and attach large files.

Practical constraints: GitHub blocks files over 100 MB and warns above 50 MB; Git LFS is available but adds complexity — keep workbooks small instead. GitHub does not preview xlsx or pbix in the browser; it does render markdown, images and PDFs. Binary files do not diff meaningfully, so the commit message carries the change description. Images in README use relative paths, e.g. ![Cover](screenshots/P4_Cover.png).

Google Drive / OneDrive folders

Drive and OneDrive let reviewers preview PDFs, view xlsx in the browser (Google Sheets preview or Excel for the web) and download. Set-up: one top-level folder Portfolio_<Name>_2026, subfolders per project mirroring the GitHub structure, sharing set to "Anyone with the link — Viewer" (disable download only if you have a reason; reviewers usually want to download). On OneDrive, check whether your link has an expiry date; personal accounts allow link settings, and organisational tenants may block external sharing entirely — so never host on an employer's OneDrive. Note that Google Sheets preview may not render dynamic arrays, data tables or some formatting faithfully; recommend downloading for the full model.

Notion page

Notion offers a clean, web-published front page: a header with profile, a gallery or table database of the six projects (cover image = key screenshot, properties = skills, tools, status), and each project as a sub-page with brief text, embedded screenshots, embedded video and links to files on GitHub/Drive. Publish via "Share to web". Advantages: mobile-friendly, visually polished, quick to update. Risks: published pages are publicly indexable if search-engine indexing is enabled; embedded Drive files inherit Drive permissions, so test them logged out.

LinkedIn Featured section

The Featured section on your profile displays up to several pinned items (posts, articles, links, media). Recommended items: (1) link to the Notion/GitHub portfolio front page, (2) the capstone deck PDF uploaded as media, (3) the dashboard video or PDF, (4) a LinkedIn post or article summarising the capstone insight. Each item has a title and description — use the STAR result line as the description. The "Projects" section of the profile can list each project with a link and associated skills. Uploaded documents on LinkedIn become downloadable/viewable by anyone who can see your profile, so the confidentiality and disclaimer rules apply.

Choosing a canonical store

Platform Best for Weakness Role in set-up
GitHub Version history, stable links, README rendering No xlsx/pbix preview; intimidating to some reviewers Canonical file store
Drive/OneDrive Easy preview and download Permissions errors; link drift if files moved Mirror for non-technical reviewers
Notion Polished navigation, mobile Depends on embedded links working Front page
LinkedIn Featured Discovery by recruiters Limited structure Discovery channel

Pick one canonical store (usually GitHub) and treat others as mirrors updated from it. Keep a link register: platform, item, URL, last tested date, result.

Edge cases & judgement calls

  • Recruiters unfamiliar with GitHub. Put a Notion or Drive link first on the CV; mention GitHub as "version-controlled files".
  • Corporate network blocks. Some employer networks block Drive or GitHub; a PDF dossier attached to an email application is a useful fallback.
  • Link permanence. Moving or renaming files in Drive keeps the file ID, so links usually survive; deleting and re-uploading does not. GitHub links break if folders are renamed — fix the README links after any rename.
  • Privacy. Do not publish your phone number or full address on a public repository; an email and LinkedIn URL suffice.
  • Licensing of content. Annual-report PDFs are publicly available but copyrighted; link to them on NSE/company websites rather than redistributing large copies.
  • Search indexing. Decide whether you want the Notion page indexed. Indexing helps discovery but exposes the work permanently.

Key takeaways

  • Use a layered set-up: GitHub (canonical), Drive/OneDrive (preview mirror), Notion (front page), LinkedIn Featured (discovery).
  • The root README is the portfolio index; each project folder has its own README, brief, files and screenshots.
  • Set sharing to "anyone with the link — viewer", never host on an employer tenant, and test links logged out.
  • Keep files small (GitHub limits at 100 MB) and link to large source documents rather than copying them.
  • Maintain a link register with last tested dates.

Practice Questions

Q1. Repository structure [L1]

Write the complete folder and file tree for a GitHub repository holding all six projects, including the root README, each project README, brief PDFs, working files, screenshots and sources subfolders, using a consistent naming convention.

Q2. Root README index [L2]

Draft the root README for your portfolio repository in markdown: profile paragraph, a project table (number, title, one-line result, link to brief, link to folder), confidentiality statement, valuation disclaimer and contact line.

Q3. Diagnosing broken access [L2]

Three reviewers report: (a) the Drive link asks them to request access; (b) the OneDrive link worked last month but now shows "This link has expired"; (c) the Notion page loads but embedded screenshots show "You need permission". Diagnose the cause of each and state the fix and the test you would run to confirm.

💡 Hint: Embedded content inherits the permissions of the platform where the file actually lives.

Q4. Platform choice for a time-pressed recruiter [L3]

A recruiter at an NSE-listed company's finance shared-services centre says she reviews candidates on her phone between meetings and forwards shortlisted profiles to the FP&A head, who uses a corporate laptop with restricted internet. Design the hosting and linking approach that serves both, specifying which link goes where on the CV and LinkedIn, and what fallback you attach to an email application.
