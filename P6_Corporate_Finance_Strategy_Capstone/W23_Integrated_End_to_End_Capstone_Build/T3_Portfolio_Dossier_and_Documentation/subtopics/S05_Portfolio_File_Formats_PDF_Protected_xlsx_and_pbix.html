Portfolio File Formats: PDF, Protected xlsx and pbix Exports

Scope: File formats: PDF summaries, protected xlsx, pbix plus PDF exports; caution with Power BI Publish to web (public)

Why it matters

Reviewers use different devices and software: a recruiter on an iPhone, a hiring manager on a locked-down corporate laptop, a technical interviewer with full Excel and Power BI Desktop. The right mix of formats means each can see the work at the depth they need. Format choices also carry risks — macro files that are blocked, protected workbooks that cannot be audited, and Power BI Publish to web links that expose data to the entire internet. Getting formats right is part of the professional judgement the portfolio is meant to demonstrate.

Core notes

PDF summaries

PDF is the universal layer: it renders identically on every device, preserves layout, and cannot be accidentally changed. Publish as PDF: every one-page brief, the dossier (all briefs plus index and skills matrix in one file), the capstone deck, sample outputs from each model (statements, DCF summary, variance pack), and Power BI report exports.

PDF practice:

  • Export from the source application (Excel: File > Export > PDF with the print areas set; PowerPoint: Save As PDF) rather than printing to PDF, so hyperlinks and bookmarks survive.
  • Set document properties (title, author = your name) and remove employer names from metadata.
  • Keep file sizes small (compress images; under about 5 MB for the deck).
  • Add bookmarks for the dossier so a reader can jump to P4.
  • Include a footer with file name, version and date on every page.

Protected xlsx

The working Excel model is the deep-verification layer. Format choice:

  • .xlsx, not .xlsm. Since 2022 Microsoft blocks VBA macros by default in Office files downloaded from the internet (Mark of the Web), and many reviewers will not unblock them. If you used macros (e.g. a copy-paste circularity breaker), provide a macro-free .xlsx version with the iteration switch approach and describe the macro in the README.
  • Protection scope. Use worksheet protection (Review > Protect Sheet) to lock formula cells against accidental overwrite while leaving input cells (blue) unlocked so the reviewer can flex assumptions. Allow "Select locked cells" so formulas remain visible in the formula bar. Workbook structure protection prevents sheet deletion or insertion. Avoid password-to-open encryption — it blocks preview entirely — and do not hide formulas: the point of the file is that reviewers can audit your logic.
  • Understand the limits. Excel sheet protection is a usability guard, not security; it is easily removed. Do not rely on it to protect intellectual property or confidential data — anything sensitive must not be in the file at all.
  • Pre-publication hygiene. Run File > Info > Check for Issues > Inspect Document to remove personal information and hidden content you do not intend to share; break external links (Data > Edit Links); remove unused names (Formulas > Name Manager); reset the scenario switch to base; set calculation to automatic (or note "Automatic except data tables — press F9"); save with the cover sheet active and cell A1 selected on each tab.
  • Size. Remove pasted raw data you no longer need, clear excess used range, and consider saving as .xlsb privately only if needed — publish .xlsx for compatibility.

pbix plus PDF exports

A .pbix file can be opened only in Power BI Desktop, which runs on Windows. Many reviewers lack it. Publish the pbix for technical reviewers, and alongside it:

  • PDF export from Power BI Desktop (File > Export > Export to PDF) or from the Service — captures every visible page as static images.
  • PowerPoint export from the Service (optional) — each page as a slide image.
  • Screenshots of the data model and DAX measures (s03).
  • Video walkthrough (s06) to show interactivity.

Before sharing a pbix: remove any credentials in data source settings, replace local file paths with relative or parameterised sources (a Power Query parameter for the folder path), and make sure the data embedded in the model is public or synthetic — the pbix contains the imported data even if visuals show only aggregates.

Caution with Power BI Publish to web (public)

Publish to web generates a public URL and embed code for a report. Anyone with the link can view it without signing in, the link may be found by search engines or shared onward, and Microsoft documents it as unsuitable for confidential or proprietary information. Key points:

  • It is controlled by a tenant admin setting; many organisations disable it or restrict it to specific security groups.
  • Row-level security does not apply to Publish to web content — every viewer sees all data in the report.
  • Embed codes can be deleted later from the Service's Manage embed codes page, but copies or screenshots already taken cannot be recalled.
  • Never use an employer tenant to publish portfolio content, and never publish anything that is not fully public or synthetic.
  • Licensing and availability change over time — check current Microsoft documentation rather than relying on older blog posts.

A safer alternative for most candidates: PDF export plus a 3-minute video, with the pbix downloadable for those who want to explore.

Format matrix

Reviewer Device Sees
Recruiter Phone Notion page, brief PDFs, video
Hiring manager Corporate laptop, browser Dossier PDF, deck PDF, Excel for the web preview
Technical interviewer Full Excel, Power BI Desktop Protected xlsx, pbix, README

Edge cases & judgement calls

  • Dynamic arrays and new functions. LET, LAMBDA, XLOOKUP and dynamic arrays fail or return #NAME? in Excel 2016/2019. State the minimum Excel version in the README (Microsoft 365 or Excel 2021+).
  • Data tables in web preview. Excel for the web may not recalculate data tables fully; tell reviewers to download.
  • Very large pbix. Reduce cardinality, remove unused columns and disable auto date/time to shrink the file.
  • Protecting against copying. If you are concerned about others reusing your templates, a watermark on PDFs and your name on the cover sheet is more effective than passwords.
  • Google Sheets conversion. Do not convert the master model to Google Sheets for sharing; some functions and data tables do not translate.

Key takeaways

  • PDF is the universal layer for briefs, dossier, deck and sample outputs; export from source to keep hyperlinks.
  • Publish .xlsx (not .xlsm), with sheet protection on formulas but inputs unlocked and formulas visible; no open-password.
  • Sheet protection is not security — only public or synthetic data belongs in the file.
  • Pair every pbix with a PDF export, screenshots and video; clean credentials and local paths first.
  • Publish to web is fully public, bypasses RLS and is often disabled by tenants; use only for public data on a personal tenant, if at all.

Practice Questions

Q1. Pre-publication checklist for the capstone workbook [L2]

Write a 12-step pre-publication checklist for the P4 workbook, covering macros, protection settings, external links, document inspection, scenario reset, calculation mode, names, file size and the final save state, with the Excel menu path for each step.

Q2. Protection settings decision [L2]

A reviewer complained that your previous model "could not be audited" because formula cells showed nothing in the formula bar and the file asked for a password to open. Explain which two protection settings caused each symptom, why they are inappropriate for a portfolio, and the correct configuration.

Q3. Publish to web risk assessment [L3]

A friend proposes using Publish to web from his employer's Power BI tenant to host his portfolio dashboard, which uses data "anonymised" from a client's sales ledger by replacing customer names with codes. Assess every risk (data, contractual, ethical, technical) and recommend an alternative.

💡 Hint: Consider what the pbix data model and the public link actually expose, not just what the visuals show.

Q4. Choosing formats for each project [L1]

For each of P1–P6, list the files you would publish and their formats, explaining in one line why each format serves a specific reviewer type.
