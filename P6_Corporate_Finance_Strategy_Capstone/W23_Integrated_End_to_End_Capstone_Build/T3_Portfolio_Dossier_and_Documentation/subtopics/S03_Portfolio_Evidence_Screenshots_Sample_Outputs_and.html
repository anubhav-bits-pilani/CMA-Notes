Portfolio Evidence: Screenshots, Sample Outputs and Check Status

Scope: Evidence: annotated screenshots of models and dashboards, sample outputs, check-sheet status

Why it matters

A brief makes claims; evidence substantiates them. This is the same logic as audit evidence under SA 500 — sufficient, appropriate evidence supports the opinion. Many reviewers cannot or will not open a 15 MB workbook on a phone, and Power BI files need Desktop on Windows. Annotated screenshots and PDF sample outputs let them inspect the work in seconds. Showing the check-sheet status — a visible "OK" master check with the individual checks listed — is the single most persuasive piece of evidence for a modelling role, because it shows you know models break and you built controls to prove yours does not.

Core notes

Annotated screenshots of models

Purpose: show structure and quality, not every number. Recommended set for a 3-statement + DCF model:

  1. Cover sheet — purpose, scenario selected, master check status, version log.
  2. Model map / tab structure — the sheet tabs visible, or a contents table with colour-coded sections (inputs, calculations, outputs).
  3. One schedule — e.g. the debt schedule or PPE roll-forward, with annotations showing opening + additions − repayments = closing, and the link to the interest line.
  4. Integrated statements — a section of the balance sheet with the balance check row visible.
  5. DCF output — FCFF build, WACC, terminal value and EV-to-equity bridge.
  6. Sensitivity table — WACC × terminal growth grid with base case highlighted.
  7. Checks sheet — every check row and the master check.

Annotation conventions: numbered callouts (circles with 1, 2, 3) linked to a short caption below the image; a red or orange outline box around the area being explained; arrows only where flow matters (e.g. "capex from PPE schedule flows to CFS investing"). Keep annotations to three or four per image. Show formula bar when it proves a point — e.g. a formula that links to a schedule rather than a hard-code. Use Windows Snipping Tool (Win+Shift+S) or macOS Screenshot (Cmd+Shift+4), and annotate in PowerPoint, Snagit or similar.

Image quality: capture at 100% zoom or higher, crop to the relevant range, hide gridlines, export as PNG (sharper than JPEG for text), keep each under about 500 KB. Use a consistent width so they align in the dossier.

Annotated screenshots of dashboards

For Power BI: capture each report page, plus one image of the data model view (star schema with relationships, cardinality and filter direction visible) and one of a key DAX measure in the formula bar. Annotations should point out interactivity ("slicer filters all visuals by segment"; "drill-through to customer detail") because a static image hides it. If you use field parameters, calculation groups or bookmarks, show them explicitly — these are differentiators.

Sample outputs

Sample outputs are PDF extracts of the deliverables a business user would receive: the three statements on one page each, the DCF summary, the variance pack, the board MIS page, the Ind AS note disclosure. They demonstrate print setup discipline (Week 23 t2 s07) and give non-Excel reviewers a readable view. Export with consistent page setup: headers with project name and version, footer with file name and date, page numbers, landscape for wide time series.

Check-sheet status

Evidence of model integrity, recorded in three places:

  • On the cover sheet — master check cell linked to the checks sheet: e.g. "Model status: OK (14 checks, 0 errors) — tested 16-Nov-2026 in base, bull and bear scenarios".
  • In a screenshot — the checks sheet with every check listed: balance check per period, cash tie-out, retained earnings roll-forward, debt and PPE roll-forwards, sum of segment revenue to total, DCF EV bridge, scenario switch reset.
  • In the README — a test log: checks run, scenarios tested, flex tests (zero revenue, 100% capex) and results.

For the Ind AS close pack, the equivalent is a reconciliation status: TB to statements tie-out, CFS to BS cash, SOCE to BS equity, and a disclosure checklist completion count. For Power BI, document data validation: dashboard totals reconciled to source (e.g. "FY25 revenue ₹8,450 crore matches annual report Note 24").

Evidence index

Keep an evidence index in the dossier: evidence ID (e.g. P4-E03), description, file name, what it proves, related brief claim. This mirrors an audit working-paper index and ensures every brief claim has at least one evidence item.

Evidence ID Description Proves Brief claim supported
P4-E01 Cover sheet screenshot Master check OK in all scenarios "Fully checked model"
P4-E04 Sensitivity table Range ₹1,780–₹2,390/share Valuation range
P4-E06 Checks sheet 14 checks, 0 errors Integrity

Edge cases & judgement calls

  • Screenshots that reveal errors. Review every image at full size before publishing; a stray #REF! or a check showing "ERROR" in a corner undermines the whole dossier.
  • Stale screenshots. If you change the model after taking screenshots, numbers in images no longer match. Retake all screenshots after the final freeze and record the model version in each caption.
  • Hidden metadata in images. Screenshots can capture file paths, usernames, email notifications or other open windows. Crop tightly and close other applications.
  • Over-annotation. Ten callouts on one image are unreadable. Split into two images.
  • Accessibility. Add alt text or a caption for each image in README and Notion; it also helps search indexing.
  • Checks that pass trivially. A check that always returns 0 because it compares a cell to itself proves nothing. Before screenshotting, deliberately break an input to confirm the check turns to "ERROR", then restore.

Key takeaways

  • Evidence substantiates every brief claim; build an evidence index linking each claim to an image or output.
  • Seven model screenshots and per-page dashboard screenshots plus the data model view cover most needs.
  • Annotate with three or four numbered callouts, crisp PNGs, consistent width.
  • Show check status in three places: cover, checks-sheet image and README test log.
  • Retake screenshots after final freeze and confirm checks actually fire when broken.

Practice Questions

Q1. Screenshot plan for the Ind AS close pack [L2]

Your P1 close pack contains a TB mapping sheet, 11 adjusting journal entries (including an Ind AS 116 lease modification and an ECL provision matrix), Schedule III statements and three notes. Specify five screenshots, the annotations for each (maximum four callouts), and the check status line for the cover.

Q2. Evidence index build [L2]

Your P3 brief makes four claims: (a) the dashboard reconciles to the annual report; (b) time intelligence measures compare YTD versus prior YTD; (c) segment margin fell from 11.2% to 7.9%; (d) the report refreshes from three source files via Power Query. Build an evidence index with at least one evidence item per claim, specifying the image or output and what it proves.

Q3. Proving the check works [L2]

Describe a step-by-step procedure to demonstrate, in a screenshot or short video clip, that your balance check genuinely detects errors. Include the input you would break, the expected effect on the check row, and how you would restore and re-verify the model.

💡 Hint: Use a change whose effect on the balance sheet you can predict in rupees.

Q4. Screenshot review findings [L1]

List six specific defects you would look for when reviewing a set of portfolio screenshots before publishing, and for each state how you would fix it.
