Key concept

Consistent File Naming Across Portfolio, Dossier and CV

Concept: Consistent naming: P1_IndAS_ClosePack_v1.0.xlsx, matching dossier numbering and CV bullets

Statement

Every portfolio artefact follows one naming pattern:

P<n>_<ShortName>_<ArtefactType>_v<major>.<minor>.<ext>

  • P<n> — project number 1–6, identical in the file name, folder name, dossier section, README table, CV bullet order and LinkedIn Featured title.
  • <ShortName> — a fixed CamelCase tag per project (e.g. IndAS_ClosePack, DCF_Capstone), never changed once published.
  • <ArtefactType> — optional for the main working file; required for others (Brief, Deck, Walkthrough, README, Screenshot_Cover).
  • v<major>.<minor> — major increments when headline outputs change (valuation, key findings); minor increments for fixes that do not change headline numbers.
  • No spaces, no "final", "new", or dates in the stem (dates go in the version log).

Explanation

Consistent naming is a control, not cosmetics. It lets a reviewer move from a CV bullet ("P4: 3-statement + DCF capstone…") to the right folder and file instantly, and it lets you verify that the brief, deck and model are the same version. Files named Model final final (2).xlsx signal poor version control — a red flag for modelling roles where version errors cause real losses.

Rules that make the scheme robust:

  • Underscores, not spaces: spaces become %20 in URLs and break some command-line and Git workflows.
  • Avoid special characters (&, #, %, /) that break URLs or are illegal on some file systems.
  • Keep names under about 60 characters to avoid path-length issues on Windows and OneDrive sync.
  • Version in the name and on the cover sheet version log — they must agree.
  • Version numbers are compared as numbers: v1.10 follows v1.9; if you expect many minor versions, use two digits (v1.09).
  • Keep only the latest published version in the public folder; archive earlier versions in Git history or an archive/ folder.

Version logic: P4 moves from v1.0 to v1.1 when you fix a label typo; it moves to v2.0 when correcting the lease treatment changes value per share from ₹2,010 to ₹2,060 — and the brief, deck and video must then all be updated to v2.0.

Practice Questions

Q1. Fix a messy folder [L1]

Rename these files to the convention and identify any that should be archived or deleted: DCF model FINAL.xlsx, DCF model FINAL v2 (use this).xlsx, deck_new.pptx, Deck.pdf, dashboard 12-Nov.pbix, screenshot1.png, Brief - DCF.docx.

Q2. Major or minor version [L2]

For each change to P4 v1.0, decide whether the new version is v1.1 or v2.0 and list which other artefacts must be updated: (a) correcting a chart axis label; (b) changing ERP from 7.0% to 6.5%, moving value per share from ₹2,060 to ₹2,180; (c) adding a new appendix slide with no new numbers; (d) fixing a broken check that was showing "OK" incorrectly, with no change in outputs.

💡 Hint: The test is whether any headline figure quoted in the brief, deck or CV changes.

Q3. Naming rule set for a team [L2]

Draft a one-paragraph naming standard that a four-person FP&A team could adopt for monthly forecast files on SharePoint, adapting the portfolio convention to include entity, period and scenario, and give three example file names.
