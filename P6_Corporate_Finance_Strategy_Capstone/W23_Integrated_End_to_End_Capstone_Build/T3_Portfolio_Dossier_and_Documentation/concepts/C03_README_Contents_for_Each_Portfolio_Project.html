Key concept

README Contents for Each Portfolio Project

Concept: README contents: objective, data sources with dates, model map, how to use, key assumptions, limitations

Statement

Every project folder contains a README.md (rendered on GitHub, also exportable to PDF) with six mandatory sections:

  1. Objective — the business question and the deliverable, in two or three sentences.
  2. Data sources with dates — each source with issuer, document, period, link or filing reference, and access date; market data with "as at" date.
  3. Model map — the list of tabs/pages in order, each with its purpose and colour category (input, calculation, output, check), and the main flows between them.
  4. How to use — software requirements, which cells to change, how to switch scenarios, calculation setting, what to check after changing inputs.
  5. Key assumptions — the five to ten assumptions that drive the result, with values and sources or rationale.
  6. Limitations — what the model does not do, simplifications, data gaps and known issues.

A version line and change log follow, plus a confidentiality and disclaimer statement.

Explanation

The README is the model's documentation, equivalent to the "basis of preparation" note in financial statements and the documentation standards in the ICAEW Financial Modelling Code and FAST Standard (Week 23 t2). It answers the questions a reviewer would otherwise ask you: what is this, where did the numbers come from, how do I use it, what should I not rely on.

Writing points:

  • Data sources with dates are critical because public data is restated and market data moves; a DCF without a valuation date is meaningless. Distinguish primary sources (annual reports, NSE filings) from cross-check aggregators.
  • Model map should match the tab order and colour coding; include a simple flow line such as "Inputs → Revenue/Cost builds → PPE, WC, Leases, Debt, Tax → IS → BS → CFS → DCF → Sensitivity; Checks read all".
  • How to use must state the minimum Excel version (Microsoft 365 / 2021+ if dynamic arrays are used), the iterative calculation setting if circularity exists, and "press F9 before reading data tables" if calculation is "Automatic except data tables".
  • Key assumptions should show value and source: "Terminal growth 5.0% (below long-run nominal GDP growth of ~10%; reflects maturing industry)".
  • Limitations demonstrate judgement: candidates who state limitations look more credible, not less.

Illustration

Extract from P4_DCF_Capstone/README.md:

Section Content (abridged)
Objective Estimate intrinsic value per share of ABC Chemicals Ltd (NSE-listed) and recommend FP&A levers. Deliverables: 17-tab model, 12-slide deck.
Data sources FY21–FY25 consolidated annual reports (accessed 10-Nov-2026); Q1–Q2 FY27 Reg 33 results; Q2 FY27 call transcript; NSE close ₹1,842 as at 14-Nov-2026; 10-year G-sec 6.45% as at 14-Nov-2026.
Model map Cover, Inputs, Hist, Rev, Cost, PPE, WC, Lease, Debt, Tax, Equity, IS, BS, CFS, DCF, Sens, Checks.
How to use Excel 365; change blue cells on Inputs; scenario switch in Inputs!D5 (1 = base, 2 = bull, 3 = bear); iterative calc on, circuit breaker Inputs!D7; press F9 before reading Sens.
Key assumptions Utilisation 78% → 85% by FY29; realisation +3% p.a.; WACC 11.8%; terminal growth 5.0%; tax 25.17% (Sec 115BAA).
Limitations Segment cost split estimated; no explicit forex hedging modelling; ESOP dilution approximated by treasury stock method; valuation not investment advice.
Version v2.0, 18-Nov-2026 — lease liabilities added to net debt; value per share ₹2,060.

Practice Questions

Q1. Write a full README [L2]

Write the complete README for P5 (budget/forecast/variance MIS) built on synthetic monthly data calibrated to a listed FMCG company's FY25 revenue of ₹6,240 crore, with a 9+3 rolling forecast and a price-volume-mix variance pack, covering all six mandatory sections, version log and disclaimer.

Q2. Limitations that build credibility [L2]

For your P6 capital budgeting/M&A project, list five genuine limitations and, for each, explain in one line why disclosing it increases rather than reduces a reviewer's confidence.

💡 Hint: Think about simplifications in tax, financing, synergies and purchase price allocation.

Q3. README versus cover sheet [L1]

State which items should appear on both the README and the workbook cover sheet, which only in one, and how you would prevent the two from contradicting each other after a model update.
